# ADR-0103 program review — feasibility, pipeline efficiency, triage accuracy (2026-09-14)

- **Scope:** the sixteen documents the component-breakdown program produced in 48 hours — ADR-0103, ADR-0101, `signal-center-design.md` §5/§12, and the unit docs 01, 02, 03, 03b, 04, 06, 07, 08, 09, 10, 11, 12, 13, 14, 16 — read in full by two independent reviewers (one per half), with one code-shape claim per doc spot-checked against the worktree that holds the unit (every spot check confirmed), plus the five pipeline-integrity inbox items filed while landing the units.
- **Asked by the operator:** *is the design feasible, and does it improve the pipeline's efficiency and accuracy?*
- **Status of the units at review time:** 01, 02, 03, 03b, 07, 08, 09, 12 merged (#584–#593); 06 in CI (#594); 04, 10, 11, 13, 14, 16 built, reviewed and floored, landing in order.

## 1. Verdict in three lines

| Question | Answer |
|---|---|
| **Feasible?** | **Yes, at the leaf.** Every unit realizes the promised shape — a leaf package with explicit DI, one module tag with registered `MODULE_SNAKE_CASE` codes emitted through one producer with `origin=Type.Method`, 100 % line + API coverage measured package-locally, Strangler facades that keep every production spelling, one wired construction under a source-scan guard, byte-identity goldens captured before the move, 41–93 build-confirmed mutants per unit. The debt is fenced (coverage gates, guards, goldens, named removal triggers) — but nearly all of the *behavioural* debt was declined by each unit and stacked onto "unit 05", which as written is four or five units on the most protected file. |
| **More efficient?** | **Neutral.** The program buys observability and testability, not throughput. Per-cycle savings are one policy read per failure floor (03b), one ancestor-ledger read per continuation audit (09), one mover construction per drained item (06), one exit-class read per launch (10). Untouched by design: the advisor's git recon subprocess, the per-phase re-parse of `phase-registry.json` (`router/policy.go:87`), the 47 policy/config load sites, the five CI-parity subprocess gates, the runner's up-to-16 settle probes. Added: fault-only events (negligible on green cycles), a per-run Center + flush on every `evolve subagent run`, a chain-Center flush per batch. |
| **More accurate for triage?** | **Yes where a Center is wired; no on the paths the operator drives by hand.** Units 07, 08, 09, 11, 14, 16 meet the "≤ 3 signal lines to the failing step" bar on the cycle/loop roots (`fields.step`, probe names, the exact log file beside `signals.ndjson`). The systemic hole every unit defers is the **Center-less roots**: `evolve phase run\|serve\|ship\|audit\|observer`, the nine `bridge.NewDefault(root, nil)` registry factories, the inbox operator commands, the triage persona's claim, compose/plan-and-execute/looppreflight/campaign — the resume and recovery paths. Unit 11 made those strictly *worse* (four forensic lines now print nothing); unit 06 kept the bytes but nothing reaches the stream; unit 16 did it right (its root builds its own Center). |

## 2. Feasibility — what the docs admit

- **"Callers untouched" is violated in every core unit under a declared "THE ONE DEVIATION"** (02 four abort sites, 03 one `Closeout`, 07 three push blocks, 08 `ApplyPolicyStages`, 09 three `…Via` spellings, 12 one `ca.Signals` line). The reason is the same each time: a package-level seam has no route to the Center. The rule should read *"no call-site change except the seam that reaches the Center"*.
- **Null-Object facades kept alive for tests/ACS** — 03's three carryover facades, 09's five audit facades, `hooks{}` literals in 24 audit tests, 33 literal `&Orchestrator{}` tests, `config.Load` (which is *not* test-only: `router/policy.go:87` runs it per phase in production and drops the warnings). Each is a documented silent-loss trap guarded only by a source-scan allowlist.
- **Preserved quirks, explicitly not fixed** (each named as a follow-up): the non-monotonic `LastCycleNumber` and the lost expiry refresh under the RMW union (03 Q1/Q3); the 1-day TTL on every mid-execution failure's P0 todo (03 Q5/03b F11); the retro-phase-name leak (03b Q1); the zero `policy.Policy{}` overlay in the advisor's own dispatch (04 Q2 — the operator's policy block never governs routing); `context.Background()` on the advisor launch (04 Q1 — a halt cannot cancel a router pane); the promote-side "landed" ambiguity and fail-open promotion (06 D2/Q8/F10); the CI-parity gate's package scope and `-p 4 -parallel 4` non-parity (14 Q2/Q7); the 11 bridge exit numerics spelled twice (10 F10).
- **Deferred signals that say what happened** (the landed codes mostly say "my own persist failed"): 02 F1 `FAILUREDIAG_DELIVERY_FAILURE`; 03's five INFO decision codes (zero producers today — the lost-refresh defect has no trace); 07 F3 `ship.landed` (no positive line on a green ship); 12 F2 the *live* observer's stall detection (still on a lowercase envelope file, off the Center); 13's halt/escalation producers (re-scoped out — the lines the operator reads on a zero-ship streak have no code).
- **Unit 05's stacked obligations:** 03b's `orchestrator.warning` handoff row (a new kind + ~10 codes; the ten `completeRetro` vs `phaseCompletionRecord.persist` divergences; seven observer/Run/cancel copies); 07's rebase engine (20 raw lines); 08 F1 the `policy` module (`cmd_cycle.go:424` resets *every* gate dial to compiled defaults with no code) and F4 one registry parser (three today); 09 F3 / 10 F2 / 11 F7 / 14-7 / 06-F1 / 13 F4 — all the Center-less roots; 12's `ca.Signals` line inside a ~300-line `wireOrchestratorDeps` that 04, 06, 09/14, 11 and 13 also edited. `orchestrator.go` **grew** (1169 → 1184: a field and an eager line per unit); 261 hand-written `[orchestrator]` lines remain — about 8 % of core's stderr lines are coded after eight units, because the units took the leaves and left the trunk.
- **Program hygiene:** every unit inserts at the same hunks (`event.go` kinds, `event_test.go` counts, `.cover-strict`, `.apicover-enforce`, the manifest, design-doc §5.1/§5.2/§12, the ADR table, `signal-codes.md`), so the merge train is a guaranteed conflict per unit — resolved as unions in this train, but a forgotten `knownKinds` row stamps `SIGNALCENTER_UNKNOWN_KIND` on every event of a module with green tests. The unit-doc template (350–450 lines, hundreds of `file:line` cites against a base SHA that drifts within days) has outgrown its reviewers' budgets.

## 4. Risks, ranked by blast radius

1. **Silence on Center-less roots** — every standalone CLI path (the recovery paths) loses or never gains the coded line; unit 11 regressed them. *Blast: every manual resume.*
2. **Unit 05 as scoped is the highest-risk change and everything converges on it** — `wireOrchestratorDeps` edited by six units, ten `completeRetro` divergences, four order invariants that reproduced cycles 1585/1587/1034.
3. **The lane ship gate's package scope is preserved** — a contract change still lands a red main; the loop never reads main's CI (inbox `2026-09-14T01-00`).
4. **Merge-train conflicts on the same hunks** — one bad union silently drops a kind, an option line or a registration with green tests.
5. **Suite litter and over-broad ACS predicates** — floors in dev worktrees commit dossiers onto the unit branch (acs/cycle8) and fail on `main..worktree` diffs (acs/cycle1529); new ProtectedSurface rows bar lanes from self-repairing config/observer/ship-landing/defect-ledger/`cmd/evolve`.
6. **Learning-erasing quirks preserved** — the 24 h TTL on mid-execution failures plus the lost expiry refresh: the failure memory the next planner reads decays in a day.
7. **Promotion/landing semantics fail-open** — `shaLandedOnMain` returns landed on exec fault, `main` hard-coded, a rename failure reads as compat-success.
8. **Preserved advisor correctness bugs** — the zero policy overlay and the uncancellable launch: every cycle's routing runs under compiled defaults; a halt can leave a router pane running.

## 5. Recommended program changes (ordered)

1. **Make the Center-less roots the next unit, before 05.** One root-Center builder under `internal/` used by `evolve phase *`, `evolve ship`, the inbox commands, the triage claim, compose/plan-and-execute/looppreflight/campaign and the nine `bridge.NewDefault(root, nil)` factories — copy unit 16's shape; retire the S3 "explicit nil" pin in the same change. Closes 09 F3, 10 F2, 11 F7, 14-7, 06-F1, 13 F4 in one PR and turns 11's regression into an improvement.
2. **Re-scope unit 05 as a series, producers first:** 05b — the `orchestrator.warning` chokepoint, coding the 261 lines file by file largest first (`phase_bindings` 22, `decision_branch` 21, `ship_recovery` 20, `composition_carryforward` 16, `leak_recovery` 15, `cyclerun` 15, `continuation_stamp` 14), measured as lines-to-zero — the operator's actual goal and the lowest behavioural risk; then 05a the composition root (the pins from 04/06/07/08/09/11/12/13 become its tests); then 05c `RunCycle` + closeout; then 05d the rebase engine. Never "composition vs RunCycle" as one PR, and never before the train has merged.
3. **Land the four "what happened" signals** as small PRs: 02 F1, 03's `CARRYOVER_MERGE_CONFLICT` (with a per-cycle cap), 07 F3 `ship.landed`, 12 F2 the live observer's stall codes.
4. **Fix the pipeline defects the units cannot reach, first:** the poison-item breaker (an item that fails at triage is re-claimed every wave — 5+ lanes of the 2026-09-14 batch burned on one item; inbox `02-30`), the red-main gate (reverse-dependency closure or CI's exact suite at the lane gate + a `main_red` step in the boundary refresh; inbox `01-00`), the suite litter (acs/cycle8 on `t.TempDir()`; inbox `00-30`), the stale resume base (inbox `23-30`).
5. **Decide the two learning-erasing quirks with data** — count, from `state.json` history, how many P0 todos expired at 24 h vs 30 d and how many re-mints lost their refresh; then take 03 Q3 and F11 as their own commits.
6. **Flip the two advisor bugs** — pass the loaded policy's `ResolveOverlays` through the existing `WithOverlayResolver` seam (one root line); thread a caller ctx into the launch. Declared behaviour changes, outside unit 04's byte envelope.
7. **Make `evolve signals codes check` a CI step and derive every closed-set count** (the module count is a literal every doc warns about); adopt one stream convention (expected-state events INFO or `fields.expected=true`; `fields.step` on every non-terminal event; cross-links as fields, not prose).
8. **Shrink the unit-doc template** to Context · Boundary · API · Module contract · Risks/byte-identity; move mutant lists, panel folds and migration steps into the PR record — the reviewer-fleet budgets cannot verify 45K-token docs, so the declared-deviation lists are not actually being checked by anyone.

## 6. What the verification wave measures

Run one full batch on the reconciled plane after the train lands, and record per module: (a) `signals.ndjson` events by module/code/severity per cycle on ten healthy cycles — any code firing on a healthy cycle gets a noise budget; (b) console WARN lines per cycle before/after; (c) the ≤ 3-line drill on the next three real failures — hand a fresh reader only `<ws>/signals.ndjson` for one blocked continuation (09), one poison item (06), one 81 timeout (10), one teardown FAIL (11), one red tier (14), one worker integrity fail (16) and write down the exact lines read; (d) hand-written stderr lines remaining per file (core 286 → per-file zero); (e) Null-Object emits at production roots (add a self-report when a unit's `SignalsWired()` is false at a root not on the nil allowlist); (f) lanes ok per wave and ship rate against the previous batch (0/3, 0/3, 2/3, 2/3, 1/3, 1/3, 0/3), with the poison item console-routed; (g) `policy.json` / `phase-registry.json` parse counts per cycle before and after 05a.
