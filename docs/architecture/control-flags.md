## Policy Config Blocks (non-flag, `.evolve/policy.json`)

Not every operator dial is an `EVOLVE_*` env flag — some are typed `.evolve/policy.json`
blocks (see [runtime-reference.md](../operations/runtime-reference.md) for the full table).
This section documents the closed-vocabulary fields those blocks use.

- `fleet.plan_source` (`.evolve/policy.json:fleet.plan_source`) — closed vocabulary: `triage` (the default, empty/absent maps here) or `manual`; any other value fails safe to `manual` (never passthrough, never the `triage` default) plus a surfaced warning naming the rejected value. Runtime meaning: `triage` is the ONLY value that arms native `evolve loop` wave dispatch (S2) — with `fleet.count>1` it makes each batch iteration a wave (one single-writer triage plan fanned out to disjoint lanes) and `--max-cycles` counts waves, not lanes; `manual` (or any fallback) keeps wave dispatch off, so multi-lane fan-out only happens via an explicit `evolve fleet` invocation. A wave whose triage plan commits zero lanes never consumes an iteration: it WARNs and falls through to the sequential path instead (D1 empty-plan guard).
- `fleet.landing` (`.evolve/policy.json:fleet.landing`) — closed vocabulary: `per-lane` (the default; empty/absent maps here) or `prefix-queue`; any other value fails safe to `per-lane` — **never** the composer — plus a surfaced warning naming the rejected value, because an operator typo must not silently route the main-push path through the unsoaked composer. Runtime meaning: `per-lane` is today's behaviour — every PASS lane independently fast-forward-merges and pushes main, serializing on `.evolve/ship.lock`. `prefix-queue` hands the SOLE main-push path to the single-writer prefix composer (`fleet.PrefixQueue`): PASS lanes enqueue instead of pushing, the composer verifies composed queue PREFIXES (L1, L1+L2, L1+L2+L3) against the native gate set, and the first failing prefix names the culprit positionally (Zuul NNFI) so the lanes behind it re-form without it — no bisection subsystem. Window sizing is AIMD (start 3, +1 per green, halve on red, floor 1); risk-tiered lanes (core / cross-cutting `TierIffy`, and any lane sharing a touched file with one already composing) take a solo slot. Design: [ADR-0078](adr/0078-fleet-landing-prefix-queue.md). Implementation: `go/internal/fleet/prefixqueue.go`, `go/internal/phases/ship/planlanding.go`; resolution: `go/internal/policy/policy.go`.
- `gates.repo_contract_gate` (`.evolve/policy.json:gates.repo_contract_gate`) — closed vocabulary: `enforce` (the default; empty/absent maps here) or `off`; any other value is treated as `enforce` plus a surfaced warning naming the rejected value, because a typo must not silently disable a red-main guard. Runtime meaning: the ship-time repo-contract scanner pack — the four deterministic repo-wide guard suites (`./internal/phasespec/...`, `./internal/profiles/...`, `./internal/phasecoherence/...`, `./internal/routingtest/...`) run in the lane worktree BEFORE the ship binds/pushes; a RED pack fails the ship closed with the dedicated `CodeRepoContractGate` so the lane FAILs honestly in place instead of redding main. Per-cycle changed-scope testing structurally cannot catch this class: the suites scan repo-wide state (on-disk catalogs, tracked profiles, rendering parity) a config-only diff never selects — four live red-main incidents in the week of 2026-08-04. The `enforce` default is a deliberate deviation from the shadow-first gate convention: the pack is existing deterministic repo tests with FP≈0 by construction (a failure here fails identically on main's next run). Implementation: `go/internal/phases/ship/repocontract.go`; resolution: `go/internal/policy/policy.go` (`GatesConfig`).
- `boot.binary_refresh` (`.evolve/policy.json:boot.binary_refresh`) — closed vocabulary: `auto` (the default; empty/absent maps here) or `off`; any other value resolves to `auto` — the self-heal is integrity posture, so a typo must not silently disable it. Runtime meaning: the boot-time binary staleness self-heal for the binary-lag class (fixes land on main but the loop keeps executing the binary it booted with — cycles 1302–1309 ran a sentinel parser the repo had already fixed at cycle-1301). At boot, BEFORE recovery and the readiness gate: when the running binary's embedded build commit is behind plane HEAD by a delta touching `go/`, rebuild via the canonical make target and re-exec the fresh binary in place. Every step is fail-open (any failure WARNs and boots the old binary — a stale batch is yesterday's status quo, a bricked loop is worse); a consume-once marker file (`.evolve/boot-refresh-marker`) caps the heal at one attempt per target HEAD so a rebuild that does not change the stamp can never re-exec forever; `--resume` never refreshes (minimal-perturbation single-cycle protocol — the heal lands at the next fresh boot). `off` is for deliberate old-binary pins (incident bisects). Implementation: `go/cmd/evolve/cmd_loop_boot_refresh.go`; resolution: `Policy.BootBinaryRefresh` (`go/internal/policy/policy.go`). Background: `docs/chronicle/2026-08-binary-lag.md`.
