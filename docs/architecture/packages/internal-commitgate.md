# internal/commitgate

> Operator view: [`/evo:commit`](../../../skills/commit/SKILL.md) and the commit-gate row of [runtime-reference.md](../../operations/runtime-reference.md). The comment-removal waiver's rule: [code-comments.md](../../conventions/code-comments.md) (Enforcement). The attestation's reader: `internal/phases/ship/commitgate.go` ([internal-phases-ship.md](internal-phases-ship.md)).

## Purpose

`internal/commitgate` is the pre-commit quality gate that the `/commit` skill runs as `evolve commit-gate run`. It detects the languages of the changed files, checks that a simplifier and one reviewer were declared (unless the change is a proven comment removal), runs lint and targeted tests per language, and on a full pass writes `.commit-gate/attestation.json` bound to the tree-state SHA. `evolve ship --class manual` is the reader that enforces that attestation. It is the Go port of the deleted `commit-gate-runner.sh`.

## Design

- **Exit codes** (`TestExitCodeContract`): 0 pass, with the attestation written; 1 a lint or test failure, an unmet reviewer precondition, or nothing to gate; 2 a git or SHA fatal (not a repo, `git diff HEAD` exiting above 1, no sha256 tool, a binary-guard error, an attestation write failure); 3 a required tool is missing and was not installed; 10 bad CLI arguments (the cmd layer returns it).
- **`Run` order:** the change set, the binary guard, language detection, the review waiver or the reviewer precondition, the language lanes in sorted order, the attestation. Every failure maps onto an exit code; `Run` never panics on a missing tool, a lint failure or a git error.
- **The change set** is the `--files` override (whitespace-separated) or `git diff --name-only HEAD`, with blank lines dropped. An empty set is ExitFail: nothing to gate.
- **The binary guard** runs `binaryguard.Scan` at its default threshold over the change set before any other work, so a large compiled executable (a stray `go build` output) is rejected repo-wide. A scan error is ExitGitFatal.
- **Language detection** maps `go` → go, `py` → python, `ts`/`tsx` → ts, `js`/`jsx`/`mjs`/`cjs` → js, `rs` → rust, sorted and unique (`TestDetectLangs_ExtensionMapping`).
- **The reviewer precondition** needs a simplify capability (`code-simplifier`, `code-review-simplify` or `refactor`) and a review capability (`code-reviewer`, `code-review`, `code-review-simplify`, or the `<lang>-reviewer` / `<lang>-review` of a changed language, where ts and js map to `typescript`). One review capability is enough, and `code-review-simplify` satisfies both. Each declared reviewer is normalized by dropping everything through its last `:` (so `ecc:go-reviewer` counts as `go-reviewer`) and all ASCII whitespace. Only the check normalizes: `reviewers_run` records the raw spellings with empties dropped. Pinned by `TestReviewersSatisfied`, `TestSplitReviewers_RawVerbatim`, `TestRun_GeneralReviewerAlone_ExitPass` and `TestRun_EccPrefixedReviewer_ExitPass`.
- **The review waiver** lists the change itself with `git diff --name-only --no-renames HEAD`, independent of `--files`. Every path must be a regular file, must not sit under `testdata/`, and must be either a Go file that `commentaudit.Equivalent` proves comment-only against HEAD or Markdown under `docs/`; at least one Go file must be proven. A denied waiver logs the path and the reason.
- **Lanes skip files deleted from the working tree**, since a deleted file carries nothing to lint (the Go, Python and Rust lanes; see Findings for the Node lane).
- **Go lane:** `gofmt -s -l` per changed file, then per module (the nearest `go.mod`) `go vet`, `golangci-lint run` when it is on PATH, and `go test` over the changed packages. The `-s` matches CI's `gofmt -d -s`; plain gofmt passes code CI rejects (`TestRun_GofmtUnformatted_ExitFail`). Packages under `./acs/` (build-tagged predicate packages, gated separately) are excluded, but `./acs` itself is not. A file with no `go.mod` above it is ExitFail. The checks are recorded as `go:gofmt`, `go:vet`, `go:golangci-lint` when it ran, and `go:test` (`TestRun_GolangciLintRecordedWhenPresent`).
- **Python lane:** `ruff check` over the changed `.py` files, then `pytest -q` over the changed test files (`test_*.py` or `*_test.py`; `TestIsPyTest`).
- **Node lane:** `eslint`, or `npx eslint` when only npx is present, over the changed ts/tsx/js/jsx/mjs/cjs files. Neither present is ExitToolMissing.
- **Rust lane:** per crate (the nearest `Cargo.toml`), `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`. A `.rs` file with no `Cargo.toml` above it contributes no crate and is skipped, unlike the Go lane's missing `go.mod`, which fails (`TestLaneRust_NoCargoTomlAbove_NoCrateFound`).
- **Tool presence.** `ensureTool` honours `ForceMissing` (`CG_TEST_FORCE_MISSING`: tools treated as absent regardless of PATH) and `TestInstall` (`CG_TEST_INSTALL`: `ok` or `fail` stands in for the install result). `NoInstall` makes every missing tool a hard ExitToolMissing. The `CG_TEST_*` seams come from `Options` fields, never from `Env`, so tests stay hermetic; the unexported `lookPath` is the presence probe tests replace. `Env` is the lint and test subprocesses' environment (nil inherits the parent).
- **The attestation** is `attestation.json` under `AttestDir` (`CG_ATTEST_DIR`; default `<RepoRoot>/.commit-gate`), written atomically. The cmd layer (`internal/cli/guardcmd/commitgate.go`) reads the three `CG_*` variables into `Options`. Its fields, in order: `tree_state_sha`, the sha256 of `git diff HEAD` from `internal/treestate.SHA`, the function the ship reader uses, so writer and reader agree by construction; `ts`, the UTC write time, informational only; `checks_passed`, in execution order; `reviewers_run`; `tool`, `shasum` when present, else `sha256sum` (neither is ExitGitFatal). The reader consumes only `tree_state_sha` and `reviewers_run`, and turns each reviewer into a `Reviewed-by` trailer.
- **The byte layout** is the deleted bash heredoc's: two-space indent, one field per line, inline arrays with no spacing (`["a","b"]`, `[]` when empty) and a trailing newline. Values are written without JSON escaping, as the bash runner did.
- **`Runner` is exactly `sysexec.RunFunc`**, so production passes `sysexec.DefaultRunner` and tests inject a fake without touching PATH (`TestRunner_AliasIsRunFunc`).

## Invariants

- **The attestation binds to sha256(`git diff HEAD`).** `TestGolden_GoPipelineWritesByteExactAttestation` runs the real pipeline over a real repo, computes the SHA independently and checks both the binding and the ts-normalized byte layout. `TestRun_AttestationStableBytes` and `TestRun_EmptyArraysMarshalInline` pin the layout from the writer side.
- **The gate never mutates the host.** Without a test seam, a missing auto-installable tool is reported as ExitToolMissing with the manual install hint; `Run` never shells out an installer (`TestEnsureTool_ForceMissingSeam`, `TestEnsureTool_NotAutoInstallable`).
- **Only a proven comment removal waives review, and nothing can hide a path from the proof.** A `--files` selection and a git rename cannot narrow the listing; a symlink or a deletion is refused, since a symlink could point a docs- or Go-looking path at content the proof never saw; a `testdata/` fixture is refused because tests read it. Pinned by `TestRun_AProvenCommentOnlyChangeNeedsNoReviewers`, `TestRun_AnyChangeBeyondCommentRemovalStillNeedsReviewers`, `TestRun_ADeniedWaiverSaysWhy` and `TestRun_ARealGitRenameCannotHideItsSourceFromTheWaiver`.
- **`go:vet` and `go:test` are recorded even when every changed package was under `./acs/` and nothing ran**, which keeps `checks_passed` identical to the bash runner's (`TestRun_AcsPackagesExcluded`).

## Findings

- `reviewers_run` keeps the raw `--reviewers` spellings and the writer does not escape values, so a reviewer name containing `"`, `\` or a control character writes an attestation that is not valid JSON. The other fields (a hex SHA, an RFC3339 timestamp, fixed check tokens, a tool name) are JSON-safe.
- The Node lane does not apply the working-tree-existence filter the other lanes apply, so a deleted `.ts` or `.js` file reaches eslint.
- The Go lane flags a file only when `gofmt -s -l` succeeds and prints it; a failing `gofmt` invocation (a parse error, or no `gofmt` binary) counts as formatted and still records `go:gofmt`.
- No test in this package drives the binary guard; `internal/binaryguard` pins the scan itself.
