# internal/commitgate

> Operator view: [`/evo:commit`](../../../skills/commit/SKILL.md) and the commit-gate row of [runtime-reference.md](../../operations/runtime-reference.md). The comment-removal waiver's rule and the history archive's: [code-comments.md](../../conventions/code-comments.md) (Enforcement). The attestation's reader: `internal/phases/ship/commitgate.go` ([internal-phases-ship.md](internal-phases-ship.md)). Decisions: [ADR-0111](../adr/0111-code-carries-no-comments.md), [ADR-0115](../adr/0115-commit-gate-keeps-history-and-records-waivers.md).

## Purpose

`internal/commitgate` is the pre-commit quality gate that the `/commit` skill runs as `evolve commit-gate run`. It refuses what never commits (a compiled executable, an added comment, a removed history comment no archive page records), detects the languages of the changed files, checks that a simplifier and one reviewer were declared (unless the change is a proven comment removal), runs lint and targeted tests per language, and on a full pass writes `.commit-gate/attestation.json` bound to the tree-state SHA. `evolve ship --class manual` is the reader that enforces that attestation. It is the Go port of the deleted `commit-gate-runner.sh`.

## Design

- **Exit codes** (`TestExitCodeContract`): 0 pass, with the attestation written; 1 a lint or test failure, an unmet reviewer precondition, a refusal (an executable, an added comment, an unrecorded history removal, a changed Go file that does not parse), or nothing to gate; 2 a git or SHA fatal (not a repo, `git diff HEAD` exiting above 1, no sha256 tool, a binary-guard error, an unreadable HEAD, an attestation write failure); 3 a required tool is missing and was not installed; 10 bad CLI arguments (the cmd layer returns it).
- **`Run` order:** the change set (listed under `Run`'s context, `TestRun_ListsTheChangeUnderItsOwnContext`), what never commits (`refuseWhatNeverCommits`: the binary guard, then the chain of added-comment, unrecorded-history and rewritten-archive refusals, each listing the change itself), language detection, the review waiver or the reviewer precondition (`reviewDecision`, which returns the waiver to record), the language lanes in sorted order, the attestation (whose writer logs the PASS line). Every failure maps onto an exit code; `Run` never panics on a missing tool, a lint failure or a git error.
- **The change set** is the `--files` override (whitespace-separated) or `git diff --name-only HEAD`, with blank lines dropped. An empty set is ExitFail: nothing to gate.
- **The binary guard** runs `binaryguard.Scan` at its default threshold over the change set before any other work, so a large compiled executable (a stray `go build` output) is rejected repo-wide, named, with no attestation and no further subprocess (`TestRun_ACompiledExecutableIsRefusedBeforeAnyOtherWork`). A scan error, such as a path it cannot stat, is ExitGitFatal (`TestRun_AnUnscannablePathIsAFault`).
- **Language detection** maps `go` → go, `py` → python, `ts`/`tsx` → ts, `js`/`jsx`/`mjs`/`cjs` → js, `rs` → rust, sorted and unique (`TestDetectLangs_ExtensionMapping`).
- **The reviewer precondition** needs a simplify capability (`code-simplifier`, `code-review-simplify` or `refactor`) and a review capability (`code-reviewer`, `code-review`, `code-review-simplify`, or the `<lang>-reviewer` / `<lang>-review` of a changed language, where ts and js map to `typescript`). One review capability is enough, and `code-review-simplify` satisfies both. Each declared reviewer is normalized by dropping everything through its last `:` (so `ecc:go-reviewer` counts as `go-reviewer`) and all ASCII whitespace. Only the check normalizes: `reviewers_run` records the raw spellings with empties dropped. Pinned by `TestReviewersSatisfied`, `TestSplitReviewers_RawVerbatim`, `TestRun_GeneralReviewerAlone_ExitPass` and `TestRun_EccPrefixedReviewer_ExitPass`.
- **The review waiver** lists the change itself with `git diff --name-only --no-renames HEAD`, independent of `--files`. Every path must be a regular file, must not sit under `testdata/`, and must be either a Go file that `commentaudit.Equivalent` proves comment-only against HEAD or Markdown under `docs/`; at least one Go file must be proven. A denied waiver logs the path and the reason. A granted waiver is recorded in the attestation as `review_waiver: "comment-only"` (`commentOnlyWaiver`), which ship turns into a `Review-waived: comment-only` trailer, so `git log` tells a waived commit from a `--bypass-commit-gate` one (`TestRun_AWaivedCommitRecordsItsWaiverAndAReviewedOneDoesNot`).
- **Lanes skip files deleted from the working tree**, since a deleted file carries nothing to lint: the Go, Python and Rust lanes through `existingFilesWithExt`, the Node lane through `fileExists` over `nodeExts` (`TestLaneNode_ADeletedFileNeverReachesEslint`, `TestLaneNode_OnlyDeletedFilesRunNoLint`).
- **Go lane:** `gofmt -s -l` per changed file (`checkGofmt`; a `gofmt` that fails to run, a parse error or a missing binary, fails the lane with its output and records no `go:gofmt`, `TestRun_AFailingGofmtFailsTheGoLane`), then per module (the nearest `go.mod`) `go vet`, `golangci-lint run` when it is on PATH, and `go test` over the changed packages. The `-s` matches CI's `gofmt -d -s`; plain gofmt passes code CI rejects (`TestRun_GofmtUnformatted_ExitFail`). Packages under `./acs/` (build-tagged predicate packages, gated separately) are excluded, but `./acs` itself is not. A file with no `go.mod` above it is ExitFail. The checks are recorded as `go:gofmt`, `go:vet`, `go:golangci-lint` when it ran, and `go:test` (`TestRun_GolangciLintRecordedWhenPresent`).
- **Python lane:** `ruff check` over the changed `.py` files, then `pytest -q` over the changed test files (`test_*.py` or `*_test.py`; `TestIsPyTest`).
- **Node lane:** `eslint`, or `npx eslint` when only npx is present, over the changed ts/tsx/js/jsx/mjs/cjs files. Neither present is ExitToolMissing.
- **Rust lane:** per crate (the nearest `Cargo.toml`), `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`. A `.rs` file with no `Cargo.toml` above it contributes no crate and is skipped, unlike the Go lane's missing `go.mod`, which fails (`TestLaneRust_NoCargoTomlAbove_NoCrateFound`).
- **Tool presence.** `ensureTool` honours `ForceMissing` (`CG_TEST_FORCE_MISSING`: tools treated as absent regardless of PATH) and `TestInstall` (`CG_TEST_INSTALL`: `ok` or `fail` stands in for the install result). `NoInstall` makes every missing tool a hard ExitToolMissing. The `CG_TEST_*` seams come from `Options` fields, never from `Env`, so tests stay hermetic; the unexported `lookPath` is the presence probe tests replace. `Env` is the lint and test subprocesses' environment (nil inherits the parent).
- **The attestation** is `attestation.json` under `AttestDir` (`CG_ATTEST_DIR`; default `<RepoRoot>/.commit-gate`), written atomically. The cmd layer (`internal/cli/guardcmd/commitgate.go`) reads the three `CG_*` variables into `Options`. Its fields, in order: `tree_state_sha`, the sha256 of `git diff HEAD` from `internal/treestate.SHA`, the function the ship reader uses, so writer and reader agree by construction; `ts`, the UTC write time, informational only; `checks_passed`, in execution order; `reviewers_run`; `review_waiver`, present only when the review waiver applied; `tool`, `shasum` when present, else `sha256sum` (neither is ExitGitFatal). The reader (`internal/phases/ship`) decodes into this same `Attestation` type, so the schema has one home, consumes `tree_state_sha`, `reviewers_run` and `review_waiver`, and turns each reviewer into a `Reviewed-by` trailer and the waiver into a `Review-waived` trailer. Ship's tests write their attestations with this package's `Marshal`, and `TestAttestation_MarshalWritesValidJSONForAnyReviewerName` round-trips every field, so a writer key that drifts from its struct tag fails a test.
- **The byte layout** is the deleted bash heredoc's: two-space indent, one field per line, inline arrays with no spacing (`["a","b"]`, `[]` when empty) and a trailing newline. `Marshal` encodes every value with `encoding/json`, so any reviewer name writes valid JSON (`TestAttestation_MarshalWritesValidJSONForAnyReviewerName`); the layout is unchanged for an attestation with no waiver (`TestRun_AttestationStableBytes`, `TestRun_EmptyArraysMarshalInline`, the golden), and a waiver adds one line before `tool` (`TestAttestation_AWaiverIsWrittenOnlyWhenOneApplied`).
- **`Runner` is exactly `sysexec.RunFunc`**, so production passes `sysexec.DefaultRunner` and tests inject a fake without touching PATH (`TestRunner_AliasIsRunFunc`).

## Invariants

- **A commit that adds a comment is refused.** `refuseAddedComments` runs `commentaudit.AddedAcrossDiff` over the change set (HEAD against the working tree), the same rule the build floor and `commentaudit comments` apply, before the review waiver: a comment-only *addition* would otherwise ride the waiver, since it is AST-equivalent. The change is listed with `--no-renames -z` as well (as the waiver lists it), so a rename's source reaches the rule, a `git mv` of a commented file moves its comments rather than adding them, and a non-ASCII path arrives as git stores it instead of quoted (a quoted `"\303\251.go"` would fail the `.go` check and pass its comments). HEAD is read through `commentaudit.ReadAtBase`, so a path new at HEAD is absent while an unreadable repository is a fault (`ExitGitFatal`), never a new file. A comment moved between files in the change is not added. It runs with the binary guard in `refuseWhatNeverCommits`. Pinned by `TestRun_ACommitThatAddsACommentIsRefused`, `TestRun_WhatAToolReadsIsNotAnAddedComment`, `TestRefuseAddedComments_ARenamedCommentedFileAddsNoComment` (a real `git mv`), `TestRefuseAddedComments_ANonASCIIPathIsRead` (a real `é.go`), `TestRefuseAddedComments_AnUnreadableHeadIsAFaultNotANewFile` and `TestRefuseAddedComments_AnUnlistableChangeIsAFault`.

- **A commit that removes history-carrying comments records them.** `refuseUnrecordedHistory` (`history_recorded.go`) lists the change as the added-comment refusal does, runs `commentaudit.RemovedHistoryAcrossDiff` (the rule `commentaudit history` uses, so a group moved whole elsewhere in the change is not removed), then `commentaudit.UnrecordedHistory`: each removed group must appear, as its fenced text, in text the change adds to its package's page under `docs/history/code-comments/`. Each unrecorded group is refused by `file:line` with the command that records it (`recordHistoryCommand`, its one spelling), and no attestation is written. A git fault is ExitGitFatal; a changed Go file that does not parse is ExitFail (`historyCheckFault`, through `commentaudit.IsUnparsable`, so the gate never names the parser's error type). The archive pages are `docs/**.md`, so a comment removal that records its history is still waived. Pinned by `TestRun_RemovingHistoryWithoutRecordingItIsRefused`, `TestRun_RemovingHistoryTheChangeRecordsIsWaived`, `TestRun_HistoryMovedWholeToAnotherFileNeedsNoRecord`, `TestRefuseUnrecordedHistory_TheCommandTheRefusalNamesSatisfiesIt` (a real repo: refused, `commentaudit.Main history` run, then passed) and `TestRefuseUnrecordedHistory_AFaultIsNotARefusal`.

- **The history archive only grows, even under the waiver.** A waived commit has no reviewer, so `refuseRewrittenHistory` refuses a change whose archive page (under `docs/history/code-comments/`, the generated `README.md` index aside) no longer starts with its text at HEAD, a deleted page included (`commentaudit.RewrittenHistoryPages`), naming the page. An unreadable HEAD or an unlistable change is ExitGitFatal. Pinned by `TestRun_ARewrittenHistoryPageIsRefusedEvenWhenTheChangeIsWaived` and `TestRefuseRewrittenHistory_AnUnreadableArchiveIsAFault`.

- **The attestation binds to sha256(`git diff HEAD`).** `TestGolden_GoPipelineWritesByteExactAttestation` runs the real pipeline over a real repo, computes the SHA independently and checks both the binding and the ts-normalized byte layout. `TestRun_AttestationStableBytes` and `TestRun_EmptyArraysMarshalInline` pin the layout from the writer side.
- **The gate never mutates the host.** Without a test seam, a missing auto-installable tool is reported as ExitToolMissing with the manual install hint; `Run` never shells out an installer (`TestEnsureTool_ForceMissingSeam`, `TestEnsureTool_NotAutoInstallable`).
- **Only a proven comment removal waives review, and nothing can hide a path from the proof.** A `--files` selection and a git rename cannot narrow the listing; a symlink or a deletion is refused, since a symlink could point a docs- or Go-looking path at content the proof never saw; a `testdata/` fixture is refused because tests read it. Pinned by `TestRun_AProvenCommentOnlyChangeNeedsNoReviewers`, `TestRun_AnyChangeBeyondCommentRemovalStillNeedsReviewers`, `TestRun_ADeniedWaiverSaysWhy` and `TestRun_ARealGitRenameCannotHideItsSourceFromTheWaiver`.
- **`go:vet` and `go:test` are recorded even when every changed package was under `./acs/` and nothing ran**, which keeps `checks_passed` identical to the bash runner's (`TestRun_AcsPackagesExcluded`).

## Findings

- Fixed 2026-10-01 (inbox `commitgate-attestation-and-lane-defects`): the writer did not escape values, so a reviewer name with `"`, `\` or a control character wrote invalid JSON; the Node lane passed deleted files to eslint; a failing `gofmt` counted as formatted; the change was listed under `context.Background()`; and no test drove the binary guard through `Run`.
- The history refusal matches a removed group by its fenced text on its package's page, not by `file:line`, so a record made against an older base (the line numbers moved) still counts. A block comment that itself holds a fenced copy of another group's text could satisfy that group; no such comment exists.
