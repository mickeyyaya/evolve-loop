# internal/subagent

## Purpose

`internal/subagent` dispatches one subagent invocation end to end: load the agent profile, mint a challenge token, compose the prompt, launch through `core.Bridge`, verify the returned artifact and append a ledger entry. It also holds the CLI-facing helpers around that dispatch — parallel sibling fan-out, cache-prefix rewriting, model-tier resolution, profile validation, context-advisory checks and the dispatch-depth recursion guard. `cmd/evolve/cmd_subagent.go` (the `evolve subagent` command group) is its only caller outside the package.

## Design

- **A façade over the `subagentrun` leaf (ADR-0103, component-breakdown unit 16).** Verdict constants, the artifact-verify contract (`Verify`/`VerifyArtifact`), path resolution and hashing are thin projections — type aliases, const aliases or one-line wrapper funcs — over `subagentrun`'s implementations, so the leaf owns the logic and this package owns the public name.
- **Ports `subagent-run.sh` (no longer in this repo) incrementally.** Parallel sibling fan-out (`DispatchParallel`), cache-prefix rewriting (`WriteCachePrefix`) and dispatch-plan log emission (`ValidateProfile`'s `DispatchPlanLog`) have shipped in Go; phase-observer spawn/reap and a fast-fail consecutive-failure counter have not and still run from bash.
- **`WriteFanoutLedgerEntry` (helpers.go) keeps its own hash-chained append skeleton beside `subagentrun`'s ledger writer** instead of sharing one implementation — a known duplication of "a chained ledger append" flagged for a future consolidation.
- **`apicover_named_test.go` closes an apicover coverage gap deliberately**: it binds each exported type/const's real producer output to an explicitly-typed variable and asserts a load-bearing field, so the identifier is both named and its producing function exercised — for symbols other tests exercise only through their producer, never by name.

## Invariants

- **One verification ladder for both dispatch paths.** `Runner.classify` (subagent.go) and `Run` (run.go) both judge through `contract.go`'s `Verify`/`VerifyArtifact`; a bridge launch/exec error only adds a leading diagnostic and never short-circuits the artifact integrity checks. Pinned by `TestClassify_BridgeErrorNonzero`.
- **A cache prefix must be byte-identical for the same (cycle, workspace, agent).** `WriteCachePrefix` carries no timestamps or randomness, so the Anthropic prompt cache reuses the prefix across sibling fan-out workers. Pinned by `TestWriteCachePrefix_ByteDeterministicAcrossInvocations`.
- **A composed prompt never starts with `--`.** claude CLI's flag parser reparses a leading dash as a flag, and the bridge driver passes the prompt as `-p "$content"`. Pinned by `TestComposePrompt_NoLeadingDashes`.
- **Git-state capture failure is non-fatal.** `Run` falls back to `"unknown"`/`"unknown"` so the ledger entry still records what it has instead of aborting the dispatch. Pinned by `TestRun_GitStateErrorFallsBackToUnknown`.
- **A ledger-append failure surfaces, it does not vanish.** `Run` appends a diagnostic to `Result.Diagnostics` and returns the error rather than swallowing it. Pinned by `TestRun_LedgerAppendError`.
- **Bridge recursion is bounded.** A fan-out worker re-enters the same `evolve` binary via `subagent run` (never the in-process Agent tool), and `EVOLVE_DISPATCH_DEPTH` threads the depth across each re-entry; `Run` and `DispatchParallel` both refuse past `maxDispatchDepth` (3) so a misconfigured profile cannot nest dispatches unboundedly. Pinned by `recursion_test.go`'s depth tests, `conformance_test.go` and `dispatchparallel_test.go`.
- **A recursive child always clears `CLAUDECODE_TYPE`.** A child is never the top-level host; a leaked `CLAUDECODE_TYPE=host` would make `sandbox.DetectNested` return false, attempt an inner OS sandbox wrap, and hang the REPL boot on macOS (`sandbox_apply()` EPERMs). Clearing it for every worker keeps `DetectNested=true` at any depth. Pinned by `recursion_test.go`, `conformance_test.go` and `worker_token_test.go`.
- **`DispatchParallel` never chooses the CLI its workers run.** It is a passthrough: each worker re-enters `subagent run`, which resolves its own CLI from the profile. The CLI `DispatchParallel` reads is only the profile's own declaration, used to inspect capability for the quality tier, so an unresolvable profile fails loudly instead of being tiered against an invented default. Pinned by `TestDispatchParallel_SilentCLIIsAnError`.
- **Per-worker artifact verification checks provenance, not just presence.** The fan-out parent dictates each worker's challenge token (`parentToken+"-"+subtask`), threads it to the worker, and `defaultVerifyWorkerArtifact` rejects an artifact that doesn't bear it. Pinned by `TestDefaultVerifyWorkerArtifact_TokenChecked`.
- **Every registered agent role satisfies the same dispatch invariants.** The conformance suite (`conformance_test.go`) is table-driven over `agentRoles`, so adding a role auto-subjects it to: bridge-only dispatch (never in-process), the one verification SSOT, sandbox-coherent recursion, the recursion depth cap, and no cross-dispatch token/artifact leakage under concurrency.
- **`agentRoles` is derived, not hand-maintained**, as the union of every phasecontract-registered agent that produces an LLM deliverable plus `nonRegistryRoles`; a second hand-typed list previously drifted from the registry (a registered role silently stayed non-dispatchable). Pinned by `TestAgentRoles_DerivedFromPhaseContractRegistry` and `TestAgentRoles_EveryRoleHasProfile`.
- **The host facade over `subagentrun` is byte-identical to the pre-extraction behavior** on every observable surface: the composed prompt, the adapter env, the Warns channel, every error text, the verdict wiring and the ledger line. `run_unit16_pins_test.go` and `run_seam_test.go` are the strangler-proof suites that pin this.
- **`validateprofile.go`'s `defaultAdapterExists` duplicates `run.go`'s `RunOptions.AdapterExists → driverExists` seam** (both decode a CLI, one still via a legacy `<AdaptersDir>/<cli>.sh` path) — a known twin flagged for a future fold onto one shape.
- **`execAdapterDeps` carries both ADR-0044 recovery-stage dials from the dispatched project's policy.json**, through the same accessor `internal/adapters/bridge`'s `productionEngineDeps` uses, so a dead pane fast-fails on this composition root exactly as it does on the cycle root; no project root fails open to the compiled defaults rather than leaving the dials unset. Pinned by `TestExecAdapterDeps_CarriesThePolicyRecoveryDials` and `TestExecAdapterDeps_NoProjectRootResolvesCompiledDefaults`.

## Findings

- Two exported-seam doc comments had drifted from the code and were corrected during comment reduction: `Config`'s doc claimed production wires it via a `NewDefault()` that does not exist (`New` fills the defaults itself), and `ValidateProfileOptions.ExecAdapter`'s doc said it "runs the bash adapter" — the default now dispatches through the in-process `gobridge` engine, not a shell.
