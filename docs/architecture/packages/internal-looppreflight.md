# internal/looppreflight

> Operator view (flags, exit code, `.evolve/loop-preflight.json`): the readiness-gate row of [runtime-reference.md](../../operations/runtime-reference.md). The base-divergence check: [ADR-0081](../adr/0081-boot-base-divergence-halt-and-in-band-ledger-seal.md). The CLI-version-freeze check: [ADR-0044](../adr/0044-unified-phase-recovery-protocol.md) C5 and [phase-recovery.md](../phase-recovery.md). The nested-fallback canary: [sandbox-confinement-ssot.md](../sandbox-confinement-ssot.md). The CLI-health bench layer: `EVOLVE_CLI_HEALTH` in [control-flags.md](../control-flags.md). This page keeps the package-level detail those do not.

## Purpose

`internal/looppreflight` is the readiness gate that `evolve loop` runs after the unfinished-cycle guard and before the first cycle. It checks that the pipeline can actually run on this host, writes the result to `.evolve/loop-preflight.json`, and aborts before any LLM spend when a check halts.

## Design

- **A deterministic host-side gate, not an agent phase.** An environment-check agent would have to run through the bridge it is meant to verify, and environment checks are deterministic work.
- **Options → Run → Result, with nil-to-default seams.** The shape follows `releasepreflight`. `resolve` fills every nil seam with the real implementation, so production passes only paths and tests inject deterministic lookups. A few seams are package variables instead (`baseDivergenceProbe`, `newGit`, `execVersion`), so tests can script git replies and `--version` output without threading them through `Options`.
- **Accumulate, then decide.** `Run` runs every check before `finalize` folds them. `CheckLevel` is ordered Pass < Warn < Halt, so the overall level is the maximum. The operator sees every problem in one pass. Checks accumulate internally too: `pipeline-structure` lists every gap, and a `host-capabilities` halt carries that check's warnings.
- **Errors are harness faults only.** `Run` returns an error only for a bad call, such as an empty `ProjectRoot`. A failed check is a Halt inside the `Result`.
- **The checks, in `Run` order:**

| Check | Level | Fires when |
|---|---|---|
| `pipeline-structure` | Halt | a spine phase lacks a registry factory or a deliverable contract; the profiles dir cannot be listed or a profile cannot load; a profile's CLI or `cli_fallback` entry names no known driver |
| `base-divergence` | Halt / Warn | the local base is behind the freshly fetched origin (Halt, naming `evolve sync-main`); the comparison could not run (Warn) |
| `llm-cli-status` | Halt | a CLI binary the resolved chains use is missing (the profiles' CLIs when there is no routing seam) |
| `host-capabilities` | Halt / Warn | Halt: no tmux, `.evolve` or `.evolve/runs` unwritable, or a required sandbox the host cannot provide. Warn: under 500 MiB free, a failed orphan-session reap, or the `EVOLVE_SANDBOX=off` opt-out |
| `cli-version-freeze` | Halt / Warn | a self-updating `*-tmux` CLI is not version-frozen (Halt); the pin or evidence state is unverifiable (Warn) |
| `cli-health` | Warn | a CLI family has an active bench in `.evolve/cli-health.json` |
| `cli-version-drift` | Warn (Pass when expected) | an inventoried CLI's version differs from `.evolve/cli-versions.json` and no chain of boundary records in `.evolve/cli-updates.json` explains it, or the chain includes a self-update the boundary smoke-booted (`self-updated, smoke OK`); a change only boundary updates explain passes as expected |
| `bridge-boot` | Halt (Warn when skipped) | a `*-tmux` driver's REPL fails to reach its prompt marker |
| `sandbox-nested-fallback` | Pass / Warn / Halt | the nested-session write canary is unverified, at the `sandbox.nested_fallback` stage (off, shadow, enforce) |
| `phase-routing-warnings` | Warn | phasespec dropped a user-phase spec while merging the catalog |
| `overlay-tier-selectors` | Warn | an `overlays` rule's `tiers` selector names no canonical tier, so it matches only a dispatch token spelled the same way (`policy.NonCanonicalOverlayTierSelectors`); an unreadable `policy.json` also warns |
| `cli-routing` | Halt / Warn | the CLI routing table does not compile (Halt, with every finding in the detail); it compiles with warning findings (Warn). With no `Options.Routing` seam, the profile seams compile a legacy table and the same rule applies to its findings (a missing profiles directory warns; a profile list that fails halts) |

- **The drivers come from the routing table.** `Options.Routing` returns the compiled table's `Routing{Drivers, Findings}`. `cmd/evolve`'s `preflightRouting` compiles the project's table (`loadCLIRouter`, the same profiles directory `evolve cycle run` compiles) and collects every candidate of each profile agent's resolved chain. Both that seam and the no-seam default go through one helper, `CompileRouting(compile, list)`: compile the table, list the agents (a profiles directory that does not exist is no error, so the no-seam path warns rather than halts), and take the union of their resolved chains (`RoutedDrivers`). `resolved.drivers()` is the one driver list `llm-cli-status`, `cli-version-freeze`, `bridge-boot` and the version inventory read, so the gate probes and boots what the chains actually launch, never a profile CLI the table routes away from. The seam is compiled once per `Run` (`routingOnce`). With no seam, the profile seams compile a legacy table (`profileRouting`), so the drivers still come from the resolver. When the table does not compile, `drivers()` is empty and `cli-routing` halts; the profile-walk fallback was deleted in the L1b fix round (2026-10-06), because it would probe and boot a CLI the table may exclude. (2026-10-06, L1b of the CLI routing table, [ADR-0119](../adr/0119-one-routing-table-one-resolver.md): before this, those checks walked the profiles' `cli` and `cli_fallback` through `distinctDrivers`, so the gate halted on codex whatever the config said.) Pinned by `TestDistinctDrivers_FollowsTheResolvedChains`, `TestPreflight_ATableThatDoesNotCompileProbesNoProfileChain`, `TestPreflight_WithoutARoutingSeamTheDriversComeFromTheResolver`, `TestRoutedDrivers_IsTheUnionOfEveryAgentsResolvedChain` and, in `cmd/evolve`, `TestPreflightRouting_BootsOnlyWhatTheResolvedChainsLaunch`.
- **Profile iteration.** `sandboxWanted` skips profiles that fail to load; only `pipeline-structure` reports load failures, and it still checks each profile's declared `cli` and `cli_fallback` names against the driver registry (`profileCLIs`). `sandboxWanted` still reads the profiles, because sandboxing is a profile property, not a routing one. A driver maps to its binary by the segment before the first dash (`claude-tmux` and `claude-p` → `claude`), and each binary is probed once.
- **Bridge boot.** Each `*-tmux` driver boots in turn, without a prompt, under its own `BootBudget` (default 90s, matching `evolve doctor boot`). The default tester provisions a throwaway workspace, plus a throwaway worktree and the `build` agent on the sandbox path. The sandbox path runs only when a profile enables sandboxing and the host is expected to sandbox. `exitWorkspaceSetupFailed` is -1 so a `MkdirTemp` failure is never misreported as `ExitBadFlags`, and an unrecognized exit code is named with its number. **A bare REPL-boot timeout is retried as many times as the driver's manifest allows**. The boot tester returns a `BootOutcome{RC, Wall, Scrollback}`, where `Wall` is the escalation pattern the attempt's workspace recorded (`bridge.EscalationPattern`). So a boot that timed out on a login or quota wall is not retried as a cold start: the halt names the wall and claims no retries (`TestRun_BridgeBoot_ABootTimeoutCarryingAWallIsNotRetriedAndNamesTheWall`; review round 1, 2026-10-06). Before that, the seam returned only the exit code and the pane, so preflight retried any exit 80. (`probe_boot_retries`; agy-tmux and agy-claude-tmux allow 1, every other driver 0) through `bridge.BootProbe.Retry`, and each attempt gets the whole `BootBudget`. The log names the cold start (`[agy-tmux] cold start: boot attempt 1 of 2 timed out …; retrying`). A second timeout still halts, and the detail says `on all 2 boot attempts` above the final pane (since 2026-10-06; [incident note](../../incidents/agy-cold-start-boot-timeout-2026-10-06.md)). Pinned by `TestRun_BridgeBoot_AnAgyColdStartThatBootsOnTheRetryPasses` and `TestRun_BridgeBoot_AnAgyThatNeverBootsHaltsAfterBothAttemptsWithThePane`. **A failed boot carries the usage verdict:** `Options.UsageEvidence` (the shared usage evidence, wired by `loopPreflightOptions` and handed to `checkBridgeBoot` by `Run`, as `MinFreeBytes` is to the disk check, so `resolve` stays within its size allowance) adds a `usage: …` line under the final pane. It says whether quota was verified as the cause, ruled out, or could not be queried, which points at auth, install or network. The check still halts; the line tells the operator which way to look ([CLI-failure triage](../../operations/cli-failure-triage.md)). Pinned by `TestRun_BridgeBoot_AFailedBootCarriesTheUsageVerdictAndAPassAsksNothing` and, in `cmd/evolve`, `TestLoopPreflightOptions_AFailedBootIsExplainedByTheUsageEvidence`.
- **CLI version freeze.** The Specification is *risky(bin) ∧ tmuxDriven(bin) ⇒ pinned(bin)*. "Risky" comes from the known-updater registry: codex keeps `~/.codex/version.json`, and claude keeps `~/.claude/settings.json`. Ahead of the registry, a CLI whose `<bin>-tmux` manifest declares `auto_update_off_env` (agy: `AGY_CLI_DISABLE_AUTO_UPDATE`) is frozen at the source when the manifest's `default_env` sets that variable, and risky when it does not; its halt names the manifest fix instead of a brew pin (`manifestFreezeEvidence`, `freezeRemedy`). "Pinned" comes from `brew list --pinned`, bounded at 5s. The halt detail gives `brew pin <bin>` and the deliberate-update procedure (`brew unpin`, `brew upgrade`, `brew pin`, never mid-batch). A CLI with no registry entry is not checked. New self-updaters are added to the registry as incidents reveal them.
- **Version inventory.** `<bin> --version` runs for every distinct profile binary, bounded at 5s each. The first `M.N` or `M.N.P` token is kept, and a binary whose probe fails or prints no token is left out. The map lands in `Result.CLIVersions` (`cli_versions` in the JSON) and in `.evolve/cli-versions.json`, which the next batch's drift check compares against. `CLIVersion` is that probe and token rule for one binary; the inventory and the boundary CLI updater (`internal/cliupdate`, wired in `cmd/evolve`) both call it, so the two read a version the same way. The probe runs with `bridge.ProcessEnv(bin)`, the process environment plus the family manifest's `default_env`, so `agy --version` never triggers agy's launch-time self-updater (`TestCLIVersion_TheRealProbeRunsAgyWithItsSelfUpdaterOff`).
- **Expected drift.** The boundary CLI updater ([internal-cliupdate.md](internal-cliupdate.md)) runs at loop boot and at each later wave boundary and records each version it accepts in `.evolve/cli-updates.json`. `classifyVersionChanges` (`boundaryupdates.go`) keeps only the records written after the baseline `cli-versions.json` was last saved (its mtime, read before this run saves it), so an old X → Y record cannot explain a new X → Y after a rollback (`TestVersionDrift_ARecordOlderThanTheBaselineExplainsNothing`), and sorts each changed binary by `cliupdate.CauseOf`, a chain of records from the baseline version to the current one: only boundary updates on it is expected (pass, and the message says the boundary updater made them); a self-update on it, which the boundary found and smoke-booted, warns as `<bin> self-updated, smoke OK: a → b`, because it means the freeze leaked; no chain is drift (warn, with the not-recorded note). Each warning lists the other classes under it. An unreadable record explains nothing, and the warning says so.
- **CLI version freeze.** The Specification is *risky(bin) ∧ tmuxDriven(bin) ⇒ pinned(bin)*. "Risky" comes from the known-updater registry: codex keeps `~/.codex/version.json`, and claude keeps `~/.claude/settings.json`. "Pinned" comes from `brew list --pinned`, bounded at 5s. The halt detail gives `brew pin <bin>` and the deliberate-update procedure (`brew unpin`, `brew upgrade`, `brew pin`, never mid-batch). A CLI with no registry entry is not checked. New self-updaters are added to the registry as incidents reveal them.
- **Version inventory.** `<bin> --version` runs for every distinct driver binary (`resolved.drivers()`), bounded at 5s each. The first `M.N` or `M.N.P` token is kept, and a binary whose probe fails or prints no token is left out. The map lands in `Result.CLIVersions` (`cli_versions` in the JSON) and in `.evolve/cli-versions.json`, which the next batch's drift check compares against.
- **Wire format.** Levels serialize as the tokens `pass`, `warn` and `halt` (`unknown` when out of range), so the persisted file is self-describing. An empty `Detail` is omitted. `Summary` is the human block printed to stderr, with each check's detail indented beneath it.

## Invariants

- **Ambiguity warns, and only confirmed risk halts.** A probe that leaves a fact unverified yields Warn: never a silent Pass, which would hide the gap, and never a Halt, which would let a transient fault bench a ready boot. This covers a failed fetch or rev-list in `base-divergence`, a failed pin listing, an unresolvable home dir, and unreadable or unparsable claude settings. Pinned by `TestCheckBaseDivergence_ProbeErrorWarns`, `TestRun_VersionFreeze_PinProbeError_Warns`, `TestRun_VersionFreeze_EvidenceProbeError_Warns` and `TestDefaultSelfUpdateEvidence_ClaudeAutoUpdatesTrueOrGarbage`. A missing evidence file is absence, not ambiguity.
- **`base-divergence` fetches origin itself.** It compares `HEAD` against the `FETCH_HEAD` its own fetch wrote, because a local `origin/<base>` ref is exactly what is stale in this failure mode. Ahead-only is healthy unpushed work and passes. Malformed `rev-list` output is an error, never a silent 0/0. A non-repo, a detached HEAD or a missing `origin` remote passes with the reason in `Detail`. The whole probe is bounded at 60s. Pinned by the `TestCheckBaseDivergence_*` and `TestDefaultProbe_*` tests.
- **The freeze check covers `*-tmux` drivers only.** The updater runs on the interactive TUI launch, and headless `codex exec` does not run it. Pinned by `TestRun_VersionFreeze_HeadlessOnly_NotChecked`.
- **The pin is a convergent steady state, not a per-cycle toggle.** The probes are read-only, so the check is idempotent. An unpin-on-exit would leak on any kill, OOM or reboot, and `brew pin` is global, so concurrent cycles would race. Pinned by `TestRun_VersionFreeze_Idempotent`.
- **claude's `autoUpdates: false` counts as frozen.** It stops the updater at the source, which is the same steady state as a brew pin. It is also the only freeze available where claude is not brew-installed (the native `~/.local/bin` installer). Without it the brew remedy is impossible there and the halt is permanent. An explicit `true` or an absent key stays risky. Pinned by `TestDefaultSelfUpdateEvidence_ClaudeAutoUpdatesDisabled`.
- **Updater state is assumed to live under the default home dirs.** No `CODEX_HOME`-style override is handled.
- **The real-tmux boot test never touches a shared server.** The package's `TestMain` is `tmuxtest.Main` ([internal-tmuxtest.md](internal-tmuxtest.md)), so `TestIntegration_BridgeBoot_ClaudeTmux` boots claude on its test process's own `evolve-bridge-t<pid>` server, not the shared default `evolve-bridge` one every other test process used to share.
- **The boot orphan sweep is deadline-bound** by `sessionreaper.DefaultReapTimeout`, so a wedged tmux server abandons the kill rather than hanging loop boot. Pinned by `TestPreflight_OrphanReapIsDeadlineBounded`, which also requires the killer to be injectable (`Options.OrphanKill`), since preflight cannot be tested against a real tmux server.
- **A required sandbox fails closed, with the same decision as bridge dispatch.** Both call `sandbox.ConfinementSatisfied`. When a sandbox-enabled profile's host cannot sandbox, the check halts before phase spend, nested session or not: a nested session does not prove the profile's restrictions, and fresh-cycle Build explanation enforcement needs a real filesystem sandbox. Only `EVOLVE_SANDBOX=off` lets the batch run, as a loud UNCONFINED warning. Pinned by `TestRun_HostCapabilities_SandboxWantedButUnavailable_Halts`, `TestRun_HostCapabilities_SandboxWantedNested_FailsClosed` and `TestRun_HostCapabilities_SandboxWantedOptOut_WarnsNotHalts`.
- **The nested-fallback canary proves little, by design.** It samples one write to a sentinel in the project's parent dir, outside the inner sandbox's allow-list. Only a permission error counts as a denial, and even that may be ordinary file permissions. A write that succeeds, or a setup failure such as a missing parent, is unverified. A denial passes, but the message still says profile-specific confinement is unverified, and it never waives the launch-time gate. Pinned by `TestSandboxNestedFallbackCanary` and `TestSandboxCanarySetupFailureIsUnverified`.
- **`overlay-tier-selectors` never halts.** A selector that names no canonical tier still matches its literal token, and the cycle's own `policy.Load` is what refuses a malformed policy, so the check only tells the operator a rule may be silently inert. Pinned by `TestRun_OverlayTierSelectors`.
- **`cli-health` and `phase-routing-warnings` never halt.** The fallback chain exists so that a benched family does not block the batch, and expired benches are canaried per cycle by the loop. A dropped user phase leaves the built-in spine intact. Halting on it would let any unrelated broken `phase.json` block every working deployment. Pinned by `TestCheckCLIHealthWarnsNamedFamilies` and `TestRun_PhaseRoutingWarnings_DoesNotHalt`.
- **`cli-routing` halts only on a table that cannot route.** An error finding is a table the composition root also refuses (`exitRoutingRefused`, exit 2), so the gate halts on it before any spend, with every finding in its detail. A warning finding warns and the batch runs. Pinned by `TestPreflight_CliRoutingHaltsOnAFinding`, `TestPreflight_CliRoutingWarnsOnAWarning` and `TestPreflight_CliRoutingPassesACleanTable`.
- **The gate never blocks a batch on its own tooling.** `defaultPhaseRoutingWarnings` swallows a catalog-load error, matching `DiscoverUserSpecs`' "missing dir, no specs" posture. A disk-probe error skips the low-disk warning and makes the `disk-space` check warn, never halt (the probe is unsupported off darwin and linux).
- **Only a change the boundary updater recorded is expected.** A self-update or a manual install between two boundary updates breaks the chain and still warns, so the drift check keeps seeing the class it was added for (cycle-308). The freeze check is not relaxed by a record at all: it reads pin and updater state, never versions. Pinned by `TestVersionDrift_AChangeTheBoundaryUpdaterRecordedIsExpectedNotDrift`, `TestVersionDrift_AChangeTheBoundaryUpdaterDidNotRecordStillWarns`, `TestVersionDrift_ExpectedAndUnrecordedChangesAreReportedApart`, `TestVersionDrift_AnUnreadableUpdateRecordLeavesEveryChangeAsDrift`, `TestVersionDrift_ASelfUpdateTheBoundarySmokeBootedIsReportedAsSelfUpdatedSmokeOK` and `TestRun_VersionFreeze_ABoundaryUpdateRecordDoesNotUnfreezeASelfUpdater`.
- **A CLI with a manifest off switch is frozen only by that switch.** The shipped agy manifests set `AGY_CLI_DISABLE_AUTO_UPDATE`, so agy passes without a brew pin (it is not brew-installed); a manifest that drops it halts with the manifest remedy. A failed brew listing still turns that halt into the ambiguity warning, as for every risky CLI. Pinned by `TestDefaultSelfUpdateEvidence_AManifestThatSetsItsOffSwitchIsFrozenAtTheSource`, `TestDefaultSelfUpdateEvidence_AManifestThatLeavesItsOffSwitchUnsetIsRisky`, `TestRun_VersionFreeze_TheShippedAgyManifestFreezesAgyWithoutABrewPin` and `TestRun_VersionFreeze_AnAgyManifestWithoutItsOffSwitchHaltsNamingTheManifestFix`.
- **Drift baselines converge.** A first batch with no cache passes and records the baseline. A corrupt cache fails open and is overwritten. The cache is saved on every run, so a stable version stops warning after one batch. Pinned by `TestVersionDrift_NoWarnWhenNoPriorRecord`, `TestVersionDrift_CorruptedCacheFailsOpen` and `TestVersionDrift_UpdatedCacheReflectsCurrentInventory`.
- **The disk-space floor is policy, not a literal.** `disk-space` halts below `policy.json` `preflight.min_free_gib` (default 1 GiB; `Options.MinFreeBytes` 0 takes it) and names `evolve gc`; `host-capabilities` still warns below its 500 MiB literal (`checks.go` is a protected control-plane path). `CheckDiskSpace` is exported so the wave boundary (`cmd/evolve` `diskSpaceHalt`) runs the same check. `statfs` block sizes of zero or less are rejected, so an unchecked cast cannot wrap into a huge "ample disk" value.
- **The disk-free probe has one implementation.** `DiskFreeBytes` exports the same probe, including its stub for platforms without `statfs`, so `evolve gc` can report the disk it released without a second `statfs` wrapper (`TestDiskFreeBytes_MeasuresTheFilesystemHoldingThePath`).
- **External contracts on the source.** `go/acs/cycle2` requires `checks.go` to call `ReapOrphans` and not to contain the text `stale bridge tmux session(s)`. `checks.go` and `drivers.go` are on the integrity surface (`internal/guards/integrity_surface.go`), because they hold the pre-spend required-sandbox halt and the sandbox-enabled profile discovery behind it.

## Findings

- **cycle-258**: a 3-cycle batch churned about 30 minutes before anyone found that the bridge could not boot the CLI (exit 80, `ExitREPLBootTimeout`). The gate and its `bridge-boot` check came from this. `TestIntegration_BridgeBoot_ClaudeTmux` (integration tag) boots a real claude-tmux REPL.
- **cycle-262 D6**: codex's updater ran `brew upgrade` on the TUI launch, printed "Update ran successfully! Please restart Codex." and dropped the REPL to a bare shell, which the bridge nudged for about 20 minutes. The host fix was `brew pin codex`. The `cli-version-freeze` check makes that steady state a verified precondition (ADR-0044 C5). The codex registry entry is the updater-state file from that incident.
- **cycle-297**: claude 2.1.173 self-updated mid-soak and removed the `esc to interrupt` affordance. That broke PaneBusy detection and caused exit 81 in cycles 286, 288, 289 and 291. claude joined the freeze registry. The `autoUpdates: false` native freeze followed once hosts without a brew-installed claude hit a permanent halt.
- **cycle-308**: claude moved from 2.1.173 to 2.1.175 between batches despite `autoUpdates: false` (a staged update applied on boot, which the setting does not gate). `loop-preflight.json` recorded no versions, so the change was invisible. That added the version inventory and the `cli-version-drift` check.
- **2026-10-06, agy self-updated outside any boundary** (1.2.14 → 1.2.16 → 1.2.17) and wave 62's `bridge-boot` halted on `agy-tmux rc=80` with a blank pane, while `evolve doctor live agy-tmux` passed a minute later. agy was outside the freeze registry. agy's launch-time updater and its off switch, `AGY_CLI_DISABLE_AUTO_UPDATE`, were found read-only in the installed binary; the agy manifests now set it, and the freeze check reads it from the manifest ([internal-cliupdate.md](internal-cliupdate.md) Findings).
- **cycle-270**: fault localization found that `bootRCName` reported every unrecognized exit code as a bare "boot failure", so rc=42 and rc=99 looked the same. The default branch now carries the number, pinned by `TestBootRCName_DefaultBranch_IncludesExitCode`.
- **wave 62 and the wave 67 boundary (2026-10-06): agy's first launch after an idle period can miss the 60 s REPL budget, and the next launch boots.** In wave 62 the `bridge-boot` halt above came first and a live doctor boot passed a minute later. At the wave 67 boundary the boundary updater's `doctor live agy-tmux` timed out, and this check's agy-claude-tmux and agy-tmux boots 80 s later both booted. The probes that run first now retry one bare boot timeout for agy (see *Bridge boot*).
- **wave 59 (2026-10-05)**: the `bridge-boot` check halted the loop because claude's folder-trust dialog took a dropped Down and an Enter on "No, exit" ([incident](../../incidents/2026-09-01-claude-2252-trust-default-flip.md), [ADR-0118](../adr/0118-confirm-a-menu-only-on-the-observed-choice.md)). A boot dialog the auto-responder cannot move now ends the smoke boot within seconds, still as `ExitREPLBootTimeout` (rc 80) so the boot-failure bench counts it, with the bridge's `FAIL` line naming the rule in the loop log; `bootRCName` is unchanged.
- **cycle-283**: codex was quota-walled all night and only the per-phase dispatch trail showed it. The `cli-health` check surfaces active benches at batch start.
- **cycle-591**: phasespec's dropped or invalid user-phase warnings were only printed to stderr by the CLI and dispatch callers, then discarded. An operator with a typo in a `phase.json` got a silently missing phase and no batch-start signal. That added the `phase-routing-warnings` check.
- **cycle-769**: the boot orphan sweep ran under `context.Background()`, so a wedged tmux server hung loop boot silently, while the per-cycle sweep (`orphanGCTimeout` in `cmd_loop_control.go`) was already bounded.
- **cycle-969 / cycle-1189**: lanes cut from a stale local base failed at push with `GIT_PUSH_REJECTED` after the batch's work was spent. That added the `base-divergence` check (ADR-0081).
- **Stale-session glob warning replaced.** An earlier server-wide glob warning for leftover `evolve-bridge-*` tmux sessions could enumerate live peers' sessions and could not reap safely. The lease-aware `sessionreaper.ReapOrphans` sweep replaced it; `go/acs/cycle2` pins the removal.
- **The opt-out cell once diverged.** Before both sites shared `sandbox.ConfinementSatisfied`, `EVOLVE_SANDBOX=off` made bridge dispatch run while preflight blocked. `TestRun_HostCapabilities_SandboxWantedOptOut_WarnsNotHalts` pins the parity.
