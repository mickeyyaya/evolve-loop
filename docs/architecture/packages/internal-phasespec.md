# internal/phasespec

> The registry itself is [phase-registry.json](../phase-registry.json). The operator guide is [user-defined-phases.md](../user-defined-phases.md), and the plugin design (metadata, multi-root discovery, the phase inventory) is [phase-plugin-system.md](../phase-plugin-system.md). Transition fields: [ADR-0058](../adr/0058-config-drive-transition-kernel.md) and [ADR-0060](../adr/0060-data-driven-transition-kernel.md). Declared deliverables: [ADR-0100](../adr/0100-declared-deliverables-gate.md). Judgment verdicts: [ADR-0091](../adr/0091-judgment-verdict-from-sentinel.md). ## Purpose

`internal/phasespec` is the one full parser of phase definitions. It reads the `phases[]` array of `docs/architecture/phase-registry.json` and every operator overlay at `<root>/<name>/phase.json`. It validates and merges them into a `Catalog` of `PhaseSpec` values, and it splices valid user phases into the routing order. A `PhaseSpec` is data only. Its methods do nothing but supply defaults.

## Design

- **Layering.** The package imports `config` (for `RoutingBlock` and `Condition`), `profiles`, `policy` and the standard library. It must not import `core`, because `core` imports it: a `PhaseRequest` carries a `PhaseSpec`. That is why `canonicalVerdicts` copies core's verdict set instead of importing it. `specrunner` imports phasespec too, so the repo-catalog guard copies specrunner's `verdict_from_sentinel` stage words for the same reason.
- **Two sources, two failure policies.** The registry is a required contract. `Load` turns an unreadable or malformed file, or a spec that fails `ValidateActivatingFields` or `ValidateOutputsPartition`, into a hard error. Overlays are opt-in, so discovery fails open: a missing root yields nothing, a directory without `phase.json` is not a phase, and a malformed `phase.json` is skipped with a warning. One broken overlay must not break the catalog. Duplicate registry names keep the first entry, and an empty name is skipped.
- **`MergedCatalog` is the one loader.** Every consumer resolves phases through it: the CLI subcommands, the agent self-check, the host contract gate, the salvage rung and the runner's reconcile-on-timeout default. It once lived in `cmd/evolve`, which left the runner resolving phases through a second, built-in-only policy. The sequence is `Load`, then `DiscoverUserSpecsFromRoots(Roots(root))`, then `ClampDiscoveredSpecs`, then `Merge`. A missing registry is an error, and the caller chooses how to degrade (the CLI and `VerifyCatalogAware` fall back to built-in-only resolution).
- **Discovery roots.** `Roots` reads `paths.phase_roots` from `.evolve/policy.json`. It is colon-separated; relative entries join the project root and absolute ones are kept as they are. It defaults to `.evolve/phases`, which is conventionally first, so the project-local root can shadow a plugin phase: across roots the left-most wins, with a shadowing warning. The policy key replaced the old `EVOLVE_PHASE_ROOTS` environment read. Within one root, specs come back sorted by directory name for determinism.
- **Discovery-time defaults.** A spec whose `phase.json` has no name takes its directory name, but only if that name passes the kebab-case floor. `ApplyArchetypeDefaults` gives an evaluate-archetype overlay `optional: true`, `prompt_context: [goal]`, `fail_if_empty` and `verdict_on_pass: PASS`. It runs only at discovery, never in `Load`, because built-in evaluate phases such as `audit` are required and must not be forced optional. Plan and control overlays get no implicit defaults.
- **Registrar-parity clamp.** Two paths admit a user phase. The registrar mint path (`phaseregistrar.Register`) holds the invariant *writes_source ⟹ sandboxed dispatch profile* by construction: it forces `optional: true` and persists a sandbox-enabled profile. Discovery takes any on-disk `phase.json` (smuggled residue, a git merge, a typo), so `ClampDiscoveredSpecs` holds the invariant by verification. It forces `optional: true`, and it keeps `writes_source` only when the spec's dispatch profile exists with the sandbox enabled and the repo writable. The profile name is `AgentName()` without its `evolve-` prefix, which is how the runner resolves it. `SandboxedProfilePredicate` reads the on-disk profile deliberately: it is the same file the runner resolves at dispatch, so this is dispatch parity, not a repo-contract scan. `phaseregistrar`'s cross-binding test pins the two styles against each other: a registrar-minted writer must pass `SandboxedProfilePredicate` over its own persisted profile.
- **Merge.** `Merge` returns a new catalog and never mutates the receiver. Built-ins win a name clash, with one exception: an overlay of an *optional* built-in is adopted in place. `memo` is the case in point: it is declared optional in the registry and carries its routing only in the overlay. A non-optional clash is dropped with a warning. User specs append in input order.
- **Routing splice.** `ApplyUserRouting` validates each spec with `ValidateUserSpecWithCatalog`, then registers its `insert_when` triggers and marks it content-routed. An invalid spec is skipped with a warning, so the safety floor holds at the wiring seam and an invalid spec never becomes a routing candidate. Placement is a fixpoint over the batch, because discovery order is alphabetical and an anchor may be a later batch-mate. When a pass strands, a spec whose anchor names no batch-mate is force-placed before `audit` with a warning. A spec anchored to a stuck batch-mate is held so it lands after that anchor. A pure anchor cycle force-places one dependency target (warned) and lets the rest follow it. An overlay already in the order never defers and never warns. The incident record has the full reasoning.
- **Advisor-facing metadata.** `description`, `when_to_use` and `categories` feed the phase inventory and the advisor's SELECT cards. Absence degrades to a name-only card. `knownCategories` mirrors the advisor's goal-type classification: the recipe table in `agents/evolve-router.md` and [domain-phase-catalog.md](../domain-phase-catalog.md) §3. An unknown category is a lint warning (`UnknownCategories`), never a load or validation failure, because metadata must not block execution. `allowed_clis` and `model_tier_envelope` are the phase's own dispatch guardrails; `router.PhaseCard` mirrors them so the advisor proposes a CLI and tier within them.
- **Menu membership.** `catalog` decides only whether the phase gets a card on the advisor's SELECT menu. It does not affect installation, routing, dispatch by an explicit plan, or minting. The measurement that motivated it and the operator rules are in [user-defined-phases.md](../user-defined-phases.md#staying-installed-without-crowding-the-menu-catalog).
- **Transition fields.** `on_pass`/`on_fail`, `branching_strategy`, `gate`, `recovery` and `early_exit` config-drive the transition kernel. Each has a literal fallback when absent, so a registry that omits one behaves as before. Config selects among edges and the hardcoded legality graph constrains them, so a recovery target is still checked at the call site. The decision policy (failure-adapter consultation, signal parsing) and the rule that a ship-intended cycle never exits early stay in Go. `ValidateActivatingFields` checks shape only: a known strategy, and `on_pass`/`on_fail` declared as a pair, since `Next` consults them only when both are set. Requiring a field is the registry guard's job.
- **Effects.** `effects` names lifecycle effects a persona performs outside its workspace (triage's `inbox-claim`), each bound to one deterministic check in the declared-deliverables gate. A user phase may declare them, because they only add checks and loosen nothing.
- **`native` kind.** `kind: native` dispatches to an in-process Go phase implementation selected per phase name, not a REPL boot. `command` is reserved and rejected.
- **Test helpers.** `TrackedPhaseDirs` and `TrackedUserPhaseNames` are exported from `tracked_realtree_test.go` (the `export_test.go` idiom), because callers span `package phasespec` and the external `phasespec_test` package. Every real-tree scan in the package derives its iteration set from them. White-box tests cannot import `go/test/fixtures`, which transitively imports `core`, so they keep local helpers such as `writeUserPhase` and `writeRegistry`.

## Invariants

- **Transition-activating fields are built-in only.** `DiscoverUserSpecs` strips `on_pass`, `on_fail` and `branching_strategy` from every overlay, with a warning, at the one point where provenance is known. An overlay can never inject a verdict, history or signal branch into the kernel (ADR-0058). Pinned by `TestDiscoverUserSpecs_StripsActivatingFields`.
- **A user phase is always optional.** It can never displace or satisfy the build→audit→ship spine. `ValidateUserSpec` rejects a non-optional spec, and `ClampDiscoveredSpecs` forces discovered specs optional. Pinned by `TestClampDiscoveredSpecs_KeepsVerifiedWriterAndForcesOptional` and `TestApplyUserRouting_SkipsInvalid`.
- **The optional-built-in exemption reads the built-in's flag, never the overlay's.** `isOptionalBuiltinName` scopes both the single-word naming exemption and `Merge`'s adoption path. Otherwise an overlay named `audit` that marks itself optional would hijack a mandatory spine phase's slot. Pinned by `TestValidateUserSpecWithCatalog_RejectsNonOptionalBuiltinNameOverlay` and `TestCatalog_Merge_NonOptionalBuiltinClashStillDropped`.
- **`writes_source` needs a sandboxed, writable dispatch profile.** A read-only sandbox grants eligibility without capability and would only produce confusing mid-cycle write failures, so it does not verify. A nil predicate fails closed. Every strip or force is a warning, because a silent strip would hide the one signal an operator needs to notice a smuggled writer. Pinned by the `clamp_test.go` tests.
- **Every admission seam clamps.** Listing and lint consumers report the same `writes_source` the dispatch path enforces, so they never disagree about eligibility. The code keeps a one-line why in `MergedCatalog`.
- **Names are safe path components.** `nameRE` (lowercase kebab-case) guards the phase name, the directory-name default and the `agent` field. The agent name becomes a persona filename under `agents/` in `phases create`, so a crafted `../../x` must never escape that directory. Pinned by `TestValidateUserSpec` (the traversal case) and `TestDiscoverUserSpecs_BadDirNameNoName`.
- **Two-tier naming.** User and optional phase names are multi-word kebab-case (`twoTierNameRE`, letters only). Single-word names are reserved for built-ins. Pinned by `TestBugRepro_Cycle229_TwoTierNamingMissing` and the `two_tier_naming_*` tests.
- **Every secondary output is classified exactly once.** The partition runs on the registry and on overlays alike, because an overlay replaces a built-in's spec wholesale (ADR-0100). Pinned by `TestValidateOutputsPartition` and `TestValidateUserSpec_EnforcesOutputsPartition`.
- **Role inference never yields an unmatchable Role.** The floor and the advisor catalog both read `RoleOrDefault`. A mis-cased or padded explicit archetype is normalized, and an unrecognized one falls through to name inference. An unknown name is Plan, the safest "needs scoping" bucket. The JSON key is `archetype` because the registry's `role` key names the agent profile. Pinned by `TestRoleOrDefault`.
- **Only the exact word `on-demand` declines a menu slot.** An unknown `catalog` word is a loud authoring-time failure through `KnownCatalogWord`, because it would otherwise leave the phase on the menu, the opposite of its author's intent. Pinned by `TestKnownCatalogWord_AcceptsOnlyTheTwoDefinedWords`.
- **Real-tree scans bind only git-tracked phase dirs.** The runtime mints untracked phase dirs and profile stubs into the live tree, and a scan that binds them reds on state that can never reach a CI checkout ([ADR-0084](../adr/0084-gate-integrity-invariants.md) I1). An unusable git state returns nil, meaning bind everything, the stricter fallback. An unexpectedly empty set on a tree with phase dirs also falls back, since going dark would unbind the gates. Pinned by `TestTrackedPhaseDirs_FixtureRepo` and `TestTrackedPhaseDirs_RealTreeExcludesUntrackedDecoy`.
- **`fail_if_signal` must not ship in a tracked phase.** Until a signal bus exists, `specrunner.EvaluateClassify` fails any phase that declares it. `TestRepoPhaseCatalog_NoInertFailIfSignal` moves that invariant to CI. Delete the test when the signal bus lands and the gate becomes evaluable.
- **The metadata allowlist only shrinks.** `metadataAllowlist` lists optional phases that still lack `when_to_use` and `description` ([ADR-0052](../adr/0052-advisor-maximization.md) WS5). A new optional phase without metadata fails, and so does a stale allowlist entry.

## Findings

- **cycle-229/230**: `ValidateUserSpec` accepted single-word user phase names, because it checked only `nameRE`. That added `twoTierNameRE`. The amplification tests pinned that digits and non-hyphen separators are rejected, that three or more words are accepted, and that `scanner-` (which passes `nameRE`) is caught.
- **cycle-263**: 15 catalog phases shipped with a `fail_if_signal` block, which the cycle-241 declared-semantics rule makes a hard FAIL. The rejection fired mid-cycle on first router insertion: `adversarial-review` wrote a clean PASS report, it was recorded as FAIL, and the cycle died. The invariant was right but enforced at the wrong boundary, so `repo_phaseconfigs_test.go` moved it to CI, and every `fail_if_signal` block was stripped from the tracked phases. `TestRepoPhaseCatalog_VerdictFromSentinelStageIsKnown` applies the same tripwire to `verdict_from_sentinel` stage words (ADR-0091).
- **cycle-547**: the built-in optional `memo` phase could never route. Its activation overlay has a single-word name, the two-tier floor rejected it, and about 150 PASS cycles produced no `memo.md` or `carryover-todos.json`. `ValidateUserSpecWithCatalog` and the three-argument `ApplyUserRouting` exempted overlays of optional built-ins.
- **cycle-554**: the cycle-547 rollout missed one call site. `Catalog.Merge` still dropped the memo overlay as a built-in clash, so every consumer that resolved memo through the merged catalog saw a hollow stub with no agent or classify rules. Renaming the registry entry was rejected in favor of extending the same `isOptionalBuiltinName` exemption into `Merge`.
- **cycle-1550**: an anchor to an alphabetically later batch-mate silently took the before-audit fallback, and a red-first Evaluate phase ran after build. See [the incident](../../incidents/2026-08-24-anchor-order-splice-misslot.md) for the fixpoint and its regression pins.
- **ADR-0073 residual 1**: the discovery path ran no registrar clamp. An on-disk spec claiming `writes_source: true` gained worktree-write eligibility (`core.worktreePhase` reads the spec) with no sandbox anywhere, because `specrunner` has no sandbox plumbing. `ClampDiscoveredSpecs` closed that path.
- **Bash-to-Go migration**: `userphases_validate_test.go` ports the eight live bash phase-validation suites into one table. The bash rows asserting `fail_if_signal` keys, and `smell-scan`'s literal `fail_if_empty` (applied by the archetype defaults at discovery, not written in its `phase.json`), were stale against the tree and were deliberately not ported. The negative corruption probes are covered by the `ValidateUserSpec` unit tests.
- **ADR-0097**: `bug-reproduction` and `test-amplification` write into the worktree but did not declare `writes_source`, so the fence would have reverted their deliverables. `TestUserSpecs_SourceWritersDeclareWritesSource` pins both.
