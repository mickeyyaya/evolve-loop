# internal/phases/triage

## Purpose

`internal/phases/triage` implements the cycle-scope task-selection phase: it composes the triage prompt (inbox batches, premise drift, carry-forward candidates, fleet scope, recent outcomes), dispatches through `internal/phases/runner`'s `BaseRunner`, and classifies the agent's `triage-report.md` and `triage-decision.json` into a verdict. It also performs several deterministic host effects — protected-surface routing and unified-commitment validation — so the LLM's selection judgment stays bounded by mechanical checks the host, not the agent, is trusted to run.

## Design

- **Skip semantics.** `EVOLVE_TRIAGE_DISABLE=1` skips the phase (`SKIPPED`, `NextPhase=tdd`, no bridge call). `ShouldSkip` delegates to `router.PolicyForProject` (`config.Load` is the sole reader of the env var) rather than reading the flag itself.
- **Verdict mapping.** Empty artifact → FAIL. Missing `## top_n` heading → FAIL. Empty `## top_n` plus an explicit `triage-decision.json` `top_n:[]` → PASS (a corroborated planned no-work). `## top_n` with no items and no explicit empty decision → FAIL. `## top_n` with one or more list items → PASS.
- **Two independent protected-surface checks.** The inbox partition (`inboxBatchesSection`, pinned by `console_routed_prompt_test.go`) excludes a protected item from the prompt before it can be offered. `Classify`'s admission check (`protected_route.go`, pinned by `protected_surface_admission_test.go`) separately refuses or routes a committed top_n card naming a protected path — needed because a card can be authored by the LLM itself, from the scout or a fleet todo, without ever passing through the inbox screen.
- **`filesFieldRE`** matches a top_n card's `files=` field in either the brace-delimited encoding `inboxbatch.RenderMarkdown` emits (`files={a;b;c}`) or the bare, comma-terminated encoding real cycle output also uses (`files=a;b;c`).
- **`routeProtectedCards`** moves each protected top_n card from the decision's `top_n` into `escalate_block` with a console-route reason, preserving every other key in the decision document, so a routed card is answered (never committed) without disturbing the rest of triage's decision.
- **`carryforward_candidates_test.go`** exists only to name and exercise `CarryforwardCandidatesSection` from within this package, so the repo-wide apicover unnamed-export gate counts it as covered; the full behavioral suite (landability filtering, `ComposePrompt` wiring) lives in `go/acs/cycle1325/predicates_test.go`.
- **`processUnifiedCommitment`** validates the optional LLM-authored `unified_commitment` claim and writes only its deterministic projection into the decision; an invalid claim is rejected (its warning, and any prior projection or campaign plan, are cleared) but stays visible in the decision for forensics — it never influences routing.
- **Premise drift** (`premise_drift.go`) gathers, for each fleet-scoped inbox item, the git evidence a premise re-check needs: commits since filing that name the item's id, commits that touched its declared paths or only its package, and declared paths no longer at HEAD. Drift is evidence to re-verify, not a verdict — most drifted items still hold; dropping a genuinely stale item at triage avoids costing a build, an audit and a repair round on a premise that no longer holds.
- **Inbox batch grouping is deterministic** (`internal/inboxbatch`); triage's LLM only judges which whole batch to pick, never the grouping itself (Core Rule 5). `ComposePrompt` renders the batch section after the earlier stable-prefix lines (cache-friendly ordering), and an empty, missing or unreadable inbox renders nothing — fail-open, since a broken backlog must not block triage.
- **The carry-forward candidate filter** (`CarryforwardCandidatesSection`) is a deterministic, zero-LLM landability screen: it lists local `cycle-*` branches under a base that `core.CarryforwardCandidateLandable` reports landable (a real 3-way `git merge-tree` dry-run, not already superseded). It probes branches newest-committed-first and caps the sweep at `carryforwardCandidatesMaxBranches`, so a truncation drops the stalest candidates, never the freshest, and surfaces itself via a trailing `(partial: N of M branches probed)` line rather than staying silent. It renders last, using `"main"` as the base to match every other production caller of the carryforward filter family.
- **`ComposePrompt`'s context for `CarryforwardCandidatesSection`** is bounded by `carryforwardCandidatesTimeout`, sized for `carryforwardCandidatesMaxBranches` branches of `git merge-tree` work each — the section must never stall triage's critical path.
- **`recent_outcomes`.** The orchestrator seeds `Context["recent_outcomes"]` with the recent-outcomes digest at cycle start; `ComposePrompt` appends it after the stable prefix lines to keep that prefix cache-friendly, and an absent or empty key renders nothing (byte-identical prompt).
- **`deliverable_kind_default` / `deliverable_root`.** Triage's own `deliverable_kind:` header is the authoritative kind for a task that declares none, so `ComposePrompt` renders the project's default deliverable kind (seeded from `.evolve/domain.json`) and configured deliverable root when the orchestrator supplies them (ADR-0099). Absent context keeps the prompt byte-identical.
- **`fleet_scope`.** Under `evolve fleet --plan`, `ComposePrompt` steers triage's selection to only the ids in `runner.LaneScope`'s assigned scope, so concurrent cycles never pick work touching the same files (ADR-0049 decision E). A control character in an advisor-authored id is sanitized before it reaches the prompt, so it cannot forge a new context bullet.
- **Typed phase I/O.** At `phaseio` enforce, `ComposePrompt` reads `carryover_summary` and `fleet_scope` from the typed `req.Input.CycleInputs()` envelope instead of the legacy `Context` map; below enforce the two sources render byte-identical prompts (ADR-0050 §3.10).
- **Every refusal `Classify` raises itself** (not the agent's verdict) carries a stable `Diagnostic.Code`, so the C1 record and a FAIL closeout can tell an operator-owned refusal from an ordinary agent failure without regexing prose. See [the triage-refusal poison-loop incident](../../incidents/2026-09-14-triage-refusal-poison-loop.md).

## Invariants

- An empty `## top_n` section is incomplete unless corroborated: only an explicit `triage-decision.json` `top_n:[]` array marks it as a genuine planned no-work; `router.Digest` treats a null, malformed or missing commitment as unknown, so it never substitutes for the explicit empty array. Pinned by `TestRun_EmptyTopN_FAIL` and `TestRun_ExplicitEmptyDecisionIsPlannedNoWork`.
- The inbox partition that excludes protected or forbidden items from the prompt only covers items sourced from `.evolve/inbox`; a top_n card can also come from the scout or a fleet todo, so `Classify` re-checks every card's `files=` field against the lane predicate independently. Pinned by `TestTriageClassify_RefusesATopNCardNamingAPathTheLanePredicateForbids` and the `protected_surface_admission_test.go` suite.
- `EvaluateClassify`'s `RequireSections` check matches a heading by prefix, so a report with `## top_n_extra` satisfies it; `Classify`'s own `topNHeadingRE` requires a word boundary immediately after the canonical heading, so `## top_n_extra` never has its body extracted and the report still FAILs overall — the two checkers disagree by design, and only the stricter one governs the verdict. Pinned by `TestRun_TopNPrefixOnlyHeading_StillFAIL`.
- `carryforwardCandidatesMaxBranches` caps how many local `cycle-*` branches `CarryforwardCandidatesSection` probes with `core.CarryforwardCandidateLandable` (each probe is a real `git merge-tree` dry-run, not free); branches are examined newest-committed-first so the cap drops the stalest candidates, never the freshest. Pinned by `TestCarryforwardCandidatesSection_NewestCommittedFirst` and `TestCarryforwardCandidatesSection_CapsBranchesAndSurfacesTruncation`.
- A commit that names an item's id includes the ship commit that consumed it: every ship commit's `## Actual diff` footer (`internal/phases/ship/gitops.go`) lists the consumed inbox file, so id-naming can be found even outside the item's declared packages. The match requires a word boundary on both sides of the id, so `warn-gap` never matches `warn-gap-v2` or `xwarn-gap`, while a timestamp-prefixed filename like `...00Z-warn-gap.json` still matches. Pinned by `TestPremiseDriftSection_ACommitNamingTheIdIsTheStrongestSignal`.
- Drift evidence lists commits by committer date (the field git's `--since` filters on and displays), not author date — a rebased commit's older author date must not look like pre-filing evidence. Pinned by `TestPremiseDriftSection_ShowsCommitterDatesAndSkipsTreeWidePackages`.
- Package-only drift commits are found via each declared file's directory, but a directory shallower than two path segments (`go/`, `docs/`) is skipped — including it would put the whole tree's churn in front of triage. Pinned by `TestPremiseDriftSection_ShowsCommitterDatesAndSkipsTreeWidePackages`.
- A declared path that escapes the repository (absolute, or a leading `..` once cleaned) is reported, never queried: git rejects an out-of-repo pathspec, which would blank the whole item's evidence. Pinned by `TestPremiseDriftSection_TextIsPromptSafe`.
- Every drift-gathering helper (`commitsSince`, `declaredDrift`, `vanishedAtHEAD`) reports unavailable (`ok=false`) only when git failed or the deadline elapsed — never for a legitimately empty result — so the caller renders a visible "drift unavailable" line instead of silently treating a failure as "no drift". Pinned by `TestPremiseDriftSection_SilentWithoutDriftVisibleWhenUnavailable`.

## Findings

- **cycle 1691** ([incident](../../incidents/2026-09-26-stale-premise-reached-build.md)): a lane committed an item whose premise had been unreachable for 17 days; nothing re-checked the premise before the cycle was spent on it. `premise_drift.go` gathers that evidence at triage so a stale item can be dropped there instead of costing a build, an audit and a repair round.
- **cycle 1343 / cycle 1356**: an uncapped local `cycle-*` branch sweep in the carry-forward candidate filter grows linearly with the branch set; unbounded, it was measured at 150+ branches and 10+ seconds of blocking git work in front of triage's critical path, and a prior disposition's claim that the sweep was already bounded was false (`context.Background()` was still live, nothing capped it). That produced `carryforwardCandidatesTimeout` and `carryforwardCandidatesMaxBranches`.
- **cycle 962 / cycle 1325 / cycle 826**: a deterministic, zero-LLM landability screen (`core.CarryforwardCandidateLandable`) existed since cycle 962 but was never wired into triage's own candidate-selection path; the LLM kept picking from raw `git merge-tree`'s non-3-way form and mis-selected an already-superseded branch at cycle 826. `CarryforwardCandidatesSection` wires the existing filter into the triage prompt.
- **F4** ([review](../../operations/batch-integrity-review-2026-08-04.md)): a top_n card the LLM authors itself, from the scout or a fleet todo, never passes through the inbox's protected-surface screen; a card naming a protected path sailed through `Classify` before its own commit-time admission check existed.
