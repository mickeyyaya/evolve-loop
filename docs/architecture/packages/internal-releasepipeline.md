# internal/releasepipeline

## Purpose

`internal/releasepipeline` is the driver behind `evolve release X.Y.Z`: one entry point, `Run`, that composes the release libraries (`releasepreflight`, `changeloggen`, `versionbump`, `releaseconsistency`, `marketplacepoll`, `rollback`), rebuilds the tracked `go/evolve`, ships through `evolve ship --class release`, and proves the published release self-consistent. Every step is a function field of `Steps`, so tests drive the orchestration with stubs and production gets `DefaultSteps()`.

## Design

- **Lifecycle.** `Run` executes, in order: `full-dry-run-preflight` (only under `RequirePreflight`), `preflight`, `changelog-gen` over `<FromTag>..HEAD`, `version-bump`, `rebuild-binary`, `release-sh-check`, `ship`, `marketplace-poll`, `release-verify`. The order is pinned by `TestRun_HappyPath`, `TestRun_RebuildBinaryStepInvokedBeforeShip` and `TestRun_ReleaseVerify_RunsAfterPollWithShipSHA`.
- **Three stages, three sentinels.** `newReleaseRun` does the setup (validate the semver target, resolve the changelog range, resolve the clock, overlay step defaults, log the banner, open the journal), then `prePublish`, `ship` and `postPublish` run. Each stage owns one sentinel: `ErrPrePublishFailed`, `ErrShipFailed`, `ErrPostPublishFailed`. `internal/cli/opscmd` (`releasePipelineExitCode`) maps them to exit codes 1, 2 and 3; 0 is success and 10 is an argument error the cmd layer detects itself. Ship and post-publish are separate methods rather than table entries because each carries a different sentinel.
- **The Result is returned even when setup fails.** `newReleaseRun` returns its object on the two setup failures (non-semver target, journal init), so the caller gets a `Result` seeded with `Target` (`TestResult_RunBadTargetReturnsSeededResult`).
- **Nil step fields fall back to the defaults.** `applyDefaultSteps` replaces each nil `Steps` field with its `DefaultSteps()` implementation. When the caller leaves `Steps.Preflight` nil, `resolveSteps` wraps the default preflight in a closure that carries `Options.StrictPass` (a WARN verdict counts as a FAIL); a caller that injects its own `Preflight` owns strict mode itself. `DefaultSteps` is for production; tests inject stubs.
- **The pre-publish helper keeps two names.** `runPrePublishStep(journalName, errLabel, …)` records the journal and `Result` ledgers under `journalName` and wraps the error with `errLabel`. For two steps they differ on purpose (`full-dry-run-preflight` / `full-dry-run preflight`, `release-sh-check` / `release.sh consistency`); the label is what `evolve release` prints and the operator's only clue to which step broke.
- **Dry run.** `preflight`, `changelog-gen` and `version-bump` receive `DryRun` and decide for themselves; `rebuild-binary`, `release-sh-check` and `ship` are journaled `skipped-dry-run` and not performed. `ship` returns `shipped=false` after logging `DRY RUN COMPLETE`, and `Run` then returns success without running post-publish. `defaultRebuildBinary` also returns nil on `dryRun`, in case it is called directly.
- **Journal.** A live run writes `.evolve/release-journal/<version>-<UTC ts>.json` (or under `Options.JournalDir`), one file per attempt; a dry run writes `release-pipeline-dryrun-<version>.json` in `JournalDir` or `os.TempDir()`, overwritten per version. The schema (`version`, `tag`, `commit_sha`, `branch`, `release_url`, `started_at`, `completed_at`, `steps`) is what `rollback.ReadJournal` reads to know what to undo. Every `appendStep` and `setJournalField` rewrites the file atomically (temp file plus rename); their write errors are ignored after `initJournal` succeeds.
- **FromTag.** An empty `Options.FromTag` resolves to `git describe --tags --abbrev=0`; a tagless repo falls back to the initial commit (`git rev-list --max-parents=0 HEAD`), and a non-git dir leaves it empty.
- **Rebuild binary.** `defaultRebuildBinary` runs `go build -ldflags … -o evolve ./cmd/evolve` in `<repoRoot>/go`, stamping `pkg/version.version=<target>`, `commit` (short HEAD) and `builtAt`, so the tracked `go/evolve` (the marketplace-installed binary) matches the version-bumped source and self-reports the target; `release-verify` asserts exactly that. Without the step a release ships source while the tracked binary stays at the previous build. The ship step (`--class release`) stages the rebuilt binary.
- **Consistency check.** `defaultReleaseSh` calls the `releaseconsistency` library (the step keeps its `release-sh-check` name). It refreshes no plugin cache; `marketplace-poll` owns cache propagation.
- **Ship.** `defaultShip` runs `<evolve> ship --class release "release: v<target>"` with `EVOLVE_SHIP_RELEASE_NOTES` (the extracted notes) and `EVOLVE_SHIP_AUTO_CONFIRM=1`, because the pipeline is non-interactive, and returns the new `HEAD`. `resolveEvolveBin` tries `EVOLVE_GO_BIN` (if executable), `<repoRoot>/go/bin/evolve` (the gitignored local build), `<repoRoot>/go/evolve` (what `rebuild-binary` just produced) and then `evolve` on `PATH`. The tracked path is required: on a host with no prior `make build`, ship must find the binary the previous step built (`TestResolveEvolveBin_TrackedGoEvolve`); the local build wins when both exist (`TestResolveEvolveBin_RepoBinBeatsTrackedGoEvolve`).
- **Release notes.** `extractReleaseNotes` takes the `CHANGELOG.md` block between `## [<target>]` and the next `## [` heading. A missing or empty entry yields empty notes: ship proceeds without notes and no lone Fingerprints section is emitted. A non-empty body gets `fingerprintsSection` appended: static text pointing corporate operators at the universal `evolve_darwin_all.tar.gz` and the `checksums.txt` asset, because goreleaser computes the SHA256s after the notes exist.
- **Release class banner.** `releaseNotes` prepends a banner from `releaseClassBanner` to non-empty notes (`TestReleaseNotes_BannerOnlyWhenNotesExist`). A release is a `binary-release` when `go/` or `.goreleaser.yml` changed since the previous tag (a new macOS fingerprint that needs a corporate approval) and a `config-release` otherwise (the fingerprint is byte-identical to a prior version). `classifyRelease` is pure behind the `goChangedProbe` seam; for a config-release it walks older tags (`gitOlderTags`, newest first) back to the newest tag that changed the binary and names it as `SinceVersion`, or the earliest tag when none did. The first release (no previous tag) is a binary-release. See `docs/operations/corporate-deployment.md` for the operator side.
- **Post-publish failure rolls back.** `marketplace-poll` and `release-verify` both fail through `failPostPublish`, so their rollback semantics cannot drift: record the failure, stamp `completed_at`, run `Steps.Rollback` unless `NoRollback`, capture a rollback error in `Result.RollbackErr`, and return `ErrPostPublishFailed`. After the ship, a failure is recoverable only by rolling back.
- **Release verify.** `defaultReleaseVerify` is the terminal self-consistency proof: sha256 of the on-disk `go/evolve` equals the blob at `<commitSHA>:go/evolve`; `.evolve/state.json` `expected_ship_sha` is re-pinned to that blob (with `expected_ship_version`) when stale, because releases never pass through the cycle-class post-cycle re-pin, and a missing or malformed `state.json` is left alone; `go/evolve --version` contains the target; and the local tag `v<target>` exists at the release commit, created when absent because `gh release create` tags remote-only.
- **GitHub CI is not checked.** The pipeline is self-contained and gh-free (headless and cron-safe), so a green pipeline does not imply a green `required CI` workflow on the pushed commit. `complete` prints a NOTE saying so (`TestRun_EmitsCINotVerifiedAdvisory`); CI gating lives in the `/evo:publish` skill.
- **Full-dry-run preflight.** `defaultFullDryRunPreflight` runs the Go-native `releasepreflight` with `dryRun=true` (mutates nothing), `skipTests=true` (the real suite runs at the step-1 preflight) and `strictPass=true` (at least as strict as step 1). It never shells out to a script (`TestDefaultFullDryRunPreflight_NoDeadScript`).
- **Bridges.** `bridges.go` calls each library in-process. `runChangelogGenLib` is idempotent: a `CHANGELOG.md` that already has the `[target]` entry is preserved and nothing is written. `runMarketplacePollLib` polls every 15 s; the default marketplace dir is `~/.claude/plugins/marketplaces/evo`.

## Invariants

- **Classification runs before the ship commits.** `rebuild-binary` leaves `go/evolve` rewritten and uncommitted, and `git diff <prevTag>..HEAD` compares committed trees, so classifying after the commit would make every release a binary-release. `ship` computes the notes before calling `Steps.Ship`; no test pins this yet (a one-line why stays at the call site).
- **Classification fails closed.** A git error yields the `unavailable` banner, which tells the operator to assume a new fingerprint that needs approval, plus the error, which `releaseNotes` logs (`TestReleaseClassBanner_FailsClosed`, `TestClassifyRelease_ProbeError`). A wrong config-release could skip a needed approval.
- **Operator-facing labels are exact.** `TestRun_PrePublishStepFailure_WrapsLabelAndJournals` pins, for every pre-publish step, the exact wrapped error text (equality, not substring: a substring assertion lets a label drift pass), the sentinel, both ledgers, and that the journal's failure `Note` is the step's own error, not the wrapped one — the journal is the forensic record of what the step reported.
- **A skipped step is not a completed one.** Dry-run steps are journaled `skipped-dry-run` and never appended to `StepsCompleted` (`TestRun_DryRun_StepLedgerExact`).
- **`defaultReleaseVerify` requires an absolute `repoRoot`,** because it executes `<repoRoot>/go/evolve`; a relative root would make that execution depend on the working directory (`TestDefaultReleaseVerify_RelativeRepoRoot`).
- **Verify reads and tags the release commit, not `HEAD`** (`TestDefaultReleaseVerify_ReadsAndTagsTheReleaseCommitNotHEAD`).

## Findings

- **Tests use hermetic repos.** Git-backed tests build an isolated `gittest.Fixture` with known tags (`initTempRepoWithTag`, `makeHermeticGitRepo`, `initClassifyRepo`) rather than `git describe` on the live worktree, whose tag set drifts and can hold non-semver tags that shadow `v*`. `findRepoRoot` skips a real-repo test outside a git checkout.
- **`TestDefaultRebuildBinary_NonDryRun_RealRepo` builds only in a copy of the module.** Building into the live tree's `go/evolve`, even with a restore afterwards, lets a concurrent ship stage the test's binary. Without the ldflags stamp a plain `go build` reports the VCS revision and `release-verify` would fail every release.
- **Dry-run tests that assert the journal exactly pin `JournalDir` to their own temp dir.** Otherwise every dry-run test in the binary shares `os.TempDir()/release-pipeline-dryrun-<version>.json`, and adding `t.Parallel()` to a sibling would make them flaky.
