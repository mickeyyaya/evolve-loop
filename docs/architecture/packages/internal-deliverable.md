## Purpose

`internal/deliverable` is the one well-formedness verifier for phase deliverables. The agent's `evolve phase verify` self-check, the host contract gate (`Reviewer`), the correction ladder's rung re-check (`Verifier`), the runner's reconcile path (`VerifyCatalogAware`) and the verdict engine (`VerifyForClassification`) all run the same `VerifyWithStage`, so no two of them can disagree about what "well-formed" means. It judges shape only. Semantic correctness is the auditor's job, and a Verify pass is never a semantic pass.

## Design

- **The return signature is the fail-open / fail-closed contract.** `err != nil` is ambiguity or an infrastructure fault (unknown phase, a read fault other than absence) and the caller fails open. `err == nil && !OK` is a confirmed agent violation and the caller fails closed. `OK` is well-formed.
- **A layered API, never a changed signature.** `Verify` → `VerifyWith` (a `Resolver`) → `VerifyWithStage` (the PhaseIO stage) → `VerifyWithReportSize` (the report-size gate). Each outer form is the next inner form at its default, so a new dial never ripples through existing callers. `VerifyBuildWithChangedPaths[Stage]` and `VerifyCatalogAware[Stage]` follow the same rule.
- **One check order, so one correction names everything.** The primary artifact first (existence with the write-in-flight grace, emptiness, then the kind-specific shape), then the agent-owed secondaries, then the declared effects. The result's messages are the correction directive the agent is re-dispatched with, so each names the file, section, item or exact command to fix.
- **Violation codes are a closed, stable vocabulary** (`missing_artifact`, `missing_section`, `bad_verdict`, `missing_secondary`, `missing_effect`, …). The correction ladder's same-defect identity keys on them, so a repeat of one defect escalates instead of re-dispatching blindly.
- **Markdown checks.** Required sections; the conditional explanation sections while the cycle's explanation contract is active, matched with `reportdoc.HasSection`, the audit gate's own predicate; a parseable verdict; the ADR-0039 failure block and its class; the challenge-token echo; a stray copy in the worktree. JSON checks: validity, the declared top-level shape, and required keys through a tolerant reader that ignores unknown keys.
- **Verdict reading.** `verdictPresent` reads the sentinel first through `phasecontract.ParseVerdictSentinel`, the one shared parser. The legacy prose scan runs only below PhaseIO enforce.
- **Declared effects are a registry of `{check, perform}` pairs** (`effects.go`). `verifyEffects` runs each declared effect's check. `HostEffects.Perform` runs each non-nil perform before every judge, resolving the phase and its roots exactly as the gate does (`rootsFor`). Today the one entry is `inbox-claim`: `checkInboxClaim` and `claimCommitted`.
- **Derived secondaries are a registry of derivers keyed by the owed basename** (`derivers` in `host_effects.go`). After the effects, `Perform` derives each secondary the registry declares in `outputs.derived_from` (`Contract.DerivedFrom`) when the agent left it absent or empty: it reads the owed path with the gate's own write-in-flight grace (`readDeliverableWithGrace`), so a file the agent wrote or is still landing is never touched and a read fault declines; it derives only from the declared primary; it writes atomically. A decline is folded into `Perform`'s error, which the orchestrator emits as the WARN `ORCHESTRATOR_HOST_EFFECT_FAILED`, and leaves the absence for the gate to judge. Today the one deriver is `triage-decision.json` from `triage-report.md` (`triagedecision.Derive`). See ADR-0106 H2.
- **`rootsFor` is the one `core.ReviewInput` → `phasecontract.Roots` translation**, shared by the gate, the rung re-check and `HostEffects`. It spells `.evolve` as the engine's `rootsFor` (`verdict/settle.go`) does. The one named difference is the engine's `DispatchedArtifact`, which only a dispatch knows.
- **The gate (`Reviewer.Review`).** Off approves everything. Ambiguity fails open and leaves the breaker alone. A clean verify resets the breaker. A sole recoverable `bad_verdict` may be salvaged. Below enforce a violation is a logged would-block. At enforce each block increments a persisted consecutive-block counter (`.evolve/contract-gate-breaker.json`, because the orchestrator is rebuilt every cycle), and the `defaultBreakerThreshold`-th consecutive block demotes enforce to advisory. `ReviewResult.Blocks` carries that counter, so the ladder escalates off the same counter that opens the circuit. Every decision is one Signal Center event through `gatesignal.Reporter`, a Null Object until `WithSignals` injects a Center.
- **Constructors are functional options applied at one point** (`newReviewer`). The report-size settings are themselves an `Option` (`withReportSize`), so a caller's later option is never clobbered by a trailing assignment.
- **Capabilities, not types, prove wiring.** `core` cannot import this package, so the composition root asks the reviewer chain for `VerifiesDeclaredDeliverables()` and `SignalsWired()`.
- **The report-size gate has its own stage**, independent of the contract gate's. Off and shadow add nothing. Advisory records `handoff_budget_exceeded`, and the Reviewer logs it as a WARN would-block but approves. Only enforce blocks. A co-occurring real violation still blocks at any size stage. The token estimate is the ~4-characters-per-token heuristic, because the repo carries no tokenizer.
- **The docs floor is additive.** `ArchitectureDocsViolations` is a pure classifier over the build's changed paths; `internal/docsfloor` owns what "architecture-class" means. The floor is appended to the well-formedness violations and never masks one.
- **The salvage layer** has two halves. Measurement: `ClassifyBadVerdict` classifies every `bad_verdict` block into `bad-verdict-baseline.jsonl`. Extraction: `RepairedVerdictContent` → `salvageVerdictWith` → `persistSalvage`. `SalvageVerdict` is the pure, built-in-resolver form. Salvage *reformats* the agent's own payload into a canonical sentinel line (`sentinelLine`, deliberately not `RenderVerdictSentinel`, which would drop the agent's other keys) and never invents a field value.
- **Classifier shapes, most specific first:** a sentinel comment whose payload has a trailing comma; a verdict object inside a code fence; a bare verdict object in prose (a displaced sentinel). Anything else is not recoverable. The classifier selects the report's *own* sentinel with two rules that are each insufficient alone. Quote-awareness excludes a sentinel contained in a closed inline-code span. Tail anchoring takes the last surviving sentinel. Echoed spans and fences are blanked with spaces rather than deleted, so every offset stays valid for the repairer.
- **Two sidecars, two questions.** `bad-verdict-baseline.jsonl` is the measured *potential* (one record per `bad_verdict` block). `salvage-applied.jsonl` records what the gate *actually* salvaged. `BaselineSummary.Saved` is never derived from `Recoverable`: refusals make the two differ. Both basenames are exported so the CLI (`evolve salvage report`) opens the files the writers append to.

## Invariants

- **Fail open on ambiguity, fail closed on a confirmed violation.** Re-dispatching an agent cannot fix a gate that cannot decide, or a file nobody could read (EISDIR, permissions). The same rule covers secondaries. Pinned by `TestVerify_UnknownPhase_FailsOpen`, `TestReviewer_Ambiguity_FailsOpen`, `TestReviewerWithCatalog_FailsOpenWhenNoContractResolves`, `TestVerify_UnreadableSecondaryIsAmbiguity`, `TestReadDeliverableWithGrace_NonAbsenceIOFailsImmediatelyAsInfra`.
- **The write-in-flight grace delays a verdict and never changes it.** A final write is not atomic with the verify after it, so absence or blankness is provisional for `readGraceWindow` (500 ms, polled every 20 ms). A genuinely missing or empty file still yields the same code, and the common already-written case costs one read with no sleep. Partial-but-non-blank content is closed upstream by the bridge's cross-poll debounce, not here. `graceSleep` is a test seam, not a dial. Pinned by the `TestReadDeliverableWithGrace_*` tests.
- **`Result.Content` is the exact bytes the verdict was computed from.** Consumers classify it instead of re-reading the path, so a file swap between verify and classify cannot split them. It is carried on a failed verify too, because a phase can derive a legitimate non-ship verdict from partial content (intent delta's `[intent-unchanged]` yields SKIPPED); the ship guard clamps any ship-eligible claim. A missing artifact has its path set and empty content. A `NoArtifact` contract (ship) has neither. Pinned by `TestVerify_OKResultCarriesTheVerifiedBytes`, `TestVerify_MalformedResultStillCarriesTheBytes`, `TestVerify_MissingArtifact_ContentEmptyPathSet`, `TestVerify_NoArtifactContract_NoPathNoContent`.
- **`Result.Owed` and `Result.Effects` record what was checked.** The verified signal reports them rather than re-resolving the declaration. Pinned by `TestVerify_ResultCarriesTheOwedFilesAndEffectsItChecked`, `TestReviewerSignals_VerifiedNamesTheOwedFilesAndEffects`.
- **A FAIL or WARN sentinel never waives the report body.** Required sections are checked on every verdict, so "I am reporting FAIL, so I need not write the report" is not a legal reading. Pinned by `TestVerify_WarnOrFailSentinel_StillRequiresSections` (also `go/acs/cycle1138`).
- **The failure block.** A sentinel FAIL or WARN owes the ADR-0039 failure block. Audit owes it unconditionally. Build, scout and triage owe it only at PhaseIO enforce, so a phase that has not adopted the sentinel is not false-blocked before the cutover. Prose-only verdicts never owe it. Only the audit's class is validated against the failurelog vocabulary, because only the audit's class feeds a decision (the retry envelope on FAIL, the failure record on FAIL and WARN). `NormalizeLegacy`'s aliases pass on purpose: one taxonomy beats a stricter gate that would duplicate the alias table. Pinned by `TestVerifyWithStage_*`, `TestVerify_AuditFailWithoutFailureBlock_Violation`, `TestVerify_FailureContextNotRequiredOnPassOrLegacy`, `TestVerify_AuditFailureClassOutsideTheVocabularyIsAViolation`.
- **At PhaseIO enforce there is no prose rescue.** An out-of-vocabulary sentinel is `bad_verdict` even when the prose contains an allowed word. A stray byte after the sentinel's JSON is tolerated by the shared parser. Pinned by `TestVerdictPresent_EnforceRequiresSentinel`, `TestVerdictPresent_Enforce_ToleratesTrailingBraceInSentinel`.
- **The challenge-token echo is checked at the correctable boundary.** Without a minted token there is nothing to echo, so the check is silent. Scout mints the token and is never required to echo it. Pinned by `TestVerify_Build_MissingChallengeToken_Violation`, `TestVerify_Build_NoTokenFile_FailOpen`, `TestContract_RequireChallengeToken_BuildOnlyAtV1`.
- **Owed files are read through `phasecontract.OwedPath`**, the one join the prompt tail also renders. A declared separator never steers the read outside the workspace, and the checked file is recorded by basename. Harness-produced outputs are never demanded of an agent. Pinned by `TestVerify_OwedFileDeclaredWithADirectoryIsReadAtTheWorkspaceRoot`, `TestVerify_HarnessProducedSecondaryIsNotGated`.
- **An effect check needs `Roots.Cycle` and `Roots.EvolveDir`**; without them it errors (fail open) rather than deciding blind. An unbound declared effect is `unbound_effect`, a registry defect, never a pass. The registry and the effect table are pinned equal both ways. Pinned by `TestVerify_DeclaredEffectNeedsCycleInRoots`, `TestVerify_UnboundDeclaredEffect`, `TestPhaseRegistry_EveryDeclaredEffectHasACheck`, `TestEffects_EveryEntryIsVerified`.
- **A host claim needs a cycle and an absolute project root**, and fails loudly without them. It claims exactly what the check owes. Pinned by `TestHostEffects_WithoutACycleIsAnError`, `TestHostEffects_WithoutAProjectRootIsAnError`, `TestHostEffects_ClaimsExactlyWhatTheCheckOwes`, `TestDeclaredEffects_HostClaim`.
- **A derived secondary never replaces a file the agent wrote or is landing.** Pinned by `TestHostEffects_NeverTouchesADecisionTheAgentWrote`, `TestHostEffects_WaitsOutTheAgentsWriteInFlight` and `TestHostEffects_DeclinesWhenTheDecisionIsPresentButUnreadable`.
- **A derivation reads only the declared primary, and every declaration has a deriver.** Pinned by `TestHostEffects_DerivesOnlyFromTheDeclaredPrimary` and `TestHostEffects_TheRegistryDeclaresTriagesDerivation`, which loads the real registry.
- **A declined derivation is loud and leaves the file absent.** Pinned by `TestHostEffects_ADeclinedDerivationIsLoudAndLeavesTheFileAbsent`.
- **The breaker counts only the gate's final judgement.** The rung re-check (`Verifier`) never touches it, or a multi-rung repair of one flaky deliverable would count as consecutive blocks and demote the gate batch-wide. A salvage neither clears nor advances it, or a persistently malformed producer would hide from both the escalation ladder and the breaker. Pinned by `TestLadder_RungRechecksAreBreakerNeutral`, `TestReviewerReview_SalvageIsBreakerNeutral`.
- **A demotion is never a bare approval.** It carries `Demoted`, the reason and the count, so the orchestrator can announce it. A clean approval and a shadow approval are never demotions. Pinned by `TestReviewer_CircuitBreaker_MarksDemoted`, `TestReviewer_ApprovalIsNeverDemoted`, `TestReviewer_ShadowApprovalIsNotDemotion`.
- **Breaker persistence fails loudly.** A write or rename failure is a stderr WARN, and the prior state is left intact. Pinned by `TestBreakerWriteFailureLogged`, `TestWriteBreaker_TmpWriteFailure_WARNsAndLeavesPriorStateUnchanged`, `TestWriteBreaker_RenameOntoExistingDir_WARNsDistinctFromWriteFailure`, `TestBreakerWriteSuccess_NoStderrNoise`.
- **Salvage acts only on a sole, recoverable, unambiguous `bad_verdict` whose repaired bytes re-verify clean.** It uses sole membership, never "a bad_verdict is present", because salvage erases every violation and must not erase a co-occurring one such as the proof-of-read check. Pinned by `TestRepairedVerdictContent_RepairsTheSoleRecoverableBadVerdictInMemory`. The repaired bytes are re-verified under the caller's own resolver, roots and stage rather than `OK` being set by hand, so every content check still applies and path checks never resolve against the process CWD (no pinning test in the package after the per-cycle predicates were retired; the code keeps a one-line why). An unresolvable phase refuses.
- **Ambiguity is what any reading can see.** `candidateCount` is the maximum of a string-aware scan, a brace-only scan and a stateless count of `"verdict":` keys, decoded as `encoding/json` decodes them (case-insensitive, `\uXXXX` unescaped). Each stateful scan has a one-character silencer in prose (an unpaired `"`, an unmatched `{`). Over-counting costs a salvage; under-counting costs the gate. Pinned by `TestReview_RefusesSalvage_WhenAnUnpairedQuoteHidesASecondCandidate`, `TestReview_StillSalvages_TheGenuineSoleCandidate`, `TestCandidateCount_CountsDecoderVisibleVerdictKeys`, `TestCandidateCount_SoleCanonicalVerdictStillCountsOne`. The unmatched-brace silencer has no in-package pin; the code keeps a one-line why.
- **The repairer never searches.** It rewrites exactly the span and payload offsets the classifier qualified (`BadVerdictClassification.span` / `.payload`), so classifier and repairer cannot disagree about which bytes are the report's verdict. Pinned by `TestRepairVerdict_RefusesSpanNotAddressingContent`, `TestSalvageVerdict_RefusesUnrepairablePayload`, and the classifier's decoy tests (`TestClassifyBadVerdict_QuotedDecoyCorpus`, `TestClassifyBadVerdict_QuotedEchoStillSuppressed`).
- **"Quoted" means contained in a closed code span, not adjacent to a backtick.** A lone backtick is prose punctuation. A banned-symbol tripwire keeps the adjacency helper from returning. Pinned by `TestClassifyBadVerdict_UnmatchedBacktickDoesNotMisclassify`, `TestClassifyBadVerdict_UnmatchedBacktickFalsePositive`, `TestClassifyBadVerdict_BacktickAtContentBoundary`, `TestNoQuotedEchoRegression` (and `go/acs/cycle1438`, which forbids those symbols in `salvage_instrument.go`).
- **An approved salvage returns and persists the bytes it verified.** Downstream phases re-read the artifact, so approving bytes that were never persisted would let a malformed FAIL be re-read as PASS by a later prose scan. A failed persist therefore fails closed: the salvage is refused and the ordinary block path runs. This is the one place the gate deliberately does not fail open. Pinned by `TestSalvageVerdict_RecoversFencedJSON`, `TestReviewerReview_PersistFailure_FailsClosed`.
- **Write-back is compare-then-write, and the guarantee is narrower than compare-and-swap.** `persistSalvagedArtifact` refuses when the file changed since the gate read it, so a live agent's newer report is never replaced by a repair of the older one. It is not atomic with the rename: a write inside that window is still clobbered. Closing it would need a lock the agent side does not take. An empty path (`NoArtifact`) is a no-op success, and a vanished file refuses. Pinned by `TestPersistSalvagedArtifact_RefusesWhenFileChangedUnderGate`, `TestPersistSalvagedArtifact_NoArtifactPathIsNoOp`.
- **Salvage effects live below the stage dial; the decision is computed above it.** Below enforce a would-salvage is only reported: the artifact, the sidecar and the breaker stay untouched, because a shadow soak must not measure a system its own disabled gate already mutated. Pinned by `TestReviewerReview_ShadowStage_NoSideEffects`, `TestReviewerSignals_WouldSalvageUnderShadowIsAWouldBlock`.
- **One verifier, one salvage.** `VerifyForClassification` offers the engine the gate's own verification. At enforce it salvages, persists and reports before classification, and `persistSalvage` is the single effect both it and `Review` reach, so a salvage happens once. Below enforce it persists nothing. `PlainVerifier` is the Null-Object form when the gate is off. Pinned by `TestVerifyForClassification_SalvagesPersistsAndReportsOnce`, `TestVerifyForClassification_OutsideEnforceReturnsTheVerifiedBytesUntouched`, `TestPlainVerifier_IsTheCatalogAwareVerifyWithoutSalvage`.
- **The baseline is one record per `bad_verdict` block, unconditionally.** A sampled baseline would measure the sampler. The engine path records only a salvage it persists, and an unsalvageable block is recorded once by `Review`, not once per settle probe. Non-verdict failures write nothing. A write failure is logged and never reaches the decision. Pinned by `TestVerifyForClassification_BaselineIsRecordedOncePerBlock`, `TestRecordBadVerdictBaseline_OnlyOnBadVerdict`, `TestRecordBadVerdictBaseline_RecordShape`.
- **The sidecars are unauthenticated, so both readers filter on their own `event_type`.** They treat torn lines differently on purpose. `SummarizeBadVerdictBaseline` errors on a torn line, since skipping it would bias the rate it exists to measure. `CountSalvageApplied` returns torn lines as a `Malformed` count: it is advisory telemetry that no decision reads, and failing there discarded the whole operator report. Pinned by `TestCountSalvageApplied_TolerantOfTornLines`, `TestCountSalvageApplied_CountsOnlyOwnEventType`, `TestSummarizeBadVerdictBaseline_NamesAndExercises`, `go/acs/cycle1439` `TestC1439_007_SalvageReportFailsLoudlyOnTornRecord`.
- **The operator summary line tells no lies.** `SalvageSummaryLine` streams the never-rotated sidecar. It reports this run's records (a legacy sidecar without run ids reports the whole file). A torn record is skipped by the total and the breakdown alike. A scanner error omits the line rather than print a partial total. It is silent at zero. Only minted `SalvagePattern` values render; anything else counts as `unknown`, so a forged pattern cannot pose as gate state in the operator log. Surfacing is pinned by `TestReviewerReview_SalvageSurfacesSummaryLine` and `TestSalvageSummaryLine_SurfacesAndIsSilentAtZero`; the allowlist and run scoping have no in-package pin, and the code keeps a one-line why for each.
- **The runner's dispatched path names the file; the contract names its shape.** `Roots.DispatchedArtifact` overrides the contract path, and the stray-in-worktree hint names the dispatched basename. Pinned by `TestVerify_DispatchedArtifactOverridesContractPath`, `TestVerify_StrayInWorktree`.
- **The report-size gate blocks only at its own enforce.** Off and shadow leave the result untouched, advisory warns and approves, and a Reviewer built without the setting never blocks on size. Pinned by `TestVerifyWithReportSize_ShadowStaysSilent_Negative`, `TestVerifyWithReportSize_AdvisoryRecordsWarnViolation`, `TestReviewer_ReportSizeGate_AdvisoryWarnsButApproves`, `TestReviewer_ReportSizeGate_BlocksOnlyAtEnforce`, `TestReviewer_ReportSizeGate_DefaultOff_ByteIdentical`.
- **The docs floor never masks a well-formedness violation and never fires without a diff.** A missing build report plus an architecture-class diff reports both, and the stage-threaded form keeps the stage-gated build checks. Pinned by `TestVerify_ArchitectureClassRequiresDocsDelta`, `TestVerifyBuildWithChangedPathsStage_AppliesFloorAndPreservesStage`, `TestVerify_BuildWithoutDiff_ByteIdentical`.
- **The catalog-aware path degrades loudly.** With no `EvolveDir`, or a catalog that fails to load, it resolves built-ins only; the failed load is a stderr WARN because it can flip a user phase's outcome. `roots.EvolveDir` must be `<projectRoot>/.evolve`. Pinned by `TestVerifyCatalogAware_DegradesToBuiltin`.

## Findings

- **cycle-1212**: a verify racing the agent's final write read ENOENT or an empty file and failed closed on a deliverable that was still being written. That produced the grace window. The partial-content half was later closed in the bridge; [deliverable-contract.md](../deliverable-contract.md#write-in-flight-grace-read-robustness) records both.
- **cycles 1406/1407**: a classifier that read backtick adjacency as proof of quoting excised a report's own verdict behind one stray backtick, inflating the not-recoverable count the baseline exists to measure. Containment in a closed span replaced it. The old helper's name stays banned by a tripwire, because a later cross-lane merge (cycles 1438/1439) landed the correct containment logic under the banned name and turned main red.
- **cycle-646**: the report-size gate shipped with shadow and advisory behaving identically, so an oversized Handoff Summary gave no signal at all until enforce. Advisory became the WARN rung. The slice that introduced the gate (cycle-565) is in [internal-phasecontract.md](internal-phasecontract.md#findings).
- **Cycles 1672, 1687, 1697, 1707**: the contract gate rejected triage with `missing_secondary` for an absent `triage-decision.json` and re-dispatched the whole phase, still after F36 had fixed the neighbouring `missing_effect` class. That produced the derivation step (ADR-0106 H2): the host writes the file from the report before any judge.
