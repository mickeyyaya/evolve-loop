# internal/cliupdate

> The plan this package implements: component C4 of [model currency](../../plans/model-currency-2026-10.md) (the operator's decision of 2026-10-05). The operator surface: `evolve cli update` in [runtime-reference.md](../../operations/runtime-reference.md). The catalog it feeds: [model-discovery-and-catalog.md](../model-discovery-and-catalog.md).

## Purpose

`internal/cliupdate` updates the LLM CLIs the operator subscribes to, at a loop boundary, and proves each changed CLI still works before a wave dispatches it. For each family it reads the installed version, smoke-tests it first when it differs from the version the last boundary recorded (a self-update or a manual install between boundaries), runs the family's updater, reads the version again, and smoke-tests a CLI whose version changed. It returns one typed `Result` per family and records in `.evolve/cli-updates.json` every version the boundary accepted, which is what the next boundary compares against and what the readiness gate's `cli-version-drift` check reads.

A CLI only lists the models its installed version knows (Sonnet 5.5 was missed until `claude update` on 2026-09-30), so the catalog refresh can only be as current as the CLI. This package is the CLI half of keeping every dispatch on the newest model of its line.

## Design

- **Logic in the package, effects behind five seams.** `Seams{Eligible, Probe, Version, Run, Smoke}` carry every effect; `Update` and `Plan` are deterministic over them, so the unit tests drive every branch with fakes and never run a real updater. The composition root (`go/cmd/evolve/cmd_cli.go`, `productionCLIUpdateWiring`) wires the real ones:

| Seam | Production | Why that one |
|---|---|---|
| `Eligible` | `Unwalled(credentialWall(clihealth store))` | the cheap selection: a family on a cli-health credential-wall bench is out, with no probe spent; L2 swaps in `cli_routing.clis` membership |
| `Probe` | `liveCheck`, the `evolve doctor live` probe | "subscribed" until L2: a family with no found change must answer `doctor live` before its updater runs |
| `Version` | `looppreflight.CLIVersion` | the `<bin> --version` probe and the version-token rule of the readiness gate. It starts through `bridge.LaunchLLM`, so the self-updater of agy stays off. The drift check and the updater read a version in the same way. |
| `Run` | `Exec(GroupRunner)` | runs the family's argv with no stdin under a 10-minute bound, in its own process group: a deadline kills the whole group and `WaitDelay` (2 s) stops a grandchild that holds the output from blocking the boundary; the env drops the family's `AutoUpdateOffEnv`, so an operator who exported it does not silently block `agy update`; a non-zero exit is an error carrying the output's tail, stderr last |
| `Smoke` | `liveCheck`, the same `doctor live` probe | the only probe that submits work, so it sees a wall as well as a boot failure |

- **The updater is manifest data.** Each family's argv is its `*-tmux` manifest's `update_argv` (`claude-tmux.json`: `["claude", "update"]`; `agy-tmux.json`: `["agy", "update"]`, from `agy --help`'s `update  Update CLI`). There is no Go conditional per CLI. A family whose manifest declares none is reported `no-updater`, never failed. codex declares none: its updater is `brew upgrade --cask codex` ([the codex update-menu incident](../../incidents/2026-10-05-codex-update-menu.md)), which a brew pin refuses and which is not one argv, and codex has no subscription.
- **Which families: the subscribed ones.** Until cli-routing L2 wires `cli_routing.clis` (the routing table plan, `docs/plans/cli-routing-table-2026-10.md`, lands with PR #770, L1a), the default is every installed `*-tmux` family (`bridge.InteractiveFamilies`) that has an updater, minus a family with a credential wall on the cli-health bench (`Eligible`, no probe), minus a family whose `doctor live` probe fails (`Probe`, logged as a `[loop] WARN:` skip). A probe whose REPL never drew its prompt is not such a failure: it is reported as `boot-timeout`, below. That is how an unsubscribed codex would be skipped. The probe runs only for a family that has an updater, so codex and ollama cost nothing. L2 replaces `Eligible` with membership in `cli_routing.clis` and the probe becomes unnecessary.
- **The flow per family.** No updater → `no-updater`. A cancelled context → `skipped: interrupted` (nothing runs). Not eligible → `skipped` with the reason. Then the version is read **first**, before any launch. An unreadable version is smoke-tested: a failed smoke is `smoke-failed`, a passed one is `update-failed` ending `smoke OK; the updater did not run`, because no change could be told afterwards. A version that differs from the family's last record (`Update` takes the record history; the last record of any kind is the version last accepted) was moved between boundaries: its smoke **is** the probe, it runs before anything else launches the new version, and a failure is `smoke-failed` with no updater run (a self-updated CLI that no longer boots halts the next wave rather than being skipped as unsubscribed). Otherwise `Probe` decides the subscription. Since 2026-10-06 a probe failure is never *inferred* to mean "unsubscribed". `Seams.Explain` runs a usage query for the family (the production seam is the shared usage evidence, see [internal-usageprobe](internal-usageprobe.md)), and the verdict decides the result:
  - `exhausted` → `quota-exhausted`, the verified cause. The evidence benched the family until the reset.
  - A boot timeout (below) → `boot-timeout`, with the verdict's summary appended, for example `quota ruled out: …`.
  - Any other failure → `skipped`, whose detail is the verdict's summary: quota ruled out (the failure stands as found), the usage query failed too (an auth, install, network or subscription cause), or quota could not be verified.
  - With no `Explain` seam, the detail says the cause is unverified.

  The exception is an error wrapping `ErrBootTimeout`: the live probe's REPL never drew its prompt, on every attempt the driver's manifest allows (`probe_boot_retries`; see [internal-bridge](internal-bridge.md)). That is `boot-timeout`, whose detail says the version was neither checked nor updated and carries the probe's attempt count and final pane. A boot timeout says nothing about the subscription, and calling it "unsubscribed" sent the operator looking at the wrong thing (wave 67). Like `skipped`, it does not run the updater, is not in `Failed()`, and prints as a `[loop] WARN:` line; preflight's bridge-boot, which runs next, is the gate that halts if the CLI still cannot boot. Then the updater runs and the version is read again.
- **An interrupt is never a failure.** Every step that can be cancelled (the probe, the updater, any smoke) checks the context: a cancelled boundary reports `skipped: interrupted: …`, never `smoke-failed`, so a SIGINT never halts the loop as a broken CLI and `evolve cli update` exits 130, not 1.
- **Two failure classes, two consequences.** `Report.Failed()` (update-failed and smoke-failed) sets the verb's exit 1. `Report.SmokeFailed()` alone halts the loop's next wave: an updater that failed but left a CLI whose smoke passed leaves the wave on a proven CLI, so the loop logs a `[loop] WARN: cli-update:` line and carries on. A failed smoke means the CLI the wave would dispatch is broken.
- **`failedSmoke` runs one usage query, as a failed probe does.** The smoke is the check that halts the next wave, so a quota wall must not halt it. `failedSmoke` runs after the interrupt check and uses the same `Seams.Explain`:
  - If the verdict is `exhausted`, the result is `quota-exhausted`. One helper, `exhaustedCause`, makes that decision for the probe and for the smoke.
  - If the verdict is not `exhausted`, the result stays `smoke-failed` and the halt stays. The detail then ends with the summary of the verdict, for example `quota ruled out by a usage query: …`.
  - A window of one model is a note, never the cause. The smoke runs the model of the dispatch tier. A drained window of another model, for example Gemini 4 Argon, cannot explain the failure. The detail names that window after the smoke error, and the halt stays.
  - If the `Explain` seam is absent, or the verdict is `unavailable` or `unknown`, the result stays `smoke-failed`. A query that proves nothing must not turn a halt into a warning.
  - A `quota-exhausted` result is in neither `Failed()` nor `SmokeFailed()`. The loop prints a `[loop] WARN: cli-update:` line and continues.
  - `accepted` skips a `quota-exhausted` result by its status, because a failed smoke can carry versions. The next boundary finds the version again and smoke-tests it again.
  - `failedSmoke` checks the context again after the query, which can take up to 120 s. An interrupt during the query reads `skipped: interrupted`, never `smoke-failed` or `quota-exhausted`.
- **The probe and the smoke run on the dispatch tier.** `cliUpdateWiringWith` builds one live check for both seams. It runs `doctor live <family>-tmux --model balanced`, where `balanced` is `unsetDispatchTier`, the tier of a dispatch with no model set.
  - A launch with no `--model` boots the persisted default model of the CLI. On 2026-10-18 that default was Gemini 4 Argon for agy, a model that the deep seats dispatch.
  - The check now tests the model that the phases of the default chain use: `Gemini 3.8 Flash (High)` for agy and `sonnet` for Claude Code.
  - The canary of the cli-health bench does not change. It passes no model.
- **`Plan` is the dry run.** It takes no seams, so it cannot probe, update, smoke or record; it lists each family as `planned` with its argv or `no-updater`.
- **The record holds accepted versions.** `Remember` appends `Record{family, kind, old, new, at}`: a `self-update` for a found change whose smoke passed (old = the last record, new = the found version), an `update` for a change the updater made (old and new both known), and a `baseline` the first time a family is seen with no change. A `smoke-failed`, `skipped`, `boot-timeout` or `quota-exhausted` result adds nothing (an interrupted smoke, an unsubscribed family or an unbooted one proves nothing; a `boot-timeout` result has no new version, so `accepted` writes nothing for it), so its version is never accepted: the next boundary finds it again and smoke-tests it again before any wave. A report that observed no version (a plan) writes nothing. It writes under the `<file>.lock` sidecar (`flock.WithPathLock`) and through `atomicwrite.JSON`, and keeps the newest 64 records; a family whose records were trimmed away gets a new baseline. An unreadable file is an error, and the file is left as it was. `CauseOf(records, family, from, to)` follows the family's records in order from `from`: `boundary-update` when the chain ends at `to` through updates only, `self-update` when a found change is on the chain, `unrecorded` otherwise.
- **agy's own self-updater is off on every loop launch, so the boundary is the only place its version moves.**
  - agy updates itself on launch, at most once in 15 minutes. Its binary carries `jetski/cli/updater` (`CheckForUpdate`, then `TriggerUpdateAndRelaunch`), with its state under `~/.gemini/antigravity-cli/updater/`.
  - The environment variable `AGY_CLI_DISABLE_AUTO_UPDATE` turns that off. The settings file of agy has no such key.
  - Both agy manifests declare it (`auto_update_off_env`) and set it (`default_env`). Thus each realized launch carries it: the phases, the boot of the readiness gate, `doctor live` and the canary.
  - Each bare exec of agy carries it too, through `bridge.LaunchLLM`. The bare execs are `agy models` and `agy --help` of the catalog refresh, the version probe, and the version and deep probes of the bridge doctor. `cmd/evolve` wires the runner of `modelquery` with `modelquery.UseLauncher`.
  - `agy update` is the explicit path. `Exec` starts it through `bridge.LaunchLLM` with the `update` purpose. That purpose drops the off switch of the family (`LLMExec.Drop`) and gives the cell environment of [llm-isolation.md](../llm-isolation.md) §5.1.
  - A self-update can still come from the operator's own `agy` use outside the loop. The found-change step absorbs it.

## Invariants

- **No test runs a real updater.** The package's tests use fakes only. `cmd/evolve`'s `TestMain` replaces `cliUpdateWiringFn` with an empty wiring, so a test that drives `evolve loop` updates nothing, and each wiring test installs its own fake (`fakeCLIHost`).
- **An unchanged version is never smoke-tested; any version the updater may have touched is.** Pinned by `TestUpdate_AnUnchangedVersionSkipsTheSmoke`, `TestUpdate_ARaisedVersionRecordsBothVersionsAndRunsTheSmoke`, `TestUpdate_AnUpdaterErrorStillSmokesTheInstallItTouched` and `TestUpdate_AnUnreadableVersionAfterTheUpdateIsSmokedAndFailed`.
- **A family without an updater, or one that is not subscribed, is reported and never probed past what selection needs.** Pinned by `TestUpdate_AFamilyWithoutAnUpdaterIsReportedNotFailed` (no seam called) and `TestUpdate_AnIneligibleOrWalledFamilyIsNeverUpdated` (only the eligibility check); `TestUnwalled_ACredentialWallMakesAFamilyIneligible`.
- **Only an accepted version is recorded, and only a chain of records explains drift.** A smoke-failed change stays unrecorded and is smoke-tested again at the next boundary; a change no boundary saw breaks the chain. Pinned by `TestRemember_RecordsTheVersionsTheBoundaryAccepted`, `TestRemember_ASelfUpdateIsRecordedOnlyWhenItsSmokePassed`, `TestRemember_AKnownFamilyThatDidNotChangeAddsNoRecord`, `TestCauseOf_NamesWhatMovedAVersionBetweenTwoBaselines` and `TestCauseOf_AnUnrecordedHopBetweenBoundaryUpdatesIsUnrecorded`.
- **A version moved between boundaries is smoke-booted before anything else launches it.** Pinned by `TestUpdate_AnUnrecordedVersionChangeIsSmokeBootedBeforeTheUpdaterRuns`, `TestUpdate_ASelfUpdateWhoseSmokeFailsHaltsWithoutRunningTheUpdater`, `TestUpdate_ASelfUpdateFollowedByABoundaryUpdateNamesBoth` and `TestUpdate_AVersionTheLastBoundaryRecordedIsNoSelfUpdate`; at the loop boot, before the readiness gate, by `cmd/evolve`'s `TestRunLoop_AnUnrecordedAgyVersionChangeIsSmokeBootedBeforeThePreflightGate`.
- **A deadline kills the updater's whole process group.** `sh -c "sleep 12 & sleep 60"` under a 1 s deadline returned after 60 s on the direct-child runner (`sysexec.DefaultRunner`) and returns in about 1 s on `GroupRunner`. Pinned by `TestGroupRunner_ADeadlineKillsTheUpdatersWholeProcessGroup`; the env strip by `TestExec_TheUpdaterRunsWithoutItsFamilysAutoUpdateOffSwitch`.
- **A found change is its own probe, and an interrupt is never a halt.** Pinned by `TestUpdate_AFoundChangeIsItsOwnProbe_ABrokenSelfUpdateHaltsInsteadOfBeingSkipped`, `TestUpdate_AFamilyWhoseDoctorLiveProbeFailsIsSkippedWithoutAnUpdate`, `TestUpdate_AnUnreadableVersionBeforeTheUpdateIsSmokedAndRunsNoUpdater`, `TestUpdate_AnUnreadableVersionWhoseSmokeFailsHalts`, `TestUpdate_AnInterruptIsNeverASmokeFailure` (during the probe, the updater, the smoke and the found-change smoke) and `TestRemember_ASkippedFamilyIsNeverRecorded`.
- **A probe failure is explained, never inferred.** Pinned by `TestUpdate_ABootTimeoutWithHealthyUsageIsABootTimeoutNotUnsubscribedNorQuota`, `TestUpdate_AnyProbeFailureWithAnExhaustedWindowIsAVerifiedQuotaCause` and `TestUpdate_AProbeFailureIsExplainedByTheVerdictNeverInferredAsUnsubscribed`. In `cmd/evolve`, through the production wiring and a real evidence source over a fake screen: `TestCLIUpdateWiring_ABootTimeoutWithADrainedWindowIsAVerifiedQuotaCauseAndBenchesUntilTheReset` and `TestCLIUpdateWiring_ABootTimeoutWithHealthyUsageStaysABootTimeout`.
- **A failed smoke is explained, never assumed to be a broken CLI and never assumed to be quota.** Pinned by `TestUpdate_ASmokeFailureWhileOnlyAModelWindowIsExhaustedStillHaltsAndNamesTheWindow`, `TestUpdate_ASmokeFailureWhileTheFamilyIsExhaustedIsAVerifiedQuotaCauseNotAHalt`, `TestUpdate_ASmokeFailureWithHealthyUsageStillHaltsAndSaysQuotaIsRuledOut`, `TestUpdate_ASmokeFailureWithoutAUsableUsageQueryStillHalts`, `TestUpdate_AnInterruptedSmokeAsksNoUsageQueryAndIsNeverAQuotaCause` and `TestUpdate_AnInterruptDuringTheUsageQueryIsSkippedNeverSmokeFailedNorQuota`. The version stays unrecorded: `TestRemember_AQuotaExhaustedResultIsNeverRecordedWhateverVersionsItCarries` and `TestRemember_AQuotaExhaustedSmokeLeavesTheVersionUnrecordedSoTheNextBoundarySmokesItAgain`. In `cmd/evolve`, through the loop boundary: `TestBootCLIUpdate_ASmokeFailureWithOnlyArgonDrainedStillHaltsAndNamesTheWindow`, `TestBootCLIUpdate_ASmokeFailureWhileTheFamilyIsDrainedWarnsAndDoesNotHalt` and `TestBootCLIUpdate_ASmokeFailureWithHealthyUsageStillHaltsTheLoop`. Through the production wiring over a real evidence source: `TestCLIUpdateWiring_ASmokeFailureWithOnlyArgonDrainedStaysASmokeFailureNamingTheWindow`, `TestCLIUpdateWiring_ASmokeFailureWhileTheFamilyIsDrainedIsAVerifiedQuotaCause` and `TestCLIUpdateWiring_ASmokeFailureWithHealthyUsageStaysASmokeFailure`.
- **The probe and the smoke launch the dispatch tier.** Pinned by `TestCLIUpdateWiring_TheProbeAndTheSmokeLaunchTheDispatchTierNotTheCLIsOwnDefault`: over a fake tmux, each seam launches agy with `--model 'Gemini 3.8 Flash (High)'` and Claude Code with `--model sonnet`. The canary passes no model: `TestDefaultLiveProbe_TheCanaryLaunchesTheCLIsOwnDefaultModelAndNeverAChosenTier`.
- **A REPL-boot timeout is reported as one.** The probe seam's error wraps `ErrBootTimeout` only for a bare exit 80 (no classified wall); `cmd/evolve`'s `liveCheckErr` adds the attempt count and the final pane's last lines. Pinned by `TestUpdate_ADoctorLiveBootTimeoutIsReportedAsABootTimeoutNotAsUnsubscribed`, and in `cmd/evolve` by `TestLiveCheck_ABareREPLBootTimeoutIsABootTimeoutWithItsPaneAndAWallIsNot`, `TestLiveProbeWith_RetriesAnAgyBootTimeoutOnceBeforeConcluding` and `TestBoundaryCLIUpdate_ABootTimeoutOrAVerifiedQuotaCauseIsAWarningLine`.
- **The updater's output keeps its end.** `Exec` puts stderr after stdout and cuts from the front, so a long download log never hides the error line. Pinned by `TestExec_ALongUpdaterOutputKeepsOnlyItsTail`.
- Every export is named by a test; the package is enrolled in `go/.apicover-enforce` and held at 100% statement coverage in `go/.cover-strict`.

## Findings

- **2026-10-05, design.** The checked-in freeze (`cli-version-freeze`, [ADR-0044](../adr/0044-unified-phase-recovery-protocol.md) C5) exists because codex once replaced its own binary mid-phase. The operator kept the freeze inside a wave and moved updating to the boundary, where no phase runs. The freeze check reads pin and updater state, never versions, so the boundary records do not relax it (`TestRun_VersionFreeze_ABoundaryUpdateRecordDoesNotUnfreezeASelfUpdater`); the 2026-10-06 finding below extended it to agy. The version comparison that tells a boundary update from a self-update is `cli-version-drift`'s ([looppreflight notes](internal-looppreflight.md)).
- **2026-10-06, agy self-updated outside any boundary** (1.2.14 → 1.2.16 → 1.2.17 within about a day). Wave 62's readiness gate then halted on `bridge-boot` (`agy-tmux rc=80 ExitREPLBootTimeout`, a blank pane after `sandbox-exec … agy --dangerously-skip-permissions`), while `evolve doctor live agy-tmux` passed about a minute later. The freeze check had treated only codex and claude as self-updaters, so nothing froze agy. Read-only research of the installed agy 1.2.17 (`agy --help`, its settings and updater files, the strings of its binary) found the launch-time updater and its environment-variable off switch; no real `agy update` ran and agy's settings were not written. The fix freezes agy at the source as manifest data (above), extends `cli-version-freeze` to any manifest that declares an off switch ([looppreflight notes](internal-looppreflight.md)), and adds the found-change step, so a version that still moves between boundaries has its first launch in a boundary smoke test rather than in the readiness gate.
- **2026-10-06, architecture review (FIX_THEN_MERGE).** The off switch first reached only realized launches; agy's catalog listing is a bare `exec` of `agy models` and `agy --help` (`modelquery.AgyLister`, `HelpEffortLister`) at cycle start, inside a wave, and the version probe was bare too; both now take `bridge.ProcessEnv`. The updater's timeout killed only its direct child, so a relaunching grandchild could hold the boundary for as long as it liked (`GroupRunner`). A self-updated CLI that no longer booted was `skipped` by the subscription probe before its version was read, so nothing halted the wave (the version is now read first and the found-change smoke is the probe). Smaller fixes: an interrupt is `skipped: interrupted`, the updater's env drops the off switch, an unreadable version is smoke-tested, and the verb refuses while a run holds a live lease (`cmd-evolve` notes).
- **2026-10-06, wave 67 boundary: a cold agy boot was reported as "unsubscribed".** The updater's `doctor live agy-tmux` was the first agy launch since wave 66 ended. Its REPL never appeared within 60 s (`rc=80`), and the updater logged `agy skipped 1.3.0: doctor live did not answer, so the family counts as unsubscribed`. Preflight's agy-claude-tmux and agy-tmux boots, 80 s later, both booted. Two fixes: the live probe retries one bare REPL-boot timeout for agy (`probe_boot_retries: 1` in agy-tmux.json), and the updater reports a boot timeout as `boot-timeout`, never as unsubscribed. See [the incident note](../../incidents/agy-cold-start-boot-timeout-2026-10-06.md).
- **2026-10-18, a drained default model halted the boundary of a healthy CLI.** `evolve wave next` did not start the loop. The boot halted with `cli_update_smoke_halt`: agy 1.4.0 → 1.4.1, `doctor live agy-tmux rc=85 pattern="exhausted"`.
  - Issue: agy self-updated to 1.4.1 outside a boundary. Its default model was then Gemini 4 Argon. The week window of Argon was 100% used, with about 133 hours until the reset. The Gemini family windows were healthy: week 43%, five-hour 1%. `evolve doctor live agy-tmux --model balanced` printed `LIVE OK`, so the smoke was a false red.
  - Gap: The smoke launched agy with no `--model`, so it tested a model that the default chain does not dispatch. `failedSmoke` also never read the usage evidence, but a failed probe does. agy self-updates on its own (1.4.0, then 1.4.1, then 1.4.2), so each new version is smoke-tested and halts the same way.
  - Solution: The probe and the smoke launch the dispatch tier `balanced`. A failed smoke runs one usage query: an exhausted family gives `quota-exhausted`, and any other verdict keeps `smoke-failed` and the halt. `accepted` skips the new status, so the next boundary smoke-tests the version again.
  - Rule: A window of one model is a note, never the cause ([internal-usageevidence](internal-usageevidence.md)). The smoke runs `balanced` now, so a drained Argon window cannot explain its failure. The detail shows the window next to the smoke error, and the halt stays.
  - Review: The first version of this change counted any exhausted window as quota. Review round 1 refuted that rule. A real fault of Gemini 3.8 Flash then shows as a warning while Argon stays drained. In this incident that was about 133 hours. Argon is the first seat of deep work, so the case recurs.
