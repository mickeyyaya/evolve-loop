## Purpose

`lifecycle` is the leaf that moves inbox items. One `Mover` owns six transitions over one inbox dir: `Claim`, `Promote`, `ReleaseFromQuarantine`, the cycle drain `Release`, `RecoverOrphans` and `RouteConsole`. It also owns the item primitives (`Locate`, `FindFileByTaskID`, the `*.json` iterator, `UpdateItemJSON`, the failure counter's reader and writer) and the chained `inbox-lifecycle` ledger line. Callers reach it only through the `internal/inboxmover` facades.

## Design

- **Injected collaborators with Null-Object defaults.** The inbox dir and the ledger appender are positional. Everything else is a functional option: stderr, the clock, the active-cycle reader, the landing probe, the protected-path predicate, the retire hook, the run-workspace spelling and the Signal Center accessor. Each default does nothing harmful, so a leaf test needs no git, no registry and no Center. Every `With*` option except `WithSignals` ignores a nil argument, so a stray nil in an option list never clears an installed seam (`TestNew_NilOptionNeverClobbersAnInstalledSeam`). A nil appender records nothing and prints nothing.
- **A leaf.** The leaf imports the standard library plus `adapters/ledger` (the record type), `continuation` (the manifest reader), `inboxbatch` (the claim layout and the routing classifier) and `signalcenter`. It never imports `gitexec`, `core`, `verifylock`, `guards`, `policy` or the host (`TestLifecycle_ImportAllowlist`). That is why `ShouldQuarantine` takes the ceiling and the system-level flag as arguments, and why the host supplies the git landing probe.
- **Only the host imports the leaf** (`TestLifecycle_OnlyHostImportsTheLeaf`). `Release` must be exported for the host to call it, so the import rule is what keeps `ApplyCycleOutcome` the one door into the cycle-outcome lifecycle (ADR-0079).
- **One producer, two links.** `warn` sends an `inbox.warning` WARN under module `inbox` to a wired Center, with `step` and `task_id` fields, or `workspace` for the manifest fault. With no Center it prints `LegacyPrefix`, the severity token and the sentence, byte for byte the line printed before the unit, so a Center-less root never goes silent. The INFO transitions, the usage lines and the ledger-append WARN print through `linef` in both cases. The ledger-append failure has no `INBOX_` code, because the file ledger reports `LEDGER_APPEND_FAILED` itself. The WARN line stays because the appender is an interface and a fake reports nothing.
- **Destination layout.** `processed/cycle-<cycle|0>/[<sha8>-]<base>`, `rejected/cycle-<cycle|0>/<base>`, `retry/<base>` and `quarantine/<base>`. Quarantine is flat because it is terminal. The triage scanner never walks it, so a poison item stops being re-picked.
- **Promote's tail order** is the console line, then the retire hook, then the ledger line (`TestMover_Promote_Order_InfoThenRetireThenLedger`). The host's retire hook releases the item's continuation binding, since every destination is out of the batch loader's reach. The unlanded-sha reason override happens before the hook, so the preserved pointer and the ledger line carry the same reason (`TestMover_Promote_Unlanded_ReroutesToRetry_RetireGetsTheOverriddenReason`).
- **`Policy`** carries a failure drain's inputs. `Ceiling` is the task retry ceiling. `SystemLevel` marks a system-level failure, which bumps and parks nothing. `Committed` names the ids that accrue failures; nil means every drained item, which is what an outcome with no committed ids selects. `Routed` means the closeout already routed the refused item to the console, so the drain bumps and parks nothing. It is a separate field so that behaviour keyed to `SystemLevel` never applies to a routed refusal.
- **One atomic failure rewrite.** `bumpWith` writes the new count, the reason and, once the ceiling is reached, the removal of the `continuation` stamp in one rewrite. Quarantine is terminal parking, so an operator revival starts fresh instead of resuming an old salvage. `BumpFailureCount` never sheds.
- **`UpdateItemJSON`** reads the item, applies the mutation to its top-level fields and writes `<path>.tmp.<pid>`, then renames it over the item. A failed rename removes the temp file. The rewrite re-marshals the whole item with sorted keys and no indent, so the first touch normalizes key order.
- **The drain stamps in the same pass.** When the failed cycle's run workspace holds a continuation manifest, `Release` writes the stamp into each item just before its rename. A missing manifest means no stamp; an unreadable one is reported and every item releases unstamped.
- **`RouteConsole`** rewrites the item where it lies, at the root or in the lane's `processing/cycle-N/`, and does not move it. The drain that follows releases it already carrying `route:console-manual`, and the claim floor refuses every later lane.

## Invariants

- **A processing claim outranks a root copy** in `Locate`, because a lane holding the item wins over a stale root copy of the same id. A missing id, or a missing inbox, is `ErrNotFound`; a read fault on an existing dir is returned as itself. Pinned by `TestLocate_ProcessingOutranksRootAndAbsentIsNotFound`.
- **`Locate`'s two reads are not one snapshot** (an accepted limit). A sibling lane's rename between them can read as `ErrNotFound` once. Every caller re-reads on its next step, and a false "absent" never fails anything closed.
- **Ids live inside the JSON**, because filenames carry timestamps. `FindFileByTaskID` skips unreadable and malformed files and returns a `ReadDir` error as itself (`TestFindFileByTaskID_ReadDirError_IgnoresNonJSON_SkipsMalformed`).
- **`ReadFailureCount` reads only the root and `processing/cycle-*/`,** never `quarantine/` or `retry/`, and a malformed record reads as absent (`TestReadFailureCount_RootAndProcessing_NotQuarantine`).
- **Routing fails open on a bad item.** An unreadable or malformed item is dispatchable, because routing enforcement must never brick claiming; `LoadDir` reports the parse fault. Pinned by `TestConsoleRoutedReason_FailsOpenOnUnreadableOrMalformed`, and the code keeps a one-line why.
- **The landing probe fails open.** A probe error treats the sha as landed and reports `INBOX_LANDED_CHECK_FAILED` (`TestMover_Promote_LandedCheckError_FailsOpenWithACode`). The code keeps a one-line why.
- **Promote's two delivery failures differ.** A destination mkdir failure is `ErrMvFailed` with `NoOp` false and the item in place, because a silent success would strand it. A rename failure stays `(NoOp=true, nil)`, which `ReconcileSuperseded` and `ApplyCycleOutcome` depend on. Pinned by `TestMover_Promote_MkdirFails_ErrMvFailed_RenameFails_NoOp`.
- **Ledger appends are best-effort.** A failed append never undoes a move that already happened (`TestLedgerLine_NilLedgerIsSilent_AppendFailureIsTheVerbatimLine`).
- **`SystemLevel` gates the bump, not only the quarantine decision.** A system-level failure leaves `failure_count` untouched (`TestMover_Release_QuarantineAtCeiling_ReplaysG2`, `TestShouldQuarantine_PureDecision`). A routed cycle does the same (`TestMover_Release_RoutedPolicyReleasesPlain`).
- **The drain fails open item by item.** A failed bump, stamp or park falls back to a plain release and is reported, so a bookkeeping fault never strands an item or quarantines it wrongly. An un-parked poison item will be re-picked. Pinned by `TestMover_Release_ItemRewriteFailed_Steps` and `TestMover_Release_QuarantineFailed_OutcomeErrorAndNoop`.
- **The drain never clobbers a root twin**, and it walks items in filename order (`TestMover_Release_DoubleMove_EmitsReleaseDoubleMove`). `RecoverOrphans` deliberately has no such guard (`TestRecoverOrphans_ClobbersExistingRootCopy` in the host).
- **`RouteConsole` never rewrites another cycle's claim,** because that item belongs to a live lane and a mis-copied id must not touch it (`TestMover_RouteConsole_RefusesAnotherCyclesClaim`). The code keeps a one-line why.
- **`LegacyPrefix` is spelled once.** The host's `TestInboxMoverPrefix_OneHome` counts the quoted literal in the leaf's non-test sources, so a comment that quotes it with a leading `"` breaks the count.
- **Clean-code limits are a test.** `TestLimits_FunctionsFilesAndNestingStayWithinTheBar` holds every function under 50 lines, nesting at 4 or less and every file under 800 lines. Comments inside a function count toward its length; its doc comment does not.
- **Preserved quirks stay pinned.** The code marks the ones a reader would otherwise "fix": the bad-state line that omits quarantine (`TestPromote_BadState_MessageStillOmitsQuarantine_AndQuarantineIsValid`), `intPtr`'s leading-digit parse (`TestIntPtr_StrPtr_FoldLifecycleMessage`), the counter reset before the quarantine-release rename (`TestReleaseFromQuarantine_CounterResetPrecedesRename`), the route check before the cycle check in `Claim` (`TestClaim_ConsoleRouteCheckPrecedesCycleValidation`), `RecoverOrphans` recovering every dir when the active cycle is unreadable (`TestRecoverOrphans_UnreadableCycleState_RecoversTheLiveDir`), and an unreadable cycle dir releasing nothing. The full list, with the reason each is kept, is in decomposition unit 06.

## Findings

- **`inboxmover-promote-mkdir-fail-loud`** ([code audit 2026-07](../../research/code-audit-2026-07/README.md)): a destination mkdir failure was returned as a NoOp success, stranding the task in `processing/`. It became `ErrMvFailed` with the item left in place.
- **The extraction (ADR-0103 unit 06)** split `Promote` (113 lines), the drain (114) and `RecoverOrphans` (52) to meet the function limit, folded three copies of the `*.json` walk into one iterator, and folded the bump and the continuation shed into one rewrite instead of two renames. The measurements and the review folds are in decomposition unit 06.
