# internal/inboxmover/lifecycle

The extraction, the signal codes, the goldens and the preserved quirks Q1 to Q16: [decomposition unit 06](../decomposition/06-inboxmover.md). Decision records: [ADR-0072](../adr/0072-system-failure-policy-and-halt.md) (the retry ceiling and quarantine), [ADR-0074](../adr/0074-typed-signal-contracts-routing-authority.md) (the claim floor), [ADR-0079](../adr/0079-cycle-outcome-inbox-lifecycle-seam.md) (one cycle-outcome door) and [ADR-0103](../adr/0103-component-breakdown-program.md) (the component breakdown). ## Purpose

`lifecycle` is the leaf that moves inbox items. One `Mover` owns twelve transitions over one inbox dir: `File`, `Claim`, `Promote`, `ReleaseFromQuarantine`, the cycle drain `Release`, `RecoverOrphans`, `RouteConsole`, `RouteLane`, `RetireUnbacked`, and the three operator curation verbs `Edit`, `Withdraw` and `VerifyPremise` ([ADR-0116](../adr/0116-inbox-curation-verbs.md)). It also owns the item primitives (`Locate`, `FindFileByTaskID`, the `*.json` iterator, `UpdateItemJSON`, the failure counter's reader and writer) and the chained `inbox-lifecycle` ledger line. Callers reach it only through the `internal/inboxmover` facades.

## Design

- **Injected collaborators with Null-Object defaults.** The inbox dir and the ledger appender are positional. Everything else is a functional option: stderr, the clock, the active-cycle reader, the landing probe, the protected-path predicate, the retire hook, the run-workspace spelling, the Signal Center accessor, the main-head reader (`WithMainHead`) and the continuation-binding reader (`WithBinding`). Those two defaults refuse, so a leaf test never stamps a premise, or withdraws an item, against a reader it did not wire. Each default does nothing harmful, so a leaf test needs no git, no registry and no Center. Every `With*` option except `WithSignals` ignores a nil argument, so a stray nil in an option list never clears an installed seam (`TestNew_NilOptionNeverClobbersAnInstalledSeam`). A nil appender records nothing and prints nothing.
- **A leaf.** The leaf imports the standard library plus `adapters/ledger` (the record type), `continuation` (the manifest reader), `inboxbatch` (the claim layout and the routing classifier) and `signalcenter`. It never imports `gitexec`, `core`, `verifylock`, `guards`, `policy` or the host (`TestLifecycle_ImportAllowlist`). That is why `ShouldQuarantine` takes the ceiling and the system-level flag as arguments, and why the host supplies the git landing probe, the `origin/main` reader `VerifyPremise` stamps and the registry read `Withdraw` consults.
- **Only the host imports the leaf** (`TestLifecycle_OnlyHostImportsTheLeaf`). `Release` must be exported for the host to call it, so the import rule is what keeps `ApplyCycleOutcome` the one door into the cycle-outcome lifecycle (ADR-0079).
- **One producer, two links.** `warn` sends an `inbox.warning` WARN under module `inbox` to a wired Center, with `step` and `task_id` fields, or `workspace` for the manifest fault. With no Center it prints `LegacyPrefix`, the severity token and the sentence, byte for byte the line printed before the unit, so a Center-less root never goes silent. The INFO transitions, the usage lines and the ledger-append WARN print through `linef` in both cases. The ledger-append failure has no `INBOX_` code, because the file ledger reports `LEDGER_APPEND_FAILED` itself. The WARN line stays because the appender is an interface and a fake reports nothing.
- **Destination layout.** `processed/cycle-<cycle|0>/[<sha8>-]<base>`, `rejected/cycle-<cycle|0>/<base>`, `retry/<base>` and `quarantine/<base>`. Quarantine is flat because it is terminal. The triage scanner never walks it, so a poison item stops being re-picked.
- **`RetireUnbacked` writes instead of moving.** An id no inbox item backs has no source to move, so the transition writes `{id, unbacked: true, retired_reason, retired_cycle, git_sha}` at the destination `Promote` would have used (`processed` with the sha prefix, or `rejected`), refuses any id that is not a plain file name and any other state, leaves a record already there as it is, and never fires the retire hook because nothing was ever bound (ADR-0106 W1). Pinned by `TestRetireUnbacked_WritesARecordEveryRetirementReaderFinds`, `TestRetireUnbacked_RejectedRecordCarriesNoShaPrefix`, `TestRetireUnbacked_LeavesAnExistingRecordAlone` and `TestRetireUnbacked_RefusesABadIDOrState`.
- **Promote's tail order** is the console line, then the retire hook, then the ledger line (`TestMover_Promote_Order_InfoThenRetireThenLedger`). The host's retire hook releases the item's continuation binding, since every destination is out of the batch loader's reach. The unlanded-sha reason override happens before the hook, so the preserved pointer and the ledger line carry the same reason (`TestMover_Promote_Unlanded_ReroutesToRetry_RetireGetsTheOverriddenReason`).
- **`Policy`** carries a failure drain's inputs. `Ceiling` is the task retry ceiling. `SystemLevel` marks a system-level failure, which bumps and parks nothing. `Committed` names the ids that accrue failures; nil means every drained item, which is what an outcome with no committed ids selects. `Routed` means the closeout already routed the refused item to the console, so the drain bumps and parks nothing. It is a separate field so that behaviour keyed to `SystemLevel` never applies to a routed refusal.
- **One atomic failure rewrite.** `bumpWith` writes the new count, the reason and, once the ceiling is reached, the removal of the `continuation` stamp in one rewrite. Quarantine is terminal parking, so an operator revival starts fresh instead of resuming an old salvage. `BumpFailureCount` never sheds.
- **`UpdateItemJSON`** reads the item, applies the mutation to its top-level fields and writes `<path>.tmp.<pid>`, then renames it over the item. A failed rename removes the temp file. The rewrite re-marshals the whole item with sorted keys and no indent, so the first touch normalizes key order. It is one of three doors into the one read-judge-write, `rewriteItemJSON`: an admission hook judges the bytes read (`RouteLane`'s), and a rewrite may refuse after mutating (`Edit`'s), so the item is written only when the rewrite returns no error. A file holding JSON `null` is `ErrInvalidItem`, never a nil-map panic (`TestUpdateItemJSON_ANullItemIsRefusedNotAPanic`).
- **The drain stamps in the same pass.** When the failed cycle's run workspace holds a continuation manifest, `Release` writes the stamp into each item just before its rename. A missing manifest means no stamp; an unreadable one is reported and every item releases unstamped.
- **`RouteConsole`** rewrites the item where it lies, at the root or in the lane's `processing/cycle-N/`, and does not move it. The drain that follows releases it already carrying `route:console-manual`, and the claim floor refuses every later lane.
- **`File` admits a new item only in the shape its readers load cleanly.** It decodes the raw item twice, as a field map (so every authored field survives) and as `inboxbatch.Item` (so a mistyped field is refused by the readers' own types). It then requires the fields the triage prompt relies on, refuses the verb-written fields (`isLifecycleOwned`: every stamp in `inboxbatch`'s owner table except `route`, by exact key), accepts an authored `route` only when `inboxbatch.IsConsoleRoute` holds (an author may send an item to the console at filing; `route: lane` stays `RouteLane`'s), and asks `inboxbatch.SanitizedFields` which prompt-rendered fields the loader would rewrite, so a filed item never loads with a sanitizer warning. It requires a `priority_class` the wired class order names (`inboxbatch.CheckPriorityClass`, the rule the rank's load warning uses; [ADR-0121](../adr/0121-inbox-priority-is-a-computed-rank.md)): an absent, unknown or mis-cased class is `ErrInvalidItem`, and a `Mover` built without `WithPriorityClasses` refuses every filing as a fault rather than admit an unjudged class (`TestMover_File_RefusesAPriorityClassTheOrderDoesNotName`, `TestMover_File_WithNoClassOrderWiredIsAFaultNotAnInvalidItem`). `Edit` does not judge the class yet; the plan's P5 adds that with the reason it requires. Identity is the whole inbox tree: `filedItemIDs` walks every `*.json` under the inbox dir (pending, claimed, retry, quarantine, processed, rejected, consumed), so a retired id is never reused and a `deps` entry may name a retired item. The file is named with `inboxbatch.FilenameStampLayout`, the stamp `FiledAt` reads. The write is create-exclusive (`os.Link` from a temp file removed on every path), so it never overwrites a file, and the encoder does not HTML-escape, so `<id>` in a criterion stays readable. The result carries the claim floor's own verdict on the filed file (`consoleRoutedReason`, the raw decode), which the CLI prints. Two filings of one id in different seconds are not serialized: the operator verb accepts that, and a lane minter routed through `File` must take the inbox `.bump.lock` around the scan and the link.
- **Field ownership is `inboxbatch`'s table, projected here** ([ADR-0116](../adr/0116-inbox-curation-verbs.md)). `inboxbatch.RoleOf` gives every key one owner: author, curator, loop stamp or operator stamp, with stamps listed by exact key. This leaf derives three rules from it. `isLifecycleOwned` is every stamp but `route`: what `File` refuses at filing and what makes an item past its filing for `Withdraw` (an authored console `route` is judged by `File`'s route rule, and every verb that writes `route` also writes `routed_*`). `IsMoverWritten` is the loop stamps only, which PR #758's sync commits or replays; an operator stamp (`premise_verified_*`) is not, so a plane-side `verify` lands through a reviewed data PR. `RouteField` names the key (it is `inboxbatch.RouteField`). `TestIsMoverWritten_IsTheLoopStampsOnly` pins the projection. `TestFieldOwners_EveryKeyALifecycleWriterWritesIsAStampOfItsOwner` and `TestFieldOwners_AnUnbackedRecordCarriesOnlyLoopStamps` drive the writers (`RouteConsole`, `RouteLane`, the failure bump with and without the continuation shed, `VerifyPremise`, `RetireUnbacked`) and require every key they write to carry the owner the table gives it, so the table cannot drift from its writers. Every writer, here and outside the leaf (the host's continuation retire, the ship phase's consumption, `evolve inbox consume`), spells a stamp key only through `inboxbatch`'s exported constant (`RoutedReasonField`, `FailureCountField`, `ConsumedField` and the rest). The one exception is `RetireUnbacked`'s record struct, whose JSON tags cannot take a constant; `TestFieldOwners_AnUnbackedRecordCarriesOnlyLoopStamps` pins it instead.
- **`Edit` writes only curator-owned fields, judges only what it writes, and never opens an item to lanes.** A field whose owner is not the curator, or `add`/`remove` on a field whose shape is not a list, is `ErrBadArgs` before anything is read. The error names the field's owner: routes are the route verbs', every stamp is its writer's, and `kind`, `created_at` and `injected_by` stay as filed. Edits apply in order inside the one read-judge-write. The result is decoded as `inboxbatch.Item` (an item its readers cannot load is refused) and judged with `File`'s own per-field rules (`itemFieldRules`, the loader's sanitizer bound included), but only for the fields the edit wrote, so a legacy item with a long title or no summary can still be reweighted. Identity follows `File`: a new id must be kebab-case and unfiled anywhere in the tree, and an edited `deps` must name filed items other than the item itself. An id is stamped only on an item that has none, which is named by its path (a `.json` target must sit directly in the inbox root); a filed id is never renamed. The same rewrite asks `inboxbatch.ConsoleRouted`, with the Mover's lane predicate (the console arm of `PlaceOnLaneMenu`), about the item before and after the edits. A console-owned item the edit would leave lane-routable is `ErrConsoleRouted`, and the message names `route-lane`, so nothing is written. The ledger line is `edit` with the edits spelled `set weight=0.4; add deps=x`.
- **`Withdraw` undoes a filing, so it applies only while the item is as filed.** It removes a pending root item. It refuses (`ErrNotWithdrawable`) an item carrying a verb-written stamp (a route stamp, a failure count, a continuation, a premise stamp); an item a pending or claimed item names in `deps`, so no dependency is left naming nothing; and an item the continuation registry binds (`WithBinding`), because no retirement path would release a binding whose scope has no item. That refusal names `evolve continuation release <id>`. A binding-reader fault is an error, never a withdrawal. The file is deleted, not archived: `File`'s identity walk covers every directory in the tree, so an archived copy would keep the id from being filed again. For a tracked item, git history is the content record. The `withdraw` ledger line carries the reason, the file's sha256 and its exact bytes, and it is written before the file is removed, so content never committed is not lost.
- **`VerifyPremise` writes the operator stamp.** On a pending root item it writes `premise_verified_at` (the Mover's clock), `premise_verified_sha` (the main-head reader) and `premise_verified_evidence` (trimmed, required), and a `verify-premise` ledger line carrying the sha as its git head. The three keys are operator stamps in the owner table, so `File` and `Edit` refuse them, `IsMoverWritten` does not claim them, and `inboxbatch`'s classifier skips them, so the evidence text never changes where the item routes (`TestVerifyPremise_EvidenceNamingAProtectedFileNeverRoutesTheItem` in the host drives this end to end). A reader failure or an empty sha stamps nothing.
- **`RouteLane` judges what `Claim` judges, and writes what it judged.** It reads the item once, decodes those bytes with the claim floor's own `routingItem` (raw JSON, never `inboxbatch.LoadFile`'s sanitized copy, which cuts each `files` entry at 160 bytes), sets `route` to `lane`, and asks `inboxbatch.ConsoleRouted` with the Mover's own lane predicate (`WithProtectedPath`, the one the claim floor reads) whether a lane may now take it. The judgment runs as the admission hook of the one read-judge-write (`updateAdmittedItemJSON`, which `UpdateItemJSON` calls with a hook that admits everything), so the bytes judged are the bytes rewritten, and on a yes it writes: `route`, `routed_reason` and `routed_at` set, a stale `routed_cycle` dropped, and a `route-lane` ledger line. The rule, its input decode and its predicate each have one home, so the operator verb cannot open anything the claim floor would still refuse. It takes no cycle, because only an operator calls it, and it has no Signal Center link, because its only root is the Center-less `evolve inbox` family.
- **`ListClaims` and `ReleaseClaim` are the claim survey's two primitives.**
  - `ListClaims(inboxDir)` gives each item in `processing/cycle-*/`: its id, its `Location`, and a flag for a root copy of the same id. It also gives the cycles whose claim dir is empty.
  - `(*Mover).ReleaseClaim(id, loc, reason)` moves one claim back to the root and appends a `release` lifecycle line.
  - If the root already holds the id with the same bytes, it removes the claim copy and keeps the root copy. The ledger reason then ends `duplicate of the root copy removed`.
  - A root copy with other bytes, or a root file of the same name, is `ErrClaimConflict`, and nothing changes.
  - The host's `inboxmover.ReleaseClaim` first decides if the holder can lose its claim. The leaf only moves.
- **`AbsorbRootCopies` gives a root copy of a claimed id back to its claim.** It reads `ListClaims` (a root copy is matched by task id, not by file name).
  - A copy with the same bytes is removed (ledger `absorb`).
  - A copy with other bytes is parked in `origin-conflicts/cycle-N/` (ledger `absorb-conflict`, a WARN line). The claim copy is never overwritten, because it can carry a lane's newer stamps.
- **`moveExclusive` never overwrites.** It makes a hard link and then removes the source. A destination that exists is `ErrExist`, which `ReleaseClaim` reports as `ErrClaimConflict`. If the remove fails, the link is removed again.

## Invariants

- **A processing claim outranks a root copy** in `Locate`, because a lane holding the item wins over a stale root copy of the same id. A missing id, or a missing inbox, is `ErrNotFound`; a read fault on an existing dir is returned as itself. Pinned by `TestLocate_ProcessingOutranksRootAndAbsentIsNotFound`.
- **`Locate`'s two reads are not one snapshot** (an accepted limit). A sibling lane's rename between them can read as `ErrNotFound` once. Every caller re-reads on its next step, and a false "absent" never fails anything closed.
- **Ids live inside the JSON**, because filenames carry timestamps. `FindFileByTaskID` skips unreadable and malformed files and returns a `ReadDir` error as itself (`TestFindFileByTaskID_ReadDirError_IgnoresNonJSON_SkipsMalformed`).
- **`ReadFailureCount` reads only the root and `processing/cycle-*/`,** never `quarantine/` or `retry/`, and a malformed record reads as absent (`TestReadFailureCount_RootAndProcessing_NotQuarantine`).
- **Routing fails open on a bad item.** An unreadable or malformed item is dispatchable, because routing enforcement must never brick claiming; `LoadDir` reports the parse fault. Pinned by `TestConsoleRoutedReason_FailsOpenOnUnreadableOrMalformed`, and the code keeps a one-line why.
- **The landing probe fails open.** A probe error treats the sha as landed and reports `INBOX_LANDED_CHECK_FAILED` (`TestMover_Promote_LandedCheckError_FailsOpenWithACode`). The code keeps a one-line why.
- **Promote's two delivery failures differ.** A destination mkdir failure is `ErrMvFailed` with `NoOp` false and the item in place, because a silent success would strand it. A rename failure stays `(NoOp=true, nil)`, which `ReconcileSuperseded` and `ApplyCycleOutcome` depend on. Pinned by `TestMover_Promote_MkdirFails_ErrMvFailed_RenameFails_NoOp`.
- **Ledger appends are best-effort, except the one that is a content record.** A failed append never undoes a move that already happened (`TestLedgerLine_NilLedgerIsSilent_AppendFailureIsTheVerbatimLine`). `Withdraw` is the exception: its ledger line is the only record of an item's content that was never committed. It therefore writes the record first, through `appendRecord`, which returns its error (a nil appender is an error there, not a silence), and removes the file only after the record landed. A failed record returns that error and leaves the item untouched (`TestMover_Withdraw_AFailedRecordKeepsTheItem`, `TestMover_Withdraw_NoLedgerMeansNoWithdrawal`). A remove that fails after the record appends a best-effort `withdraw-aborted` line, so the ledger never claims a withdrawal that did not happen (`TestMover_Withdraw_ARemoveFaultIsNotARefusal`).
- **`SystemLevel` gates the bump, not only the quarantine decision.** A system-level failure leaves `failure_count` untouched (`TestMover_Release_QuarantineAtCeiling_ReplaysG2`, `TestShouldQuarantine_PureDecision`). A routed cycle does the same (`TestMover_Release_RoutedPolicyReleasesPlain`).
- **The drain fails open item by item.** A failed bump, stamp or park falls back to a plain release and is reported, so a bookkeeping fault never strands an item or quarantines it wrongly. An un-parked poison item will be re-picked. Pinned by `TestMover_Release_ItemRewriteFailed_Steps` and `TestMover_Release_QuarantineFailed_OutcomeErrorAndNoop`.
- **The drain never clobbers a root twin**, and it walks items in filename order (`TestMover_Release_DoubleMove_EmitsReleaseDoubleMove`). `RecoverOrphans` deliberately has no such guard (`TestRecoverOrphans_ClobbersExistingRootCopy` in the host).
- **`RouteConsole` never rewrites another cycle's claim,** because that item belongs to a live lane and a mis-copied id must not touch it (`TestMover_RouteConsole_RefusesAnotherCyclesClaim`). The code keeps a one-line why.
- **A filed item is one the loader reads cleanly.** Every refusal leaves no file and no ledger line (`TestMover_File_RefusesAnInvalidItem`, fifteen shapes); an id anywhere in the tree is refused (`TestMover_File_RefusesAnIDTheInboxAlreadyHolds`); a dependency must name an item, retired ones included (`TestMover_File_ADependencyMustNameAnItem`); an existing file is never clobbered (`TestMover_File_NeverClobbersAFileAtTheDestination`); every lifecycle-owned field is refused (`TestMover_File_RefusesEveryLifecycleOwnedField`), an authored console route is kept and reported (`TestMover_File_AnAuthoredConsoleRouteIsKeptAndReported`), and the result reports what the claim floor would refuse (`TestMover_File_ReportsWhatTheClaimFloorWouldRefuse`); a scan or write fault is not an invalid item (`TestMover_File_AnUnreadableInboxIsAScanFault`, `TestMover_File_AWriteFaultIsNotAnInvalidItem`).
- **`RouteLane` never widens what the claim floor refuses.** A declared protected file or an agent-autofiled item is `ErrConsoleRouted`, the file stays byte-identical and no ledger line is written (`TestMover_RouteLane_RefusesWhatALaneMayNotTake`). A routed item is one `ConsoleRouted` passes (`TestMover_RouteLane_OpensAPipelineRepairItemToLanes`). A protected file past the loader's 160-byte field cut is still refused, because the verb judges the raw item as the claim floor does. A claimed or missing item is `ErrNotFound` and untouched, and an empty id is `ErrBadArgs` (`TestMover_RouteLane_LeavesAClaimedOrMissingItemAlone`). An unreadable inbox is the read fault itself, never `ErrNotFound`, so the CLI reports it as an I/O failure (`TestMover_RouteLane_AnUnreadableInboxIsNotAMissingItem`). An item its decode cannot read is refused and left untouched: the claim floor fails open on such an item to keep claiming alive, but an operator write that widens what a lane may take must not be made unjudged (`TestMover_RouteLane_RefusesAnItemItCannotJudge`).
- **The curation verbs leave a refused item byte-identical and unrecorded.** `TestMover_Edit_RefusesAFieldOutsideTheCurationSet` (ten requests), `TestMover_Edit_NeverOpensAConsoleOwnedItemToLanes`, `TestMover_Withdraw_RefusesAnItemAContinuationBinds`, `TestMover_Edit_RefusesAResultInboxAddWouldRefuse` (thirteen shapes), `TestMover_Edit_RefusesAnItemItsReadersCannotLoad` (an item that does not decode is refused until an edit repairs it), `TestMover_Withdraw_RefusesAnItemALifecycleVerbHasWritten`, `TestMover_Withdraw_RefusesAnItemAPendingItemDependsOn` and `TestMover_VerifyPremise_AMainHeadFaultStampsNothing`. An edit changes only its fields (`TestMover_Edit_SetsOnlyTheNamedFieldAndRecordsIt`), is judged only on them (`TestMover_Edit_JudgesOnlyTheFieldsItWrites`) and stamps an id only where none was filed (`TestMover_Edit_StampsTheIDOfAnIDlessItemNamedByItsPath`). A withdrawn id files again (`TestMover_Withdraw_RemovesAnAsFiledItemAndTheIDMayBeFiledAgain`). A claimed, retired or missing item is `ErrNotFound` to all three, through the one pending locator `RouteLane` also uses (`locatePending`). A write, scan or stat fault is neither a refusal nor a missing item (`TestMover_Edit_ARewriteFaultIsNeitherARefusalNorAMissingItem`, `TestMover_Edit_AScanOrStatFaultIsNotARefusal`, `TestMover_Withdraw_ARemoveFaultIsNotARefusal`, `TestMover_VerifyPremise_ARewriteFaultIsNotAMissingItem`). The dependents scan reads the root and every `processing/cycle-N/`; an unreadable claim directory is a fault, and an unreadable or malformed item names no dependency, as it names none to the loader and the dispatch gate (`TestMover_Withdraw_AnUnreadableClaimIsAScanFaultAndUnreadableItemsNameNoDependency`).
- **`LegacyPrefix` is spelled once.** The host's `TestInboxMoverPrefix_OneHome` counts the quoted literal in the leaf's non-test sources, so a comment that quotes it with a leading `"` breaks the count.
- **Clean-code limits are a test.** `TestLimits_FunctionsFilesAndNestingStayWithinTheBar` holds every function under 50 lines, nesting at 4 or less and every file under 800 lines. Comments inside a function count toward its length; its doc comment does not.
- **Preserved quirks stay pinned.** The code marks the ones a reader would otherwise "fix": the bad-state line that omits quarantine (`TestPromote_BadState_MessageStillOmitsQuarantine_AndQuarantineIsValid`), `intPtr`'s leading-digit parse (`TestIntPtr_StrPtr_FoldLifecycleMessage`), the counter reset before the quarantine-release rename (`TestReleaseFromQuarantine_CounterResetPrecedesRename`), the route check before the cycle check in `Claim` (`TestClaim_ConsoleRouteCheckPrecedesCycleValidation`), `RecoverOrphans` recovering every dir when the active cycle is unreadable (`TestRecoverOrphans_UnreadableCycleState_RecoversTheLiveDir`), and an unreadable cycle dir releasing nothing. The full list, with the reason each is kept, is in decomposition unit 06.

## Findings

- **`inboxmover-promote-mkdir-fail-loud`** ([code audit 2026-07](../../research/code-audit-2026-07/README.md)): a destination mkdir failure was returned as a NoOp success, stranding the task in `processing/`. It became `ErrMvFailed` with the item left in place.
- **The extraction (ADR-0103 unit 06)** split `Promote` (113 lines), the drain (114) and `RecoverOrphans` (52) to meet the function limit, folded three copies of the `*.json` walk into one iterator, and folded the bump and the continuation shed into one rewrite instead of two renames. The measurements and the review folds are in decomposition unit 06.
