# internal/cli/phasecmd

> Covered elsewhere: the self-check shares the host gate's verifier ([ADR-0034](../adr/0034-unified-deliverable-contract.md)); `phase lint` ([ADR-0035](../adr/0035-unified-phase-descriptor.md)); `phases create` and the envelope ([ADR-0038](../adr/0038-structured-phase-plugin-system.md), [phase-plugin-system.md §3.5](../phase-plugin-system.md)); the docs floor in `phase verify build` ([ADR-0077](../adr/0077-docs-floor-for-architecture-changes.md) addendum); declared effects ([ADR-0100](../adr/0100-declared-deliverables-gate.md)); the frozen-pin reachability gate (the row in [runtime-reference.md](../../operations/runtime-reference.md)); the `phase-observer` root ([decomposition/12-phaseobserver.md](../decomposition/12-phaseobserver.md)); the coherence checks themselves ([internal-phasecoherence](internal-phasecoherence.md)). This page keeps the package-level detail those do not.

## Purpose

`internal/cli/phasecmd` holds the `evolve` subcommand handlers for the phase subsystem: `phase` (with its `verify` and `lint` subcommands), `serve-phase`, `phases` (`list`, `validate`, `check-coherence`, `check-artifact-coherence`, `add`, `create`), `phase-order`, `phase-inventory`, `phase-observer` and `phase-watchdog`. Each exported `Run*` has the standard subcommand signature and is wired in `cmd/evolve/registry.go`. The logic lives in the `internal/*` packages these handlers call.

## Design

- **Extracted from `cmd/evolve`.** The handlers left a large `package main` so the composition root shrinks and each handler is directly testable. Nothing imports `cmd/evolve`, so the split carries no import-cycle risk. Shared helpers (`EnvOrCwd`, `FilterEvolveEnv`) come from `cmd/evolve/cmdutil`. Tests snapshot the phase registry with `registry.SnapshotForTest`.
- **Built-in phases self-register.** `phase.go` blank-imports every built-in phase package, and each one registers in its own `init()`. A new built-in phase is a new package plus one import line; there is no dispatch switch to edit.
- **`evolve phase <name>` protocol.** stdin carries one `PhaseRequest` JSON object, stdout one `PhaseResponse` JSON object, stderr diagnostics. Exit 0 on success, 1 on a runner or marshal error, 10 for a missing or unknown phase, 11 for unparseable stdin. On a runner error the partial response is still printed, so the parent can read its diagnostics. The same binary serves as the in-process runner and as the target of the per-phase subprocess override `EVOLVE_PHASE_<NAME>_BIN` (`adapters/runner.PerPhase`), so a phase can be implemented in any language that speaks this protocol.
- **`evolve serve-phase <name>`** wraps the same handler in `phaseproto.ServeStdio` and pairs with `phaseproto.SubprocessRunner`: one request envelope line in, one response or error envelope line out, one process per invocation. A handler error travels as a `CodeHandlerError` error envelope with exit 0, because the envelope is the response. Exit 1 means a framing or I/O failure, 10 a bad argument.
- **`evolve phase verify`** is the self-check every agent's Deliverable Contract tells it to run.
  - Exit 0 well-formed, 1 confirmed violation (the agent must fix it), 2 infra ambiguity (callers fail open), 10 usage error.
  - The phase positional is taken before flag parsing, so `verify build --workspace X` and `--workspace=X` both work.
  - Contracts resolve through the merged catalog (`phasespec.MergedCatalog`: built-in registry plus phase-root overlays), the one the host gate uses. A catalog-load failure falls back to `phasecontract.BuiltinResolver`, so built-in phases always verify.
  - `--evolve-dir` defaults to `<project>/.evolve` from the root the resolver used, so orchestrator deliverables, the persisted cycle state and the inbox a declared effect is judged in all resolve against one project.
  - The PhaseIO stage comes from `config.Load` over the registry and the filtered env, as the host gate resolves it ([ADR-0050](../adr/0050-modularization-and-unified-phase-io.md) §3.8). An unreadable registry falls back to env and code defaults.
  - Only a contract that declares conditional explanation sections or effects reads the persisted cycle state. With a workspace, the per-run mirror (`core.RunStateFile`) wins, because under fleet lanes the global state file holds whichever run wrote last. Without one, `core.ResolveCycleStatePath` applies.
  - `verifyDeliverable` adds the ADR-0077 docs floor for `build` and the frozen-pin reachability gate for `tdd`, each only with `--worktree`, since the worktree is the one place the diff and the import graph exist. The changed-path set is `core.ChangedWorktreePaths`, the derivation the host-side docs-floor reviewer uses. The frozen-pin gate emits the stable code `unreachable_frozen_pin`.
- **`evolve phase lint`** reuses the runtime path (discovery, `ValidateUserSpec`, `FromSpec`) and adds the soft checks in `softLintWarnings`, which `phases create` shares: an evaluate phase with no required sections, no `outputs.files`, and unknown categories.
- **`evolve phases`** exits 0 ok, 1 I/O error, 2 validation failure, 10 usage error. `list`, `validate` and the two coherence checks are read-only. `add` scaffolds `.evolve/phases/<name>/` (`phase.json`, `agent.md`, `profile.json`). `--profile-dir` and `--persona-override` are flags of `evolve phases` itself, so they come before the subcommand verb.
  - `validate` prints per-phase verdicts on stdout and discovery warnings on stderr. It also checks profile provenance: each profile in `--profile-dir` (default `<project>/.evolve/profiles`) without `generated_from` prints `WARN: profile <name> missing generated_from` on stdout. That is advisory (exit 0) unless `--strict-provenance` makes it exit 2. An eval greps `missing.*generated_from`, so the wording is an output contract.
  - `check-coherence` (persona `tools:` against profile `allowed_tools`) and `check-artifact-coherence` (persona `output-format` artifact against profile `output_artifact`) print one line per violation and exit 0; `--strict` makes any violation exit 2. `--persona-override <path>:<name>` substitutes one persona file.
- **`evolve phases create`** prints one JSON envelope (`createEnvelopeOut`) on stdout, so an LLM caller self-corrects from `errors` and `hint` without screen-scraping. Exactly one of `--spec` and `--mint` is required, and at most one input may read stdin. `--mint` takes an advisor `router.MintSpec` plus a `name`, because a runtime mint carries its name on the plan entry, not in the spec; the prompt becomes the persona body and its first non-empty line the description. After the write, the phase inventory is force-rebuilt so the next cycle's advisor sees the phase.
- **`phase-observer`** is the composition root of the manual stall observer ([ADR-0103](../adr/0103-component-breakdown-program.md) unit 12). It parses argv once, arms SIGUSR1 (the subagent has exited), SIGINT and SIGTERM to close the shutdown channel, builds a stderr-only Signal Center through `signalcenter.ConsoleSink` (the one home of the console's WARN threshold), defers its `Flush`, and hands `phaseobserver.Run` a Config. The engine reads the Center late through `Config.Signals`; a nil Center is the Null Object. The orchestrator's auto-spawned observer is the in-process `adapters/observer.CoreAdapter`, which reads its own `RecoveryStage`; nothing spawns this subcommand, so no parent injects the stage key today.
- **Observer and watchdog settings** come from the `observer` block of `.evolve/policy.json`; `EVOLVE_PROJECT_ROOT` locates the file. `observerEnvConfig` and `watchdogEnvConfig` keep their old names although they no longer read env.
- **`phase-order`** prints the registry's phase order, or `phaseorder.HardcodedOrder` when `EVOLVE_USE_PHASE_REGISTRY=0` or the registry file is missing. The project root is `EVOLVE_PROJECT_ROOT`, made absolute with `paths.AbsoluteRoot`, else `git rev-parse --show-toplevel`, else the cwd. Only the env root can be relative.
- **`phase-inventory build`** is the phase counterpart of skill-inventory (ADR-0038). Exit 0 on a cache hit or a fresh build, 10 on a bad argument, 1 on an internal error.

## Invariants

- **Self-check equals gate.** `phase verify` shares the host gate's verifier, catalog resolver, PhaseIO stage, changed-path derivation and cycle-state source. Otherwise an agent would see OK on a report the gate blocks. Pinned by `TestPhaseVerify_UserPhaseParity`, `TestPhasesCreate_VerifyRoundtrip`, `TestPhaseVerify_FailureContextPhaseIO_RespectsStage`, `TestPhaseVerify_ExplanationSectionFollowsCycleState` and `TestPhaseVerify_DeclaredEffectFollowsCycleState`.
- **Exit 1 is confirmed; exit 2 is ambiguity.** Infra trouble (a verifier error, a declared effect with no readable cycle state) exits 2 and callers fail open. A stray artifact in the worktree is a confirmed violation. Pinned by `TestPhaseVerify_StrayInWorktree_Exit1` and `TestPhaseVerify_DeclaredEffectFollowsCycleState`.
- **A missing cycle state is never a silent zero.** `persistedCycleState` returns a problem string, and each consumer states its consequence: the section check is skipped with a warning (the host gate still applies it), while a declared effect cannot be judged, so verify exits 2. Pinned by the two `...FollowsCycleState` tests.
- **The docs floor is build-scoped and needs `--worktree`.** With no worktree there is no diff and behaviour is unchanged; other phases never see the floor's code. Pinned by the tests in `phase_verify_docsfloor_test.go`.
- **The frozen-pin gate fails open.** An unparseable handoff, no module or a `go list` failure yields no violation. Only a compiler-provable import cycle turns a well-formed tdd deliverable red, and only for tests the handoff freezes (`doNotModifyTests: true`). Pinned by `TestPhaseVerifyTDD_FrozenPinCycle_Exit1`, `TestPhaseVerifyTDD_FrozenPinReachable_Exit0` and `TestPhaseVerifyTDD_FrozenPinScopeAndFailOpen`.
- **Lint never blocks.** Every `phase lint` finding exits 0; only a missing name exits 10. The runtime gates are where enforcement lives. Pinned by the `TestPhaseLint_*` tests.
- **The stall policy arms only at exact `enforce`.** `resolveStallPolicy` returns the ADR-0044 chain-backed policy for `--enforce`, or for an injected stage key equal to `enforce` (kept for a parent that does inject it). Off, shadow, unset or a typo return nil, which keeps the legacy Enforce branch and never arms a kill path. Pinned by the four tests in `stallpolicy_test.go`.
- **The liveness probe is always wired.** `ProcessAlive` is deterministic ground truth, not policy; acting on a dead process group stays Enforce-gated. Pinned by `TestParseObserverArgs_TableVerbatim`.
- **`phase-observer` keeps its exact argv lines, and Atoi errors are discarded.** A bogus pgid or cycle parses as 0, and `phaseobserver.Run` rejects a zero cycle. Pinned by `TestParseObserverArgs_TableVerbatim` and `TestRunPhaseObserver_RendersObserverCodesOnStderr`.
- **The observer's Center writes no file.** A second writer into the orchestrator's per-cycle `signals.ndjson` would interleave a second process's sequence space. `phase_observer.go` is one of the two production roots allowed to build a Center and must consume `signalcenter.ConsoleSink`, pinned in `cmd/evolve` by `TestConsoleSinkThresholdHasOneHome` and the Center-roots scan in `cmd_inbox_signals_test.go`. `TestRunPhaseObserver_FlushesItsCenterOnReturn` is a source pin, because a missing `Flush` is not observable at runtime on a synchronous Center.
- **Source-text pins on this package.** Keep these true in code and comments alike, because the readers match raw file text:
  - `phase_observer.go` must not contain `os.Getenv("EVOLVE_PHASE_RECOVERY")` and must contain `PHASE_RECOVERY_STAGE` (`go/acs/cycle12`). The stage key is spelled `"EVOLVE_" + "PHASE_RECOVERY_STAGE"` so the whole key never appears as a string literal, which the flagreaders guard would flag, and it carries the `// SSOT IPC-protocol-allowed` marker.
  - `phases.go` must not read `EVOLVE_PROFILE_DIR` or `EVOLVE_PERSONA_OVERRIDE` through `os.Getenv` (`go/acs/cycle16`).
  - `phase_verify.go` must name `VerifyBuildWithChangedPaths` and `ChangedWorktreePaths` (`go/acs/cycle1150`), and it is one of the Center-less `config.Load` sites that `TestCenterlessConfigLoadSitesArePinned` lists.
  - `phase_observer.go` must contain `defer signals.Flush()` (`TestRunPhaseObserver_FlushesItsCenterOnReturn`).
- **`phases create` never writes outside what the pipeline reads.** The spec is untrusted LLM input. The persona path must resolve inside `agents/`, as defense in depth over `ValidateUserSpec`'s kebab-case agent floor, and an existing persona is never overwritten. `--root` must be a configured discovery root or a path inside the project, so a rollback's `RemoveAll` can never reach an arbitrary directory. Pinned by `TestPhasesCreate_RejectsTraversalAgentName`, `TestPhasesCreate_RefusesPersonaOverwrite` and `TestPhasesCreate_RejectsRootOutsideProjectAndRoots`.
- **Rollback removes only what this invocation created.** A pre-existing phase directory may hold operator files, so only `phase.json` is removed from it. Pinned by `TestPhasesCreate_RollbackPreservesPreexistingDir`. Check-then-write is not atomic across concurrent `create` runs; that is accepted for a single-operator CLI, and `atomicwrite` keeps each file write atomic.
- **The collision check fails open on the registry.** An unreadable registry still lets the user roots be checked, following the rule that a lookup layer degrades rather than blocks.
- **The envelope is always valid JSON**, even when marshalling it fails, because it is a machine contract.
- **`phases add` validates the name before any mkdir**, through `ValidateUserSpec`'s kebab-case floor, which closes path traversal. Pinned by `TestRunPhases_BadName`.

## Findings

- **Flag swallow.** The generic `reorderArgs` helper grouped flags together and let a space-separated flag swallow the next flag as its value, so `verify build --workspace X` mis-parsed. Taking the positional first fixed it. `TestPhaseVerify_SpaceSeparatedFlags` is the regression.
- **cycle-1150**: the ADR-0077 blocking-grade classifier had no production caller, because `phase verify build` never saw the diff, so an architecture-class build with no docs passed the agent's own self-check. See the ADR-0077 addendum. `phase_verify_docsfloor_test.go` drives the real CLI over a real git worktree rather than an internal seam that was already green.
- **cycle-644, cycle-1238**: a frozen test pinned a call that could only build by closing an import cycle, and the build phase spent a whole cycle discovering it. Cycle-1238 wired the reachability gate into `phase verify tdd`. `phase_verify_frozenpin_test.go` is the permanent guard, since a cycle's ACS predicates leave with the cycle.
- **The never-injected stage key**: renaming the observer's stage read to a split-const key that no parent injects silently disabled the manual `--enforce` path while every deterministic gate stayed green. Review caught it ([ADR-0063](../adr/0063-autonomous-loop-integrity-hardening.md), #216). The fix made `--enforce` itself the live signal and added the behavioural tests in `stallpolicy_test.go`.
- **cycle-16**: `--profile-dir` and `--persona-override` replaced the `EVOLVE_PROFILE_DIR` and `EVOLVE_PERSONA_OVERRIDE` reads in `phases.go` ([control-flags.md](../control-flags.md)).
- **cycle-119**: a relative project root makes a worktree agent and the in-process bridge resolve the same artifact path to different places, which caused an artifact timeout. `phase-order` absolutizes `EVOLVE_PROJECT_ROOT` through `paths.AbsoluteRoot` for that reason.
- **cycles 274/277**: pane echo is not proof of liveness, which is why the process-liveness probe is always wired ([internal-recovery](internal-recovery.md) Findings).
- **Unit 12 review fold R1**: the subprocess root first re-spelled the console's WARN filter, giving the threshold two homes. `signalcenter.ConsoleSink` became the one home. See decomposition/12-phaseobserver.md.
