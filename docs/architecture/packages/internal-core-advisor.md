# internal/core/advisor

> Extraction record, API and test plan: [04-advisor.md](../decomposition/04-advisor.md) (unit 04 of [ADR-0103](../adr/0103-component-breakdown-program.md)). Decisions: [ADR-0024](../adr/0024-conditional-ship-gate-floor-and-phase-advisor.md) (the upfront whole-cycle plan) and [ADR-0052](../adr/0052-advisor-maximization.md) (identity, recursion guard, re-plan, recall, recon, capture, span, replay). This page keeps the package-level detail those do not.

## Purpose

The phase advisor is the LLM brain behind `router.Proposer` (per-transition advice) and `router.Planner` (the upfront whole-cycle plan and the post-scout re-plan). It composes the prompt, dispatches the router persona through the router profile's CLI fallback chain, persists a redacted capture and a decision span, and parses the strict-JSON answer. Every output is advisory: the router clamp re-validates it against the integrity floor, and any failure returns an error so the caller degrades to the static path.

## Design

- **Leaf under core.** It imports the standard library and fourteen named internal packages, never `internal/core`. Core adapts its Bridge to the leaf-owned `Launcher` port once, so the brain never names a core type. It never runs git (core injects its reader as `RecentFiles`) and never writes stderr: it reports through six `advisor.warning` codes under module `advisor`. `core.AgentIdentity` and `core.AdvisorSpan` are aliases of `Identity` and `Span`.
- **One closed `decision` enum**: plan (the zero value), replan, proposal. `decisionRows` holds every per-call literal: contract, capture kind, completion, error prefix, signal origin and span depth. The artifact name is projected from `phasecontract.ArtifactName`, so the contract and artifact pair is spelled once. Because the kind is closed, the `<kind>` token in the capture filenames cannot be built from outside, which retired a runtime path-safety check.
- **`Identity` is a shared Value Object.** The phase advisor and the failure advisor both select their brain by the same fields (CLI, model, profile, persona, agent label), so one struct holds them. It is deliberately not the launch call: the phase advisor launches under `context.Background`, while the failure advisor threads its caller's context. 04-advisor.md records that an orchestrator cancellation therefore cannot reach an in-flight advisor launch.
- **Call pipeline**: compose, preflight (nil launcher, then empty workspace, then the depth guard), profile path, chain dispatch, capture, parse, then report the mint drops. The plan prompt is composed before the guards run, matching the pre-extraction argument order.
- **Chain dispatch** goes through `llmroute.Dispatch`, the same walk the runner uses for every phase. `identity.CLI`, not the profile's `cli`, is the primary, so the composition root's bench-aware CLI swap holds. The chain comes from `cli_fallback` in `.evolve/profiles/router.json`, whose path is projected from `paths.EvolveDirOf`.
- **Skill overlays** resolve per attempted CLI, on the same contract as an ordinary phase dispatch. The identity's Model is tier-shaped (`deep`, `top`), so it serves as both the model and the tier selector. The default resolves over the zero `policy.Policy`, which gives the compiled defaults (deep/top → `fable`); the operator's `policy.json` overlay block does not govern the advisor's own dispatch. `WithOverlayResolver` is the seam to change that, and no production caller passes it yet (04-advisor.md, operator question 1).
- **Two plan-prompt paths.** The persona path (production) is the persona body, then `# This cycle`, the routing context, the optional recon digest, the catalog, the response schema and the absolute artifact instruction. Without a persona the legacy inline framing (`buildPlanPrompt`) is used. Both call `writePlanResponseSchema`, so their response contracts cannot diverge.
- **Routing context order**: cycle header, goal, CLI health, objective signals (signal lines, carryover todos, recall memory), optional phases, unavailable phases, and the rubric ending with the FORBIDDEN line.
- **Deterministic prompts, for prompt-prefix caching.** Every section renders sorted or in a stable order, and an empty section emits nothing. The routing prompt adds the failure vocabulary only on a failure transition (post-retro, or audit FAIL), so happy-path prompts stay byte-identical. The goal is stable across a run, so it renders ahead of the per-cycle sections.
- **The rubric is a projection** of the routing config the kernel walks: `conditional_mandatory` rules with the op negated (the rule says when a phase is pinned; the rubric says when it may be skipped), `insert_when` triggers, and `rubric_hint` lines. A threshold therefore cannot disagree between the walk and the prompt. Only the FORBIDDEN line is hardcoded, because it is a kernel invariant rather than phase data.
- **Catalog.** Cards carry the phase spec's advisor-facing metadata ([ADR-0038](../adr/0038-structured-phase-plugin-system.md)). Judging relevance is the model's job; Go only bounds the token cost. The menu biases toward selecting over minting, because a selectable phase already has a tuned persona and profile. At most `MaxEnrichedCatalogCards` cards render enriched. Over the cap, a stable partition gives the slots to optional cards with metadata, then optional cards without, then spine cards, which run through the mandatory config however they render. Overflow is pointed at the Core Values table and `.evolve/phase-inventory.json`. A card with per-phase guardrails renders its `allowed_clis` and `model_tier_envelope`, so a `{cli, tier}` proposal has the legal bounds.
- **On-demand index.** Phases that declined an enriched slot are named in one line. Hiding a phase is not removing it: a phase absent from the prompt cannot be selected at all.
- **Recall memory** (the last failure's reason and the lessons that match it) is pre-computed by the orchestrator, which owns the knowledge-base lookup, so the render stays pure.
- **Recon digest**, gated by `cfg.ReconDigest`. Off means no gather and no render, so the prompt is byte-identical. The gather fails open.
- **Pure parsers.** `ParseProposal` and `ParsePhasePlan` take the last balanced JSON object or array (`LastBalancedSpan`, which skips delimiters inside JSON strings), so a fence, surrounding prose or an echoed example before the answer does not matter. They stay Center-free because resume, replay and the routing-eval corpus call them and must emit nothing. The unexported `parseFailure` carries `fields.cause` out without an exported error type, and mint drops return as data (`ParsedPlan.RejectedMints`) for the entry point to report once. The plan judge and the retry adjudicator reach `LastBalancedSpan` through core's facade.
- **Minting.** `MintConfigsFrom` collects every entry with a mint block, whatever its `run` flag. Registration (wiring the phase into runners, catalog and routing) is separate from dispatch (whether it runs this cycle, which `run` governs), so `run:false` reserves a phase without running it. It maps only the name, inline prompt, tier, CLI, `writes_source` (default true) and the SELECT metadata; the registrar later forces Optional and clamps tier and CLI.
- **`SanitizeTier`** projects `modelcatalog.CanonicalTiers` rather than copying it. Unlike `policy.TierRank`, which accepts `opus`/`sonnet`/`haiku` for an operator pin, it drops an advisor-emitted alias outright, keeping the advisor on abstract tiers.
- **Replay.** `ReplayPlanFromResponse` runs the same parse and `router.ClampPlanToFloorWith` pair as the live path, so a recorded response is proven against the real floor, not a parallel reimplementation. The routing-eval golden corpus builds on it.
- **`RePlan`** plans again once scout's handoff has populated `in.Signals`, so need is measured rather than inferred from the goal text. It writes `routing-replan.json` and stamps `replan_depth=1`. The orchestrator gates it with `cfg.RouterReplan` (`core/cyclerun_replan.go`).
- **Capture artifacts**: `advisor-prompt-<kind>.txt` (redacted), `advisor-response-<kind>.txt` (redacted, otherwise untransformed so replay reparses it to the same plan) and `advisor-span-<kind>.json`, whose keys follow the OTel GenAI semantic conventions so a collector can ingest it directly.
- **Signals.** The Center is read through an accessor at every use; a nil accessor or a nil Center reports nothing. The `fields.step`, `fields.cause` and `fields.op` values are constants from which both the emit sites and the registered reasons are built, so the stream and the generated signal-codes.md cannot drift.
- **A nil launcher is deliberately not a Null Object.** Every launch then fails with `<prefix>: nil bridge`, the fail-safe the orchestrator degrades on.

## Invariants

- **Error texts are the orchestrator's printed texts**: the decision's prefix plus the preflight, launch or parse error. `TestAdvisor_ErrorTextsAreTheOrchestratorsStderrText`.
- **Preflight order** is launcher, workspace, depth, profile; a refusal reaches neither the profile loader nor the launcher. `TestLaunch_PreflightOrderIsBridgeWorkspaceDepthProfile`.
- **Compose before the guards**, so a recon fault reports ahead of a preflight refusal. `TestComposePlanPrompt_ReconGitFaultWarnsOnceAndTheDigestDegrades`.
- **Capture before parse**, so an unparseable response is still recorded and replayable. `TestLaunch_CapturesEvenWhenTheResponseIsUnparseable`.
- **Capture is fail-open.** A forensic failure must never become a routing outage, or a full disk would degrade the whole cycle to the static path. Each failed artifact is one `ADVISOR_CAPTURE_WRITE_FAILED`, the rest are still attempted and the decision still returns. The span's marshal and write faults fold into one warning under `fields.op`; `op=marshal` is dormant because a `Span` always marshals. `TestCapture_RedactsPersistsAndWarnsPerFailedArtifact`, `TestCapture_SpanOpChainRoutesMarshalAndWriteThroughOneWarn`.
- **Only the persisted copy is redacted**; the prompt the model reasons over is untouched. Same test.
- **The span's SHAs are the SHA-256 of the persisted redacted bytes** and must equal the ledger's `bindArtifactSHA`, which reads the file. That holds because core injects its atomic temp-file-plus-rename writer. `TestPlan_RecordsDecisionSpanMetadata`.
- **`replan_depth` and `tokens` are always emitted**: depth 0 means the initial plan, and zero tokens means no telemetry resolved, not absence. Same test.
- **Profile reads.** An empty path reads nothing; an absent file is the silent single-CLI degrade; any other read or parse fault is reported, because the configured fallback chain is then silently narrower than the operator believes, and the dispatch still runs once on the primary. `TestLaunch_ProfileLoadFaultWarnsOnceAndAbsenceIsSilent`.
- **Worktree fallback.** The worktree is the cycle's active worktree, else the workspace, because the tmux driver refuses an empty worktree under `EVOLVE_FLEET`. `TestLaunch_ThreadsWorktreeArtifactContractCompletionAgentCycleEnv`.
- **Recon fails open.** A reader fault is one `ADVISOR_RECON_GIT_FAILED` and yields no file facts; the goal, backlog and carryover facts come from the `RouteInput` and survive. An empty project root reads nothing and is configuration, not a fault. `TestComposePlanPrompt_ReconGitFaultWarnsOnceAndTheDigestDegrades`.
- **Recursion guard.** A minted phase may never assume a control-plane identity (`router`, `evolve-router`, `advisor`, `phase-advisor`, `failure-advisor`, `evolve-failure-advisor`, matched trimmed and case-insensitive): a minted router would let a brain schedule a brain and break the compose-versus-execute layering (ADR-0052 D1). The denylist is the primary guard; the preflight depth check (`EVOLVE_ADVISOR_DEPTH`) is defense in depth. `TestMintConfigsFrom_RejectsAdvisorRoleMint`.
- **A mint drop is reported once, at decision time**, never on resume or replay. `TestPlan_EmitsMintRejectedOncePerDropWithTheDecisionStamp`, `TestReplayPlanFromResponse_EqualsParsePlusClampAndDropsAreSilent`.
- **Exactly the four canonical tiers survive `SanitizeTier`**, and the downstream clamp trusts that instead of re-validating. `TestSanitizeTier_KeepsExactlyTheFourCanonicalTiers`, which also pins that `parse.go` never spells the list itself.
- **The artifact path in the plan prompt is absolute** and equals `LaunchRequest.ArtifactPath`. A relative path lands in the REPL's cwd, which under claude-tmux is not the workspace. `TestComposePlanPrompt_PersonaCompositionAndAbsoluteArtifactPath`.
- **Compose-time stamps.** `ComposePlanPrompt` is the entry the core test facade reaches with an arbitrary artifact name, so it maps anything but the re-plan artifact to Plan. Production composes from its decision directly, so `RePlan`'s compose-time events carry the re-plan stamp. `TestComposePlanPrompt_ReconGitFaultWarnsOnceAndTheDigestDegrades`.
- **Every decision completes on its artifact.** Each prompt tells the model to write the artifact, so the scrollback holds only the prompt's echoed example. `TestDecision_TableProjectsTheContractRegistry`.
- **Rubric exemptions.** A conditional rule pins only while every clause holds, so each clause's negation renders as its own exemption line. `negateOp` accepts word-form ops as well as the symbolic ones `parseCondRule` stores, so an in-process caller cannot lose a line; an unknown op renders no line rather than a wrong one. `TestWriteRubricLines_ProjectsTheRoutingConfig`, `TestOpSymbolAndNegateOp_Tables`.
- **Carryover todos** sort by rank, then recency, as a stable sort of a copy: ties keep on-disk order and the caller's slice is never mutated. An unknown priority ranks 0, so it sorts last without being dropped. The ranks bind the carryover unit's vocabulary (P0 blocking, P1 lesson and prescription, P3 memo default) plus the legacy word forms. At most `MaxCarryoverTodosInPrompt` render, with a trailer counting the rest. Each action is capped at 600 runes, which also bounds oversized entries already on disk that creation-time caps cannot shrink. `TestWriteCarryoverTodos_OrdersByRankThenRecencyCapsAtTwentyAndSixHundredRunes`, `TestCarryoverPriorityRank_BindsToTheCarryoverVocabulary`.
- **The goal is capped at `MaxGoalTextRunes`**, so an oversized pasted goal cannot push the catalog and rubric out of the context window. `TestTruncateGoal_CapsAtTheAdvisorBound`.
- **`LaunchRequest`'s json keys match the bridge's**, so the launch goldens replay through it, and the tests build it positionally so a new field breaks the build and the core adapter is revisited. `TestLaunchRequest_GoldenPerDecision`, `TestRequestShapes_HaveExactlyTheDeclaredFields`.
- **Leaf-ness.** `importgraph_test.go` rejects any undeclared internal import, any third-party import, and the spellings `os.Stderr` and `advisor.New(` anywhere in non-test source, comments included. Core's `TestPhaseAdvisor_OneConstructionSite` pins `advisor.New(` to `core/phase_advisor.go`.
- **Clean-code limits** are a test (`limits_test.go`): functions under 50 lines, counting comments inside the body; nesting at most 4; files under 800 lines.

## Findings

- **cycle-210**: a relative plan-artifact path landed in the REPL's cwd, which under claude-tmux is not the workspace, so the bridge never saw the file. The prompt and the launch now name the same absolute path.
- **cycle-283**: a benched CLI family was discovered one phase at a time. The CLI-health section lets the advisor plan around it: fewer inserts routed there, scope sized for the fallback. A quota wall renders as `WALLED/unavailable`.
- **cycle-435**: the advisor launched once with no fallback, and an `agy-tmux` exit 81 failed it. The launch now walks the router profile's chain through `llmroute.Dispatch` ([internal-llmroute.md](internal-llmroute.md)).
- **cycle-436**: per-phase `{cli, tier}` proposals and their guardrails ([internal-router.md](internal-router.md)). The catalog card projects each phase's own guardrails so a proposal is not made blind.
- **cycle-505**: the carryover section rendered an insertion-order `todos[:20]` prefix, so the newest, most severe items (a leak among them) hid behind "N omitted". The rank-then-recency sort replaced it.
- **token-waste #2**: persona-less phases were offered as optional and proposed from memory. They are filtered from the optional list and named, with the reason, in the unavailable section.
- **#293**: the persona path never rendered the response schema (mint block, tier policy), so production prompts lacked it while the legacy path had it. Both paths now share `writePlanResponseSchema`.
- **Catalog crowding**: 53 never-selected cards crowded out the 12 enriched slots. Declining fixed that; the on-demand index keeps the declined phases discoverable, so one invisibility defect was not traded for another.
- **2026-09-14, cycles 1673–1677**: the proposal still completed on REPL-idle stdout while its prompt asked for `routing-proposal.json`, so the model wrote the file, the kernel read the scrollback, and every proposal was `ADVISOR_RESPONSE_UNPARSEABLE`. Every decision now completes on its artifact. See [the incident record](../../incidents/2026-09-14-router-proposal-read-the-scrollback.md).
- **Unit 04 extraction**: the file's only stderr line (the dropped-mint print, repeated on every re-parse) became one `ADVISOR_MINT_REJECTED` at decision time, and five silent fault paths became visible, among them the per-transition Propose path, whose errors the router strategy swallowed.
- **Token telemetry**: the advisor's own token usage was dropped before (only its cost was captured elsewhere). The span now records it.
