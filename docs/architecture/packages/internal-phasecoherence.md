This page keeps the package-level detail those do not.

## Purpose

`internal/phasecoherence` reports drift between surfaces that together define a phase but are edited by hand: persona frontmatter (`agents/evolve-<name>.md`), profiles (`.evolve/profiles/<name>.json`), and the provenance header an artifact carries. It is the retrospective's Invariant-1 meta-gate. It only reports and never edits what it inspects. Its test files also hold live-tree guards that run in the ship-time repo-contract pack (`repoContractPackages`, `internal/phases/ship/repocontract.go`).

## Design

- **Three checks, one record.** `Check` (pairing and tools), `CheckArtifactNames` (output artifact) and `CheckProvenance` (header fields) all return `[]Violation`. The persona checks iterate personas, not profiles, so a profile without a persona is silent there. The live-tree pairing test covers that direction.
- **Inputs are filesystems.** `Options.AgentsFS` is a root that contains `agents/` (the `prompts.Loader` layout). `Options.ProfilesFS` holds `<name>.json` at its top level (the `profiles.Loader` layout). `Overrides` substitutes an OS file for one persona, so a caller can check an edited persona before it lands.
- **Tools check.** Only the `tools:` frontmatter line counts. `tools-gemini:` and `tools-generic:` are out of scope, because multi-CLI coherence is a non-goal. Names compare on the part before `(`, so `Bash` matches `Bash(x:*)` and `Skill` matches `Skill(code-review-simplify)` in both directions. `disallowed_tools` is not consulted. Kind `disallowed` is a persona tool the profile does not allow. Kind `undeclared` is a profile tool the persona omits, reported once per normalized name.
- **Artifact check.** The persona side is the first token ending in `.md` on the `output-format:` line, since later prose may name other files. Both sides compare by basename: a persona token may be dir-qualified (`learn/reflector-synthesis.md`), and the profile path carries `{cycle}` template directories.
- **Provenance check.** The header is `<!-- evolve:provenance phase=… cycle=… tree_sha=… inputs_digest=… -->`. `phase` and `cycle` are always compared. `tree_sha` and `inputs_digest` are compared only when the expectation is non-empty. `tree_sha` is also compared with the ledger entry whose cycle and canonical role match (`build`/`builder` and `audit`/`auditor` are aliases). The ledger path comes from `paths.Resolve(os.Getenv, "")`, so the result depends on `EVOLVE_PROJECT_ROOT` and `EVOLVE_LEDGER_OVERRIDE`.
- **Severity vocabulary.** Persona drift is `WARN`, and its messages use the eval vocabulary (`contradiction`, `mismatch`, `disallowed`, `undeclared`). A missing provenance header is `WARN`. A provenance field mismatch is `error`.

## Invariants

- **Persona drift is a WARN, never a hard gate.** The eval that introduced the checks requires exit 0 on the live tree, because the goal is visibility. Pinned by `TestCoherence_UnpairedPersonaWarns` and the tools tests.
- **An unpaired persona WARNs unless it is exempt.** A persona without a profile cannot be dispatched and dies with exit 10 at launch if routed, so silence is not acceptable. `-reference` personas are documentation and are never dispatched. A persona whose frontmatter says `dispatch: none` (the operator playbook) runs outside the profile system. Pinned by `TestCoherence_ReferencePersonaIsDocumentation` and `TestCoherence_DispatchNonePersonaExempt`.
- **`dispatchNone` fails toward the WARN.** An unreadable or unparsable persona returns false. Pinned by `TestDispatchNoneDirectBranches`.
- **No `allowed_tools` means no constraint.** An absent or empty list skips the tools check. Pinned by `TestCoherence_ProfileWithoutAllowedToolsSkipped` and `TestCoherence_EmptyAllowedToolsList`.
- **Configuration errors fail loudly.** A nil filesystem, a missing `agents/` directory (a wrong root, not an empty result), malformed profile JSON and an unreadable override file all return an error. A persona missing from `AgentsFS` with no override is skipped. Pinned by `TestCoherence_NilAgentsFSErrors`, `TestArtifactCoherence_OverrideReadErrorReturnsError`, and the `Missing*Errors` and `*MalformedProfileJSON` tests.
- **A declared artifact with no profile contract WARNs.** When the persona names an output artifact and the profile has no `output_artifact`, the check reports it rather than skipping it. A persona that promises an artifact no contract polls is the same incoherence as a name mismatch. Pinned by `TestArtifactCoherence_ProfileMissingField`.
- **A non-`.md` deliverable skips the name comparison.** Beside a JSON deliverable (memo's `carryover-todos.json`), the first `.md` token names a secondary artifact, so a comparison would always report a false mismatch. Pinned by `TestArtifactCoherence_SkipsNonMdProfileArtifact`.
- **One bad `tree_sha` yields one violation.** The ledger cross-check runs only when the direct check did not fire. Pinned by `TestCheckProvenance_LedgerAndDirectMismatch_SingleTreeSHAViolation` and `TestProvenanceGate_LedgerCrossCheck`.
- **Provenance tests are hermetic.** The ledger resolves from the environment, so every provenance test points `EVOLVE_PROJECT_ROOT` at a temp root (`hermeticEnv`) and the real ledger never leaks in.

### Live-tree guards

- **Persona–profile bijection** (`TestRepoPersonaProfilePairing`). Direction A: every `agents/evolve-<name>.md` has `.evolve/profiles/<name>.json`, except `-reference` docs and the `personaOnly` allowlist. Direction B: every tracked profile has a persona at `agents/evolve-<name>.md` or `agents/<name>.md`, except the `profileOnly` allowlist. Every allowlist entry carries its reason.
- **Direction B binds only tracked profiles.** An untracked profile is a runtime mint. It never reaches a CI checkout and cannot turn main red, so it is runtime state, not repo config. The exclusion is structural, so a new mint needs no allowlist entry. `trackedProfiles` delegates to `repostate.TrackedSet`, which surfaces git's stderr, counts a staged profile as tracked (the stricter direction, with no plane-versus-CI skew) and reads only the top level, so a nested tracked profile cannot alias a same-named top-level stub. Pinned by `unpaired_tracked_test.go` and `unpaired_tracked_edge_test.go`.
- **An empty tracked set is not "no profiles".** A git pathspec that matches nothing exits 0, so an empty set on the real tree means a misresolved root or a sparse checkout. The test then binds every on-disk profile, as it does without git, which is the stricter direction.
- **Decoy tests never write into the live tree.** A phase sandbox denies writes under `.evolve/profiles`, and a test that mutates tracked config is itself a hygiene defect. `mirrorTrackedProfiles` commits the live tracked set into a temp repo, and the decoy is planted there.
- **Tracked corpora admit new files** (`TestTrackedCorpusDirsAllowNewBirths`). Every `(directory, extension)` pair tracked under `.evolve/` must admit a new file in one of the two shapes the ignore ladder uses: a new name beside the exemplar (`.evolve/evals/*.md`), or the exemplar's name in a new sibling directory (`.evolve/phases/<new>/phase.json`). The `.evolve` root is exempt because it ships an explicit per-file whitelist. `designedIgnoredPrefixes` lists surfaces whose new files are runtime state by design. `.evolve/inbox-parked/` is allowlisted rather than carved out of the ladder, because parked items are undecided and must not ship automatically.
- **One `check-ignore` call.** Every probe goes through one batched `git check-ignore` (exit 1 means none is ignored), the `dropIgnoredPaths` pattern. One subprocess per probe cost about 1.5 s on the ship-time pack's critical path.
- **Known limit of the birth test.** It asserts that some ignore rule admits the probe, not that the corpus's own carve-out does. An over-broad future negation such as `!.evolve/*/*.md` would satisfy it for the wrong reason. The ladder has no such rule today.
- **No runtime artifacts tracked** (`TestNoRuntimeArtifactsTracked`). A `.gitignore` rule governs only future files. It says nothing about a file committed before the rule or added with `git add -f`, so this test enforces what the ladder states. It stays narrow: it lists only classes with a known production writer, and each rule names that writer and the governing ignore line. General binary policy lives in `ship/binary_staging_guard.go`, and copying it here would leave two places to update. `lint-baseline.txt` is the one rule with no known writer. It stays listed so that every artifact the 2026-08-27 sweep removed stays removed. The nested-`.evolve/` rule matches only below the root, because the root corpus ships. A stale `allowed` entry fails the test, because it would pre-approve a future regression at that path.
- **Stripping keeps operational directives** (`TestAuditorStripKeepsOperationalContract`, `TestPersonaStripKeepsOperationalSentinels`). The body is stripped as the runner's dispatch path strips it (`prompts.ParseFrontmatter`, then `prompts.StripOnDemandSections`). In a tracked, dispatched persona, no line that matches the sentinel regex may sit below the `## Reference Index` marker. The regex is deliberately coarse: a false positive costs a relocation above the marker, while a false negative strips a directive from every dispatch. `pendingCuration` is empty and may only shrink. An excepted persona that becomes clean fails the test until it is removed from the list. The test requires at least 8 bound personas, so a broken `TrackedFiles` scope cannot pass on nothing.

## Findings

- **Artifact-name drift, cycle 225** (drift mode (d) in the [campaign retrospective](../../research/campaign-retrospective-cycles-215-231-2026-06-06.md)): the plan-review persona told the agent to write `plan-review.md` while the contract polled `plan-review-report.md`. Two artifact timeouts (exit 81) made the batch fatal. `CheckArtifactNames` and the tools check were added in cycle 238.
- **Unpaired debugger, cycle 270**: the debugger persona existed without a profile and died with exit 10 at launch with no earlier signal, because `Check` skipped pairs with a missing side. That produced the `unpaired` WARN and `TestRepoPersonaProfilePairing`.
- **Direct `tree_sha` check, cycles 241–242**: the cycle-241 audit found that `CheckProvenance` compared `tree_sha` only against the ledger, so a bad value with no ledger produced no violation. Cycle 242 added the direct comparison and the one-violation dedup.
- **Minted-stub storm, cycles 1402/1403/1405** (fingerprint `cd49274beab2`): Direction B bound every on-disk profile, so an untracked runtime stub (`defect-disposition-ledger.json`) turned the repo-contract pack red and blocked three audit-green ships until the identical-fingerprint ceiling halted the batch. Earlier firings had been patched with per-name allowlist entries, a ratchet that re-armed on every new mint. See the [zero-ship batch record](../../incidents/2026-08-09-zero-ship-batch.md).
- **Evals born ignored, cycles 1345/1346/1348**: see the [incident record](../../incidents/cycle-1348-evals-birth-ignored-batch-halt.md). The adversarial review of that fix produced the `inbox-parked` allowlist decision, the batched `check-ignore` and the known limit above.
- **Persona-strip lobotomy, cycles 1390–1429**: see the [incident record](../../incidents/2026-08-10-persona-strip-lobotomy.md) and [internal-prompts](internal-prompts.md).
- **Repo-hygiene sweep, 2026-08-27**: twenty runtime artifacts (about 655 KB, the oldest from cycle 104) were tracked on main. See [ADR-0094](../adr/0094-runtime-corpora-tracked-upstream.md).
- **Sandbox EPERM, cycles 1676/1679**: the decoy test wrote into the live `.evolve/profiles`, the audit sandbox denied the write, and the instrument fault was charged as a defect. See the [verification-wave findings](../../research/verification-wave-findings-2026-09-14.md).
