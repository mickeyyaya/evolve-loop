## Purpose

`internal/core` is the orchestrator. It allocates each cycle's number, dispatches the phases in order, decides every transition and failure disposition, and runs the deterministic floors that grade a phase's output before the next phase may start. It also owns the batch-level blocker breaker and the boot-time recovery of a dirty main tree. It relocates build output a builder leaked into the main tree, carries audited work forward across fleet rebases and failed cycles, and connects the carryover memory to each cycle.

## Design

- **Cycle-number allocation.** `StateUpdater` is an optional storage capability, kept apart from the `Storage` port so every existing fake and adapter stays valid. With it, `allocateCycle` mints `max(LastCycleNumber, LastAllocatedCycleNumber, highest occupied go/acs/cycle<N>) + 1` through the serialized `UpdateState` read-modify-write, before any artifact exists under that number. Without it, the orchestrator takes the legacy `LastCycleNumber + 1` path above the same source floor. Resume never allocates: `RunCycleFromPhase` carries the cycle from the run record.
- **Cycle-end persist is a merge, not a write.** On a `StateUpdater`, `persistCycleEndState` replaces the state with the run's own outcome but max-merges the lease and `LastCycleNumber` with disk, keeps the disk revision (the `UpdateState` increment owns the bump), and unions `FailedAt` and `CarryoverTodos` with what peers wrote, because under `EVOLVE_FLEET` the global lock is skipped.
- **Audit-FAIL disposition at the audit chokepoint** (`decideAfterAuditFail`, [ADR-0093](../adr/0093-retry-envelope-and-terminal-retro.md)). It builds and writes the failure dossier (best-effort forensics), reads the audit's own declared class, computes the retry envelope from the policy table, and only then consults the `RetryAdjudicator` Strategy, and only when more than one action is legal. The proposal is clamped to the envelope. A granted retry re-enters `tdd` or `build` through `reentryPhase`; a decline goes to retro, which is now the terminal learning step once per cycle. A floor halt still routes to retro, so the halted cycle gets its post-mortem, but the returned `SystemFailureSignal` is what stops the loop. `emitAuditRepairDecision` makes the outcome one coded signal: WARN `CodeAuditRepairDeclined` or INFO `CodeAuditRepairGranted` with the attempt number.
- **Round-scoped audit artifacts** (`audit_round_artifacts.go`). The auditor persona pre-writes `acs-verdict.json`, and `audit.Classify` honors a pre-staged file. So every audit re-dispatch (repair round, bookkeeping regrade, ship-error recovery, debugger `RERUN_PHASE`) first renames the previous round's `acs-verdict.json` and `audit-report.md` to `*.round<N>.*` archives. The one primitive, `supersedePreviousAuditRound`, sits in the audit pre-dispatch block of both dispatch surfaces, beside `resetFloorFailReason`, never at a branch site: a branch site would cover only some re-audit paths and open a window with no verdict artifact across the re-entered `tdd`/`build` phases. The round index is the greater of the persisted `AuditDispatches` counter and the count of completed audit phases (the backstop for checkpoints written before the counter existed). The full design is in [the incident record](../../incidents/2026-09-02-repair-round-stale-acs-verdict.md).
- **Bookkeeping regrade** (`bookkeeping_regrade.go`, [ADR-0086](../adr/0086-bookkeeping-regrade-microcycle.md)). The classifier owns the reason prefixes (`defect ledger: `, `closure claim without a citation: `, and the anchored `verdict-conflict: auditor narrative=PASS|WARN` record). The producers in `internal/phases/audit` are pinned to these matchers by `phases/audit/bookkeeping_reason_singlesource_test.go`, which feeds real minted diagnostics through them. The target phase resolves through the `bookkeeping-regrade` RecoveryMap key, so catalog config may remap it; the compiled fallback is `audit`.
- **Blocker breaker** (`blocker_breaker.go`). A pure, deterministic function over a batch's failure digests, evaluated by the loop after every iteration. Rules, in evaluation order: `guard-class` (guard aborts are pipeline machinery failing by construction), `unexplained-failures` (digests with no machine-readable reason: a diagnosability breakdown), `identical-fingerprint` (Rule B: identical failure identities cannot be distinct honest defects) and `consecutive-failures` (back-to-back failed cycles, whatever their fingerprints). The first rule that trips names the halt. The breaker is task-agnostic: same-task repeats belong to S5 quarantine (`task_retry_ceiling`), so a batch of many different honest rejections never trips it. A zero ceiling disables its rule, the policy escape hatch.
- **Fingerprint ack ledger.** `.evolve/resolved-fingerprints.json` is an append-only JSON array (`fingerprint`, `resolved_at`, `resolved_by`). `LoadResolvedFingerprints` feeds `BlockerBreakerConfig.AckedFingerprints`. It is written by `evolve loop --reset --fingerprint` (`AppendResolvedFingerprint`) and by transactional inbox consumption (`ConsumePipelineDefectFingerprint`), which parses the fingerprint from an item's `consumed_by` text and falls back to its auto-filed `notes`.
- **Boot recovery** (`boot_preflight.go`). A leak into the main tree makes every later cycle's tree-diff guard FAIL against whichever phase runs first, wedging the loop until someone stashes by hand. So `runLoop`'s boot path calls `QuarantineDirtyTree`, which moves leaked tracked source into a named stash (recoverable with `git stash pop`, never discarded), and `ShipSHAMismatch`, which reports the `SELF_SHA_TAMPERED` drift at boot instead of only when ship fails. The wiring lives in `cmd/evolve/cmd_loop_boot_recovery.go`.
- **Build handoff floor** (`build_floor_reviewer.go`). Deterministic checks run as part of Build verification, so a red floor rejects the deliverable and the existing correction ladder turns it into a bounded in-phase fix; audit and adversarial review still follow as the judgment layer. The reviewer owns policy only. The engine is injected as a `BuildFloorCheckFn` (production: `DefaultBuildFloorChecks`). The engine composes:
  - `RemovalClaimFailures`, `PlaceholderTokenFailures` and `personaBudgetFailures`, which run outside `changedPackageFloorChecks` because that engine returns early when the diff yields no Go test packages. Both a build whose only claim is a deletion and a lane whose only change is a persona doc produce exactly zero packages.
  - `docsFloorWarn`, the [ADR-0077](../adr/0077-docs-floor-for-architecture-changes.md) floor. It labels with the blocking-grade classifier `docsfloor.IsArchitectureClass`, which drops test-only diffs (the WARN's main false positive), but its verdict stays WARN.
  - `changedPackageFloorChecks`, which reuses the post-build selfcheck machinery (`changedGoTestPackages` → `runBuildSelfCheck`). Packages enrolled in `.apicover-enforce` run once, under the coverage-instrumented pass in `apicoverNamingFailures`, which doubles as their selfcheck and applies CI's apicover naming floor at handoff. The rest take the plain selfcheck. The floor writes `build-selfcheck.json` for the ACS toolchain gate, and the advisory binding skips its duplicate run when the floor is enforced, so there is one go-test pass per build.
  - `addedTaggedTestFailures`, which runs every added test package under the build tags its files declare, using the same seed (`changedpkgs.ChangedFilesChecked`) and grouping (`addedtests.Groups`) as the ship gate's added-test backstop.

  The changed-path set is derived once per handoff (`changedFloorPaths`) and passed down, so the path-driven engines judge the same diff with one `git diff`.
- **Protected-surface floor** (`ProtectedSurfaceFloorChecks`). It asks the ship tripwire's question (`ship/integrity.go` `verifyNoControlPlaneEdits`) at the one phase that can still act on the answer. The membership predicate (`guards.IsProtectedSurface`) is injected by the composition root, because `guards` imports `core`.
- **Build explanation floor.** `NewBuildExplanationReviewer` is composed outside the optional reviewer seam, so a caller cannot disable or replace it. `NewExplanationLifecycleReviewer` is the last reviewer in the production chain and seals a Build output only after every earlier reviewer approved, so a rejected attempt is never frozen. The lifecycle vocabulary that `guards/integrity_surface_explanation_callsites_test.go` derives is parsed from the function declarations of `build_explanation_handoff.go`.
- **Advisor seams kept in core.** `AgentIdentity` is an alias of `advisor.Identity`, so the failure advisor and the retry adjudicator keep their spelling. `AdvisorDepthExceeded` is a dormant injectable backstop that always returns false: the `EVOLVE_ADVISOR_DEPTH` signal was retired, and the mint denylist is the only active recursion guard ([04-advisor.md](../decomposition/04-advisor.md), operator question 6).
- **ShipError has no code-to-class mapper in core.** Each call site in `internal/phases/ship` chooses the class, and `NewShipError` records it verbatim. The table in `apicover_shiperror_test.go` is transcribed from those call sites, so a drift between the table and production is a protocol regression.
- **Test-side fixtures.** `advisor_fixture_test.go` holds the one rich `RouteInput` the advisor goldens are captured over, rendering every prompt section at once. `apicover_*_test.go` files name and exercise exported symbols for the `apicover` gate ([ADR-0050](../adr/0050-modularization-and-unified-phase-io.md)). Each asserts a real behavior, never `_ = pkg.X` padding.
- **The handoff floor's text checks** (`build_removal_check.go`, `build_placeholder_check.go`, `build_persona_budget_check.go`). A removal claim is machine-read only from a fenced ```` ```json ```` block with a `removedPaths` array, taken from the build report or its promoted copy under `deliverables/`. Prose is never parsed, because a matcher on "removed" would false-block honest reports. Each claimed path is checked against the worktree and then against its Git index (`git ls-files --error-unmatch`), since a filesystem-only deletion comes back on the next checkout. `PlaceholderTokenFailures` refuses any `UPPER_SNAKE_PLACEHOLDER` slot left in the report, one failure per token per line. The persona budget check runs `./internal/prompts` only when the diff touches `agents/evolve-*.md` and that package is not already in the derived set.
- **Build-leak recovery** (`recoverBuildLeak`, tests in the integration-tagged `buildleak_recover_test.go`). A non-Claude builder is not bound by the Claude-only role gate, and the OS sandbox is off on nested macOS, so it can write into the main tree. Recovery moves that output into the worktree, stages only the relocated paths so the auditor's `git diff HEAD` sees it without pollution, and restores the main tree. The tests use a real `git worktree add`, because a fixture of two independent repos once masked a directory-rename bug.
- **Carry-forward filter** (`carryforward_filter.go`). A deterministic, zero-LLM screen. `CarryforwardCandidateLandable` runs an is-ancestor and `git cherry` patch-id supersession screen, then a real 3-way `git merge-tree --write-tree` dry run, which writes only to the object DB. `ClassifyFleetRebaseCandidate` splits a not-landable answer into already-landed and conflict for ship recovery's fleet-rebase pre-screen (`recoverFromShipError`); `evolve branches audit|prune` uses the same screen. All git goes through the `gitRunner` seam, which `carryforward_filter_test.go` scripts per subcommand (`seamGit`).
- **Composition carry-forward** (`composition_carryforward.go`, `composition_scoped_review.go`). Core's half of RUNG 0 (trivial rebase) and RUNG 2 (scoped merge review). `internal/adapters/ledger` imports core, so the snapshot, the composed-tree gate run, the verdict writer and the scoped reviewer are `Option`-injected closures that `cmd/evolve` binds; `CompositionVerdictInput` and `compositionPatchID` mirror the ledger's types. `CompositionFastPathWired` and `ScopedMergeReviewWired` let the composition root prove its wiring in a real test (`cmd/evolve/cmd_cycle_composition_test.go`). `IntersectingHunks` builds the reviewer payload on the same old-side overlap test as the wired `RunScopedMergeReview`.
- **Carryover seam** (`carryover_lifecycle.go`, [03-carryover-lifecycle.md](../decomposition/03-carryover-lifecycle.md)). An `Orchestrator` built as a literal gets its lifecycle lazily. `wiredCarryover` reads the Signal Center live, because tests apply `WithSignalCenter` after construction. The exported package-level facades run on a Null-Object lifecycle for tests and ACS predicates and carry `Deprecated:` notes naming the wired path.
- **Console lease** (`console_lease.go`, [ADR-0080](../adr/0080-runtime-console-plane-separation.md) S4). An exact-path, expiring operator waiver for the tree-diff guard, read from the git common dir and adopted once at cycle start; the cycle log records the digest of the adopted bytes.
- **Continuation-on-fail** ([ADR-0076](../adr/0076-convergence-architecture.md) C). At the preserve decision a FAILed cycle's dirty worktree is snapshot-committed onto its cycle branch, and a manifest is stamped into the workspace, but only when the carry-forward screen reads the snapshot Clean against main. The manifest is also registered under the lane's `lane-scope.json` todo ids, so a wave-planner lane with no inbox claim still leaves a binding; adoption resolves claims first and lane scope second. The adopting cycle provisions from the snapshot commit (work inherits through git history, never dirty state), keeps the original base as its review base so the cumulative work is reviewed whole, and serves the prior findings to Build. `advanceContinuationBase` then merges the pinned main tip while the merge is clean. An invalid continuation falls back to fresh provisioning, loudly. A declined binding is released at the decline site ([ADR-0085](../adr/0085-continuation-registry-release.md)).
- **`ChangedWorktreePaths`** is the exported projection of the host reviewer's changed-path derivation, so `evolve phase verify build` cannot drift from it ([ADR-0077](../adr/0077-docs-floor-for-architecture-changes.md)).
- **Persisted shapes are additive-only** (`bytestability_test.go`). The legacy JSON key sets of `State`, `LedgerEntry` and `CycleState` never change; a new field is `omitempty` and appended to its additive list, so an older file keeps its bytes.
- **`RealInboxForTest`** holds the real inboxmover functions. `continuation_adopt_inbox_test.go` (package `core_test`) injects them from `init`, because an in-package inboxmover import is a cycle while `core_test → inboxmover → adapters/ledger → core` is not.
- **Contract-block CLI escalation** (`contract_escalation.go`). A correction ladder that keeps re-dispatching the same CLI after a deliverable-contract block can burn every correction and trip the contract-gate breaker, silently demoting it from enforce to advisory for the rest of the run. Escalation retries the re-dispatch — never the phase itself — on a different CLI family: a soft overlay (`llmroute.ApplySoftOverlay`) promotes the target ahead of the profile's own chain for that one re-dispatch and reverts when the ladder ends; the profile on disk is never touched. It triggers at the contract gate's own second consecutive block (`ReviewResult.Blocks`, the breaker's own counter, never a locally re-counted ordinal that could desync from it) or a second identical remediation-carrying rejection (`ReviewResult.Remediation`, set only by evalgate); a remediation-less zero-block rejection (a capacity or task-binding failure) never escalates.
- **Only an identical contract block escalates.** Two blocks are the same defect when their `deliverable.Violation.Code` sets intersect — covering subset, superset and equal — computed from the parsed violation codes rather than the whole rendered reason text, because a whole-string compare reads a partially repaired defect set as a different defect and suppresses escalation exactly where an incapable CLI's signature is strongest. When either block yields no codes, identity falls back to `failure_digest.go`'s `normalizeReasonForFingerprint`; the zero-value "no prior block observed" case reports identity=true so a cycle that aborted mid-ladder (leaving the process-global breaker hot) still gets an escalation on the next ladder's first block.
- **A phase whose whole dispatch chain is one CLI family gets a structured re-prompt instead of nothing.** `composeContractSalvageRetry` re-dispatches the same CLI, same round, same budget, changing only the directive: it carries the contract validator's output verbatim under a distinct heading instead of a paraphrasable rejection. It is breaker-neutral (no extra dispatch, no extra correction, no `ModelRoutingCLI` change) and disjoint from escalation, so one block's budget is never spent twice.
- **`contractArtifactDetermined` is an allowlist, fail-closed classifier**, not a denylist: a violation code it has never seen has unknown repair mechanics, and the safe answer is false (skip the hash short-circuit). It has no production caller yet — it exists so a future hash-equality short-circuit has this precondition ready; building that short-circuit alongside it would be scope creep.
- **A contract-gate demotion stages an autofile intent through `dispositionrouter` rather than writing `.evolve/inbox` directly**, because a mid-flight inbox write can race `inboxmover.Claim`'s rename and resurrect a claimed item into double work across fleet lanes; `recurrence.ApplyBoundary` is the only sanctioned inbox writer.
- **Chronicle digest seeding** (`seedChronicleDigest`, called once per cycle from `planCycle`; the resolved `policy.ChronicleConfig` is injected at the composition root via `WithChronicleConfig`, and the zero-option default is `shadow`). Three modes: `off` writes and injects nothing; `shadow` assembles `DigestInput` from the committed dossier history and live failure state and writes `recent-outcomes.md` into the run workspace but does not inject `Context["recent_outcomes"]`; `enforce` does the same write and additionally carries the rendered bytes into every phase request so scout/triage render it. Best-effort throughout: a digest failure WARNs and the cycle proceeds.
- **Fleet scope resolution** (`planCycle`). `Context["fleet_scope"]` is authoritative from `<workspace>/lane-scope.json` when a supervisor or a prior attempt of this orchestrator provisioned one, over the env snapshot, so cross-lane env drift can no longer split lane identity; an absent file falls back to the env snapshot (sequential-loop byte-identical), and an env-scoped run pins its own `lane-scope.json` before any phase runs. `fleet_scope_paths` then discloses each scoped id's live inbox record path beside the id list — only PENDING ids resolve, so a consumed or non-inbox id is silently omitted rather than pointing at stale evidence.
- **`finalizeCycle`'s floor stack** runs in a fixed order after `finalizeOutcome`: the cross-artifact invariant stack (four weak deterministic verifiers over the cycle's own artifacts, purely advisory, recorded beside the verdict-coherence floor's decision without ever influencing it), the verdict-coherence floor itself (a negative verdict whose on-disk artifacts are green means the pipeline forged the verdict, a SYSTEM-level failure that halts the batch — unless a fully green, fully-valid audit report shows the mismatch was only a benign clean-exit-late-write race, which self-heals to PASS instead), the lost-landing floor (a PASS verdict attached to a cycle whose ship hit landing-queue contention and correctly routed elsewhere, keyed on the cycle's own ship artifacts rather than a HEAD delta, which in fleet mode belongs to whichever sibling landed last), and the silent-no-ship warning (phases ran but this cycle's own ship never landed and no audit-advisory block was recorded, so any worktree changes were discarded).
- **Graduated remediation** (`maybeRemediate`, between `reviewAndGuard` and `recordAndBranch`). On a FAIL verdict from a remediable, deterministic gate with rounds remaining, the builder is dispatched once per round with the gate's own report as the correction directive, then the same gate re-runs and its fresh verdict replaces the original — remediation re-earns a verdict, it never overrides one, so every downstream phase runs unchanged after it. The round cap is hard (`workflow.remediation_rounds`, zero in core's zero-value config so untouched paths stay byte-identical) and only phases in `workflow.remediable_phases` participate; `remediationDenied` refuses judgment/control phases outright regardless of configuration, because granting a re-roll against an LLM-judgment verdict would be a gamed verdict, not a fix. `CycleResult.Remediations` records every round's outcome, so a remediated cycle is never a silent PASS. The economics: a mechanical, gate-prescribed defect (missing tests, format, naming) costs a bounded in-phase fix instead of discarding and re-running a whole sound cycle.
- **Re-plan rejection telemetry** (`recordPlanRejectionsKind`, `decision_branch.go`). `ValidatePlan` runs on the raw re-plan before the floor clamp, so an unknown phase the clamp would silently drop still leaves an attributable rejection record. Each plan kind (the upfront `plan` and each post-scout `replan-<n>`) writes its own `advisor-rejections[-<kind>].json`, so accumulation across re-plans needs no read-modify-write of a shared file. Pinned by `TestReplan_UnknownPhase_RecordsRejection`, `TestReplan_KnownPhasesOnly_NoSpuriousRejection` and `TestReplan_MultipleReplans_AllRejectionsRecorded`.
- **Post-phase leak classification has three guard-only exemptions** (`cyclerun_postreview.go`). `filterRealLeaks` exempts specific legitimate main-tree writes so the guard stays armed for real escapes: `isLegitimateMainTreePath` (a phase's own `.evolve/` workspace writes / orchestrator gate state), `isScoutEvalMaterialization` (scout's contract-mandated eval writes, since scout is not a `WorktreePhase`), `isActiveMintPhasePath` (a concurrent fleet lane's registered, TTL-fresh mint write — a registry read error disables the exemption, fail-safe). Source files and both sides of a leak-disguising rename still classify as real leaks. Pinned by `TestGuardIgnoresScoutEvalMaterialization`, `TestIsScoutEvalMaterialization`, `TestIsActiveMintPhasePath`, `TestVerifiedActiveMints`, `TestGuardRecoversCatalogWritesSourcePhaseLeak` and `TestGuardStillAbortsNonSourcePhaseLeak`.

## Invariants

- **A cycle number is never reused.** The lease is minted before any run artifact exists, and a crashed run burns its number, because a burned number may have orphaned artifacts and reuse would mix two runs' state. Pinned by `TestAllocateCycleNumber_ConcurrentAllocatorsDistinct` and `TestAllocateCycleNumber_CrashBurnsNumber`.
- **The cycle-end persist never rolls back the lease.** A run's in-memory `LastAllocatedCycleNumber` is stale once a concurrent run allocates, so a blind write would let the next allocator re-mint a number another run holds. Pinned by `TestPersistCycleEndState_NeverRollsBackLease`. The outcome-record union is pinned by `TestMergeFailedRecords_UnionsDiskAndIncoming` and `TestMergeCarryoverTodos_DedupByID`.
- **Storage without `StateUpdater` behaves exactly as before the lease existed.** Pinned by `TestOrchestratorAllocateCycle_LegacyStorageFallsBack` and `TestPersistCycleEndState_LegacyStorageFallsBack`.
- **Deterministic evidence, then policy, then judgment.** The adjudicator chooses only among actions the envelope already allowed. It may be more conservative, never less, and it cannot overturn a floor halt. It is skipped when only one action is legal, so the deep tier is paid only where a real choice exists. A nil adjudicator (Null Object) still yields the policy default. Pinned by `TestDecideAfterAuditFail`, `TestDecideAfterAuditFail_AdjudicatorCannotOverturnTheFloor` and `TestDecideAfterAuditFail_NilAdjudicatorIsSafe`.
- **`audit→tdd` and `audit→build` are decision-only edges.** They sit in the one legality graph, so `decideAfterAuditFail` can schedule them and the graph stays single-sourced with `phase-registry.json` and the trust anchor. `decisionOnlyEdge` refuses them to the routing advisor, which validates its proposals through the same graph. An advisor-routed re-entry would never call `consumeAuditRepairGrant` (it keys on a reason prefix only `decideAfterAuditFail` emits), so the retry would go uncounted, bounded only by `defaultMaxPhaseIterations` (32) instead of `MaxRetries` (2). It could also route backwards after a halt, or override `audit→ship` on a passing audit. Pinned by `TestRouterCannotProposeTheAuditReentryEdges` and `TestAuditFailReentryEdgesAreLegal`.
- **The adjudicator's reasoning reaches the operator.** The clamp rejects an unjustified proposal because the justification is the adjudicator's deliverable, so the reason carries it, and a clamped proposal says it was clamped. Pinned by `TestDecideAfterAuditFail_SurfacesTheAdjudicatorsReasoning` and `TestDecideAfterAuditFail_RecordsAClamp`.
- **The repair reason is built from `auditRepairReasonPrefix`, never a literal.** `TestAuditRepairReasonPrefix_IsSingleSourced` reads `audit_fail_decision.go` as text, so even a comment in that file must not spell the quoted literal `"audit-repair: "`.
- **Audit-round retirement ordering.** `supersedePreviousAuditRound` runs before the pre-phase cycle-state write, so a round that crashes or quota-pauses has already persisted its dispatch, and its dead attempt's pre-written verdict is retired on resume instead of honored. Round 0 retires nothing, so an operator or CI pre-staged verdict keeps the honor `audit.Classify` gives it. An existing archive is never overwritten, because the first retirement holds that round's evidence; the stale file is removed with a WARN instead. If a rename fails, the stale file is removed, because a surviving stale verdict silently recreates the cycle-1603 class. Every evidence-losing outcome is reported. Pinned by `TestSupersedePreviousAuditRound_AdvancesThePersistedDispatchCounter`, `TestResumedCrashedAudit_RetiresTheDeadAttemptsVerdict`, `TestRetireSupersededAuditArtifacts_RoundZeroHonorsPreStagedVerdict`, `TestRetireSupersededAuditArtifacts_NeverClobbersAnExistingArchive`, `TestAuditRedispatch_RetiresPreviousRoundVerdicts` and `TestResumedAuditRedispatch_RetiresPreviousRoundVerdicts`.
- **The repair brief derives from persisted cycle state.** The live loop and crash-resume therefore seed the same brief. Both surfaces pass the dispatched phase (`next`), and the seeder never mutates the caller's map, because the dispatch loop reuses `ctxSnap` across iterations and an in-place write would leak a stale brief into every later phase. `AuditRepairAttempts` is a monotonic counter, not a "currently repairing" flag, so gating on it would re-inject a finished repair into unrelated later dispatches. Pinned by `TestSeedAuditRepairContext`, `TestSeedAuditRepairContext_DoesNotMutateCallerMap` and `TestAuditRepairBrief_SeededOnBothDispatchSurfaces`.
- **The bookkeeping regrade cannot be triggered or unbounded by an agent.** Eligibility reads `CycleState.AuditFailReasons`, orchestrator memory set at the `recordFloorVerdictFailure` chokepoint, never a workspace file. The once-per-cycle bound is `CycleState.BookkeepingRegradeAttempted`, consumed by the one primitive `consumeBookkeepingRegradeGrant` that both branch surfaces call. The regrade sits below the ADR-0072 floor and above the router. Pinned by `TestDecideAfterRetro_RegradeOncePerCycle`, `TestDecideAfterRetroRouted_RegradeNotRouterOverridable`, `TestDecideAfterRetro_FloorOutranksRegrade` and `TestRecordAndBranch_RegradeGrantConsumesSlotAndSchedulesAudit`.
- **Unexplained digests never count as identical.** Distinct failures collapse into the empty-evidence bucket (`|unknown|`) or the self-marked `Unexplained` bucket by construction, so the unexplained rule owns them. They do count toward the consecutive streak, which is fingerprint-agnostic by design; filtering them there would reintroduce the masking the rule exists to close. Pinned by `TestConsecutiveFailures_UnexplainedDigestsCountTowardTheStreak`.
- **The streak is keyed by cycle number.** Several digests from one cycle collapse to one entry, so a cycle that repaired twice cannot trip the ceiling-3 streak by itself. The audit-repair loop depends on this. Pinned by `TestBlockerBreaker_RepairAttemptsWithinOneCycleCountOnce` and `TestConsecutiveFailures_DuplicateDigestsForOneCycleCountOnce`.
- **The more specific rule names the halt.** `consecutive-failures` is evaluated last, so a guard-class or identical-fingerprint halt, whose reason carries an actionable repro hint, wins on overlap. Pinned by `TestConsecutiveFailures_GuardClassRuleWinsOnOverlap` and `TestConsecutiveFailures_IdenticalFingerprintRuleWinsOnOverlap`.
- **An ack is scoped to one fingerprint.** It excludes exactly that fingerprint from Rule B and breaks the streak, so a batch resumed to verify a fix does not re-halt on the history it is verifying. A different, unacked fingerprint still halts at the ceiling. Pinned by `TestEvaluateBlockerBreaker_UnackedIdenticalFingerprintStillHalts` and `TestConsecutiveFailures_AckCannotMaskAnIndependentlyTrippingHalf`.
- **Digest collection tolerates damage.** A missing or malformed `failure-digest.json` is skipped, because a PASS cycle writes none and one corrupt artifact must not disable the breaker for the rest of the batch. Pinned by `TestCollectBatchFailureDigests_ScopesAndTolerates`.
- **The consumption parser fails closed.** It anchors on the literal `fingerprint` token, so a `docs/a|b|c.md` path or any other triplet-shaped text never matches, and `ConsumePipelineDefectFingerprint` writes nothing when neither field names a fingerprint. Pinned by `TestParseConsumptionFingerprint_IgnoresUnrelatedPipeDelimitedText` and `TestConsumePipelineDefectFingerprint_ErrorsWhenNoFingerprintFound`.
- **Boot recovery never touches the loop's own state.** `.evolve/` and `knowledge-base/` churn is normal cycle activity and is never quarantined. `go/bin/evolve` is excluded twice: at classification, and again in the stash pathspec, because git may report a collapsed untracked parent directory (`go/`) that an exact-path exclusion cannot see. Boot recovery re-pins the ship binary in the same pass, so stashing it would revert to the old committed binary and reopen the SHA mismatch the re-pin heals. Pinned by `TestClassifyDirtyPaths_IgnoresLoopManaged`, `TestClassifyDirtyPaths_ExcludesShipBinary` and `TestQuarantineDirtyTree_LeavesStatusCleanAndPreservesContent`; the pathspec exclusion keeps its one-line why in code.
- **The build floor fails open on its own plumbing.** A nil engine, a missing worktree, a `go list` error, a coverage-generation error or an apicover measurement error approves with a loud WARN, because the downstream gates (ACS toolchain, apicover, CI) stay armed, and the floor must never false-block a build over its own plumbing. A test failure inside the coverage run is a real finding, never dropped. Pinned by `TestBuildFloorReviewer_ChecksErrorFailsOpen` and `TestBuildTagVisiblePackagesFailsOpen`.
- **The floor diffs against the cycle base.** The builder's protocol commits its work, so at review time (before the post-record soft reset) a `HEAD` diff is empty and the floor would approve vacuously. With no recorded base, it falls back to the `HEAD` diff plus untracked files. Pinned by `TestDefaultBuildFloorChecks_SeesCommittedBuilderWork`.
- **The protected-surface floor runs with rename detection off.** With it on, `git diff --name-only` prints only a rename's new path, so a protected file moved to an unprotected name, and weakened while it stays over 50% similar, would pass. A nil predicate fails open, since ship's tripwire stays armed. A note in `build-report.md` never clears the check, because it reads only paths. Pinned by `TestProtectedSurfaceFloorChecks_SeesARenameOutOfTheSurface` and `TestProtectedSurfaceFloorChecks_RefusesTheCycle1689Shape`.
- **The apicover floor is diff-scoped.** Only violations in files the change touched hard-fail; a touched package's older debt WARNs. The check needs a coverage profile, because apicover's enforce contract is named and executed, and without a profile every named export reads as false-green. The coverage run takes the host-wide verification single-flight (`verifylock`), the same lock as the EGPS suite, and a lock failure degrades to an unserialized run, never a skipped one.
- **Packages with no Go files under the default tags are dropped before the selfcheck.** `go test` on one is a setup failure ("build constraints exclude all Go files"), not a test failure. This is the second line of defense; the first is that modern `acs` packages are not enrolled in `.apicover-enforce` (see its rationale block). Pinned by `TestBuildTagVisiblePackagesDropsACSPackages` and `TestAPICoverEnforceDoesNotEnrollModernACSPackages`.
- **A failing package's diagnostic keeps the last 400 bytes.** `go test` writes its `--- FAIL` lines, panics and stack traces at the end, and this text is the whole story the next builder is handed. Complete output carries no elision marker, so the marker stays a trustworthy signal. Pinned by `TestBuildFloorSelfCheckFailures_KeepsTailDiagnostic`.
- **`docsFloorWarn` is read as text by an ACS predicate.** `go/acs/cycle1151` counts the lines of that function's body (`acsassert.CountInGoFunc`, comments included) that contain `docsfloor.IsArchitectureClass(` or `docsfloor.LabelArchitecture(`, and requires exactly one labeler. A comment inside `docsFloorWarn` must never spell either call with its opening parenthesis.

A phase-local `agent.md` is a scaffold for humans and does not count. Control-role detection uses the production inference (`RoleOrDefault`), never a private allowlist. Pinned by `TestRepoPhaseCatalog_MenuPhasesResolveAPersona`.
- **A missing persona skips only a genuinely optional phase.** Mandatory phases, ship-floor phases (even one mis-marked Optional) and configured-mandatory phases still fail loudly, so the skip can never weaken ship ⇒ build ∧ audit ∧ tdd. The skip is ledgered under its own kind, `optional_missing_persona_skip`, never the infra key, and is learned deterministically without dispatching a retrospective agent. Pinned by the tests in `agent_doc_missing_test.go`.

Only the exact word declines; an unknown word would silently leave the phase on the menu, so the repo catalog is checked for known words. Every render layer is pinned, because a test at one layer never proves the next: `TestAdvisorPrompt_OnDemandPhaseLeavesTheMenuButStaysNamed`, `TestComposePlanPrompt_CarriesTheOnDemandIndex` (persona path), `TestBuildPlanPrompt_CarriesTheOnDemandIndex` (persona-less path), `TestAdvisorPlanInput_PopulatesOnDemandFromTheOrchestratorCatalog` (orchestrator input), `TestRepoPhaseCatalog_CatalogWordIsKnown` and `TestKnownCatalogWord_RejectsTypos`.

The guard derives its expectations from the literal rather than a fresh golden, so it catches drops and divergence alike. The debugger has no registry home, so its seam value (`builtinControlSpec`) must equal the literal too. Pinned by `TestRegistryActivatingFields_AgreeWithLiteralKernel` and `TestControlSeamActivatingFields_AgreeWithLiteralKernel`.
- **`PhaseBoundaryCheckpointer` is package-global.** The checkpoint package sets it from `init()`, and core cannot import that package, so tests assign their own closure and must not run in parallel with other `RunCycle` tests.
- **A removal claim is judged against the repository, and only claims can fail.** A path absent from disk but still tracked fails; an untracked absent path is an honest removal; a non-repo worktree, a missing root, an escaping or absolute path and unparseable JSON all fail open; a claim false on both axes reports once, with the worktree message. The check runs in the production engine even when the diff yields zero packages. Pinned by `TestRemovalClaimFailures`, `TestRemovalClaimFailures_TrackedButAbsentFromDisk`, `TestRemovalClaimFailures_UntrackedAbsent_StaysHonest`, `TestRemovalClaimFailures_TrackedAndPresent_ReportsExactlyOnce`, `TestRemovalClaimFailures_MissingRootsFailOpen`, `TestRemovalClaimFailures_DeliverablesFallback`, `TestDefaultBuildFloorChecks_IncludesRemovalClaimCheck` and `TestBuildFloorReviewer_RemovalClaimNotActuallyRemoved`.
- **Only an `UPPER_SNAKE` token ending in `_PLACEHOLDER` is a slot**; prose, lowercase names and a missing report pass. Pinned by `TestPlaceholderTokenFailures_RefusesAnUnsubstitutedTemplateToken`, `TestPlaceholderTokenFailures_CleanReportAndProseAreNotTokens` and `TestDefaultBuildFloorChecks_IncludesThePlaceholderTokenCheck`.
- **The persona budget check is a conjunction.** A touched persona doc alone never rejects, and a lane that touches no persona doc never runs the package. Pinned by `TestPersonaBudgetFailures` and `TestDefaultBuildFloorChecks_IncludesPersonaBudgetCheck`.
- **Build-leak recovery preserves work and never widens the audit view.** Staging is scoped to relocated paths, never `git add -A`, which would sweep a worktree's pre-existing leftovers into the audit diff. A leaked edit to a tracked file relocates when the worktree copy is still at HEAD, including the staged-only `M ` case that `git checkout --` would miss; when the worktree changed the same file, the main-tree copy is discarded and the worktree wins. Gitignored build output never reaches the loop, so `.gitignore` is the discard mechanism and no path list is hardcoded. The tracked release binary `go/evolve` is always discarded, because only the release pipeline commits it. Orchestrator runtime state under `.evolve/`, at the top level or nested under a subdirectory, is skipped, and so is a nested worktree that `git status -uall` reports as a bare directory; `.evolve/` deliverables (evals, phase configs, profiles, tracked configs) relocate like any other path. Operator dirt already in the baseline is untouched. A correction re-dispatch is a fresh builder dispatch with the same escape risk, so its leak is recovered before review. Pinned by the `TestRecoverBuildLeak_*` tests and `TestCorrectionRedispatch_RecoversLeakBeforeReview`.
- **The carry-forward screen separates conflict from supersession.** A real conflict is `(false, nil)`, never an error; only a git failure errors. Supersession runs before the merge dry run, because a dry run of an already-absorbed change reads clean. A not-landable candidate is `FleetRebaseAlreadyLanded` only when the supersession screen says so, since calling a conflict landed would drop overlapping work. Pinned by `TestCarryforwardCandidateLandable_ConflictIsFalseNotError`, `TestCarryforwardCandidateLandable_SupersededShortCircuitsBeforeMerge`, `TestCarryforwardCandidateLandable_PatchIdDuplicateSuperseded`, `TestClassifyFleetRebaseCandidate_ThreeWayVerdicts` and `TestClassifyFleetRebaseCandidate_GitInfraErrorIsError`; the ordering and disambiguation keep a one-line why in code.
- **The composition fast paths can only narrow what ships.** A missing seam, patch-id drift, a red composed-tree gate, a reviewer error or a writer error falls back to the full re-audit. A RUNG 2 `compatible` verdict composes only when its resolution re-verifies by patch-id against the audited change, never on the reviewer's word (one-line why in code), and `Composes` is true only for `compatible`, so an unknown verdict fails closed. "Wired" means all three RUNG 0 closures are bound. Pinned by `TestOrchestrator_CompositionFastPathWired`, `TestScopedReviewVerdict_Composes`, `TestReverifyResolution_MatchAndReject`, the `TestIntersectingHunks_*` tests and `mergerung2_consolidation_test.go`.
- **Carryover retirement and minting are conservative.** `RetireCarryoverTodos` removes committed ids and their fingerprint twins, keeps survivors in order, never matches a blank id, and never mutates its input, because the caller re-reads state under a lock and a mutated slice would corrupt a concurrent peer's merge. A defect todo inherits the record's `ExpiresAt`; a record without one leaves the todo unstamped, because the prune keeps unstamped entries and a fabricated stamp would age out data of unknown age. A cross-cycle re-mint of the same defect collapses into one entry and refreshes its expiry. The closeout order is memo merge, prescription merge, then triage retirement. Pinned by the `TestRetireCarryoverTodos_*` tests, `TestApplyDefectsAsCarryoverTodos_StampsExpiryFromRecord`, `TestApplyDefectsAsCarryoverTodos_NoRecordExpiryLeavesTodoUnstamped`, `TestAdoptDefects_CrossCycleFingerprintDedupe`, `TestAdoptDefects_SuppressedRemintRefreshesExpiry`, `TestFinalizeCycle_CloseoutKeepsTheThreeStepOrder` and `TestFinalizeCycle_RetiresTriageDroppedCarryover`.
- **Every carryover construction lives in `carryover_lifecycle.go`.** `TestCarryoverLifecycle_OneConstructionSite` scans the text of every non-test Go file in the module for `carryover.New(`, `MergeWorkspaceCarryover(`, `MergeWorkspacePrescriptionCarryover(` and `ApplyDefectsAsCarryoverTodos(`, so no other non-test file may spell them, even in a comment.
- **A console lease waives nothing it should not.** An absent, malformed, expiry-less or expired lease yields an empty set, and a lease written inside a checkout is ignored, so the guard stays armed; a waiver is exact-path and WARNs. Pinned by the `TestReadConsoleLease_*` tests and `TestFilterRealLeaks_LeaseWaiverIsExactAndLoud`; the location's why stays in code.
- **A continuation binds only resumable, immutable work.** The snapshot is a commit reachable from the recorded branch, so it survives worktree pruning. Only a Clean snapshot is stamped or registered, so unresumable work leaves no binding that later attempts would adopt and re-reject. A cycle without lane scope creates no registry, a blank id never becomes a key, every lane id is registered, and a cycle scoped to a different id never adopts. Registry failures WARN and never fail finalization. Pinned by `TestSnapshotPreservedWorktree_CommitsDirtAndUntracked`, `TestStampContinuationManifest_WritesGatedManifest`, `TestStampContinuationManifest_ConflictingWorkIsNotStamped`, `TestStampContinuationManifest_UnstampableWorkRegistersNothing`, `TestStampContinuationManifest_NoLaneScopeRegistersNothing`, `TestStampContinuationManifest_RegistersEveryLaneScopeID` and `TestRunCycle_UnrelatedLaneScopeDoesNotAdopt`.

Pinned by `TestAbnormalEpilogue_StampsContinuation` and `TestStampContinuationManifest_WritesGatedManifest`.
- **A failed base advance stops before Build.** A conflicting merge is aborted under `context.WithoutCancel`, so cancellation never strands a half-merge in preserved work; no phase dispatches against the rejected snapshot and neither the old nor the seeded work is lost. Pinned by `TestAdvanceContinuationBase_ConflictReturnsErrorAndAborts`, `TestAdvanceContinuationBase_NoOpWhenCurrent` and the integration-tagged `TestRunCycle_ContinuationAdvanceFailureStopsBeforeBuild`.
- **Releasing a declined binding removes only the declined scopes.** A scope bound to a different ancestor survives. Pinned by `TestReleaseDeclinedBinding_RemovesMatchingScopesOnly`.
- **An exhausted dispatch loop is an explained, cycle-level failure.** When the iteration bound ends the loop before `PhaseEnd`, the cycle records a terminal abort naming the transition-table cycle, so `cyclehealth.ClassifyOutcome` reads `FAILED_EXPLAINED`, and `RunCycle` returns no batch-fatal error. Pinned by `TestRunCycle_TransitionCycleGuard_RecordsChokepointEscape`.
- **`ChangedWorktreePaths` reports tracked and untracked changes and is empty for a clean repo or a non-repo**, which makes the docs floor skip instead of inventing a violation. Pinned by `TestChangedWorktreePaths_ExportedForCLIConsumers` and `TestChangedWorktreePaths_EmptyWorktreeIsEmpty`.
- **A trailing `WithCatalogPublisher(nil)` never unwires an earlier publisher.** Pinned by `TestWithCatalogPublisher_TrailingNilDoesNotUnwireAnEarlierValidPublisher`. A nil catalog refresher writes no `catalog_refresh` ledger entry, because a refresher that never ran has no outcome to stamp. Pinned by `TestOrchestrator_CatalogRefresh_NilRefresherNoLedgerEntry`.
- **Source readers of these files.** `go/acs/cycle1153` counts quoted `"build-report.md"` and `"audit-report.md"` literals in `readBuildReport`'s body, comments included. `go/acs/cycle1152` requires `build_removal_check.go` to call `phasecontract.ArtifactName(` or `phasecontract.ArtifactFilename(`. `go/acs/cycle968` requires `ClassifyFleetRebaseCandidate`'s body to mention `CarryforwardCandidateLandable`. `go/acs/cycle1159` counts every non-test file outside `carryforward_filter.go` that mentions `ClassifyFleetRebaseCandidate` as a production caller, so a comment elsewhere would fake one. `go/acs/cycle1181` requires `carryforward_filter.go` to carry no `QUARANTINED-DEAD` marker.

The audit↔ship recovery loop is itself bounded (1 initial attempt plus `maxRecoveryDepth` (2) re-audits, the same bound for ship attempts), and exhausting that budget is cycle-level too. Pinned by `TestErrCycleLevelFailure_WrapsCauseForErrorsIs`, `TestOrchestrator_BridgeExhaustion_CycleLevelFailure`, `TestOrchestrator_IntegrityBreach_StillBatchFatal` and `TestOrchestrator_RecoveryDepthBudget`.

Pinned by `TestStampContinuation_NeverSnapshotsTheProjectRoot`.

Pinned by `TestAbnormalEpilogue_TeardownMarkedAndTailKept`.
- **`clearActiveWorktree` only unnames the worktree it just pruned.** It is a read-modify-write against storage, not a rewrite of the `newCycleRun`-era snapshot, because by teardown the cycle run has persisted phase progress through its own `CycleState` copy and writing the stale init snapshot back would discard it; the path guard makes it a no-op once the record has moved on.

A finding never blocks: it changes no verdict, raises no system failure, and is recorded on every cycle, all-ok included, because an ungathered false-positive rate can never be evidenced, and that evidence is the only door to graduating any of these invariants to blocking. Pinned by `TestFinalizeCycle_EmitsAdvisoryCrossArtifactInvariantsArtifact`, `TestFinalizeCycle_CrossArtifactViolationsNeverBlockTheCycle`, `TestFinalizeCycle_CrossArtifactBindsTheLaneWorktreeNotTheProjectRoot` and `TestFinalizeCycle_VerdictIncoherenceFloorSurvivesTheAdvisory`.

See ADR-0097. Pinned by `TestDispatch_ReadOnlyPhasesAreFencedAndSourceWritersAreNot` and `TestDispatch_ReadOnlyFlagOnResumeAndEvaluateBatchSurfaces`.

## Findings

- **Retro on the retry path** ([ADR-0093](../adr/0093-retry-envelope-and-terminal-retro.md)). An audit FAIL always routed to retro, which analysed, classified and gated the retry in one step, so the retry depended on retro's prose and ADR-0092's repair was reachable on only 3 of 16 failures. Retro costs 20–47 minutes per attempt. The decision moved to the audit chokepoint, keyed on the audit's own declared class; cycles 1572/1574/1576/1577 all declare `code-audit-fail`. The adversarial review of the first cut found the global graph widening (hence `decisionOnlyEdge`), a prose-driven halt, and an inert resume surface.

- **Repeatedly re-dispatching the same CLI after a deliverable-contract block can silently demote the contract gate.** The CLI fallback chain fires only on infra exit codes, never a contract violation, so a CLI that systematically mis-formats a deliverable burns every correction until the breaker opens and enforce quietly becomes advisory for the rest of the run.
- **Comparing a contract block's whole rendered reason text is not a safe identity check.** A partially repaired defect set changes the rendered string, which can suppress escalation exactly where an incapable CLI's signature is strongest; violation-code-set intersection is the safe identity.
- **A contract-block escalation trigger with no available target still needs a remedy.** Without one, an incapable CLI keeps receiving the same plain directive until the breaker opens purely for lack of anywhere to escalate to.
- **A CLI family can be capable of ordinary dispatches yet incapable of a whole class of contract-mandated repairs** (e.g. creating a missing artifact), while a sibling family never fails that same class — which is why a remediation-carrying rejection also escalates, not only a bare contract block.
- **A ledger entry recording only Kind/Role with no evidence blinds breaker diagnostics.** A demotion entry's Action field must carry the decision verb and the evidence, not just its category.
- **cycle-7 (worktree teardown).** A wrong prune destroyed an entire PASS cycle's work, which is why `teardownCycleWorktree`'s decision stays asymmetric: a missed prune only costs disk, so both no-prune conditions (preserve, or the cycle did not complete normally) err toward keeping the tree.
- **The resume path used to leak worktrees.** `teardownCycleWorktree` was originally an anonymous closure inside `RunCycle`'s cleanup stack. `RunCycleFromPhase` registered the other exit actions (lock release, run-ID clear, lease stop) by hand but had no counterpart for worktree disposal, so every resumed cycle leaked its worktree regardless of verdict; extracting the one shared rule closed the gap.
- **cycle-1048 (abnormal exit blind spot).** The loop's abort path returned immediately on failure, skipping `finalizeCycle`, so the seal, dossier and coherence floors never ran and left a two-hour stale `phase=retro` record with no dossier — invisible to every monitor, since detectors read artifacts the failure path itself never produced. `abnormalEpilogue` now runs as a deferred, construction-guaranteed epilogue on every exit path. - **Workspace pollution across cycle-number reuse.** A killed attempt's leftover `scout-report.md`/`build-report.md` made Scout short-circuit on stale artifacts and steer downstream phases via the old task selection; the workspace is now archived before any phase runs when a prior attempt polluted the same cycle number.
- **A committing builder's work must become pending again.** Recording the worktree's HEAD at creation as the cycle base lets the post-build soft-reset (`normalizeWorktreeToBase`) restore a builder's committed work to the working tree instead of leaving it buried in a commit the audit never sees as a diff.
- **`cs.ActiveWorktree` was write-only for a while.** Teardown deleted the worktree directory but left the record naming it, so the next reader (retro's dispatch, resume, checkpoint) handed a deleted path to the bridge, whose IsDir guard refused the launch.
- **A bare scoped id can resolve to a stale duplicate.** With many inbox records once sharing one id, a bare name resolved to a two-week-old consumed namesake and every phase worked the cured ghost, which is why `fleet_scope_paths` discloses each id's live path beside it.

The orchestrator now mints it once per cycle in the same 8-byte-hex shape the bridge already used, so ledger entries stay indistinguishable across the change.
