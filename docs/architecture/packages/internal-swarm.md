## Purpose

`internal/swarm` is the primitive that lets one phase fan out to N heterogeneous LLM-CLI workers and fan back in. It holds the plan types and parser (`SwarmPlan`, `ParsePlan`), the pure validator and merge order (`Validate`, `TopoOrder`), the dispatcher (`Dispatch`), writer fan-in (`RunMergeTrain`) and reader fan-in (`Synthesize`), worktree provisioning (`WorkerProvisioner`), session tracking (`SessionRegistry`), and three reapers: the manifest reaper (`Reap`), the per-run registry reaper (`ReapRunSessions`), and the liveness GC (`ReapOrphanSessions`, `ReapOrphanSockets`).

## Design

- **Ports defined where used.** `Launcher`, `WorkerProvisioner`, `SessionKiller`, `GitMerger`, `AcceptanceChecker` and `ConflictResolver` live here, and `swarmrunner` adapts `core.Bridge` to `Launcher` at the composition root. The package does not import `core` directly, and `LinkGuardDeps` is injected so that `core.LinkGuardDeps` can be supplied without an import. It does reach `core` transitively through `bridge`.
- **Proposer–Validator.** The planner LLM proposes a partition. `Validate` is pure, with no filesystem or git access, and checks it before anything launches. A `ParsePlan` error means "no usable plan", and the caller falls back to one worker rather than aborting the cycle. `ParsePlan` takes the first ```` ```json ```` fence and falls back to bare JSON, which keeps it robust to a CLI that omits the fence.
- **Validation order.** A declared fallback (`IsFallback`: non-partitionable, or fewer than two workers) short-circuits without looking at ownership. A duplicate `worker_id` is rejected next. Then writers need disjoint normalized file ownership and a valid `depends_on` DAG, whose topological order becomes the merge order. Readers skip the disjointness check (read overlap wastes tokens but never corrupts), yet still collapse on an invalid DAG, because a bad dependency is a planner bug worth surfacing.
- **Merge order.** `TopoOrder` delegates to `internal/dag` (shared with the campaign wave planner, so Kahn's algorithm is not duplicated) and breaks ties by `worker_id`.
- **Dispatch shape.** Writer provisioning runs serially first, because `git worktree add` writes shared `.git/worktrees` metadata. The launches then run in parallel under a buffered-channel semaphore (the same raw-sync pattern as `internal/fanoutdispatch`, with no errgroup). The first fatal launch error cancels the shared context. `Dispatch` blocks until every goroutine finishes and reaps every registered session before returning. It does not merge or synthesize; the caller reduces the results.
- **Worker prompt.** `workerPrompt` (scope, owned files, acceptance) is the prompt the worker receives. The bridge launcher adds skill overlays but does not replace it.
- **Writer ports.** Writer worker `i` gets `PORT=base+i` (default base 51000, in the dynamic/private range) as a per-worker env overlay, so concurrent dev servers in separate worktrees never collide. Readers share the read-only tree and get no port.
- **Merge train.** `RunMergeTrain` is strictly sequential, so only one merge touches the integration index at a time and `.git/index.lock` never contends. Each step is a merge, then the acceptance check against the integration tip. On a conflict or an acceptance failure, the authoring worker's `ConflictResolver` runs and the merge is retried. The train stops at the first worker that still fails, because a half-built integration must not proceed. Gating each step on acceptance rather than on git success alone follows the research in [swarm-concurrency-2026-05.md](../../research/swarm-concurrency-2026-05.md). `ExecGitMerger` runs `git merge --no-ff --no-edit` inside the integration worktree and aborts on any failure.
- **Registry.** `SessionRegistry` rewrites the whole manifest on every mutation (temp file with a PID suffix, then rename). A swarm has single-digit sessions, so a full rewrite is simpler and safer than append-and-compact. The manifest outlives a SIGKILL of the orchestrator so `evolve swarm reap` can load it and run `Reap`. An empty manifest path keeps the registry in memory only. The package never calls `time.Now`; callers stamp `StartedAt`.
- **Three reap axes.**
  - `Reap` walks the swarm manifest (clean path, and `evolve swarm reap` after a crash).
  - `ReapRunSessions` reads the run's own `tmux-sessions.jsonl` registry, written by the bridge when it creates a session. It never lists the server, so a run's teardown cannot see, let alone kill, another run's sessions. Killing an already-dead session is a no-op, so reaping after a clean cycle is harmless.
  - `ReapOrphanSessions` covers the hole the per-run registry leaves: a SIGKILL'd loop never runs its teardown, and the next loop's registry does not list the corpse. It reaps on a different axis, the creator PID that every auto-generated bridge/recipe session name carries (`...-pid<PID>-n<nonce>-<ts>`). A dead PID can only mean a corpse. `ReapOrphanSockets` does the same for per-run sockets (`evolve-bridge-p<looppid>` from `bridge.DeriveRunSocket`): a crashed loop leaves its whole socket server running, and a session sweep on one socket cannot see another socket's sessions, so the dead owner's server is killed outright. `kill-server` is safe there only because that socket belongs to the dead run alone.
- **Worktree naming.** Integration and worker branches come from `runscope` (`cycle-<lane>-<N>-integration`, `cycle-<lane>-<N>-<workerID>`), and each worktree directory's leaf matches its branch name. Branches are named, not `--detach`, so the merge train and ship can resolve them with `git symbolic-ref --short HEAD`. The base is `policy.json` `worktree.base` (injected through `NewGitWorkerProvisioner`, replacing the `EVOLVE_WORKTREE_BASE` env read whose gamed removal motivated [ADR-0064](../adr/0064-pipeline-integrity-boundary.md)) or `<root>/.evolve/worktrees`.
- **Test seams.** `tmuxRun`, `tmuxListRun` and `socketGlob` are package variables that tests swap, so the unit suite never touches a real tmux server or socket directory. Tests that swap them must not run in parallel.

## Invariants

- **A writer plan runs only when it is provably disjoint.** Any overlap collapses to N=1 (ADR-0032 rejects best-effort repair). `normalizePath` trims, cleans, converts to slashes, drops a trailing slash and case-folds, so `./a.go`/`a.go` and `Foo/A.go`/`foo/a.go` collide. It case-folds because the macOS and Windows filesystems are case-insensitive. It does not reject absolute or escaping paths. Pinned by `TestValidate_WriterOverlap_NormalizedPaths` and `TestValidate_WriterOverlap_CaseInsensitive`.
- **Duplicate worker IDs collapse.** They would silently dedupe in the ownership and in-degree maps, so a two-worker plan could validate with a one-entry merge order. Pinned by `TestValidate_DuplicateWorkerID_Collapses`.
- **Merge order is deterministic.** Pinned by `TestTopoOrder_Deterministic`.
- **A mid-provisioning failure releases what it provisioned.** The launch section never starts, so the post-wait `Reap` cannot cover those worktrees. Pinned by `TestSwarm_CoverageDispatchProvisioningErrors`.
- **Every worker gets a result.** A worker still queued on the semaphore when the context is cancelled records the context error. Each `results` index has exactly one writing goroutine, so no lock is needed. Pinned by `TestDispatch_CancelWhileQueuedOnSemaphore` and `TestDispatch_ConcurrencyCapHonored`.
- **No session outlives `Dispatch`.** The final `Reap` runs under `context.Background()`, so teardown still runs after cancel-on-fatal. Pinned by `TestDispatch_LaunchesAllWorkersAndReaps`.
- **Register before launch, and abort when registration fails.** A tmux worker's session name is pinned (`swarm-c<cycle>-<workerID>` through `bridge.NamedSessionName`) and registered before `Launch`, so a spawn cancelled mid-flight, which never returns a session identity, is still reapable by name. The manifest is the crash-safe reaper's only record, so a registration that fails to persist aborts the worker before any spawn. An unrecorded session would be an invisible orphan. Headless workers register an empty session; context cancellation kills their subprocess. Pinned by `TestDispatch_TmuxWorker_PreRegisteredAndReapedOnLaunchFailure`, `TestLaunchWorker_RegisterFailure_AbortsBeforeLaunch` and `TestDispatch_HeadlessWorker_NoTmuxSession`.
- **Session names use the cycle and worker ID, never the task slug.** A slug-based name could exceed length limits or truncate two workers into the same name. Worker IDs are unique after validation.
- **A failed persist never leaves memory ahead of disk.** `Register` and `MarkReaped` snapshot the sessions first and restore them when the write fails, because the manifest is the reaper's source of truth. The snapshot is a plain slice copy, which is complete only while `SessionHandle` holds value fields alone. Pinned by `TestRegister_PersistFailure_RollsBackInMemory`, `TestMarkReaped_PersistFailure_RollsBackStatus` and `TestRegister_ReplacePersistFailure_RollsBackToOriginal`.
- **The registry mutex guards against lost updates.** Pinned under `-race` by `TestSessionRegistry_ConcurrentRegister_NoRaceNoLostUpdate`.
- **`Reap` never stops early.** A kill error is recorded, and the session is still marked reaped: the process is most likely already gone, and a Live corpse would be retried by every future sweep. A `MarkReaped` persist failure is surfaced in `Errors`, because the stale Live entry would make the next sweep re-target a corpse. Pinned by `TestReap_ContinuesPastKillError` and `TestReap_MarkReapedFailure_SurfacedInErrors`.
- **The process-group kill needs `pgid > 1`.** The kill is `kill(-pgid)`; pgid 0 is the caller's own group, and pgid 1 signals every process the caller may signal. The group kill exists to reap the inner CLI's grandchildren, which a bare process kill would orphan. The two teardown steps are independent, so a partly torn-down worker is still fully cleaned. Pinned by `TestExecSessionKiller_RejectsPGID1` and `TestExecSessionKiller_KillGroupError_ContinuesToKillTmux`.
- **An empty tmux target is refused before any exec.** tmux resolves an empty `-t` to the client's current session, so a blank name fired from inside any tmux pane kills the caller's own session. `ExecTmuxKill` refuses it; `ReapRunSessions` and `ReapOrphanSessions` also skip empty names. Everything else is best-effort, since a missing session is the desired end state. Pinned by `TestExecTmuxKill_EmptySessionRefusedBeforeExec` and `TestExecTmuxKill_RunnerErrorIsBestEffort`.
- **Teardown targets the bridge socket.** Agent panes live on the bridge's isolated socket, so a default-socket kill would leave them orphaned. Pinned by `TestExecTmuxKill_TargetsIsolatedBridgeSocket`.
- **The liveness GC fails safe.** A foreign or empty name, a name with no PID token, and a live (or recycled-and-now-live) PID are all skipped, never killed. The worst case is a leak that the next sweep catches. A list error kills nothing, and a list that errors after partial output is treated as an error, never as a truncated view. The `-pid` token needs its leading dash, so `rapid7` never parses as a PID, and PID 0 is refused. Pinned by `TestReapOrphans_KillsDeadKeepsLive`, `TestReapOrphans_SafetySkips`, `TestSessionPID` and `TestExecListBridgeSessions_PartialOutputOnError`.
- **Only per-run sockets can be killed.** `socketPidRE` matches `^evolve-bridge-p(\d+)$` only, so the shared default socket and probe sockets never match. Pinned by `TestReapOrphanSockets`.
- **A stopped tmux server is an empty list.** tmux exits non-zero with no output when no server exists, and that is the "nothing to reap" state, not a failure. Pinned by `TestExecListBridgeSessions_NoServerIsNoError`.
- **An unreadable run registry is counted as an error, not reaped fuzzily.** The run degrades to leaking on crash rather than falling back to a server-wide sweep.
- **The worktree base must be absolute.** A relative base would resolve `git worktree add` against an unintended cwd and break the tree-diff guard. The guard lives in `worktreeBase` itself, for both the override and the default (relative project root) branches, before any `MkdirAll` or git call. Pinned by `TestWorktreeBase_RelativeOverrideReturnsError`, `TestWorktreeBase_RelativeProjectRootRefused` and `TestGitProvisioner_RelativeWorktreeBaseHasNoFilesystemSideEffects`.
- **Reuse needs two probes.** An existing directory is reused only when it has a `.git` entry at its root and `git rev-parse --git-dir` succeeds. A plain stub directory inside the parent repo passes rev-parse by walking up to the parent's `.git`. Anything else is torn down and re-added. Pinned by `TestAddWorktree_StaleStubRemoved`.
- **Sibling worktrees never collide.** Branch and directory names are lane-scoped per project root. Pinned by the integration-tagged `TestGitWorkerProvisioner_ConcurrentSiblingsNoCollision`.
- **`git worktree add` retries through the shared helper.** It uses `gitexec.WorktreeAddRetry` with the shared transience classifier and bound, on both `CreateIntegration` and `CreateWorker`. This is the highest-contention add in the tree (N workers against one `.git`), and the classifier fails a permanent error at once instead of spending the backoff on every worker. Pinned by `TestSwarmCreateWorker_PersistentFailureStillFailsLoudly` (attempts equal `gitexec.DefaultWorktreeAddAttempts`), `TestSwarmCreateIntegration_RetriesTransientAddFailure` and `TestSwarmCreateWorker_CleanRunCostsOneAttemptAndNoSleep`.
- **Cleanup never force-deletes a branch.** It runs `git branch -d` on the worktree's leaf name after the remove, and only for `cycle-` leaves. git's merged check is the only safety net, so a refusal is a warning, never escalated to `-D`. Pinned by `TestCleanup_UnmergedBranch_NeverForceDeletes` and `TestGitWorkerProvisioner_Cleanup_UnmergedBranchSurvives`.
- **External contracts on the source.** `go/acs/cycle296` counts `filepath.IsAbs` lines inside the `worktreeBase` (at least one) and `addWorktree` (none) functions of `provision.go`, so the guard must stay in `worktreeBase`. `go/acs/cycle294`, `cycle296` and `cycle297` run this suite by test name (`TestDispatch_CancelWhileQueuedOnSemaphore`, `TestWorktreeBase*`) and read `Dispatch`'s coverage, so those names are part of the contract.

## Findings

- **killer-B (2026-06-11).** A test live-fired `tmux kill-session -t ''` against the shared default socket. tmux resolved the empty target to the client's current session, which destroyed every concurrent soak session. That produced the empty-name refusal, the `tmuxRun` seam, and the per-run registry reaper (CB.5, concurrency campaign W4) that replaced name-fuzzy teardown on the shared server. See the [soak report](../../operations/soak-report-2026-06-12.md) and [concurrency architecture](../../research/concurrency-architecture-2026-06-18.md).
- **Crash-orphan accumulation.** Per-run registry reaping cannot reach a SIGKILL'd run, so orphans piled up across crashes until the shared tmux server starved the machine. The PID-liveness GC closed that. Known gap: named sessions (`bridge.NamedSessionName`, which includes swarm worker sessions) carry no PID token, so the GC counts them as unparseable and leaves them for their creator, an operator, or the swarm manifest reaper. Closing it would mean baking a creator PID into `NamedSessionName`.
- **Per-run sockets (F6).** Once each loop owned its own tmux socket, a crashed loop left the whole server running, invisible to a session sweep on another socket. That added `ReapOrphanSockets`.
- **cycle-283.** A stub directory inside the parent repo passed the reuse `rev-parse` by walking up to the parent's `.git`, and was silently reused as a worktree. That added the `.git`-entry probe.
- **cycles 294, 296, 297** (inbox defect `swarm-tests-relative-worktree-base`). Cycle 294 refused a relative base in `addWorktree`. Cycle 296 moved the guard into `worktreeBase`, but only for the override branch. Cycle 297 closed the default branch, which still returned `.evolve/worktrees` for a relative project root such as `.`.
- **cycle-1268** (`worktree-provisioning-retry-consolidate`). `addWorktree` issued one unretried `worktree add` at the tree's highest-contention site. It adopted the shared helper rather than a swarm-local copy of the constants ([ADR-0082](../adr/0082-shared-worktree-add-retry.md)).
- **Registry race coverage (ADR-0050 Phase 2, S2.5).** The only incidental concurrent path (`Concurrency: 2`) tripped `-race` about once in 20 runs, because the workers' other work staggered the two `Register` calls, so a stripped mutex would have passed CI about 95% of the time. The concurrency test drives real contention with `fixtures.StressN`, and removing the lock drops the final count below n×k.
- **Session-accounting failures were swallowed** (inbox `swarm-session-accounting-fail-loud`). A failed pre-registration and a failed `MarkReaped` persist were both silently dropped. Both now fail loud, and the registry rolls back on a failed persist.
- **Token telemetry S5.** Per-worker token counts were dropped at the N→1 merge and only cost survived. `LaunchResult.Tokens`, `WorkerResult.Tokens` and `TotalTokens` carry them.
- **Session naming review.** A go-reviewer HIGH finding showed that a task-slug-based session name could overflow validation limits or truncate two workers into one name, which led to cycle-plus-worker-ID naming.
- **apicover naming (ADR-0050 Phase 5).** Fourteen exported types were exercised only indirectly (fakes implemented the interfaces structurally, and producers returned the report structs), so apicover could not see them. `apicover_named_test.go` names each one through a real use.
