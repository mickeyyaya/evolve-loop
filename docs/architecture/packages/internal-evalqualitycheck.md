## Purpose

`internal/evalqualitycheck` holds four deterministic, authoring-time checks. `Check` grades one eval's grader commands for rigor. `CheckDiversity` grades a suite of evals for negative-case coverage. `LintFlakyPredicates` lints ACS predicate Go sources for shapes that flake under fleet load. `LintUnsatisfiablePredicates` lints the same sources for predicates that cannot pass on any tree. The callers are `internal/evalgate` (Gate B runs `Check`; Gate D runs `LintFlakyPredicates`; Gate E runs `LintUnsatisfiablePredicates`) and `internal/cli/guardcmd` (`evolve eval quality-check [-predicates]`, which runs both predicate lints, and `evolve eval diversity-check`).

## Design

- **Level numbering.** `LevelPass`, `LevelWarn` and `LevelHalt` are 0, 1 and 2, the same values the CLI returns as its exit code. The skill docs number rigor tiers the other way round: their "Level 0" is the always-pass tautology, which is `LevelHalt` here.
- **One eval parser.** `scanBashCommands` serves both `Check` and `CheckDiversity`, so the two can never disagree about what an eval's commands are. It reads non-blank, non-`#` lines inside fences whose opening line contains `bash`, plus the scout template's top-level `` - `[code]` `<command>` `` bullets. The bullet capture takes the second backtick span greedily, because a command may itself contain backticks. `[model]` and `[human]` bullets are not bash.
- **Classification order.** `classify` tries the exact tautologies (`:`, `true`, `exit 0`, `/bin/true`), then trivial bracket tests, then commit-presence ranges (all HALT), then echo-only and grep against an inlined literal (both WARN). Anything else passes. RE2 has no backreferences, so the grep rule accepts any two adjacent quoted arguments rather than two equal ones.
- **Commit-presence rule.** `commitPresenceRE` matches a revision range (`a..b`, `a...b`, trailing-open `a..`) in the arguments of `git log` or `git rev-list`. It is unanchored, so it also fires inside `$(...)` and after `&&`. The `[^|&;]*` guard stops a range in a later pipeline segment being attributed to this invocation. Both ends of the range must be rev-name characters, so a pathspec such as `dir/../file` does not fire. Deliberate gaps: a left-open `..HEAD`, `^main HEAD` exclusion syntax (both rare in evals), and `git diff a..b`, because content parity (`git diff <ref> --quiet`) is the sanctioned pattern.
- **Diversity heuristics.** They are keyword-based and deterministic, a complement to mutation testing, not a replacement. They favor precision over recall, because a false HALT blocks honest work while a missed WARN costs little. A negative case needs a shell-level construct: `! cmd`, `exit 1`, `-ne 0`, `!=` inside a test bracket, or an `assert/expect/should/must` + `fail/error/reject/not` helper name. English words such as "fail" appear in doc-grep evals and never count. Edge-case keywords (invalid, missing, corrupt, malformed, overflow, boundary, empty, empty quotes) are counted and reported but never gate.
- **Diversity scope.** Only `.md` files count. Underscore-prefixed files are meta, canary or example evals and are skipped, and so are files with no parsed commands. `Slug` filters by substring of the file name.
- **Flaky lint layout.** `flakylint.go` holds the pattern rules and their reporters. `flakylint_exec.go` answers "which argv position did this string reach?" and produces no findings itself. The split exists only for the file-size ceiling; the two files are one lint.
- **One predicate-source reader.** Both predicate lints take a `.go` file or a package directory and read it through `predicateSourcePaths`: the file itself, or the directory's top-level `.go` files in name order (`ReadDir` sorts), so output is deterministic. A directory with none is an error that says nothing was linted. Pinned by `TestPredicateSourcePaths_ListsTopLevelGoFilesInNameOrder`.
- **Flaky lint pipeline.** Parse every `.go` file `predicateSourcePaths` lists. Collect package-level string consts and vars so a const-indirected pattern resolves where it is used. Index plain functions by name for the helper hop; methods are left out because they would need receiver resolution. Then, per function: build the argv-position index, walk the body, and dedupe findings per (class, reason).
- **Recognized exec constructors.** `exec.Command`, `exec.CommandContext` (its context argument is skipped and binds the child's lifetime) and `acsassert.SubprocessOutput` (no context). A non-literal argument resolves to `""` so argv positions stay aligned.
- **Argv-position awareness.** A package pattern gets a suite-scope finding only if it reached a `go test` argv, or reached no exec argv at all. A pattern handed only to `go build`, `go vet` or `rg` is a compile or a search. An unresolvable pattern keeps its note, the safe direction for an advisory lint.
- **Helper hop.** The index also walks the bodies of same-package helpers the function calls, with the call's string arguments bound to the helper's parameters. `bindParams` returns a copy, so helper bindings never leak into the package-const map the finding scan reads, and it stops at a variadic parameter (many arguments, one name).
- **`-run` narrowing.** It suppresses only the known-slow finding, and only when every `go test` argv carrying the pattern is narrowed. A recursive pattern stays flagged, because `-run` selects which tests run, not which packages are built and loaded.
- **Repo anchoring for git.** `-C` counts at any nesting depth inside the arguments (the `append([]string{"-C", dir}, args...)` idiom); presence can only unflag, so deep matching is safe. A `.Dir` assignment on the variable the constructor was assigned to also anchors, and inside `sh -c` a `cd` segment before the `git` segment does.
- **Shell scripts.** A `sh -c` script string contains spaces, so it is never a package pattern and never reaches the literal scan. The go-test, git, kill and load-generation rules are therefore applied per segment, splitting on `;`, `&`, `|` and newline.
- **Wall-clock rule.** Only `Add`, `Before`, `After` and `Sub` on a direct `time.Now()` chain, plus `time.Since` and `time.Until`, count. The `Unix*` methods are excluded: `time.Now().UnixNano()` is the unique-name idiom, not a deadline, and flagging it would print a claim that is false about the code.
- **PID rule.** A literal PID below 100000 fires only at a liveness site: `os.FindProcess`, `syscall.Kill`, `unix.Kill`, a `kill` argv, or a `/proc/<pid>` path. Such a PID is a stale artifact of the authoring session. A small int const elsewhere is left alone.
- **Known-slow suites.** `internal/core` and `cmd/evolve` take 40s+ under contention even as a single named package. The keys are module-relative, via `gopkgpattern.Key`. The package-pattern rule itself lives in `internal/gopkgpattern`, shared with `internal/acssuite`'s run-time scope-lint.

## Invariants

- **Zero parsed commands is WARN, never PASS.** A gate that parsed nothing verified nothing. The WARN carries one explanatory `ClassifiedLine`, so `Result.Commands` can hold a diagnostic entry that is not a parsed command. Pinned by `TestCheck_ZeroCommandsIsWarnNeverSilentPass` and `TestCheck_NonBashFencedBlock_Ignored`.
- **A score_cap eval with zero bash commands passes with a note.** The ACS suite grades those evals, and a blanket WARN on most of the corpus would train operators to ignore real WARNs. Detection is a line-anchored `score_cap:` key anywhere in the file. Pinned by `TestCheck_ScoreCapGradedEvalPassesWithNote`.
- **Grader bullets count only at top level.** A `[code]` bullet inside any fence is illustration or a decoy planted to fake rigor. Pinned by `TestCheck_FencedDecoyBulletIsNotACommand`.
- **The template and the scanner cannot drift.** `TestCheck_TemplateExampleRoundTripsThroughScanner` reads the `eval-format-template` anchor in `agents/evolve-scout-reference.md`, unwraps its four-backtick `markdown` illustration fence, and requires at least three parsed commands.
- **Diversity gate levels.** No evals with commands: PASS. Any negative case: PASS. A cohesive suite of 3 to `maxCohesiveSuiteSize` (12) evals with zero negative cases: HALT. Anything else with zero negatives: WARN. A cycle authors a handful of evals, and a larger directory is an accumulated archive (`.evolve/evals/` holds every historical task) that must never hard-block. Pinned by `TestCheckDiversity_Levels` and `TestCheckDiversity_ArchiveScaleZeroNegativeIsWarnNotHalt`.
- **Negative-case precision.** Pinned by `TestCheckDiversity_NegativeCasePrecision`, including `!=` inside a grep string (not negative) against `!=` inside a test bracket (negative).
- **Nothing linted is never clean.** Unreadable or unparseable input is an error, and so is a directory holding no `.go` files. `FlakyLintReport.Files` travels with the findings and callers print `Linted()` unconditionally, so "0 findings over 0 files" cannot pass for "0 findings over a linted tree". Pinned by `TestLintFlaky_DirWithNoGoFiles_Error`, `TestLintFlaky_UnparseableSource_Error`, `TestLintUnsatisfiablePredicates_RefusesAMissingPathAndAnEmptyDirectory` (a missing path wraps `fs.ErrNotExist`, which Gate E reads as "no predicate package"), and the receipt checks in the `lintDir` and `unsatisfiableFindings` test helpers.
- **Go-test evidence wins.** A `go vet` on a pattern in the same function never hides a `go test` on it. Pinned by `TestLintFlaky_GoTestArgvWins_EvenBesideNonTestUse`, `TestLintFlaky_PatternInNonTestExecArgv_NotFlagged` and `TestLintFlaky_HelperMediatedPattern_StillFlagged`.
- **The helper hop goes exactly one level.** A helper's own calls are not followed and a self-call is skipped, so the walk terminates without recursion or a visited set. A two-level chain stays unresolvable and keeps its note. Pinned by `TestLintFlaky_HelperHopIsDepthOneOnly`; `TestLintFlaky_HelperHopStillFlagsWideInvocation` pins that the hop also finds wide invocations. The duplicated exec in `go/acs/regression/cycle1270`'s helpers depends on this bound.
- **Narrowing needs every invocation.** Pinned by `TestLintFlaky_NarrowedPlusWideSameSuite_StillFlagged`, `TestLintFlaky_RunNarrowedKnownSlow_NotFlagged` and `TestLintFlaky_RunNarrowedRecursive_StillFlagged`.
- **Preconditions before promotion past advisory.** Narrowing is presence-only on purpose at the advisory stage, where a false claim costs author trust and a missed finding costs nothing. Before any enforce stage: reject trivial `-run` values (`.`, `.*`, `^Test`, empty), all of which read as narrowing today; and treat a pattern built at runtime (`fmt.Sprintf`, `os.Getenv`), which never reaches the scan at all, as not narrowed. Today the risk is bounded: recursive findings are checked before the suppression, and `acssuite`'s run-time scope demotion still fires.
- **What a finding proves.** Each finding is a statement about one function's source, in source order and lexical scope. For `inverted-idiom`: the primitive's TB argument is a name that, in scope, is declared with a concrete testing type or holds a tracked self-reporting `testing.TB` value. For `go-run-exit-code`: the compared operand is an `ExitCode()` whose receiver is a name whose latest visible binding in scope is a `go run` command or its exit error, or a name whose latest visible binding is such an exit code (copied from that `ExitCode()`, or the third result of `acsassert.SubprocessOutput("go", "run", …)`), and the literal is a code that command cannot return. When nothing outside that view rebinds the name, the predicate is red on every tree. `absence-message` proves nothing; it is a keyword heuristic.
- **What the tracker does not see, and in which direction it errs.** Measured with probe predicates on 2026-10-05:
  - *It can over-flag* when a name is rebound where the tracker does not look: through a pointer (`p := &err; *p = other()`), by a callee (`reset(&err)`), through a struct field or a map, or by a backward `goto` over a rebinding. The binding it last saw stays, so a comparison on the rebound value is flagged. None of these shapes is in the `go/acs` corpus.
  - *It misses, and only misses*, when the chain runs through something other than a plain name in the same function: an error copied into another name (`e2 := err`), a helper across functions, an exit code returned from a helper, a method value (`run := cmd.Run`), a command held in a struct field, a slice or a map, a repo-local runner helper, or the clause type a type switch narrows to (a `case *exec.ExitError:` clause variable is not followed). A `testing.TB` interface value read inside a closure from outside it is unknown, so a captured interface TB is missed. A closure's write to, or read of, a name declared outside it is unknown to the go-run rule, so a check inside a closure on an outer `go run` result (a `t.Run` subtest reading the parent's command, say) is missed, and a closure's write can only cause a miss.

## Unsatisfiable-predicate lint

`LintUnsatisfiablePredicates` flags a predicate that is red on every tree, so a lane never burns a build proving it. Each finding carries a kind and names the remedy for its shape. `unsatisfiable.go` holds the kinds, `unsatisfiable_scope.go` the scoped name table both rules read, and `unsatisfiable_gorun.go` the go-run rule.

| Kind | Shape | Why it can never pass | Remedy named |
|---|---|---|---|
| `inverted-idiom` | `if acsassert.FileContains(t, …) { t.Errorf(…) }`, for any self-reporting positive primitive (`FileContains`, `FileMatchesRegex`, `FileExists`, `JSONFieldEquals`) | the primitive Errorf's through `t` on the absent state, and the body fails on the present one | `acsassert.FileNotContains`; for `FileExists`, `os.Stat` with `errors.Is(err, fs.ErrNotExist)`; for `JSONFieldEquals`, a swallowing-TB probe |
| `absence-message` | `if !acsassert.FileContains(…) { t.Errorf("… still holds …") }` | a positive primitive cannot express the absence its failure text demands, so the intended (absent) state is red | `acsassert.FileNotContains` |
| `go-run-exit-code` | an `ExitCode()` on the result of a `go run` command, or a name holding that exit code or `acsassert.SubprocessOutput("go", "run", …)`'s exit code, compared with `==` or `!=` to an exit code the go command cannot return: 2 or more, or 3 or more when go flags precede the package | `go run` reports any non-zero exit of its program as 1 (and a build failure as 1); it exits 2 only when its own flags are bad, so the program's own exit code never reaches `ExitCode()` | build the program with `go build` and run the built binary |

- **One scoped name table.** Both rules read `walkScoped`, a symbol table over one function, walked in source order. A scope opens at every block, `if`, `for`, `range`, `switch`, type switch, `case` clause, `select` clause and closure, and closes when the walk leaves it. A name is declared by a parameter or a named result (the function's or a closure's), `:=`, a `range ... :=` variable, a `var`, or an `if` statement's init, which is declared before the `if`'s condition and body are judged. `=` (an assignment, an `errors.As` target, or a `range ... =` variable) updates the innermost scope that declares the name, and a name no scope declares (a package-level variable) is bound at the function's scope. So a name re-declared in an inner scope shadows the outer one only there. A closure's frame is marked: a go-run value never crosses it in either direction. A write inside a closure to a name declared outside it (an assignment or an `errors.As` target) makes that name's value unknown, and a read inside a closure of a name declared outside it sees an unknown value, because a closure runs when it is called, not where it is written. The concrete-TB fact (`*testing.T`/`B`/`F`) is a declared type, not a value, so it does cross: `t` captured by a closure still self-reports. A `testing.TB` interface is a value and does not.
- **Self-reporting is decided by what the TB argument holds where the `if` stands.** A concrete `*testing.T`, `*testing.B` or `*testing.F` is a type fact: every value of that type self-reports, so a parameter, named result or `var` declared with it self-reports whatever it was initialised with, and the fact crosses closures (`t` captured by a closure still self-reports). A `testing.TB` interface is a value fact, because it can hold a swallowing probe: a parameter typed `testing.TB` self-reports, a `var tb testing.TB = <init>` takes its initializer's binding (from `t` it self-reports, from `nopTB{}` it does not), a copy of a self-reporting TB (`tt := t`) self-reports, and a closure reading an interface TB declared outside it sees an unknown value. A swallowing probe (`nopTB{}`, a `recordingTB`, or `var t nopTB`) shadowing `t` is never flagged, and `t` used after the shadowing block is the real `t` again. Only the `acsassert` package's primitives self-report; a same-named helper in another package (`repoassert.FileContains`) is never flagged.
- **Only an unconditional failure counts.** The failure call must be a direct statement of the `if` body, so a guard holding a nested check is not a failure condition.
- **The message is judged whole.** The literals of one failure call are joined before the intent test, so a split message's later "not"/"must" still counts. Messages carrying a missing-state marker ("not", "missing", "must", "expected") are never flagged.
- **The go-run rule follows the result in scope.** It binds a name to a `go run` command (any constructor in the flaky lint's table, read by the shared `execArgv`: `exec.Command`, `exec.CommandContext`, `acsassert.SubprocessOutput`), to the error that command's `Run`, `Output`, `CombinedOutput` or `Wait` returned, and to the `*exec.ExitError` taken from that error by type assertion or `errors.As`. It also binds a name to the exit code itself: one assigned (`:=`, `=` or `var`) from `ExitCode()` on such an exit error or `ProcessState`, from another such name, or from the third result of `acsassert.SubprocessOutput` on a `go run` argv (that wrapper is never treated as a command). It flags an `ExitCode()` only on such an exit error or on the command's `ProcessState`, or a name bound to such an exit code, so a built binary's exit code, a `go vet` result, or any other type's `ExitCode()` method is never flagged, and a `range` variable, closure parameter, type-switch or `select`-clause variable that shadows the name stops it being followed only inside its own scope.
- **Only what the go command provably cannot return.** Measured on go 1.27 (2026-10-05): a program that calls `os.Exit(3)` under `go run` gives 1, a build failure gives 1, a bad `$GOFLAGS` gives 1, and only a bad flag before the package (`go run -badflag ./prog`, `go run -race=maybe ./prog`) gives 2. So 0 and 1 are always reachable, 2 is reachable when the argument after `run` is a flag or is not a string literal (it might be one), and a negative literal (`-1`, a signal kill) is not an integer literal and never fires. The reason names the claim exactly: the program's exit code never reaches `ExitCode()`.
- **Known residuals.** The lint is syntactic. It does not follow a TB passed through a struct field, a helper across functions, an exit code copied into a variable or returned from a helper, the code `acsassert.SubprocessOutput("go", "run", …)` returns, a repo-local runner helper, or the clause type a type switch narrows to (a `case *exec.ExitError:` clause variable is not followed). A missed shape only goes unflagged.

The production callers are `internal/evalgate` Gate E, which runs it at the end of every tdd phase and never blocks, and `evolve eval quality-check -predicates` (`internal/cli/guardcmd`), where findings raise PASS to WARN and an `unsatisfiable-lint: linted N file(s)` receipt prints on every run.

**The committed corpus holds no proof-kind finding.** `TestLintUnsatisfiablePredicates_GoAcsCorpusHasNoProofKindFinding` lints every `.go` file under `go/acs`, the nested regression packages included (531 packages and 556 files on 2026-10-05), and requires each file to be linted. It fails on any finding of the two proof kinds, `inverted-idiom` and `go-run-exit-code`, naming it with its remedy; within the tracker's view (above) each is red on every tree. An `absence-message` finding is a keyword heuristic, not a proof, so it is logged and never fails the test: the test runs in ship's repo-contract pack ([internal-repocontract.md](internal-repocontract.md)), and lane ships land `go/acs/cycle<N>` packages, so a heuristic false positive must never block a lane's ship. `TestCorpusProofFindings_ReturnsProofKindsAndOnlyLogsAnAbsenceMessage` pins the split on a fixture corpus holding one of each. A lane that commits a proof-kind predicate anywhere under `go/acs` is stopped at ship, before main. All three kinds are clean on the corpus today.

Pinned by `TestAbsenceIntent`, `TestLintUnsatisfiablePredicates_FlagsOnlyUnconditionalSelfReportingShapes` (the scoping rows included), `TestLintUnsatisfiablePredicates_RemedyMatchesPrimitive`, `TestLintUnsatisfiablePredicates_FlagsTheLiveCycle1488PredicateOnceUnrepaired`, `TestLintUnsatisfiablePredicates_GoAcsCorpusHasNoProofKindFinding`, `TestCorpusProofFindings_ReturnsProofKindsAndOnlyLogsAnAbsenceMessage`, `TestLintUnsatisfiablePredicates_FlagsCycle1788ExitCodeThroughGoRun` (the real `TestC1788_008` body, whose earlier `if err := os.WriteFile(…)` re-binds `err`) and `TestLintUnsatisfiablePredicates_GoRunExitCodeRuleSparesReachableCodesAndBuiltBinaries` (the shadowing, leak-direction, declaration-site, closure-boundary, go-flag and `go vet` rows included) and `TestLintUnsatisfiablePredicates_GoRunExitCodeRuleFollowsExitCodeVariables` with `TestLintUnsatisfiablePredicates_GoRunExitCodeVariableReasonNamesTheCodeAndRemedy` (the exit code copied into a variable or taken from `acsassert.SubprocessOutput`, with its rebinding, shadowing and closure rows; cycle 1846).

## Findings

- **cycles 236/237**: predicates asserted commit presence with `git log`/`git rev-list` ranges. Worktree-normalize soft-resets builder commits to base before audit, so such a predicate is structurally false and killed both cycles (inbox item `normalize-vs-commit-claims`). That produced the commit-presence HALT and its content-parity advice; cycle-236's `001-rescue-parity-landed.sh` is the good exemplar. `TestCheck_CommitPresenceRange_HALT` and `TestCheck_ContentParityAndPlainGit_PASS` are the regressions.
- **ADR-0084 invariant 2** ([incident 2026-08-09](../../incidents/2026-08-09-zero-ship-batch.md)): 281 of 625 live evals used the template's `[code]` bullets, which the scanner did not read, so they parsed zero commands and the gate returned PASS. That produced bullet scanning, the zero-commands WARN and the template round-trip test. Its adversarial review added the top-level-only rule (a BLOCK finding: fenced decoy bullets) and the score_cap note (a MEDIUM finding: about 82% of the corpus is score_cap-graded, so a blanket WARN is alert fatigue).
- **cycles 1173/1175/1178**: the origin of the flaky-shape lint; see [internal-evalgate.md](internal-evalgate.md) Gate D. The review that held it back found it had no production caller, and a silent-clean path where a dropped `-predicates` flag made "nothing linted" look like "clean". That produced the `Files` receipt and the no-`.go`-files error.
- **Argv-position calibration**: an earlier calibration flagged 121 of 284 corpus directories, with patterns handed to non-test subprocesses the largest false-positive source. That produced the argv-position index. The shapes it clears include cycle-969's `buildEvolve` and cycle-941's `module_builds` (`go build`/`go vet` over package patterns), pinned by `TestLintFlaky_GoBuildVet_NotSuiteScope`. The later measurements and the effect of each cut are in [acs-predicate-quality-gate.md](../acs-predicate-quality-gate.md).
- **acsassert.SubprocessOutput**: recognizing only `exec.Command` left the argv-position rule inert, because the corpus's `go vet ./...` predicates went through the house helper and landed in the "unresolvable, keep the note" bucket. Adding the helper to `execConstructors` also surfaced true positives: the multi-package and git-without-`-C` findings, and its load generation, which is unreaped because the helper binds no context. Pinned by `TestLintFlaky_AcsassertSubprocessOutputIsAnExecConstructor`.
- **Helper hop (HIGH-2)**: `go/acs/cycle1034`'s idiom puts the package pattern in a const the test names and the `-run` in a shared helper. Body-only indexing printed "narrow the invocation with -run" at code that already narrowed, 142 of 297 findings (48%). Pinned by `TestLintFlaky_HelperHopResolvesNarrowedInvocation`.
- **cycle-1117**: a predicate named its package through a const (`bridgePkg`), which is why package-level string consts resolve at the use site.
- **cycles 962/968**: the house git idiom passes `-C` inside an `append` composite, which is why `-C` is matched at any depth. Pinned by `TestLintFlaky_GitDashCInAppend_Clean`.
- **Unreaped load generation**: orphaned `yes` generators burned 8 cores for 9 hours across batches 18 to 21, which produced pattern 5 and its `CommandContext` plus `WaitDelay` advice.
- **cycles 1488, 1492 and 1495**: `TestC1488_003` used `FileContains` to assert that a string was absent, which is red on every tree; three lanes burned on it before it was re-authored with `FileNotContains`. That produced the unsatisfiable-predicate lint (inbox `acs-absence-primitive-and-unsatisfiability-lint`). The lint's false-positive cuts came from its first corpus sweep: the swallowing-TB exemption from `go/acs/cycle986` and `cycle1702`, the direct-statement rule from `go/acs/regression/cycle99`, and the whole-message rule from `go/acs/cycle25` and `cycle49`.
- **cycles 1788 and 1793**: both lanes building this lint failed on their own unsatisfiable contracts. 1788's `TestC1788_008` asserted exit code 2 through `go run` (the retrospective reproduced `go run` returning 1 for a child's `os.Exit(2)`), which produced the `go-run-exit-code` kind. 1793's `TestC1793_006` asserted output only the protected `internal/cli/guardcmd` formats. The console landed the lint, its CLI wiring and the acceptance as package tests, and archived both predicate packages under `docs/private/research/archived-2026-10-05/superseded-predicate-packages/` (CHANGELOG, 2026-10-05).
