## Purpose

`internal/evalqualitycheck` holds three deterministic, authoring-time checks. `Check` grades one eval's grader commands for rigor. `CheckDiversity` grades a suite of evals for negative-case coverage. `LintFlakyPredicates` lints ACS predicate Go sources for shapes that flake under fleet load. The callers are `internal/evalgate` (Gate B runs `Check`; Gate D runs `LintFlakyPredicates`) and `internal/cli/guardcmd` (`evolve eval quality-check [-predicates]` and `evolve eval diversity-check`).

## Design

- **Level numbering.** `LevelPass`, `LevelWarn` and `LevelHalt` are 0, 1 and 2, the same values the CLI returns as its exit code. The skill docs number rigor tiers the other way round: their "Level 0" is the always-pass tautology, which is `LevelHalt` here.
- **One eval parser.** `scanBashCommands` serves both `Check` and `CheckDiversity`, so the two can never disagree about what an eval's commands are. It reads non-blank, non-`#` lines inside fences whose opening line contains `bash`, plus the scout template's top-level `` - `[code]` `<command>` `` bullets. The bullet capture takes the second backtick span greedily, because a command may itself contain backticks. `[model]` and `[human]` bullets are not bash.
- **Classification order.** `classify` tries the exact tautologies (`:`, `true`, `exit 0`, `/bin/true`), then trivial bracket tests, then commit-presence ranges (all HALT), then echo-only and grep against an inlined literal (both WARN). Anything else passes. RE2 has no backreferences, so the grep rule accepts any two adjacent quoted arguments rather than two equal ones.
- **Commit-presence rule.** `commitPresenceRE` matches a revision range (`a..b`, `a...b`, trailing-open `a..`) in the arguments of `git log` or `git rev-list`. It is unanchored, so it also fires inside `$(...)` and after `&&`. The `[^|&;]*` guard stops a range in a later pipeline segment being attributed to this invocation. Both ends of the range must be rev-name characters, so a pathspec such as `dir/../file` does not fire. Deliberate gaps: a left-open `..HEAD`, `^main HEAD` exclusion syntax (both rare in evals), and `git diff a..b`, because content parity (`git diff <ref> --quiet`) is the sanctioned pattern.
- **Diversity heuristics.** They are keyword-based and deterministic, a complement to mutation testing, not a replacement. They favor precision over recall, because a false HALT blocks honest work while a missed WARN costs little. A negative case needs a shell-level construct: `! cmd`, `exit 1`, `-ne 0`, `!=` inside a test bracket, or an `assert/expect/should/must` + `fail/error/reject/not` helper name. English words such as "fail" appear in doc-grep evals and never count. Edge-case keywords (invalid, missing, corrupt, malformed, overflow, boundary, empty, empty quotes) are counted and reported but never gate.
- **Diversity scope.** Only `.md` files count. Underscore-prefixed files are meta, canary or example evals and are skipped, and so are files with no parsed commands. `Slug` filters by substring of the file name.
- **Flaky lint layout.** `flakylint.go` holds the pattern rules and their reporters. `flakylint_exec.go` answers "which argv position did this string reach?" and produces no findings itself. The split exists only for the file-size ceiling; the two files are one lint.
- **Flaky lint pipeline.** Parse every `.go` file (a directory is read in `ReadDir` order, so output is deterministic). Collect package-level string consts and vars so a const-indirected pattern resolves where it is used. Index plain functions by name for the helper hop; methods are left out because they would need receiver resolution. Then, per function: build the argv-position index, walk the body, and dedupe findings per (class, reason).
- **Recognized exec constructors.** `exec.Command`, `exec.CommandContext` (its context argument is skipped and binds the child's lifetime) and `acsassert.SubprocessOutput` (no context). A non-literal argument resolves to `""` so argv positions stay aligned.
- **Argv-position awareness.** A package pattern gets a suite-scope finding only if it reached a `go test` argv, or reached no exec argv at all. A pattern handed only to `go build`, `go vet` or `rg` is a compile or a search. An unresolvable pattern keeps its note, the safe direction for an advisory lint.
- **Helper hop.** The index also walks the bodies of same-package helpers the function calls, with the call's string arguments bound to the helper's parameters. `bindParams` returns a copy, so helper bindings never leak into the package-const map the finding scan reads, and it stops at a variadic parameter (many arguments, one name).
- **`-run` narrowing.** It suppresses only the known-slow finding, and only when every `go test` argv carrying the pattern is narrowed. A recursive pattern stays flagged, because `-run` selects which tests run, not which packages are built and loaded.
- **Repo anchoring for git.** `-C` counts at any nesting depth inside the arguments (the `append([]string{"-C", dir}, args...)` idiom); presence can only unflag, so deep matching is safe. A `.Dir` assignment on the variable the constructor was assigned to also anchors, and inside `sh -c` a `cd` segment before the `git` segment does.
- **Shell scripts.** A `sh -c` script string contains spaces, so it is never a package pattern and never reaches the literal scan. The go-test, git, kill and load-generation rules are therefore applied per segment, splitting on `;`, `&`, `|` and newline.
- **Wall-clock rule.** Only `Add`, `Before`, `After` and `Sub` on a direct `time.Now()` chain, plus `time.Since` and `time.Until`, count. The `Unix*` methods are excluded: `time.Now().UnixNano()` is the unique-name idiom, not a deadline, and flagging it would print a claim that is false about the code.
- **PID rule.** A literal PID below 100000 fires only at a liveness site: `os.FindProcess`, `syscall.Kill`, `unix.Kill`, a `kill` argv, or a `/proc/<pid>` path. Such a PID is a stale artifact of the authoring session. A small int const elsewhere is left alone.
- **Known-slow suites.** `internal/core` and `cmd/evolve` take 40s+ under contention even as a single named package. The keys are module-relative, via `gopkgpattern.Key`. The package-pattern rule itself lives in `internal/gopkgpattern`, shared with `internal/acssuite`'s run-time scope-lint.

## Invariants

- **Zero parsed commands is WARN, never PASS.** A gate that parsed nothing verified nothing. The WARN carries one explanatory `ClassifiedLine`, so `Result.Commands` can hold a diagnostic entry that is not a parsed command. Pinned by `TestCheck_ZeroCommandsIsWarnNeverSilentPass` and `TestCheck_NonBashFencedBlock_Ignored`.
- **A score_cap eval with zero bash commands passes with a note.** The ACS suite grades those evals, and a blanket WARN on most of the corpus would train operators to ignore real WARNs. Detection is a line-anchored `score_cap:` key anywhere in the file. Pinned by `TestCheck_ScoreCapGradedEvalPassesWithNote`.
- **Grader bullets count only at top level.** A `[code]` bullet inside any fence is illustration or a decoy planted to fake rigor. Pinned by `TestCheck_FencedDecoyBulletIsNotACommand`.
- **The template and the scanner cannot drift.** `TestCheck_TemplateExampleRoundTripsThroughScanner` reads the `eval-format-template` anchor in `agents/evolve-scout-reference.md`, unwraps its four-backtick `markdown` illustration fence, and requires at least three parsed commands.
- **Diversity gate levels.** No evals with commands: PASS. Any negative case: PASS. A cohesive suite of 3 to `maxCohesiveSuiteSize` (12) evals with zero negative cases: HALT. Anything else with zero negatives: WARN. A cycle authors a handful of evals, and a larger directory is an accumulated archive (`.evolve/evals/` holds every historical task) that must never hard-block. Pinned by `TestCheckDiversity_Levels` and `TestCheckDiversity_ArchiveScaleZeroNegativeIsWarnNotHalt`.
- **Negative-case precision.** Pinned by `TestCheckDiversity_NegativeCasePrecision`, including `!=` inside a grep string (not negative) against `!=` inside a test bracket (negative).
- **Nothing linted is never clean.** Unreadable or unparseable input is an error, and so is a directory holding no `.go` files. `FlakyLintReport.Files` travels with the findings and callers print `Linted()` unconditionally, so "0 findings over 0 files" cannot pass for "0 findings over a linted tree". Pinned by `TestLintFlaky_DirWithNoGoFiles_Error`, `TestLintFlaky_UnparseableSource_Error`, and the receipt check in the `lintDir` test helper.
- **Go-test evidence wins.** A `go vet` on a pattern in the same function never hides a `go test` on it. Pinned by `TestLintFlaky_GoTestArgvWins_EvenBesideNonTestUse`, `TestLintFlaky_PatternInNonTestExecArgv_NotFlagged` and `TestLintFlaky_HelperMediatedPattern_StillFlagged`.
- **The helper hop goes exactly one level.** A helper's own calls are not followed and a self-call is skipped, so the walk terminates without recursion or a visited set. A two-level chain stays unresolvable and keeps its note. Pinned by `TestLintFlaky_HelperHopIsDepthOneOnly`; `TestLintFlaky_HelperHopStillFlagsWideInvocation` pins that the hop also finds wide invocations. The duplicated exec in `go/acs/regression/cycle1270`'s helpers depends on this bound.
- **Narrowing needs every invocation.** Pinned by `TestLintFlaky_NarrowedPlusWideSameSuite_StillFlagged`, `TestLintFlaky_RunNarrowedKnownSlow_NotFlagged` and `TestLintFlaky_RunNarrowedRecursive_StillFlagged`.
- **Preconditions before promotion past advisory.** Narrowing is presence-only on purpose at the advisory stage, where a false claim costs author trust and a missed finding costs nothing. Before any enforce stage: reject trivial `-run` values (`.`, `.*`, `^Test`, empty), all of which read as narrowing today; and treat a pattern built at runtime (`fmt.Sprintf`, `os.Getenv`), which never reaches the scan at all, as not narrowed. Today the risk is bounded: recursive findings are checked before the suppression, and `acssuite`'s run-time scope demotion still fires.
- **Known residuals.** A package-pattern literal used as pure data in a function with no exec (`strings.Contains(enforceFile, "./internal/core")`) is still flagged. Patterns assembled by concatenation, `fmt.Sprintf` or local variables are invisible, and so is a `time.Now()` split across statements, since there is no local dataflow. A missed shape only goes unflagged; the run-time scope-lint and the bounded flake retry remain the backstops.

## Findings

- **cycles 236/237**: predicates asserted commit presence with `git log`/`git rev-list` ranges. Worktree-normalize soft-resets builder commits to base before audit, so such a predicate is structurally false and killed both cycles (inbox item `normalize-vs-commit-claims`). That produced the commit-presence HALT and its content-parity advice; cycle-236's `001-rescue-parity-landed.sh` is the good exemplar. `TestCheck_CommitPresenceRange_HALT` and `TestCheck_ContentParityAndPlainGit_PASS` are the regressions.
- **ADR-0084 invariant 2** ([incident 2026-08-09](../../incidents/2026-08-09-zero-ship-batch.md)): 281 of 625 live evals used the template's `[code]` bullets, which the scanner did not read, so they parsed zero commands and the gate returned PASS. That produced bullet scanning, the zero-commands WARN and the template round-trip test. Its adversarial review added the top-level-only rule (a BLOCK finding: fenced decoy bullets) and the score_cap note (a MEDIUM finding: about 82% of the corpus is score_cap-graded, so a blanket WARN is alert fatigue).
- **cycles 1173/1175/1178**: the origin of the flaky-shape lint; see [internal-evalgate.md](internal-evalgate.md) Gate D. The review that held it back found it had no production caller, and a silent-clean path where a dropped `-predicates` flag made "nothing linted" look like "clean". That produced the `Files` receipt and the no-`.go`-files error.
- **Argv-position calibration**: an earlier calibration flagged 121 of 284 corpus directories, with patterns handed to non-test subprocesses the largest false-positive source. That produced the argv-position index. The shapes it clears include cycle-969's `buildEvolve` and cycle-941's `module_builds` (`go build`/`go vet` over package patterns), pinned by `TestLintFlaky_GoBuildVet_NotSuiteScope`. The later measurements and the effect of each cut are in [acs-predicate-quality-gate.md](../acs-predicate-quality-gate.md).
- **acsassert.SubprocessOutput**: recognizing only `exec.Command` left the argv-position rule inert, because the corpus's `go vet ./...` predicates went through the house helper and landed in the "unresolvable, keep the note" bucket. Adding the helper to `execConstructors` also surfaced true positives: the multi-package and git-without-`-C` findings, and its load generation, which is unreaped because the helper binds no context. Pinned by `TestLintFlaky_AcsassertSubprocessOutputIsAnExecConstructor`.
- **Helper hop (HIGH-2)**: `go/acs/cycle1034`'s idiom puts the package pattern in a const the test names and the `-run` in a shared helper. Body-only indexing printed "narrow the invocation with -run" at code that already narrowed, 142 of 297 findings (48%). Pinned by `TestLintFlaky_HelperHopResolvesNarrowedInvocation`.
- **cycle-1117**: a predicate named its package through a const (`bridgePkg`), which is why package-level string consts resolve at the use site.
- **cycles 962/968**: the house git idiom passes `-C` inside an `append` composite, which is why `-C` is matched at any depth. Pinned by `TestLintFlaky_GitDashCInAppend_Clean`.
- **Unreaped load generation**: orphaned `yes` generators burned 8 cores for 9 hours across batches 18 to 21, which produced pattern 5 and its `CommandContext` plus `WaitDelay` advice.
