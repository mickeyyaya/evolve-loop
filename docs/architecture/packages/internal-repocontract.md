# `internal/repocontract`

Ship's repo-contract fixed scanner pack, in one place: which suites it runs and whether it runs for a tree. Ship's gate (`internal/phases/ship/repocontract.go`) and the build handoff floor (`internal/core/repo_contract_floor.go`) both read it.

## What it owns

- **`Packages()`** is the pack's suite list and its one home. Ship projects it into `repoContractPackages`, and the red message names each suite from it. The list holds the catalog, profile and phase-coherence scanners, the routing tests, and the packages the detector below finds reading the whole tree that are cheap enough to run at every ship: the raw git fixture ratchet, the function-size ratchet, the `TestMain` exit check (`testmainexit`), the env-agnostic param check (`policy`), the trust-kernel call-site scans (`guards`), the ACS tag guard (`acssuite`), fleet's module-graph partition (`fleet`), the unsatisfiable-predicate lint's live-bytes test and its `go/acs` corpus sweep, which fails only on the two proof kinds (`inverted-idiom`, `go-run-exit-code`) and logs the `absence-message` heuristic, so a heuristic false positive in a lane's new `go/acs/cycle<N>` package never blocks its ship (`evalqualitycheck`, under half a second), the inbox rank's weight-sort guard and its snapshot golden (`inboxrank`, since 2026-10-06, ADR-0121 P2: a lane that sorts inbox items by weight anywhere goes red at its own ship) and this package.
- **Test-only helpers stay out of production code.** `TestTestOnlyHelpersAreNeverImportedByProductionCode` walks the module's non-test Go files (skipping `testdata`, `vendor` and dot directories) and fails on any import of `internal/fakeclitest` or `internal/tmuxtest`. `fakeclitest`'s `init` runs whatever script sits beside the running binary, and `tmuxtest.Main` starts and kills tmux servers, so either in a production binary would be a trust-boundary hole. It runs at every ship because this package is in the pack. `TestProductionImporters_FlagsOnlyNonTestFiles` pins that a `_test.go` file or a `testdata` fixture importing a helper is not flagged.
- **`TreeReadingTests()`** is the pack's by-name half: each `TestSelection` is a package pattern and the tests in it that read the whole tree. Ship runs them as one more `go test -run '^(…)$'` over those packages, after the whole packages. One anchored alternation covers every package, so a selected name that also exists in another selected package runs there too; that only adds tests, it never drops one.
- **`PackRuns(gate, root)`** decides whether the pack runs: only while `gates.repo_contract_gate` is on and `<root>/go/go.mod` declares evolve-loop's own module. **`GateOn`** reads the dial, and **`ModuleDir`** gives the module directory.

## Why the list is small and fixed

Every suite costs wall time at every ship, every build handoff and every `evolve selfcheck build`, and it must carry the same near-zero false-red rate, because a red fails the lane. The whole packages run as one `go test` invocation in parallel, so the cost of an addition is bounded by the slowest member, not added on top. The by-name tests run as a second invocation after it; on this tree the two together take about 30s cold, inside the build floor's 120s deadline.

## Why a test that reads the whole tree must run before main

Changed-scope testing selects the packages a lane changed and the packages that import them. A test that reads the whole tree breaks when any file changes. A lane that changes neither its package nor an importer can therefore still break it, and only main's CI would find out.

Cycle 1779 did exactly that (2026-09-30). Its lane ship grew `cmd/evolve.runCycleRun` past the function-size ratchet. The pack held the raw-git ratchet but not the size ratchet, so main went red for every open PR.

## How the list is kept honest

`TestPackages_HoldEveryTestThatReadsTheWholeTree` reads every tracked test file through `rawgitratchet.BoundTestFiles`. A new test file is found once it is tracked or staged. It finds each package whose tests leave their own directory for the tree, in either of two ways:

- **A climb out of the package.** A call whose string-literal path parts, joined and cleaned as `filepath.Join` does (so `./..`, empty parts and a name followed by `..` resolve as they would at run time), lead out of the package's directory, in one of two shapes:
  - It lands on the module root, with or without a subpath after it: `filepath.Abs("../..")`, `filepath.Join(filepath.Dir(self), "..", "..", "acs")`, `PartitionGraph(todos, 2, "../..")`.
  - It lands on a top-level directory with nothing after it, as when `explanationCallSiteFiles("..", vocab)` walks all of `go/internal`.

  Inside a `Join`, a leading `Dir(...)` call is taken to be the package's own directory, any other non-literal before the climb is an unknown base (so the call is not a climb from the package), and a non-literal after it counts as a subpath. Any other call ignores its non-literal arguments, as `PartitionGraph(todos, 2, "../..")` and `explanationCallSiteFiles("..", vocab)` show. `strings` and `bytes` calls are string matching, not paths, so they are ignored.
- **A walk up to `go.mod`.** A bare `for { … }` loop that names `"go.mod"`. A `range` or counted loop naming it writes fixtures; it does not climb.

Each package it finds must be in `Packages()`, or every test that reaches its read must be named in `TreeReadingTests()`. The detector works per declaration: a function, a package-level `var`, `const` or type whose body climbs or walks up reads the tree, any declaration that mentions a reading one reads it too (followed to a fixpoint across the package directory's test files), and every `Test…` function that reads is credited by name. So `TestVerdictEngine_OneConstructionSite`, whose climb sits in the helper `nonTestSourcesMentioning`, is found by name. `packProblems` fails on a reading test that is not selected, on a package whose read no test reaches (it must go into `Packages()` whole), and on a selection that is in the pack or no longer reads the tree. Since cycle 1829 the large packages whose seam or single-writer tests read the tree (`cmd/evolve`, `core`, `phases/ship`, `phases/runner` and nine others) run that way: 50 tests by name instead of the whole packages, which were too slow for every ship. No package is recorded outside the pack any more. `TestClimbsOutOfItsPackage`, `TestWalksUpToGoMod`, `TestReadingTestsOf_CreditsTheTestsThatReachARead` and `TestPackProblems` pin each shape, the negative ones included. The test itself is in the pack, so it runs before main does.

The detector knows these shapes and no others. A test that finds the tree another way is not caught until someone adds its shape here.

## What the detector skips

- **`acs/`.** Main's required CI runs only `-tags acs ./acs/regression/...` (`.github/workflows/ci.yml`), and the audit's CI-parity gate replays that suite for every lane (`internal/phases/audit/ciparitygate`), so a lane that breaks a regression predicate is stopped before ship. The per-cycle predicates under `acs/cycleN` (and `acs/redteam`) are `//go:build acs` and never run in required CI, so they cannot turn main red.
- **Tests that climb past the module root** into the repository's `agents/`, `docs/` or `skills/`. A lane's non-Go edit can break those, but that is a different class: a changed non-Go file mapped to the tests that read it.

## Why no test may write into the real tree

The pack runs at the build handoff floor, during the Builder's self-check and again at ship. In a lane, the tree it runs in is the lane's own worktree, and the build floor reads that same worktree to decide which paths the build must explain. A test that writes into the tree it was built from, even one that removes the file in `t.Cleanup`, leaves a path there for as long as it runs, and for good if its run is killed.

Cycles 1795 (its `signals.ndjson` seq 74) and 1804 were rejected exactly that way. `internal/phasespec`'s real-tree decoy test planted `.evolve/phases/zz-decoy-phasespec-funnel/phase.json` under `repoRoot()`. The pack ran it while the Builder's self-check overlapped, and the explanation floor counted the untracked fixture as an unexplained material path. 1804's disposition records `false-rejection` with root cause `pipeline-code`, and its killed run never removed the decoy. The decoy proof now mirrors the real tracked set into a `gittest` fixture (see [internal-phasespec](internal-phasespec.md)).

### The guard

`TestNoTestWritesIntoTheRealTree` (`realtree_writes_test.go`) parses every tracked test file through `rawgitratchet.BoundTestFiles` (`acs/` and build-tagged files included, since a lane's ACS run and the e2e tier execute in the worktree too). It fails, naming each `file:line` and call, on any write whose path is rooted in the real tree.

- **A write** is a call to `os.WriteFile`, `MkdirAll`, `Mkdir`, `Create`, `Rename` (either side), `Remove`, `RemoveAll`, `Symlink`/`Link` (the new name only), `Chmod`, `Chtimes`, `Truncate`, `CopyFS`, `MkdirTemp`, `CreateTemp` (the directory), `ioutil.WriteFile`, `ioutil.TempDir`, `ioutil.TempFile`, or `os.OpenFile` with a create, write, append or truncate flag. A removal counts: a test that cleans up the real tree wrote there first.
- **A real-tree root** is a `..` climb out of the package (the same `climb` the reader detector uses), `os.Getwd()`, the file from `runtime.Caller`, or the output of a `git rev-parse --show-toplevel` run with no non-literal argument (that is, in the test's own directory). An `os.Getwd()` that comes after the function's first `Chdir` (one not deferred and not inside a closure) reads the directory the test moved to, so it is a root exactly when that `Chdir`'s argument is: a move into `t.TempDir()` makes it clean, a move to `filepath.Join("..", "..")` keeps it rooted. One before the move is always a root.
- **The flow** follows a root through assignments, `var` declarations (package-level too), `range` values, slice literals and indexes, `filepath`/`path` `Join`, `Abs`, `Clean`, `Dir`, `EvalSymlinks`, `FromSlash`/`ToSlash`, `fmt.Sprintf`, `strings`/`bytes` trims, `string(...)` and a command's `Output`/`CombinedOutput`. It is interprocedural within one package's test files (an external `_test` package in the same directory is scanned apart, so two same-named helpers, such as `phasespec`'s `repoRoot()` and `phasespec_test`'s `repoRoot(t)`, never stand in for each other): a function that returns a root (`repoRoot()`, `findRepoRoot(t)`, a `join(root, rel)` helper) yields one at every call site, and a function that writes one of its parameters makes every call passing a root a write, however many calls deep and in whatever order the functions are declared (the e2e harness's `captureLiveFailure` was found that way). Methods are not followed: a method's body is scanned for its own writes, but a call `x.m(root)` is never resolved to it.
- **Names.** A name declared in a function or a closure (a parameter, a `:=`, a `var`) hides a package-level root of the same name inside that function or closure and the closures nested in it, never outside it: a `t.Run` closure's `root := t.TempDir()` leaves an outer use of a package-level `root` rooted. The values a name holds are still tracked per function, ignoring order and blocks: a name that ever holds the real root is the root everywhere in that function, including another subtest's closure. A test that reuses one name for the real root and for a temp dir is flagged; the failure message says to rename the temp-dir variable.
- **Reading is never flagged**, so no allowlist is needed: `os.ReadFile`, `ReadDir`, `Stat` and a read-only `OpenFile` under the real root are the normal way a test proves a property of the real tree. Copying real files into a `t.TempDir()` or `gittest` fixture is the sanctioned way to exercise the real set (`phasespec`'s decoy proof, `profiles`'s `mirrorTrackedProfiles`).

The test also fails when the scan finds no test helper anywhere in the module that returns the real tree. A scan blinded to every root kind would otherwise report a clean tree and pass. The check names no helper, so renaming `phasespec`'s `repoRoot()` cannot break it; losing one root kind while others still work is left to the shape tests. Those tests pin the rest:
- `TestRealTreeWrites_FlagsEveryShapeThatReachesTheRealTree` pins each root and flow shape, including a writer two calls deep declared after its caller (the fixpoint), a working directory read before a `Chdir` or after a `Chdir` into the real tree, and a package-level root used outside the subtest closure that shadows it.
- `TestRealTreeWrites_FlagsEachSinkAtItsPathArgumentOnly` pins every sink at its path argument from an explicit list (not from the scan's own table), and pins the arguments that are not paths.
- `TestRealTreeWrites_SparesReadsTempDirsAndFixtures` pins the negative shapes, including a package-level root shadowed by a parameter or a local temp dir and a working directory read after a move to a temp dir.
- `TestParseTestPackages_KeepsAnExternalTestPackageApartFromItsPackage` pins the per-package grouping.

Removing any one of the fixpoint, a sink, the shadowing rule or the `Chdir` rule turns at least one of these rows red.

### Why a static scan and not a before-and-after `git status`

A test that runs the pack and compares `git status --porcelain --ignored` before and after would be green on the very test that caused 1795 and 1804, because that test cleaned up after itself on success; the harm was the window while it ran. It would also be recursive (this package is in the pack) and as slow as the pack. The scan costs about a second of parsing, runs in the pack, and sees a write whether or not it is undone.

### What the scan cannot see

- **Writes made by production code** a test calls with the real root, or with an empty root that production resolves against the working directory (the package directory under `go test`). Four such leaks were found by running the integration tier and diffing `git status --porcelain --ignored`, and fixed: `go/internal/core/audit-report.md` (a resume test whose fake storage held no workspace path), `go/cmd/evolve/.evolve/guards.log` (two `evolve guard ship` dispatches with the default relative `--evolve-dir`), `go/internal/deliverable/.evolve/ledger.*` (a host-claim effect built without a ledger) and `go/internal/subagent/.evolve/runs` (two `subagent.Run` calls with no project root). A guard for this class has to run the suites. It is the next component: a before-and-after filesystem-walk delta over the tree with no allowlist, written in Go and run through the CLI and `make`. A `git status --porcelain --ignored` diff was rejected for it: git does not show empty directories (the subagent leak was the empty `.evolve/runs/cycle-0` and `cycle-1`), and it would need an allowlist for the build's own outputs. That component consumes inbox `tests-leak-artifacts-into-package-dirs`.
- **Subprocesses.** A command run against the real tree writes through a process the scan does not follow: `exec.Command("git", "-C", root, …)`, a command whose `cmd.Dir` is the real root, or `go run ./cmd/evolve flags generate` pointed at it (the old shape of `core`'s regeneration test).
- **Methods as callees**, **function values** (`w := os.WriteFile; w(root…)`) and **closures called through a variable** (`write := func(p string) {…}; write(root)`): the call is not resolved to the body that writes.
- **`filepath.WalkDir` and `filepath.Walk` callbacks**: the path the callback receives is not tied to the root being walked.
- **A root carried in a struct field**, and a root passed through a function in another package.
- **A relative path**, whether a literal such as `os.WriteFile("out.json", …)` or `filepath.Abs(".")`, which lands in the package directory: the scan treats relative paths as unknown, because a test may have changed its working directory first.
- **A symlink alias.** A temp directory holding a symlink to the real tree, such as the temp worktree whose `go/` links to the real module in `core`'s regeneration test, is a temp path to the scan; a write through the link lands in the real tree. That test writes only `docs/architecture/control-flags.md` under the temp root, never under the link.
