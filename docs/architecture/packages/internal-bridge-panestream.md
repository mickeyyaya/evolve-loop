## Purpose

`panestream` reads rendered tmux `capture-pane` snapshots of an interactive LLM REPL (claude, codex, agy, ollama). It separates agent content from CLI chrome (`ClassifyLine`), extracts newly stable content lines (`PaneDelta`), reports whether a turn is running (`PaneBusy`), judges liveness per CLI (the `LivenessProbe` strategies), and keeps and aggregates that liveness per session (`LivenessCenter`). It imports only the standard library.

## Design

- **One classifier, many projections.** `ClassifyLine` maps a line to `LayerContent`, `LayerChrome` or `LayerAffordance`. `PaneBusy` (any affordance line), `cleanPane` / `PaneHasSubstantiveChange` (content only) and the delta trim (`isVolatileTailRow`: anything but content) are projections of it, so the chrome vocabulary lives in one place. `ClassifyLine` tests for an affordance before chrome, because `statusRE` also matches `esc to interrupt`. It is profile-independent: ollama's `IdlePlaceholder` is a whole-pane rule and lives in `PaneBusy`.
- **Chrome vocabulary.** Status-row leaders (claude `✽`/`✻`, agy `⣯`/`▸`), braille spinner frames, a line that is only an ASCII spinner frame, `Deliberating… 1m 2s` clocks, standalone token counters in either direction, lines made only of `─`, and `statusRE`. `statusRE` is one small frame-derived union of status and footer fragments shared by all four CLIs, not a per-CLI list: the real frames showed one small family of separator, status and footer rows.
- **Affordances.** `esc to interrupt` / `esc to cancel`, and claude's spinner-stats line `(<dur> · <arrow> <n> tokens`. Bare spinner words (`Inferring`, `Generating`, `Kneading`) are not affordances: they add nothing where the esc hint exists, and they can appear in an idle answer.
- **Delta boundary rule** (`stableLines`). Every CLI echoes the submitted prompt on a line that starts with its input marker, then repaints the empty input box near the bottom. The box, the separators around it, the footer and the spinner are volatile. `stableLines` strips ANSI, drops the blank rows `capture-pane` pads the pane with, cuts at the last boundary line (prefix match on the left-trimmed line, or an exact match on the trimmed line when `BoundaryExact` is set), and then trims a trailing run of non-content rows. With no boundary line, the bottom three rows (input box, separator, footer) count as volatile. The trailing trim is what lets an index cursor work: the volatile zone between the echoed prompt and the input box has the same height in the thinking and the answer frame, so a cursor primed on the thinking frame would otherwise land on the spinner and skip the answer.
- **Priming.** The first `Next` call records the baseline and returns nil, so the boot banner, setup warnings and the echoed prompt are never emitted.
- **Content-anchored cursor.** `Next` finds the last emitted line again by its text, searching from the bottom so a repeated line anchors on its freshest copy, and emits what follows it. When the anchor is gone it falls back to a positional count. When the stable region has shrunk below that count, it re-anchors and emits nothing.
- **Per-CLI profiles** (`Profiles`):
  - claude `❯`: the echoed prompt and the empty input box. Answers render as `⏺ …`.
  - codex `›`: after an answer there are three `›` lines (the echoed prompt, an input echo, and the next-prompt placeholder `› Summarize recent commits`). The last one is the boundary, so neither the footer (`gpt-5.5 medium · /dir`) nor the placeholder leaks. The placeholder-bearing input box is why codex keeps prefix matching.
  - agy `>`: `BoundaryExact`, because `>` also starts a markdown blockquote. The empty box is exactly `>`, while the echoed prompt and a blockquote have text after it. The driver's boot marker `? for shortcuts` sits below the input box and is not the content boundary. agy's `▸ Thought for Ns` reasoning preamble is real model output and is emitted as content; only a trailing status leader is trimmed.
  - ollama `>>>`: prefixes both the echoed prompt and the idle input line `>>> Send a message (/? for help)`. While generating, the pane has no bottom `>>>` line, so almost nothing is baselined. When the answer frame arrives, the visible chain-of-thought, the `…done thinking.` delimiter and the bullets all become stable and are emitted. The visible chain-of-thought stays content on purpose: the extractor does no mid-buffer surgery, and suppressing it belongs to a downstream normalizer.
- **Busy detection** (`PaneBusy`). Busy means an affordance line is present, or the profile's `IdlePlaceholder` is set and absent (ollama, whose `Thinking…` header persists into the answer). The input-box marker cannot be the signal, because it persists during generation for claude and agy and ollama echoes it on the prompt line. The bridge's correlation span brackets `idle_reached` on a busy-to-idle transition.
- **Liveness strategies.** `LivenessProbe` is a Strategy. Every probe is stateful (a `PaneDelta` cursor plus counters) and is assessed once per review interval. `DefaultDetector` reads content growth: new content is `LivenessConverging` (0.9); otherwise a quiet pane is `LivenessIdle` (0.7) and resets the stall run; otherwise the pane is busy, `LivenessBusyButStagnant` (0.6) until `hungAfter` consecutive busy-stagnant intervals, then `LivenessHung` (0.8). It needs no busy affordance, so a CLI without one still reads Idle or Converging. `ClaudeDetector`, `OllamaDetector` and `AgyDetector` compose over it. Each returns the base verdict on its first call (priming); after that a CLI-specific signal upgrades the verdict to Converging with higher confidence: a strictly rising `↓` response-token count (0.95), ollama's `Thinking...` line while `...done thinking.` is absent (0.92, checked done-marker first because the pane accumulates), or agy's `⣯ Generating...` line (0.92). Without the signal they return the base verdict unchanged. `ClaudeDetector` counts only `↓`; `↑` is the prompt direction.
- **`DetectorFor` is the only per-CLI branch.** The reviewer (`bridge/stopreview.go`) never switches on the CLI. `LivenessCenter.RegisterHandler` adds or overrides a CLI's strategy without editing that switch, and the center consults the registry before `DetectorFor`.
- **`ExtractResponseTokens`** is the one token extractor, shared by `ClaudeDetector` and the bridge's stop-review. It reads both `↓ 5.2k tokens` and `↓ 5200 tokens` and returns the peak across the pane.
- **`ExhaustionProbe` (Decorator).** The center wraps every probe it creates in one. `Assess` runs the inner probe first so its cursor always advances, then returns `(LivenessExhausted, 1.0)` when `ExhaustedRegex` matches. The bridge fills `ExhaustedRegex` from the CLI manifest (`paneProfileFor`), so `panestream` stays manifest-agnostic. `matchExhaustedPattern` compiles the pattern on every call instead of caching it: patterns are small, and each poll's `capture-pane` IPC costs orders of magnitude more. `bridge/usageclassify.go`'s `matchExhausted` is the same predicate on the far side of the one-way bridge-to-panestream import boundary.
- **Session projections.** `Observe` folds `PaneBusy` and `cleanPane` into each session's `Busy` and `Changed`, so the driver's checkpoint does not parse chrome itself. `Changed` compares against the same key's previous `Observe`, checkpoint to checkpoint.
- **Stateless twins.** `BusyOf` and `ExhaustedOf` serve callers at other loop points than the checkpoint: autorespond's tick busy-gate, the `idle_reached` bracket, and the driver's ~2s fast poll. They never touch the session map, so they cannot disturb the checkpoint's Observe/Aggregate baseline, and they are safe on a nil receiver for callers that hold an optional center. `ExhaustedOf` lets the fast poll see a wall at once rather than at the next 300s checkpoint.
- **Aggregation.** `Aggregate` returns the most dominant observed state: Exhausted, then Converging, Hung, BusyButStagnant, Idle, and 0 for an empty center. ADR-0068 states the rule without Exhausted; ADR-0070 puts Exhausted on top.
- **Handlers (Observer).** `RegisterLivenessHandler` observers receive a `LivenessEvent` on each state transition. The handler list is copied under the structural lock and dispatched outside every lock.
- **`LivenessState.String`** is each state's one spelling (`idle`, `busy-stagnant`, `converging`, `hung`, `exhausted`). `pane.liveness` signals carry it in `fields.state`, and the bridge's timeout summary derives its snake_case word from it.
- **apicover anchors in tests.** Some test files hold `var _ … = …` blocks only so `apicover -enforce` finds each exported type and method named in a test AST (`livenesscenter_apicover_test.go`, the conformance blocks in `liveness_conformance_test.go`, `liveness_exhaustion_test.go` and `livenesscenter_exhaustion_test.go`).

## Invariants

- **Standard library only.** `ansiRE` duplicates `bridge/tmux.go`'s pattern so the package never imports `bridge`.
- **A markdown bullet is content.** Only a line that is nothing but an ASCII spinner frame is chrome. An open prefix match would eat agent content.
- **Token-counter chrome matches both arrows.** claude renders `↑` while generating, the other CLIs `↓`.
- **The spinner-stats duration accepts every shape a turn passes through** (`4s`, `12m 34s`, `1h 5m`). Missing the hour shapes would reopen the stall bug for the longest turns.
- **Affordances are not progress.** A ticking spinner-stats clock never makes `cleanPane` differ, so an agent whose only delta is the clock does not read as working. A working agent still progresses through its transcript (tool calls, output).
- **A boundary marker matches only at line start** (after left-trim), so a marker character inside prose never cuts the region.
- **A zero `LivenessState` means unset.** The deterministic reviewer pauses on it; there is no fallback to the old Progressed/Busy booleans.
- **`defaultHungAfter` (3) stays below the bridge's `defaultArtifactMaxExtends` (6)**, so Hung fast-fails before the maxExtends×interval backstop.
- **Hung needs consecutive busy-stagnant intervals.** A quiet frame resets the run; new content resets it too.
- **`LivenessExhausted` is terminal.** The artifact will never come, so consumers fail over (the bridge's wait loop exits 85 once the wall persists) instead of extending.
- **Exhaustion detection fails open.** An empty or uncompilable `ExhaustedRegex` matches nothing, so a gate misconfiguration never bricks a session.
- **Lock order.** `LivenessCenter.mu` guards only the sessions map, the registry and the handler list, and it is released before any `sessionSignals.mu` is taken. Each `sessionSignals.mu` guards all of that session's fields, and readers (`Aggregate`, `Busy`, `Changed`) read under the same lock `Observe` writes under, so no read is torn.
- **Handlers run inline in `Observe`, outside all locks.** A slow or re-entrant handler cannot serialize other sessions or deadlock, but it delays its own caller, so handlers must be cheap and non-blocking.
- **One probe per session key.** A registered factory runs once per new key, never per `Observe`, so detector state (stall counts, token peaks, cursors) persists. An empty name and a nil handler are ignored; a duplicate name is last-writer-wins.
- **Edge-triggered dispatch.** A key's first observation is a transition from 0, so a session walled on its first frame still dispatches Exhausted. Staying in a state dispatches nothing.
- **Known accepted limit.** When an answer ends in a stable blank line, `PaneDelta` keeps the old anchor and the positional cursor drives the next call, so the top-shift protection is off for that call. Blank content lines are rare enough to accept this.
- **Source readers.**
  - `go/acs/cycle429` asserts that `liveness.go` does not contain `extractTokenCountLiveness` or `rxLivenessTokens`. Do not name them there, even in a comment.
  - `go/acs/cycle433` reads `livenesscenter_parallelevaluate_test.go` and requires the substrings `NewLivenessCenter(`, `.Observe(`, `.Aggregate(`, `.Busy(`, `.Changed(` and `RegisterHandler(`.
  - `TestSignalCenter_SingleDefinitionAntiDuplication` counts package-level `func cleanPane(` and `func PaneHasSubstantiveChange(` definitions in the non-test source of `panestream` (exactly 2) and `bridge` (none).

## Findings

- **Real frames over fabricated ones** (2026-06-04 captures): raw `pipe-pane` output needs a terminal emulator, and marker-presence busy detection never fired. See [bidirectional-channel.md §2](../bidirectional-channel.md).
- **The content-vs-chrome disease** ([ADR-0047](../adr/0047-surface-classification-and-channel-separation.md)): the cycle-312 claude frame `· Schlepping… (50s · ↑ 3.1k tokens)` was chrome to `PaneBusy` but content to `cleanPane`, so a working agent's ticking clock read as progress and a stalled one's did not. The single classifier fixed the class, and `TestClassifyLine_DetectorsAgree` pins it. The chrome regexes `bridge/stopreview.go` used to hold now sit in `classify.go` beside `statusRE`.
- **Two chrome regexes were too open.** The ASCII-spinner pattern first used the prefix `^[-/|\\]\s`, which trimmed every markdown bullet as chrome; it became a whole-line shape. The token-counter pattern first matched only `↓`, so claude's rising `↑` counter leaked into progress.
- **claude 2.1.173** (the 2026-06-11 soak, cycles 286 and 288) dropped `esc to interrupt` from generating panes; the spinner-stats line became claude's only busy chrome. Reading those frames as idle reopened the cycles-254/255 failure: quiet extended thinking, a stall verdict, a pause, exit 81. `testdata/claude/thinking-v2.1.173.txt` is the live capture.
- **codex has a busy signal.** codex was documented as a weak-signal CLI because its committed "thinking" fixture was the idle boot frame. A live codex 0.139 capture (cycle 336) shows `• Working (<dur> • esc to interrupt)`, which `busyAffordanceRE` matches; `testdata/codex/generating.txt` pins it. `codex/thinking.txt` stays the idle boot frame because it is the `PaneDelta` baseline. [bidirectional-channel.md](../bidirectional-channel.md) §2.3 and §6 still describe codex as weak-signal.
- **Top-of-buffer shifts in the real `final.txt` frames** produced the content anchor: codex prepends its trust-prompt prelude (stable region 24 to 36 lines), and agy and ollama prepend a leading blank (18 to 19, 35 to 36) while the answer is unchanged. A positional cursor re-emitted the last bullet.
- **One token extractor** (cycle 429, signal-center S1): the bridge's k-only extractor returned 0 for plain integers such as `↓ 5200 tokens`; `ExtractResponseTokens` replaced both copies.
- **Per-session locks were measured, not assumed** ([ADR-0068](../adr/0068-bridge-signal-center-concurrency.md), cycle 433): with one `RWMutex` held across `Assess`, ns/op rose with parallelism; per-session locks scale about 6x from 1 to 8 procs. `BenchmarkSignalCenter_ParallelObserve` measures it (run with `-cpu=1,2,4,8`).
- **The quota-wall livelock** ([ADR-0070](../adr/0070-signal-center-exhaustion-signal.md)): a walled agy re-printed its quota error, which read as new content, then Converging, then extend forever; phases hung 15+ minutes. Checkpoint-only detection still left about 5 minutes per walled phase at the 300s interval, which `ExhaustedOf` on the fast poll removes.
- **`BusyOf`** (cycle 434) moved autorespond's busy gate and the `idle_reached` bracket off the standalone `PaneBusy` without calling `Observe`, because those sites fire at other loop points than the checkpoint and would have polluted its baseline.
