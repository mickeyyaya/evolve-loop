# internal/auditchain

> The design and its rationale: [ADR-0088](../adr/0088-audit-chain-of-reasoning.md) and the incident record it cites. The single-sourcing rule for the example block: [ADR-0084](../adr/0084-gate-integrity-invariants.md) I2. How the audit phase dispatches and consumes the chain: [internal/phases/audit](internal-phases-audit.md). This page keeps the package-level detail.

## Purpose

`auditchain` makes the audit verdict the conclusion of a chain of reasoning across every prior phase instead of an assertion attached to one. The auditor reports seven stage-to-stage links, each with a status, a finding and a citation; the package parses that chain from the audit report, validates it, derives the verdict from the link statuses, names the human-recognisable failure patterns, and builds the shadow record that compares the chain with the auditor's narrative verdict. It is pure: no I/O.

## Design

- **The four failures are incoherences between stages**, invisible to a check that reads one artifact: derailed (the change is coherent in itself and delivers something other than the intent, `LinkDelivery`), specious (the narrative is larger than the bytes, `LinkNarrative`), paradoxical (the tests were moved to meet the code: `LinkSpecification` incoherent while `LinkImplementation` is coherent), and deceptive (the evidence was produced by the party being judged, `LinkEvidence`).
- **The link set is closed.** `RequiredLinks` lists the seven in reasoning order: intent, selection, specification, implementation, narrative, delivery, evidence. The chain's shape is the contract, so an auditor can neither invent a link to report on nor quietly drop one, and a missing one is detectable.
- **`Conclude` is total and never reads `Finding`.** A missing required link is FAIL; any incoherent link is FAIL, naming it; any unverifiable link is WARN; otherwise PASS. The cases are checked in that order. The auditor supplies statuses and citations and the conclusion is arithmetic over them, which is what makes PASS unassertable over an incoherent link. Unverifiable is the honest middle, deliberately not a defect: an auditor forced to choose between fine and broken for something it could not see chooses fine, which would make unverifiability a laundering channel.
- **`Finding` is the judgement; `Citation` is what a third party can go and look at** (a `file:line`, an artifact path, a command and its output). No machine checks the finding, so no verdict is computed from it. `Conclusion.Diagnoses` names the failure patterns.
- **`Validate`** reports the chain's own defects, independent of what it concludes: an unknown link, a link reported twice (one relationship carries one status), a missing citation or finding, and a chain of more than one link whose citations all name one artifact. `artifactOf` strips the location after the first `:` so two lines of one file count as one artifact; a chain citing a single artifact was narrated rather than walked.
- **`Diagnose`** produces the four names mechanically from link statuses, sorted, so a pattern is reported the same way every time instead of depending on whether a reader noticed. A paradox needs the contradiction; both halves incoherent is an ordinary double failure.
- **Wire format** (`chainblock.go`): an HTML comment opened by `<!-- evolve-audit-chain` and closed by `-->`, one row per link, `id | status | citation | finding`. A comment because the block is machine state that must not clutter the human report; a row per link because a missing link must show as a missing row rather than a subtly different JSON shape. The finding is last, the only free-prose field, and `ParseChainBlock` splits with `SplitN(…, 4)`, so a separator inside the prose stays in the prose instead of shifting later columns. `RenderChainBlock` flattens newlines inside a finding.
- **`ChainBlockExample` is single-sourced.** The literal the persona shows, the parser's round-trip fixture and the text injected into the dispatched prompt are one constant, because every earlier generation that kept the example in the prompt and the parser in Go drifted apart, and the drift surfaced as a gate blaming the agent for producing what it was told to produce. The example is a complete chain concluding PASS: an auditor copies the shape it is given, and a partial example teaches a partial chain, which `Conclude` treats as decisive.
- **`ParseChainBlock` is strict and tail-anchored.** The last block wins, as in `phasecontract`'s sentinel parser: the persona carries the delimiter, so an auditor quoting its instructions above its real block has the quote ignored. Leading and trailing pipes are trimmed from each row, because a markdown table row splits into exactly four fields and would otherwise parse into a link id like `| intent-fidelity`, making every required link read as missing: a silent, plausible, wrong record. Every malformed row, unknown status, missing block or empty block is an error, never a skip: a dropped row becomes a missing link, which `Conclude` treats as decisive, so a silent skip would turn a formatting slip into a FAIL naming the wrong cause.
- **Evidence entitlement** (`evidence_access.go`): a phase that judges must be handed what the phases before it produced, because each of the four failures is measured against an artifact the judge did not write. Withholding them does not make a review stricter; it makes it guess, and a guess that must produce a verdict produces PASS. `IsJudging` follows the act of deciding (audit, adversarial-review, coverage-gate, plan-review, inherited-defect-reconcile, retrospective, retro), not seniority: a producing phase handed the whole prior corpus is cost with no decision attached, and prompts that grow without bound are how the persona-strip truncation happened.
- **`linkEvidence`** maps each link to the artifacts it is read from, which makes "every required link has something behind it" checkable. `RequiredEvidence` is their union for a judging phase and empty for a producing one, sorted because it lands in a dispatch record. `MissingEvidence` names, rather than counts, what a judging phase was entitled to and not given: the failure a gap causes appears later and elsewhere, so it is reported where it is still attributable.
- **Conditional evidence.** `conditionalEvidence` lists artifacts a cycle produces only under a condition, so their absence is "not applicable" rather than "withheld". It holds only `intent.md`, written only when the intent phase runs (`run.json` `intent_required`), which is false on most cycles. Every entry is a downgrade that can never fire on that artifact, so the list is a liability register and stays minimal.
- **`ConcludeWithEvidence` gives the entitlement teeth.** A link reported coherent is downgraded to unverifiable when any of its non-conditional sources was not supplied, whatever the judge claimed: not an accusation, the honest status for a relationship nobody was in a position to check. Without it, a phase dispatched without the intent could report delivery coherent and PASS, a narrated chain indistinguishable on paper from a walked one. When no link loses a source, the pure conclusion stands and the rationale still names the gap.
- **Shadow stage** (`shadow.go`, ADR-0088's rollout): `Shadow` parses the chain, concludes it against the evidence the judging phase was actually given, and returns a `ShadowRecord` the audit phase writes to its workspace as `audit-chain-shadow.json`, while the phase's own verdict stays byte-identical. The datum a soak collects is the disagreement between chain and narrative, and which link the narrative was silent about; enforcing before that record exists would switch a gate on against an unmeasured population. `Shadow` is total, because a shadow stage that can fail to record measures a biased sample.
- **`ShadowRecord` fields.** `ChainPresent` separates "no chain" (expected during rollout; `ChainVerdict` is `absent` and `Absence` holds the parse error) from an empty chain (a defect); conflating them would poison the measurement. `ShippedVerdict` and `OverrodeBy` record what the cycle actually carried after the deterministic gates, which separates "agreed with a PASS a gate then force-FAILed" from "agreed with a PASS that shipped". `ChainVerdict` is the pure conclusion, and `Agrees` compares only it with the narrative verdict; `EvidenceAdjustedVerdict` carries the entitlement downgrade separately and is set only when it differs. `MissingEvidence` is recorded even when the chain agrees, since a chain that agreed while blind is no evidence the chain works. `ChainErrors` lists `Validate`'s findings.

## Invariants

- `Conclude` treats a missing required link as FAIL, never WARN, so omitting a link never lands in a gentler bucket than an honest incoherent answer. `TestConclude_AnIncompleteChainCannotConclude` pins only "not PASS", so the code keeps a one-line why until a test pins FAIL.
- Unverifiable entails WARN, never PASS. Pinned by `TestConclude_UnverifiableCannotSupportPASS`.
- The paradox diagnosis requires the contradiction. Pinned by `TestDiagnose_ParadoxRequiresTheContradiction`.
- Citations must span more than one artifact. Pinned by `TestValidate_ChainMustCiteMoreThanOneStage`.
- The example parses, validates, covers every required link and concludes PASS (`TestChainBlockExample_IsParseableAndComplete`). The auditor persona names every link, both delimiters and the three statuses, and carries the chain instruction above the `## Reference Index` strip marker, so compaction never deletes it (`TestPersona_InstructsExactlyTheShapeTheParserReads`).
- Render then parse is the identity, and a separator inside a finding survives. Pinned by `TestRenderChainBlock_RoundTrips` and `TestChainBlock_FindingMayContainTheSeparator`.
- Table-shaped rows parse, and the last block wins over an echoed example. Pinned by `TestParseChainBlock_HandlesTheShapesAnLLMActuallyEmits`.
- A conditional artifact's absence is never a withholding and never downgrades a link; a link whose required sources are absent is still downgraded. Pinned by `TestMissingEvidence_NamesWhatTheJudgeWasNotGiven` and `TestConcludeWithEvidence_ALinkWithASurvivingSourceIsNotDowngraded`.
- `RequiredEvidence` is sorted, since it lands in a dispatch record. No test pins the order, so the code keeps a one-line why.
- `Agrees` measures the pure chain verdict, so an entitlement gap never masquerades as auditor disagreement, and an absent chain never records as agreement. Pinned by `TestShadow_RecordsTheThreeStatesARolloutProduces`.

## Findings

- The first live shadow cycles reported an evidence gap for `intent.md` on runs where the intent phase never ran. Treating every link's source list as alternatives removed that false positive but disarmed four of the seven downgrades, because a link keeps its teeth only while some source can go missing. Conditioning the one conditionally produced artifact removed the false positive and left the rest armed. `TestConcludeWithEvidence_ALinkWithASurvivingSourceIsNotDowngraded` keeps its name from the alternatives rule.
- Folding the evidence downgrade into `Agrees` once made every clean PASS on a cycle without an intent phase record a disagreement; a soak whose disagreement column is constant measures nothing, so the adjusted verdict became its own field.
- A truncated audit prompt once cost 15 of 30 cycles before anyone noticed the auditor had never been shown the rules it was held to; this is why entitlement is scoped to judging phases and why the chain instruction must sit above the persona's strip marker.
- `withLink` (it returns a copy of the chain with one link replaced) lives in `auditchain.go` but only the tests call it; it belongs in a `_test.go` file.
