## Purpose

`internal/gc` decides which of the resources that finished cycles leave behind are garbage, and releases them. It owns six planners, each paired with its apply step:

| Planner | Resource | Liveness or ownership proof |
|---|---|---|
| `Discover` + `Plan` / `Apply` (`gc.go`, `discover.go`, `logcatalog.go`) | run dirs under `.evolve/runs/`, `operator-salvage`, `.ephemeral` trackers, and the logs of the log catalog (`dispatch`, `loop`, `console`) | a run dir needs a marker file or a polluted-archive name to be considered at all. It is live if it is the current run workspace or has a fresh `.lease`. A log must match a catalog home. The target of `.evolve/logs/current` is never planned |
| `PlanWorktrees` / `ApplyWorktrees` (`worktrees.go`, `salvage.go`) | cycle worktrees under `.evolve/worktrees/` and `cycle-*` branches | the plane's `cycle-state.json`, an open run's `run.json` pointer, a fresh lease whose owner is alive |
| `ReapFinishedCycleOrphans` (`processes.go`) | processes left running by finished cycles | orphan (ppid 1) with its cwd inside a cycle tree that `isLive` rejects and that is gone or closed out |
| `PlanDispatchProcesses` + `StaleDispatch` / `OrphanLogTail` (`dispatch_processes.go`) | processes of a finished dispatch (MCP servers, CLI children) and orphan console log tails | Stale dispatch: the tag parses and the absolute root matches. The owner pid is dead and the process is not a shared helper. Or the cycle is closed out, the ppid is 1, and the process is in the persisted tree and is not a shared helper. Log tail: ppid 1, the program `tail`, and file arguments only under `<root>/.evolve/`. Its age is over `gc.temp_ttl_hours`, and 0 turns it off. See [internal-proctree.md](internal-proctree.md). |
| `TrimGoCache` (`gocache.go`) | Go build cache entries | unused (mtime) past the horizon, or the least recently used beyond the size cap; the cap never takes an entry whose mtime is inside `GoCacheInUseWindow`, and every removal re-checks the entry's mtime first |
| `ReapPipelineTemp` (`tempdir.go`) | pipeline temp artifacts in `os.TempDir()` | exact name shape plus age |

Two callers drive it. The loop's hook (`runGCHook` in `cmd/evolve`), which runs at every batch start and batch end, runs the run-dir and worktree planners and applies them only under `gc.mode: enforce`. The checked-in policy sets enforce since 2026-10-06. An absent mode is shadow, which plans and publishes manifests and mutates nothing. The hook does not run the process, cache, temp or tmux steps; only the operator command `evolve gc` runs those. `evolve gc` runs every planner and always applies them.

## Design

- **Plan is pure, and Apply re-checks.** The two preview mechanisms differ by sweep. The process, cache and temp sweeps take their mutations as injected effects (`kill`, `remove`, `removeAll`), so a `--dry-run` runs their exact code path with no-op effects. The worktree and run-dir sweeps are Plan/Apply: Plan never mutates, and a `--dry-run` stops after it (the salvage-remove's own writes happen only inside Apply). Every apply re-proves liveness per item immediately before mutating it: `Apply` uses `nowLive`, and `ApplyWorktrees` uses `isLive` plus a dirty re-check, all under `.evolve/ship.lock`; `refuseChangedTargets` is the one re-check pass for every action, with per-action rules (a plain remove must be neither live nor dirty, a salvage-remove only not live). A target that became live since planning is refused and reported, never touched, and a salvage-remove re-checks liveness once more after its salvage, immediately before `--force`, because resume-time worktree reuse does not take `ship.lock`.
- **Evidence, not names.** A run dir is a run only when it holds a marker file, and the marker list is derived from `phasecontract.RequiredArtifacts()`, not re-typed (cycle 1141). A worktree's branch comes from `git worktree list --porcelain`, not from its directory name. A cycle is finished when its closeout dossier exists (`dossier.ClosedOut` / `ClosedOutAt`). A process belongs to a cycle through its working directory.
- **The liveness pointer that outlives its run.** A sealed run's `run.json` keeps `active_worktree` forever. Until 2026-09-29 `isLive` treated that pointer as liveness, so the worktree sweep planned nothing for 87 finished trees (7.3 GB). A `run.json` match now counts only for a run with no closeout dossier (`runClosedOut`). The plane's `cycle-state.json` and the lease checks are unchanged.
- **Salvage before force.** A dirty or unmerged finished tree is not flagged forever once `salvage_after_hours` has passed since its closeout. `salvageWorktree` writes `HEAD` (sha and branch), `uncommitted.patch` (`git diff HEAD --binary`) and `untracked.tgz` (`git ls-files --others --exclude-standard`, symlinks stored as links) into `.evolve/operator-salvage/<leaf>/`, which is already on the `salvage_ttl_days` ladder. Only then does `git worktree remove --force` run. The branch is never deleted, so committed lane work and a continuation's `snapshot_sha` survive. Continuation adoption seeds from the SHA; the binding's `Worktree` field is informational.
- **One owner for the salvage layout.** `OperatorSalvageDir` is the only place the directory name is spelled, and the leaf file names (`HEAD`, `uncommitted.patch`, `untracked.tgz`) are constants that the writer `salvageWorktree` and the reader `ListSalvage` (`salvage_list.go`) share. `ListSalvage` is read-only and starts no subprocess. It returns every readable leaf sorted by (cycle, leaf), and it joins one `gc: salvage leaf <leaf>: <cause>` error for each leaf whose HEAD is missing or malformed or whose patch or archive cannot be read. `evolve salvage list` adds the `landed` check against `origin/main`. Pinned by `TestApplyWorktrees_SalvageRemoveKeepsARestorableCopyAndTheBranch` (gc's own salvage reads back through `ListSalvage`) and `TestListSalvage_ReadsEveryLeafAndNamesEachUnreadableOne`.
- **The closeout time is the dossier's mtime.** A published dossier is a tracked file whose mtime is its checkout or merge time, which is at or after the closeout, so the measured age can only be underestimated. That errs toward keeping a tree.
- **Processes are owned through their cwd, and liveness has one owner.** `finishedCycleTree` first asks `isLive`, the same rule the worktree sweep uses, and only then looks for finished evidence (the tree is gone, or a dossier exists). A dossier alone would be a second, weaker belief: a resumed cycle keeps its FAIL dossier while it runs again in the same tree. Phase agents run inside their cycle's worktree, and a load loop or server they background keeps that cwd after the tmux pane dies and it is reparented to pid 1. `lsof -a -d cwd -u <uid> -R -F pRn` lists every process's parent and cwd in about 0.1 s. `leafUnder` compares both the literal and the symlink-resolved worktree base (macOS `/var` vs `/private/var`), and the leaf must carry the `cycle-` prefix, because a numbered non-cycle directory would otherwise map onto a closed-out cycle's number.
- **The cache trim is Go's own trim with a policy horizon.** The go command refreshes an entry's mtime when it uses it, and its `cache.Trim` removes entries unused for 5 days. The loop outgrows that: each cycle builds in a new worktree path, and a package's cache key includes its directory, so each cycle re-caches the module in every mode (about 40 GB a day on 2026-09-29). `TrimGoCache` removes only `<hash>-a`/`<hash>-d` files in the 256 hex shards. The cache root's `README`, `trim.txt`, `testexpire.txt` and the `fuzz` corpus are never touched. A build that looks an entry up at the instant it is trimmed can see a miss or a missing output file, the same race Go's own trim has; an entry unused past the horizon is in no running build's working set.
- **The cache also has a size cap (2026-10-06).** The age trim alone cannot bound a cache that fills within its horizon. On 2026-10-06 the cache held 71 GB, of which 2 GB was older than 24 hours, so a 24-hour trim released almost nothing. `TrimGoCache` now plans in one pass. It first marks the entries unused past `gc.go_cache_ttl_hours`. Then, over what is left, it takes the least recently used entries (ordered by mtime, then path) until the remainder fits `gc.go_cache_max_gb`. Because the plan comes before any removal, a dry run counts each entry once. The report carries the age trim's and the cap's counts separately, and the bytes that remain.
  - **The in-use window is an mtime window.** The cap never takes an entry whose mtime is less than `GoCacheInUseWindow` old. The window is derived visibly as `2 × goMtimeRefresh`, where `goMtimeRefresh` is one hour.
    - **Why mtime lags.** The go command refreshes an entry's mtime only once it is more than an hour old (`mtimeInterval` in `cmd/go/internal/cache`). An entry looked up within about the last hour can therefore carry an mtime up to an hour old.
    - **What the window covers.** Entries looked up within about the last hour, plus a one-hour hold for a build that keeps a looked-up output that long before it reads it.
    - **What it does not cover.** It is not "used within 2 hours", and it does not protect a build that holds an output for longer than that.
    - **When the cap stops short.** If the entries inside the window alone exceed the cap, the trim stops short, and `evolve gc` warns with the bytes that remain.
  - **The age trim is floored at the window too.** A `go_cache_ttl_hours` below 2 acts as 2: `unusedBefore` takes the later of the policy horizon and the in-use window, so no setting lets the age trim take an entry a running build may still read. Pinned by `TestTrimGoCache_AnAgeHorizonShorterThanTheInUseWindowNeverTakesAnEntryInsideIt`.
  - **Every removal re-checks its entry.** The plan is a snapshot. A long removal pass can race a concurrent build that looks a victim up and refreshes its mtime, so `release` `Lstat`s each victim immediately before removing it. It skips any victim whose mtime has moved inside the age cutoff (age victims) or the in-use window (cap victims). A skipped entry still counts in the bytes that remain. The plan also never picks an entry inside the window, so the window is held twice: at plan time and at removal. Pinned by `TestTrimGoCache_TheCapSkipsAVictimABuildUsedAfterThePlan`, `TestTrimGoCache_TheAgeTrimSkipsAVictimABuildUsedAfterThePlan` (a `remove` that touches the next victim) and `TestLeastRecentlyUsedOverCap_NeverPlansAnEntryInsideTheInUseWindow`.
  - **mtime, not atime.** mtime is the use clock Go itself writes. atime depends on mount options and proves nothing.
  - **Why the cap is 20 GB.** The 2026-10-06 measurement put 15.5 GB of the cache inside the last 2 hours and 22.4 GB inside the last 4 hours, with concurrent console floors and three lanes building. A 20 GB cap sits above the in-use window, so it is reachable, and it keeps the last two to three hours of builds warm. Entries older than that are almost all keyed by worktree paths that no longer exist (see the age-trim bullet), so keeping them buys no cache hits.
- **Temp artifacts are matched by shape, not prefix.** `pipelineTempRe` lists the exact shapes the pipeline's own code creates, plus Go's build work dir: `go-build<N>`, `acs[-cycle]<N>-…`, `cycle<N>-…` and `release-pipeline-dryrun-….json`. A `go-build<N>` dir is meaningful only while its build process lives, so one past the horizon is a killed build's leftover. Go's `t.TempDir` shape (`Test…`) was dropped in review: in a shared temp dir, any project's or program's `Test…` entry would match, so it proves no ownership. The list is code knowledge of these artifacts, not a threshold; the horizon is policy.
- **One leaf parser.** `LeafCycleNumber` maps a worktree leaf or `cycle-*` branch to its cycle (a swarm `-integration`/`-w<N>` suffix stripped). It is exported so `evolve worktree cleanup --stale` and `evolve branches audit|prune` (`go/cmd/evolve/cmd_worktree_stale.go`) read a lane's cycle, and with it its dossier and run lease, the same way this sweep does.
- **Logs follow one catalog (2026-10-08).** `gcpolicy.Policy.LogCatalog` gives each log category its homes, its TTL and its size cap. A home is a dir and a glob, for files or for run dirs. `logPlanner.planCategory` sorts the entries of each category newest first. It deletes an entry older than the TTL (rule `logs.<category>.ttl_days`). Then it deletes the oldest entries that take the total over the cap (rule `logs.<category>.max_total_mb`).
  - The cap counts only the entries that the TTL keeps. The kept total includes the logs that gc never deletes. These are the target of `logs/current` and a log with a live writer. A live writer is a `<log>.writer-pid` file that names a live pid, or that gc cannot read. When those logs alone keep a category over its cap, `Manifest.Warnings` carries one line, and `evolve gc` and the batch hook print it as a WARN.
  - A run log dir ages by its newest file, because a dir mtime does not change when a file in it grows.
  - Symlinks (`boundary-loop.log`, `logs/current`) are never planned.
  - The catalog replaces the old Rule 4, which covered only `dispatch-logs/*.log`. The plan is [logging-and-process-hygiene-2026-10.md](../../plans/logging-and-process-hygiene-2026-10.md).
- **Polluted archives are dead runs.** `core.archivePollutedWorkspace` renames a polluted workspace to `cycle-N.polluted-<stamp>`. The archive holds only gc manifests, so it has no run marker, and before 2026-10-08 `Discover` skipped it forever (20 dirs on the plane). `Discover` now takes the archive name as evidence. The name is minted by `gcpolicy.PollutedArchiveName` and matched by `gcpolicy.IsPollutedArchive`, one source for the writer and the reader. The archive cannot be live, because nothing writes to the renamed dir.
- **Config is a leaf.** The knobs live in `internal/gcpolicy` (`Policy`, `RunsPolicy`, `WorktreesPolicy`), re-exported here as aliases, because `internal/policy` must not depend on an engine. Every horizon's zero value means never, and `WithDefaults` never invents a deletion horizon. The cache cap is the one exception, and it is a bound, not a horizon. `Policy.GoCacheMaxBytes` resolves an unset or non-positive `go_cache_max_gb` to 20 GB, because a cache entry is regenerable (losing one costs a rebuild), and an unbounded cache is what filled the disk. A host that wants no effective cap sets a large value.

- **Discovery never hides a run.** A symlinked run dir (an operator alias for a relocated run) is stat'ed through its link and discovered. A dangling link or a loose file at the root is not a run. Skipping symlinks makes the run invisible to `keep_full` and to liveness. Pinned by `TestDiscover_SymlinkedRunDirIsVisible`.
- **Liveness signals fail closed.** An unreadable `cycle-state.json`, or an in-flight workspace that is not absolute, aborts discovery. Classifying runs as dead on an unreadable signal lets a live run be collected. Pinned by `TestDiscover_FailsClosedOnUnreadableRunStateFile` and `TestDiscover_FailsClosedOnNonAbsoluteWorkspace`.
- **Apply is not a replay.** Archives are not idempotent: a re-applied archive fails on its missing source. A stored manifest is never re-applied; each run plans fresh.
- **Removal order.** Worktrees are removed before their branches, because git refuses `branch -d` on a branch still checked out in a linked worktree. One trailing `git worktree prune` reconciles the batch.
- **Archive collisions take a numeric suffix.** The suffix is deterministic and needs no clock. A rename across filesystems fails with EXDEV, so `.evolve/archive` must stay on the same mount as the runs it receives.
- **Subtree items re-check their parent.** Apply re-checks liveness on an item and on its parent, because a subtree item such as `.ephemeral` lives under a run dir. Any verification error counts as live.

## Invariants

- **Nothing live is ever touched.** A live run dir, a live worktree, and a live cycle's processes are excluded at plan time and re-checked at apply time. Pinned by `TestPlanWorktreesNeverTouchesLiveDirtyUnmerged_Property` (random populations of live, dirty, merged, closed-out and aged trees under a random salvage horizon), `TestApplyWorktrees_ASalvageTargetThatTurnedLiveIsRefusedUntouched` `TestApplyWorktrees_ATreeThatTurnsLiveDuringItsSalvageIsKept` and `TestIsLive_AClosedOutRunsStalePointerDoesNotKeepItsWorktreeLive`.
- **Unsalvaged work is never force-removed, and an unmerged branch is never deleted.** A plain remove is only for merged, clean trees (`git branch -d`). `salvage-remove` requires a finished, policy-aged, dead tree, and a failed salvage keeps it. Pinned by `TestApplyWorktrees_SalvageRemoveKeepsARestorableCopyAndTheBranch` (the saved patch applies cleanly on the kept branch and reproduces the uncommitted edit) and `TestApplyWorktrees_AFailedSalvageKeepsTheTree`.
- **A process is signaled only on the ownership proof.** Pinned by `TestFinishedCycleOrphans_TakesOnlyOrphansWhoseCwdIsInsideAFinishedCycleTree` (ten cases, including an attached shell, a live tree, a resumed cycle's tree that already holds its dossier, a numbered non-cycle directory and a base-prefix sibling) and by a real orphaned `sleep` in `TestRunGC_TerminatesAnOrphanLeftRunningInAClosedOutCycleTree`.
- **Only the exact artifact shapes go.** Pinned by `TestTrimGoCache_RemovesOnlyEntriesUnusedSinceTheCutoff` and `TestReapPipelineTemp_RemovesOnlyStalePipelineArtifacts`, whose fixtures include `com.apple.*`, `tmp*`, a `Test…` dir and near-miss names that must survive.
- **The cache cap takes the least recently used entries and never one a running build may read.** Pinned by `TestTrimGoCache_TheCapTakesTheLeastRecentlyUsedEntriesUntilTheCacheFits`, `TestTrimGoCache_ACacheAlreadyUnderTheCapIsLeftUntouched` (every mtime unchanged), `TestTrimGoCache_TheCapNeverTakesAnEntryARunningBuildMayStillRead` and `TestTrimGoCache_TheCapCountsOnlyWhatTheAgeTrimLeavesSoAPreviewNeverCountsAnEntryTwice`. At the command level they are pinned by `TestRunGC_TrimsTheGoBuildCacheToItsCapLeastRecentlyUsedFirst` and `TestRunGC_WarnsWhenEntriesInUseKeepTheCacheOverItsCap`. Every `runGC` test aims `GOCACHE` at a temp directory through `gcWorktreeEnv`, so no test reaches the host cache.
- **The batch hook in enforce never touches a dev worktree, a live lane, an unmerged branch or a continuation snapshot.** Pinned by `TestRunGCHook_TheCheckedInEnforcePolicyNeverTouchesADevWorktreeALiveLaneAnUnmergedBranchOrAContinuationSnapshot`, which loads the checked-in `.evolve/policy.json` gc block. Its fixtures are built to tempt the sweep:
  - two hub dev worktrees named and branched `cycle-console-*`, with closed-out dossiers. One is dirty and unmerged. The other is merged and clean, and the sweep plans a `branch -d` for its branch, which git refuses because the branch is checked out.
  - a dirty, unmerged lane whose cycle closed out 72 hours ago but which holds a fresh lease again (a resumed cycle).
  - an unmerged orphan `cycle-*` branch.
  - a continuation lane whose snapshot commit is bound in `continuation-registry.json`.

  The control in the same test: that continuation lane's tree is salvaged and removed, while its snapshot commit stays on the kept branch and the registry is unchanged. Adoption seeds from the SHA. `TestTheCheckedInPolicyRunsTheWaveEndGCInEnforce` pins the mode itself.
- **Protected paths are never planned.** `quarantine/`, the ledger files (`ledger.jsonl`, `ledger.tip`, `ledger.lock`, `ledger-segments/` and, since 2026-10-06, the evidence store `ledger-artifacts/`, spelled by `ledgerartifacts.DirName`) and `archive/` are manual-only (`protected`). The evidence store is the ledger's: a composition-verdict line whose diff is gone breaks the chain, and ship then refuses every carry ([incident](../../incidents/2026-10-06-carry-refused-ledger-verify-f5.md)). Pinned by `TestApply_RefusesTheLedgerEvidenceStore`, and across every sweep, the loop's enforce hook and an operator `evolve gc`, by `cmd/evolve` `TestGC_TheEnforceHookAndTheOperatorRunKeepTheLedgerEvidenceStore`. No sweep reaches the store today (run dirs, registered worktrees, the Go cache, temp files and dev worktrees all live elsewhere); the protection keeps a future rule from changing that.
- **A log that a live loop writes is never planned.** Pinned by `TestPlan_LogCatalogNeverPlansALogThatALiveLoopWrites` and `TestPlan_LogCatalogKeepsALogWhoseWriterPIDFileCannotBeRead`.
- **The current loop log is never planned.** The target of `.evolve/logs/current` is skipped before the TTL and the cap. Pinned by `TestPlan_LogCatalogNeverPlansTheCurrentRunDir`, with a 4 MB log over a 1 MB cap and a 1-day TTL. `TestPlan_LogCatalogNeverPlansForeignFilesOrSymlinks` pins that `guards.log`, a non-log file and every symlink stay.
- **A fresh heartbeat with a dead owner is not liveness.** A lease whose named owner pid is dead is collectable even inside the heartbeat window: that window is the crashed owner's 2 to 6 minutes. Pinned by `TestPlanWorktrees_DeadPidFreshLeaseCollected`.
- **A failed listing mutates nothing.** An unreadable cache or temp dir, or a failed `lsof`, is reported as an error and no entry is touched (`TestTrimGoCache_AMissingCacheIsReportedNotIgnored`, `TestReapFinishedCycleOrphans_AFailedListingSignalsNothingAndIsReported`).

## Follow-ups

- **One `cycleTreeHold` spec.** Two places decide whether a finished cycle tree may go: gc's `keptOrSalvaged` (`worktrees.go`), and `evolve worktree cleanup --stale`'s `readLaneBindings` (`cmd_worktree_stale.go`). They disagree on continuation-bound trees. `--stale` keeps a tree that a continuation binding names, by branch or by worktree leaf. gc salvages and removes it once it is past `salvage_after_hours`, and keeps the branch, which holds the snapshot commit. No data is lost today, because adoption seeds from the snapshot SHA. Still, both should read one shared spec, `cycleTreeHold`, so the two sweeps cannot drift. This note is recorded here, not filed as an inbox item, per the 2026-10-06 review.

## Findings

- **2026-10-08, the logs that no rule deleted.** The operator asked if gc cleaned the loop log after a job. It did not. `boundary-loop.log` had 2.74M lines (312 MB), because each wave appended to one file. 86 top-level `.evolve/*.log` files held 1.35 GB, and Rule 4 covered only `dispatch-logs/`.
  - The log catalog now covers the loop, console and dispatch logs. Each launch writes a new log dir.
  - On the same day, the inventory found 20 polluted run archives that `Discover` skipped.
- **2026-10-06, the GC that only reported.** The operator asked whether GC ran after a task or a wave. The hook did run, at every batch start and batch end, but its mode was never set, so it ran in shadow, the soak stage it landed in on 2026-09-29. Each run printed `[gc] shadow: 0 items` and `[gc] worktree shadow: 49 items` (all 49 flagged unmerged orphan branches) and released nothing. The cache was outside the hook altogether. `evolve gc` trims it only by age, and the whole cache was younger than the 24-hour horizon. Free disk fell from 161 GB to 84 GB in a day, with 70 GB of that in the Go build cache. The fix promotes the hook to enforce, after the safety test above, and adds the size cap. The dev-worktree half of the same question belongs to `evolve worktree cleanup --dev` (`cmd/evolve/cmd_worktree_dev_cleanup.go`), which now accepts a content-landed proof.

- **2026-09-29, the sweep that saw nothing.** 87 finished trees, 79 dead sockets, 14 orphaned CPU loops, 60 GB of Go cache and 56 GB of temp artifacts were all outside what `evolve gc` could see: the stale `run.json` pointer made every tree live, `kill-server` left the socket files behind, and nothing looked at processes, the cache or the temp dir. The mutation sweep over the new decision points killed 13 of 13 mutants after two gaps it found were closed: the `cycle-` prefix guard, and the failed-salvage path.
- **Cycle 1762.** The auditor reproduced a flake under load with `hw.ncpu` busy loops and never stopped them. They ran for 47 minutes at a load average of 118 and starved the cycle's own host predicate run, which then failed with "produced no execution results". The process sweep is the release; the auditor's hygiene is its own inbox item.
