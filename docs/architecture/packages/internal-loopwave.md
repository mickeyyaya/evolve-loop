## Purpose

`internal/loopwave` is the loop's wave engine. One `Engine` decides sequential versus wave, runs the one dispatch body that the wave fan-out and the min-width repair share, loads and reloads the fleet block, builds the freshness-gated launcher, sizes each wave against quota benches and the budget, and produces the wave's plan. The wave coordinator, the pool scheduler, the budget probe and the loop's halt and escalation producers stay in `cmd/evolve`.

## Design

- **A leaf beside `cmd/evolve`, not under `internal/core`.** `fleet`, `guards`, `inboxmover` and `triagecap` all reach `internal/core`, so a `core` sub-package would form an import cycle. The package imports twelve declared internal packages and never `core` or `guards` directly. The protected-surface predicate and the prior-cycle readers are ports. The allowlist is a declaration; the compiler remains the cycle guard.
- **The Engine.** It holds the two roots, four required ports (`LastCycle`, `Workspace`, `Protected`, `Shrink`), a writer for the report lines that are not signals, and a Signal Center accessor. It reports its failure modes as `loop.wave` WARNs under module `loop`, and every event carries `fields.wave`. `EmitWave` is the only `loop.wave` producer; `cmd/evolve`'s `emitLoopWave` projects onto it.
- **Which root each reader uses.** `--evolve-dir` can move `EvolveDir` away from `<ProjectRoot>/.evolve`, and each call site keeps the root it read before extraction. The plan, the seed and the widen read `EvolveDir`. The lifecycle probe, the consumed prune, the refill, the bench store and the routed resolver read `<ProjectRoot>/.evolve` (Q-W7, Q-W8). `RootsOf` serves host facades that carry only a project root (the pool scheduler, the budget wrapper). The zero `Roots` is the rootless engine of the pure dispatch facades.
- **One gate.** `ShouldRunWave` is `Count > 1`, plan source `triage`, and scheduling not `pool`. It is the only seam that decides sequential versus wave.
- **One dispatch body.** `dispatch` runs preflight, plan, adapt (the fan-out into at most `count` disjoint specs) and launch. Every failure is a `*StepError` and launches nothing. An empty adapted plan returns `Ran=false` and launches nothing, so the caller falls back to sequential instead of burning an iteration. `Dispatch` is the gate plus the body at `Config.Count`, and emits one `LOOP_WAVE_DISPATCH_FAILED{path=wave, step, error}` on failure. `ForceOneLane` is the body at a count of one, ungated and silent. `StepError` exists so the producer can stamp `fields.step`; its text is the `wave N: <step>: <cause>` line the host always printed.
- **Min-width repair.** The coordinator reaches `RepairMinWidth` when `Dispatch` returns `ran=false` with no error. Eligibility is the operator's asserted width alone: `fleetCfg.Count > 1` means the operator wanted a fleet, so both the quota-shrunk wave and the empty plan at full width repair to one isolated lane instead of falling through to sequential, the only unisolated mode. Its four branches emit one WARN each: guard not met gives `LOOP_WAVE_EMPTY_PLAN cause=empty_triage_plan` and touches nothing; a dispatched lane gives `LOOP_MIN_WIDTH_REPAIR` and returns `handled=true`; an empty backlog gives `LOOP_WAVE_EMPTY_PLAN cause=empty_backlog`; a step error gives `LOOP_WAVE_DISPATCH_FAILED path=repair`.
- **Two fleet loaders, one deliberate divergence.** `LoadFleetConfig` runs at batch start and falls back to the defaults (`Count=1`, sequential) on any error. `ReloadFleetConfig` runs at every wave boundary so a width directive committed mid-batch takes effect at the next wave. On an unreadable or malformed policy it holds `prev`, the operator's standing width. The "fleet config reloaded" line prints only when count, min_lanes, plan_source or scheduling changed, never for concurrency alone (Q-W4). It is a package function because it reads one root and needs no engine.
- **Freshness-gated launcher (Decorator).** `Engine.Launcher` wraps a `fleet.Supervisor` over the same exec launcher `evolve fleet` uses, so lanes inherit `EVOLVE_FLEET=1` and `EVOLVE_FLEET_SCOPE`. Decorating there gates both the wave and the repair at one seam, and the wave index rides in so the all-stale WARN is wave-indexed. The probe: a pending id is fresh unless a declared dep is still pending, processing or in retry; an id with no lifecycle evidence is fresh; any other state is stale, with the state as its reason. The refill takes the highest-weight pending todo outside the exclude set and shapes it as a lane (scope plus `EVOLVE_FLEET_SCOPE`; the supervisor forces `EVOLVE_FLEET`). It is deliberately minimal: weight only, with no file-disjointness re-check against the kept lanes.
- **Sizing in two layers.** First the `Shrink` port (`fleet.QuotaAwareCount`) shrinks the count by the active `clihealth` benches, to a minimum of one, with one WARN per benched family. Any bench shrinks the wave because a lane is a full `evolve cycle run` that may route to any installed family. `Store.Active` degrades a missing or corrupt bench file to an empty map, so bench state never breaks a dispatch. Second, only when a `fleet.budget` block exists, `fleetbudget.Plan` sizes the shrunk count against measured quota headroom and pace. Stage `enforce` applies `plan.Lanes` and returns `plan.PaceDelay`. Every other stage, `shadow` included (the default), logs the would-be size and holds the count. The shadow join is logged on both stages and never feeds the plan.
- **The plan source.** Preferred is the immediately prior cycle's committed `triage-decision.json` (`LastCycle`, then `Workspace`), pruned of consumed ids, then of console-routed ids, then widened to fleet width. An absent decision (fresh start, a sealed run dir, a cycle that failed before triage) or a failed last-cycle read falls through to the inbox seed, so a two-wide wave starts on the first cycle. `cardPackages` is always nil: no card-package reader exists, and `top_n[].id` cards flow through the fan-out's own fallback. Only `LastCycle` observes ctx; the decision read is a plain `os.ReadFile` (Q-W10).
- **The seed.** `SeedWavePlanFromInbox` clamps count to at least two. Fewer than two disjoint lanes is an error, counted as menus rather than flattened ids, so one four-item cluster still cannot fill a two-lane wave. Each lane is deepened with its same-file cluster mates up to `inboxbatch.DefaultMaxItems`.
- **The widen.** It prunes the committed `top_n` through `triagecap.PruneConsumed` (the seed's primitive), backfills to `count` disjoint lanes and deepens each lane with its cluster mates at the seed's cap, so the mid-batch path amortizes a lane's worktree, build and audit across its cluster exactly as the seed does. An empty `top_n` is not a no-op: it widens fully from the backlog.
- **Two re-marshal fidelities, as two named functions.** The prunes keep every key of the decision (`remarshalFull`); the widen emits `{"top_n": …}` only (`remarshalTopN`, Q-W3). Both fall back to the original bytes if marshalling fails, which cannot happen for parsed JSON.
- **Which reports stay plain lines.** The reload WARN (the boundary reload also runs on the pool path), the routed resolver's refusal (the pool scheduler calls it with no Center), the `[budget]` lines (INFO never reaches the console, and there is no `budget` module), the prune WARN lines (the pool path has no Center), and fleet's own per-lane skip lines. Turning them into codes is tracked as follow-ups F3, F6 and F9 in [13-loopwave.md](../decomposition/13-loopwave.md) §8. The four coded conditions reach stderr only through the Center.

## Invariants

- **Roots are set in both halves or neither.** A half-populated `Roots` would resolve its empty half relative to the working directory. Pinned by `TestRootsOf_DerivesEvolveDirTheProductionWay` and, at the host seam, `cmd/evolve` `TestNullWaveEngine_EveryConstructionCarriesBothRootsOrNone`.
- **Ports are required.** A nil port is a programming error and panics at first use; there is no default.
- **The Signal Center accessor is read at every use.** The batch Center is built per batch, and the coordinator is assembled as a literal. A nil accessor, or one that returns nil, emits nothing. Pinned by `TestEngine_NullObjectAndSignalsWired`.
- **`EmitWave` never writes the caller's map.** The wave is stamped on a copy. Pinned by `TestEmitWave_InfoWithoutCodeWarnWithAndStampsWaveOnACopy`.
- **The wave and pool gates are mutually exclusive**, so one iteration never fires both. Pinned by `TestShouldRunWave_GateTable`.
- **One body, one fan-out call.** `TestDispatchAndForceOneLane_ShareOneBody` reads `dispatch.go` and every other non-test file and requires exactly one `fleet.PlanFromTriage(` token, in `dispatch.go`. It counts comments too, so never write that token in a comment in this package.
- **The shared body never emits.** Each caller owns its signal. Pinned by `TestForceOneLane_CapsAtOneLaneUngatedAndSilent` and `TestDispatch_EmptyPlanIsRanFalseWithNoSignalAndNoLaunch`. With the gate off, `Dispatch` runs neither preflight nor plan nor launcher (`TestDispatch_GateOffTouchesNothing`).
- **Routed refusals are logged as they fire**, so `dispatch` discards the fan-out's refusal slice.
- **Prune before widen.** A consumed or console-routed id is dead work; dropping it first frees the slot for the widen to refill, and pruning afterwards would leave the wave a lane short. Pinned by `TestPlanFn_PriorDecisionIsPrunedThenWidened` and `TestPlanFn_ConsoleRoutedPriorIDsArePrunedBeforeWidening`.
- **Inside the widen, the prune runs before the fleet-width shortcut, and a pruned id disarms both shortcuts.** The original bytes still carry the consumed id, and returning them would re-pin it into the next wave's `lane-scope.json`. Pinned by `TestWidenNarrow_PrunedDisarmsBothShortcutsAndRemarshalsTopNOnly`.
- **A decision carrying `committed_floors` passes through the prunes and the widen unchanged.** The fan-out dispatches the floors and ignores `top_n`, and a `top_n`-only re-marshal would silently drop the floors. Pinned by the widen test above and `TestPruneConsumed_PreservesKeysAndReturnsOriginalWhenNothingDropped`.
- **Both prunes fail open.** Only positively consumed or routed ids are dropped; pending ids and ids with no lifecycle evidence stay, because over-pruning would starve the wave.
- **One routing authority.** `routedBase` backs both the dispatch gate (`RoutedResolver`) and `pruneRouted`, so the prune drops exactly what the gate would refuse. Each reads the inbox fresh, so mid-batch inbox changes are seen, and an inbox write that lands between the two reads is caught by the gate, which stays the backstop. Pinned by `TestRoutedResolver_RefusalPrintsTheVerbatimLineOnceAndPassesThrough` and the console-routed plan test above.
- **The freshness gate runs at the last moment before launch**, because the plan was made earlier and may be stale. A wave whose lanes are all stale and whose backlog is exhausted launches nothing and emits one `LOOP_WAVE_ALL_LANES_STALE`: a shorter wave, never a doomed lane. Pinned by `TestLauncher_AllStaleLaunchesNothingAndSignals` and `TestLauncher_PartiallyFreshLaunchesTheKeptSpecsWithTheSameCtx`.
- **The probe fails open.** Not every planned id is inbox-backed, and a missing file must never skip a lane. Pinned by `TestFreshnessProbe_ResolvesTheInboxLifecycle` and `go/acs/cycle1180`.
- **The refill reads `<ProjectRoot>/.evolve`, not `EvolveDir`.** Pinned by `TestRefill_PicksHighestWeightNotExcludedWithFleetScopeEnv` with `ProjectRoot` distinct from `EvolveDir`.
- **Three "consumed" beliefs coexist on purpose.** The plan-time prune (`isConsumed`) drops processed, consumed, rejected and retry, but keeps processing (in flight, and its own claim keeps a second lane off it) and quarantine. The widen's `triagecap.PruneConsumed` drops processed, consumed, rejected and quarantine and keeps retry. The dispatch probe treats every state but pending and unknown as stale, processing and quarantine included. Pinned by `TestConsumedHasThreeBeliefs`; unifying them is an operator decision (follow-up F7 in 13-loopwave.md §8).
- **`Size` works on a copy.** Benches expire and quota moves, so every wave re-reads them and the batch-level config never compounds a shrink. Pinned by `TestSize_ShadowLogsAndHolds` and `TestSize_EnforceResizesAndPaces`.
- **Without a budget block, sizing is byte-identical to the bench shrink alone**: no resize, no pace, no line (`TestSize_NilBudgetByteIdentical`).
- **The preflight checks the main checkout.** Waves ship from the main tree, so its uncommitted control-plane edits are what kill audit-passed lanes at ship. An unverifiable root refuses (`TestPreflight_RefusesANonGitRoot`).
- **The reload holds width on a bad policy and reports only dispatch-relevant changes.** Pinned by `TestReloadFleetConfig_HoldsWithTheVerbatimWarnAndReportsOnlyChanges` and `cmd/evolve` `TestFleetDispatch_MalformedPolicyAtWaveBoundaryHoldsWidth`.
- **Clean-code limits are a test.** Every function stays under 50 lines, nesting at most 4, every file under 800 lines. Comments inside a function count toward its length; its doc comment does not. Pinned by `TestLimits_FunctionsFilesAndNestingStayWithinTheBar`.
- **The import allowlist.** Never `internal/core`, never `internal/guards` directly, never a third-party module. Pinned by `TestImportGraph_LeafImportsOnlyTheDeclaredPackages`.
- **Readers outside the package.** `cmd/evolve` `TestInboxCenterlessRootsArePinned` allow-lists `launcher.go` and `plan.go` by path for their `inboxmover.Options` literals, so renaming either file breaks it. `cmd/evolve/cmd_loop_unit13_golden_test.go` replays this package's `testdata` goldens. The sizing fixtures in `plan_test.go` match `cmd/evolve/cmd_loop_wave_budget_test.go` so the shared golden replays.

## Findings

- **cycle 547** (`go/acs/cycle547`): a wave shrunk by quota or budget to one lane or fewer fell through to the leak-prone sequential path even with a disjoint candidate available. That produced the min-width repair.
- **cycle 554** established that an empty committed `top_n` is not a no-op: the widen fills it from the backlog.
- **cycle 739** (`go/acs/cycle739`, with the `-race` suites in cycles 744 and 746): an operator width directive committed mid-batch did not take effect until the next batch. That produced the wave-boundary reload and its hold-on-malformed rule.
- **cycle 767**: about 3 of 8 failed lane slots in one width-3 batch were doomed at dispatch. That produced the freshness gate; the full account is in [internal-fleet.md](internal-fleet.md) Findings.
- **cycle-1116**: a fleet-width decision carrying a consumed id was returned verbatim and re-pinned the id into a later `lane-scope.json` ([ADR-0079](../adr/0079-cycle-outcome-inbox-lifecycle-seam.md)). That is why a pruned id disarms both widen shortcuts (Q-W2).
- **cycle 1180** (`go/acs/cycle1180`): the probe must treat an id with no lifecycle evidence as fresh (Q-W6).
- **F29** (research [verification-wave-findings-2026-09-14.md](../../research/verification-wave-findings-2026-09-14.md)): the widen's protected-surface predicate judges the declared surface, the path-shaped `files[]` tokens, so a protected backlog item must declare a path to be excluded.
- **F34** (same report): the prior decision kept ids the classifier now routed to the console. They filled the fleet width, the widen short-circuited, and the gate refused them only after the lanes were cut, so the wave ran 1 of 2 lanes. `pruneRouted` drops them before the widen.
- **The extraction** ([13-loopwave.md](../decomposition/13-loopwave.md) §1) found two false doc comments in the original: one claimed plan time and dispatch time "can never disagree about what consumed means" while three beliefs coexisted, and one claimed ctx reached the decision read. Both are now characterized rather than claimed: `TestConsumedHasThreeBeliefs` and Q-W10.
