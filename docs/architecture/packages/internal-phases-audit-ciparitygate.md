# internal/phases/audit/ciparitygate

> Unit 14 of the component breakdown: [the unit's design record](../decomposition/14-ciparity.md) (extraction map, decision tables, mutants and review folds) under [ADR-0103](../adr/0103-component-breakdown-program.md). The gate itself is [ADR-0069](../adr/0069-cycle-ci-parity-audit-gate.md), and the codes it registers render into [signal-codes.md](../signal-codes.md). This page keeps the package-level detail.

## Purpose

`ciparitygate` holds the audit phase's five CI-parity gates: `go vet ./...`, the `-tags acs` durable suite, the `-tags integration -race` tier over the touched packages, `apicover -enforce` over the touched and enforced packages, and the new-package graduation check. Each runs the command CI runs against the cycle's own worktree, so a cycle cannot ship green locally and red in CI. It is a leaf under `internal/phases/audit`: the host projects the request and supplies the change set.

## Design

- **One `Gates`, four injected collaborators.** The subprocess runner (`sysexec.RunFunc`), the change-set Strategy (`ChangedSetFunc`, the host's locator, so git and the build handoff never enter the leaf), a clock for the retake lock wait (`WithClock`), and the Signal Center through an accessor read at every use (`WithSignals`). A nil runner or change-set function is a programming error that panics at first use; `New` does not guard it. A nil accessor, or one returning nil, is the Null Object: `Emit` on a nil Center is a no-op, and `SignalsWired` reports whether a root wired one.
- **The hook contract is the host's.** `([]offenders, nil)` is FAIL, `(nil, err)` is a fail-open WARN (the gate could not run), `(nil, nil)` is clean. The leaf never writes stderr; its ten failure modes are `audit.warning` WARN events under module audit, coded `AUDIT_CIPARITY_*`, and a clean five-gate run emits none.
- **`Request` is the one input shape**: the four `core.PhaseRequest` fields the gates read, projected once by the host (`audit.requestOf`). `ProjectRoot` is the cycle-shared runtime root that hosts `.evolve/locks/integration-tier.lock`; `Worktree` is the shipped tree holding the go module and the change set; `Workspace` is where `integration-tier.log` and the cycle's `signals.ndjson` land.
- **Two root rules.** `root()`, the tree the gates inspect, prefers `Worktree` and falls back to `ProjectRoot`. `lockRoot()` is deliberately reversed: it prefers `ProjectRoot`, so the retake lock lives on the cycle-shared path and lanes contend on one file; a per-lane path would defeat cross-lane serialization.
- **`Timeouts` is the one home of the five budgets.** `GoVet` and `ACSDurable` bound one command. `Apicover` bounds the forked pre-steps and the in-process measurement together. `TierAttempt` bounds each integration-tier attempt separately, so the retake gets a fresh budget. `TierLockWait` bounds the lock wait independently, never with attempt 1's leftovers, because under the contention the retake exists to absorb, attempt 1 may have used most of its deadline. They are compiled defaults (4m, 8m, 8m, 15m, 5m), not env toggles; `WithTimeouts` lets a test shrink one to reach a deadline arm.
- **Producers.** `warn` is the one event producer: cycle, audit phase, module audit and `fields.gate` on every event, with key/value pairs. `failed` is the one writer of `fields.cause` (one `GATE_FAILED` per offender return, carrying the offender count and the first offender, offenders returned unchanged), `stepFailed` of `fields.step`, and `lockDegraded` of `fields.reason`. `gateOrigin` pairs each exported method's `Origin` with its `fields.gate` token and travels into the shared steps, so a shared-step event names the gate being triaged.
- **Typed vocabularies.** `gateStep`, `gateCause` and `lockReason` are typed closed sets in `vocabulary.go`, and the registered code docs render them with `vocabulary()` as `{a, b, c}`: one home, two projections (the event field and `docs/architecture/signal-codes.md`). Commas, never pipes: the registry writes each doc into a markdown table cell unescaped, so a `|` splits the row.
- **What each vocabulary value means.** `fields.step` (the pre-verdict step that could not run; the gate then fails open): `exec` (the gate's one command could not start), `tier_attempt` (the integration tier's first attempt could not start), `tier_list` (`go list ./...` for the module-root fallback), `bin_dir` (ensuring `<module>/bin` for the scratch profile), `cover_run` (the scoped coverage run), `cover_func` (`go tool cover -func`), `write_func_cover` (writing the `-func` profile), `pkg_dirs` (`go list -e -f {{.Dir}}`), `measure` (the in-process apicover measurement was interrupted). `fields.cause` (why a gate returned offenders): `exit` (the command ran and exited non-zero), `retake_exec_failed`, `deadline_with_markers`, `retake_red`, `underivable` (an apicover gate could not prove its set empty), `apicover` (enforce offenders or a measurement error), `ungraduated` (a new package absent from `.apicover-enforce`). `fields.reason` (how the retake lock degraded): `no_root` (no `ProjectRoot` and no `Worktree` to host the lock file), `error` (`flock.TryLock` failed), `timeout` (held past `TierLockWait`).
- **`runGate` maps by exit code.** `sysexec.Capture` returns a non-zero process exit as `(code, nil)` and reserves the error for start failures, so only the exit code tells "the tool ran and found problems" (FAIL, `cause=exit`) from "the gate could not run" (WARN, `step=exec`). Stdout and stderr are both captured, since go vet writes its diagnostics to stderr; a non-zero exit with no output gets a synthesized offender line.
- **`scope` is the one owner of the touched-and-derivable decision** for the three whole-repo gates (go vet, acs-durable, integration tier); no gate derives the change set on its own. Three outcomes: a derivable set touching at least one package runs, scoped to it; an underivable set (git failed, for example on a concurrent-fleet `.git/index.lock` race) is a loud fail-open WARN with `CHANGESET_UNDERIVABLE`, because a hard FAIL on that transient race would discard a shippable cycle; a derivable empty set (a docs-only cycle) stays silent. The no-module guard runs first, so a worktree without `go.mod` gains no WARN whatever git says. Each gate resolves its own scope, so one underivable cycle records three WARNs and three events (preserved quirk Q1).
- **`moduleDir` requires a real module.** `codequality.ModuleDir` falls back to the root itself when there is no `go/` subdirectory, so an `IsDir` check alone would run a gate in a non-module directory, where go vet fails "go.mod not found": a false offender. A synthetic test worktree has no `go.mod`.
- **The integration tier's scope.** `tierScope` is the pure split of the already-derived change set: the touched packages, minus `/acs/` (the acs-durable gate owns it), minus the env-exclusive set (returned separately). A module-root change (a `./...` pattern from `go.mod`, `go.sum` or a root `main.go`) wins at once and falls back to the whole module: `wholeSuite` runs `go list ./...` and drops `/acs/` and the env-exclusive packages, as CI's `go list ./... | grep -v /acs/` does. Scoping is load-bearing for reliability, not only speed: it bounds the `-race` run's contention exposure, and whole-repo integration coverage stays CI's job, the same backstop apicover-enforce relies on. The module-root listing runs under the caller's env; every tier attempt runs under the scrubbed env.
- **`tierArgs` is the one `go test` vector.** It is faithful to CI's tier and flags: `-race` is included, because a genuine data race in a touched package must fail the gate; only `-cover`, a CI-only concern, is dropped.
- **Bounded parallelism.** `tierParallelism = 4` bounds both `-p` and `-parallel`. The gate shares a machine with concurrent fleet lanes, where an unbounded `go test -race ./...` spawns enough git subprocesses to race on pipe FDs (EBADF, `Path:"|0"`) and spikes memory (the race detector costs 5 to 10 times) until clean isolated tests fail at 0.00s on mkdir. Raising `RLIMIT_NOFILE` would not help: the Go runtime already lifts the soft limit to the hard maximum at startup, and the EBADF is a concurrent-spawn pipe race, not exhaustion. Bounding changes `-race` interleavings relative to CI's unbounded run, so it is a fail-open aid rather than strict outcome parity: CI, isolated and unbounded, still catches a race the local run misses.
- **CI-parity env scrub.** `scrubbedRun` wraps the runner so every call carries `ciparity.CIEnv(os.Environ())`, captured once at wrap time, instead of the env the caller passes; nil would inherit the lane's full environment, whose `EVOLVE_*` and session variables flip env-sensitive tests. The tier attempts and the apicover coverage run both use it.
- **Retake on red.** A red first attempt is retaken once, serialized under a cross-lane exclusive lock, because under a live fleet a single red is not yet evidence and serialization removes the contention that caused it. `acquireLock` goes through `internal/adapters/flock`, which owns the `runtime.KeepAlive` raw-fd defense and in-process held-tracking. The lock is best-effort: a lock error, a missing root or a wait past `TierLockWait` (polling every 2 s on the injected clock) degrades to an unserialized retake with `TIER_LOCK_UNAVAILABLE` and a note in the log header, never a blocked gate. Worst-case gate wall-clock doubles, on red paths only; a false FAIL that discards a shippable cycle costs more.
- **`decideTier` is the pure four-way table** over the two attempts. A retake that cannot start keeps attempt 1's offenders (`retake_exec_failed`, after a `TIER_RETAKE_EXEC_FAILED`): a real red is never laundered by retake trouble. Red then green is a contention flake, absorbed as a visible WARN (`TIER_FLAKE_ABSORBED`). A retake killed at its deadline first reports the offenders its truncated output already flushed (`deadline_with_markers`: go test prints each completed package's verdict before the kill, and evidence outranks the budget); only a marker-free truncation degrades to a WARN (`TIER_DEADLINE_NO_VERDICT`), because a bare exit code from a killed run is not a verdict. Red twice within budget is genuine (`retake_red`): the serialized clean-env retake is the truthful attempt. Attempt 1's deadline flag is recorded but never consulted.
- **`integration-tier.log`.** `tierLog` appends each attempt (`# attempt N<note>`, `# go <args>`, `# exit: <code>`, then the output) to `<Workspace>/integration-tier.log`, mode 0o644; `state.json` truncates, so the log is the one-grep diagnosis of both attempts. An empty `Workspace` is a declared no-op, not a fault; a failed open or append is `TIER_LOG_WRITE_FAILED`. A FAIL's offenders end with a `full output: <path>` pointer line, which inflates the offender count by one for discoverability.
- **Offender extraction.** `offenderMarkerLine` is the one definition of a real failure marker, anchored on the line: `--- FAIL`, a `FAIL` package summary, `panic:`, a `# ` build-failure header, `import cycle`, `UNCOVERED` (apicover), `measurement error` (apicover's synthesized infra line), or a compiler/vet `file.go:N:` diagnostic. `offenderLines` keeps the marker lines, falls back to the non-empty lines among the last six when none match, and caps the result at the last twelve so a runaway log cannot bloat the verdict. `hasOffenderMarker` must not inherit the fallback, because the deadline path degrades to WARN exactly when no marker exists, and the fallback would make every non-empty truncation look judged.
- **Env-exclusive packages.** `tierEnvExclusive` holds the single record per package: the module-relative package dir, the exclusion evidence, and the backstop naming where its integration tests actually run, rendered verbatim into the WARN. The skip predicate, the WARN text, the mixed-scope event and the whole-suite filter all project from it; no prose restatement is authoritative. The only entry is `internal/bridge`: its `requireTmux` tests boot real tmux sessions that time out under a live wave (13 offenders, all exit 80, on one wave; 7 of 7 pass in 17.2 s on a quiet host), and runners have no tmux, so its backstop is a quiet-host run. A package pattern resolves to its record whether spelled `./dir/...`, as a full import path, or as a bare relative dir. An all-exclusive scope skips the tier with `scope=all`; a mixed scope runs the remainder and records `scope=mixed`.
- **The two apicover gates share one prologue** (`inputs`): no module means done; the `.apicover-enforce` read comes before the derivability check, so a missing enforce list is a silent no-op even when git failed; an underivable set with an enforce list is a hard FAIL (`cause=underivable`, the caller's own sentence, and no `CHANGESET_UNDERIVABLE`: one fact, one event). That severity is deliberately the opposite of the whole-repo gates' WARN: neither apicover gate can prove its set empty, and the silent no-op it replaced shipped an uncovered export.
- **`ApicoverEnforce` measures in-process.** It scopes to the touched-and-enforced set (`ciparity.IntersectEnforced`), forks three toolchain pre-steps in `coverageProfile` (the scoped coverage run, with tag parity through `ciparity.CoverageTestArgs` because an untagged run under-reports a tag-gated package by up to 43 points; `go tool cover -func`; the `go list -e -f {{.Dir}}` package-dir listing), then calls `apicover.Run` in-process over those dirs, so no `bin/apicover` is built at runtime. Each pre-step failure is fail-open with `GATE_STEP_FAILED` naming the step. Scratch profiles live under the module's `bin/`, created if absent, and are removed best-effort afterwards so a persistent worktree does not accumulate them. FALSE-GREEN (coverage-dependent) checking is left to CI, matching the `acs/regression/apicover` completeness/correctness split.
- **`enforceVerdict` is the pure exit-code contract** of the in-process run: 0 is clean; 1 is offenders; a measurement error (exit 2) is also a FAIL, because in-process there is no exec-start failure mode and an unparseable enforced package is a real finding about the touched code. Only a context deadline or cancel is infrastructure weather, surfaced as an error so the gate fails open (`step=measure`).
- **`ApicoverGraduation`** flags changed `internal/<pkg>` packages that are new and absent from `.apicover-enforce`: the blind spot `IntersectEnforced` drops, since a package new this cycle cannot yet be enrolled. Each offender carries the exact edits (`ciparity.GraduationPrescription`): an `.apicover-enforce` entry and an `apicover_named_test.go`. `go/cmd/...` is out of apicover's scope and never flagged. A package with no production `.go` file is deferred with `GRADUATION_DEFERRED` rather than flagged, the same predicate as the build-entry seam, so the vacuous FAIL is not moved one phase later; the obligation re-raises on any later change to that package, because this seam has no new-this-cycle filter. When every package is deferred the offender list is empty but non-nil, and the host's `applyCIGate` keys off its length.

## Invariants

- Every tier attempt and the apicover coverage run carry the scrubbed allowlist env, captured once at wrap time and identical on both attempts; nil (inherit) is never passed. Pinned by `TestTierAttempts_ScrubbedEnvIsCapturedOnceAndIdenticalOnBothAttempts` and `TestCoverageProfile_RunsGoTestUnderTheScrubbedEnv`.
- The retake lock lives under `ProjectRoot`, never the per-lane worktree. Pinned by `TestRequest_HasExactlyTheDeclaredFields` and `TestAcquireLock_TableOverAnInjectedClock`.
- Attempt 1 is on disk in `integration-tier.log` before the lock is sought, so a kill during a contended wait never loses it. Pinned by `TestSignals_NullObjectLiveAccessorAndStreamGolden`.
- `tierLog.path` is set on the first successful write and never cleared, so a later append failure keeps the pointer to the attempt already on disk. Pinned by `TestTierLog_FailuresAreCodedAndTheEarlierPointerStands`.
- The order of `tierArgs` is an on-disk contract through the log header. Pinned by `TestTierLog_BytesMatchTheGoldenForBothOutcomes` and `TestWholeRepoGates_ArgVectorsMatchTheGolden`.
- A clean five-gate run emits nothing and writes nothing to stderr; every FAIL emits exactly one `GATE_FAILED`. Pinned by `TestGates_CleanRunEmitsNothing_AndEveryFailEmitsOneGateFailed`.
- `warn` panics on an odd key/value count before emitting, never silently dropping a field. Pinned by `TestWarn_OddTrailingKeyPanicsBeforeEmitting`.
- Every typed vocabulary const is in its rendered set, no production line converts a literal into a vocabulary type, each field has one production writer, and no unit doc carries a raw pipe. Pinned by `TestVocabulary_TypedConstsAreTheRenderedClosedSets`.
- A package may be env-exclusive only when the serialized retake cannot make red-twice trustworthy and CI provides no backstop; every backstop carries `envExclusiveNoCIMarker` ("NOT covered by CI"), the one home of that phrase. Pinned by `TestEnvExclusive_EntriesDeclareNoCIBackstop`; `TestIntegrationTierScope_CoversCoreCmdShip_Cycle1594` keeps `internal/core`, `cmd/evolve` and `internal/phases/ship` in the lane tier.
- `hasOffenderMarker` has no fallback. Pinned by `TestOffenderLines_MarkersFallbackAndCap`.
- The apicover prologue reads the enforce list before the derivability check, and its underivable arm is one `GATE_FAILED{cause=underivable}` with no `CHANGESET_UNDERIVABLE`. Pinned by `TestApicoverEnforce_InputsOrderAndSeverity`.
- The package stays a leaf, importing stdlib plus eight declared internal packages (`TestImportGraph_LeafImportsOnlyTheDeclaredPackages`), within the clean-code limits (`TestLimits_FunctionsFilesAndNestingStayWithinTheBar`). `apicover_named_test.go` names every export, because the apicover completeness predicate and `apicover -enforce` count package-local tests only.

## Findings

- Inheriting the lane's environment false-REDded env-sensitive integration tests deterministically, and the apicover coverage step failed on every audit of a wave for the same leak (`EVOLVE_CYCLE_STATE_FILE`, `EVOLVE_FLEET`), until both ran under the scrubbed allowlist.
- Under a live fleet the `-race` tier starves for CPU and IO: one package took 469 s and failed, then passed in isolation. A single red under contention is not evidence; the serialized retake is the cure.
- Substring offender heuristics ("error" or "FAIL" anywhere in a line) kept passing tests' verbose chatter while the last-twelve cap pushed the real `--- FAIL` lines out, so verdicts cited twelve lines of noise with the true offender unknowable. Line-anchored markers fixed it (`TestOffenderLines_DropsPassingTestChatter`).
- `internal/core`, `cmd/evolve` and `internal/phases/ship` were once env-exclusive for contention false-REDs. The serialized retake that cures contention landed a day later, and the never-revisited skip let a real red sit on main for 2.5 days. The exclusion evidence over-attributed `cmd/evolve` (its fleet-soak suite is in-process fakes with no real tmux; its ~69 s is CPU), and a compile-only floor would not have caught that red, an assertion failure: running the tier is the point.
- The integration tier closes the parity hole one tier above go vet: `TestFleetSoak` once went red in CI under a green per-cycle audit because the audit never built the integration tier.
- `context.WithTimeout(ctx, 1ns)` may arm a timer instead of expiring synchronously (two clock reads inside one tick), so an instant fake runner can return before `ctx.Err()` is set and a deadline test sees `retake_red` (2 of 40 runs). The `killedAtDeadline` test fake returns only after `ctx.Done()`, as a real SIGKILL follows the deadline.
