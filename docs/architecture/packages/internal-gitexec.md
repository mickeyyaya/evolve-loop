# internal/gitexec

## Purpose

`internal/gitexec` puts the git CLI behind one small, injectable type, `Git`, so every git invocation in the fast test tier can be faked and the git dependency lives in one leaf package ([ADR-0050](../adr/0050-modularization-and-unified-phase-io.md) P2/P3). It depends only on `internal/sysexec`, the command seam. It also owns the two git answers several packages must agree on: where the local main sits against its remote, and how `git worktree add` is retried.

## Design

- **`Git` is a value: a working directory and a `sysexec.RunFunc`.** `Exec` is required; production code builds it with `Default(dir)` (`sysexec.DefaultRunner`), and tests inject a fake runner. An empty `Dir` inherits the caller's working directory.
- **Three call shapes, by what a non-zero exit means.** `Capture` returns stdout, stderr and the exit code, and reports a non-zero exit through the code, never through `err`: callers branch on it (`git diff --quiet` exits 1 to mean "there are differences"). `err` is non-nil only for a failure to run git at all. `Output` folds any non-zero exit into its error and returns trimmed stdout, for queries where a non-zero exit is a failure (`rev-parse`, `describe`, `symbolic-ref`). `Run` is `Output` for side effects, discarding stdout. Pinned by `TestGit_Capture_NonzeroExit_ReturnsCodeNotError`, `TestGit_Output_TrimsStdoutAndNonzeroIsError` and `TestGit_Run_SuccessNilFailureErr`.
- **`DirtyPaths` is file-exact.** It runs `git status --porcelain -uall`: `-uall` lists every untracked file on its own line, never a bare directory. The result is the sorted set of tracked-modified and untracked paths plus the source side of every rename or copy, because a rename dirties both paths. A clean tree yields an empty set, never a spurious `""` path. Pinned by `TestGit_DirtyPaths_SortedWithRenameOld`, `TestGit_DirtyPaths_CleanTreeReturnsEmpty` and `TestGit_DirtyPaths_NonzeroIsError`.
- **Porcelain parsing.** A porcelain line is `XY <path>`, and a rename or copy is `XY <old> -> <new>`. `PorcelainPath` takes the new path, `PorcelainOldPath` the source (or `""` for a non-rename line). git quotes a path that holds a space, and both sides are unquoted. A line too short to hold a path yields `""`, never a panic. Pinned by `TestPorcelainPath_RenameAndPlain`, whose quoted-rename case is real `git status --porcelain -uall` output.
- **`TreeOfIndexCopy` is the one scratch-index tree writer.** It resolves the worktree's index (`rev-parse --git-path index`), copies it into a private temp directory (mode 0600) from one open file handle, keeping the original's mtime, runs the given `git add` commands, if any, with `GIT_INDEX_FILE` pointing at the copy, and returns `write-tree`. The real index is never written, not even for git's cache-tree update, and its `index.lock` is never taken, so it runs safely beside another process's `git add`. The mtime matters: git judges an entry "racily clean" against the index file's mtime, and a fresh mtime on old content would let `add` skip a file modified in the same second the index was written. With no add command it is the staged tree; with `add -A -- .` it is the full working tree (untracked files in, ignored files out). `internal/wtcheckpoint` is its caller; `internal/treefence` keeps an older private copy of the same steps (`writeTreeMode`), which should move onto this one in its own refactor (inbox `treefence-writes-its-snapshot-through-gitexec-tree-of-index-copy`). Pinned by `TestTreeOfIndexCopy_WritesTheStagedAndTheFullTreeWithoutTouchingTheIndex` (through both `Default` and `Isolated`) and `TestTreeOfIndexCopy_FailsLoudlyOnAFailingAdd`.
- **`Isolated(dir)` is `Default(dir)` without the inherited git location variables.** `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and `GIT_COMMON_DIR`, which a git hook, for one, sets, would point git at another repository or index than `dir`; `Isolated` drops them from the inherited environment, the rule `internal/treefence` applies to its own git calls. `TreeOfIndexCopy` applies the same rule to every call it makes, whatever runner it was given. Only the inherited environment is filtered: an environment a decorator passes down explicitly, such as the copy's `GIT_INDEX_FILE`, goes through unchanged. Pinned by `TestTreeOfIndexCopy_IgnoresAmbientGitDirAndIndexFile`.
- **Per-root branch namespacing is not this package's.** The lane token for a project root is `runscope.LaneFromRoot` ([ADR-0054](../adr/0054-concurrent-evolve-loop-sibling-worktrees.md)).
- **`MainRelation` is the one resolution of "where is the local main relative to its remote".** The wave boundary (fast-forward or halt) and the lane base (which ref a fresh lane starts from) both read it and print its `String`, so the two can never disagree on the state or on the words. `RelationToRemote` compares `HEAD` with an already-fetched ref and classifies it as `current` (same sha), `behind` (ahead count 0, fast-forwardable), `ahead` (behind count 0, unpublished local commits) or `diverged`. Pinned by `TestRelationToRemote_FourKinds` over a real bare origin, seed clone and checkout (`relationFixture`).
- **`RelationToRemote` never guesses a state.** Every git failure, an unknown ref, or a `rev-list --left-right --count` output that is not two integers is an error; each caller decides its own fail-open disposition. A count that silently parsed as zero could reclassify `ahead` as `behind`. Pinned by `TestRelationToRemote_UnknownRefIsAnError` and `TestRelationToRemote_UnparseableCountsAreAnError`. The zero value's `String` is `local main relation unknown` (`TestMainRelation_ZeroValueString`).
- **`AddWorktreeWithRetry` is the one `git worktree add` retry loop.** N lanes of one repository provision concurrently, and `git worktree add` takes repository-level locks in the shared `.git`; a collision exits 255 with nothing on stderr but `Preparing worktree`. One unretried collision leaves the lane without an active worktree, and the downstream fail-fast then costs it the whole cycle. Core, swarm and the operator CLI all call this loop instead of keeping copies, because `gitexec` is the one package all three already depend on (swarm must not import core).
- **The retry knobs are a value, `WorktreeAddRetry`, not package globals.** That keeps the loop single-sourced while each caller keeps its own test seams. The zero value is usable: real `time.Sleep`, no announcement, retry on every failure (`TestAddWorktreeWithRetry_ZeroValueConfigUsesDefaults`, `TestAddWorktreeWithRetry_NilRetryablePreservesRetryEverything`).
  - `Sleep` is the backoff clock seam, so tests count sleeps instead of paying them.
  - `OnRetry` is called before each re-attempt, never before the first, with the 1-based attempt index, the bound, and the failing attempt's exit code and stderr, so a caller can announce contention in its own voice.
  - `Retryable` classifies a failed attempt before any backoff is paid; `false` returns the failure at once.
- **`DefaultWorktreeAddAttempts` is 3: the first try and two retries**, with a 2 s then 4 s backoff. Two retries absorb lock-window collisions at the standing fleet width; a third identical failure is a real condition the fail-fast must surface.
- **`RetryableWorktreeAddFailure` is the shared transience classifier, a deny-list.** Only conditions proven permanent are subtracted: `not a git repository`, `is already checked out`, `already exists` (matched case-insensitively in stderr). Contention is the open-ended class, so anything unrecognised stays retryable: a transient misclassified as permanent costs a lane its cycle, while a permanent misclassified as transient costs 6 s. Pinned by `TestRetryableWorktreeAddFailure_ClassifiesPermanentAndUnknown`.

## Invariants

- **A clean add costs exactly one invocation and no backoff.** The retry is a collision absorber, not a rate limiter on every cycle. Pinned by `TestAddWorktreeWithRetry_CleanRunCostsOneAttemptAndNoSleep`.
- **A persistent failure still fails loudly after the bound**, returning the final exit code and git's own stderr intact, because the downstream fail-fast alarm is correct and must stay armed. Speed comes from not waiting, never from not reporting. Pinned by `TestAddWorktreeWithRetry_BoundedThenSurfacesFinalFailure` and `TestAddWorktreeWithRetry_RetriesTransientFailure`.
- **A permanent failure costs one attempt, no sleep and no announcement.** The classifier runs before the sleep: backoff bought on a permanent condition is pure latency, and an announcement would claim contention that was never established. Pinned by `TestAddWorktreeWithRetry_PermanentFailureSkipsBackoff`; `TestAddWorktreeWithRetry_TransientStillRetriesToBound` is the negative guard that a transient failure still rides the whole bound.
- **The announcement comes before the backoff.** A lane stalled inside the 2 s/4 s window has already said so. Pinned by `TestAddWorktreeWithRetry_AnnouncesBeforeBackoff`.
- **The initiating failure survives in the diagnostic.** When a retried add ends in a different terminal failure (a transient 255 with empty stderr followed by a 128 `already exists` over the half-built directory it left), the returned stderr is `initial worktree add failure (rc=N): …` followed by `final worktree add failure: …`, and the exit code is the terminal one. A success carries no retry history. Pinned by `TestAddWorktreeWithRetry_PreservesFirstFailure` and `TestAddWorktreeWithRetry_SuccessCarriesNoRetryHistory`.
- **The `worktree add` prefix is prepended inside the helper**, so no call site can drift into another subcommand while claiming this retry contract. Pinned by `TestAddWorktreeWithRetry_IssuesWorktreeAddArgv`.

## Findings

- A retry loop that slept the whole 2 s + 4 s ladder on every non-zero exit charged 6 s for a permanent `fatal: not a git repository` (exit 128). In `go/cmd/evolve`, 33 tests reach the loop over a `t.TempDir()` that is not a repository: 198 s of sleep in a package the build floor runs with `-timeout 120s`, deterministically. `Retryable` is the fix; it narrows only when the loop sleeps.
- **A filter that also strips what a decorator added defeats the decorator** (2026-10-06). The first `Isolated` filtered every environment it was handed. `TreeOfIndexCopy` wraps its caller's runner, and with an `Isolated` caller the inner filter removed the `GIT_INDEX_FILE` the outer layer had just set, so `git add` and `write-tree` ran on the real index. `internal/wtcheckpoint`'s real-index test caught it; the gitexec test had used only `Default`. Now only the inherited environment is filtered, and the test runs through both.
