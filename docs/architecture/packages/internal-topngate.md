## Purpose

`internal/topngate` checks that the TDD and build deliverables work on the task set triage committed. It mounts two gates behind one `core.DeliverableReviewer` (`NewReviewer`): `topn-tdd-scope` after tdd and `topn-task-binding` after build. The only cases it blocks are TDD authoring under an empty commitment and a multi-member lane whose declared members differ from its contract.

## Design

- **Composite reviewer, same shape as evalgate.** Each gate names the phase it inspects (`appliesTo`) and returns `(reason, block)`. `Review` logs every non-empty reason through one `logf` seam (stderr, prefixed `[topngate]`), so advisories are observable and testable. At `StageEnforce` the first `block=true` rejects; at `StageShadow` everything is logged and approved. `StageOff` is never constructed: `cmd/evolve/cmd_cycle.go` skips the reviewer. Stage gating is the whole rollout control.
- **Two task-identity sources.** Scout's `## Selected Tasks` and triage's `## top_n` can diverge. The package makes the triage commitment the authority at the TDD→Build and Build→Audit transitions.
- **Build gate (`topNBindingGate`).** It compares build-report.md's `## Task:` slug with triage-report.md's `## top_n`. A mismatch returns a `label drift` reason with `block=false`. It never blocks.
- **TDD gate (`tddScopeGate`), in order:**
  1. No triage-report.md, or no test-report.md: fail open.
  2. The contract's committed set (`core.ContractTaskIDs`: the lane pin, else `triage-decision.json`'s top_n, minus deferrals) has more than one member: the declared slugs must equal it as a set, else a fatal `scope-mismatch` naming the missing and unexpected members.
  3. Nothing authored: pass (the compliant no-op).
  4. Empty markdown `## top_n` with authored files: fatal.
  5. No parseable `## Task:` claim: fail open.
  6. Claim in the markdown top_n: the file-scope advisory.
  7. Otherwise: a `label drift` advisory.
- **Declaration parsing.** The declared members come from the `slugs` of the first JSON fence under `## Handoff to Builder` that declares `slugs` or `testFiles` (info string `json` or empty); without one, from the comma-separated `## Task:` header. The authored files are that fence's `testFiles`. Fences are tracked by delimiter character and length, so a `~~~markdown` or four-backtick example that shows a handoff is never read as one.
- **File-scope advisory.** It reads the `- **targetFiles:**` line inside scout-report.md's `### Task N: <slug>` block for the committed slug and takes the backticked paths, ignoring the prose scout writes beside them. Any authored file in the same directory as a declared target is in scope. Zero overlap returns a `file scope drift (advisory)` reason.
- **Report names.** All four filenames come from `phasecontract.ArtifactName`.
- **Deterministic messages.** `normalizedSlugs` trims, sorts and deduplicates both sets before `reconcileMemberSets`, so the same inputs always produce the same reason.

## Invariants

- **Only a certain violation blocks.** Every ambiguity (missing report, empty or unparseable claim, missing scout scope) returns `block=false`, so enforce does not false-block a healthy cycle.
- **`block`, not `reason`, is the violation signal.** Advisories carry a reason at `block=false` so they reach the log. Pinned by the `enforce stage approves the file-scope advisory end to end` subtest of `TestTDDScopeGate_FileScopeBinding`.
- **Label drift never blocks, on either gate.** It compares two LLM-written strings, and the lane exists because triage committed these ids, so the committed set binds rather than the label. Pinned by `TestTopNBindingGate`, `TestTDDScopeGate_LabelDriftIsAdvisory`, `TestNewReviewer_EnforceApprovesLabelDrift` and `TestReplayCycle640Shape`.
- **Authoring under an empty top_n stays fatal.** No committed item exists that the files could be a differently labelled answer to, so it is not a labelling dispute. A blanket `block=false` rewrite would pass the advisory tests and fail these: `TestTDDScopeGate_EmptyTopNStillBlocks`, `TestNewReviewer_TDDEnforceBlocksEmptyTopN`, and the `empty top_n still blocks regardless of declared scope` subtest.
- **The TDD gate is tested through the reviewer.** `TestNewReviewer_TDDEnforceBlocksEmptyTopN` and `TestNewReviewer_TDDShadowApprovesEmptyTopN` drive `NewReviewer(...).Review` at `PhaseTDD`, so an `appliesTo` typo or a gate missing from the `gates` slice fails the package. `go/acs/cycle1113` mutates `reviewer.go` through `go test -overlay` by exact text: the lines `gates: []gate{topNBindingGate{}, tddScopeGate{}},` and `if block && r.stage == config.StageEnforce {` are part of that contract, and the predicates fail loudly when either changes shape.
- **Multi-member lanes bind to the contract, not the markdown top_n.** Triage's markdown may list decomposition sub-ids for a lane pinned to one id; binding to them would block a TDD that declared exactly its contract. Deferred members are not committed. Pinned by `TestTDDScopeGate_DecompositionSubIDsDoNotBlockThePinnedMember` and `TestTDDScopeGate_DeferredMemberIsNotCommitted`.
- **Set equality, not list equality.** The members are unordered work items. Pinned by `TestTDDScopeGate_TwoSlugDeclarationOrderIsIrrelevant` and `TestTDDScopeGate_ScopeMismatchIsDeterministic`. A complete declaration proceeds (`TestTDDScopeGate_TwoSlugCompleteDeclarationProceeds`), single-member lanes are unaffected (`TestTDDScopeGate_SingleSlugLaneUnaffected`), and the rule holds past two members (`TestTDDScopeGate_ThreeSlugPartialDeclarationBlocks`).
- **A missing test report fails open for multi-member lanes too.** Pinned by `TestTDDScopeGate_MissingReportFailsOpenForMultiMemberLane`.
- **The first declaring fence wins.** A JSON fence with neither `slugs` nor `testFiles` (RED output, a status object) must not shadow the real declaration after it. Pinned by `TestTDDScopeGate_CompleteDeclarationAfterUnrelatedJSONFenceProceeds`; `TestTDDScopeGate_IncompleteDeclarationAfterUnrelatedFenceStillBlocks` shows the gate still discriminates. An explicit `"slugs": []` with `testFiles` is a declaration of nothing and does not fall back to the header (`TestTDDScopeGate_HandoffDeclaration`).
- **Illustration is not declaration.** A handoff shown inside an outer example fence is never read. Pinned by `TestHandoffTestFiles_IgnoresExamples` and `TestTDDScopeGate_OuterFenceFakeCompleteHandoffStillBlocks`.
- **The reconciliation fires at TDD→Build only.** Firing again at the build boundary would move the abort past the spend it exists to save. Pinned by `TestTDDScopeGate_AppliesBeforeBuildNotAfter`.
- **File scope is advisory.** A legitimate deliverable can touch a shared helper or an incidental file scout never named; shadow evidence decides whether it ever becomes fatal. Pinned by `TestTDDScopeGate_FileScopeDriftIsAdvisory`.
- **One directory is one scope.** Scout names the production file while TDD authors its `_test.go` sibling; exact path equality would fire on every healthy cycle. Pinned by the `authored test file beside a declared target passes silently` subtest.
- **Scope is read per slug.** A sibling task's `targetFiles` never satisfies the committed slug. Pinned by the `scope is read per-slug, never borrowed from a sibling task` subtest.
- **The personas must produce what the parsers read.** `agents/evolve-builder.md` must name triage's `## top_n` as its sole task source and demote scout-report.md to background (`TestBuilderPromptNamesTopNAsSoleTaskAuthority`). `agents/evolve-tdd-engineer.md` must instruct the `slugs` handoff field, the `## Task: <id>[, <id>` header and the Task Contract binding (`TestTDDPromptDeclaresHandoffSlugs`); otherwise only test-authored reports would pass the multi-member gate.
- **An empty workspace reads nothing.** `readWorkspaceFile` refuses it, because `filepath.Join("", name)` would resolve against the working directory.
- **Known gap.** A complete multi-member reconciliation returns before the file-scope advisory, so multi-member lanes get no file-scope check (inbox `multi-member-file-scope-advisory`).

## Findings

- **Wrong-task builds** (cycles 282, 310, 522, 575, 577, 599, 640, 645; inbox `builder-task-binding-topn-gate`): Builder bound to scout's selection instead of triage's commitment, audit graded the wrong diff, and the committed task's ACS suite failed, burning an audit and ship pair on a doomed cycle. In cycle 640 triage committed `statefile-rmw-flock-single-source` and Builder implemented the other fleet lane's `fix-token-resolver-transcript-source`: audit PASS 0.93, ACS FAIL with red_count=9. The root cause was the persona, which told Builder to read its task from scout-report.md and copy `## Task:` from `## Selected Tasks`. That produced the build gate (then fatal) and the persona fix. `TestReplayCycle640Shape` replays the shape.
- **Cycle 660** (inbox `tdd-topn-binding-gate`, third recurrence): triage committed an empty `## top_n`, TDD read scout-report.md and authored RED scaffolds for a declined slug, and build, correctly honouring the empty commitment, choked on the orphans. That produced `tddScopeGate`.
- **Cycles 916 and 1012**: both recorded fatal rejections of the build gate discarded correct work whose report named the committed task differently. On 2026-07-22 label drift became advisory (PR #348); cycle 1073 applied the same change to the TDD gate on 2026-07-23 and kept the empty-top_n case fatal.
- **Cycle 1111** (`tdd-file-scope-binding-check`): a deliverable could carry the right label and touch nothing the committed item names. The file-scope advisory is the construction-level complement to the label check.
- **Cycle 1113**: every reviewer-level test drove build or audit, so an unwired TDD gate left the package green. The two `TestNewReviewer_TDD*` tests and the `go/acs/cycle1113` mutation predicates closed that.
- **Cycle 1480** (batch-20260815c wave 2, recurred in 1483): a lane bundled `minted-phase-verdict-contract-unsatisfiable` and `dead-api-sweep`. TDD minted predicates for both while the Builder contract bound only the first; nothing reconciled the two, so the lane ran the whole spine and failed at audit with the second slug undelivered. That produced the multi-member set equality (inbox `multi-slug-lane-scope-reconciliation`, cycle 1620).
- **Cycle 1620 audit and salvage review**: M1, any JSON fence under the handoff heading counted as the declaration, so an unrelated fence shadowed a complete one and falsely blocked; L1, the report's `ok` was ignored on the multi-member path, so a missing report blocked as "missing both members"; CRITICAL 1, the gate bound to the markdown top_n and blocked decomposed lanes; CRITICAL 2, the TDD persona did not instruct the declaration shape. See [the token-waste report](../../reports/2026-09-09-token-waste-root-cause.md).
- **Recovery review 2026-09-09**: the outer-fence false-accept control; a handoff documented inside a `~~~markdown` example must not count.
