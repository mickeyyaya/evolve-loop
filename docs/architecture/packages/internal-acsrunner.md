# internal/acsrunner

## Purpose

`internal/acsrunner` runs `go test -json` over one predicate package and aggregates the per-test results into an `acs-verdict.json`. It is the engine of `evolve acs run --cycle N <pkg>` (`cmd/evolve/cmd_acs.go`), the single-package companion of the gate's own runner, `internal/acssuite` (`evolve acs suite`). The audit phase never uses it: the audit regenerates the verdict through `acssuite`. Its verdict can still reach a gate, because a manual `evolve ship` with a workspace consumes inbox items on the verdict string `PASS` alone (`internal/phases/ship`, `consumeCommittedItems`).

## Design

- **`Run`** starts `go test -json -count=1 <pkg>` through the `execCommand` seam, parses the stream with `ParseTestJSON`, then waits. A nonzero exit with no predicate red is returned as an error beside the parsed verdict: `go test` exits nonzero on a failing test, which is a result, not a runner failure, so only an exit that no predicate red explains is an error. The `egps/no-predicates` harness red explains nothing (`hasPredicateRed` skips `acsverdict.SyntheticRedPrefix`), so a compile failure is still an error and the CLI exits 1 (`TestRun_AnExitNoPredicateExplainsIsARunnerErrorBesideTheHarnessRed`, `TestRun_CompileFailureBubblesUp`).
- **The child environment is scrubbed.** `execCommand` projects the environment through `ipcenv.Scrub`, the projection every `go test` a cycle spawns to judge the repository shares, so a fleet lane's `EVOLVE_FLEET`, cycle-state file and the rest of the `EVOLVE_` namespace never reach a predicate (`TestExecCommand_ScrubsTheLaneIPCEnvironment`). It does not forward `acs.predicate_env`'s operator keys the way `acssuite` does: its `go test` carries no `-tags acs`, so no curated predicate that reads one runs here.
- **Parse, then record.** `scanPredicates` folds the stream into one `Predicate` per test; `Verdict.record` is the one place a counter moves. A run that reported no predicate at all (a package with no test, one that does not exist or did not compile) records the `egps/no-predicates` red (`acsverdict.NoPredicatesID`), the same red the suite writes, so `red_ids` names the condition from either writer ([ADR-0114](../adr/0114-the-acs-verdict-is-always-written-and-complete.md) decision 7).
- **The headline is derived once, from the counters.** `ShipEligible` is `red_count == 0 AND incomplete_count == 0`, and `verdict` is `PASS` exactly when it holds. A SKIP is a declared non-result and stays neutral; an incomplete predicate (a stream that ended before it reported) is an undeclared one and is never read as consent; a run with no predicate is FAIL through its harness red, not through a special case.
- **The schema is kept in step with `acssuite.Verdict`** for the fields the gates read (`schema_version`, `verdict`, `ship_eligible`, `green_count`, `red_ids`, `predicate_suite.total`), pinned by `schema_lockstep_test.go`.
- **`WriteVerdict`** writes the path `acsverdict.Path` derives, `<evolveDir>/runs/cycle-<N>/acs-verdict.json`, through a random-suffix temp file and a rename. `Path` refuses a relative evolve dir, so this writer can no longer litter the process cwd (`TestWriteVerdict_RefusesARelativeEvolveDir`); the CLI also hands it an absolute, existing evolve dir.

## Invariants

- A run that executed no predicate is the `egps/no-predicates` red, never a pass and never a FAIL with `red_count` 0 (`TestParseTestJSON_AStreamWithNoPredicateIsTheNoPredicatesHarnessRed`, `TestRun_EmptyPackageNoTests`), spelled exactly as `acssuite` spells it (`TestNoPredicates_BothVerdictWritersNameTheSameHarnessRed`); through the CLI, a run whose `go test` could not execute also exits 1 (`TestRunACSRun_ARunThatCouldNotExecuteExits1WithAFailVerdict`).
- A killed or truncated run is never a pass: an incomplete predicate keeps the verdict FAIL with `red_count` 0 (`incomplete_count`, `incomplete_ids`; `TestVerdict_TruncatedStreamIsNotShipEligible`).

## Findings

- **2026-10-01**: `evolve acs run` on a package that did not compile wrote `verdict: PASS, ship_eligible: true, total: 0` and exited 0, since the headline was derived from the red and incomplete counts alone and the CLI's exit code only from the red count. A manual ship with that workspace would have consumed inbox items on work that never ran. Found while making `acssuite` write a complete verdict in every mode ([ADR-0114](../adr/0114-the-acs-verdict-is-always-written-and-complete.md)).
- **2026-10-01, architecture review**: the first fix expressed "no predicates" here as `total > 0` in the headline (FAIL with `red_count` 0, the shape ADR-0114 rejects for the suite), spelled the file name as a literal and had no relative-dir refusal, while `acssuite` had moved to a named red, `VerdictFilename` and the refusal. The two writers now share `NoPredicatesID` and `Path`, first through `acssuite`, then (re-review) through the leaf `internal/acsverdict`, so this package depends on `acsverdict` and `ipcenv` only instead of seventeen internal packages.
