# internal/setup

## Purpose

`internal/setup` is the deterministic core behind `evolve setup` and the in-session `/evo:setup` skill: `Detect` aggregates each CLI family's binary, auth and capability status with every phase's current routing and profile constraints, `Recommend` computes the configured presets from that digest, `Apply` merges the chosen preset into `.evolve/policy.json` as per-phase pins, `ComputeLatest` backs the read-only `evolve setup latest` staleness probe, and `Complete` stamps the first-run marker into `state.json`. The user-facing contract lives in [setup-onboarding.md](../setup-onboarding.md) and [setup-auto-config-presets.md](../setup-auto-config-presets.md); these notes cover the package's internals.

## Design

- **`Roles`** lists the phase agents setup configures, in pipeline order; each is resolvable by `resolvellm.Resolve` and has a `<role>.json` profile. `Version` is the onboarding schema version `Complete` stamps.
- **CLI-name normalization.** `baseCLI` strips driver suffixes (`claude-tmux`/`claude-p` → `claude`, `codex-tmux` → `codex`, `agy-tmux` → `agy`); `Detect` groups `bridge.Doctor`'s per-driver rows by that base family, one `CLIStatus` per family. `capManifest` maps a base family to its capability-manifest stem; only `agy` differs (`antigravity.capabilities.json`).
- **One tier vocabulary.** `abstractTiers` (`fast`, `balanced`, `deep`, `top`) is the canonical vocabulary used end to end: profile `model_tier_default` and `model_tier_envelope`, each manifest's `model_tier_map` keys, and resolvellm's sentinel defaults.
- **`tierModelsFor`** resolves each abstract tier to the family's native model id from the bridge manifest's `model_tier_map` (`familyDriverManifest`: the interactive `-tmux` drivers carry the map; headless variants declare none and resolve through the same family table), honoring operator manifest overrides via `bridge.LoadManifest`. A tier the manifest does not declare passes through as its own name (identity fallback). That fallback is only safe for a base with no manifest at all: echoing a tier word as a model id is a `--model <tier>` launch the CLI rejects (`bridge.isUnresolvedModelToken` is the sink guard), so a family whose manifest declares a tier must resolve it to a real model id.
- **`CLIStatus`.** `AuthMode` is one of `SUBSCRIPTION_OAUTH`, `API_KEY`, `CUSTOM_PROXY`, `SUBSCRIPTION`, `MISCONFIGURED`; `CapabilityTier` one of `full`, `delegated`, `n/a` (`unknown` when no adapters dir or the manifest read fails with anything but not-found); `Verdict` one of `ready`, `warning`, `blocked`. `TierModels` surfaces the family's native model per tier so per-phase routing is self-documenting.
- **`authMode`.** For claude the precedence is proxy (`ANTHROPIC_BASE_URL`) > API key (`ANTHROPIC_API_KEY`) > OAuth credentials > misconfigured; other families are `SUBSCRIPTION` when configured, else `MISCONFIGURED`.
- **`PhaseStatus`.** `Source` is `profile` for the profile default or `policy-pin` when a `.evolve/policy.json` pin overrides it; resolvellm emits a tier, never an exact model. `DefaultCLI`/`DefaultTier` carry the profile defaults (profile `cli` and `model_tier_default`) independently of any pin overlay, so `Recommend` can compute "differs from default" without re-loading the profile: unpinned phases have them equal to `Current*`, pinned phases keep the profile default while `Current*` shows the pin.
- **Pin overlay.** `Detect` overlays each policy pin (dispatch honors a pin absolutely) and validates it against the same floor dispatch enforces (`allowed_clis`, the tier envelope), reporting a breach in `PinViolation` while still showing the pin, so onboarding can fix it before it hard-fails a real cycle. A pin for a phase with no profile cannot be floor-checked, so it is reported as a violation rather than a false green.
- **`PolicyError`.** A present but malformed `policy.json` disables the pin overlay (phases stay profile-sourced; the floor still applies at dispatch) and is surfaced so onboarding fixes the JSON instead of silently ignoring the user's pins.
- **`DetectOptions` seams.** `Env`, `Doctor`, `CapTier` and `Now` keep detection deterministic and offline in tests. A nil `Env`/`Now` uses `os.Getenv`/`time.Now`; a nil `Doctor` runs `bridge.NewEngine(Deps{}).Doctor`; a nil `CapTier` runs `capability.Inspect` under `AdaptersDir`.
- **`Recommend` is pure** over `(DetectReport, PresetConfig)`: no clock, env, randomness, disk or map-iteration order reaches the output. The preset definitions are injected through `PresetConfig`; the only preset behavior in code is the generic tier-bias interpreter.
- **`canonTier`** maps any tier spelling (canonical, legacy alias or native model id) to canonical `fast|balanced|deep|top`, or `""` when unclassifiable; it round-trips `top` (rank 4 in `policy.TierRank`).
- **`effectiveDefaultTier`** is a phase's baseline: the profile `model_tier_default`, else the envelope default, else `balanced`. It is the baseline for both `biasTier` and the differs-from-default check, so a profile that omits `model_tier_default` never looks like a diff.
- **`biasTier`** applies a preset's strategy to the baseline before clamping: `default` keeps it, `down` is one rank cheaper, `up` one rank richer (up to `top`), `min`/`max` the envelope floor/ceiling; an unrecognized strategy keeps the baseline. **`clampTier`** then forces the result into `[envelope.min..envelope.max]` (the envelope wins over the bias) and reports whether it clamped; an empty envelope passes through, and an unclassifiable request falls to the default or the floor.
- **Family choice.** The builder/auditor family pair is computed once per preset so the two phases stay consistent: `chooseCrossFamilyPair` prefers each profile's default family and splits them across families when at least two are available (adversarial integrity), keeping the builder on its default family. `chooseCLI` picks a non-paired phase's family: the profile default when available and allowed, else the first available allowed family, else the default kept (legible) with a warning. `allowedBaseSet` treats an empty allow-list or the `all` wildcard as allow-any. Available families are sorted, so every "first" pick is deterministic.
- **`Assignment`.** `CLI` is the base family, `Tier` the canonical tier within the envelope, `Model` the native id from `CLIStatus.TierModels[Tier]`.
- **Presets are data.** `PresetSpec.TierBias` names a strategy from `knownTierBias`; an empty value means `default`. The shipped `presets.json` is embedded and parsed once at init; a malformed embedded default panics (a build-time programming error). `LoadPresets` prefers a valid per-repo `.evolve/setup-presets.json`; a present but malformed or invalid override (bad JSON, no presets, a default naming no preset, an unknown tier bias) is an error, never silently replaced by the default.
- **`Apply`** is pure given its inputs (the cmd layer does the disk I/O) and is the gate that refuses to persist an illegal config: a degraded preset, a malformed existing policy or a floor-breaching pin returns an error and no bytes. The existing policy round-trips through a raw map (never the typed `Policy`, which would reorder keys and drop unmodeled ones), so foreign top-level keys and foreign pins survive. A pin is emitted only where the assignment differs from the profile default, and a matching phase has any stale pin removed, so re-applying a lighter preset drops a heavier one's upgrades. Pins store the abstract tier, never the native model id: `policy.ValidatePin` ranks `pin.Model` through `TierRank`, where a native id ranks 0 and would skip the envelope floor. A phase with no profile is skipped and its existing pin left untouched.
- **`Complete`** stamps `setupCompletedAt` and `setupVersion` into `state.json` through a lossless raw merge that preserves unmodeled keys (such as `expected_ship_sha`) `core.State`'s `WriteState` would drop; it writes a temp file and renames it into place.
- **`evolve setup latest`.** Pins stay abstract tiers (`policy.ValidatePin` rejects native ids), so adopting a newer model is never a pin; it is a catalog refresh (`evolve models refresh`). `ComputeLatest` is the pure core of the read-only staleness check that justifies offering one, run across every ready CLI (the live capture and the catalog read are the cmd adapter's job).
- **`ComputeLatest`** picks the freshest candidate in the current model's own lineage under the CLI's `modelquery.FreshnessPolicy`; an alias-resolving CLI (claude's bare `opus` tracks the newest release at launch) prefers the alias, since caching a concrete version would freeze what the alias already outruns. `stale` is true only when the pick differs from the current model; a newer model in a different lineage never marks the map stale. `observed` reports whether the current model or a lineage sibling appeared live at all; when it did not, `latest` is the current model and `stale` is false, and the caller must present "not seen live", never "confirmed freshest". A tier word from the identity fallback reads as never observed.
- **`FamilyLatest`.** `CurrentDeepModel` is what dispatch resolves for the deep tier today (catalog first, the hot-reloading dispatch authority; manifest tier map otherwise) and is only the display anchor. Staleness is judged across the whole tier map, since most phases dispatch `balanced`: `StaleTiers` carries each stale tier's operator-quotable pair (a bare tier name is unquotable), `UnverifiedTiers` names tiers whose mapped model and every lineage sibling were absent from the live capture, and `MapStale` (`len(StaleTiers) > 0`) is the condition under which the skill offers a catalog refresh. `Candidates` of 0 with `Error` set means the probe failed. `LatestReport.Source` is always `live`.

## Invariants

- `Apply`'s gate and merge semantics. Pinned by the `TestApply_*` suite in `apply_test.go` (unknown preset, only differing pins, lossless merge, foreign pins, re-apply clears upgrades, malformed refuses, emitted pins pass `ValidatePin`, degraded refuses, `TestApply_PinStoresTierNotNativeModel`, cross-family pins legal).
- `Recommend`'s shape, baseline, clamp, bias, family choice and determinism. Pinned by the `TestRecommend_*` suite in `recommend_test.go`; the empty-default baseline by `TestRecommend_EmptyDefaultTier_NoSpuriousDiff`; the full bias vocabulary by `TestRecommend_CustomPresetConfig_UpAndMin`.
- The `top` tier round-trips through `canonTier`, `biasTier`, `clampTier` and `Recommend`, and every family resolves a `top` model. Pinned by `TestCanonTier_TopPassesThrough`, `TestBiasTier_UpBias_ReachesTopWhenEnvelopeAllows`, `TestClampTier_EnvelopeMinTop_ClampsUpToTopNotEmpty`, `TestRecommend_MaxQualityBiasesToTop` and `TestTierModelsFor_TopResolvesToModelNotTierName` (which also pins the identity fallback for a base with no manifest).
- Preset loading. Pinned by the `TestLoadPresets_*` tests and `TestBuiltinPresetsValid`, which keeps a broken shipped default from ever shipping.
- Detection, pin overlay, violations and the malformed-policy path. Pinned by `TestDetect`, `TestDetect_PolicyPinOverlay`, `TestDetect_PhaseDefaultsFromProfile`, `TestDetect_PolicyPinCLIViolation`, `TestDetect_PolicyPinTierViolation`, `TestDetect_PolicyPinNoProfile`, `TestDetect_MalformedPolicy`, `TestDetect_DefaultSeams` and `TestDetect_NilDoctorAndCapTierSeams` (one `CLIStatus` per base family whatever the host has installed).
- `Complete` preserves unmodeled `state.json` keys, is idempotent, and fails loudly when its directory cannot be created. Pinned by `TestCompletePreservesUnmodeledKeys` and `TestCompleteMkdirFails`.
- `ComputeLatest`'s lineage, alias and observed semantics and the JSON keys the skill reads. Pinned by `TestComputeLatest_OtherLineageNeverPromotes`, `TestComputeLatest_AliasPreferredWhenPolicySaysSo`, `TestComputeLatest_TierWordFallbackIsNotObserved`, `TestComputeLatest_EmptyCurrentIsInert` and `TestFamilyLatestAndLatestReport_AreTheWireShape`.

## Findings

- agy answers a model name it does not recognize with a one-time warning and serves a different model for the session, so a mistyped `model_tier_map` entry silently downgrades a tier instead of failing; a test that pins the wrong name stays green the whole time. The manifest test pins agy's exact model names.
- `TestTierModelsFor_TopResolvesToModelNotTierName` is hermetic without a catalog seam because the test binary's cwd (the package directory) has no `.evolve`, so `paths.ResolveFromEnv` finds no catalog to overlay; the real catalog seam is `bridge.SetModelCatalogDirFn`, not an environment variable.
