## Purpose

`internal/tokenusage` recovers the tokens one CLI launch consumed and derives how full its context window got. It is best-effort instrumentation. Nothing in it fails a launch. A launch that no source observed is reported as unmeasured, never as free or as an empty context.

## Design

- **Collector chain.** A `Collector` is a lazily evaluated `func() Result`. `Chain` runs collectors in fidelity order and returns the first whose `Source` is not `SourceNone`. So a higher tier that succeeds spares the cost of the lower ones. An all-empty chain returns `SourceNone`, never the first tier's result.
- **Three tiers, highest fidelity first:**
  1. *transcript* (`TranscriptCollector` over `ScanConfigRoot`): Claude Code JSONL under `<configRoot>/projects`. It carries input, output and both cache counters for every turn. A scan error reports `SourceNone`.
     - `Result.ServedModel` is the `message.model` of the assistant reply with the newest timestamp in the window, not the reply that the walk reads last (`TestScanConfigRoot_ANewerReplyInAnEarlierWalkedFileBeatsAnOlderReplyWalkedLater`).
     - The scan skips Claude Code's `<synthetic>` placeholder (`TestScanConfigRoot_ServedModelIsTheLatestRealAssistantModelInTheWindow`). The other tiers leave the field empty.
  2. *events result* (`EventsResultCollector`): the phase's `*-events.ndjson` result envelope. It is parsed by `cyclecost.ParseEventsLog`, the same function cyclecost uses, so the two report identical counts by construction. There is no second parser.
  3. *scrollback peak* (`ScrollbackPeakCollector`): `panestream.ExtractResponseTokens` over the captured pane content (content, not a pane id). It sees output only.
     - For a non-claude driver whose manifest declares `token_line_regex` (carried in `Window.TokenLineRegex`), `TokenLinePeakCollector` follows it in the same tier and source.
     - `panestream.TokenLinePeak` reads the CLI's own token line, agy's `▸ Thought for 14s, 1.5k tokens`. It returns the peak as an output-only floor.
     - The dispatch is data, not a driver-name branch. A driver with no pattern gets nothing from this collector, so it still reports the uncovered warning.
     - Pinned by `TestDefaultResolver_AgyThoughtLineIsMeasuredNotUncovered`, `TestDefaultResolver_TokenLinePatternIsDriverDataNotADriverName` and `TestTokenLinePeakCollector_ParsesCommasAndScaleAndIgnoresUnanchoredText`.
- **The agy conversation store (2026-10-21).** agy 1.4 no longer prints the `Thought for …, N tokens` line. Its pane shows `○ Thought for 8m 0s (…)` with no count. The fixture `testdata/agy14/final-pane-cycle1967-build.txt` is the build pane of cycle 1967. Every agy row of `llm-calls.ndjson` thus had zero tokens. agy writes each conversation to its own data root, `$HOME/.gemini/antigravity-cli` (`AgyDataRoot`).
  - `conversation_summaries.db` lists each conversation with its `workspace_uris` and its `last_user_input_time`. One bridge dispatch is one conversation: in cycle 1967 the five agy dispatches matched five conversations, one each, inside the dispatch windows.
  - `conversations/<id>.db` holds one `gen_metadata` row for each model generation. The row is a protobuf with no published schema. Field 1 is the generation, and its field 4 is the usage. In the usage, field 2 is the uncached input, field 3 the output and field 5 the cache read. The reading is from the data: the first generation has no cache read, and each later one reads the prior context from the cache.
  - `AgyConversationCollector` is the first tier for each driver whose manifest names `agy-conversation-v1`, for example `agy-tmux`. It selects the conversations of `Window.Worktree` whose last user input falls inside the dispatch window, and it sums the usage of every generation. The largest single prompt (input plus cache read) is the peak, so the context fill uses one generation and not the sum. The source is `agy_conversation`, which the bridge records as `measured`.
  - The store is read through the `sqlite3` command, read-only (`SQLiteCLI`, `sqlite3 -readonly`, a 10 s timeout). Only `SQLiteQuery` is a seam.
  - A missing store, an unreadable store or an id that is not a UUID gives no source, so the next tier runs. A conversation that cannot be read, or a malformed generation row, is not counted, and `Result.Warn` names it.
  - The limits: a conversation belongs to the dispatch by the time of its last user input. Two dispatches that run in one worktree at the same time can claim the same conversation. The fields are inferred from the data, because agy publishes no schema; the sum over generations treats field 3 as the output of one generation. `walkFields` reads the protobuf wire format. It refuses a truncated varint, a length past the end, a truncated fixed field and an unknown wire type.
  - On the cycle-1967 build dispatch, the 111 generations give input 554617, output 69220 and cache read 13904571. The fixture `gen-metadata-cycle1967-build.hex` holds the usage message of each real row (`TestAgyConversationCollector_Agy14BuildPaneHasNoTokenLineButItsConversationCounts`). Pinned also by `TestAgyConversationCollector_NoDataIsNoSource`, `TestAgyConversationCollector_AQuoteInTheWorktreeIsEscaped`, `TestSQLiteCLI_ReadsAStoreReadOnly`, `TestResolver_AnAgyDriverReadsItsConversationStoreFirst` and `TestAgyGenerationUsage_ReadsOnlyTheUsageCountersOfEachGeneration`.
- **One resolver, dispatched per driver.** `Resolver(Roots{Claude, Agy}, query)` is the constructor, and `DefaultResolver(configRoot)` is it with the agy root of the process `HOME`. The bridge adapter passes the roots of the launch environment.
  - The composition roots wire it into `bridge.Deps.TokenResolver` (`internal/adapters/bridge` and `internal/subagent`'s exec adapter), so the two cannot drift.
  - The manifest of the driver picks the chain ([llm-isolation.md](../llm-isolation.md) §11.1, X9). The bridge puts the manifest field `collectors.tokens` into `Window.Collector`. `collectorFormats` has one chain for each format id: `claude-jsonl-v1` gets the three tiers, and `agy-conversation-v1` gets the agy conversation tier first. A window with no known collector gets the events and scrollback tiers.
  - `HasCollector(format)` is true for a format id of `collectorFormats` only. The bridge asks it with the collector of the manifest, so the chain and the tripwire agree. A driver name matches its manifest exactly, so `CLAUDE-TMUX` has no collector.
  - If a window with no collector has no usage, the source is `no_collector` (`SourceNoCollector`), and the warning says that the driver has no usage collector. If a collector found no usage, the source is `none`, and the warning says that the usage is uncovered. The bridge fires its telemetry tripwire only for a driver with a collector (inbox `agent-router-token-resolver-nil`, the review of 2026-09-27). Pinned by `TestHasCollector_OnlyTheFormatsWithAnImplementation`, `TestResolver_ADriverWithNoCollectorIsNoCollectorNotZero` and `TestResolver_TheCollectorFormatNotTheDriverNamePicksTheChain`.
- **Fill is derived, not measured twice.** The resolver stamps `FillPct` from the usage that the same resolve recovered: `windowOccupancy(r) / Window.ContextWindow × 100`. The bridge takes `ContextWindow` from the manifest field `context_window`. There is no second scan.
- **Transcript attribution.** When `Window.ArtifactPath` is set (every production launch) it alone attributes: the transcript's first user message must contain an anchor immediately followed by that path. The anchors (`artifactAnchors`) are every form a dispatched prompt uses to disclose its deliverable path:
  - `Artifact path: `: both subagent prompt assemblers. One prefixes it with a list bullet, which sits outside the key.
  - `DELIVERABLE PATH: ` (`phasecontract.FooterMarker`): the contract footer every bridge-dispatched loop phase carries.
  - `<artifact-path>`: the contract tail element.
  An empty `ArtifactPath` (legacy launches, unit fixtures) falls back to an exact `cwd == Worktree` match on any line. The session-directory slug is never trusted: it is a lossy sanitisation of cwd, and swarm readers can share one.
- **Both content encodings.** The first user message's `content` is either a bare JSON string or an array of text blocks. Real transcripts carry the phase prompt as a bare string, so `contentText` decodes both.
- **Streamed deltas.** The CLI repeats a message id across the streamed usage deltas of one turn, and each delta is cumulative. The scanner keeps the last line per id and never sums them. The per-id map spans every attributed transcript.
- **The transcript locator.** `LocateTranscript(root, w)` gives the path of the transcript of one dispatch, or "" when there is none. It uses the attribution rule of the scanner (the artifact anchor, else the exact `cwd`). It also needs an entry with a parseable timestamp inside `[w.Start, w.End]`. Two sessions of one phase can share one anchor and one `cwd` (cycle 1853).

  When more than one file matches, the file with the latest timestamp in the window wins. A file that has not changed since `w.Start` is not read, and a symlink is skipped. An empty root gives "".

  `ClaudeConfigRoot(env)` is the one home of the Claude config directory. `CLAUDE_CONFIG_DIR` wins, because Claude Code writes its transcripts there when it is set: the request value first, then the process value, which the agent inherits.

  Only an absolute value of `CLAUDE_CONFIG_DIR` counts, and it is cleaned. Else it is `$HOME/.claude` (the request `HOME` first). With neither, it gives "", and `TranscriptCollector("")` gives `SourceNone`. The phase runner calls it after an abnormal end ([internal-attemptpostmortem.md](internal-attemptpostmortem.md)). Pinned by `TestLocateTranscript_PicksTheSessionInsideTheDispatchWindowWhenTwoShareAnchorAndCwd` and `TestLocateTranscript_FallsBackToTheCwdAndNeedsAStampInTheWindow`.
- **Launch window.** A turn counts when its timestamp lies inside `[Start, End]` (inclusive). A missing or unparseable timestamp is admitted, because its transcript is already attributed by content.
- **Two readings off the same turns.** `Usage` is the sum across turns: what the launch cost. `PeakPromptTokens` and `PeakUsage` describe the single fullest turn: how full the window got. The peak stands in for the last turn, because the per-id map has no reliable turn order. Also, the question that the fill WARN answers is how close the launch came to compaction at all. Within a phase, context only accumulates, so on real transcripts the peak is the last turn.
- **Contributor breakdown.** `FillWarnWithContributors` shows exactly the counters the caller passes. Choosing the basis (peak turn or launch total) is the caller's job in `internal/bridge`. Counters are listed largest first and zeros are omitted. Any negative counter drops the breakdown and keeps the base warning. Control characters in the phase name become spaces.

## Invariants

- **Telemetry never errors a launch.** `DefaultResolver` always returns a nil error, and `ScanConfigRoot` returns nil on a missing directory or a failed walk. The risk is that a resolver error surfaces as a WARN on every launch, not only on genuine failures. Pinned by `TestDefaultResolver_EmptyConfigRoot_ReturnsSourceNoneNotError`, `TestDefaultResolver_AllTiersEmpty_SourceNoneNilError` and `TestScanner_UnknownDriverFailsOpenNoError`.
- **Unmeasured never reads as zero.** When no tier has data, the Result carries a `Warn` that names the driver and `FillPct = FillPctUnmeasured`. The risk is that silent zeros read as covered, free launches with empty contexts. Pinned by `TestScanner_PerDriverCoverageWarnsNotZeros` and `TestFillTelemetry_UnmeasuredResolveCarriesSentinel`.
- **Lower tiers never fabricate.** The scrollback tier leaves input and cache counts at zero, and a usage block without cache fields contributes zero cache. Pinned by `TestScrollbackPeakCollector_OutputOnlyFloorFromPane` and `TestScanner_UsageBlockMissingCacheFieldsStaysZeroNotFabricated`.
- **The sentinel is negative.** `FillPctUnmeasured` is `-1`, so it cannot collide with a real 0–100 reading and every threshold comparison fails closed on it. Pinned by `TestFillTelemetry_ZeroWindowGuard`.
- **`FillPct` never returns Inf or NaN.** A window of zero or less, or a negative prompt total, yields the sentinel. Over-full readings are not clamped: 120% is a real signal. Pinned by `TestFillTelemetry_ZeroWindowGuard`, `TestFillTelemetry_PctFromPromptTokensAndWindow` and `TestFillWarn_OverHundredPercent_StaysLegible`.
- **Output tokens never count toward fill.** They do not sit in the prompt. The risk is that the code counts them, and then the WARN fires on long answers instead of big prompts. Pinned by `TestFillTelemetry_PromptTokensSumsInputSideOnly`.
- **`PromptTokens` guards its sum.** The counters are driver-controlled JSON. A negative counter, or an addition that overflows `int`, returns a negative total, which `FillPct` turns into the sentinel. The risk was that a silently wrapped sum publishes a fabricated percentage that `FillWarn`'s negative rule then silences. The launch with bogus telemetry is then the one launch that raises no warning. Pinned by `TestFillTelemetry_PromptTokenOverflowIsUnmeasured`; `TestFillTelemetry_OverflowGuardKeepsHonestReadings` proves honest large readings survive.
- **The fill numerator is one turn.** `windowOccupancy` uses `PeakPromptTokens` when it is non-zero, otherwise `PromptTokens(Usage)`. Each turn's `cache_read` already holds that turn's whole prior context. So the sum of turns counts the same context once per turn. The events and scrollback tiers report one envelope, which is already a single reading (`PeakPromptTokens` stays 0).
- **A negative peak.** A negative peak means turns were expected but none fell inside the window. It passes through to the sentinel, because an unobserved context is not the same as an empty context. `Usage` stays the sum, since it is the cost figure. Pinned by `TestFillPct_UsesTerminalTurnNotSumOfTurns`, `TestResultPeakPromptTokensNamed`, `TestFillPct_ZeroObservedTurns_IsUnmeasured` and `TestScanConfigRoot_MultiTurnTranscript_UsageStaysTheSum`.
- **Effective windows.** The manifests of the claude, agy and codex drivers set `context_window` to 200 000, the values of the old table (since 2026-10-21). `ollama-tmux` sets none. A window of 0 gives the sentinel, because a guessed window publishes a false reading. `TestManifests_CarryTheCollectorsWindowsAndCapabilitiesThatGoHeldBefore` (`internal/bridge`) pins each value.
  - 200 000 sits below every advertised maximum (codex 400K, agy 1M), because the useful signal is nearness to degradation, not the hard ceiling.
  - The window and the collector come from one manifest, so they cannot disagree about a driver. A name with no manifest has no window.
  - `ollama-tmux` has no window because the served model, not the CLI, owns the window.
  - Each tmux driver sets the same window as its headless driver, so fill readings compare across lanes. `agy-claude-tmux` gets the window of `agy-tmux` through its `base`.
- **`FillWarn` fires strictly above the threshold** and never on a negative reading. The message names the phase, because an unattributed fill WARN cannot be acted on. Pinned by `TestFillWarn_FiresOnlyStrictlyAboveThreshold`.
- **Every anchor form stays listed.** Dropping one does not narrow attribution loudly: it silently degrades those launches to the scrollback tier, with input and `cache_read` at zero. `TestArtifactAnchors_MatchRenderedContract` renders the real phasecontract footer and tail and requires an anchor to match each, and the `go/acs/cycle1457` predicates pin the subagent format strings.
- **Anchors match exactly**, label case and punctuation included. Hyphenated, lowercased and `key=value` lookalikes do not attribute, and neither does a prose citation of the path. Pinned by `TestAttributes_MarkerAnchored`.

## Findings

- **Batch bkm5wr3ey (cycles 612–619)**: the first full S1–S7 binary recorded every count as zero because no composition root wired a resolver. `DefaultResolver` became the one shared constructor (cycle-623). See the post-mortem.
- **cycle-754**: all 124 `llm-calls.ndjson` files under `.evolve/runs/` showed `source:none` for tmux-driven launches. `DefaultResolver` chained only the transcript tier, although the events and scrollback collectors already existed. `Window` gained `EventsLogPath` and `Scrollback`, and the resolver now chains all three tiers.
- **cycle-779**: the 2026-07-13 baseline showed input, `cache_read` and `cache_write` at zero across every phase. The baseline also recorded agy and codex launches as zero usage, as if covered. Input outweighs output from 2:1 to 100:1, so the dominant cost was invisible. The fix added the per-driver dispatch and the uncovered `Warn`. `go/acs/cycle779` binds `TestScanner_PerDriverCoverageWarnsNotZeros` and `TestScanner_UnknownDriverFailsOpenNoError` by name.
- **cycle-867 / ADR-0071**: cwd-keyed attribution never matched on the tmux path. `WORKTREE_PATH` fell back to the repo root, and the agent changed into `go/`. So the transcript tier fell through to scrollback and a real 173 121-token `cache_read` read as zero. The first ArtifactPath fix (`c41fa94b`) shipped inert because the fixtures used the block content form while real transcripts use the string form. Lesson: verify a parsing fix against real on-disk data.
- **cycle-1457**: matching the bare path billed a retrospective launch to the builder's Window, because the retrospective profile tells it to read `.evolve/runs/cycle-{cycle}/build-report.md`. Anchoring on label plus path closed that. The real cycle-1457 build prompt carried only the footer form. So the anchor set had to include the phasecontract forms as well as the subagent marker.
- **cycle-1444**: fill telemetry landed as a reading derived from the resolved usage. Its audit (M1) found the unguarded `PromptTokens` sum; **cycle-1446** added the overflow guard.
- **cycle-1455**: summing per-turn prompt sides reported 566.9% (scout) and 114.3% (triage) in one monitored wave. The numerator became the fullest single turn, and `Usage` stayed the sum.
- **cycle-1482**: codex and agy lanes read as unmeasured forever, although their windows are documented. So they gained the conservative mapping. The cycle-1458 audit (M1) found a risk. The risk was that a contributor breakdown built from summed usage contradicts a peak-turn percentage. An example is a 75% reading annotated with components totalling 1500% of the window. So `FillWarnWithContributors` takes its basis from the caller, and `Result.PeakUsage` carries the peak turn's counters.
