# internal/phases/specrunner

## Purpose

`internal/phases/specrunner` turns a declarative `phasespec.PhaseSpec` into a runnable `core.PhaseRunner` with no per-phase Go: it derives the artifact name, prompt composition and verdict classification that `runner.BaseRunner` needs from the spec's fields. It is what makes a user phase pure data (a `phase.json` spec, an `agent.md` prompt and a `profile.json` permission set). Its judgment-verdict stage, `verdict_from_sentinel`, is decided in [ADR-0091](../adr/0091-judgment-verdict-from-sentinel.md).

## Design

- specrunner is a constructor only and never self-registers; the composition root (`registerBuiltinSpecRunners` in `cmd/evolve/cmd_cycle.go`, and `internal/phaseregistrar`) wires spec-derived runners.
- `hooks` is the spec-driven `runner.Hooks` implementation and holds the spec by value (specs are small, immutable data).
- `ArtifactFilename` returns the basename of the first declared output file, else `<name>-report.md`. The registry may store a templated path (`.evolve/runs/cycle-{cycle}/scout-report.md`), and `BaseRunner` joins the basename with the request workspace.
- `ComposePrompt` appends the base cycle context plus each `prompt_context` key that has a non-empty value in `req.Context`. A one-line value is a `- key: value` entry under the cycle context. A multi-line value, such as the Task Contract, follows as its own `## <Key Words>` block (`task_contract` → `## Task Contract`), the shape the built-in tdd, build and audit render, never a block hung after a list marker (`TestHooks_ComposePrompt_AMultiLineContextValueIsItsOwnHeadedBlock`). `req.UpstreamSignals` is not injected: declared-signal injection needs the Stage-3 signal bus.
- `Config.PromptBody`, when non-empty, is the in-band prompt (`runner.InlinePromptProvider`), which lets a minted phase ship its persona as data; empty loads `agents/<AgentName>.md` from disk, byte-identical to the on-disk path.
- `Config.ContractVerifier` is the deliverables gate's verifier accessor, passed to the verdict engine so gate and engine share one verifier; nil selects the catalog-aware default.
- `Classify` returns `spec.OnPass` as the next-phase hint; empty lets the orchestrator's state machine pick the successor.
- `EvaluateClassify` is the declarative verdict evaluator shared with built-in phases (`internal/phases/triage` and `internal/phases/intent` delegate to it). It is pure, so its matrix is exhaustively unit-tested. Its rules, in order: an empty artifact FAILs when rules are absent or `fail_if_empty` is set (rules present with it unset let an empty artifact pass, an explicit opt-out); every `require_sections` entry must appear line-anchored, else FAIL with a diagnostic naming the missing sections; a non-empty `fail_if_signal` FAILs; `verdict_on_pass` overrides the pass verdict but must be canonical, else FAIL; the sentinel stage runs last.
- `hasSection` is heading-aware: a leading markdown heading marker (a `#` run followed by whitespace) is stripped from both the rule and the line before the prefix compare, so the rule "Baseline" matches "## Baseline" and "## Findings" matches a bare "Findings" line. There is one semantic, not two matching modes. Line anchoring still rejects mid-line occurrences, and a `#` run glued to text ("##Findings") is not a heading.
- `classifyOutcome` is one evaluation pass read two ways: the verdict view (`EvaluateClassify`) and the measurement view (`classifyShadow`). Two evaluators could drift, and a shadow record that disagrees with the routing it describes measures nothing. `hooks.Classify` evaluates once and projects the record from that pass (`shadowRecord`).
- The shadow record is written in `hooks.Classify`, the I/O boundary, not in the pure `EvaluateClassify`. `writeVerdictShadow` is a no-op for any phase that has not declared `verdict_from_sentinel`, so no phase pays for a measurement it did not ask for and no phase name appears in Go.
- `verdict_from_sentinel` reuses `phasecontract.ParseVerdictSentinel`, the parser the contract gate and the verdict cache already read, rather than a second grammar for "FAIL" that could drift from the first. Every judgment report already carries a well-formed sentinel, so this is wiring, not new grammar.
- Rollout stages: off (the absent key; structure decides and the stated verdict is discarded, byte-identical for every phase that does not opt in), shadow (routes exactly as off and records what the stated verdict would have made it), and enforce (the stated verdict is authoritative). It is a staged rollout, not a switch, because the stated-verdict population is uncalibrated and turning it authoritative in one step would halt nearly every cycle at that phase. ADR-0091 owns the measured counts.
- `VerdictShadowRecord` answers what the promotion decision turns on. `StructuralVerdict` keeps the legacy reading, so a record read after promotion still shows what was suppressed. `SentinelConsulted` separates "looked and found nothing readable" from "never looked" (the stage runs last, so a structural failure or a typo'd stage word returns before the parse). `SentinelPresent` separates "stated nothing readable" from "stated PASS" and is meaningful only when `SentinelConsulted` is true. `WouldFlip` is the soak's datum and is false under enforce by construction. `Rationale` states the record's meaning so a soak sweep need not re-derive it from the fields.
- `writeVerdictShadow` is best-effort, the same posture as the audit-chain shadow: a measurement must never influence, delay or brick the decision it measures. It is not silent: a write error becomes a warn diagnostic at the call site, because a permanently failing write yields an empty soak and nothing else would say so, and diagnostics do not affect routing.

## Invariants

- The sentinel stage runs after every structural check, so a stated verdict can never launder an empty artifact, missing sections, an inert gate or an invalid `verdict_on_pass` (pinned by `TestEvaluateClassify_StructuralFailurePrecedesSentinel`, `TestEvaluateClassify_EmptyArtifactStillFails`).
- Inert or mistyped gates fail loudly with an error diagnostic, never pass silently: a non-empty `fail_if_signal` (it cannot be evaluated without the Stage-3 signal bus), an invalid `verdict_on_pass`, and an unknown `verdict_from_sentinel` stage word (pinned by `TestEvaluateClassify_FailIfSignal_RejectsWithErrorSeverity`, the `invalid_verdict_on_pass_fails_loudly` row of `TestEvaluateClassifyExported`, `TestEvaluateClassify_UnknownStage_FailsLoudly`). `phasespec.TestRepoPhaseCatalog_NoInertFailIfSignal` enforces the `fail_if_signal` rule at authoring time, so the rejection never fires mid-cycle.
- Fail-open: an absent, malformed or non-canonical stated verdict keeps the structural verdict and says so in a warn diagnostic (pinned by `TestEvaluateClassify_Enforce_FailsOpenWhenSentinelAbsent`, `TestEvaluateClassify_Enforce_NonCanonicalStatedVerdictFailsOpen`). `core.IsVerdict` is case-sensitive, so a lowercased "fail" fails open rather than being honoured (pinned by `TestEvaluateClassify_Enforce_LowercaseVerdictFailsOpenLoudly`).
- Shadow never changes routing and still discloses the would-be verdict (pinned by `TestEvaluateClassify_Shadow_RoutingUnchangedOnRealCycle1528`, `TestEvaluateClassify_Shadow_DisclosesTheWouldBeVerdict`). Under enforce the stated verdict is the routed one, WARN and SKIPPED included (pinned by `TestEvaluateClassify_Enforce_HonorsRealCycle1528FAIL`, `TestEvaluateClassify_Enforce_HonorsWARN`, `TestEvaluateClassify_Enforce_HonorsSKIPPED`).
- The sentinel parser is tail-anchored, so a report that quotes the sentinel shape in an example or fenced block cannot outvote its real final sentinel (pinned here by `TestEvaluateClassify_Enforce_TailSentinelWinsOverEarlierDecoys`, not only by phasecontract's tests).
- The shadow record filename is phase-scoped (`judgment-verdict-shadow-<phase>.json`). The workspace is `core.RunWorkspacePath(root, cycle)`, one directory per cycle shared by every phase, and both opted-in judgment phases routinely run in the same cycle, so a shared name would let the later phase overwrite the earlier one's sample, biased toward the cycles that also produced a build (pinned by `TestHooksClassify_TwoJudgmentPhasesInOneCycleBothKeepTheirRecord`). Non-portable characters fold to `_`, so a phase name can never traverse out of the workspace (pinned by `TestVerdictShadowRecordFile_IsScopedAndSafe`).
- A failed shadow write surfaces a diagnostic and never changes the verdict; with no workspace nothing is written (pinned by `TestHooksClassify_UnwritableWorkspaceIsReportedNotSwallowed`, `TestHooksClassify_NoWorkspaceIsSafe`).
- An opted-out phase is byte-identical to the legacy path: same verdict, no diagnostics, no record (pinned by `TestHooksClassify_OptedOutPhaseIsUnchanged`).
- Records are taken for agreement and under enforce too, so the soak can compute a flip rate and the measurement survives promotion (pinned by `TestClassifyShadow_RecordsAgreement`, `TestClassifyShadow_TakenUnderEnforceToo`). An unreadable sentinel is not recorded as agreement (pinned by `TestClassifyShadow_UnreadableSentinelIsNotAgreement`), and a structural failure records that the sentinel was never consulted (pinned by `TestClassifyShadow_StructuralFailureSaysTheSentinelWasNeverConsulted`).

## Findings

- The fixtures in `testdata/` are real reports (a premise-challenge that stated FAIL and an adversarial-review that stated PASS), because the acceptance criterion is that the live population parses; a hand-written fixture proves only what its author imagined.
- Before `verdict_from_sentinel`, a judgment phase that stated FAIL, with a well-formed machine sentinel, classified PASS on structure alone and the cycle ran on; the loop paid for the dispatch and discarded its conclusion. The measured counts are in ADR-0091.
- `TestHooksClassify_WritesTheShadowRecordForAnOptedInPhase` is the wiring proof: a mutation that stops `Classify` writing the record survived the component tests.
- `TestEvaluateClassify_OmittedKeyEqualsExplicitOff` cannot prove byte-identity with the legacy classifier, because `SentinelStageOff` is the zero value and the two rule structs are equal; `TestHooksClassify_OptedOutPhaseIsUnchanged` is the byte-identity pin.
- `shadowRecordsIn` globs for records instead of stat'ing one expected name, because a dropped `optedIn` guard writes a zero-value record under a different filename.
