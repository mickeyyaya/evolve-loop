# internal/recurrence

> Related: [ADR-0121](../adr/0121-inbox-priority-is-a-computed-rank.md) (the inbox rank's recurrence factor reads this ledger), [internal-inboxrank.md](internal-inboxrank.md), and the failure-disposition boundary escalation whose staged intents `ApplyBoundary` applies ([ADR-0107](../adr/0107-failure-disposition-boundary-escalation.md)).

## Purpose

`internal/recurrence` keeps the deterministic recurrence ledger, `.evolve/recurrence-ledger.json`: one `Entry` per lesson `pattern:` key with the cycles it closed out in, its `Count`, the linked fix item (`fix_item_id`) and whether the pattern is classification noise (`Generic`). `Ledger.RecordClosure` upserts a retro closeout and applies the count-to-weight escalation policy, idempotent per cycle. `ApplyBoundary` applies the intents the disposition router staged, at the loop's boundary under the inbox lock. `BackfillFromLessons`, `IsGeneric` and `WriteDigest` build the ledger from history, mark noise and render the failure digest. The ledger itself (`ledger.go`) needs only the standard library, `internal/atomicwrite` and `internal/adapters/flock`; the applier, the backfill and the digest also import `cyclestate`, `dispositionrouter`, `dossier`, `failureadapter`, `failurelog` and `retrofile`.

## Design

- **Two reads of one file.** `Load` takes the `<path>.lock` sidecar lock (`flock.WithPathLock`) and decodes; it is the read half of a read-modify-write that ends in `Save`, which writes under the same lock by atomic rename. `ReadSnapshot` is the same decode without the lock, for a reader that only looks: the file is replaced by rename, so a lockless read sees either the old or the new ledger, never a torn one, and it creates no sidecar file. `Load` is the lock wrapped around `ReadSnapshot`, so the two cannot decode differently. The decode rules: a missing or empty file is an empty ledger; a file without `entries`, or with `"entries": null`, gets an empty map; anything else that fails to parse is an error naming the path, with no ledger.
- **The inbox rank's linkage lives here.** `Ledger.ItemCounts()` maps an inbox item id to its recurrence count: every non-generic entry counts under its pattern key (an autofiled recurrence item is filed under its pattern) and under its `fix_item_id`, and when several entries name one id the largest count wins. A nil ledger or a nil entry counts nothing. Since P2 (2026-10-06) `internal/inboxrank/rankinputs` is the one reader that composes `inboxrank.Inputs.Recurrence` from `ReadSnapshot(...).ItemCounts()`, for every rank consumer (`evolve inbox rank` and `batches`, the wave seed, the triage prompt, the dashboard), so the rank package never imports this one.
- **An autofile carries the staged intent's class.** `applyIntent` copies `Intent.PriorityClass` into the `retrofile.PreventiveAction` it files, and `retrofile.FileActions` writes it as the item's `priority_class`, so the one generic filer needs no class of its own: the stager chooses it for the finding it stages (the contract-gate demotion stages `correctness`, `core.ContractGateDemotion.Intent`). `dispositionrouter.StageIntent` refuses an autofile intent with no class (`inboxbatch.ErrNoPriorityClass`), and `retrofile.FileActions` refuses an action with no class after its dedupe (`inboxbatch.ErrNoPriorityClass`), so an already-filed action still dedupes. An intent staged before the field existed is therefore refused at apply, not filed: `applyIntent` records its id in `ApplyResult.Refused` (the report's `refused`) and consumes its slot, so a legacy line never wedges the boundary; the loop's boundary applier prints each refused id as a `[loop] WARN` line and counts it in its signal (the P2 architecture review's W2 and the delta re-review's H1, 2026-10-06; `TestApplyBoundary_AnAutofileCarriesTheStagedIntentsPriorityClass`, `TestApplyBoundary_AClasslessAutofileStagedBeforeClassesIsRefusedNotFiledAndDoesNotWedge`). Items carry no fingerprint field yet; the plan's P3 adds one and the linkage moves with it.
- **The inbox is written at the boundary only.** Staging happens mid-cycle, while fleet lanes are in flight. An inbox write at that time races the `os.Rename` of `inboxmover.Claim`. It resurrects a claimed item into double work across lanes. So `ApplyBoundary` runs at the loop's per-iteration boundary, after the dispatch returns with no lane running. It holds the inbox lock for the whole read, change and write.
- **The applier is the only inbox writer on this path.** The autofile path goes through `internal/retrofile`, not a second writer. An absent staging file is not an error. The report is still written, so its presence does not depend on there being work.
- **The applier has four safety properties.** It is idempotent per cycle: a stamp file beside the staging file stops a re-run from escalating twice. It never lowers a weight. It skips claimed items (under `inbox/processing/`) and never resurrects them. In the shadow stage it writes the report artifact and does not change the inbox.
- **The stamp is presence-checked.** A missing key reads as the map zero value. The fleet boundary passes the 0-based pool iteration as `Cycle`. A bare `stamp[key] == opts.Cycle` skipped every never-applied intent on iteration 0 (the enforce-flip swallow of 2026-08-10).
- **Backfill counts history and escalates nothing.** `BackfillFromLessons` seeds a fresh ledger from `.evolve/instincts/lessons/*.yaml`. It accepts both lesson shapes: the deterministic-floor lesson (pattern equals errorCategory) and the richer LLM lesson. It passes a nil escalator and a nil autofiler. So escalation stays boundary-only, and `RecordClosure` cannot fail.
- **Backfill skips bad files and keeps order.** A malformed or empty file is skipped and named in the second result. Only an unreadable directory is an error. `Generic` is sticky: a pattern that is generic in any lesson stays generic. Files are scanned in sorted order, so the ledger is deterministic.
- **Generic noise stays out of escalation.** The denylist holds classification labels that dominate raw counts without being a defect (`operator-reset` and `loop-fatal`, about 59% of the corpus at the time). The pattern-equals-errorCategory echo rule catches the rest. An LLM defect whose pattern differs from its category is the signal to keep. Every owned label is projected from its home (the failurelog taxonomy, the engine's default class). `cycle-fatal` and `unknown` have no owner yet.
- **The digest is a prompt-injection surface.** Digest values are LLM-authored and are re-injected into later prompts. So `sanitizeLine` collapses newlines, carriage returns and tabs, and every rendered value passes through it.
- **Digest priority is retention.** Lines are in priority order: cycle outcomes newest first, then failed approaches, then pattern stats. Truncation drops from the end. Generic patterns roll up into one aggregate line, so noise cannot crowd out actionable patterns. A compiled constant caps the pattern section.
- **The digest is empty or absent when history is empty.** Empty history writes no file. A headers-only artifact wastes prompt tokens every cycle and signals false coverage. The token estimator is local (chars divided by 4), because importing `deliverable.charsPerToken` is an import cycle.
- **The escalation formula is injected.** The caller supplies `EscalationPolicy` (`min(Cap, base + Step*(count-1))`), so no consumer bakes the constants into Go. `DefaultEscalationPolicy` holds the defaults for a caller with no override. `BumpedCycle` and `Autofiled` are the dedup guards. A re-run of one cycle's closeout re-appends nothing and re-escalates nothing. An orphan pattern is filed exactly once while open.

## Invariants

- **`Load` and `ReadSnapshot` decode alike, and `ReadSnapshot` writes nothing.** `TestReadSnapshot_DecodesAsLoadDoesWithoutTakingTheLock` runs each decode rule through both and compares the directory before and after the snapshot read; `TestReadSnapshot_AMalformedOrUnreadableLedgerIsAnError` pins the parse error (the same text from both) and a read error.
- **`ItemCounts` is the one id linkage.** `TestLedger_ItemCounts_CountsThePatternAnItemCarriesOrFixes` pins the pattern and `fix_item_id` keys, the largest-count rule, and that generic and nil entries count nothing.
- **Persistence round-trips.** `TestLedger_LoadSaveRoundTrip`.

## Findings
