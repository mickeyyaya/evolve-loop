# internal/usageevidence

> The operator procedure: [CLI-failure triage](../../operations/cli-failure-triage.md). The query and its verdicts: [internal-usageprobe](internal-usageprobe.md), *Usage evidence*. The wiring: `cmd/evolve/usage_evidence_wiring.go` ([cmd-evolve](cmd-evolve.md)).

## Purpose

`internal/usageevidence` makes "query the CLI's usage" a step of every failure path that classifies a CLI as not working, and records the answer as evidence. Before 2026-10-06 those paths inferred the cause from what was missing. The boundary updater read a `doctor live` that did not answer as "the family counts as unsubscribed", and a phase that timed out on a drained quota pool looked like any other timeout.

## Design

- **`Explain`** (`func(ctx, driver) usageprobe.Evidence`) is the one shape every site calls. `New(Options)` builds the production one over `usageprobe.EvidenceSource` (`Options.Now` injects the clock; production leaves it nil):
  - the CLI's usage pane comes through `Options.Probe` (`UsagePane(factory)`: a fresh controller session, never the failing pane);
  - the manifest's window reader (`ReadWindowsNow`) and the whole-family regex read the pane;
  - the bench store comes from `ProjectRoot`;
  - the timeout and the TTL come from `cli_health` (`Options.Config`);
  - `Act` lets the query bench and record.

  The failing driver's **binary** is queried (`llmroute.Binary`, so `agy-claude-tmux` reads agy's screen), and the verdict is judged for the driver's **routing family** (`llmroute.Family`, so the Claude group's windows decide `agy-claude`).
- **`Report(center, Record)`** writes one JSON line to `<workspace>/usage-evidence.ndjson` (`core.UsageEvidenceFile`): origin, phase, driver, trigger, exit code, summary, and the evidence with its windows. It then emits `BRIDGE_USAGE_EVIDENCE`, module `bridge`, kind `bridge.warning`, WARN for `exhausted` and `unavailable` and INFO otherwise, with fields `driver`, `cli`, `family`, `verdict`, `trigger`, `exit_code`, `cached`, and `record_error` when the append failed. The registered description lists them all. A failed append is returned and also named in the signal's `record_error` field, so a caller that cannot log still surfaces it.
- **`Wrap(inner, explain, signals)`** is a `core.Bridge` decorator.
  - The composition root wraps the raw bridge adapter with it once, and the bridge-chain walker wraps the result. So every attempt of both walks passes through it: the runner's own walk launches with `ChainAttempt` through the walker into the decorator, and so does the walker's walk for the retro, the advisors and the swarm.
  - After an attempt returns a non-zero exit other than 127 (a missing binary is its own definitive cause), it queries usage, reports, and returns the attempt unchanged. It does this before the walk moves on, so an exhausted family is benched before the next attempt.
  - A cancelled context queries nothing. Its exit 85 still benches its report, as on the runner's walk.
  - It forwards `Signals()` and `SignalsWired()` of the inner adapter, because the walker and the runners assert those methods on their bridge.
- **Every exit 85 benches its escalation report through one rule, whatever the usage verdict.**
  - **Wave 69 (live, 2026-10-06).** Both lanes' router launches on agy-claude-tmux exited 85 on `⚠ Individual quota reached … Resets in 1h3m47s`, matched by the inherited `exhausted_regex` and classified `exhausted`. Yet the plane benched nothing for agy-claude, so every router decision re-hit the wall. The router is the phase advisor, which walks its own chain with `ChainAttempt` set; `bridgechain.Walking` passes such attempts through, and only the runner's walk called `BenchOnEscalation`.
  - **The rule.** The decorator, which every attempt of every walk passes through, calls `bridgechain.BenchOnEscalation` on every exit 85, after the usage query. The runner's walk and the walker's walk call the same function with the same `bridgechain.Escalation`. It benches a report once (a family benched at or after the report's capture is skipped), so the calls agree and add one strike between them.
  - **The verdict is evidence, not a veto.**
    - `exhausted`: the query has already benched the family until the screen's reset, so the report is skipped as already benched.
    - `healthy`: the classified wall still benches the failing family, with the wall's own reset hint or the strike cooldown. A family screen does not show every wall: a per-model window (claude's Fable week) or a wall the screen does not list.
    - `unavailable` or `unknown`: the same. The wall benches the **failing** family (agy-claude, never agy's Gemini family).
  - **Why no verdict gate (delta re-review, 2026-10-07).** Round 1 benched only on `unavailable` or `unknown`. The runner's walk and the generic walker bench ungated, so a per-model wall was benched on the runner's walk and never on the advisor's, exactly the wave-69 path. Per-model precision is the [model-level benches](../../plans/model-level-benches-2026-10.md) item, not a verdict gate here.
  - **The runner's and the walker's own calls stay.** A composition root or test that wires no explainer gets the bare bridge from `withUsageEvidence`, and there those calls are the bench.
  - Pinned by `TestBridge_TheLiveAgyClaudeWallWithADrainedClaudeGroupBenchesAgyClaudeUntilTheScreensReset` (the live pane text from `internal/bridge/testdata/agy-claude-individual-quota-wall.txt`), `TestBridge_AnUnavailableUsageQueryFallsBackToTheAttemptsOwnWallAndBenchesTheFailingFamily`, `TestBridge_AWallTheFamilyScreenDoesNotShowBenchesAlikeOnTheAdvisorsWalkAndOnTheRunnersWalk` (red before the rule; the reviewer's probe), `TestBridge_AFreshHealthyUsageScreenIsRecordedAsEvidenceAndTheClassifiedWallIsStillBenchedOnce` (inverted from round 1's "rules the wall out") and `TestBridge_OnlyAnEscalatedExitBenchesItsWallAsOnTheRunnersWalk`.
- **A read taken before the failure does not describe it.** `Explain(ctx, driver, since)` passes the failing attempt's start, and the query reuses a healthy read only when it was taken at or after it ([internal-usageprobe](internal-usageprobe.md), *Usage evidence*). Two things depend on it. The evidence describes this failure, not the pre-wave probe's screen from minutes before. A fresh `exhausted` read benches until the screen's reset, which is longer and truer than the wall's hint: wave 69's screen said 2h15m where the wall said 1h4m. A read another lane took during the attempt is reused without a second query. Pinned by `TestBridge_AHealthyReadRecordedBeforeTheFailingAttemptIsQueriedAgainSoTheScreensResetSetsTheBench` and `TestBridge_AHealthyReadTakenDuringTheAttemptIsReusedWithoutASecondQuery`. The other sites pass `time.Now()` (one-off probes), and the observer passes the stall's start.
- **A caller that stops waiting is never evidence.** The query runs detached from the failing caller's context and is bounded only by its timeout. A caller whose context ends gets `unknown` at once; the query lands for everyone else. A phase that ends during a stall, or an attempt's deadline, no longer records "auth, install or network" for the TTL (delta re-review, 2026-10-07; [internal-usageprobe](internal-usageprobe.md)). The detached query has one orphan window. If the process exits while a query is still booting or reading, its usage REPL (`evolve-recipe-…-pid<N>-…`) is left on the bridge socket, because `captureControl`'s deferred kill never runs. The crash-recovery liveness GC (`swarm.ExecReapOrphans`, run by the loop's `gcOrphanSessions` and by `evolve gc`) kills it once that creator PID is dead. The registry-based `sessionreaper` does not see it, because the query's workspace is `.evolve/usage-evidence`, not a run directory. To keep the window small, the decorator and the stall observer start no query once their context has ended (`TestBridge_ACancelledLaunchQueriesNothing`, `TestPhaseStallSignal_AStallReportedAfterThePhaseEndedStartsNoUsageQuery`).
- **What a burst of failures costs** (corrected 2026-10-07: round 1 claimed one query per CLI per TTL per process, which held only for a CLI whose screen does not read healthy).
  - Each query is bounded by `cli_health.usage_evidence_timeout_s` (default 120 s). Concurrent failures of one CLI in a process share one query, and a query for one CLI never waits on another's.
  - A read that rules nothing out is reused for `cli_health.usage_evidence_ttl_s` (default 600 s), in memory and through `.evolve/usage-windows.json`, so lanes and the pre-wave probe share it. That covers a failed or timed-out query, a screen with no window for the family, and an `exhausted` read until its latest reset. A down, drained or unreadable CLI is therefore queried at most once per TTL per process, and only one query in a TTL can take the full timeout.
  - A CLI whose screen reads `healthy` is queried again for each failing attempt that started after the last read. That costs one usage round trip per failed attempt, which answered last time. **Decision: not bounded further.** A healthy read from before the failure can neither verify nor rule out its cause, and the fresh read is what sets an exhausted family's bench to the screen's reset. Pinned in both directions by `TestEvidence_AnObservationOlderThanTheFailureIsNotEvidenceForIt` and `TestEvidence_AFailedQueryReadBeforeTheFailureIsStillReusedSoADownCLIIsNotStormed`.
  - The e2e fixture projects set `usage_evidence_timeout_s: 1` (`writeProjectPolicy` in `cmd/evolve`). Their fake CLIs show no usage window, so a query's answer is never needed there. The first measurement showed the timeout did not bound the query: the recipe adapter's boot wait polled its full 60 s deadline after the context ended, and each of the six queries took 62 s. The boot wait now honours the context ([internal-bridge](internal-bridge.md), *CLI control adapter*), so the configured timeout bounds the production query. Measured on the `cmd/evolve` e2e run (2026-10-07): 65 `Explain` calls, 6 real queries at about 2 s each (12 s in all) and 59 reused. The reviewer had measured 8 queries at 5 to 8 s (about 49 s), and the first cut 6 queries at 62 s.

## Sites

| Site | Wired | How |
|---|---|---|
| Boundary CLI updater, a failed `doctor live` (`internal/cliupdate`) | yes | `Seams.Explain` decides the result: `quota-exhausted`, `boot-timeout` with the verdict appended, or `skipped` explained by the verdict. "Counts as unsubscribed" is no longer inferred. |
| Preflight `bridge-boot`, a failed boot (`internal/looppreflight`) | yes | `Options.UsageEvidence` adds a `usage:` line to the halt detail. The check still halts. |
| Bridge launch failures before the fallback (exit 80, 81, 85, 86 and any other non-zero but 127), for both chain walkers | yes | The `Wrap` decorator at `cmd/evolve` `wireOrchestratorDeps`. |
| `LIVENESS_PHASE_STALLED`, a pane stall (`internal/adapters/observer`) | yes, as evidence only | `CoreAdapter.UsageEvidence`, read by the adapter's own `phaseStallSignal` and `reportStallUsage` methods. A stdout stall has no known CLI and is left alone. |
| `evolve doctor live <driver>`, failed (`internal/cli/opscmd`) | yes, read-only | It prints the verdict and windows on stderr, and `--json` adds `usage`. It never benches or records. |
| The boundary updater's smoke after an update | left alone | A smoke failure halts the wave as a broken CLI. Whether verified quota exhaustion should turn that halt into a warning is a separate decision. |
| `evolve doctor boot` | left alone | It boots without a prompt, and a quota wall does not stop a boot. |

## Invariants

- **Every failure quota could explain is explained once, recorded and signalled; a success, a missing binary or an interrupt is not.** Pinned by `TestBridge_EveryFailureQuotaCouldExplainIsExplainedRecordedAndSignalled`, `TestBridge_ASuccessOrAMissingBinaryIsNotQuotaEvidence` and `TestBridge_ACancelledLaunchQueriesNothing`.
- **The decorator hides nothing of the inner bridge.** Pinned by `TestBridge_ForwardsTheInnerSignalCenterAndItsWiringProof`.
- **The code is registered and its severity follows the verdict.** Pinned by `TestReport_AnUnavailableVerdictIsAWarningAndNoWorkspaceIsOnlyASignal`.
- **The production constructor reads the binary's screen, judges the routing family, benches an exhausted one and honours the configured timeout and TTL.** Pinned by `TestNew_ReadsTheFailingDriversBinaryScreenAndJudgesItsRoutingFamily` and `TestNew_TheTimeoutAndTTLComeFromTheCLIHealthBlock`.
- **The composition root shares one evidence between the bridge and the observer.** Pinned by `TestWithUsageEvidence_WrapsTheBridgeOnlyWhenThereIsAnExplainer` and `TestWireOrchestratorDeps_TheObserverAndTheBridgeShareOneUsageEvidence` (`cmd/evolve`). `TestMain` there sets `usageEvidenceFn` to nil, so no test boots a real CLI for a query.
