# internal/modelquery

## Purpose

`internal/modelquery` is the live acquisition layer for the model catalog: it asks each installed LLM CLI which models it offers, has an LLM call classify those ids into the canonical tiers, and assembles a fresh `modelcatalog.Catalog`. `modelcatalog` stays a dependency-free leaf because live CLI dispatch reaches this package only through the `Lister`, `ModelCapturer` and `PromptDispatcher` seams, which the composition root in `cmd/evolve` wires. The feature narrative is in [model discovery and catalog](../model-discovery-and-catalog.md).

## Design

- Per CLI, `liveTiers` runs List → family filter → reuse gate → Classify → `PromoteLatest` → `CompleteTiers`. The classifier keeps the qualitative decision (which model line serves a tier); Go keeps the numeric one (the newest version of that line, alias-aware per the CLI's `FreshnessPolicy`); completion fills any tier the reply omitted.
- A per-CLI live failure (listing fails, the list is empty, the family filter empties it, the classifier errors, or it maps no tier) logs one WARN naming the reason and falls back to that CLI's detect-derived tier map, so a refresh never aborts wholesale and never blocks a cycle. `liveTiers` returns the failure as an error and `snapshotFor` records its text as the snapshot's `FallbackReason`, which `modelcatalog` persists as the entry's `fallback_reason`, so the catalog says why an entry is not live. `Refresh` errors only when `Lister` or `Classifier` is nil; a CLI with neither live data nor a fallback is skipped.
- `ChainClassifier` is the production `Classifier`. It holds the ready CLIs in the order the composition root gives (`pickClassifierCLI` in `cmd/evolve`) and runs a `CLIClassifier` on each in turn: a launch error, a reply with no JSON object, or a reply that maps no tier to an offered id is logged with the CLI and the reason (`classifier cli=<cli> failed: …`) and the next CLI is tried. The first success wins; a cancelled context stops the chain before the next launch; an exhausted chain returns one error naming every CLI and every reason. A single picked CLI made one dead CLI decide every family's tiers: on 2026-10-05 a codex with no subscription but a stale auth file was the classifier, its launch failed, and every family fell back to its detect map.
- `DefaultRouter` (through `routerWith`, which a test gives a fake `Runner`) is the single production registry of which CLI is enumerated how. `agy` and `agy-claude` share one `onceLister` over `AgyLister`: both catalog entries come from one `agy models` run per refresh, the first call's result (models or error) serving both, and each key's `catalog.allowed_families` filter (`gemini`, `claude`) splits the listing (pinned by `TestRefresh_OneAgyListingYieldsAGeminiEntryAndAClaudeEntry`, `TestDefaultRouter_AgyAndAgyClaudeShareOneLister`, `TestOnceLister_AFailedListingFailsEveryEntryThatSharesIt`).
- A CLI registered in `DefaultRouter` has a non-interactive listing that is more faithful than its picker (ollama: `ollama list`; agy: `agy models`); every other CLI falls through to `RecipeLister`, which drives the `/model` picker. There is one registry because a CLI added to one copy of a duplicated registry but not the other falls through silently to the picker and yields plausible but wrong model names.
- agy is listed with `agy models`, never its picker. The picker renders the model list and the reasoning effort as two separate controls, so a pane capture yields bare family names ("Gemini 3.1 Pro") that are not valid `--model` arguments. agy needs the combined display name ("Gemini 3.8 Flash (Low)") exactly as `agy models` prints it; given a bare family name it warns once and silently serves a different model for the whole session.
- `parseAgyModels` takes the display-name column, not the id column, because the rest of the catalog (`tier_fallbacks`, the manifest `model_tier_map`) speaks display names and agy accepts either; mixing the two vocabularies in one catalog hides drift. A row counts only when its id column is a lowercase, space-free token (`agyModelID`), so a header row or banner can never become a model.
- `AgyLister.List` returns an error, not an empty slice, when it parses zero models. Downstream treats both the same, but the error names the CLI that could not be enumerated instead of reading as "agy offers nothing".
- `RecipeLister` parses a captured `/model` pane with a per-CLI strategy (`pickerParsers`, overridable per CLI through `RecipeLister.Parsers`): codex takes the first token after the list number; claude's picker labels are aliases, so the family word (`opus|sonnet|haiku`, what `claude --model` accepts) is extracted and lower-cased; agy's flat picker is bounded by the "Switch Model" header and the keyboard-hint footer, with the selection marker and "(current)" tag stripped and the effort parenthetical kept.
- `Runner` returns combined stdout and stderr because CLI output frames the useful content with header and footer lines on an unspecified stream; the JSON extractor tolerates the surrounding noise.
- The production `PromptDispatcher` lives in `cmd/evolve` and routes through `bridge.Engine.Launch` (sandboxed, liveness-probed, `cli_fallback`-aware), which keeps live dispatch out of the unit-tested classifier. The seam is named generically so any one-shot model-reaching helper in this package can reuse it.
- `Classify` scans every balanced JSON object in the reply and takes the first that yields a non-empty valid tier map. CLIs such as `codex exec` echo the prompt, including its literal JSON template, before the answer; the echoed template maps every tier to `<id>`, which is never an offered id, so it sanitizes to empty and is skipped. `jsonObjects` is brace-, string- and escape-aware.
- `sanitizeTierMap` keeps only canonical tiers whose model is one of the offered ids, so a hallucinated or empty model is dropped per tier and the caller's fallback covers it.
- The classification prompt is deterministic, so identical inputs cache the same way at the LLM layer. Its tier block and JSON template are generated from `modelcatalog.CanonicalTiers`, never a hardcoded tier list, so a canonical tier can never be omitted from the prompt.
- `CompleteTiers` fills an omitted tier from the nearest present neighbour in `CanonicalTiers` order, preferring the more capable side on ties, because a deep task degrades better to the frontier model than to a mid one. It only reuses ids the sanitizer already validated, and an empty map stays empty for the caller's fallback path. Completion is what keeps the reuse gate's full-coverage condition satisfiable.
- The family filter restricts a CLI's candidates to its `policy.json` `catalog.allowed_families` before classification, because cross-family coverage belongs to the `cli_fallback` chain, never to a CLI's own tier map. `FamilyOf` tests families in a fixed order with case-insensitive substring tokens, so a display name classifies the same as a bare id; an unknown or local id classifies as "". Under a constraint an unknown id is dropped; an empty allow-list is a passthrough.
- **One family table, two readings** (2026-10-07). `FamiliesIn(label)` names every family whose tokens a label mentions, in table order; `FamilyOf` is its first entry. The bridge's launch-time model check needs the whole list, because a footer naming two families (`Gemini 3.1 Pro (Claude Opus 5.5 unavailable)`) is no evidence of either, while `FamilyOf` would call it Claude. Pinned by `TestFamiliesIn_NamesEveryFamilyALabelMentionsInTableOrder`.
- `LineageKey` is the version-free identity of an id: lowercased, the first date run and the version token removed, separator runs collapsed to "-". Two ids share a key iff they are the same model line at different versions or dated snapshots, and are therefore substitutable; different keys are different capability classes. The key and the `NewestInLineage` comparator strip the same version token and share one date strip (`withoutDate`), so the bucket key and the compared version never disagree about which digits are a date.
- `dateRun` is anchored on a `19xx`/`20xx` year so it never fires on capability-bearing digits such as `:8b`, `:70b`, `32b` or a short dotted version.
- `NewestInLineage` compares versions component-wise numerically, so "opus-4.10" beats "opus-4.9", and returns the full id unmodified. It reads the version with the date removed, lets a versioned id beat an unversioned one, orders equal versions by calendar date only when both are dated, and otherwise keeps the first-listed id. `newer` is a strict partial order, so a scan's winner is either its starting id or strictly newer than it.
- `FreshnessPolicy` is data declared per CLI in the bridge manifest (`model_freshness`) and threaded in as a plain value by the composition root; modelquery never imports `bridge`, and no CLI name appears in a conditional in this package. The zero value means "newest concrete version". `PreferAlias` marks a CLI that resolves a bare alias ("opus") to the family's newest release at launch, where the alias is fresher than any concrete id a catalog could cache. The alias rule sits in front of `NewestInLineage` rather than modifying it: versioned-beats-unversioned is right for enumerating CLIs and backwards only for alias-resolving ones.
- `PromoteLatest` upgrades each selected tier model to the freshest member of its own lineage bucket. It puts the classifier's pick first (`incumbentFirst`), so a tie never displaces the selection and only a strictly newer member replaces it; a selection absent from the candidates is kept verbatim. It returns a new map and never mutates its inputs.
- `Fingerprint` hashes the decision inputs (`decisionVersion`, CLI, candidates, freshness policy, tier vocabulary) into `CLIEntry.CandidatesHash` as `sha256:<hex>`. Every field and list member is length-prefixed and NUL-separated, because agy ids contain spaces and parentheses and a bare separator join would be ambiguous. Candidates and tiers are sorted on copies: pane order is presentation, not identity.
- The reuse gate keeps an unchanged offering's prior tier map with zero classifier calls, which removes tier flap on identical inputs.
- `EffortLister` discovers each CLI's reasoning-effort ladder. An unmapped rung is not a no-op: `bridge.realizeScalar` drops an effort value missing from a manifest's values table, so the phase launches with no effort flag, silently weaker than intended. Discovering the ladder turns that silence into a catalog diff.
- `HelpEffortLister` parses the enum out of `<cli> --help`. claude wraps its enum onto a continuation line separated by ", "; agy keeps it inline separated by "|". The parser accumulates the `--effort` flag's block across continuation lines and stops at the next flag-shaped line or a blank, so a neighbouring flag's parenthetical (claude's `--sandbox` values) is never read as a ladder.
- An enum is the first parenthetical in that block with at least two separator-delimited tokens, all of them bare lowercase words (`effortToken`). The match is all-or-nothing: a partial match means the parenthetical is prose, and half a ladder would silently narrow the discovered range.
- codex is absent from `DefaultEffortListers` on purpose: its `--help` documents no reasoning effort (its rungs live behind the `/model` picker's "More reasoning..." submenu), so a help parse would return an empty ladder that reads as "codex has no dial". codex's ladder comes from the manifest it declares, and the verify step proves those values are real.
- Effort discovery is enrichment. A discovery failure is logged and the refresh continues with no ladder recorded, since models are the payload. The log keeps the two silent outcomes distinct: "no lister" means the ladder is not discoverable by us, an error means we asked and could not tell.
- **The default runner takes its environment from the composition root.** `UseProcessEnv(env)` installs a per-binary environment source that `defaultRunner` sets on every exec (`nil`, the default, inherits the process environment); `cmd/evolve` installs `bridge.ProcessEnv`, so `agy models` and `agy --help` run with the agy manifest's `default_env` (`AGY_CLI_DISABLE_AUTO_UPDATE=1`) and never self-update agy at cycle start, inside a wave. The package still never imports `bridge`. Pinned by `TestAgyLister_TheDefaultRunnerExecsAgyModelsWithTheInjectedProcessEnv`, `TestHelpEffortLister_TheDefaultRunnerExecsAgyHelpWithTheInjectedProcessEnv` and `TestUseProcessEnv_WithoutASourceTheDefaultRunnerInheritsTheProcessEnv`.
- `ollama list`, `agy models` and `<cli> --help` are metadata-only: they reach no model and are passed no prompt or stdin, so they run through the package `Runner` and are exempt from the rule that every model-reaching call goes through the `PromptDispatcher`/bridge seam.

## Invariants

- `decisionVersion` must be bumped by hand whenever `buildClassifyPrompt`, the tier-vocabulary semantics, or the `PromoteLatest`/`CompleteTiers` algorithm changes; otherwise an algorithm fix is silently reused away for every CLI whose candidate list is unchanged. `TestDecisionVersion_PinnedToAlgorithmSurface` hashes the raw bytes of `classifier.go`, `latest.go`, `complete.go`, `lineage.go` and `newestwins.go` and fails on any edit, comments included, until the editor updates `decisionSurfacePin` (and bumps `decisionVersion` when semantics changed).
- Reuse requires all three conditions, not just a hash match: the hash is non-empty and equal, the prior entry is live-sourced (a detect entry is never laundered into an authoritative one), and the prior covers every canonical tier (a tier-incomplete prior reclassifies once instead of staying sticky). Pinned by `TestRefresh_UnchangedOfferingSkipsClassifier`, `TestRefresh_ChangedOfferingClassifies`, `TestRefresh_ReuseRequiresLiveAndFullCoverage` and `TestRefresh_PromotesCompletesAndStamps`.
- Only live-queried entries carry `Source: live`, the one source `modelcatalog.DispatchModel` honours; a detect fallback is informational only (pinned by `TestRefreshHappyPath`, `TestRefreshListFailureFallsBack`, `TestRefreshEmptyModelListFallsBack`).
- agy and ollama are routed off the picker, codex is not registered, and `Default` stays set (pinned by `TestDefaultRouter_RoutesAgyAndOllamaOffThePicker`). Every agy model name keeps its effort or capability suffix (pinned by `TestAgyLister_KeepsTheEffortSuffixThatMakesTheNameValid`); header and banner rows never become models (pinned by `TestAgyLister_HeaderAndBannerRowsNeverBecomeModels`); a failed `agy models` is an error, not an empty list (pinned by `TestAgyLister_PropagatesFailure`).
- `CLIClassifier` never shells out: a nil `Dispatcher` is an error, and `classifier.go` may not reference `defaultRunner`, `classifierArgv` or `Runner` (pinned by `TestCLIClassifierClassify_NilDispatcherErrorsNeverShellsOut` and the AST guard `TestGuard_ClassifierHasNoDirectModelExec`). Pre-dispatch guards reject before the dispatcher is called (pinned by `TestCLIClassifierGuards`).
- A prompt-echoed JSON template is skipped in favour of the real answer (pinned by `TestCLIClassifierClassify_SkipsPromptEcho`).
- A failing classifier CLI never decides the tiers while another ready CLI can: a launch failure, a no-JSON reply and an unmapped reply each fall through to the next CLI and are logged with the CLI (pinned by `TestChainClassifier_LaunchFailureFallsThroughToTheNextReadyCLI`, `TestChainClassifier_UnusableRepliesFallThroughToo`); the exhausted chain names every failure, an empty chain is an error, and a cancelled context launches nothing (pinned by `TestChainClassifier_ExhaustedChainNamesEveryFailure`, `TestChainClassifier_EmptyChainIsAnError`, `TestChainClassifier_CancelledContextStopsBeforeDispatch`); through `Refresh`, the second CLI's answer lands as a live entry (pinned by `TestRefresh_ChainClassifierRecoversLiveTiersWhenTheFirstCLIFails`).
- Every detect fallback carries the live failure as its `FallbackReason`, and a live entry carries none (pinned by `TestRefresh_DetectFallbackRecordsWhyTheLiveQueryFailed`, `TestRefresh_LiveEntryCarriesNoFallbackReason`).
- `tierBriefs` carries a brief for every canonical tier and the prompt carries a JSON slot for each (pinned by `TestBuildClassifyPrompt_CoversEveryCanonicalTier`).
- The metadata listers pass no prompt argument and no stdin (pinned by `TestOllamaListerReachesNoModel` and the stdin assertion in `TestAgyLister_KeepsTheEffortSuffixThatMakesTheNameValid`). `ollama.go` must keep a comment matching `metadata|no model|not model-reaching`, because `TestOllamaListMetadataExceptionDocumented` reads the source for it.
- `Runner` returns combined stdout and stderr (pinned by `TestRunner_CapturesCombinedOutput`).
- Different lineage keys are never substituted: Flash never replaces Pro, `-mini` never stands in for the base line, size suffixes survive the date strip, and dated snapshots of one line share a key (pinned by `TestLineageKey_SeparatesCapabilityClasses`, `TestLineageKey_RealCatalogIDs`). Buckets keep input order, which the first-listed tie-break depends on (pinned by `TestGroupByLineage_OrderPreservingBuckets`).
- A date never outranks a version, and a tie with no date on one side keeps the selection in either candidate order (pinned by `TestNewestInLineage_VersionDecidesBeforeDate`, `TestPromoteLatest_MixedDatedBucketsNeverDowngrade`, `TestPromoteLatest_DatedSnapshotPromotion_Repro`).
- The alias wins over a concrete sibling under `PreferAlias`, and with no alias in the bucket the newest concrete version wins (pinned by `TestFreshest_AliasPreferred`).
- Candidates reach the classifier already filtered to the CLI's allowed families, and a CLI with no allow-list entry is unfiltered (pinned by `TestRefreshFamilyFilterAppliedBeforeClassify`, `TestRefreshNoAllowedFamiliesIsPassthrough`). A list with no allowed-family model filters to empty, never a passthrough (pinned by `TestFilterByFamily_NoGeminiYieldsEmptyNotPassthrough`).
- The `--effort` flag matches as a whole token, so a neighbouring `--effort-budget` cannot capture the scan (pinned by `TestHelpEffortLister_EffortPrefixedNeighbourDoesNotCaptureTheScan`); only a dash run followed by a letter ends the flag's block, so a bullet or prose such as "-1 disables it" does not truncate it (pinned by `TestHelpEffortLister_DashLeadingProseDoesNotTruncateTheBlock`).
- A CLI without an effort flag yields an empty ladder and no error; a failed `--help` is an error (pinned by `TestHelpEffortLister_NoEffortFlagIsEmptyNotError`, `TestHelpEffortLister_PropagatesRunFailure`). claude and agy are registered for help discovery and codex is not (pinned by `TestDefaultEffortListers_CodexIsNotHelpDiscoverable`).
- A discovered ladder reaches the catalog, a CLI with no lister records none, and a discovery failure never sinks the refresh (pinned by `TestRefresh_RecordsDiscoveredEffortLadder`, `TestRefresh_EffortDiscoveryFailureDoesNotSinkTheRefresh`).

## Findings

- Fixture-based unit tests only prove a parser handles what a CLI printed when the fixture was captured. `effort_live_test.go` (`-tags integration`) asks the real binaries, and `TestLive_CodexStillHidesItsLadderFromHelp` fails the day codex starts publishing its ladder in `--help`. CI provisions no agent CLIs, so there every case SKIPs; a green CI run is not evidence that a live ladder still matches. They are an operator and developer guard, run where the CLIs are installed.
- `TestLive_DiscoveredLadderReachesTheCatalog` is the live wiring proof: the real `DefaultEffortListers` registry and the real CLI, with a fake model lister so no classifier call and no quota is spent.
- Fixture provenance: `realAgyModelsOutput` and `realAgyHelp` are verbatim from agy 1.1.22, `realClaudeHelp` from Claude Code v2.1.248, and the picker panes from codex v0.135.0, agy 1.0.3 and Claude Code v2.1.159.
- `TestOllamaListMetadataExceptionDocumented` reads `ollama.go` for a comment, which conflicts with the zero-comment convention; the behaviour that comment describes is already pinned by `TestOllamaListerReachesNoModel`.
- The Discovery section of [model discovery and catalog](../model-discovery-and-catalog.md) listed agy under `RecipeLister` and the picker while production routed agy to `AgyLister` (`DefaultRouter`); corrected 2026-10-05.
- Until 2026-10-05 `evolve models refresh --source live` printed `Refreshed model catalog (source: live /model (detect fallback))` and exited 0 even when every CLI had fallen back, so a refresh that learned nothing read as success. The fallback reason now rides each catalog entry and the CLI verb exits 1 when no CLI was classified live ([cmd/evolve](cmd-evolve.md)).
