# internal/phaseobserver

> The engine split, its test and mutant map, the preserved quirks and the clock-read sites: [decomposition unit 12](../decomposition/12-phaseobserver.md). The stall policy: [ADR-0044](../adr/0044-unified-phase-recovery-protocol.md) C4 and [internal/recovery](internal-recovery.md). The observer `evolve loop` runs per phase: [internal/adapters/observer](internal-adapters-observer.md). The original bash design and its event schema: [phase-observer.md](../phase-observer.md). This page keeps the package-level detail those do not.

## Purpose

`internal/phaseobserver` hosts the standalone `evolve phase-observer` subcommand, which `phasecmd.RunPhaseObserver` calls. `Run` validates a `Config`, applies defaults, builds one `observerengine.Engine` and drives it with a real ticker until shutdown. The engine owns the log tail, the stream-json decoding, the stall rules, the incident response and both output files. This is not the per-phase observer of `evolve loop`; that one is `internal/adapters/observer`.

## Design

- **Strangler seam.** Validation, defaults and the ticker, stop-timer and shutdown select loop (`pollLoop`) stay here. Everything one tick does lives in `internal/observerengine`. `Run` keeps its name and signature for phasecmd and the tests that call it by name.
- **One construction, one projection.** `wiredEngine` is the only non-test call of the engine's constructor in the module, and `settingsOf` is the only projection from `Config` onto the engine's `Settings`. `settingsOf` also binds the observer's own pid.
- **The nudge goes to the bridge inbox.** The engine's `Nudge` port is an `inbox.Append` with kind `nudge` and source `observer`, keyed on the agent positional rather than the phase. `inbox.Append` reads the injected clock to stamp the envelope, so it is one of the clock reads the count-stepping tests budget for.
- **Output files are named by agent.** `<agent>-observer-events.ndjson` is append-only, one envelope per line. `<agent>-observer-report.json` is written atomically at shutdown. A non-empty `stdoutPath` overrides the tailed log; an empty one keeps the engine's `<agent>-stdout.log`.
- **Nil seams are Null Objects.** A nil `StallPolicy` keeps the legacy branch: Enforce sends SIGTERM and the INCIDENT envelope carries no `action`. A nil `ProcessAlive` turns the process probe off. A nil `Signals` keeps the engine's own faults silent. phasecmd wires all three in production (`resolveStallPolicy`, `DefaultProcessAlive` and its console Center).
- **A stall policy outranks Enforce.** With a policy injected, `extend` and `escalate` suppress the kill even under Enforce, and `kill_retry` kills even without it. The decision and its reason land in the INCIDENT envelope as `action` and `action_reason`.
- **Two stall clocks.** `StallS` resets on any valid stream-json line, so an agent that only streams assistant text never trips it. `MaxNoProgressS` resets only on `tool_use` and `tool_result` and fires `stuck_no_progress`. Zero disables it.
- **Unported rules.** The bash observer's `infinite_loop`, `error_spike`, `cost_anomaly` and `rate_limit` rules were never ported. `LoopN`, `LoopWindowS`, `ErrorRate`, `CostSigma`, `ThrottleN` and `CycleState` stay on `Config` only for the literal shape callers build; nothing reads them. Retiring them is the decomposition's question 5 and follow-up F5.
- **The stop arm costs nothing per tick.** `stopChan` returns a nil channel for a nil timer, and a nil channel's select arm never fires. It is resolved once, before the loop. With `StopAfterMS` set, the ticker runs at a quarter of it, so a test can tail a log and stop in well under a second.

## Invariants

- **One goroutine drives the engine.** `Run` builds the engine locally and never returns or shares it, and only the poll loop calls it. That is why the engine has no locks. The code keeps a one-line why on `Run`.
- **Host defaults agree with policy.** `withDefaults` and policy's compiled `ObserverConfig` both give PollS 5 and StallS 600, so the subcommand and a bare `Run` never disagree on those. NudgeS is the named divergence: policy compiles 300, which phasecmd feeds in, so the subcommand nudges; a bare `Run` leaves 0 and never nudges. EOFGraceS 10 is host-only, since policy leaves it 0. Pinned by `TestWithDefaults_MatchPolicyCompiledDefaults`, which lives in the external `phaseobserver_test` package so it can import `policy` without an import cycle.
- **`ProcessAlive` has no default.** Fixture Configs carry fake pgids, and a defaulted probe would read them as dead and fire `process_dead`. The probe also skips a pgid of 0 or less. The code keeps a one-line why on the field and on `withDefaults`.
- **EPERM counts as dead.** `DefaultProcessAlive` treats any error from `kill(-pgid, 0)` as a dead group. That is safe only because the observer and the agent run as the same UID, so a live group never answers EPERM. Cross-UID subagents would need ESRCH and EPERM told apart. The code keeps a one-line why.
- **A dead process fires once.** `process_dead` is emitted once per run, not once per tick, and the chain policy resolves it to `kill_retry` whatever the idle budgets say. Pinned by `TestRun_DeadProcessFiresOnceAndKills`.
- **The report never changes the exit code.** The engine reports a failed report write as `OBSERVER_REPORT_WRITE_FAILED`, and `Run` still returns `ExitOK`. Pinned by `TestRun_WriteReportFailure_WarnsButReturnsOK`.
- **Validation lines are byte-stable.** The three `[phase-observer]` lines and exit 10 are part of the subcommand's contract. Pinned verbatim by `TestRun_ValidationLinesAreVerbatim`.
- **Only the two known scopes run stall rules.** Any other `Scope` runs none, while `observer_started` still records the value. The process probe is not scope-gated. Pinned by `TestRun_UnknownScopeRunsNoRules`.
- **Every clock read is load-bearing.** The count-stepping tests jump the clock after a fixed number of `Now` calls. `TestGolden_IdleScenarioSequence` makes exactly 20 reads: construction (1) and `observer_started` (2); tick 1 reads once per ingested line (3-6), then for the idle rule (7), the no-progress rule (8) and the heartbeat (9); tick 2, at +400 s, reads for the idle rule (10), `inbox.Append` (11), the `soft_stall_nudge` emit (12), no-progress (13) and the heartbeat (14); tick 3, at +700 s, reads for the idle rule (15), the INCIDENT emit (16), no-progress (17) and the heartbeat (18, where the clock closes `ShutdownSig`); then the shutdown (19) and the report (20). One extra or missing read shifts the shutdown and every later `ts`. `observerengine`'s replay of the scenario must match it call for call.
- **Emits can share an id.** Under a frozen clock two emits in one tick share an `id`, because the id's counter is the line count, not an emit sequence. The sequence golden records this.

## Findings

- **cycles 274/277** (R3.4): a wedged shell read as alive for more than 25 minutes after the CLI died, because pane and log echo are not liveness. That added `ProcessAlive`, `DefaultProcessAlive` and the `process_dead` INCIDENT. See the [internal/recovery](internal-recovery.md) Findings.
- **cycle-262** ([ADR-0044](../adr/0044-unified-phase-recovery-protocol.md) C4): detection and action were welded into one inline Enforce-then-SIGTERM branch, so recovery policy could not change without editing the detector. The `StallPolicy` seam split them. It shipped nil by default and behavior-neutral, pinned by `TestRun_StallPolicyNil_EnvelopeUnenriched`.
- **Workstream E1** ([ADR-0030](../adr/0030-phase-observer-autospawn-in-evolve-loop.md)): an agent that babbles assistant text forever never tripped `StallS`. `MaxNoProgressS` added the progress-only clock.
- **ADR-0103 unit 12**: the 601-line `Run` became this seam over `observerengine`. The tick order, the rule invariants and the idle-scenario sequence were pinned by mutation-proven tests on the base before the move, and those tests stay here as the regression net. `ExitFatal` had no consumer and was deleted.
- **Allocation in the stop arm**: the poll loop once built a fresh channel on every select iteration when no stop timer was set. `stopChan` replaced it, pinned by `TestStopChan_ZeroAlloc`.
- **A stale scope promise**: an earlier `Scope` doc said cycle scope runs only the no-output rule. That was never implemented; both known scopes run every rule, and any other value runs none (decomposition §8, preserved quirks).
