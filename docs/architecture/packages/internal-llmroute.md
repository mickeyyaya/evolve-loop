## Purpose

`internal/llmroute` resolves a phase's dispatch decision in one place: the ordered CLI chain, the exit codes that advance it, the concrete model and the tier fallback chain, all in one `Plan`. It also owns the two walks over a plan (`Dispatch` over CLIs, `DispatchTiered` over tiers × CLIs) and the pure reorderings a caller applies before walking: probe, bench, universal fallback and soft overlay.

## Design

- **One resolver.** Before this package the runner stitched the decision together from two paths: `runner.resolveCLIChain` picked the chain, and `resolvellm.Resolve` (called only to expand `"auto"`) computed a CLI that the runner then discarded. `Resolve` folds both into one `Plan`. The advisor reuses the same seam when it mints a phase.
- **Precedence.**
  - A `policy.Pin` overrides everything below it.
  - CLI primary: `EVOLVE_<AGENT>_CLI` > `EVOLVE_CLI` > `profile.cli` > `claude-tmux`.
  - CLI chain: the primary, then `profile.cli_fallback`, trimmed, deduped and in declared order.
  - Triggers: `profile.cli_fallback_on_exit`, else the default set below.
  - Model: `EVOLVE_<AGENT>_MODEL` > `profile.model_tier_default` > the phase's default model. A result of `"auto"` is expanded through the injected `AutoModel`, and stays `"auto"` when the expander declines.
  - Tiers: `TierChain(model, envelope.Min)`.
- **Leaf package.** It imports `envchain`, `policy`, `profiles` and the standard library only, never the runner, `resolvellm`, `core` or `bridge`. `resolvellm` stays an independent API that the runner bridges in through the `AutoModel` closure, so `"auto"` expands exactly as it did before this package existed.
- **`AutoModel` is keyed by phase; env and profile lookups are keyed by agent.** The asymmetry comes from the removed `llm_config.json` layer, which was phase-keyed. `TestAutoModel_NamedSeamExpandsAuto` and `TestResolve_AutoExpandedViaSeam` pin it.
- **Mirrored tables instead of a `bridge` import.** `defaultFallbackOnExit` mirrors `bridge/exitcodes.go` as integer literals, and `cliBinaryFor` mirrors `bridge.doctorBinaryFor`. Inside this package `cliBinaryFor` is the one list of registered driver names (`KnownDriver`, `Family`, `defaultDriverForFamily`, `Probe`).
- **The default trigger set** is 80 (a `*-tmux` REPL never showed its prompt), 81 (artifact timeout), 85 (an unhandled prompt, including provider rate-limit and quota escalations; the escalation report is written before the chain advances), 124 (coreutils `timeout(1)`, defensive) and 127 (binary not on `PATH`). Operators extend it per agent, for example with 2 (the safety gate), or shrink it to `[80, 127]` for a strict posture. Any other exit hard-fails.
- **Copy-struct convention.** `Probe`, `ApplyBench`, `ApplyDriverBench`, `ApplyUniversalFallback` and `ApplySoftOverlay` copy the input `Plan` and overwrite only the fields they own, so a new `Plan` field is carried through without edits.
- **Demote, never drop.** `Probe` moves a candidate whose binary is missing to the chain end, which saves a 60-second boot timeout. It keeps the candidate because a CLI can be installed but not yet on `PATH` at probe time, and the bridge's launch may still resolve it. An unknown driver name keeps its position.
- **Two bench scopes.** `ApplyBench` is keyed by family (`Family(cli)`), because a transient outage such as a quota wall or an expired login hits every transport of a family. `ApplyDriverBench` is keyed by the full driver name, because a boot-timeout bench is transport-specific: benching `codex-tmux` does not bench `codex`.
- **`ChainFor` takes an already-chosen primary.** It never re-derives one through `resolvePrimary`, which reads `profile.cli` and would undo a composition-root swap away from a benched family. `Resolve` and `ChainFor` share `buildCandidates` and differ only in whether `prof.CLI` is excluded (see policy-config.md).
- **Pin versus overlay.** A pin is absolute and applied inside `Resolve`. An `Overlay` is soft: it reorders the existing chain and never removes a candidate, so a benched or failing overlay CLI still falls back through the ordinary chain. `model_routing=auto` proposes; it never pins. An overlay tier replaces `Plan.Model`, and the bridge translates the tier to a concrete model later through the manifest's `ModelTierMap`.
- **Overlay CLI rungs.** `ApplySoftOverlay` resolves `ov.CLI` in order:
  1. an exact chain entry is promoted, because the chain was resolved for this phase and holds drivers it can run;
  2. a bare name (no hyphen) is a family selector and promotes the first same-family chain entry, whatever its transport, because chain order is the phase's resolved preference;
  3. otherwise the name is normalized like a pin (`defaultDriverForFamily`): a bare family the chain lacks gets its default driver, and a hyphen-qualified driver selector passes through as written.

  An explicit `claude-tmux` against a chain of `[claude-p]` therefore wins as written. An explicit transport request is never satisfied by promoting its opposite.
- **Tier × CLI walk.** `DispatchTiered` walks `Tiers` in the outer loop and `Candidates` in the inner one, and within a tier behaves exactly like `Dispatch`. `TierChain` steps down one `policy.TierRank` at a time and never below the envelope `Min`. An empty or unclassifiable `Min` means the universal `balanced` floor, the same floor as the router's `universalTierFloor`. An unclassifiable resolved tier, such as an exact model id, gets a single-element chain.
- **Universal-fallback filters.** `AllowedDiscovered` is the security gate: discovery may route a phase only to a family its `allowed_clis` permits (an empty list or `"all"` permits every family), so a per-phase allowlist is never bypassed by whatever happens to be installed. `ExcludeFamilies` applies the operator's family ban to the discovered tail only; a banned family may still be a configured primary. The runner's universal fallback and the bridge-chain decorator's plan resolver share `AllowedDiscovered`, and the decorator falls back to `DefaultTriggers` when a resolver hands it a plan with no triggers.

## Invariants

- **A non-trigger exit stops the walk.** A legitimate FAIL is never rerouted to another CLI, where it would pass for a CLI hiccup. Pinned by `TestDispatch_StopsOnNonTriggerExit`, `TestDispatch_NonTriggerBoundaryCodesNeverReroute` and `TestDispatchTiered_LegitimateFailStopsImmediately`.
- **An empty chain fails loudly.** `Dispatch` and `DispatchTiered` return an error for zero candidates, because a caller that checks only `Err` would read nil as a successful dispatch to no CLI. `buildCandidates` always returns at least the primary, so the guard is defensive. Pinned by `TestDispatch_EmptyCandidatesNeverCallsLaunchOrClaimsSuccess` and the `all-noise-fallback-collapses-to-primary` case.
- **Exhaustion returns the last error**, so the caller can degrade to its own backstop: the advisor's static spine, or the runner's FAIL classification. `TestDispatch_AllCandidatesFailReturnsLastError`.
- **Only exit 85 steps a tier down, and only when every attempt at that tier exited 85.** The other trigger exits are CLI problems, not tier availability, and a mixed 81/85 tier does not step down. The terminal quota error is therefore reachable only after the lowest tier is also drained, which is the precondition for the all-families-exhausted classification in `core/quota_exhaustion.go`. Every step-down calls `onStepDown`, so a downgrade is never silent. `TestDispatchTiered_NonQuotaExitsNeverStepTier`, `TestDispatchTiered_TerminalOnlyAfterLowestTierExhausted`, `TestDispatchTiered_StepsDownAfterQuotaExhaustedChain`.
- **A pin is absolute but keeps resilience.** `pin.CLI` replaces the primary, normalized from a bare family to `<family>-tmux` when that driver is registered, and the profile's fallback chain is still appended. `pin.Model` skips the env, profile and default chain and the `"auto"` expansion, so it never triggers a catalog lookup, and its tier chain is the pinned model alone: a pinned model never steps down. Validating the pin (`policy.ValidatePin`) and honoring `--bypass-policy` (pass a nil pin) are the caller's job. `TestResolve_PinCLIOverridesEnv`, `TestResolve_PinPreservesProfileFallbackChain`, `TestResolve_PinModelBypassesAutoExpand`, `TestResolve_PinBaseFamilyNormalizesToDefaultDriver`.
- **A soft overlay never shrinks the chain and never mutates its input.** `TestApplySoftOverlay_CLIPromotedToPrimaryChainPreserved`, `TestApplySoftOverlay_PureDoesNotMutateInput`.
- **An overlay never changes the transport of a name the chain already holds**, because the exact-entry and family rungs run before normalization. `TestApplySoftOverlay_PromotesAnExistingCandidateWithoutRewritingItsTransport`, `TestApplySoftOverlay_BareFamilyDoesNotCrossTransportWhenTheChainHoldsANonDefaultDriver`, `TestApplySoftOverlay_DriverQualifiedOverlayWinsOverSameFamilyChainEntry`, `TestApplySoftOverlay_BareFamilyPromotesFirstSameFamilyEntry`.
- **An overlay tier rebuilds `Tiers`, floored at the phase's own envelope.** The dispatch closure launches at `Tiers[0]`, so a stale `Tiers` would ignore the overlay. The router's clamp raises only the starting tier to `Min` and does not carry `Min` into the fallback floor, so the overlay rebuilds the chain from `envelopeMin(prof)`, the floor `Resolve` uses. Without that, an overlaid phase declaring `min: deep` could step below its quality floor under a full quota wall. `TestApplySoftOverlay_TierChainHonorsPhaseEnvelopeFloor`.
- **Bench is advice, never a veto.** When every candidate is benched, the chain runs least-recently-benched first and dispatch proceeds; the caller logs loudly. `TestApplyBenchAllBenchedLeastRecentFirst`.
- **`Probe` keeps the order when every binary is missing**, so the classifier still sees a real `ExitMissingBinary`. `TestProbe_AllMissingKeepsOrder`.
- **The universal tail never outranks configuration and never hides absence.** Discovered CLIs are appended after the configured chain and deduped against it, and an empty discovery leaves the plan untouched. The `lookPath` parameter is unused, since presence no longer suppresses the tail. `TestApplyUniversalFallback_*`.
- **The package doc carries the overlay selector decision.** `go/acs/cycle1647` (`TestC1647_001`) runs `go doc ./internal/llmroute` and requires the package comment to contain "overlay", "family selector" and "driver selector".
- **The tests clear `EVOLVE_CLI`.** `TestMain` unsets it so an operator shell that exports it cannot leak into the profile and default tiers. A test that needs env precedence passes the variable in the env map, which outranks the process environment.

## Findings

- **cycle-267**: codex exhausted its usage quota mid-batch, the rate-limit escalation exited 85, and 85 was not a trigger, so the codex→claude chain never fired. A quota-blocked primary is exactly when another family can serve, so 85 joined the defaults.
- **cycle-283**: a walled codex re-burned its 5 to 15 minute boot on every dispatch. That produced the family bench (`ApplyBench`); see `EVOLVE_CLI_HEALTH` in control-flags.md.
- **cycle-378**: `evolve setup apply` and policy pins emit bare families, since `Assignment.CLI` is the base family. A bare `codex` pin selected the headless `codex` driver, which lacked the manifest `model_tier_map` and the ChatGPT-account model clamp, so codex exited rc=1 every cycle and the loop spun. `defaultDriverForFamily` now normalizes a bare family to its tmux driver, the project's default execution path. Since 2026-09-09 `codex.json` adopts the family tier table through `model_tier_map_from`; the clamp is still missing from the headless driver.
- **cycle-435 (WS-G1)**: the advisor launched once with no fallback, and a live `agy-tmux` exit 81 failed it. `Dispatch` was extracted from the runner's inline loop so the advisor and the runner share one walk.
- **cycle-440 (MR4)**: introduced `Overlay` as the advisor's soft routing projection, distinct from a pin.
- **PR #390**: a headless phase with chain `[claude-p codex]` escalated its contract-blocked re-dispatch to `codex` and was sent to `codex-tmux`, so one string resolved two ways inside one chain. That is exit 10 on a host without tmux, and a silent change of transport, cost and quota behavior on a host with it. It added the exact-entry rung. See [change-log §8b](../../operations/change-log-2026-07-30.md).
- **cycle-1647**: a bare family the chain holds only under a non-default driver (`[claude-p codex]` with overlay `claude`) still fell through to `claude-tmux`. It added the family rung and put the decision in the package doc. See the [cycle-1647 build explanation](../../explain/builds/cycle-1647-01m2cwsn8sda4z9b65nvys9edy.md).
- **WS-876**: added the tier walk (`TierChain`, `DispatchTiered`, `Plan.Tiers`) and the overlay's envelope floor.
- **cycle-1265**: collapsed `candidatesFrom` and `chainCandidates` into `buildCandidates` (policy-config.md).
- **ADR-0104**: made the universal tail unconditional. Before it, the tail was added only when every configured binary was absent, so a configured CLI that was present but walled ended the phase and, at the last phase, the cycle.
