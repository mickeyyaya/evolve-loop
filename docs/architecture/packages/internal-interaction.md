# internal/interaction

> Decision record: [ADR-0045](../adr/0045-corrective-interaction-protocol.md). Full design, threat model (S1–S10) and as-built deltas: [interaction-protocol.md](../interaction-protocol.md). Ledger and registry file formats: [runtime-reference.md](../../operations/runtime-reference.md). This page keeps the package-level detail those do not.

## Purpose

`internal/interaction` owns the corrective-interaction layer's deterministic parts. It holds the telemetry chokepoint every injection into a phase agent records through (`Recorder`, `Event`, `Outcome`), the per-cycle rollup (`Rollup`, `WriteRollup`), the correction ladder's decision (`NextCorrection`), the closed-vocabulary kernel answerer (`KernelAnswerer`), and the auto-respond rule promotion registry (`ValidateRule`, `PromoteRule`, `EnforceRule`, `LoadRules`).

## Design

- **Leaf package.** Both `core` and `bridge` import it, so it imports neither. Its internal dependencies are `panetrust` (the digest), `atomicwrite` (durable rule writes) and `bridge/keyspec` (key classification), a leaf sub-package, not `bridge` itself. Identifiers from packages it cannot import cross as strings: `CorrectionInput.Violation` is a string because `deliverable` imports `core`, the same move `recovery` makes for verdicts.
- **One recording chokepoint.** `Recorder.Record` neutralizes, keeps the outcome in memory, then appends one ndjson line to `<workspace>/<phase>-interactions.ndjson`. A nil `Recorder` records nothing, so producers carry no nil guards (the `recovery` detector idiom). An empty workspace keeps records in memory only, so the recorder never invents a file location in the cwd. An empty phase writes to `unknown-interactions.ndjson` rather than to an unnameable `-interactions.ndjson`.
- **Neutralize at the chokepoint, never trust the producer.** `Payload`, and `Result` as defense in depth, pass through `panetrust.Digest` before they reach memory or disk (threat S10). Closed-vocabulary strings pass through unchanged. The digest caps each of at most 3 tail lines at 200 runes, and `neutralize` then caps the joined string at 200 runes again, because `Event.Payload`'s contract is a total cap. Both cuts are deliberate.
- **Telemetry never aborts a phase.** Ledger write errors are swallowed; the in-memory record survives.
- **Outcome resolution uses external evidence only.** Results come from artifact presence, pane pattern state and re-dispatch verdicts, never from the agent's self-assessment. `ResultNoEffect` records a failed interaction honestly. `ResultSuppressedLingering` exists because a dismissed fire-once prompt still in scrollback cannot be told apart from an unanswered dialog at this layer, so it gets its own bucket instead of a guess.
- **Submit-verify vocabulary.** The tmux driver (`bridge/driver_tmux_submitverify.go`) records `KindSubmitVerify` on every outcome, including the clean one, because stderr is discarded on the phase-success path and the ledger is the only durable place a recovered stall shows. The clean case is `ResultSubmitVerified`, deliberately not `ResultPromptCleared`: every other producer of `prompt_cleared` (auto-respond, kernel answer) means "our injection worked", and submit-verify fires on every dispatch, so folding its no-ops in would turn `ByResult["prompt_cleared"]` into mostly "nothing happened". `ResultNotVerified` means "could not check" and must never read as clean. `ResultSubmittedAfterResend` is the result that makes the guard measurable: the stall occurred and was absorbed.
- **Rollup reads the ledgers.** `Rollup` globs every `*-interactions.ndjson` in the workspace (in sorted order) rather than reading any in-memory state, so records from the bridge subprocess and from the orchestrator aggregate the same way. Rung `""` buckets as `"none"`. `Decisions` counts distinct non-empty `DecisionID`s, which makes re-dispatches averted computable. `WriteRollup` writes nothing when there is nothing to summarize, so a quiet workspace gets no empty-noise file.
- **Correction ladder as a pure Chain of Responsibility.** `NextCorrection` consumes only caller-supplied facts (no filesystem, no pane reads), so the order is unit-testable without an orchestrator. It never mutates `RungBudget`; the caller decrements on execution and also owns executing and stage-gating the chosen rung. The rungs, cheapest first:
  1. `salvage`: deterministic relocate-then-verify, no agent involved.
  2. `live_fix`: one templated instruction into the phase's own preserved, named REPL. It needs `NamedREPL` and an idle pane.
  3. `recover`: the recovery agent restructures the deliverable around the logic the phase already built (ADR-0106 F1). It needs `Repairable`, which the caller sets only for an all-form violation of a phase that may be repaired; the ladder does not execute it yet.
  4. `redispatch`: the evidence-enriched fresh re-dispatch.
  An empty `Rung` means every rung is exhausted and the caller aborts the cycle. Every decision carries a `Reason` (the ADR-0044 every-decision-justified rule).
- **Kernel answerer as a Strategy over a closed fact set.** `KernelAnswerer` maps a question by keyword to one of four dispatch facts (`artifact_path`, `workspace`, `worktree`, `cycle`) that the agent's own prompt already carried. It does no I/O and calls no LLM; the advisor tail for novel questions is the caller's. `KernelFacts.Cycle` arrives pre-rendered, so the leaf carries no int formatting policy.
- **Rule promotion is a payload specialization of `recovery/promote.go`.** One promotion idiom, two payloads: absent-only content-hash YAML, corrupt-safe replay, operator edit wins. The payload here is `{regex, response_keys, note}` plus a per-rule stage, which rides inside the file rather than a flag. The file id is a short hash of the regex, so re-promotion targets the same file.

## Invariants

- **The recorder runs at every `EVOLVE_PHASE_RECOVERY` stage, including `off`.** Recording is side-effect-free observation (the `FatalPaneDetector` precedent); only corrective actions gate on the stage.
- **The ledger's `O_APPEND` writes are safe only because producers are disjoint in time.** The bridge subprocess writes its outcomes before `runner.Run` returns, and the orchestrator records corrections only after that. POSIX guarantees append atomicity only up to `PIPE_BUF`, so a producer in another process that writes while the phase runs needs a file lock or a single-writer funnel. The code keeps a one-line why on `appendLedgerLine`.
- **A kernel-answer miss is never improvised.** A question that maps to no fact, or to a fact whose value is empty, returns `("", false)`, and the caller falls through to the exit-85 cross-family fallback chain, which the answerer must never suppress. `factFor` returns `""` for any key outside the vocabulary, so the answerer can never disclose anything off-list (threat S7). Pinned by `TestKernelAnswerer_ClosedVocabularyOnly`, `TestKernelAnswerer_EmptyFactIsMiss` and `TestKernelAnswerer_NeverDisclosesOffList`.
- **Question topics match most specific first.** "Directory" phrasing maps to the worktree, the code root a source-writing agent edits in. The workspace is the scratch dir and is keyed only by its own explicit words, so a "scratch directory" question is not taken by the worktree's directory synonyms. The code keeps a one-line why on `questionTopics`.
- **The ladder order is load-bearing.** salvage, then live_fix, then recover, then redispatch. Pinned by `TestNextCorrection_OrderIsLoadBearing`, `TestRung2_RequiresNamedSession_ElseSkipsToRedispatch`, `TestNextCorrection_RecoverPrecedesARedispatch` and `TestNextCorrection_RecoverNeedsARepairableViolation`. A busy agent is never interrupted, and a judgment phase never reaches `recover`.
- **`ValidateRule` is a rejecting trust boundary.** It is stricter than the operator hatch (`keyspec.Validate` warns but sends), because a promoted rule fires keystrokes:
  - the regex compiles under Go's RE2, so there is no catastrophic backtracking;
  - the regex source is at least 12 characters (`minRulePatternLen`, mirroring `recovery.minPromotedSubstrLen`), because a short pattern would inject keystrokes into healthy work;
  - every response key classifies as non-suspect, and one `ClassSuspect` token refuses the whole rule;
  - there is at least one response key;
  - the pattern matches no line of the immutable healthy-pane corpus, because a rule that fires on normal output is a DoS.
  A rejection returns an error; the caller escalates and never relaxes the gate.
- **Promoted rules land at `shadow`.** Enforcement is a measured step (zero false fires observed through the telemetry), never assumed. `parseRule` normalizes any stage other than `enforce` to `shadow`, so a typo never escalates a rule.
- **Every stage re-validates against the current corpus.** `EnforceRule` re-validates before the flip, so corpus rot since promotion blocks it (`TestEnforceRule_CorpusRotBlocksFlip`). `LoadRules` re-validates every rule at boot and drops a now-matching one from the active set while leaving its file for the operator (`TestBootReplay_RevalidatesAgainstCorpus_DemotesNowMatching`). A corrupt file is skipped, so boot never bricks.
- **`EnforceRule` rewrites only the stage line.** An operator-edited file keeps its extra fields and reworded note through the flip. A missing rule is an error (the flip never creates a file), and an already-enforced rule is a no-op. The caller owns the fire-count evidence; this function owns only the safety re-check and the durable flip.
- **Rule writes go through `atomicwrite`.** Its per-call unique temp file keeps concurrent writers of one content-addressed path from colliding. For the flip, last writer wins, which is benign because every writer converges on `stage: enforce`. Pinned by `TestPromoteRule_ConcurrentSameID_NoLostWrite` and `TestEnforceRule_ConcurrentSameID_NoLostWrite`.

## Findings

- **Validation batch, cycles 263–269** ([interaction-protocol.md §2](../interaction-protocol.md)): `nudgeSent=true` was recorded, and nothing measured whether any nudge worked. That is why telemetry shipped first in the ADR-0045 build order: every later component's effectiveness claim needed to be measurable from day one.
- **cycle-265**: contract rejection had one tool, a full re-dispatch, and burned two on a misplaced but valid file that a `mv` would have fixed. It motivated the salvage rung.
- **cycle-267**: a stuck prompt escalated exit 85 and the fallback CLI redid the whole phase to get past a question one injected line would have cleared. It motivated the kernel answerer.
- **ADR-0049 N14**: concurrent fleet cycles promoting the same rule, or flipping it, shared a `path + ".tmp"` temp file. The loser's rename hit ENOENT (a lost promotion) and a partial write could tear a rule every later boot replays. Routing both writes through `atomicwrite` fixed it, as it did for `recovery.PromoteSignature`.
- **`EnforceRule` review**: the first flip reconstructed the YAML from parsed fields and silently dropped operator-added keys. The line-surgical rewrite replaced it.
- **Submit-verify, cycles 1505/1510/1517** ([2026-08-25 incident](../../incidents/2026-08-25-submitverify-false-wedge-release-red.md), [2026-09-14 incident](../../incidents/2026-09-14-codex-prompt-submit-wedge.md)): the parked-input stall class that the submit-verify results measure. `ResultSubmitWedged` makes the exhausted re-send budget visible about 20 minutes before the phase would time out, where it was previously typed nowhere. Adding `KindSubmitVerify` grew `Summary.Total` and `ByRung["none"]` by one or two per dispatch, so interaction-summary volumes are not comparable across that change.
- **ADR-0106 (2026-09-26)**: a form defect in a deliverable re-ran the whole phase because the ladder had no rung between the phase's own preserved agent and a fresh re-dispatch. `recover` is that rung; the design and its guards are in [logic-first-delivery-design.md](../logic-first-delivery-design.md).
