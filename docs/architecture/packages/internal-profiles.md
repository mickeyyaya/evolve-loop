# internal/profiles

> Related: [model-routing-policy.md](../model-routing-policy.md) (capability tiers, never vendor names), [ADR-0029](../adr/0029-cli-fallback-chain-and-per-agent-overrides.md) (fallback chain and trigger codes), [ADR-0104](../adr/0104-fallback-is-a-property-of-the-bridge-handle.md) (every agent names a chain; the Claude-family floor), [ADR-0096](../adr/0096-repair-rounds-escalate-and-carry-findings.md) (`effort_overrides`), [ADR-0023](../adr/0023-live-injection-and-launch-rules.md) (system prompt and digest precedence), and the "Deep-tier family arrangement" row of [runtime-reference.md](../../operations/runtime-reference.md). This page keeps the package-level detail those do not.

## Purpose

`internal/profiles` loads the agent profiles in `.evolve/profiles/*.json`. A profile pins what a phase agent subprocess runs under: its CLI and fallback chain, model tier and effort, allowed and denied tools, sandbox, and turn budget. The package's tests also act as the repo-wide guards on the routing config committed in that directory; the ship repo-contract gate runs them before every lane ship.

## Design

- **One loader over `fs.FS`.** The same implementation serves tests (`fstest.MapFS`), the on-disk directory (`os.DirFS`) and an embedded FS, with no change at the call site. A nil FS is a valid zero loader: `Get` returns `fs.ErrNotExist` and `List` returns nil.
- **Typed fields plus `Raw`.** The struct types only what the runtime reads. `Raw` keeps the file's bytes so a caller can decode keys the struct does not model (`parallel_subtasks`, `context_anchors`, `_comment` notes) with a second `json.Unmarshal`.
- **Shared tool lists.** `tool-policy.json` holds named lists under `policies`. A `$include_policy:<name>` entry in `allowed_tools` or `disallowed_tools` expands to that list at load time. Expansion keeps first-seen order and drops duplicates. A profile with no sentinel never reads the policy file. An unknown policy name fails the load.
- **Fallback trigger codes.** An empty `cli_fallback_on_exit` means the `llmroute` default, `[80, 81, 85, 124, 127]` (`defaultFallbackOnExit`). Older notes that list only 80/81/124/127 predate exit 85.
- **Tier evidence.** The benchmark evidence behind which model family holds which tier (for example Opus vs Sonnet on SWE-bench) lives in [model-profiles.md](../../research/fable-simulation-2026/model-profiles.md). The effort and family guards here enforce that choice; they do not restate it.
- **What counts as a profile.** `List` returns JSON files with a non-empty `name`. That excludes `tool-policy.json`, notes such as `AGENTS.md`, and subdirectories.
- **Provenance.** `generated_from` records where a profile came from: `hand-authored` today, a generated projection such as `phasespec:<name>@<sha>` later. The vocabulary is free-form here. `evolve phases validate` owns its validation and treats an absent key as unstamped. The field is `omitempty`, so an unstamped profile marshals unchanged.
- **One funnel for real-tree scans.** Every test that iterates the live `.evolve/profiles` goes through `RealTreeProfiles` (root-parameterised as `treeProfiles`). The helpers live in `tracked_realtree_test.go` but are exported, because the external `profiles_test` package calls them too.
- **Rules projected from one home.** `claudeFamilyFloor` (`family_floor_test.go`) is the only list of phases kept on the Claude family. The deep-tier arrangement guard takes its grader exceptions from it and pins only the router (the advisor) itself. `codexDeepTopRung` is the one constant for the codex deep/top effort level; the matrix pin, the class guard and the `effort_overrides` pin all read it, so a directive change is one edit.

## Invariants

- **`Raw` is unexpanded.** It holds the bytes as written, sentinels included. Code that needs the effective tool sets reads `AllowedTools` and `DisallowedTools`.
- **Guards bind only git-tracked profiles.** The runtime writes untracked profile stubs into the same directory. A guard that binds them fails on state no CI checkout has ([2026-08-09 zero-ship incident](../../incidents/2026-08-09-zero-ship-batch.md)).
- **An unusable git state binds everything.** When the tracked set cannot be read, the funnel logs why and binds every on-disk profile, the stricter fallback. An empty tracked set counts as unusable: a pathspec that matches nothing still exits 0, and treating that as "no profiles" would switch every guard off.
- **A guard reports a profile that fails `Get`; it never skips it.** `Get` also expands policies, so a profile with valid routing fields can fail for an unrelated reason. A skip would shrink the checked set without anyone noticing.
- **No guard passes vacuously.** Each corpus guard fails when its selector matched nothing, or fewer profiles than its floor. The one exception is the `max`-placement guard, where zero matches is the expected state; decode regressions in `effort_level` still surface in the sibling class guard.
- **The decoy test never writes the live tree.** Phase sandboxes deny writes under `.evolve/profiles`, so the test mirrors the tracked profiles into a temp git repo and plants the untracked decoy there.
- **Run `go test -count=1` after a profile-only edit.** The guards read `../.evolve/profiles`, outside the Go module, and Go's test cache does not track those reads. A cached run can report a stale pass while the regression is on disk.
- **Effort guards read the declared tier.** They check `model_tier_default`, not the tier a phase dispatches at. A `model_tier_overrides` escalation (scout runs at deep on cycle 1) keeps the declared effort unless the profile's own `effort_overrides[tier]` says otherwise.
- **`max` effort only on deep or top profiles, on every CLI family.** It is the most expensive level wherever it exists, and a fast or balanced phase was costed at a lower one. An unset `model_tier_default` resolves to `balanced` at dispatch, so it counts as a violation, not an exemption.
- **The floor's membership test is adversarial judgment of build content.** The floor holds the two graders (`auditor`, `adversarial-review`), the test author (`tdd-engineer`, kept apart from the builder's family against cooperative bias) and the two spec verifiers. Verdict-declaring mechanical gates (`merge-to-main-gate`, `coverage-gate`) run on codex on purpose: their verdicts are deterministic measurements the host re-verifies. The `classify.require_sections("Verdict")` discriminator in `phase.json` does not define the floor.
- **The floor compares against the live builder.** `TestClaudeFamilyFloor` reads the builder's family from `builder.json` instead of a literal, so a future builder flip cannot make the floor contradict itself. It checks `cli`, every `cli_fallback` entry, and `allowed_clis`, because a policy pin can dispatch any family `allowed_clis` admits.
- **`family` mirrors `policy.BaseCLI` locally.** Importing `internal/policy` from these tests would create an import cycle.

## Findings

- **Pin a rule, not a list.** The 2026-08-28 effort change edited the 21 codex deep/top profiles that existed then. `failure-adjudicator.json` landed hours later from another branch (PR #508), missed the sweep, and reached main at a different level with nothing reporting it. `TestCodexDeepTierProfilesAllRunAtDirectedRung` now checks every codex deep/top profile, so a new one must state its effort on purpose.
- **Raw scans break in the runtime plane.** The first version of that class guard scanned the directory directly. In the live plane it failed on two minted stubs with no `effort_level` (`disposition-preflight`, `regression-predicate-precheck`), which would have failed the test gate on every cycle. It now uses the tracked-profile funnel, the same fix as the 2026-08-09 incident.
- **Overrides escaped their own envelope.** Before `TestModelTierOverridesWithinEnvelope` (cycle 974), six profiles shipped a `model_tier_overrides` value below their envelope's `min` or above its `max`. The existing checks tested that tier names were canonical and that each envelope was ordered, but never compared an override with its own envelope.
- **Triage moved to codex on evidence, not hope (2026-09-02).** The earlier triage failure (cycle 1215) was specific to agy. Codex had since honored the deliverable contract at volume: 76 dispatches at a 44% share over cycles 1530–1552 with zero quota halts, and the v22.21.0 soak (cycles 1589–1594) shipped on codex scout and build handoffs with the contract gate green. The same rebalance moved 24 Claude-family profiles to codex, leaving only the floor on Claude. The tier stayed `balanced`: the move changed quota, not reasoning budget.
- **Retrospective routing followed model strength and volume.** Retrospective moved from agy to claude/deep on 2026-08-14, because agy's deep tier (Gemini 3.1 Pro) was then the weakest deep model in the fleet. It moved on to codex/deep on 2026-08-26: retrospectives are about 40% of deep-tier dispatches and do not judge the builder's work, so they need not stay off the builder's family.
