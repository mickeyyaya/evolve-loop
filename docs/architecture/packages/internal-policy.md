## Purpose

`internal/policy` loads `.evolve/policy.json` and turns each block into resolved configuration. It is the config-as-code surface that replaced the `EVOLVE_*` env dials. It holds no behavior of its own: each consumer reads a resolved value and acts on it.

## Design

- **Raw block plus pure resolver.** Each block is a pointer field on `Policy` and has a resolver (`FleetConfig`, `GatesConfig`, ...). The resolver starts from the compiled defaults and overrides only the fields the operator set. A nil block means compiled defaults, so the zero `Policy{}` is always safe to read. Some blocks are their own resolved type (`ObservationMaskPolicy`, `RouterPolicy`, `SandboxPolicy`, `DocsFloorPolicy`, `RecoveryPolicy`); the others have a separate `XxxConfig` struct.
- **No env, no I/O in resolvers.** The package is enrolled in `param_env_agnostic_test.go`, which fails on any `os.Getenv`, `os.LookupEnv` or `os.Environ`. That guard matches only the canonical `os` identifier, so an aliased import would get past it; code review has to catch that case. Resolvers return advisories as data (`FleetConfig.Warnings`) instead of logging them.
- **Explicit zero versus absent.** Pointer fields (`*bool`, `*int`) keep an operator's explicit `0` or `false` distinct from an omitted key: `observer.nudge_s: 0` disables nudging, and `chain.enabled: false` is not the same as absent. `RetryPolicy` does the same with a custom `UnmarshalJSON` that records whether `retry_backoff_base_s` and `contract_correction_retries` were present, because zero disables those two.
- **`gates.scan_cache_gate`.** `GatesPolicy.ScanCacheGate` is the stage of the ship scan cache (landing plan S5). `ScanCacheFor(projectRoot)` serves the ship scan and the floor writer of ship, which hold only a project root. It returns the stage and the bounds of the tree hash (`scan_cache_max_mb`, `scan_cache_budget_seconds`). It fails open to the defaults (`shadow`, 2048 MB, 60 seconds). The word `off` turns off the shadow and the floor writer, and only `enforce` lets the ship skip a package (plan wave-latency-2026-10 D6).
- **The whole policy decodes strictly** (X18a, [llm-isolation.md](../llm-isolation.md) §27, ADR-0156 rule 12).
  - Before the decode, `Parse` walks the raw JSON against the `Policy` type (`strict_keys.go`). A key that names no field fails with `ErrUnknownKey` and the full path, for example `unknown policy key "fleet.cuont"`, `"floor[1].idd"` or `"cli_routing.agents.builder.modle"`.
  - Three top-level metadata keys pass the walk and have no effect: `$schema`, `description` and `version` (`metadataKeys`). The error names the fix: `remove it or check its spelling`.
  - The walk matches the exact `json` tag. Thus `"Fleet"` fails, but `encoding/json` folds the case and accepts it. The walk goes into maps, slices and the struct of a type with a custom `UnmarshalJSON`.
  - `strict_keys_shape_test.go` pins the two conditions of the walk. Each reachable field has a named `json` tag and no struct is embedded. The set of custom decoders is a reviewed list, so a new decoder with a different wire shape gets a `keyShapes` entry.
  - The JSON shape of two blocks is not their struct. `keyShapes` maps `handoff` to `handoffPairJSON` and `quality` to `qualityPanelJSON`, the shapes that their decoders use.
  - The walk skips a value of the wrong kind. The decode then fails with the error of the block, not as an unknown key.
  - X18a removed the three stale keys of the tracked file: `description`, `disposition` (the live key is `failure_disposition`) and `version`. Pinned by `strict_keys_test.go`, which also parses the tracked file and each fixture under `testdata/`.
- **`LoadOrDefaults(path, warn)`** is `Load` for a best-effort reader that has no error path. Each former `pol, _ := policy.Load(...)` reader uses it, so a policy error is never silent. A reader that can fail its step still calls `Load` and returns the error.
  - A refused policy prints one `[policy] WARN` line that names the error. The call returns the compiled defaults, but each safety floor fails closed to `enforce` (`failClosed`): `docs_floor` (both stages), `comment_floor` and `cover_changed`.
  - The other safety keys need no fail-closed value here, because no `LoadOrDefaults` reader reads them. A `gates` error stops the cycle at the routing refusal, and the repo-contract floor runs as `enforce`. A `sandbox` error halts the preflight. The `floors` default is the compiled Claude floor.
  - The `isolation` readers are in the bridge (item `control-flags-bridge-policy-readers`).
- **Root-based loaders.** `StrictAuditFor`, `WorktreeBaseFor`, `RegressionTIAStageFor`, `InteractivePolicyFor` and `ResolveLaunchOverlaysFailOpen` serve callers that hold only a project root. They fail open to the default. The loud malformed-policy error still comes from the cycle's own `Load`. `ResolveLaunchOverlaysFailOpen` is the one function here that writes (a WARN to stderr). It exists because the non-phase launch seams (subagent, retro, swarm) have no report to carry an error, while the phase runner hard-fails on a malformed policy. Those seams have no routing tier, so the model doubles as the tier.
- **The explanation-correction budget is a failure category.** `CategoryExplanationCorrection` (`explanation-correction`, task level, `retry-with-fix`, `max_retries` 1) bounds the document-only rung of a passing audit (X2, [logic-first design §5.15](../logic-first-delivery-design.md)). `failure_policy.categories` overrides it like any category. `core` reads only `MaxRetries`. Pinned by `TestFailurePolicyConfig_TheExplanationCorrectionBudgetDefaultsToOneAndComesFromPolicy`.
- **`workflow.findings_repair` is one block per judging phase** ([ADR-0124](../adr/0124-code-review-phase.md)). `FindingsRepairPolicy.CodeReview` (`workflow_findings_repair.go`) holds `stage` and `threshold`, and `WorkflowConfig().CodeReviewRepair` resolves it over the compiled default `{stage: shadow, threshold: MEDIUM}`. The threshold is the strict severity: findings at or above it must be fixed or accepted-deferred (operator Q-D2). It is checked against `reportdoc`'s severity vocabulary (`knownSeverity`), so the finding grammar keeps one home. An unknown stage or severity falls back loudly into `JudgeRepairConfig.Warnings`, as `fleet.budget.stage` does. `enforce` is refused with its own warning until the review loop (Q3) and the audit cross-check (Q5) land. `max_rounds` and the audit judge join the block with Q3. Pinned by `TestCodeReviewRepair_*`.
- **`workflow.quality_index` holds the index's thresholds** (`workflow_quality_index.go`). `WorkflowConfig().QualityIndex` resolves `thresholds` through `qualityindex.ResolveThresholds`, the index's one rule (4 everywhere by default, `"*"` first, then per-key, 1–5, with warnings). `QualityIndexThresholdsFor(projectRoot)` is the root-based loader the deliverable gate uses for the report grammar. Unlike `StrictAuditFor`, it never swallows a load error: a malformed policy returns no thresholds and the wrapped error, and the caller decides how loud to be. The gate treats it as its own fault, so `GATE_CONTRACT_FAIL_OPEN` fires and the agent sees no violation. Pinned by `TestQualityIndex_*` and `TestQualityIndexThresholdsFor_ReadsTheProjectPolicyAndNeverSwallowsALoadError`.
- **Tier and CLI vocabulary.** `TierNames()` is the one ordered list of tier names (fast, balanced, deep, top) and `TierName(rank)` its inverse of `TierRank`; `llmroute` and `cliroute` read them instead of keeping copies, and `TestTierNames_AreTheOneRankOrderedVocabulary` pins that the two agree. `TierRank` maps fast/balanced/deep/top (and the haiku/sonnet/opus aliases or a model id) to 1-4. Rank 0 means unclassifiable. `ValidatePin` exempts rank 0, and the function is exported so stricter callers, such as the phase registrar clamping a minted phase, can reject it. `BaseCLI` is the exported driver-suffix normalizer; since 2026-10-05 it delegates to `profiles.BaseCLI`, so `profiles` can use the same normalizer without importing this package.
- **Evaluator floor in two places.** `evaluatorFloorPhase` duplicates `router.EvaluatorFloorPhase` on purpose: each layer guarantees the evaluator on its own, and a shared constant would create an import cycle. `TestEvaluatorFloorPhase_SingleSource` in the router catches drift.
- **`cli_routing` is a strict block.** `Policy.CLIRouting` (`cli_routing.go`) holds the routing table of the operator: `clis`, `default`, `work` (by role), `agents` (by agent), `tiers` (a per-tier ceiling) and `after_chain`.
  - `CLIRouting.UnmarshalJSON` decodes the block with `DisallowUnknownFields`. A typo inside it (`defualt`) fails `Load` and names the key path.
  - A `null` block or agent rule is refused too. A pointer field never reaches `UnmarshalJSON` for `null`, so `Load` pre-scans for `"cli_routing": null`. Without the scan, that value decodes as an absent block and selects the legacy sources.
  - An `agents` entry is an array of CLIs or `{"cli": [...], "model": "<tier>"}`. `AgentRule.UnmarshalJSON` takes both forms and decodes the object form strictly.
  - This package only decodes the block. `cliroute.Compile` checks the names, roles, tiers, the floor and the two-sources rule ([internal-cliroute.md](internal-cliroute.md)).
  - An absent block (`nil`) means that the legacy sources (`pins`, `workflow.universal_fallback*`, `router.cli/model`) still apply.
- **`inbox_priority` is the other strict block** ([ADR-0121](../adr/0121-inbox-priority-is-a-computed-rank.md)). `Policy.InboxPriority` (`inbox_priority.go`) holds the inbox rank's `class_order`, `factors`, `age_halflife_days`, `unblocks_cap`, `recurrence_cap`, `active_campaigns` and `preempt_margin`. `InboxPriorityPolicy.UnmarshalJSON` decodes it with `decodeStrict`, as `cli_routing` does, then validates it: an empty or duplicated class order, a blank or padded name, a negative factor, all-zero factors, a half-life at or below 0, a cap below 1 or a negative margin fails `Load` naming `inbox_priority`. A present `factors` block must name all six factors (`InboxPriorityFactors.UnmarshalJSON`), so an omitted one never silently weighs 0. The factor names (`inboxFactorNames`) and the weights they validate (`InboxPriorityFactors.weights()`) are matched by index; this package cannot import `inboxrank`, so `inboxrank`'s `TestFactors_AreThePolicysFactorNamesInItsOwnOrder` pins both against `inboxrank.Factors()`, the order the rank scores in. The scalars are pointers, so an explicit `preempt_margin: 0` is honoured rather than read as absent. `InboxPriorityConfig()` resolves the block over the compiled default (the operator's class order as corrected on 2026-10-06, correctness first and security last; factors 0.45, 0.20, 0.15, 0.10, 0.05, 0.05; half-life 30 days; caps 3 and 5; margin 0.05) and returns copies of its lists. A `null` block is read as absent, which is the compiled default, unlike `cli_routing`, whose absence means the legacy sources. The checked-in `.evolve/policy.json` names the class order and the factors explicitly; `TestLoad_TheCheckedInPolicyCarriesTheOperatorsClassOrder` pins it.
- **`workflow.convergence` is the block of the convergence policy** ([ADR-0126](../adr/0126-every-iterative-loop-converges-or-escalates.md), [convergence-policy.md](../convergence-policy.md) §8). `WorkflowPolicy.Convergence` (`convergence.go`) holds `stage`, `max_fix_rounds`, `base_blocking_bar`, `raised_blocking_bar`, `concentration_threshold`, `concentration_window`, `concentration_min_findings` and `max_backward_edges`.
  - `ConvergencePolicy.UnmarshalJSON` decodes the block with `decodeStrict`. An unknown key fails `Load` with its key path. A count below 1 or a threshold outside (0, 1] fails `Load` under its key.
  - The two enum kinds resolve and do not fail. `ConvergenceConfig()` turns an unknown `stage` into `shadow` and an unknown bar into its default (`MEDIUM`, `HIGH`). Each gets a `Warnings` line in the wording of the fleet block (`unknown value %q, falling back to %q`).
  - A raised bar below the base stays at the base, with its own warning. Thus rung 2 never lowers the bar.
  - `ConvergenceConfig.Validate` is the one home of the ranges and words. Each count is at least 1, the threshold is in (0, 1], and the stage and the two bars are known words. The check at `Load` is `Validate` over the block resolved onto the defaults. `Input.Validate` of `convergence` calls it and does not restate the ranges. Pinned by `TestConvergenceConfig_ValidateRefusesAnUnresolvedConfigUnderItsKey`.
  - The compiled defaults are shadow, 3, MEDIUM, HIGH, 0.6, 2, 5 and 3. The bar words are CRITICAL, HIGH and MEDIUM. `TestDecide_Rule10_EveryBarThePolicyAcceptsIsASeverity` of `convergence` pins that each word is a severity.
  - The resolver does no I/O. `evolve convergence decide` prints the warnings. Pinned by `convergence_test.go`.
- **`checkpoint` is the `evolve checkpoint` retention.** `Policy.Checkpoint` (`checkpoint.go`) holds `keep_per_worktree`, the number of `refs/checkpoints/<worktree>/*` refs a save keeps per worktree. `CheckpointPolicy.UnmarshalJSON` decodes the block with `decodeStrict`, the same helper `cli_routing` uses, so a typo such as `keep_per_worktee` fails `Load` with the block named instead of silently keeping the default, and it refuses a zero or negative `keep_per_worktree` with the fix in the message (remove the key for the default), rather than quietly substituting 20 (`TestCheckpointPolicy_UnmarshalJSONRefusesAnUnknownKey`, `TestCheckpointPolicy_UnmarshalJSONRefusesANonPositiveRetention`). `CheckpointConfig()` resolves it, and still lets only a positive number override the compiled default of 20 for a block built in code, so no value can make a save delete every checkpoint (`TestCheckpointConfig_KeepsTwentyPerWorktreeUnlessAPositiveNumberIsSet`, `TestCheckpointConfig_TheRetentionReachesTheVerbFromPolicyJSON`). A save that cannot load the policy still saves but prunes nothing; `evolve checkpoint prune` refuses ([internal-wtcheckpoint.md](internal-wtcheckpoint.md)).
- **`resume` bounds the age of a resumable checkpoint** (2026-10-21). `Policy.Resume` (`resume_config.go`) holds `max_checkpoint_age_h`. `ResumeConfig().MaxCheckpointAge()` resolves it over the compiled default of 192 h, one weekly quota reset plus a day. `core.LoadResumeState` refuses an older checkpoint ([internal-core.md](internal-core.md)).
  - `ResumeConfig.UnmarshalJSON` decodes the block with `decodeStrict`, as `checkpoint` does. An unknown key, or a zero or negative value, fails `Load` with the block named.
  - Pinned by `TestResumeConfig_TheCheckpointAgeBoundDefaultsToEightDaysAndIsConfigurable` and `TestResumeConfig_UnmarshalJSONRefusesAnUnknownKeyAndANonPositiveAge`.
- **Naming.** The ADR-0072 decision table is `SystemFailurePolicy`, not `FailurePolicy`, because `Policy.FailurePolicy()` already resolves the separate `failure_floor` learning block.
- **One source, projected.** `failure_disposition.stage` defaults to the resolved `chronicle.escalation` stage rather than repeating `"shadow"`, so an operator moves both with one word. Chronicle's bump step, cap, autofile weight and historian cap stay compiled constants in their owning packages; only the stages and digest budgets are policy.
- **One writer for `policy.json`.** `Parse(raw)` is `Load` without the file (it refuses a `null` `cli_routing` the same way). `PatchBlocks(existing, patch)` sets or removes top-level blocks (a `nil` value removes one), keeps every other block as written, refuses a malformed file rather than clobbering it, and writes `MarshalIndent` with a trailing newline; the checked-in file round-trips byte for byte. The `cli-routing` write verbs and `setup apply` both write through it. Pinned by `TestPatchBlocks_*` and `TestParse_IsLoadWithoutTheFile`.
- **Advisor skill clamp ("advisor proposes, kernel disposes").** `ClampAdvisorSkills` checks each proposal against the filesystem registry (`SkillRegistryFromFS`, never a hand-kept list), then the allow list, the deny list and the per-dispatch cap. It keeps the advisor's order and records one `AdvisorSkillRejection` per dropped skill. Registry membership is exact string equality and the name is never joined to the skills root, so a proposal like `../../etc/passwd` can never resolve. `ResolveOverlaysWithAdvisor` only appends: with no proposal it returns exactly `ResolveOverlays`.
- **Overlay rules are one intersection of selectors.** `OverlayRule.matches` requires every set selector: `phases`, `clis`, `models` (globs over the raw token), `tiers`, `when` (signal clauses that fail closed) and `writes_source`. `tiers` goes through `matchTier`: a raw glob match, else a plain selector whose `canonicalTier` equals the dispatch's. `canonicalTier` is `TierName(TierRank(token))`, the one canonicalization; there is no second alias table. `NonCanonicalOverlayTierSelectors` lists the selectors that name no canonical tier, for the preflight warning. `writes_source: true` matches only an `OverlayDispatch` whose `WritesSource` is set; false is a wildcard, as an empty list is. The package does not decide who writes: the phase runner copies `PhaseRequest.WritesSource()`, the orchestrator's fence projection, onto the dispatch. `compiledDefaultOverlays` is the one built-in rule table (deep/top get `fable`; a document cycle's scout, build and audit get the solution personas; a code cycle's source writers get `engineering-craft` and `SelfReviewSkill`, which is `code-review-simplify`). The writer row is last, so every older resolution keeps its order, and the two skills share it because their selectors are identical. `SelfReviewSkill` is a named constant because the phase runner's self-review check reads the same name. The audit does not load it: by operator decision (2026-10-07) the `code-review` phase is the one home of independent review. `CompiledDefaultOverlaySkills` projects the table for the guards' manifest pin. Pinned by `TestResolveOverlays_TierSelectorsMatchTheCanonicalTier`, `TestNonCanonicalOverlayTierSelectors`, `TestCompiledDefaultOverlays_EngineeringCraftOnEveryCodeSourceWriterAtAnyTier`, `TestCompiledDefaultOverlays_EngineeringCraftNeverReachesAReadOnlyOrDocumentDispatch`, `TestResolveOverlays_WritesSourceSelectorMatchesOnlyWriters`, `TestCompiledDefaultOverlays_CodeReviewSimplifyReachesOnlyCodeSourceWriters`, `TestSelfReviewSkill_IsTheSkillTheCompiledWriterRuleLoadsLast` and `TestCompiledDefaultOverlaySkills`.
- **Smaller defaults and their reasons.**
  - `workflow.compact_prompts` (default on) strips about 23 KB per cycle of on-demand reference tails.
  - `parallel_evaluate.concurrency` defaults to 3, the soak sweet spot (about 11% saving, with diminishing returns past it).
  - `classify.hang_classifier` is opt-in, so a misconfigured git log can never mask a real integrity breach as a transport hang.
  - `catalog.allowed_families` filters a CLI's live model ids by family before classification, so agy never receives Claude models.
  - `observation_mask.window_turns` defaults to 10, the optimum reported in arXiv 2508.21433.
  - `fleet.budget.history_window` defaults to 10 cycles: enough for a stable pace median without reaching into stale regimes. `safety_fraction` is validated only by `fleetbudget`, its single owner.
  - `cli_health.proactive_probe` benches capped families before a phase boots them. It complements the reactive bench, which learns of a cap only after a phase has burned a boot.
  - `cli_health.usage_evidence_timeout_s` and `cli_health.usage_evidence_ttl_s` bound the usage query a failing CLI triggers (since 2026-10-06; see the [CLI-failure triage runbook](../../operations/cli-failure-triage.md)). The accessors `CLIHealthConfig.UsageEvidenceTimeout()` and `UsageEvidenceTTL()` resolve a non-positive or absent value to the compiled defaults, 2 minutes and 10 minutes. The struct keeps the raw seconds, so a zero-value comparison still means "no block". Pinned by `TestCLIHealthConfig_UsageEvidenceTimeoutAndTTLComeFromTheBlockWithCompiledDefaults`.
  - `retro_autofile.default_weight` defaults to 0.75.
  - `failure_policy.thresholds.build_deep_escalate_at_failures` (ADR-0076 D) defaults to 1: an item whose failure count reaches it builds next at the deep tier, because retrying a hard item at the same tier re-fails identically. It only raises the tier, and the envelope's max still clamps. 0 keeps the default; escalation is disabled through the core escalation seam, not this knob.
  - The size-budget scaler (ADR-0076 A) multiplies correction rounds and the build artifact timeout by `workflow.size_budget_multipliers`, and clamps the scaled correction limit to `MaxContractCorrectionRetries`, the same bound `RetryConfig` enforces.
  - `acs.predicate_env` (default empty; the checked-in policy names `EVOLVE_FLAG_CAMPAIGN`) lists the operator-owned `EVOLVE_` keys the ACS suite forwards to predicates past its scrub of the namespace ([ADR-0114](../adr/0114-the-acs-verdict-is-always-written-and-complete.md)). The policy holds only the names; `internal/acssuite` bounds the list (a lane protocol key or a suite export is refused with a verdict warning) and copies the values, so this package still reads no environment and needs no import of the suite's key names. `ACSTimeoutConfig` returns the whole `acs` block despite its name: historical cycle predicates call it, so a rename would break their compile.
- **Reasons that sat beside the fields.**
  - `acs.go_timeout_s` of 0 means `DefaultTimeout`; a caller must never read it as a zero timeout. `MaxContractCorrectionRetries` caps build correction re-dispatches, and the size-budget scaler clamps to it too.
  - `context_fill.warn_threshold_pct` is honored only in 1..100. Otherwise it falls back to 60, because 0 or 900 are typos that break the WARN. `research.recall_k` falls back to 5 outside 1..`maxRecallK`. A lower default narrows the advisor's failure recall on every install. The cap keeps a typo from flooding the advisor prompt. `novelty_threshold` falls back to a strict 0.9, because suppressing a lesson destroys failure evidence.
  - `defaultPhaseArtifactTimeoutS` keys each phase by both its agent label and its persona alias, because the two differ permanently. It stays narrow, so every other phase keeps the 300 s hang-detection builtin. `PhaseArtifactTimeouts` returns a fresh map.
  - **The legacy retro label (`legacy_agent_label.go`).** Since 2026-10-20 the retrospective launches with the agent label `retro`, not `retrospective`, because it runs through the shared phase runner. A project can still hold `interactive_policies.retrospective` or `phase_artifact_timeout_s.retrospective`. `InteractivePolicyFor` and `PhaseArtifactTimeouts` apply such a key to the `retro` label and write a `[policy] WARN` line that names the key to rename. A `retro` key wins over the legacy key, and an empty or non-positive legacy value never applies. Pinned by the four tests in `legacy_agent_label_test.go`.
  - `observer` and `fanout` use pointers so an explicit zero (`nudge_s: 0` disables) stays distinct from absent, and their resolvers never hand out a nil pointer. `ObservationMaskConfig` never returns a non-positive window, which `phasestream` reads as off.
  - `isolation`: `i2.stage` sets the stage of the hermetic environment of each LLM child (`IsolationEnvStage`, [llm-isolation.md](../llm-isolation.md) §6.1). Empty means the compiled default `shadow`. `i3.stage` sets the stage of the exec deny of LLM binaries (`IsolationExecStage`, §7.1), with the same default. `i8.stage` sets the stage of the typed flow decisions (`IsolationFlowStage`, §12.1). Empty means the compiled default `legacy`.
  - `isolation`: `i2.stage` sets the stage of the hermetic environment of each LLM child (`IsolationEnvStage`, [llm-isolation.md](../llm-isolation.md) §6.1). Empty means the compiled default `shadow`. `i3.stage` sets the stage of the exec deny of LLM binaries (`IsolationExecStage`, §7.1), with the same default. `i5.stage` sets the stage of the read isolation of the cell (`IsolationReadStage`, §8.5 and §9), with the same default. `lineage_max` caps the lineage cycles of the input index (`IsolationLineageMax`; 0 means the compiled default 5).
  - `isolation`: `i2.stage` sets the stage of the hermetic environment of each LLM child (`IsolationEnvStage`, [llm-isolation.md](../llm-isolation.md) §6.1). Empty means the compiled default `shadow`. `i3.stage` sets the stage of the exec deny of LLM binaries (`IsolationExecStage`, §7.1), with the same default. `i7.stage` sets the stage of the protected write rule of the sandbox (`IsolationGuaranteeStage`, §9.1), with the default `shadow`. `i8.stage` sets the stage of the typed flow decisions (`IsolationFlowStage`, §12.1). Empty means the compiled default `legacy`.
  - `recovery`: `phase_recovery` also arms the bidirectional channel and adviser promotion. So `spine_floor` and `fatal_pane` have their own dials. `spine_floor` is the clean-absence handoff-gap abort; below `enforce` it WARNs and proceeds. `fatal_pane` is the stop-review fast-fail: `enforce` ends the wait, `shadow` records `would_fast_fail`, and `off` skips the detector. `docs_floor` only WARNs, even at `enforce`. The `merge_gate` composition root maps an unknown stage word to off, so a typo can never arm auto-merge.
  - `goal_stall.nonprogress_threshold` sits above the empty-only default of 3 because a mixed FAIL and EMPTY streak is noisier evidence. The item builder re-floors a lower goal-stall weight to 0.9.
  - `catalog.allowed_families` passes nil through (no constraint) and keeps it distinct from an empty map. `catalog.refresh_stage` derives from `auto_refresh` when absent.
  - Overlays: `compiledDefaultOverlays` is the only built-in tier-to-skills mapping, a policy `overlays` block replaces it wholesale, and `ProtectedSurfaceManifest` is pinned to it. `ResolveLaunchOverlaysFailOpen` fails open because the non-phase launch seams have no report to carry the error. `ClampAdvisorSkills` compares exact strings and never path-normalizes, so a path-like proposal can never resolve. `matchWhen` fails closed: an absent signal, a non-string value or an unknown op never matches in either polarity. A rule's `when` clause on an absent signal never matches.
  - `failure_floor`: `always_learn=false` only makes the retro lighter. It never suppresses the deterministic floor. An unknown `audit_fail_routes_to` falls back to the default, so some learning phase always runs. `FailurePolicyConfig` lets an override replace a whole category row, and unmentioned rows keep their defaults. It then re-stamps the floor rows. `guard_class_halt_ceiling` exists because guard aborts are pipeline failures, never task defects.
  - `boot.binary_refresh` is `off` only for an exact `off`. The self-heal is integrity posture, so a typo must not disable it. `fleet.plan_source`, `scheduling`, `landing` and `budget.stage` fail safe to their default on an unknown word, and add a `Warnings` entry (the default `shadow` raises none). `fleet.budget` is in native quota units, never dollars. `FleetConfig` does no I/O. The caller reports `Warnings`.
  - `regression_tia` treats any unknown word as `off`, and `gates.report_size_gate`, `manifest_gate` default to `shadow` so a budget or manifest is observed before it can block. `repo_contract_gate` defaults to `enforce` because those guard suites fail on main's next run anyway.
  - `workflow`: `strict_audit` promotes a WARN audit verdict to FAIL in the audit phase and the ship audit-binding and makes the failure adapter block. `compact_prompts` strips the `## Reference Index (Layer 3, on-demand)` section and everything after it from agent docs before dispatch. `remediable_phases` must list only deterministic gates, never judgment phases such as audit. `universal_fallback_exclude` absent means `["agy"]`, and an explicit `[]` lifts the ban; the excluded families may still be a profile's configured primary.
  - `Policy.GC` cannot relax the hard retention rules: quarantine is manual-only, and the ledger and live runs are never touched. `MandatoryPhases` can only add to the mandatory set, and `Floor` lists closeout gates, not phases (contrast `ShipFloor`).

## Invariants

- **Policy can add constraints but never remove the floor.** `FloorPhases` re-appends `audit` to any supplied ship floor. `FailurePolicyConfig` re-stamps the `verdict-incoherence` and `infra-systemic` rows over any override. `MergeMandatory` only adds phases.
- **Unknown words fall toward the safe side.** For `merge_gate`, `parallel_evaluate`, `regression_tia`, `catalog.refresh_stage`, `fleet.scheduling`, `fleet.landing` and `fleet.budget.stage`, the safe side is the dormant or already-soaked option (off, shadow, wave, per-lane): a typo must never arm an unsoaked mode. `regression_tia` gives the plainest reason: selection that skips a predicate can hide a regression class. Two dials deliberately fall the other way. `boot.binary_refresh` resolves anything but an exact `off` to `auto`, because the self-heal is integrity posture. `fleet.plan_source` falls back to `manual`, not the `triage` default, as its spec requires. The fleet fallbacks also add a warning that names the rejected value.
- **Stage strings are not normalized.** `GatesConfig` passes words through verbatim, and consumers such as `reconcileManifest` compare them to the exact literal `"enforce"`, so `"Enforce"` does not arm a gate. `BridgeRecoveryStages` parses through `config.GateStage`, the Loader's own parser, so a bridge root that bypasses the Loader resolves every word exactly like the cycle root does.
- **Thresholds never resolve to zero by accident.** Numeric overrides apply only when positive (`MergeGateConfig`, `FailurePolicyConfig` thresholds, `ChainConfig`, and since cycle 1815 `ChronicleConfig`'s digest budgets and `FailureDispositionConfig`'s threshold, step and cap, so a negative cap can no longer push a recurrence weight below zero; `TestChronicleConfig_NegativeOverridesResolveToDefaults`, `TestFailureDispositionConfig_NegativeOverridesResolveToDefaults`). `DefaultChainMaxBatches` must stay positive, because a 0 cap would silently refuse to run a batch for an operator who asked to chain. `FleetConfig` keeps `Count ≥ 1` and clamps `MinLanes` to `Count`.
- **Weight floors.** `fleet.starvation_weight` clamps up to 0.9 here. `goal_stall.weight` accepts a lower value, but the item builder re-floors it to 0.9, so the effective floor is always 0.9: a stall signal is never a low-weight afterthought.
- **The effort lives in `cli_routing` (2026-10-08).** `cli_routing.tiers.<tier>` takes the list form (the chain) or the object form `{"clis": [...], "effort": "<level>"}`, the same pattern as `AgentRule`. `AgentRule` takes an optional `effort` beside `model`. An object with only an effort inherits the chain. `AgentRule` also takes `max_tier` and `max_effort`, the bounds of the retry ladder that `cliroute.Compile` checks (ADR-0142 L4). A chain-only `TierRule` writes back as a list.
  - `Policy.Efforts()` returns the `EffortTable`. `EffortTable.Resolve(tier, agents...)` is the one resolver. The order is the first agent key with an effort, the tier effort, then the compiled default `defaultTierEffort`. The default is fast `low` and `medium` for the other tiers. It also returns the source.
- **The order keys of an agent rule (2026-10-19, W4).** `AgentRule` takes an optional `order` and `headroom_pct` beside `model` and `effort`. This package only decodes them. `cliroute.Compile` checks them ([internal-cliroute.md](internal-cliroute.md), *The headroom order*). The fixture is `testdata/headroom-builder.policy.json` (`TestAgentRule_DecodesTheHeadroomOrderAndItsLimit`).
  - `EffortLevels()` returns a copy of the ordered vocabulary (`low` to `max`), like `TierNames()`. `ValidateEffort` refuses any other value. `policy.Load` and the routing compiler use it, with the same error text. An empty `TierRule` does not marshal.
  - Pinned by `TestCLIRoutingTiers_TakeTheListAndTheObjectForm`, `TestTierRule_MarshalsAChainOnlyRuleAsAList`, `TestEffortTable_ResolvesAgentThenTierThenTheCompiledDefault`, `TestTheCheckedInPolicy_EffortMatrix` and `TestTheCheckedInPolicy_PinsNoEffortAboveMedium`.
- **Kept in sync with a peer.** The `FailureDispositionConfig` defaults (threshold 2, step 0.03, cap 0.99) must equal `recurrence.DefaultEscalationPolicy`; `policy_disposition_test.go` pins that.
- **`RetryPolicyFor` ok=false means no retry**, never a default allow.
- **Resolvers hand out copies.** `WorkflowConfig` clones every slice and map it returns (`PhaseEnables`, `RemediablePhases`, `UniversalFallbackExclude`, `InteractivePolicies`, `SizeBudgetMultipliers`), so a caller that edits the result never changes the loaded policy or the next resolve (`TestWorkflowConfig_MutatingResultDoesNotChangeNextResolve`, cycle 1815). It assigns each remediation knob once; an explicit `0`, `[]` or `false` still wins.
- **`attempt_postmortem` is a strict block** (`policy_attempt_postmortem.go`, [ADR-0130](../adr/0130-a-retry-carries-the-evidence-of-the-attempt-it-replaces.md)). `AttemptPostmortemPolicy.UnmarshalJSON` decodes it with `decodeStrict` and validates the resolved `attemptpostmortem.Config`: an unknown key or a value below 1 fails `Load` naming `attempt_postmortem`. `AttemptPostmortemConfig()` gives `attemptpostmortem.DefaultConfig()` for an absent block, else the defaults with each set key over them; `suspect_window_s` is in seconds. `max_pane_capture_bytes` caps the pane capture of each dispatch and the pane read of the collector. Pinned by `TestAttemptPostmortemConfig_EachKeyOverridesItsCap` and `TestAttemptPostmortemPolicy_RefusesAnUnknownKeyAndANonPositiveCap`.
- **Only the `cli_routing`, `checkpoint`, `inbox_priority`, `attempt_postmortem` and `workflow.convergence` blocks are strict.** Each other block, and each other key of `workflow`, keeps the leniency of `json.Unmarshal`. Thus an unknown key in them is ignored. `TestLoad_KeysOutsideTheCLIRoutingBlockStayLenient` pins the boundary. These tests pin the strict side:
  - `TestLoad_CLIRoutingRejectsAnUnknownKey`;
  - `TestCheckpointPolicy_UnmarshalJSONRefusesAnUnknownKey`;
  - `TestLoad_InboxPriorityRefusesAnUnknownKey`;
  - `TestAttemptPostmortemPolicy_RefusesAnUnknownKeyAndANonPositiveCap`;
  - `TestConvergencePolicy_AnUnknownKeyIsRefused`.
- **Wire shapes are contracts.** `AdvisorSkillRejection` is written to `advisor-rejections.json`, so its JSON tags are pinned. The `bridge.phase_artifact_timeout_s` key and the compiled budgets must appear in runtime-reference.md, which `artifact_budget_docs_pin_test.go` checks by reflecting on the struct tag.

## Findings

- **2026-06-22 doc↔impl audit**: the `floor` key sat in the checked-in policy.json with no struct field, so `json.Unmarshal` dropped it and the gate enforced nothing. See [ADR-0062](../adr/0062-doc-impl-reconciliation.md).
- **cycle-440**: `BaseCLI` consolidated the duplicated `policy.baseCLI` and `bridge.baseCLIName`, adopting the semantics of the more-exercised `policy.baseCLI`: trim, then strip `-tmux` and `-p` repeatedly.
- **cycle-516**: adding the `top` tier. Until `TierRank` ranked it 4, it returned 0, and `ValidatePin`'s rank-0 exemption would have opened every deep-ceilinged profile to the frontier tier.
- **cycle-542 (C542_005)**: seed default values in the struct literal before the nil-block early return, so the absent-block path returns them too. `FleetConfig` seeds its starvation defaults that way.
- **cycle-573**: the shipped memo pin (`fast`) sat outside the memo profile's `[balanced..balanced]` envelope and logged an abnormal on every PASS cycle. The fix was config-only. Since 2026-08-14 the checked-in policy has no memo pin, so `memo_envelope_config_test.go` skips; it re-arms for any future pin.
- **cycle-980**: twelve judgment-light scan profiles carry a `{fast, balanced}` envelope; `secret-leak-scan` and `flake-rerun-scan` stay on their floor. Since 2026-10 (L2 of the CLI routing plan) the envelope is `{balanced, balanced}`: under the routing table a fast tier is Gemini 3.8 Flash (Low), and the operator runs every non-deep, non-top phase at Flash (High). `scan_tier_envelope_test.go` pins the shipped profiles; `internal/profiles` `TestNoTrackedProfileDefaultsToTheFastTier` refuses a fast bound on any tracked profile.
- **Goal-stall union breaker**: the empty-only goal-stall counter and the consecutive-FAIL breaker each reset on the other's outcome, so a goal alternating FAIL and EMPTY crossed neither ceiling and ran forever. `nonprogress_threshold` counts any non-shipping outcome. It defaults to 5, above the empty-only 3, because a mixed streak is noisier evidence.
- **Graduated remediation (2026-07-21 directive)**: coverage-gate FAILs were the measured waste class (cycles 983, 992, 1007, 1019, 1020). That set the default of one remediation round for `coverage-gate` only.
- **Size budgets (ADR-0076 A)**: under uniform budgets, batch-8 gave structural items about 10-minute build windows including corrections, which starved the verification tail. That motivated the size multipliers.
- **Halt ceilings**: `identical_fingerprint_halt_ceiling` comes from the cycle 862–899 storm (ADR-0072). `unexplained_failures_halt_ceiling` first fired in batch-6, where three distinct failures without a reason shared one degenerate fingerprint. `consecutive_failures_halt_ceiling` comes from the 2026-08-09 batch (runtime-reference.md). `lane_deferral_halt_ceiling` (default 3) comes from cycle 1806 (2026-10-06): a lane deferral writes no failure digest, so it needs its own ceiling, or a persistent provisioning fault would defer every lane without a halt. `FailurePolicyConfig` merges every threshold through `mergeThresholds` (a positive override wins, anything else keeps the default), pinned by `TestLaneDeferralHaltCeiling_DefaultsToThreeAndMergesFromOperatorPolicy` and `TestConsecutiveFailuresHaltCeilingMergesFromOperatorPolicy`.
- **`no_work_handoff_halt_ceiling`** (default 4) and **`no_work_handoff_window`** (default 12, 2026-10-20) bound the console hand-offs among the most recent cycles. Four of twelve is one lane in three, the partial regression the rule exists for. Pinned by `TestFailurePolicyConfig_TheNoWorkHandoffCeilingAndWindowHaveDefaultsAndComeFromPolicy`.
- **2026-10-01, `acs.predicate_env`**: the ACS suite began stripping every `EVOLVE_` key from the predicate environment, which also stripped the operator's `EVOLVE_FLAG_CAMPAIGN` and turned the ADR-0063 `flagprogress` gate off during a campaign. The key cannot be named in production Go: the `flagreaders` and `envtaint` regression gates read such a literal as an unregistered dial, and the flag registry is at its ceiling. Naming it in policy keeps the rule "strip the namespace except named, operator-owned keys" without a new flag.
- **F27 review**: before `BridgeRecoveryStages`, the bridge's own case-folding normalizer read `"Enforce"` as enforce while the cycle root read it as off. One parser now serves both.

## fleet.orchestrator.admission (ADR-0143 W1)

`OrchestratorConfig.Admission` is `shadow` by default. `enforce` moves the pool to the optimistic admission rule. Any other word is refused at parse. The key is independent of `fleet.orchestrator.stage`. `OrchestratorConfig.OptimisticAdmission()` is true only at `enforce`. The pool, the supply census and the wave shadow read it, so the three count by one rule.
- **The compiled routing defaults are one data file (X6, ADR-0154 I-6).** `routing_defaults.json` is embedded in the binary and decoded strictly once (`mustRoutingDefaults` panics on a malformed file, so a bad build cannot start). It holds:
  - `floors`: today's Claude floor. `DefaultFloors()` returns a copy. `Policy.Floors()` returns the `cli_routing.floors` key when it is present (`{}` means no floor) and the default otherwise. `Floors.FamilyOf(agent)` reads the first family in name order that lists the agent.
  - `seats`: the compiled default of each flow seat that has no route of its own. `phase-advisor` and `failure-advisor` are (`claude-tmux`, `deep`), and `plan-judge` is (`claude-tmux`, `fast`). `router` is `deep`. `contract-escalation`, `postmortem`, `observer`, `subagent`, `no-profile` and `wave-health` are `claude-tmux`. `SeatDefault(name)` reads one. The models are tier words; the manifest maps `deep` to the same model as the old `opus` (`bridge.translateV1TierKey`).
  - `classifier_families`, `unmeasured_order` and `universal_fallback_exclude`: the lists that `cliroute` and `WorkflowConfig` used as Go literals.
  - `CLIRouting.MarshalJSON` writes a non-nil empty `floors` as `{}`. Thus a write through `PatchBlocks` keeps a declared "no floor", and `evolve cli-routing unset floors.<family>` of the last family writes `{}` (`TestCLIRouting_AnEmptyFloorsKeySurvivesAWrite`). `unset floors` removes the key and returns to the default.
  - Pinned by `routing_defaults_test.go`, which also requires the checked-in `.evolve/policy.json` to strict-decode with the `floors` key and to hold the compiled default (`TestCheckedInPolicy_StrictDecodesWithTheFloorsKey`).
