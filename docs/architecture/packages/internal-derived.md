# internal/derived

> Decision record: [ADR-0128](../adr/0128-landing-queue-tiered-reverification.md); spec: [fleet-landing-queue.md](../fleet-landing-queue.md) §7.1; plan: [concurrent-cycle-landing-2026-10.md](../../plans/concurrent-cycle-landing-2026-10.md) component Q1.

## Purpose

`derived` is the one catalog of the generated outputs. It tells which paths a generator writes, with which marker or region, from which inputs, and which `evolve` verbs generate and check them. Each consumer reads this catalog and keeps no second list. Today the consumers are the post-build normalizer (`core.normalizeDerivedProjections`), the build floor (`core.DerivedFloorChecks`), the ship gate (`refuseStaleDerived` in `phases/ship`), the fleet rebase (`core.rebaseWithDerivedRegen`) and `evolve pr refresh`. The overlap proof (Q3) and the composition (Q4) read it next.

## Design

- **Five entries.** `flag-index` writes the `GENERATED:flag-index` region of `docs/architecture/control-flags.md`. `signal-codes` writes the `GENERATED:signal-codes` region of `docs/architecture/signal-codes.md`. `research-index` writes the `GENERATED:research-index` region of `docs/research-index.md` from the files in `docs/research-index/` (`evolve docs index`). `darwin-set` writes `go/.darwin-set` as a whole file with a marker (`evolve ci darwin-set`). `skill-projections` writes `commands/*.md`, `.codex-plugin/plugin.json` and `.agents/plugins/marketplace.json` as whole files, and the `GENERATED:phase-facts` region of `skills/*/SKILL.md`.
- **The darwin-set inputs.** Each changed `.go` file under `go/` makes it stale: the entry has `Inputs: go/` and `InputExt: .go`, and `isInput` requires the extension for a directory input. Before 2026-11-14 the entry had no input, so `Stale` never chose it. A lane that added a package did not regenerate the file, and `TestDarwinSetFile` failed on main. Now the regeneration after Build and `evolve pr refresh` both cover it. Pinned by the darwin-set cases of `TestStale_AnInputOrAHandEditedOutputMakesItsEntryStale`.
- **The floor and the ship gate check, the normalizer regenerates.** `core.StaleDerivedFindings` takes the changed paths. It selects the entries with `Stale` and runs the check verb of each. A check that exits non-zero is a finding. The finding names the entry and the generate verb of the entry, for example `evolve ci darwin-set generate`. It also holds the last 400 bytes of the check output, where the check names the file.
- **One source of the generate verb.** The catalog gives the generate verb, so no gate holds a second copy. When the input is broken, the output of the check names the broken file. The builder must fix that file first, and then run the generate verb.
- **A check that cannot run is not a finding.** `go run` returns exit 1 for any exit code of the program, so a non-zero exit of the check is a verdict.
- **What the floor and ship do with an error.** A start error is an error. A check that passes its deadline is also an error (`core.DerivedCheckDeadline`, 120 seconds for the whole run). At the floor, the error is a WARN with the signal `BUILD_DERIVED_FLOOR_SKIPPED`, and the floor passes. At ship, the error is a refusal of class transient. Ship never passes a tree that it cannot judge.
- **The order in a lane.** `prepareForReview` runs the normalizer before each floor round. The normalizer regenerates a stale index first, so the floor does not refuse it.
- **What the floor refuses.** The floor refuses what the normalizer cannot fix. An example is a research entry that starts with a blank line: `researchindex.readEntries` refuses it for the generate verb too.
- **What the ship gate refuses.** The ship gate runs after the audit binding. It refuses a tree that drifted after audit. Ship does not regenerate, because it must not change the audited tree. A `DERIVED_STALE` refusal of class precondition routes to the Build phase (`derived-stale-rebuild` in [internal-router.md](internal-router.md)), because the audit phase does not regenerate derived files.
- **One home for darwin-set.** The repo-contract pack runs `TestDarwinSetFile_MatchesTheSetDerivedFromTheTree` through a data-file row, and it runs before the ship gate. For `go/.darwin-set` the builder therefore sees the floor line of this catalog first, and at ship the pack refuses first. The catalog is the home of the rule. The pack row is CI parity, as [internal-repocontract.md](internal-repocontract.md) states.
- **No entry for the router recipes.** `agents/evolve-router.md` holds the `GENERATED:goal-recipes` region, but no `evolve` verb writes it. A conflict there is genuine.
- **Inputs.** An entry has path inputs (a prefix that ends in `/`, or an exact path) and, at most, one set of Go inputs. The caller resolves the Go inputs with `ResolveGoInputs`. `CodeRegistrars` are the directories of the Go files that call `RegisterCode(`. `SkillcheckClosure` is the main-module closure of `go/internal/skillcheck` from `go list -deps`. When `go list` fails, `ResolveGoInputs` returns the error and keeps the registrars that it found.
- **Staleness.** `Stale(changed, dirs)` gives the entries whose inputs or outputs one change touched. The normalizer uses it. An output in the change can be a hand edit that its generator does not make. The normalizer refreshes each stale entry. A refresh regenerates only when the check verb fails, so an output that is in sync costs one check.
- **Firing.** `Fires(lane, peer, conflicted, dirs)` gives the entries that fire for a composition (spec §7.1). An entry fires when a conflicted path is one of its outputs. It also fires when one side touched an input and the other side touched an input or an output. No consumer calls `Fires` yet. The composition and the overlap proof of the landing queue (Q3, Q4, Q13, Q14) read it.
- **The conflict class.** For a whole-file output with a marker, `IsDerivedConflict(path, merged)` is true only when both sides of the file carry the marker. Our side is the text outside the blocks plus the first part of each block. Their side is the text outside the blocks plus the last part. A JSON manifest has no marker, so its conflict is always derived.
- **The region class.** For a region output, `IsDerivedConflict` is true only when the file has the region and each conflict block lies strictly inside it. A file with no closed block is genuine.
- **Regeneration.** `Worktree` binds a generator, a git runner and a base. `Regenerate` runs the generate verb, then the check verb, then `git diff --check <base> -- <outputs>`. Exit 0 is clean. Exit 2 with a leftover conflict marker is an error, and exit 2 with only a whitespace report is not. Each other exit is an error, so a bad pathspec cannot pass the check.
- **Refresh.** `Refresh` runs the check verb first, and regenerates only when the check fails.
- **The generator is the one of the worktree.** The package does not run `evolve`. `core` passes a generator built on `WorktreeEvolveInvocation`, which runs `go run ./cmd/evolve` in the worktree with the worktree root key. The host binary never regenerates.
- **Markers.** A region output has a BEGIN and an END line. A Markdown whole file has `Output.Marker`. The JSON manifests carry no marker, because JSON has no comment.
- **Protected surface.** The package is on the protected surface (`guards/integrity_surface.go`), because it decides which conflicts the protected recovery regenerates. Pinned by `TestProtectedSurfaceManifest_CoversTheDerivedOutputCatalog`.

## Invariants

- **The catalog matches the tree.** Each output matches a file, and each whole-file Markdown output and each fixed region output carries its markers. Pinned by `TestCatalog_EveryOutputCarriesItsGeneratedMarker` and `TestCatalog_EveryInputExists`.
- **The skill projections are outputs.** Pinned by `TestCatalog_SkillProjectionsAreDerivedOutputs`.
- **The router recipes are no entry.** Pinned by `TestCatalog_TheRouterRecipeRegionIsNotAnEntry`.
- **A block inside the region is derived, and a block outside it is genuine.** Pinned by `TestRegionConflict_ABlockInsideTheRegionIsDerived` and `TestRegionConflict_ABlockOutsideTheRegionIsGenuine`.
- **Each entry declares an input.** An entry with no input is never stale, so no consumer checks it. This was the cause of the 2026-11-14 red main (see Findings). Pinned by `TestCatalog_EveryEntryDeclaresItsInputs` and `TestStale_AGoFileUnderGoSelectsTheDarwinSet`.
- **A failed check is a finding, a check that cannot run is an error.** Pinned in `core` by `TestDerivedFloor_ANewPackageWithoutDarwinSetNamesTheGenerateVerb`, `TestDerivedFloor_ABrokenResearchEntryNamesTheInputTheCheckReports`, `TestDerivedFloor_ACheckThatCannotRunIsFailOpenAndWarns` and `TestStaleDerivedFindings_ADeadlineIsAnErrorNotAFinding`. Only the entries that the diff touches run. Pinned by `TestDerivedFloor_RunsOnlyTheChecksOfTouchedEntries`.
- **Ship refuses a derived file that fails its check.** Pinned in `phases/ship` by `TestShip_CycleRefusesAResearchEntryThatStartsWithABlankLine`, `TestShip_CycleRefusesAValidNewEntryWithAStaleIndexAndNamesTheGenerateVerb`, `TestShip_CycleShipsWhenTheDerivedFilesAreInSync`, `TestShip_ACheckThatCannotRunIsATransientRefusalNotAPass` and, with the real generator on a clone, `TestShip_TheRealGeneratorRefusesABlankLeadingEntryOfACloneAndPassesACleanOne`.
- **A hand-edited output makes its entry stale.** Pinned by `TestStale_AnInputOrAHandEditedOutputMakesItsEntryStale`.
- **Cross staleness needs both sides.** Pinned by `TestFires_CrossStalenessNeedsBothSides`.
- **A leftover conflict marker fails the regeneration.** Pinned by `TestRegen_RefusesALeftoverConflictMarker`.
- **Two research-index PRs merge in either order to one index.** Pinned in `researchindex` by `TestTwoEntryPRs_MergeInEitherOrderToOneIndexWithNoHandMerge`.
- **The rebase regenerates a conflict in a command stub.** Pinned in `core` by `TestRebaseWithDerivedRegen_ACommandStubConflictRegenerates` and `TestRegen_UsesTheGeneratorOfTheWorktree`.

## Findings

- **The wave-171 class** (2026-11-14): main went red at `ba124fd27`. A lane added `go/cmd/testlatency` and did not regenerate `go/.darwin-set`. The cause was a selection gap: the darwin-set entry had no inputs, so `Stale` never chose it. PR 1462 added `Inputs: go/` and `InputExt: .go`.
  PR 1538 added a data-file row. That row makes the repo-contract pack run `TestDarwinSetFile_MatchesTheSetDerivedFromTheTree` at the floor and at ship.
- **The gaps after PR 1538.** Three gaps stayed. A malformed research entry made only a normalizer WARN, and no gate refused it. A normalizer failure for any entry failed open. The correction text named `make -C go darwin-set`, not the generate verb of the catalog. The floor check and the ship gate close these gaps.
- **Cost, not yet measured on Go 1.23.** Go 1.23 keeps no cached executable for `go run`, so each check links `cmd/evolve` again. The deadline bounds the run. A build of the worktree binary once, then one run of each check with it, removes most of this cost. This work is open.

- **The cycle-1841 class** (2026-10-09): a peer regenerated the 32 command stubs while a lane was open. The old rebase catalog held only `control-flags.md`, so a rebase whose only conflicts were in those stubs went to the debugger. Now the rebase regenerates the stubs with the generator of the worktree.
- **The cycle-2123 class** (2026-11-03): the build of cycle 2123 added a row to `docs/research-index.md` by hand, with no entry file under `docs/research-index/`. `Stale` then read only the inputs, so the normalizer did not refresh the index, and main shipped out of sync at 3491a4878. On that main, the precondition of `TestPRRefresh_TheRealGeneratorsOfACloneCommitOnlyTheStaleIndex` failed in each lane. Cycle 2121 failed with the class infra-systemic, and the failure decision cites the same offender in cycles 2111 and 2113. Now a touched output also makes its entry stale, and the normalizer removes the hand row before audit.
