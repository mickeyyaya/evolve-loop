# internal/bridge/phaseidentity

> Decision record: [ADR-0106](../adr/0106-logic-first-delivery.md) (logic-first delivery, component P3). Design: [logic-first-delivery-design.md §5.4](../logic-first-delivery-design.md#54-the-agents-identity-and-its-pane).

## Purpose

`phaseidentity` renders the two statements a tmux driver gives a phase pane. `Authority()` is the standing statement, identical on every dispatch: the operator launched the evolve pipeline that runs this pane unattended, the pasted prompt is the operator's instruction for the phase, and the console's interactive conventions are not this pane's; it is claude-tmux's system prompt and is pasted by a CLI without that channel. `Block(Facts)` is the facts statement a tmux driver appends to the bytes it pastes into a phase pane: which phase and cycle the agent is, which tmux session it runs in, which files the bridge wrote to deliver the prompt, and which artifact it alone writes. An agent that inspects its environment then recognises its own traces. Cycle 1707's tdd agent listed the tmux sessions, found its own, read its own prompt file, and refused the phase as a prompt injection racing "the real agent"; an operator's one-line identity clarification resumed it an hour later. The block says that line before the agent needs it.

## Design

- **A pure projection of facts.** `Block(Facts) string`: no I/O, no clock, no CLI branch. `Facts` holds `Agent`, `Cycle`, `Session`, `PromptFile` (the prompt the engine composed), `PastedFile` (`resolved-prompt.txt`, the exact bytes pasted) and `Artifact`.
- **Only true claims.** A phase whose answer the bridge reads from the pane (`completion: stdout`, the router and the advisor) never writes the artifact, so the driver passes no artifact and the sole-writer line becomes "The bridge reads your answer from this pane". `TestBlock_WithoutAnArtifactStatesThePaneIsRead` and `TestTmuxDispatch_StdoutCompletionClaimsNoArtifact` pin it.
- **Null object for a pane that is no phase.** `Block` returns `""` when `Agent` or `Session` is empty: a probe pane has no phase to be, and a headless run has no pane to speak of. The driver appends nothing rather than a half-true statement.
- **The wording is the component.** `Block` has four lines: the phase (and the cycle when numbered); the session name; the two prompt files and that finding them is expected; and the sole-writer fact with the standing instruction not to kill, pause or hand off the session or wait for an operator. `Authority` has three lines, under its own heading (`AuthorityHeading`): the operator's instruction, to be carried out by reading the files the prompt names and writing its deliverable; and that instruction files written for the console operator's interactive sessions (confirm direction, stop and ask when something is unclear, rules about bridges, guards and in-process agents) describe those sessions, not this one, so the agent makes the reasonable call and records it in the deliverable. The third line tells the agent that the tmux server of the run holds this pane and the panes of the other phases, and that it must never run `tmux` without its own `-L <private-socket>`, never run `tmux kill-server`, and never kill, pkill or killall `tmux` or a process it did not start. `TestAuthority_AuthorizesThePasteAndScopesTheConsoleConventionsAway` pins it; it states no per-dispatch fact, so its bytes, and a system prompt made of them, are the same on every spawn. `TestBlock_StatesEveryTraceTheAgentCanFind` pins the block byte for byte.
- **The two paragraphs of the Opus 5.5 manual (2026-10-08).** After its three lines, `Authority` ends with two paragraphs quoted exactly from the manual ([Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)). The first is the paragraph of the section "Unattended agentic runs": it names four kinds of early stop that the pane must not make. Its last sentence keeps the need for confirmation on risky or destructive actions. The second is the system note of the section "Mark pasted text in user messages".
  - `TestAuthority_EndsWithTheManualParagraphsQuotedExactly` pins the words of both. Each sentence is on its own line, so no line has 1024 bytes or more. A line-mode REPL in a canonical-mode tty cannot take a longer pasted line, and the rest of the paste stops there. `TestAuthority_EveryLineFitsACanonicalModeTTYLine` pins the limit.
  - The text is a quotation from the manual, so the house STE rules do not apply to it.
- **`WrapPasted(text)`** encloses inbox text that a prompt builder inlines in `<pasted_content id="<id>">` and `</pasted_content id="<id>">`, each tag on its own line. The id is 16 hex characters from 8 bytes of `crypto/rand`, new for each block, so the inbox author cannot write a matching closing tag. If `crypto/rand` fails, the id comes from the clock and a counter, and the prompt builder does not stop. Empty text gives no block. The triage `inbox_batches` note and the advisor lane scope use it. Pinned by `TestWrapPasted_EnclosesTheTextBetweenTagsWithOneRandomID`, `TestWrapPasted_EachBlockGetsAFreshID`, `TestWrapPasted_AFailedRandomSourceStillGivesDistinctIDs` and `TestWrapPasted_EmptyTextGivesNoBlock`.
- **`Heading`** (`## Who you are (stated by the evolve bridge)`) is the one spelling the drivers and their tests look for.
- **Placement is the caller's.** `driver_tmux_prepare.go` writes `Authority` to the system prompt file when the driver's realization carries a `SystemPromptFile` and otherwise pastes it before the facts; it appends `Block` after the composed prompt, so the engine's bytes stay a stable prefix (the cached skill and policy blocks hold across dispatches) and the deliverable path stays the last thing the agent reads.

## Invariants

- **Every trace is named verbatim.** Session, both prompt paths and the artifact path appear exactly as the driver holds them; a swapped path is caught by the golden (`TestBlock_StatesEveryTraceTheAgentCanFind`).
- **No agent, no session → no block.** Pinned by `TestBlock_NeedsAnAgentAndASession`.
- **Cycle 0 is unstated**, never "cycle 0". Pinned by `TestBlock_UnnumberedCycleIsNotStated`.
- **One heading, a terminated last line.** Pinned by `TestBlock_OpensWithTheHeadingOnce`.
- **A fact stays on its line and inside its code span.** Control bytes and backticks are dropped from every fact before it is rendered, so a hostile agent name or path cannot append markdown that reads as the bridge's own instruction. Pinned by `TestBlock_AFactCannotBreakOutOfItsLine`.
- **No manifest pattern matches the block.** The auto-responder drops pane lines that echo the injected prompt before it scans for a wall; `TestIdentityBlockMatchesNoManifestPattern` (package `bridge`) keeps every `interactive_prompts`, `exhausted_regex` and `transient_regex` from matching the block's text.
- **Standard library only**, so the package never imports `bridge`.

## Findings

- 2026-10-09 (cycle 1853, wave 89): a builder agent killed the run's tmux server ([incident](../../incidents/cycle-1853-tmux-run-server-kill.md)). The block no longer tells the agent to run `tmux display-message` or to look at `tmux ls`. The pane shell has no `TMUX` now, so those commands do not reach the run server. `Authority` got the line that forbids `tmux` without a private `-L` socket. The line also forbids `tmux kill-server` and a kill of a process the agent did not start.

- 2026-10-08: the Opus 5.5 manual says that an unattended loop stops when a turn ends with text only. It also says that marked pasted text resists the instructions inside it. `Authority` got the two manual paragraphs, and `WrapPasted` came for the inbox text ([plan](../../plans/opus55-effort-config-2026-10.md)).
- 2026-09-27: review found the sole-writer line false for stdout-completion phases (the router never writes its artifact); the driver now passes no artifact for them and the block states the pane is read.
- 2026-09-26: built as ADR-0106 P3 with ten mutants (both gates, the cycle guard, a doubled heading, each fact swapped or dropped, the trailing LF) all killed by the four tests.
- 2026-09-28 (cycle 1734, T3): claude declined the whole paste, this block included, as "untrusted pasted text, not something you asked me to do", citing the project CLAUDE.md's "confirm direction" and "surface ambiguity" rules, and declined the bridge's typed nudge the same way. The standing authority (the operator's instruction, the conventions scoped away from the pane) became its own block and claude's system prompt; the facts stay in the paste.
