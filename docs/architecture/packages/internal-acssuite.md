# internal/acssuite

## Purpose

`internal/acssuite` is the deterministic, host-side EGPS predicate-suite runner (ADR-0042): it runs the Go predicate lane over three scopes (this cycle, curated regression, red-team) as separate `go test -json -tags acs` invocations and writes the `acs-verdict.json` schema the audit and ship gates read. The `evolve acs suite` CLI (`cmd/evolve/cmd_acs.go`) calls `Run` directly; the audit and ship phases (`internal/phases/audit`, `internal/phases/ship`) and the cycle orchestrator (`internal/core`) read its `Verdict`/`Result` types and use the evidence-sealing functions (`SealEvidence`, `VerifyEvidence`) to bind a verdict to the audited tree before a cycle can ship.

## Design

- **The verdict is always complete ([ADR-0114](../adr/0114-the-acs-verdict-is-always-written-and-complete.md)).** `Run` returns an error only for options it cannot run at all (no `Root`, a cycle that is not positive, a root it cannot make absolute). Every other outcome is a `Verdict`, and anything that kept predicates from producing evidence is a harness red in it: a result whose `ac_id` starts with `acsverdict.SyntheticRedPrefix` (`egps/`), exit code 1, whose `evidence_excerpt` carries the reason and whose full text lands in `acs-red-evidence/`. The shapes are:
  - `egps/no-predicates`: no Go predicate tree (`<moduleDir>` lacks `go.mod` or `acs/`), no active scope for the cycle, or no scope produced a single result. A cycle with nothing to prove is a FAIL that says so, never an empty PASS and never a missing file;
  - `egps/go-lane-scope-failed/<scope>`: a scope exited nonzero with no red of its own (a compile error, a `go list` failure), declared tests never ran (`errIncompleteInventory`, the TestMain filter class), or the lane budget ran out. The results the scope did produce stay beside it, the reason carries the process error and the scope's output, and the red counts in its scope's `predicate_suite` bucket (`classifyGoPkg` on the scope's last element; `TestRun_AScopeFailureIsCountedInItsOwnScopesBucket`);
  - `egps/go-lane-parse-error` and `egps/go-lane-incomplete/<test>`: a truncated stream or a test with no terminal result, as before.
  A harness red is an ordinary red to every reader (`record`, `ReadVerdict`, the audit and ship gates), so `red_count==0` stays the only path to PASS. `retryFlakyReds` never retries a scope that carries one. The audit gate appends the first harness red's reason to its EGPS diagnostic, so `audit-fail-reason.json` names the cause.
- **The predicate environment (`predicateEnv`) is the suite's own.** It starts from `ipcenv.Scrub(os.Environ())`, which drops every `EVOLVE_` key, drops the suite's own export keys from the host environment too (so a caller's stale `CHANGED_PACKAGES`, which the scrub would keep, never reaches a predicate), and adds two named sets (`predicateExports`): the operator-owned keys the state root's policy names in `acs.predicate_env`, copied from the host environment when set (`entriesNamed`; the checked-in policy names `EVOLVE_FLAG_CAMPAIGN`, which `regression/flagprogress` reads to arm the ADR-0063 gate), then the suite's own exports (`suiteExportKeys`: `EVOLVE_PROJECT_ROOT`, the worktree-root key and `CHANGED_PACKAGES`).
- **`acs.predicate_env` is bounded, in one place (`forwardableKeys`).** An entry that is a lane protocol key (`ipcenv.ProtocolKeys`: fleet, scope, width, worktree root, cycle-state file, tmux socket) or one of the suite's own exports is refused: it is not forwarded, `[acs] WARN` names it on stderr, and the verdict's `warnings` carry `acs.predicate_env names <key>, …; it is not forwarded`. The refusal happens when the lane reads its policy (`loadLaneConfig`), not in `policy.Load`: the policy package is shared by every loop consumer and a load error there fails the phase runner, the suite's exports are this package's own names (the policy package cannot import them without a cycle), and refusing one entry keeps the rest of the forward (the flag-campaign key) working. Only the state root's policy is read, never a cycle worktree's (`TestRun_ACycleWorktreesPolicyCannotWidenTheForwardedKeys`). A fleet lane's `EVOLVE_FLEET`, scope, width, cycle-state file and tmux socket never reach a predicate, or an inner `go test` a meta-predicate shells, because that child inherits the predicate's environment. The toolchain keys (`PATH`, `HOME`, `GOFLAGS`, `GOCACHE`, …) survive. The operator keys are named in policy, not in Go, because a production Go literal of an `EVOLVE_` key is an unregistered dial to the `flagreaders` and `envtaint` regression gates, and the flag registry is at its ceiling ([ADR-0114](../adr/0114-the-acs-verdict-is-always-written-and-complete.md), alternatives).
- **The dual-root pattern.** `EVOLVE_PROJECT_ROOT` (the state root) resolves `.evolve/` to main even when the suite runs from a cycle's worktree. The worktree-root key (the source root, `internal/ipcenv`) points a doc-validating predicate (e.g. `evolve flags check`) at the cycle's committed artifact instead of main's stale copy. `CHANGED_PACKAGES` carries the cycle's touched packages so a predicate can scope `go test` to them.
- **One state root (`Options.stateRoot`).** Every `.evolve/` path the suite reads or writes resolves under `ProjectRoot`, or under `Root` when the caller named none: the policy that sets the lane budget and the forwarded operator keys (read once per run, `loadACSConfig`), the build handoff behind `CHANGED_PACKAGES`, the red-evidence directory and the `EVOLVE_PROJECT_ROOT` a predicate receives. The verdict's own `project_root` stamp still records only what the caller passed, so an unstamped verdict stays unstamped.
- **Absolute roots.** `resolveOptions` makes `Root`, `ProjectRoot` and `GoModuleDir` absolute before anything runs, so no path the suite derives depends on the process cwd, and the `suite_root`/`project_root` stamps are absolute. `WriteVerdict` refuses a relative evolve dir outright; `evolve acs run|suite` resolve `--evolve-dir` to an existing directory first.
- **One shared lane budget (`laneBudget`).** `acs.go_timeout_s` (else `DefaultTimeout`) is a single deadline for the whole Go lane, shared by every scope, not a per-scope allowance: the suite holds the host-wide single-flight lock for the whole run, and a per-scope budget of N scopes could hold it far past `maxLockWait`, turning every sibling lane unserialized. A scope that finds the budget spent is never started; it is reported as `…budget … was spent before this scope started`. A scope the deadline killed carries `…expired while this scope ran: context deadline exceeded` beside whatever it produced. Pinned by `TestRun_TheGoLaneBudgetIsOneDeadlineSharedByEveryScope`.
- **Host-wide single-flight (`Run`, ADR-0080 P1).** Fleet lanes are separate processes each shelling full package suites; run concurrently they oversubscribe the host and produce false reds. Verification MUST run, serialized, never skipped — but a wedged holder degrades the lane to unserialized (WARN) rather than deadlock the fleet. The lock wait is bounded (`maxLockWait`) precisely so that degrade path stays reachable.
- **The scope lint (`scopelint.go`) demotes an out-of-scope meta-predicate to SKIP** rather than letting it false-fail a cycle: a whole-suite sweep (e.g. "go test \<core+bridge+recovery\> stays green") samples everything in those packages, so an auditor probe, a shared test fixture root, or a concurrent lane looks like a builder regression. Whole-repo staleness is the regression suite's job, not a cycle predicate's. Its known conservative limitation: a pattern assembled by string concatenation or returned from a helper function is invisible to it — a missed broad predicate merely stays un-demoted (the safe direction), and the demotion floor (see Invariants) bounds what a deliberately-broad authoring style could hide.
- **`phantomBindings` (`phantom_binding.go`) distinguishes a red whose bound test never ran from one that genuinely failed.** Cycle-suite predicates commonly delegate to a named "binding" test in a production package (`go test -run '^(Name)$' <pkg>`, then require `--- PASS: Name`); that bind is identity by name across a package boundary, and the name can silently stop resolving (a renamed test, or one never written). Such a predicate reds forever otherwise: `go test -run` on a pattern matching nothing exits 0 with "no tests to run", the assert reports "did NOT pass", and the red reaches the gate as a bare, unactionable count. The discriminator is deliberately not the bare "no tests to run" string (that only appears when nothing matched); it also covers the partial shape — siblings matched, the renamed one silently didn't. FailingTests is the source of truth because it is extracted from the full output before the excerpt cap, so truncation cannot fake a phantom. Anti-gaming boundary: this classification never changes the verdict — a phantom red is still red (skipping it would make deleting a test the way to green a gate); what changes is that the red now names its own cure.
- **`excerpt()` keeps head+tail, not just head**, because a predicate's own diagnosis line prints first but go test accumulates `--- FAIL:` detail in the tail; pure head-truncation used to lose the failing test's identity entirely (see Findings).
- **`goLanePatterns`/`runGoTest` run the three scopes as SEPARATE `go test` invocations** (never a recursive `./acs/regression/...`) so one sub-package's compile error can't hide behind another's events (ADR-0042). Only the current cycle, the curated regression set and the red team run, never every historical cycle, which would drag bit-rotted point-in-time predicates into the gate.
- **The `GoExec` seam fixes the scope list** (`CyclePackage(cycle)`, `./acs/regression/...`, `./acs/redteam`) independent of the filesystem, and the seam decides each scope's output: empty output with no error is an inactive scope. In production an active scope cannot be empty without an error, because `executeCompleteGoScope` fails any scope whose declared tests did not all report.
- **`parseGoTestJSON` keys results by `Package+"/"+Test`**, not bare `Test`, so the same test name in two packages stays two distinct results.
- **`goLane.retryFlakyReds`**: a scope with at least one real red (and no synthetic `egps/` parse-error red) is re-run exactly once. A red that passes on retry flips to green with `Flaky="passed-on-retry"` (first-run evidence retained deliberately — the flake's signature); a red that stays red keeps `RetryOutcome="red-on-retry"`; no result on retry gives `"retry-inconclusive"`. Bounded to one retry, annotated on the wire, surfaced as a verdict warning — never silently absorbed.
- **`defaultGoExec` sets `cmd.WaitDelay`** because `CommandContext` only kills the direct `go` process, not test-binary grandchildren spawned by meta-predicates that shell an inner `go test`; without a delay a surviving grandchild pins the `CombinedOutput` pipe past ctx expiry and the held single-flight lock starves every other lane.
- **`demoteOutOfScope` and `writeRedEvidence` ordering**: a red demoted to skip must leave no phantom red-evidence file, so the forensic surface matches the verdict.
- **Every `go/acs/**/predicates_test.go` must carry the `//go:build acs` constraint** (`TestAllACSPredicatesAreTagged`, tagguard_test.go): EGPS predicates are state/environment assertions, not unit tests, and must not run in the normal `go test ./...` / CI suite. The `acs` tag is what excludes them from the normal suite and includes them in the host-side Go predicate lane (`go test -tags acs ./acs/...`).
- **The verdict's names live in `internal/acsverdict`**: the file name, `Path` (which refuses a relative evolve dir), the harness-red prefix and `NoPredicatesID`. `WriteVerdict` writes through `acsverdict.Path`, and `noPredicatesRed` builds the suite's red from `NoPredicatesID`; `acsrunner` uses the same names without importing this package, so the two writers of `acs-verdict.json` cannot drift (`acsrunner.TestNoPredicates_BothVerdictWritersNameTheSameHarnessRed`).
- **Files.** `acssuite.go` holds the options, the verdict, the predicate environment, the parser and the writer; `golane.go` holds the Go lane itself: `goLane` and its scopes, the harness reds, the shared budget and the flake retry.
- **`WriteVerdict`** uses a random tmp-file suffix (not PID) so concurrent same-process writers to the same cycle dir cannot collide.

## Invariants

- `red_count==0` is the only path to PASS/`ship_eligible` (ADR-0042); `record()` is the single place `RedCount` increments, and a skip increments neither `GreenCount` nor `RedCount`.
- A flaky predicate's first-run failure evidence is retained deliberately (the flake's signature) and is never silently absorbed; it is visible on the wire as `Flaky="passed-on-retry"`. Pinned by `go/acs/cycle468`: a deterministic red carries no `flaky` key; retry outcomes for a red that stays red live in `RetryOutcome` instead.
- A scan error while parsing `go test -json` output must never silently truncate the stream: `parseGoTestJSON` emits a synthetic red (`egps/go-lane-parse-error`) so the verdict blocks rather than silent-passing on a partial parse. A synthetic `egps/` red also suppresses any retry (a truncated stream is not retryable evidence).
- A predicate scope that could not produce complete evidence is a named harness red in the verdict, never an error that leaves no verdict and never a silent pass: a compile error (`TestRun_ANonCompilingScopeIsANamedRedCarryingTheCompilerOutput`, `TestGoLane_PerScopeCompileError`), declared tests that never ran (`TestRun_AnIncompleteInventoryIsANamedRedKeepingWhatRan`, `TestRun_AnIncompleteInventoryIsNamedEvenBesideARealRed`), a spent or expired lane budget (`TestRun_AScopeLeftWithoutBudgetReportsTheSpentDeadline`, `TestRun_AnExpiredLaneBudgetIsReportedAsTheDeadlineNotAsAnEmptyScope`, `TestRun_AScopeTheDeadlineKilledMidRunSaysSoBesideItsReds`), and no predicates at all (`TestRun_NoGoPredicateTreeIsARedVerdictNamingTheMissingTree`, `TestRun_AGoTreeWithNoActiveScopeIsARedVerdict`, `TestRun_ASeamWithEveryScopeInactiveIsARedVerdict`). Each of those tests also reads the verdict back through `ReadVerdict`, so the harness red is a well-formed FAIL the ship gate refuses.
- No predicate sees a key from the `EVOLVE_` namespace except the suite's own exports and the operator keys `acs.predicate_env` names (`TestRun_PredicatesSeeNoLaneIPCEnvironment`, `TestRun_WithoutAProjectRootPredicatesGetTheSuiteRootAsTheStateRoot`, `TestRun_PredicatesSeeTheOperatorKeysThePolicyNamesAndNoOther`, and `TestRun_ARealPredicateInAFleetLaneSeesNoLaneKeys`, which runs a real `go test` under a fleet lane's environment). A policy entry naming a lane protocol key or a suite export is refused with a warning in the verdict (`TestRun_APolicyCannotForwardALaneProtocolKeyOrASuiteExport`); only the state root's policy decides the forward (`TestRun_ACycleWorktreesPolicyCannotWidenTheForwardedKeys`); a caller's `CHANGED_PACKAGES` never reaches a predicate (`TestRun_ACallersChangedPackagesNeverReachAPredicate`).
- Every `EVOLVE_` key a curated predicate (`acs/regression/*`, `acs/redteam`) reads through `os.Getenv` or `os.LookupEnv` reaches it under the checked-in policy (`TestCuratedPredicatesReceiveEveryEvolveKeyTheyRead`, which parses the predicates, resolves same-package constant keys, and fails on a read it cannot resolve). The reverse holds too: every checked-in `acs.predicate_env` entry is read by some curated predicate (`TestCheckedInPredicateEnvNamesOnlyKeysACuratedPredicateReads`, same scan). A real regression predicate in a fleet lane sees an active flag campaign (`TestRun_ARealRegressionPredicateInAFleetLaneSeesTheFlagCampaignKey`, against the checked-in policy).
- `CyclePackage` is the only spelling of a cycle predicate pattern in the package's code (`TestCyclePackage_NoOtherCodeInThePackageSpellsACyclePattern`).
- `demoteOutOfScope` never lets a cycle ship with its whole own predicate set demoted (the demotion floor): if demotion would leave zero live (non-skip) own predicates, all demotions for that cycle are cancelled and a warning explains why — a cycle whose only predicate is broad keeps its red instead of vanishing it. Pinned by `TestRunGoTest_DemotionFloorCancelsWhenAllOwnPredicatesWouldSkip` and `TestRunGoTest_DemotesOutOfScopeMetaPredicateToSkip`.

## Findings

- **issue #9 / #12**: audit running with cwd=worktree meant `Root` was the worktree, so `.evolve/` state resolution silently missed main. `ProjectRoot` / `EVOLVE_PROJECT_ROOT` were introduced to keep state resolution pointed at main regardless of which worktree the suite runs from.
- **cycle 106**: a Go-native EGPS predicate asserting "no uncommitted changes" ran in the normal `go test ./...` / CI suite and was false mid-edit — a state/environment assertion is not a unit test. This is why every predicate file needs the `//go:build acs` constraint, enforced by `TestAllACSPredicatesAreTagged`.
- **cycle 200**: `CHANGED_PACKAGES` was added so a predicate can scope `go test` to the cycle's touched packages.
- **cycle 215**: the builder-written handoff the scope lint could have read had gone extinct, making a handoff-based lint dead code on every live cycle; the lint now derives its touched-package set from git only, never the (agent-authored) handoff.
- **cycle 355**: a doc-validating predicate (e.g. `evolve flags check`) read main's stale copy of a generated doc instead of the cycle's worktree, red-failing correct work because the doc only reaches main at ship, after audit; `predicateEnv` now exports the worktree as the source root for such predicates.
- **batch 16**: fleet lanes running full package suites concurrently oversubscribed the host and produced false reds (`TouchedPackagesStayGreen` red on cycles 1166/1167/1169, green in the preserved worktree) — an identical-fingerprint halt over infrastructure, not the code. The suite execution is now host-wide single-flight (ADR-0080 P1); an unbounded lock wait would have made the unserialized-degrade path unreachable, so the wait is bounded (`maxLockWait`) instead.
- **cycle 468**: `parallel_evaluate=enforce` runs the -race predicate suites under concurrent evaluate-phase host load; contention flakes burned four verified-good cycles (444, 447, 466 and 467) before `retryFlakyReds` bounded a single retry per scope.
- **cycles 1115, 1116, 1117 and 1123**: each FAILed on one predicate shaped like "go test \<core+bridge+recovery\> stays green" — a whole-suite sweep that samples everything in those packages, so an auditor probe, a shared fixture root, or a concurrent lane looked like a builder regression. Out-of-scope meta-predicates are now demoted to SKIP instead (scopelint.go).
- **cycles 1107, 1115, 1116, 1117 and 1123**: measured across all five red predicates, `evidence_excerpt` was head-truncated at `evidenceMax`, and a go-test run's first 600 chars are compiler/WARN noise — "--- FAIL:" appeared in none of them, and for 1107/1116/1123 the failing test name was permanently unrecoverable from disk, so those cycles' false reds could never be confirmed or refuted. `excerpt()` is now tail-anchored (Go test output accumulates assertion detail and the FAIL line at the end), and `FailingTests` now extracts inner failing-test identity from the full output before the excerpt cap applies.
- **cycle 1117**: a predicate referenced its out-of-scope package pattern only through a package-level const (a `bridgePkg`-shaped indirection), invisible to a literal-only scan. `LintPredicateScope` now resolves const indirection too.
- **cycle 1434** (ADR-0072 halt): a verdict minted under the wrong state root red-failed three predicates that the correct-root run showed green, and the artifact recorded nothing about which roots it was minted under — the misdiagnosis was invisible from the file. `Verdict` now stamps `SuiteRoot`/`ProjectRoot`; readers treat absence as "unstamped" (pre-stamp verdicts stay honored), never as a mismatch.
- **cycle 1532**: a continuation cycle renamed bound tests (or a builder never wrote them), so a binding silently stopped resolving and its predicate reded forever with no actionable cause — the trigger case for the phantom-binding class below.
- **cycles 1539–1546**: an absorbing streak of phantom-binding reds — a continuation chain reds forever once a bound test's name stops resolving, since the underlying assert can never re-pass. This class dominated the streak; PR #486 cured one instance with a 2-line binding repoint that took a full console session to diagnose. `phantomBindings` now names a phantom binding directly instead of leaving it a bare, unactionable red.
- **batch 18, cycles 1173, 1175 and 1178**: three false reds were undiagnosable after the fact because the 600-byte excerpt elides the MIDDLE of the inner go-test stream (the same lesson class as 1107/1116/1123, which FailingTests only partially fixed: names survive, assertions do not). A confirmed red was also indistinguishable from a starved retry in the forensic record. The red predicate's complete captured stream is now persisted to acs-red-evidence/ (`fullEvidence`) instead of relying on the capped wire excerpt, and `RetryOutcome` now records `"red-on-retry"` vs `"retry-inconclusive"`.
- **cycle 949**: the cycle's predicate package did not compile (`undefined: core.WithJudgeModel`). The suite returned an error, the audit wrote no verdict, and the only diagnostic an operator saw was `acs-verdict.json: read: no such file or directory`; the real cause sat in the retrospective's log. PR #535 carried the compiler excerpt into `audit-fail-reason.json`; the verdict itself now names the cause (`egps/go-lane-scope-failed/acs/cycle949`), so no layer sees a missing file.
- **cycle 1700 (2026-09-26)**: the predicate `go test` environment was `os.Environ()` plus the suite's keys, so every predicate, and every inner `go test` a meta-predicate shells, inherited the lane's `EVOLVE_FLEET`, scope, width and cycle-state keys: the 2026-09-14 incident (ship ran `go test` in the lane's IPC environment) through a different spawner. `predicateEnv` now starts from `ipcenv.Scrub`.
- **2026-10-01, architecture review of the scrub**: the first version of the `ipcenv.Scrub` projection also stripped `EVOLVE_FLAG_CAMPAIGN`, operator runtime state that `regression/flagprogress` reads to decide whether the ADR-0063 strict-reduction gate is armed. Under `EVOLVE_FLAG_CAMPAIGN=1` the suite gave PASS with the gate skipped, where it had given FAIL. A skip is also what the gate does outside a campaign, so nothing would have noticed. The key is now forwarded by name from the policy, and the curated-predicate guard fails when any key a curated predicate reads is dropped.
- **cycle 1762 (2026-09-29)**: a `-count=50 -race` cycle predicate spent the whole 600 s lane budget, the next scope's `go list` died on the expired context, and the audit reported only `active predicate scope "./acs/regression/apicover" produced no execution results`, dropping the `context deadline exceeded` that explained it. The budget is now stated as shared, and its exhaustion is reported as such.
- **cycle 104 in the cycle-949 worktree**: an invocation from `<worktree>/go` resolved the default `--evolve-dir .evolve` against that cwd and wrote a phantom `go/.evolve/runs/cycle-104/acs-verdict.json`. A relative resolution in the write path could as well have fed a gate the wrong root. `Run` now makes its roots absolute, `WriteVerdict` refuses a relative evolve dir, and the CLI refuses an `--evolve-dir` that is not an existing directory. A sweep of the hub on 2026-10-01 found no remaining `acs-verdict.json` under any `go/` tree.
- **2026-10-01, architecture re-review**: `acs.predicate_env` was unbounded (it could re-admit `EVOLVE_FLEET` to every predicate), the rule that a cycle worktree's own policy cannot widen it was unpinned, and a caller's `CHANGED_PACKAGES` passed the scrub. The bound, its tests and the export strip followed. The verdict names moved to `internal/acsverdict` so `acsrunner` stops importing this package.
- **VerdictFilename** (now `acsverdict.Filename`): before this const existed, the `"acs-verdict.json"` literal had drifted into 7+ separate copies across the codebase; `phasecontract.ArtifactFilename` centralizes the audit-report name the same way.
