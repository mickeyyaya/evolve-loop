# internal/shipmanifest

> Consumers: [internal/phases/ship](internal-phases-ship.md) stages the selection; [internal/phases/audit](internal-phases-audit.md) snapshots it (F43 part 2, component 4).

## Purpose

`shipmanifest` is the single source of "which paths Ship commits". A non-release ship never runs a blanket `git add -A`: it stages the paths the cycle's build and TDD reports declare, plus the changed paths those declarations cover. This package holds every pure step of that selection, so a second reader can compute the same tree without importing the ship phase:

- `Declared(workspace, reportFiles)` is the union of the repo-relative paths named in the given phase reports, plus the prior attempt's declarations when the workspace carries a continuation manifest (ADR-0076 slice C).
- `ChangedPaths(porcelain)` parses `git status --porcelain` into the sorted set of paths it names, both sides of a rename included.
- `Stageable(porcelain, manifest, isFile)` is the declared selection: `ChangedPaths`, then `pathspec`, minus the paths a `git add` pathspec must not carry (a staged deletion, the source of a staged rename; `gonePaths`, unexported), because naming one fails the whole add with rc=128. It returns a fresh slice. `Select` is its one production caller.
- `RegularFileIn(root)` is the `isFile` rule both callers pass: the path under `root` exists and is a regular file.
- `pathspec` (unexported; reached only through `Stageable`) is the explicit pathspec: every declared entry that is a file on disk, plus every changed path a declared entry covers exactly or by directory prefix. No manifest, or one that covers nothing, selects nothing (until 2026-09-28 both fell back to the whole changed set, residue included).
- `OutOfManifest(changed, manifest)` is the manifest gate's question: the changed paths no declaration covers.
- `UnquoteGitPath(token)` decodes one C-quoted path token from git output; every ship reader of git path output decodes through it.
- `Select(read, root, workspace)` is the whole selection. It reads `git status --porcelain -uall`. With a workspace it selects only what the cycle declares: `Stageable` over `Declared(workspace, ReportFiles())` with `RegularFileIn(root)`, so a workspace whose reports declare nothing selects nothing. Without a workspace (an operator's manual `evolve ship`) it selects every changed path except the gone ones. It then asks `git check-ignore` about the result. The `Selection` carries the paths to stage, the ignored paths it dropped, the manifest, the changed count, and the probe's error: a failed probe keeps every selected path (fail-open) and reports why. A failed status read is an error, and an empty selection asks no probe.
- `ReportFiles()` is the one report list: the build and TDD artifact names resolved through `phasecontract`. `Select` and Ship's manifest gate both read it.
- `RawPathRead(args...)` prefixes a path-reporting git read with `-c core.quotePath=false`, before the subcommand where git accepts it; every path read in the selection and in Ship goes through it.
- `GitRead` is the reader `Select` runs git through, with Ship's `landing.Capture` contract: it returns stdout, exit 1 is an answer (`check-ignore` finding nothing ignored), and an exit above 1 is an error. `GitIn(ctx, dir)` is that reader over `gitexec` with `--no-optional-locks`, so a `git status` never refreshes the real index; the audit reads through it.
- `IgnoredInAddRefusal(stderr)` names the paths a `git add` refused as ignored: the lines between git's "The following paths are ignored…" header and the first `hint:`, decoded. It reads the header anywhere in a line, so a caller's error text that carries git's stderr (treefence's) names the same offenders.
- `StageRetrying(paths, stage)` is the refusal retry every stager shares. An empty set never reaches `stage` (`git add -A --` with no pathspec stages the whole tree). Otherwise it runs `stage(paths)`; when that fails and git's refusal names some, but not all, of the paths, it drops them and runs `stage` once more. It returns what was staged last, the paths it dropped, and the last error. A refusal that names nothing in the set, or every path in it, is not retried.

- `TakeShipTree(ctx, read, worktree, workspace)` is the tree Ship will commit, as a `treefence.Snapshot`: `Select`, then `treefence.TakeStaged` over the selected paths (the real index, every tracked edit, and those paths, in a throwaway index) under `StageRetrying`; an empty selection is `TakeStaged(nil)`, the index and the tracked edits.

**The one ship tree.** Three readers need "the tree Ship will commit" and all three compute it through `TakeShipTree`: the audit's predicate tree (`audit.predicateTreeFor`, which requires the full worktree to equal it), the audit binding (`core.worktreeContentSHA`, the `WorktreeTreeSHA` Ship verifies its receipt and staged tree against, the composition entries' `TreeStateSHA`, and the verdict-cache key), and Ship's worktree staging, which runs `git add -u` and stages the same `Selection.Paths` into the real index, its commit pinned equal to `TakeShipTree` (F43 part 2, component 4). The tracked edits enter through `add -u`: the binding and Ship's worktree path run it on the real index, and `TakeStaged` runs it in the throwaway index, after the declared add so a declared file removed with plain `rm` stages as a deletion. `internal/phases/audit` must not import `internal/phases/ship` and `core` must not import either, which is why the selection lives here.

## Design

- **Git reads are injected; `git add` stays with the stager.** The pure steps (`Declared`, `ChangedPaths`, `Stageable`, `OutOfManifest`) run no git. `Select` runs its two reads through the `GitRead` its caller passes: Ship passes its own capture, so its fake runners and error types still apply; the audit passes `GitIn`; core passes `gitReadIn`, an adapter over its `gitCapture` seam. Ship runs its own `git add` into the real index; `TakeShipTree` stages into treefence's throwaway index; `StageRetrying` owns only the decision to drop and retry.
- **No dependency on the orchestrator.** The package imports `cyclestate` (for the build and TDD phase names), `phasecontract`, `continuation`, `gitexec` and `treefence`, never `core`, so `core` can call `TakeShipTree` for its binding.
- **One report list.** `ReportFiles()` resolves the build and TDD artifact names through `phasecontract`. `Declared` still takes the list as a parameter, so its tests name reports directly. Deriving the list from the registry's `writes_source` phases instead of naming two is component 5 (design §5.12).
- **One coverage predicate.** An entry covers a path exactly or as a directory prefix, component-wise (`docs/adr` covers `docs/adr/x.md`, not `docs/adr-other.md`). `pathspec` and `OutOfManifest` share it.
- **One repo-relative guard.** Extraction drops absolute and repo-escaping tokens, and `pathspec` drops them again from a manifest that came from an older serialized source, so an absolute pathspec never reaches git argv.
- **Quote-aware porcelain.** Rename entries are split only on the structural ` -> ` delimiter, never on one inside a quoted filename, and every endpoint is decoded. Decoding happens only for a token wrapped in quotes on both ends; any other token is returned verbatim.

## Invariants

- **Report prose reduces to repo-relative paths.** Slashed paths and bare root files with a known extension are extracted; `./` prefixes normalize; absolute, `../` and ellipsis-glued tokens are dropped; dot-directories survive. Pinned by `TestExtractReportPaths`, `TestExtractReportPaths_BareRootFilenames`, `TestExtractReportPaths_RelativeDotPrefix`, `TestExtractReportPaths_NeverAbsoluteOrParent`, `TestExtractReportPaths_DotDirsPreserved` and `TestIsRepoRelative`.
- **A continuation unions the prior attempt; without one the manifest is unchanged.** Pinned by `TestDeclaredManifest_UnionsPriorAttemptViaContinuation` and `TestDeclaredManifest_NoContinuationIsByteIdentical`.
- **Only the named reports count, and no readable report is an empty manifest.** Pinned by `TestDeclared_ReadsOnlyTheNamedReports`.
- **Coverage is component-wise.** Pinned by `TestOutOfManifest_FlagsUndeclaredPaths` and `TestOutOfManifest_InManifestDiffHasNoFalsePositive`.
- **No non-relative manifest entry reaches the pathspec.** Pinned by `TestStagePathspec_RejectsNonRelativeManifestEntries`.
- **Quoted porcelain decodes to the on-disk path; ASCII porcelain is unchanged.** Pinned by `TestPorcelainChangedPaths_QuotePathUnescapesNonASCII`, `TestPorcelainChangedPaths_QuotePathAsciiUnchanged` and `TestUnquoteGitPath_DecodesOnlyWrappedTokens`.
- **A ` -> ` inside a quoted name is content, not a delimiter; malformed input degrades verbatim.** Pinned by `TestPorcelainChangedPaths_QuotedRenameArrowKeepsBothEndpoints`, `TestStagedGonePaths_QuotedRenameArrowSourceDecodes`, `TestPorcelainChangedPaths_RenameArrowMalformedIsSafe` and `TestPorcelainChangedPaths_OrdinaryRenameArrowUnchanged`.
- **`Stageable` is the declared selection.** A changed declared path is named though no file backs it; a declared directory takes only the changes it covers (the cycle-645 leak); a manifest that covers nothing, and no manifest, select nothing; a staged deletion and a staged rename's source are never named; a both-deleted conflict (`DD`) stays named as its resolution. Pinned by `TestStageable_IsThePathspecShipStages` and `TestRegularFileIn_CountsOnlyRegularFilesUnderRoot`.
- **`Select` is the selection every reader shares.** The declared changes are selected and an ignored declared path is dropped; every read asks git for raw paths; the probe asks about exactly the selected paths; a failed probe keeps the full set and reports why; a failed status read is an error; a workspace without reports selects nothing; without a workspace every changed path but the gone ones is selected; an empty selection asks no probe. Pinned by `TestSelect_TakesTheDeclaredChangesAndDropsTheIgnoredOnes`, `TestSelect_AFailedIgnoreProbeKeepsEverySelectedPath`, `TestSelect_AFailedStatusReadIsAnError`, `TestSelect_AWorkspaceWithoutReportsSelectsNoUndeclaredPath`, `TestSelect_WithoutAWorkspaceEveryChangedPathIsSelected` and `TestSelect_NothingSelectedAsksNoIgnoreProbe`.
- **`TakeShipTree` is the tree Ship will commit.** The declared untracked document and an undeclared tracked edit are in it and residue is not; a report-less cycle is its index and tracked edits, one snapshot; a declared file removed with plain `rm` (unstaged at audit time) ships its deletion; a path git refuses as ignored after the probe missed it is dropped and the snapshot retaken. Pinned by `TestTakeShipTree_IsTheTreeShipWillCommit`, `TestTakeShipTree_AnEmptySelectionIsTheIndexAndTheTrackedEdits`, `TestTakeShipTree_ADeclaredFileRemovedWithPlainRmShipsItsDeletion` and `TestTakeShipTree_RetriesWithoutThePathsGitRefusesAsIgnored`; the three readers are pinned equal to it by `TestPredicateTreeFor_Cycle1735_*`/`_Cycle1694_*` (audit), `TestWorktreeContentSHA_BindsTheTreeTheAuditSealed` (binding) and `TestShipFromWorktree_CommitsTheOneShipTree` (Ship, end to end).
- **Quoted probe output decodes; nothing else matches.** A quoted ignored path is dropped, and a different or escaped spelling drops nothing. Pinned by `TestWithoutIgnored_DecodesQuotedProbeOutput`.
- **The audit's reader never writes the index, and exit 1 is an answer.** Pinned by `TestGitIn_ReadsWithoutWritingTheIndexAndTakesExitOneAsAnAnswer` (a mutant without `--no-optional-locks` goes red: `git status` rewrites the index's stat cache).
- **The refusal retry drops only what git named, once, and an empty set stages nothing.** Pinned by `TestStageRetrying_DropsWhatGitRefusesAndRetriesOnce`, `TestStageRetrying_AnEmptySetStagesNothing` and the `TestIgnoredInAddRefusal_*` parser tests.
- **Every export is named by a test** (`.apicover-enforce`).

## Findings

- **2026-09-28, the extraction.** The selection lived in `internal/phases/ship/manifest.go`, so only Ship could answer "which paths will be committed". The audit had no way to bind the same tree without importing the ship phase. The pure functions moved here unchanged, and their tests moved with them under their original names. The behaviour-level staging tests (`TestShipDirect_CycleClass_StagesDeclaredPathsNotAddAll`, `TestStageExplicitPaths_QuotePathDisabledOnGitReads`, the `dropIgnoredPaths` tests) stay in ship.
- **2026-09-28, the review.** The architecture review found the gone-path drop still composed inside ship (a caller building on `Pathspec` alone would name a staged rename's source and fail rc=128, F43's bug class again) and four mutants of the contract surviving the moved suites. `Stageable` now owns the composition and is the only exported door (`pathspec` is unexported), and its table kills three of them; the fourth (`changedSet[d] ||`) was equivalent, because a changed declared path is also staged by the coverage loop, which matches exact paths, so the dead set was deleted.
- **2026-09-28, component 4: the selection became one call.** The audit's ship tree was `TakeTracked` (index plus `add -u`), a second belief about what Ship commits. Ship's remaining selection steps moved here so the audit could make the same call: the `status` read and `check-ignore` probe (`dropIgnoredPaths` → `Select` and the unexported `withoutIgnored`), the add-refusal parser (`ignoredPathsFromAddRefusal` → `IgnoredInAddRefusal`), the retry decision (→ `StageRetrying`), the report list (`manifestReportFiles` → `ReportFiles`) and the raw-path prefix (`rawPathRead` → `RawPathRead`). The parser and probe tests moved with them (`TestIgnoredInAddRefusal_*`, `TestWithoutIgnored_DecodesQuotedProbeOutput`); Ship's behaviour tests stayed in ship.
- **2026-09-28, component 4's review: the binding was a third belief.** The architecture review of the first version (audit against `Select` + `TakeStaged`) found that `core.worktreeContentSHA` recorded its own ship tree, `git add -u` then `write-tree`, and Ship checks both the predicate receipt and its staged tree against it: the eight F43 cycles would have passed the audit and failed at Ship. It also corrected a premise: the binding's `add -u` stages every tracked edit, so Ship did commit undeclared tracked edits, and the first version's refusal of them was wrong. The redesign made `TakeShipTree` the one definition (the index, every tracked edit, the declared paths), made `TakeStaged` run `add -u` (and deleted `TakeTracked`, which `TakeStaged(nil)` now equals), and removed `pathspec`'s fallbacks, which would have carried untracked residue into the binding (the cycle-1594 pins).
- **History carried with the code.** The quote-path decoding (cycle 1108), the rename-arrow tokenizer (cycle 1469), the absolute-pathspec guard (cycle 1098), the staged-rename gone set, and the bare-root-file extraction (2026-07-14) were all fixed in ship before the move. Their contracts are the tests listed above.
