# internal/phases/retro

## Purpose

`internal/phases/retro` is the retrospective phase as a `core.PhaseRunner`: a post-mortem that runs only when the previous verdict is FAIL or WARN, dispatches the `evolve-retrospective` persona, and grades the result on a non-empty `retrospective-report.md` plus a failure lesson for this cycle. A PASS cycle short-circuits to SKIPPED with no bridge call (the memo phase handles PASS-cycle observation). Unlike most phases, retro is a hand-rolled runner that calls the bridge itself rather than going through `internal/phases/runner`'s `BaseRunner`, so it re-implements the pieces of that runner it needs.

## Design

- **Verdict mapping.** A previous verdict other than FAIL/WARN → SKIPPED, `NextPhase=end`, no bridge call. A non-empty report (bridge stdout, else the artifact file) and a failure lesson for this cycle → PASS. Anything else → FAIL. A failing explanation-review floor also FAILs.
- **Artifact path.** Retro polls `retrospective-report.md` in the workspace, the file the persona writes, and passes `disposition.json` and `carryover-todos.json` as secondary artifacts. Polling any other name makes the bridge wait out its timeout on every retro.
- **CLI resolution mirrors `BaseRunner`:** `EVOLVE_CLI` from the request env, else the `retrospective` profile's `cli`, else `claude-tmux`. Retro reads the profile from `<project>/.evolve/profiles`.
- **Model resolution.** Retro never reaches the dispatch resolver that expands the `auto` sentinel, so it expands it itself: `Config.Model` defaults to `auto`, which dispatches the profile's `model_tier_default`, else `balanced`. An explicit tier passes through unchanged; `auto` never reaches the bridge.
- **Skill overlays.** Retro resolves the tier-gated persona overlays for its launch (`policy.ResolveLaunchOverlaysFailOpen`) and threads their names onto `BridgeRequest.Skills`, as the phase runner does; a deep- or top-tier retro gets the fable operating-discipline overlay. Resolution is fail-open.
- **Prompt compaction.** `Config.CompactPrompts` strips the persona's on-demand reference tail (below `## Reference Index`) before composing the prompt, mirroring `BaseRunner` compaction; off by default. It never changes the PASS short-circuit.
- **Read-only worktree fence (ADR-0097).** Because retro calls the bridge itself, it holds the same `treefence` the shared runner does, so the tree it hands the retry envelope (tdd re-entry, salvage) is the tree it was given, and a write is reported on its response.
- **A delivery failure is relaunched once**; any other bridge error is final for this launch.
- **A bridge failure is never fatal.** Retro is the failure analysis on the audit-FAIL path, and a non-nil error from `Run` becomes a hard abort that stops the whole batch. On a bridge error retro returns a FAIL verdict with a nil error, carrying the bridge error as an error diagnostic, so the orchestrator routes through `decideAfterRetro` (failure adapter: retry, block or proceed); `NextPhase` is advisory there.
- **CLI fallback chain.** The composition root hands retro a chain-walking bridge handle, so a timeout on the primary CLI falls back to the profile's next CLI: one CLI's timeout costs one attempt, not the cycle.
- **Worktree fallback (`retroWorktree`).** Under a fleet supervisor the bridge drivers refuse a launch whose working directory fails their guard: an empty worktree is refused as `errWorktreeRequired`, and a non-existent path at `gobridge.IsDir` (exit `ExitBadFlags`). A lane whose worktree was torn down or never provisioned would lose its retrospective entirely, a failure in the failure handler. In fleet mode, when the worktree is not an existing directory, retro dispatches against a disposable scratch cwd it mints under the workspace it already owns (`gobridge.ScratchCwd`, the `applyScratchCwd` precedent); retro is read-mostly and Evaluate-archetype, so a scratch cwd is enough. The condition is the guard's own predicate (is it a directory), not a string shape: a torn-down lane hands retro a non-empty but stale path, because `cs.ActiveWorktree` is not cleared on lane teardown.
- **What the fallback never does.** It never passes a live provisioned worktree anything but verbatim (an unconditional fallback would strand every normal retro in a scratch dir with no repo); never points retro at the shared main tree (`req.ProjectRoot`; the worktree is the write-authority predicate) or at the dispatching process cwd (the leak the guard closes); never fabricates a path when there is no workspace to mint under (it returns `""` and the bridge decides); never rewrites a stale path outside fleet mode, where the bridge keeps its process-cwd fallback and reports the bad directory to the operator. The bridge guard itself is untouched: the fix is supplied by the phase.
- **`fleetMode`** reads the fleet flag through the same key and parser the bridge guard uses (`ipcenv.FleetKey`, `envchain.BoolValue`), request env first and process env as the fallback, the driver's own lookup order, so the phase and the guard agree about which launches fail closed.
- **Failure-lesson resolution (`hasFailureLesson`).** The persona writes lessons to `.evolve/instincts/lessons/inst-L<cycle><suffix>-<slug>.yaml`; `lessonsDirRel` single-sources that directory with the persona's documented output path (`agents/evolve-retrospective.md`). The check is cycle-scoped: `lessonPrefixForCycle` builds the persona's `inst-L<cycle>` prefix and `matchesCycleLesson` requires a non-digit delimiter after the number, so cycle 157's gate is not satisfied by `inst-L1574a-…` and cycle 1's by any lesson whose number starts with 1. A gate that accepted any lesson would pass unconditionally. The legacy shape, `failure-lesson*.yaml` in the cycle workspace, still counts.
- **Explanation review (`validateExplanationReview`, ADR-0102).** Retro applies its policy around the shared `explanationdocs.ValidateReviewedHandoff` contract. The review's shape (the section, its fields, correction-todo bookkeeping, handoff echoes, citations) is advisory: each finding rides the retrospective's record as a warning diagnostic. The only blocking outcomes are the reasoning floor (a token Evidence; a missing or duplicated review section is no review text at all) and host-side defects in the handoff itself, and the findings made before a host defect ride along with its error. A correction todo that `carryover-todos.json` does not back is an advisory. Retro refreshes the build-explanation handoff itself before composing the prompt (`refreshExplanationHandoff`), so a lost or stale handoff becomes an advisory, not a block.
- **Self-registration.** `init` registers the retro factory with the phase registry like every other built-in phase; the subprocess dispatcher (`internal/cli/phasecmd`) resolves phases by name and never constructs retro directly (phase-agnostic flow, ADR-0035/0038). The factory builds the default project-rooted bridge and prompts loader with model `auto`.

## Invariants

- PASS short-circuits to SKIPPED without a bridge call, with or without compaction. Pinned by `TestRun_PreviousPASS_SKIPPEDWithoutBridgeCall` and `TestRetroPhase_CompactEnabled_PreviousPASS_StillSkips`.
- Retro polls `retrospective-report.md`. Pinned by `TestRun_PreviousFAIL_PASSWithLesson`.
- CLI resolution: `TestRun_DispatchesProfileCLI`, `TestRun_EnvCLIOverridesProfile`, `TestRun_NoProfileFallsBackToClaude` assert the dispatched `BridgeRequest`, never the profile file.
- `auto` never reaches the bridge. Pinned by `TestRun_AutoModel_ResolvedBeforeDispatch`, `TestRun_ExplicitModel_PassesThroughUnchanged`, `TestRun_AutoModel_ProfileWithoutTier_ResolvesToDefaultNotAuto` and `TestRun_AutoModel_NoProfile_NeverDispatchesSentinel`.
- Compaction strips the tail only when enabled. Pinned by `TestRetroPhase_ConfigHasCompactPrompts`, `TestRetroPhase_CompactEnabled_StripsBody`, `TestRetroPhase_CompactDisabled_BodyIdentical` and `TestRetroPhase_CompactEnabled_PromptSizeStrictlySmaller` (a size check that complements the content check).
- The fence holds around retro's own launch. Pinned by `TestRun_ReadOnlyWorktreeIsFencedAroundRetrosOwnLaunch`.
- A bridge error yields FAIL with a nil error. Pinned by `TestRun_BridgeError_FAIL`.
- A primary-CLI timeout falls back through the chain. Pinned by `TestRun_TimeoutOnThePrimaryCLIFallsBackThroughTheChain`.
- The worktree fallback's four shapes (empty, stale, live, no workspace) and its fleet gating. Pinned by `TestRetro_EmptyWorktree_FallsBackToScratchUnderWorkspace`, `TestRetro_EmptyWorktree_NeverMainTreeOrProcessCwd`, `TestRetro_RealWorktree_PassedThroughUnchanged`, `TestRetro_EmptyWorktreeAndWorkspace_NoFabricatedPath`, `TestRetroWorktree_StaleNonExistentPathFallsBackToScratchCwd`, `TestRetroWorktree_FleetNeverEmitsANonExistentPath`, `TestRetroWorktree_FleetProvisionedWorktreePassesThroughVerbatim`, `TestRetroWorktree_NonFleetStalePathPassesThroughVerbatim`, and at the join with the bridge guard by `TestRetroWorktree_FleetScratchCwdSatisfiesBridgeGuardPredicate`, which asserts the dispatched value is a real directory, not merely non-empty.
- Failure-lesson resolution is cycle-scoped with a digit boundary and accepts the legacy workspace shape. Pinned by `TestResolveFailureLesson`, `TestHasFailureLesson_NonexistentWorkspace_False` and `TestHasFailureLesson_IgnoresDirectoriesAndOtherFiles`.
- The gate's lesson directory and the persona's documented output path are one string. Pinned by `TestLessonPathIsSingleSourcedWithThePersona`, which reads the persona file.
- The explanation-review policy. Pinned by `TestValidateExplanationReview_RequiresReviewForAvailableBuild`, `TestValidateExplanationReview_ListValuedEvidence`, `TestRun_PreviousFAIL_LostHandoffAdvisoryRidesTheRecord`, `TestValidateExplanationReview_BookkeepingFindingsAreAdvisory`, `TestValidateExplanationReview_DuplicateSectionIsAdvisoryButFailsTheFloor`, `TestValidateExplanationReview_NeedsCorrectionTodoRulesAreAdvisoryAndHostDefectsAreLoud` and `TestValidateExplanationReview_HostDefectKeepsTheFindingsMadeBeforeIt`.
- Retro self-registers without the dispatcher. Pinned by `TestRetroSelfRegisters`; `TestPhase_NamedConcreteRunner` names `*Phase` as a `core.PhaseRunner`.

## Findings

- A gate whose search location differs from the persona's documented output path grades retros FAIL for not producing an artifact the persona is told never to produce: measured on the runtime plane, 220 of 238 retro FAILs (92%) had a substantial retrospective and no workspace lesson. The persona's convention is load-bearing (its lessons feed future agents' instinct summaries), so the gate follows the persona.
- The runtime lessons directory holds about 600 lessons in two conventions (about 135 `inst-L*` and 464 an older `cycle-<N>-*`), which is why the lesson check must be cycle-scoped: accepting any lesson turns the gate into a rubber stamp. A git worktree's copy of that directory is empty because it is gitignored, so measurements come from the runtime plane.
- A hand-rolled runner that ignores `profile.cli` makes editing `retrospective.json`'s `cli` a no-op; only an assertion on the dispatched `BridgeRequest` catches it.
