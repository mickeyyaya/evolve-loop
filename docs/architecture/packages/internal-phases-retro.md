# internal/phases/retro

## Purpose

`internal/phases/retro` is the retrospective phase as a `core.PhaseRunner`. It is a post-mortem that runs only when the previous verdict is FAIL or WARN. It dispatches the `evolve-retrospective` persona and grades a non-empty `retrospective-report.md` plus a failure lesson for this cycle. A PASS cycle gives SKIPPED with no bridge call (the memo phase observes PASS cycles). Since 2026-10-20 retro is a set of `runner.Hooks` on the shared `BaseRunner` of `internal/phases/runner`, like every other dispatched phase. Thus retro gets the phase stream, the routing, the model resolution, the chain walk and the verdict engine of every other phase.

Before, retro was a hand-rolled runner that called the bridge itself. It wrote no `retro-events.ndjson`, so each FAIL cycle surveyed one gap (inbox item `retro-events-stream-missing`).

## Design

- **Verdict mapping (`hooks.ShouldSkip`, `hooks.Classify`).** A previous verdict other than FAIL/WARN gives SKIPPED, `NextPhase=end` and no bridge call. A non-empty report and a failure lesson for this cycle give PASS. Anything else, or a failing explanation-review floor, gives FAIL. The verdict engine of the runner reads the report from the artifact file. It verifies the deliverable against the `retro` contract through `Config.ContractVerifier`, as for every phase.
- **Artifact path.** The hooks name `retrospective-report.md` in the workspace, the file that the persona writes. `hooks.SecondaryArtifacts` names `disposition.json` and `carryover-todos.json`. The profile is `retrospective.json`, because the runner strips `evolve-` from the persona name `evolve-retrospective`.
- **CLI resolution goes through the CLI router ([internal-cliroute.md](internal-cliroute.md), [ADR-0119](../adr/0119-one-routing-table-one-resolver.md)).** `Config.Router` is the router of the composition root. The runner resolves the `retrospective` agent through it and walks the whole plan with `llmroute.DispatchTiered`. With no router, the runner uses `runner.DefaultRouter`, else a one-profile launch router over the `retrospective` profile. That launch router refuses a project that declares a `cli_routing` table. (2026-10-20: this replaces `resolveCLI`, which launched only `Decision.Plan.Candidates[0]`.)
- **A routing refusal is a FAIL verdict, never fatal.** When the router refuses the route, the runner returns a FAIL response and an error. `Phase.Run` keeps the FAIL, adds the error as an error diagnostic and returns a nil error, for the same reason as a bridge failure (below).
- **Model resolution.** `Config.Model` is the default tier of the hooks, and it defaults to `auto`. `llmroute.Resolve` takes the env tier, then the `model_tier_default` of the profile, then that default. The runner expands `auto` through the root router, as for every phase. The old retro-only rule, `auto` to the profile tier else the literal `balanced`, is gone (prescription `retro-failure-identity#1568-llmroute`). A profile tier now outranks an explicit `Config.Model`.
- **Skill overlays.** The runner resolves the tier-gated persona overlays for each try of the walk, as for every phase.
- **Prompt compaction.** `Config.CompactPrompts` goes to the runner, which strips the on-demand reference tail of the persona. It never changes the PASS short-circuit.
- **Read-only worktree fence (ADR-0097).** The runner holds the `treefence` around the dispatch, as for every phase.
- **A delivery failure is relaunched once (`deliveryRelaunch`).** Retro wraps its bridge in a decorator. The decorator acts when `core.DeliveryFailureCause` names a cause (a `submit_wedged` prompt). It prints a `[retro] WARN` line with the cause and the CLI, and it relaunches the same CLI once.
  - A cancelled context gets no relaunch.
  - Before the relaunch the decorator moves the logs of try 1 to `<agent>-stdout.attempt-1.log` and `<agent>-stderr.attempt-1.log`. Thus the first capture stays, and the phase stream reads the final try.
  - The chain walk of the runner gets any other bridge error.
- **A bridge failure is never fatal.** Retro is the failure analysis on the audit-FAIL path. A non-nil error from `Run` is a hard abort that stops the whole batch.
  - The runner can return a FAIL response with an error. Then `Phase.Run` returns the FAIL, which already carries the error as a diagnostic, with a nil error. Thus the orchestrator routes through `decideAfterRetro` (the failure adapter: retry, block or proceed).
  - A configuration error that has no response, such as a missing bridge or a missing persona, stays an error.
- **CLI fallback chain.** The runner walks the plan and marks each try `ChainAttempt`. Thus the walking bridge handle of the composition root does not walk a second time. A timeout on the primary CLI costs one try, not the cycle.
- **Phase stream.** The runner launches with `Agent=retro`, so the bridge writes `retro-stdout.log`. After each try the runner runs `phasestream.Produce`, which writes `retro-events.ndjson`. Thus `phaseoutputs.Survey` finds the events stream of a retro. `Config.Bridge` signals go to the verdict engine when the bridge has a `Signals()` source.
- **Worktree fallback (`retroWorktree`).** Under a fleet supervisor the bridge drivers refuse a launch whose working directory fails their guard: an empty worktree is refused as `errWorktreeRequired`, and a non-existent path at `gobridge.IsDir` (exit `ExitBadFlags`). A lane whose worktree was torn down or never provisioned would lose its retrospective entirely, a failure in the failure handler. In fleet mode, when the worktree is not an existing directory, retro dispatches against a disposable scratch cwd it mints under the workspace it already owns (`gobridge.ScratchCwd`, the `applyScratchCwd` precedent); retro is read-mostly and Evaluate-archetype, so a scratch cwd is enough. The condition is the guard's own predicate (is it a directory), not a string shape: a torn-down lane hands retro a non-empty but stale path, because `cs.ActiveWorktree` is not cleared on lane teardown.
- **What the fallback never does.** It never passes a live provisioned worktree anything but verbatim (an unconditional fallback would strand every normal retro in a scratch dir with no repo); never points retro at the shared main tree (`req.ProjectRoot`; the worktree is the write-authority predicate) or at the dispatching process cwd (the leak the guard closes); never fabricates a path when there is no workspace to mint under (it returns `""` and the bridge decides); never rewrites a stale path outside fleet mode, where the bridge keeps its process-cwd fallback and reports the bad directory to the operator. The bridge guard itself is untouched: the fix is supplied by the phase.
- **`fleetMode`** reads the fleet flag through the same key and parser the bridge guard uses (`ipcenv.FleetKey`, `envchain.BoolValue`), request env first and process env as the fallback, the driver's own lookup order, so the phase and the guard agree about which launches fail closed.
- **Failure-lesson resolution (`hasFailureLesson`).** The persona writes lessons to `.evolve/instincts/lessons/inst-L<cycle><suffix>-<slug>.yaml`; `lessonsDirRel` single-sources that directory with the persona's documented output path (`agents/evolve-retrospective.md`). The check is cycle-scoped: `lessonPrefixForCycle` builds the persona's `inst-L<cycle>` prefix and `matchesCycleLesson` requires a non-digit delimiter after the number, so cycle 157's gate is not satisfied by `inst-L1574a-…` and cycle 1's by any lesson whose number starts with 1. A gate that accepted any lesson would pass unconditionally. The legacy shape, `failure-lesson*.yaml` in the cycle workspace, still counts.
- **Explanation review (`validateExplanationReview`, ADR-0102).** Retro applies its policy around the shared `explanationdocs.ValidateReviewedHandoff` contract. The review's shape (the section, its fields, correction-todo bookkeeping, handoff echoes, citations) is advisory: each finding rides the retrospective's record as a warning diagnostic. The only blocking outcomes are the reasoning floor (a token Evidence; a missing or duplicated review section is no review text at all) and host-side defects in the handoff itself, and the findings made before a host defect ride along with its error. A correction todo that `carryover-todos.json` does not back is an advisory. Retro refreshes the build-explanation handoff itself before composing the prompt (`refreshExplanationHandoff`), so a lost or stale handoff becomes an advisory, not a block.
- **The handoff refresh consults the host first (`refreshExplanationHandoff`).** Before 2026-10-18 a zero `ExplanationDocumentationVersion` mapped to `Legacy` with no host consult. A caller that dropped the field thus disabled the explanation review in silence. That is the shape the audit gate had before the belt. The refresh now calls `explanationdocs.CrossCheckActivation` first. A `(false, nil)` belt result is genuine legacy.
  - A belt error degrades the handoff to `Invalid` with the belt's reason. Examples are a zero version against an active host, a stale version and a foreign run. The review gate maps `Invalid` to NEEDS_CORRECTION and a concrete todo, and it honors `Invalid` at version zero.
  - `NotYetBuilt` returns after the belt. A retro after a FAIL before the Build seal carries a provisioned worktree that the host has not sealed. The belt accepts that. After the belt proves the host active, `Verify` cannot return inactive, so the refresh reads only its error and its view.
- **Self-registration.** `init` registers the retro factory with the phase registry like every other built-in phase; the subprocess dispatcher (`internal/cli/phasecmd`) resolves phases by name and never constructs retro directly (phase-agnostic flow, ADR-0035/0038). The factory builds the default project-rooted bridge and prompts loader with model `auto`.

## Findings

- A gate whose search location differs from the persona's documented output path grades retros FAIL for not producing an artifact the persona is told never to produce: measured on the runtime plane, 220 of 238 retro FAILs (92%) had a substantial retrospective and no workspace lesson. The persona's convention is load-bearing (its lessons feed future agents' instinct summaries), so the gate follows the persona.
- The runtime lessons directory holds about 600 lessons in two conventions (about 135 `inst-L*` and 464 an older `cycle-<N>-*`), which is why the lesson check must be cycle-scoped: accepting any lesson turns the gate into a rubber stamp. A git worktree's copy of that directory is empty because it is gitignored, so measurements come from the runtime plane.
- A hand-rolled runner that ignores `profile.cli` makes editing `retrospective.json`'s `cli` a no-op; only an assertion on the dispatched `BridgeRequest` catches it.
- The inbox item `explanation-identity-belief-remaining-copies` (2026-09-01) found the version-zero shortcut in the handoff refresh. The phase trusted a typed field that only the host marker can confirm. The fix routes the refresh through the belt and lets the review gate honor an `Invalid` handoff at version zero. `TestValidateExplanationReview_AnInvalidHandoffAtVersionZeroWalksTheCorrectionPath` pins the gate: at version zero an `Invalid` handoff demands NEEDS_CORRECTION, and a concrete todo that `carryover-todos.json` backs passes clean.
