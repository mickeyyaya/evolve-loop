## Purpose

`cmd/evolve` is the composition root and CLI of the `evolve` binary. It is `package main`: one handler per subcommand in the `commands` table, plus the wiring that builds the orchestrator, the loop and the campaign runner from the internal packages. It owns argument parsing, output formatting and the few decisions that belong to no internal package.

## Design

- **Thin handlers.** Each `runX(args, stdin, stdout, stderr) int` parses its flags and delegates. Most handlers exit 10 on bad arguments; `campaign`, `audit` and `build-invocation-context` exit 2. `reorderArgs` forwards to `cmdutil.ReorderArgs`, the one definition the extracted `internal/cli/*` groups share.
- **Removed budget flags.** `loop` and `cycle run` strip `--budget-usd`, `--budget` and `--batch-cap-usd` before `flag.Parse` in every form it accepts (`-f`, `--f`, `-f=v`, `--f=v`, `-f v`), with one WARN, so an old script gets a notice instead of a "flag provided but not defined" abort. A following token is the flag's value only when it parses as a finite float: `-1` is consumed, while `--cycles` and a goal word such as `NaN` are not.
- **One pre-wave probe protocol.** `runPreWaveProbes` serves both the loop (`prepareIteration`) and the campaign runner (`BeforeWave`). It runs the CLI-health canary, then the proactive usage probe, and returns the context's error.
  - The canary gives each expired bench one `bridge.LiveSmokeTest` through `defaultLiveProbe`, whose 4-minute bound derives from the runner's context. A clean probe clears the bench. A benchable wall re-benches it with one more strike (a doubled cooldown, or the pane's own reset hint). Any other failure clears it too: non-wall failure classes belong to the capability probe and the fallback chain, and a canary that kept such a bench would re-probe it every cycle. Active benches are never probed.
  - The usage probe is opt-in (`cli_health.proactive_probe`) under the `EVOLVE_CLI_HEALTH` master switch, and fails open. It benches families already at a cap before the first phase boots them, through per-family controllers isolated under `<evolve-dir>/usage-probe`.
  - `bridgeUsageProbe` is the single way to send a family's usage command and read its pane. The cap probe and the budget quota probe (`probeWaveQuota`, under `<evolve-dir>/budget-probe`) both use it.
- **Budget-aware wave sizing** (`cli_wave_budget.go`) is the host half of the two-layer sizing in [internal-loopwave.md](internal-loopwave.md). It measures quota and pace only when a `fleet.budget` block exists. Pace comes from the last `history_window` cycles. `paceBeforeNextWave` idles for the enforce-stage `PaceDelay` and an interrupt ends the idle.
- **`evolve acs run|suite`.** `run` runs `go test -json` on one package. `suite` runs the Go predicate lane ([ADR-0042](../adr/0042-egps-v11-go-native-predicates.md)) and exits 2 on any RED predicate and 1 on a hard error such as a predicate package that fails to compile. When `--root` is left at `.`, the suite root is the cycle's `active_worktree` from its `cycle-state.json`. The predicates' `EVOLVE_PROJECT_ROOT` is the parent of `--evolve-dir` when that directory holds this cycle's `cycle-state.json`, and otherwise the parent of the git common dir ([ADR-0053](../adr/0053-dual-root-source-state-resolution.md)).
- **`evolve apicover`** calls `apicover.Main`, the same entry as the standalone `cmd/apicover`, so a deployed cycle runs the API gate without building a second executable.
- **`evolve build-invocation-context`** (`runBedrock`) emits byte-identical output per role, so the prompt cache can reuse it.
- **`evolve branches audit|prune`** is the production caller of `core.PruneSupersededOrphans` and `core.CarryforwardCandidateLandable`. `audit` prints `<ref> superseded=<t|f> landable=<t|f>` for each local `cycle-*` branch. `prune` is a dry run by default (`would-prune`). With `--dry-run=false` it deletes a superseded ref only when it has no open PR, and reports `kept-open-pr` otherwise.
- **`evolve bridge`** is a thin CLI over `bridge.Engine`: `launch`, `probe`, `report`, `add-rule`, `send`, `watch`, `recipe`, `capabilities`, `introspect`, `control`, `doctor` and `billing`. It builds `bridge.NewEngine(bridge.Deps{})`, so it is a Center-less root and its bridge signals go nowhere (10-bridgeengine.md, "Where the stream is BLIND"). The `probe` JSON shape (`{os, results:[{cli,tier}]}`) is what the adapter parses. `introspect` exits 3 on catalog drift, which is non-fatal. `control` exits 3 for an unsupported family and event pair and 1 for any other failure. `watch` is read-only; `--follow` polls every 500 ms from the end of the feed until SIGINT or SIGTERM.
- **`evolve campaign study|replan|run|status`** ([ADR-0056](../adr/0056-advisor-driven-preliminary-study-cycle.md), [ADR-0059](../adr/0059-cross-session-campaign-ownership-lease.md)).
  - `run` verifies the plan, splits it into waves and runs each through `fleet.Supervisor` with `--concurrency` (default `campaign.MaxWaveWidth`) and `--cycle-timeout` (default 2 h; a cycle past it is reaped so it cannot hang the campaign). A wave's failed cycles get one batched retry, after `campaignQuotaCooldown`: the longest active quota bench, capped at `clihealth.MaxCooldown`, or zero when nothing is benched.
  - Progress is checkpointed per goal hash and bound to the plan's SHA. A rerun of an unchanged plan resumes after the last completed wave unless `--ignore-progress` is given. SIGINT or SIGTERM reaps the in-flight cycles and leaves that checkpoint intact. `status` reads the same checkpoint.
  - `study` and `replan` run the `preliminary-study` phase through a Center-less `bridge.NewDefault(projectRoot, nil)`. The phase is registered persistence-free (no `ProfilesDir`), which is why `phaseregistrar` refuses a phase with no `dispatch.cli` only when it would persist a profile.
- **`evolve carryover apply-decisions`** applies a reviewed keep/drop/cluster decisions file (`{source_count, decisions[]}`) to `state.json:carryoverTodos`. The TTL prune only removes expired entries; this command acts on a judgment. `drop` and `cluster` ids are removed, because clustered ids live on as sweep-group inbox items and would otherwise count twice. It is a dry run unless `--apply` is given. The write goes through `statemap.UpdateStateMap`: the path is symlink-resolved, the lock is taken on the resolved path, `stateRevision` is bumped and a stale write is refused. The 25-entry ceiling is reported with a WARN, never enforced.
- **`evolve compose --phases`** runs registered phases in order through the orchestrator's factories without consulting the state machine, for re-audit and mix-and-match runs. It sets `PhaseRequest.ComposePhases`, so the kernel `evolve guard phase` hook warns instead of blocking. A verdict other than PASS or SKIPPED fails the composition, and the remaining phases still run. `ship` is refused without `--ship-anyway` (exit 2); the OS-level ship gate enforces regardless, so the early refusal only gives a clearer error.
- **`evolve reachability check-pin`** is the CLI over `reachabilityprobe.BuildImportGraph` and `CheckCallSite`; see [internal-reachabilityprobe.md](internal-reachabilityprobe.md).

## Invariants

- **A cancelled canary touches no bench**, before the loop and after each probe: a smoke test cut short by an interrupt reports "not a wall", which would clear a bench that is still walled. Pinned by `TestCanary_CancelledContextTouchesNoBench`.
- **Probes run on the runner's interrupt context**, and `runPreWaveProbes` returns its error, so a caller never dispatches a wave that would be cancelled at spawn.
- **One `now` per budget sizing.** The quota snapshot and the plan share it so `ObservedAt` and the reset-horizon math agree.
- **Only `cycle-state.json` proves a plane.** A bare `runs/cycle-N` directory is not proof: `evolve acs run` creates exactly that path under its own working directory, so an agent running it inside a cycle worktree would otherwise make the worktree the plane. Presence is the whole proof, so an empty `active_worktree` never demotes a real plane to the git fallback. The git common-dir walk (`mainProjectRoot`) is wrong whenever the plane is itself a linked worktree, because all linked worktrees share one common dir. Pinned by `TestSuiteProjectRoot_NestedPlaneWorktree` and `TestSuiteProjectRoot_FallbackToGitDerivation`.
- **The suite-root resolver falls back rather than guesses.** An absent, malformed, empty or non-string `active_worktree`, or another cycle's file, yields `""` and the `--root` default (`TestACSSuiteRootFallback`, `TestACSSuiteRootAutosolve_NullAndTypeMismatch_Amp`, `TestACSSuiteRootAutosolve_WrongCycle_Amp`).
- **Read-only branch walks cannot delete.** `audit` and a dry-run `prune` pass `alwaysOpenPR`, and `PruneSupersededOrphans` never deletes a ref with an open PR (`TestBranchesAudit_ReportsSupersededAndLandable`, `TestBranchesPruneDryRunDefault_KeepsSuperseded`). `remoteOpenPR` reports no open PR when the repo has no remote or `gh` is missing, since no remote PR can then protect the ref; a failing `gh` call is an error.
- **Campaign run and status agree on one progress file.** The goal hash (SHA-256 of the plan goal) keys both each cycle's `--goal-hash` and the checkpoint. `campaignEvolveDir` always absolutizes its root, because `status` passes the raw flag and a relative root would read an empty checkpoint and never see completed waves (`TestCampaignEvolveDir_AbsolutizesRelativeRoot`).
- **`--simulate` is a plumbing check, not an owned run.** It takes no ownership lease and installs no pre-wave hook, since the probes launch real CLIs (`TestCampaignRun_SimulateSkipsOwnershipLease`). A real run releases the lease on exit (`TestCampaignRun_AcquiresAndReleasesLease`). The owner record is informational; the flock is the liveness signal.
- **A rejected decisions file leaves `state.json` byte-identical.** Validation (non-empty unique ids, the keep/drop/cluster enum, a non-blank reason on every row, a `cluster_group` on every cluster row) runs in memory before any lock or write (`TestCarryoverApplyDecisions_RejectsMissingReason` and the `_amplify_` tests). A missing state file is an error, not an empty apply. The unlocked pre-read only skips a no-op write; `UpdateStateMap` re-reads under the lock. Entries that are not objects are kept. The lock and the symlink are pinned by `TestCarryoverApplyDecisions_UsesLockedRMW` and `TestCarryoverApplyDecisions_PreservesStateSymlink`.
- **Every `bridge.NewEngine` root is on record** with its call count and Signal Center wiring (`TestBridgeEngineRootsAreEnumerated`). Calls are counted through the import alias in the AST, so a comment never counts.
- **`bridge watch` never writes** the feed or the inbox, and `--follow` starts at the end of the feed so it does not repeat what the one-shot read printed.

## Findings

- **cycle 230**: `evolve acs suite` trusted the caller's working directory as the suite root, and the resulting topology nondeterminism false-FAILed cycles 226 and 227. The suite root now comes from the kernel-owned cycle state.
- **cycle 1434** (#449, an [ADR-0072](../adr/0072-system-failure-policy-and-halt.md) halt): the plane was itself a linked worktree, so the git common-dir walk skipped it and landed on the console checkout, whose `.evolve` had none of the cycle's run state. Three predicates went red against that root while the audit's own run was 8/8 green, and the CLI-written verdict won. The review then rejected a bare `runs/cycle-N` directory as proof of a plane. See runtime-reference.md and [egps-v10.md](../egps-v10.md).
- **cycle 644**: a frozen structural pin that closes an import cycle can never be satisfied. The probe library landed in cycle 1226 with no production caller, so nothing ran the check until `evolve reachability check-pin` wired it.
- **cycles 962 and 969**: `core.PruneSupersededOrphans` and `core.CarryforwardCandidateLandable` shipped tested but callerless; `evolve branches` became their caller.
- **cycles 997 to 1001**: the cycle-997 sweep authored the carryover decisions, but cycle 998 found the apply had never run and `carryoverTodos` still held 135 entries. Its eval fixtures had also assumed a flat top-level list instead of `{source_count, decisions}`, which `TestCarryoverApplyDecisions_RejectsFlatArraySchema` now rejects. In cycle 999 the hand-rolled temp-and-rename write replaced a worktree's `state.json` symlink with a detached file, stranding the 135-to-14 convergence in a dead copy. The write moved to `statemap` (cycles 999 and 1001). Cycle 1498 retired a consumed fleet alias through the same command.
- **cycles 1189, 1191 and 1194**: the `bridge watch --follow` tests flaked on a loaded macOS runner. The follow loop seeds its start offset asynchronously, so an append that lands first is skipped for good, and a fixed 10 ms sleep inside a 200 ms deadline lost that race. The tests now re-append on every tick and wait for the rendered line under a 30-second context.
- **F20** (2026-09-15): the loop ignored SIGINT and SIGTERM while its pre-wave probes ran, and the first fix let an interrupted canary clear a walled bench. That review also merged the loop's and the campaign's pre-wave protocols into `runPreWaveProbes`. See [verification-wave-findings-2026-09-14.md](../../research/verification-wave-findings-2026-09-14.md).
- **ADR-0059**: a second autonomous session killed the live 47-to-0 campaign three times, which produced the goal-hash ownership lease in the git common dir.
