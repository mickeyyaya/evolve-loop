## Purpose

`cmd/evolve` is the composition root and CLI of the `evolve` binary. It is `package main`: one handler per subcommand in the `commands` table, plus the wiring that builds the orchestrator, the loop and the campaign runner from the internal packages. It owns argument parsing, output formatting and the few decisions that belong to no internal package.

The cycle's production composition root, `wireOrchestratorDeps` in `cmd_cycle.go`, lives here too, beside its `--simulate` twin. It is the only place allowed to depend on every adapter at once, so it binds the adapters to the ports `core` declares. The routing-config seam it calls is [08-config.md](../decomposition/08-config.md), and the Signal Center topology it builds is [signal-center-design.md](../signal-center-design.md) ([ADR-0101](../adr/0101-signal-center.md)).

## Design

- **Thin handlers.** Each `runX(args, stdin, stdout, stderr) int` parses its flags and delegates. Most handlers exit 10 on bad arguments; `campaign`, `audit`, `build-invocation-context` and `cli-routing` exit 2. `reorderArgs` forwards to `cmdutil.ReorderArgs`, the one definition the extracted `internal/cli/*` groups share.
- **Removed budget flags.** `loop` and `cycle run` strip `--budget-usd`, `--budget` and `--batch-cap-usd` before `flag.Parse` in every form it accepts (`-f`, `--f`, `-f=v`, `--f=v`, `-f v`), with one WARN, so an old script gets a notice instead of a "flag provided but not defined" abort. A following token is the flag's value only when it parses as a finite float: `-1` is consumed, while `--cycles` and a goal word such as `NaN` are not.
- **One pre-wave probe protocol.** `runPreWaveProbes` serves both the loop (`prepareIteration`) and the campaign runner (`BeforeWave`). It runs the CLI-health canary, then the proactive usage probe, and returns the context's error.
  - The canary gives each expired bench one `bridge.LiveSmokeTest` through `defaultLiveProbe`, whose 4-minute bound derives from the runner's context. A clean probe clears the bench. A benchable wall re-benches it with one more strike (a doubled cooldown, or the pane's own reset hint); a credential wall (`clihealth.CredentialPattern`, [ADR-0106](../adr/0106-logic-first-delivery.md) Q2) re-benches the same way and the canary prints `clihealth.OperatorAction` — the operator's login makes the next probe succeed and clear the bench. Any other failure clears it too: non-wall failure classes belong to the capability probe and the fallback chain, and a canary that kept such a bench would re-probe it every cycle. Active benches are never probed.
  - The usage probe is opt-in (`cli_health.proactive_probe`) under the `EVOLVE_CLI_HEALTH` master switch, and fails open. It benches families already at a cap before the first phase boots them, through per-family controllers isolated under `<evolve-dir>/usage-probe`.
  - `bridgeUsageProbe` is the single way to send a family's usage command and read its pane. The cap probe and the budget quota probe (`probeWaveQuota`, under `<evolve-dir>/budget-probe`) both use it.
- **The boundary CLI update** (`cmd_cli.go`, `cmd_loop_cliupdate.go`; [internal-cliupdate.md](internal-cliupdate.md), plan C4 in [model currency](../../plans/model-currency-2026-10.md)). `evolve cli update [--dry-run] [--json] [--project-root P]` and the loop share one function, `updateCLIs`: it takes the families and seams from `cliUpdateWiringFn` (production: `productionCLIUpdateWiring`; `TestMain` swaps in an empty wiring so no test reaches a real updater), loads the record history (`cliupdate.LoadRecords`; an unreadable file is a WARN and an empty history), runs `cliupdate.Update` with it (or `Plan` for `--dry-run`), and records the accepted versions with `cliupdate.Remember`. A version that differs from the last record is smoke-booted first, so at loop boot a self-updated CLI's first launch is the boundary smoke, not the readiness gate (`TestRunLoop_AnUnrecordedAgyVersionChangeIsSmokeBootedBeforeThePreflightGate`). The verb (`cliUpdateVerb`, behind `runCLICommand`'s SIGINT/SIGTERM context) prints a `FAMILY STATUS VERSION DETAIL` table or the JSON report, and exits 0, 1 when any family is `update-failed` or `smoke-failed`, 2 on a usage error or when a run holds a live lease under `<evolve-dir>/runs` (`runlease.LiveRuns`; a mid-wave update would otherwise be recorded as a boundary `update` and pass `cli-version-drift` as expected; `--dry-run` still runs), and 130 when interrupted. Production seams: `Eligible` = `cliupdate.Unwalled(credentialWall(...))`, `Probe` and `Smoke` = `liveCheck`, `Run` = `cliupdate.Exec(cliupdate.GroupRunner)`; each family carries its manifest's `auto_update_off_env`, which the updater's env drops.
  - **Two boundary points, one update each.** At loop boot, `prepareFreshBatch` calls `bootGateHalts` after the unfinished-cycle guard: `bootCLIUpdateHalts` first, then the readiness gate (`loopPreflightHalts`); the catalog refresh runs later, at cycle start. At each later wave boundary, `probeSyncAndPublish` calls `updateCLIsAtBoundary` after the plane sync and before the dossier publish and the boundary refresh. The first iteration a process runs (`iteration <= cfg.ResumeWaves`) is left to boot, and a process re-exec'd at a wave boundary skips its boot update (`cfg.HandedOff`, from `takeReexecHandoff`; a re-exec at wave 0 hands off `WavesDone=0`, so the wave count alone cannot say), because the boundary that re-exec'd it already ran one. A chain resets both for its later batches. A `--resume` batch never updates: it continues a cycle.
  - **Only a smoke failure halts.** `haltOnCLISmokeFailure` sets `stop_reason: cli_update_smoke_halt`, puts the failed results in the loop result's `cli_update_halt` (family, old and new version, detail), and emits one `LOOP_HALT` incident whose fields name the families and versions; the batch exits 2. An `update-failed` family whose smoke passed, and a family `skipped` (a failed `doctor live` probe, a credential wall, an interrupt), are `[loop] WARN: cli-update:` lines and the wave proceeds. An interrupt during the update is an interrupt (exit 130), never a halt. Pinned by `TestRunLoop_TheBootCLIUpdateRunsBeforeThePreflightGate`, `TestRunLoop_ASmokeFailureAtBootHaltsBeforeAnyCycleNamingTheFamilyAndVersion`, `TestBootCLIUpdate_AReexecHandoffLeavesTheUpdateToTheBoundaryThatRanIt`, `TestPrepareIteration_ASmokeFailureAtAWaveBoundaryHaltsTheNextWave`, `TestPrepareIteration_TheFirstIterationOfAProcessLeavesTheUpdateToBoot`, `TestPrepareIteration_AnUpdateFailureWithAHealthySmokeWarnsAndTheWaveProceeds`, `TestPrepareIteration_AProbeFailureSkipIsALoudWarn`, `TestPrepareIteration_AnInterruptDuringTheUpdateStopsTheBatchWithoutAHalt`, `TestCLIUpdate_RefusesWhileARunHoldsALiveLeaseUnlessDryRun` and `TestCLIUpdate_AnInterruptExitsOneThirtyNotOne`.
  - **The composition root carries each family's manifest env into bare execs** (`process_env_wiring.go`): `init` calls `modelquery.UseProcessEnv(bridge.ProcessEnv)`, so the catalog refresh's `agy models` and `agy --help` (which `modelquery` runs itself, not through the bridge) launch agy with its self-updater off. Pinned by `TestLiveRefreshListers_ExecAgyWithItsManifestDefaultEnv`, which drives the production `DefaultRouter` and `DefaultEffortListers`.
- **Pending closeout dossiers are published only when no other run is live** (`cmd_loop_dossiers.go`, [cycle 1704](../../incidents/2026-09-26-a-failed-cycles-closeout-moved-main-under-a-passed-sibling.md)). A fleet lane leaves its dossier in `dossier.PendingDir`, and `publishPendingDossiers` commits it through `dossier.PublishPending`. Three sites call it: `prepareIteration` right after the plane sync, `loopResult.emit` (every loop exit) before the spine fail-open rollup, and `runLanesThenPublish`, which `evolve fleet` (through the `fleetLaunchFactory` seam) and each `evolve campaign run` wave run their lanes through.
  - The rule lives in the publisher, because `emit` also runs on exits taken while another run owns the plane (`owned_by_live_run`, `self_sha_boot_halt`, `unfinished_cycle`, `preflight_failed`, nothing to resume). It asks `loopchain.LiveSiblingRun`, the chain refresh's own rule (`FleetLaneActive` delegates to it), before the lock and again under the lock at the head of `publishHold`, immediately before the publish; a lease can appear while it waits (`TestPublishPendingDossiers_ReChecksForALiveRunOnceItHoldsTheLock`, through the `dossierPublishLock` seam). A run under `.evolve/runs` holds the pairs when its fresh lease belongs to another live process ("live pid N"), when a fresh lease has no owner pid, or when it is the run `cycle-state.json` names and has no readable lease; the WARN names the run dir and the reason and points at `evolve cycle reset` for a stale one. A discovery it cannot complete holds them with "cannot prove that no other run is live". The caller's own leases and a sealed lane's lease do not hold it (`TestPublishPendingDossiers_RefusesWhileAnotherRunIsLive`, `TestPublishPendingDossiers_NamesARunTheCycleStateNamesWithoutALease`, `TestPublishPendingDossiers_HoldsWhenItCannotProveNoOtherRunIsLive`, `TestLoopSummary_ASecondLoopExitingBesideALiveRunPublishesNothing`).
  - It holds the shared git-mutation lock (`flock.ShipLockPath`), and it commits only onto a plane current with or ahead of origin/main; behind, diverged or never fetched keeps the pairs pending with a WARN naming the relation. A plane without an origin has nothing to fork from and publishes.
  - With nothing pending it returns before the lock; outside a git checkout it does nothing.
  - The ordering is proved by behaviour: a publish moved before the sync diverges the plane and halts the boundary (`TestPrepareIteration_PublishesPendingCloseoutsOntoTheSyncedPlane`), and one moved after the rollup counts nothing (`TestLoopSummaryCountsTheLastWavesPendingCloseouts`).
- **Budget-aware wave sizing** (`cli_wave_budget.go`) is the host half of the two-layer sizing in [internal-loopwave.md](internal-loopwave.md). It measures quota and pace only when a `fleet.budget` block exists. Pace comes from the last `history_window` cycles. `paceBeforeNextWave` idles for the enforce-stage `PaceDelay` and an interrupt ends the idle.
- **`evolve acs run|suite`.** `run` runs `go test -json` on one package. `suite` runs the Go predicate lane ([ADR-0042](../adr/0042-egps-v11-go-native-predicates.md)) and exits 2 on any RED predicate, the harness reds included: a predicate package that fails to compile, declared tests that never ran, a spent lane budget and a cycle with no predicates are each a named `egps/` red in the written verdict ([ADR-0114](../adr/0114-the-acs-verdict-is-always-written-and-complete.md)). It exits 1 when the suite cannot run at all or the verdict cannot be written. `run` exits 1 when its `go test` exited nonzero with no predicate red to explain it, after writing the partial verdict, which carries the same `egps/no-predicates` red as the suite when no predicate ran. Both resolve `--evolve-dir` to an absolute, existing directory first and exit 10 otherwise, so a run from `go/` can no longer mint a phantom `go/.evolve/runs/` tree (`acsFlags.resolved`, `existingEvolveDir`). When `--root` is left at `.`, the suite root is the cycle's `active_worktree` from its `cycle-state.json`. The predicates' `EVOLVE_PROJECT_ROOT` is the parent of `--evolve-dir` when that directory holds this cycle's `cycle-state.json`, and otherwise the parent of the git common dir ([ADR-0053](../adr/0053-dual-root-source-state-resolution.md)).
- **`evolve apicover`** calls `apicover.Main`, the same entry as the standalone `cmd/apicover`, so a deployed cycle runs the API gate without building a second executable.
- **`evolve build-invocation-context`** (`runBedrock`) emits byte-identical output per role, so the prompt cache can reuse it.
- **`evolve branches audit|prune`** is the production caller of `core.PruneSupersededOrphans` and `core.CarryforwardCandidateLandable`. `audit` prints `<ref> superseded=<t|f> landable=<t|f>` for each local `cycle-*` branch. `prune` is a dry run by default (`would-prune`). With `--dry-run=false` it deletes a superseded ref only when it has no open PR, and reports `kept-open-pr` otherwise.
- **`evolve bridge`** is a thin CLI over `bridge.Engine`: `launch`, `probe`, `report`, `add-rule`, `send`, `watch`, `recipe`, `capabilities`, `introspect`, `control`, `doctor` and `billing`. It builds `bridge.NewEngine(bridge.Deps{})`, so it is a Center-less root and its bridge signals go nowhere (10-bridgeengine.md, "Where the stream is BLIND"). The `probe` JSON shape (`{os, results:[{cli,tier}]}`) is what the adapter parses. `introspect` exits 3 on catalog drift, which is non-fatal. `control` exits 3 for an unsupported family and event pair and 1 for any other failure. `watch` is read-only; `--follow` polls every 500 ms from the end of the feed until SIGINT or SIGTERM.
- **`evolve campaign study|replan|run|status`** ([ADR-0056](../adr/0056-advisor-driven-preliminary-study-cycle.md), [ADR-0059](../adr/0059-cross-session-campaign-ownership-lease.md)).
  - `run` verifies the plan, splits it into waves and runs each through `fleet.Supervisor` with `--concurrency` (default `campaign.MaxWaveWidth`) and `--cycle-timeout` (default 2 h; a cycle past it is reaped so it cannot hang the campaign). A wave's failed cycles get one batched retry, after `campaignQuotaCooldown`: the longest active quota bench, capped at `clihealth.MaxCooldown`, or zero when nothing is benched.
  - Progress is checkpointed per goal hash and bound to the plan's SHA. A rerun of an unchanged plan resumes after the last completed wave unless `--ignore-progress` is given. SIGINT or SIGTERM reaps the in-flight cycles and leaves that checkpoint intact. `status` reads the same checkpoint.
  - `study` and `replan` run the `preliminary-study` phase through a Center-less `bridge.NewDefault(projectRoot, nil)`. The phase is registered persistence-free (no `ProfilesDir`), which is why `phaseregistrar` refuses a phase with no `dispatch.cli` only when it would persist a profile.
- **`evolve carryover apply-decisions`** applies a reviewed keep/drop/cluster decisions file (`{source_count, decisions[]}`) to `state.json:carryoverTodos`. The TTL prune only removes expired entries; this command acts on a judgment. `drop` and `cluster` ids are removed, because clustered ids live on as sweep-group inbox items and would otherwise count twice. It is a dry run unless `--apply` is given. The write goes through `statemap.UpdateStateMap`: the path is symlink-resolved, the lock is taken on the resolved path, `stateRevision` is bumped and a stale write is refused. The 25-entry ceiling is reported with a WARN, never enforced.
- **`evolve cli-routing show|check|explain`** (`cmd_cli_routing.go`, `cmd_cli_routing_print.go`, 2026-10-06, L1b of the CLI routing table, [ADR-0119](../adr/0119-one-routing-table-one-resolver.md)) renders the routing table the dispatching roots compile, through the same `buildCLIRouter`, and writes nothing. `show [--static] [--json]` resolves every profile agent (for its own phase, with `balanced` as the default model) and groups the agents by chain, with each tier's first permitted CLI and model, the CLIs a tier ceiling drops, the claude-family `FLOOR`, the agent's findings and any benched family. `--static` resolves without the host: every binary counts as present, with no bench and no discovered tail. `check` compiles the table statically and exits 0 when it compiles (naming the legacy projection or the declared table and the warning count) and 1 on an error finding. `explain <agent> [--phase P] [--static]` prints one agent's rule, allowed set, chain, tiers and notes, and exits 1 when the router refuses that agent. `show` and `explain` also exit 1 when the table does not compile. All three take `--project-root` (then `EVOLVE_PROJECT_ROOT`, then the working directory), and a usage error exits 2. The write verbs (`set`, `unset`, `init`, `migrate`) are L2. Pinned by `TestCLIRouting_UsageErrorsExitTwo`, `TestCLIRoutingCheck_ExitsZeroWhenItCompilesAndOneOnAnErrorFinding`, `TestCLIRoutingShow_GroupsAgentsByChainAndNotesTheFloorAndTheCeiling`, `TestCLIRoutingShow_JSONCarriesEveryAgentRoute`, `TestCLIRoutingShow_ARefusedTableExitsOne` and `TestCLIRoutingExplain_NamesTheRuleChainAndAllowedSet`.
- **Every other dispatching root compiles the same table.** `evolve resolve-llm`, `evolve subagent run` and `evolve subagent validate-profile` build a router through `loadCLIRouter` and the production `routingHost`, print the findings and exit 2 (`exitRoutingRefused`) when it refuses, and resolve roles through `Router.ResolveRole` (`roleResolver` feeds `subagent.RunOptions.ResolveLLM` and `ValidateProfileOptions.ResolveLLM`). The loop's readiness gate compiles it with an empty host for its `cli-routing` check and its driver list (`preflightRouting`, `routedDrivers`; [internal-looppreflight.md](internal-looppreflight.md)). `TestOnlyCliRouteBuildsChains` (`internal/guards`) keeps `llmroute.Resolve`, `llmroute.ApplyUniversalFallback` and `resolvellm.Resolve` out of this package (2026-10-06, ADR-0119).
- **`evolve compose --phases`** runs registered phases in order through the orchestrator's factories without consulting the state machine, for re-audit and mix-and-match runs. It sets `PhaseRequest.ComposePhases`, so the kernel `evolve guard phase` hook warns instead of blocking. A verdict other than PASS or SKIPPED fails the composition, and the remaining phases still run. `ship` is refused without `--ship-anyway` (exit 2); the OS-level ship gate enforces regardless, so the early refusal only gives a clearer error.
- **`evolve reachability check-pin`** is the CLI over `reachabilityprobe.BuildImportGraph` and `CheckCallSite`; see [internal-reachabilityprobe.md](internal-reachabilityprobe.md).
- **`evolve cycle run`** absolutizes `--project-root` before deriving any path, reaps dead-owner tmux sessions (not under `--simulate`), then builds its deps through `wireOrchestratorDeps`, or `wireSimulateOrchestrator` under `--simulate`. Both return `orchDeps` and build the same signal topology through `newRootSignalCenter`.
  - Every fleet lane runs `cycle run` as a subprocess, and `fleet.Result` carries neither the lane's cycle nor its workspace, so the parent wave cannot apply a lane's verdict. The lane applies it itself through `closeoutCycleOutcome`: the inbox failure walk on FAIL (from an error or from the final verdict), the planned-no-work hand-off (`cycleoutcome.ApplyNoWork`, which also retires every scoped id no inbox item backs as rejected, so the next wave plans around it) for a lane that answered its scope without committing it, nothing otherwise. That mirrors the PASS half in `phases/ship/postship.go` and is what makes the [ADR-0072](../adr/0072-system-failure-policy-and-halt.md) retry ceiling reachable for fleet work. A closeout error is WARNed and never changes the exit code. One asymmetry is filed as `quota-pause-closeout-parity`: a resume paused by a quota wall defers the walk, while `cycle run` and the sequential loop charge it ([incident](../../incidents/2026-09-15-shipped-item-re-pinned-and-sealed-lease-blocks-refresh.md)).
  - The exit code is a lane's only channel back to its parent wave, so a halting `SystemFailure` gets its own code, and the lane writes the escalation dossier and the P0 inbox item itself through the helper the sequential path uses.
- **`evolve cycle reset`** seals through `core.SealCycle`. Liveness is decided there, from the per-run lease heartbeat plus the owner pid (`PidAlive`): a dead pid seals without `--force` even while its heartbeat is fresh, a live owner is refused with steering to `--resume` or SIGTERM (never `pkill`), and `--force` overrides a live owner with a WARN.
- **`evolve cycle timing`** renders `phase-timing.json` as a per-phase table plus the archetype roll-up (productive build, checking, planning, control), and a shadow estimate of parallelizing the independent checking phases when it saves time. With no cycle given it picks the highest-numbered cycle that has a timing log; a reset-suffixed directory parses on its leading integer. **`evolve cycle outputs`** is a thin adapter over `internal/phaseoutputs`, whose loaders the loop's post-cycle signal emitter shares, so the CLI and the signal stream cannot read a cycle differently. It resolves report names through the builtin plus user catalog, as the contract gate does.
- **The composition root `wireOrchestratorDeps`** builds in an order that matters:
  1. It pins the model-catalog dir to `evolveDir`, the `.evolve` the cycle-start refresher writes, whatever `EVOLVE_PROJECT_ROOT` says.
  2. It builds the Signal Center first and always, since the bridge takes it at construction. The ledger comes next, observed at its append chokepoint (`ledger.WithSignals`), so the bridge's stop-review callback can append `kind=stop_review` entries.
  3. It resolves routing config through the unit-08 Loader, the sole reader of routing env and registry ([08-config.md](../decomposition/08-config.md)), before the runners, so `cfg.PhaseIO` reaches the reconcile rung. `policy.json` can only add mandatory phases; it also supplies `ship_floor` and `failure_floor`. A malformed policy prints `[policy] WARN` and continues on a zero `Policy` for the mandatory merge. It used to fail loudly only at the first dispatch, where the runner reloaded it for pins; since L1b the routing table refuses it in step 4, before any dispatch (2026-10-06, ADR-0119; `TestWireOrchestratorDeps_AMalformedPolicyIsRefusedBeforeAnyDispatch`).
  4. It compiles the CLI routing table once ([internal-cliroute.md](internal-cliroute.md), [ADR-0119](../adr/0119-one-routing-table-one-resolver.md)), before any constructor. `loadPhaseCatalog` merges the user phases over the built-in catalog first (step 7's catalog, now loaded here), and `wireCLIRouter` builds the router through `buildCLIRouter` (`cli_routing_root.go`): the loaded policy, the merged catalog, the profiles directory, `bridge.HasToolUse` as the tool-capability check and `routingHost`'s production host. Every finding is printed as a `[cli-routing]` line. An error finding (or a malformed policy) sets `orchDeps.RoutingErr`, and `evolve cycle run` and `evolve loop` exit 2 (`exitRoutingRefused`) before any dispatch (`TestWireOrchestratorDeps_AnErrorFindingRefusesBeforeAnyDispatch`, `TestRunCycleRun_ARefusedRoutingTableExitsTwo`, `TestRunLoop_ARefusedRoutingTableExitsTwo`). The router is stored in `runner.DefaultRouter`, handed to `bridgechain.DefaultPlanResolver`, retro, the failure advisor, the routing advisor, the catalog publisher and `core.WithCLIRouter`, and returned as `orchDeps.Router`, so one router reaches every launch path (`TestWireOrchestratorDeps_OneRouterReachesEveryLaunchPath`). `routingHost` carries the cli-health bench and the universal-tail discovery: a memoized raw `bridge.Doctor` probe under a 30-second bound (`doctorDiscovery`, `memoized`), from whose report `universalFallbackTail` builds one `<family>-tmux` per installed, not-blocked family whose driver has tool use (`bridge.HasToolUse`); pinned by `TestUniversalFallbackTail_KeepsOnlyPresentFamiliesThatCanRunAWorktreePhase`. The router, not the tail, applies `workflow.universal_fallback_exclude`, once, for every launch path (ADR-0119 decision 6; `TestUniversalFallbackTail_LeavesTheExclusionToTheRouter`). That the checked-in policy keeps agy in the tail (the operator's 2026-10-05 addition of the Antigravity CLI) is pinned by `TestTheCheckedInPolicyPutsAgyInTheLastResortTail`. A timeout means no discovery, which fails loud, never a hang. (2026-10-06, L1b of the CLI routing table, ADR-0119: this step used to set the runner's `DefaultUniversalFallback` and `DefaultDiscoverCLIsFn` seams when `workflow.universal_fallback` was on, and `universalFallbackTail` itself subtracted the excluded families.)
  5. It wraps the bridge once in `bridgechain.New`. Every consumer (phase configs, the swarm decorator, retro, debugger, spec runners, registrar, advisors) launches through that chain-walking handle. The raw adapter is only configured: `Set*` calls, `wireBridgeStages`, the catalog publisher's resolver sink, and `orchDeps.Bridge`.
  6. Every `BaseRunner` reads the contract verifier through one accessor, so the verdict engine classifies the same bytes the contract gate approves. Gate off keeps the Null-Object `deliverable.PlainVerifier`; gate on swaps in the gate's reviewer.
  7. User phases (`.evolve/phases/<name>/phase.json`) merge over the built-in catalog (loaded in step 4, since the routing table compiles against it). Only valid specs are routed and get a spec runner, and runner registration uses the same catalog-aware validator as `phasespec.ApplyUserRouting`. `registerBuiltinSpecRunners` then gives every advisor-selectable `kind:llm` builtin without a hand-wired runner a spec runner. Control phases are skipped, and a phase with no persona file is WARNed rather than wired.
  8. The routing advisor resolves its dispatch through the router: `routerDecision` asks for `Resolve{Agent: "router", Launch: LaunchAdvisor}` with `opus` as the default model. With no `cli_routing` block the legacy projection reproduces the old order, `claude-tmux`/`opus`, then `.evolve/profiles/router.json`, then `policy.RouterPolicy` (`router.cli`/`router.model`), byte for byte against `legacy-advisor.golden.jsonl` (`TestLegacyAdvisorDispatch_MatchesTheGolden`); a declared table answers it from its own rules (`TestRouterDispatch_ComesFromTheTable`). Plan and re-plan use `PlanModel`, propose and judge use `ProposeModel` (`decisionModel`, [ADR-0052](../adr/0052-advisor-maximization.md)). A benched family falls back to the first unbenched candidate of the router's chain; the legacy chain ends with `claude-tmux`, so the result changes from the old hard-coded `claude-tmux` swap only for a router profile with a `cli_fallback`. With every candidate benched it keeps the chain's primary with `ok=false`, and the advisor degrades to the static spine, since `clihealth` is the only breaker. A routing refusal here is a `RoutingErr` too ("the routing advisor has no route"). The same advisor is the whole-cycle planner, which the orchestrator consults only at Stage ≥ Advisory in DynamicLLM mode. (2026-10-06, L1b of the CLI routing table, ADR-0119: `resolveRouterDispatch*` used to read `router.json` and `RouterPolicy` itself.)
  9. The failure advisor resolves its CLI through `Router.ResolveRole("failure-advisor", …)` (`failureAdvisorCLI`), with `GitRoot` pinned to the project root, because resolvellm's git fallback runs from the process cwd; with no `cli_routing` block that is `resolvellm.Resolve` over `.evolve/profiles/failure-advisor.json`, as before (`TestFailureAdvisor_ComesFromTheTable`). The mint registrar's `RegistryPath` anchors to the project root, where the tree-diff guard reads it ([ADR-0073](../adr/0073-crosslane-mint-registry-guard-exemption.md)).
- **The deliverable reviewer chain** is one `ChainReviewers`, because `WithReviewer` takes one reviewer. Each gate is gated on its own and fails open on ambiguity, and with every gate off no reviewer is wired. The order is:
  1. The build handoff floor's composed half, `composedBuildHandoffFloor(workflow, cfg)` in `cmd_cycle_config.go`, mounted as the `core.BuildHandoffFloor` list itself (the list is the only floor constructor; there is no opaque engine to mount): `production` (`productionBuildFloorChecks`: protected surface, then the deterministic engine, then ship's repo-contract scanner pack through `core.RepoContractFloorChecks`), plus `document-solution` (`SolutionFloorChecks`) when the registry declares a document contract; empty, so not mounted, when `workflow.build_floor` is off. Core's mandatory reviewer runs the mandatory half (the explanation check) ahead of the whole chain. It runs first because its rejection carries the defect list the correction ladder needs. - **`evolve solution check <slug>`** ([ADR-0099](../adr/0099-deliverable-kinds.md) slice 2) is the document deliverable's self-check and eval `[code]` grader. It runs the SAME engine (`internal/solutioncheck`) as the build handoff floor's `SolutionFloorChecks` and the audit gate, over the contract `docs/architecture/phase-registry.json` declares, so the three surfaces can never disagree on what a document deliverable owes. - **`evolve swarm status|reap|reap-orphans`** ([ADR-0032](../adr/0032-swarm-harness.md)) is the operator surface for the swarm harness's per-cycle session manifest (`<evolveDir>/runs/cycle-<N>/.swarm/sessions.json`): `status` reads it, `reap` is the crash-safe backstop for a hard SIGKILL of the orchestrator — the in-process dispatcher reaps on a normal exit, but only the on-disk manifest can recover the orphaned tmux sessions and process groups a crash leaves behind. `reap-orphans` sweeps every cycle's manifest at once and supports `--dry-run`.
- **`evolve sync-main`** reconciles a locally-diverged main with origin via a plain merge — the sanctioned successor to hand-running git after `ship`/`repair` refuses on a diverged origin (`repair.go` only ever preserves the local commit and points here; it never mutates the tree itself). It fetches origin, then `git merge --no-edit origin/<branch>`: a clean divergence produces a real merge commit, a conflict aborts back to the exact pre-merge state (`git merge --abort`) and refuses. It never rebases, force-pushes, or pushes — local history only ever moves forward via merge. Exit 0 merged (or already up to date); exit 1 refused/error, with the tree left unchanged on refusal (`TestSyncMain_MergesQuietDivergedTree`, `TestSyncMain_RefusesCleanlyOnConflict`).
- **`evolve tokens report [--last N]`** is the read-only token-telemetry reporter: it walks the last N cycles' `phase-timing.json` logs (the same per-cycle walk `budgethistory.Collect` uses for duration/cost) and rolls their per-phase terminal token usage into a ranked top-consumers table — the evidence for "which phase/site is burning the most tokens." `--json` emits the `TokensReport` struct for tooling. Missing or unreadable cycles are skipped as absent evidence, matching `budgethistory.Collect`'s degrade-gracefully contract.

## Invariants

- **A capacity deferral is nobody's failed approach.** The sequential dispatcher pauses on `core.ErrAllFamiliesExhausted` before it records a failed approach or runs the failure closeout, so a wall never demotes the item or counts as a recoverable failure (ADR-0106 Q3). Pinned by `TestRunLoop_AFreshCycleWalledOnCapacityIsNobodysFailedApproach`.

- **A cancelled canary touches no bench**, before the loop and after each probe: a smoke test cut short by an interrupt reports "not a wall", which would clear a bench that is still walled. Pinned by `TestCanary_CancelledContextTouchesNoBench`.
- **Probes run on the runner's interrupt context**, and `runPreWaveProbes` returns its error, so a caller never dispatches a wave that would be cancelled at spawn.
- **One `now` per budget sizing.** The quota snapshot and the plan share it so `ObservedAt` and the reset-horizon math agree.
- **Only `cycle-state.json` proves a plane.** A bare `runs/cycle-N` directory is not proof: `evolve acs run` creates exactly that path under its own working directory, so an agent running it inside a cycle worktree would otherwise make the worktree the plane. Presence is the whole proof, so an empty `active_worktree` never demotes a real plane to the git fallback. The git common-dir walk (`mainProjectRoot`) is wrong whenever the plane is itself a linked worktree, because all linked worktrees share one common dir. Pinned by `TestSuiteProjectRoot_NestedPlaneWorktree` and `TestSuiteProjectRoot_FallbackToGitDerivation`.
- **The suite-root resolver falls back rather than guesses.** An absent, malformed, empty or non-string `active_worktree`, or another cycle's file, yields `""` and the `--root` default (`TestACSSuiteRootFallback`, `TestACSSuiteRootAutosolve_NullAndTypeMismatch_Amp`, `TestACSSuiteRootAutosolve_WrongCycle_Amp`).
- **Read-only branch walks cannot delete.** `audit` and a dry-run `prune` pass `alwaysOpenPR`, and `PruneSupersededOrphans` never deletes a ref with an open PR (`TestBranchesAudit_ReportsSupersededAndLandable`, `TestBranchesPruneDryRunDefault_KeepsSuperseded`). `remoteOpenPR` reports no open PR when the repo has no remote or `gh` is missing, since no remote PR can then protect the ref; a failing `gh` call is an error.
- **Campaign run and status agree on one progress file.** The goal hash (SHA-256 of the plan goal) keys both each cycle's `--goal-hash` and the checkpoint. `campaignEvolveDir` always absolutizes its root, because `status` passes the raw flag and a relative root would read an empty checkpoint and never see completed waves (`TestCampaignEvolveDir_AbsolutizesRelativeRoot`).
- **`--simulate` is a plumbing check, not an owned run.** It takes no ownership lease and installs no pre-wave hook, since the probes launch real CLIs (`TestCampaignRun_SimulateSkipsOwnershipLease`). A real run releases the lease on exit (`TestCampaignRun_AcquiresAndReleasesLease`). The owner record is informational; the flock is the liveness signal.
- **A rejected decisions file leaves `state.json` byte-identical.** Validation (non-empty unique ids, the keep/drop/cluster enum, a non-blank reason on every row, a `cluster_group` on every cluster row) runs in memory before any lock or write (`TestCarryoverApplyDecisions_RejectsMissingReason` and the `_amplify_` tests). A missing state file is an error, not an empty apply. The unlocked pre-read only skips a no-op write; `UpdateStateMap` re-reads under the lock. Entries that are not objects are kept. The lock and the symlink are pinned by `TestCarryoverApplyDecisions_UsesLockedRMW` and `TestCarryoverApplyDecisions_PreservesStateSymlink`.
- **Every `bridge.NewEngine` root is on record** with its call count and Signal Center wiring (`TestBridgeEngineRootsAreEnumerated`). Calls are counted through the import alias in the AST, so a comment never counts.
- **`bridge watch` never writes** the feed or the inbox, and `--follow` starts at the end of the feed so it does not repeat what the one-shot read printed.
- **Every root carries a Signal Center, and the few exceptions are pinned.**
  - Every non-test `core.NewOrchestrator(` passes `WithSignalCenter(`, counted per file, and `internal/routingtest` is the one nil root (`TestNilSignalCenterRootsArePinned`).
  - Every `bridge.NewDefault` outside the cycle root passes an explicit `nil` (`TestNilSignalBridgeRootsAreExplicit`).
  - Every `ledger.New(` passes `ledger.WithSignals(` or is on the pinned list with its reason (`cmd_cycle_ledger_roots_test.go`), and every observer adapter gets its `.Signals` accessor (`TestObserverAdapterConstructionsAreWired`).
  - The console's WARN threshold lives only in `signalcenter.ConsoleSink` (`TestConsoleSinkThresholdHasOneHome`).
  - The cycle, loop and chain roots defer `Flush`, because an `Emit` that finds a drain in progress returns before delivery (`TestSignalCenterFlush_IsWiredAtBothRoots`).
  - The `--simulate` root builds the same topology (`TestWireSimulateOrchestrator_SignalCenterWired` and the per-unit `…WarningRenders` tests).
- **One contract verifier.** The verdict engine and the deliverables gate share one verifier, so a phase is classified on the bytes the gate approves (`TestWireOrchestratorDeps_ContractVerifierReachesEveryPhaseRunner`). The declared-deliverables gate rides the contract gate, which is on by default (`cmd_cycle_deliverables_gate_test.go`).
- **The raw bridge is never launched.** `bridgechain.New` appears once in `wireOrchestratorDeps`, and every other line that names `br` must match the allow-list (`TestWireOrchestratorDeps_EveryConsumerGetsTheChainWalkingBridge`).
- **Routing and dispatch validate user phases the same way.** Runner registration and `ApplyUserRouting` both call `ValidateUserSpecWithCatalog`; the bare `ValidateUserSpec` rejects optional built-ins such as `memo`, so the router would plan a phase that never dispatches (`TestWireOrchestrator_MemoRunnerRegistered`, against the real registry and overlay).
- **A mid-cycle mint reaches the bridge's contract resolver.** `catalog.Get` is bound to the pre-mint catalog value and `Catalog.Merge` returns a new map, so `catalogPublisher` installs a fresh resolver on every publish, a second mint in the same cycle included (`TestWireOrchestrator_CatalogPublisherWired`, `TestCatalogPublisher_RebindsResolverOnEachPublish`). Since L1b the same publish also recompiles the CLI router with the new catalog (`recompileRouter` → `Router.Recompile`), so a minted phase's profile routes in the cycle that minted it; a recompile that would carry an error finding is refused with a `[cli-routing] WARN`, and the table compiled at start keeps routing (2026-10-06, ADR-0119 decision 4; `TestCatalogPublisher_RecompilesTheRouterOnAMint`, `TestRecompileRouter_ARefusedMintWarnsAndKeepsTheTable`).
- **Only a reusable audit is carried forward.** `latestAuditEntry` is run-scoped, because the ledger is host-global across fleet worktrees and records FAIL audits too (`TestLatestAuditEntry_*`). `requireReusableAudit` reads the verdict from the bound artifact, since the ledger's `exit_code` is 1 for WARN and FAIL alike. It accepts only the audit phase's own sentinel, because the parser is tail-anchored and a quoted build-report sentinel would otherwise count. There is no fallback to an older PASS, and it runs before any git work (`TestRequireReusableAudit_*`, `TestReadCompositionSnapshot_RefusesFailBeforeAnyGitWork`).
- **The composed `apicover` gate enforces.** Its Makefile recipe must pass `-enforce` and read `go/.apicover-enforce`, pinned on the recipe text so the test never mutates the tree (`TestComposedApicoverGate_TargetRecipeEnforces`).
- **`--simulate` never touches the operator's git**: no commit, no `cycle-*` branch, no worktree, and neither the host's `gofmt -w` nor leak recovery touches tracked files (`TestWireSimulateOrchestrator_NeverMutatesGit`). A `--simulate` campaign runs no live probes (`TestCampaignBeforeWave_SimulateRunsNoLiveProbes`).
- **`cycle reset` compares absolute paths and fences on the lease, not the lock.** A relative root is absolutized before SealCycle's containment check (`TestRunCycleReset_RelativeProjectRootAbsolutized`). A held `.evolve/.lock` with no fresh lease does not block a seal, because the dispatcher's lock is released between cycles (`TestRunCycleReset_HeldLockAloneDoesNotBlock`). A live owner is refused with actionable steering (`cmd_cycle_reset_test.go`).
- **A stale lease never bricks a scope.** `continuationLaneIsLive` judges by heartbeat freshness alone, and an unreadable lease WARNs but does not block, so a dead lane's leftover `.lease` cannot lock its scope forever.
- **`dossier retro-mislabel` never rewrites the corpus it audits**, and its `candidates` count always equals `len(mislabeled)+len(uncorroborated)` — derived per record from a ledger or run-dir receipt, never estimated from the record's own reason string (`TestDossierRetroMislabel_DerivedCountCrossChecksArtifacts`). An absent `knowledge-base/cycles/` fails loudly rather than reporting zero (`TestDossierRetroMislabel_AbsentCorpusFailsLoudly`).
- **`isTaskLevelFailure` gates automatic quarantine to genuine per-task defect classes** (build/audit/ship-gate-config failures); infrastructure and integrity-breach classes never quarantine — they take the halt path instead (`TestIsTaskLevelFailure_AllClassifications`).
- **`evolve gc`'s workspace sweep never force-deletes unsalvaged work, and never deletes an unmerged branch.** `gc.PlanWorktrees` plans a plain removal only for a merged, clean, dead worktree/branch (`git branch -d`, never `-D`). A dirty or unmerged tree is flagged, unless its cycle closed out at least `gc.worktrees.salvage_after_hours` ago; then it is planned `salvage-remove`, whose apply writes the tree's uncommitted state to `.evolve/operator-salvage/<leaf>/` before `git worktree remove --force`, keeps the branch, and keeps the tree if the salvage fails. A live tree gets no action of any kind (`TestPlanWorktrees_DirtyIsFlaggedNeverRemoved`, `TestPlanWorktrees_UnmergedBranchKept`, `TestPlanWorktrees_AFinishedDirtyOrUnmergedTreePastTheSalvageAgeIsSalvageRemoved`, `TestApplyWorktrees_SalvageRemoveKeepsARestorableCopyAndTheBranch`, `TestApplyWorktrees_AFailedSalvageKeepsTheTree`, `TestPlanWorktreesNeverTouchesLiveDirtyUnmerged_Property`).
- **`evolve gc` signals a process only on an ownership proof**: an orphan (ppid 1) whose cwd is inside a cycle tree that is not live by `isLive` and is gone or closed out. An attached process, a live cycle's tree (including a resumed cycle that already holds its FAIL dossier), a numbered non-cycle directory and anything outside the worktree base are never signaled, and a preview signals nothing (`TestFinishedCycleOrphans_TakesOnlyOrphansWhoseCwdIsInsideAFinishedCycleTree`, `TestRunGC_TerminatesAnOrphanLeftRunningInAClosedOutCycleTree`).
- **The cache and temp steps are age-gated and off by default.** With `gc.go_cache_ttl_hours` or `gc.temp_ttl_hours` unset, the step prints that it is off and touches nothing. Set, it removes only Go cache entries, or temp entries of the pipeline's exact name shapes, whose mtime is older than the horizon (`TestRunGC_LeavesTheGoBuildCacheAloneWithoutAPolicyTTL`, `TestRunGC_TrimsGoBuildCacheEntriesUnusedPastThePolicyTTL`, `TestRunGC_ReapsStalePipelineTempArtifactsPastThePolicyTTL`).
- **A run-dir retention apply error fails `evolve gc`.** `gc.Apply`'s errors include real removal failures, not just refusals, so `gcRun.runDirs` returns failure instead of printing the error and passing it over (`TestRunGC_ARunDirRetentionCannotDeleteFailsTheRun`).
- **The `evolve gc` command tests never touch the host's tmux.** `gcWorktreeEnv` points `TMUX_TMPDIR` at a test temp dir, because the real reapers now unlink dead sockets' files. The loop-batch tests still run the loop's real socket sweep, which is filed as an inbox item.
- **`runGCHook`'s worktree/branch sweep is best-effort and fails open.** A `ProjectRoot` that is not a git repo warns and skips only the worktree sweep, leaving the pre-existing run-dir GC intact; it never panics or aborts the batch-end hook (`TestRunGCHook_NonGitProjectRootIsFailOpen`).
- **A tombstoned run registry (`.reaped` suffix) is an idempotent no-op for a later `ReapOrphans` sweep** — it is skipped, never re-swept, and a killed session's owning run is then discovered through `sessionrecord.ReadAllResolving` (tombstone-aware), not the live-path `ReadAll`. A session that still resolves to no owning run is a hard failure, not relaxed by the tombstone-aware path (`TestFleetSoak_AllFourInvariants`).
- **`laneGoalHash` prefers a lane spec's own `GoalHash`** over the wave/campaign-level fallback the launcher was built with, because a wave planner (`PlanFromTriage`/`PlanCycles`) can build a scoped spec with no `GoalHash` of its own, which would otherwise send the lane into `evolve cycle run`'s "--goal-hash is required" error and fall the wave back to sequential (`TestLaneGoalHash_FallsBackToLaunchGoalHashWhenSpecEmpty`).
- **The unit-08 seam stays single.** `cmd_cycle_config.go` holds the one Loader construction, the one policy-stages projection, the one bridge-stage forwarding (each dial on its own setter: `TestWireBridgeStages_*`) and the one build-floor composition, which is also the only reference to `core.DefaultBuildFloorChecks` (`cmd_selfcheck_test.go`). `parseGateStage` and `parseRouterStage` stay silent (`TestParseGateStage`, `TestParseRouterStage_LadderAndUnknown`) until their two readers' dials become `PolicyStages` fields (F2 in 08-config.md); a warning there would print outside the Center. The file is on the protected-surface manifest (`guards/integrity_surface.go`).
- **`readCarryoverCount` never reads an unreadable state as complete.** It returns `ok=false` for an absent, unreadable, or malformed `state.json`, so the caller skips the completion check rather than treating unknown state as a drained backlog (`TestReadCarryoverCount`).
- **`batchFirstCycle` is set before any cycle runs.** It is the only way a fleet batch's committed dossiers (whose lane cycles never return a `CycleResult` to the parent process) get rolled into this batch's spine fail-open totals; an unread window (0) reports nothing rather than folding all of history (`TestLoopSummary_RollsUpSpineFailOpensPerBatch`).
- **A ship-SHA auto-repin at boot never operator-authorizes.** `attemptBootRepin`/`defaultBootRecovery` repin `expected_ship_sha` only when the running binary's build-commit is provenance-verified (a git ancestor of HEAD); an unverifiable binary is refused and stays flagged, and a within-version mismatch (SHA differs but `expected_ship_version` matches the current plugin version) always halts pre-scout instead of auto-repinning (`TestDefaultBootRecovery_AutoRepinsWhenProvenanceVerified`, `TestDefaultBootRecovery_DeclinesRepinWhenProvenanceUnverified`).
- **The boot-quarantine stash label carries a timestamp.** A fixed constant label would let every boot quarantine collapse under one ambiguous name; `quarantineLabel` embeds a UTC RFC3339 timestamp so successive boot quarantines stay individually identifiable (`TestDefaultBootRecovery_QuarantineStashLabelIsTimestamped`).
- **Boot binary refresh never rebuilds while a fleet lane is active.** `bootRefreshFleetLaneFn` reads every `<EvolveDir>/runs/<run>/` lease heartbeat; a fresh lease or an unreadable/unparsable one both refuse the rebuild rather than risk swapping the shared plane binary out from under a running lane (`TestBootBinaryRefresh_ConcurrentFleetLaneStopsRefresh`, `TestBootBinaryRefresh_FleetLaneCheckErrorFailsOpen`, `TestBootBinaryRefresh_NoConcurrentLaneProceedsNormally`).
- **The boot refresh's ship pin is reconciled to the rebuilt binary before the re-exec, never after.** A present `expected_ship_sha` pin must repin via the same provenance-gated primitive the boot heal uses before `bootBinaryRefresh` execs; a decline skips the exec entirely, since the child would otherwise read the fresh hash as tampering and halt pre-scout.
