# internal/phases/audit

## Purpose

`internal/phases/audit` implements the audit phase's EGPS gate: it classifies a cycle's `audit-report.md` and `acs-verdict.json` into the phase's verdict, wiring the CI-parity gates (`ciparitygate`), the closure-citation gate, the explanation-documentation cross-check and the unit-09 defect ledger. `internal/phases/runner` hosts the shared dispatch machinery; this package supplies the `Hooks` and the verdict-classification logic. The composition root (`cmd/evolve`) and the phase registry are its callers.

## Design

- Verdict resolution order: an empty or unparseable verdict declaration is FAIL; a missing or unparseable `acs-verdict.json` is FAIL with an error diagnostic; `acs-verdict.json` `red_count > 0` is FAIL with an EGPS diagnostic; WARN under `workflow.strict_audit` is FAIL; otherwise the verdict is whatever `audit-report.md` declares (PASS/WARN/FAIL/SKIPPED).
- The verdict declaration is recognized in several agent-produced shapes — the canonical `## Verdict` heading and single-line inline variants such as `**Verdict: PASS**` — because prose formatting varies by CLI. `extractAuditVerdict` tries the machine-readable sentinel first (`phasecontract.ParseVerdictSentinel`), falling back to the prose grammar below `config.StageEnforce`.
- The regex-on-prose verdict fallback is single-homed in `reportdoc.Verdict` (ADR-0095): the dashboard's round history and the repair-brief seed read the same grammar as the gate, so what the gate scores and what the operator sees cannot disagree.
- `auditchain.ChainBlockExample` is the one constant shared by the persona's prompt illustration, the parser's own round-trip fixture, and the dispatched text, so the three cannot drift apart (ADR-0084). The chain parser is tail-anchored, so an auditor that echoes the persona's example block above its real one has the echo ignored.
- `GenerateVerdict` always runs the ACS predicate suite on every classification; an injected candidate never suppresses execution.
- The predicate tree is the tree Ship will commit (F43 part 2, component 4): `predicateTreeFor` requires the full tree (`treefence.Take`) to equal `shipmanifest.TakeShipTree` (read through `shipmanifest.GitIn`) at capture and at sealing. That tree is the index, every tracked edit and the paths the build and TDD reports declare, the same one the audit binding records and Ship stages, so an undeclared tracked edit ships and is audited, and only an undeclared untracked input is refused. Before, it compared against the tracked tree (`TakeTracked`, since deleted), so eight cycles' declared, untracked deliverables were refused. Replays: `TestPredicateTreeFor_Cycle1735_TheDeclaredExplanationDocumentIsInTheShipTree`, `TestPredicateTreeFor_Cycle1694_TheDeclaredPredicateAndEvalAreInTheShipTree`, `TestPredicateTreeFor_AnUndeclaredUntrackedInputIsRefusedByName`, `TestPredicateTreeFor_AnUndeclaredTrackedEditShipsAndIsAudited`.
- The predicate-tree refusal (`predicateTreeFor`) names the undeclared inputs: `treefence.Snapshot.Differing` lists every path that differs between the full tree and the ship tree, and `undeclaredInputs` carries the first 20 (`undeclaredInputsShown`) with a count of the rest as `cyclestate` detail, which the failure digest strips before it classifies or fingerprints. Before, the error named no path, so the correction directive could not say what to stage (F43, cycles 1626, 1647, 1674, 1684, 1685, 1694, 1705).
- `internal/phases/audit/ciparitygate` holds the deterministic CI-parity gates (go vet, acs-durable, the integration tier, apicover enforce and new-package graduation) that stop a cycle shipping green-locally / red-in-CI. `ciparity.go` is the seam between the audit phase and those gates: they are wired only through `NewDefaultWithStageCompactSpec` (production); `New(Config{})` leaves them nil so the package's own `go test` never recursively forks the go toolchain. They run in the phase-runner process (an unrestricted subprocess), never inside the sandboxed auditor LLM.
- The integration-tier gate reports what it measured locally, not what it infers CI would do: the real-tmux tier is guarded by `requireTmux`, which skips when tmux is absent from PATH. GitHub runners have no tmux, so a `requireTmux`-guarded offender found locally corresponds to no CI failure. The discriminator (`ciParityCaveat`) is derived from the same predicate `requireTmux` uses, not a hardcoded file list, so it stays accurate as the guarded set changes.
- The closure-citation gate requires a report that claims a prior cycle's defect is closed to cite the per-defect disposition record (`defect-dispositions.json` or `defect-ledger.json`) on the same line; an assertion like "verified closed" with no citation is unfalsifiable prose. The gate is line-scoped, not document-scoped: a whole-document reading, where one incidental mention of the disposition file vouches for every closure claim in the file, is the loophole the design refuses.
- Only the weak closure-claim rung (bare "closed" + a cycle reference) honors the negation/openness guards; the strong rung ("verified closed") accepts none, so an appended "…still open" clause cannot bypass an unambiguous laundering phrase.
- When a continuation cycle's defect-ledger reconcile has run and verified every inherited defect against its own per-id disposition, that machine record is strictly stronger evidence than the line citation the closure gate demands, so a prose closure-miss demotes to a warning diagnostic instead of a verdict-forcing FAIL (the formatting note is never waived, only its power to force the verdict).
- Classify reads the authoritative `ship_eligible` field from `acs-verdict.json` on the normal-completion path, symmetric to the timeout/reconcile path (both route through Classify, no duplicate branch), because `red_count==0` alone can diverge from ship-eligibility — a pre-staged or agent-written verdict, or a future acssuite that gates on more than the red count.
- On a verdict conflict, Classify surfaces both halves of the forensic pair from one call: the auditor's own declared narrative verdict, and the gate's own red identity facts (red_count and the normalized red ids, or `ship_eligible=false`), each as its own Severity=="error" diagnostic, so both ride `cyclestate.ErrorMessages` into `AuditFailReasons` and the dossier's SubstantiveError. The gate's evidence is additive: on a coherent verdict (auditor and gate agree) no conflict record is emitted, but the gate's own diagnostic still reaches the dossier untouched.
- The verdict-conflict reconciliation lives in Classify, not the auditor's prompt: acs-verdict.json is written after audit-report.md, so the auditor cannot reconcile its own narrative against a gate file that does not yet exist when it writes; Classify runs after both files exist.
- The conflict record's narrative token is validated to the four canonical verdicts (PASS/WARN/FAIL/SKIPPED): `narrative` originates from `phasecontract.ParseVerdictSentinelFull`, which rejects only the empty string and never otherwise constrains the value, and audit-report.md is LLM-authored content in an agent-writable workspace, so an unvalidated string could otherwise reach an error-severity diagnostic and the failure fingerprint. The three accepted values must still reach the operator verbatim, so the records are not byte-identical, but `narrative=<verdict>` is the one token they differ in — the contract `core.normalizeReasonForFingerprint` relies on to fold several attempts at one defect into one fingerprint.
- The closure-claim demotion applies only within the accounted lineage: a claim naming a cycle number outside the reconciled lineage, a ref-less strong claim ("verified closed" naming no cycle the machine record could vouch for), a lineage whose ancestor ledger is missing, a blocked reconcile (dispositions absent), and a non-continuation cycle (no lineage at all) all keep forcing FAIL. Pinned by the suite in `closure_claim_demotion_test.go`.
- Every gate that forces FAIL over a found, non-FAIL narrative — the three EGPS branches (unreadable acs-verdict.json, red_count>0, ship_eligible=false) and the seven CI-parity/gofmt/skills-drift gates — emits the same `verdict-conflict:` record naming the overridden narrative verdict. Exactly one record is emitted per Classify call no matter how many gates fired, because the record is a statement about the call, not about each gate. `workflow.strict_audit`'s WARN→FAIL promotion is deliberately excluded: it is a policy decision on a narrative the auditor already declined to pass, not a mechanical gate disagreeing with a clean read.
- `probe_quarantine.go` preserves any `*_test.go` file created after the audit dispatch under `<workspace>/audit-probes/` and removes it from the tracked tree before the EGPS suite runs: an adversarial auditor's engineered-failure probe left in the package under test would otherwise poison any predicate that shells `go test` over that package, misattributing the auditor's own failure to the builder. `go/acs/` is exempt from quarantine, since deleting the cycle's predicate package would remove the gate itself. The sanctioned way to write a throwaway probe is `go test -overlay`, which never writes into the tree.
- The dispatch anchor `probe_quarantine.go` uses to decide "new since dispatch" is the FIRST audit dispatch of the cycle, persisted under `audit-probes/`, not the latest: `bridge.Engine.Launch` rewrites `audit-prompt.txt`'s mtime on every retry, so anchoring on the latest prompt would let a stale probe from a dead first attempt slip through as apparent builder work on a later retry.

## Invariants

- A PASS verdict written inline as `**Verdict: PASS**` grades PASS, not FAIL, when `red_count==0`; multi-shape verdict recognition is pinned by `TestExtractAuditVerdict_Formats` and `TestRun_InlineVerdictFormat_PASS` in `audit_test.go`.
- `auditReportMaxBytes` (32KiB) bounds the size of `audit-report.md`; the overflow diagnostic is severity "warning", never "error", because `cyclestate.ErrorMessages` keys off `Severity=="error"` to build `AuditFailReasons`, and the check never reads a truncated copy — ship SHA-binds the full file. The check is diagnostic-only: an oversized but green report still ships, and the on-disk artifact is never mutated. Pinned by `TestAuditReportLength` in `audit_report_length_test.go`.
- The two apicover gates split ownership by shape: `apicoverEnforceChangedDefault` covers touched∩enforced changes — including a new exported symbol landing in an existing enforced package via a brand-new file, since `changedpkgs.ChangedPackages` folds both the handoff's `files_new` and `files_modified` buckets into one changed-package set — while `apicoverNewPackageGraduationDefault` covers only a genuinely new package and explicitly ignores an already-enforced package's new file.
- The integration-tier CI-parity gate is proven by behavior, not by grepping its command for a flag string: a fixture package carries an integration-tagged test with a genuine, unsynchronized data race (invisible to a plain `-tags integration` run, since an int race never panics, only silently loses updates) that only `-race` reliably reports, and a companion test proves the same fixture passes without `-race`, so a positive result is provably from the race detector and not a compile or logic error.
- `changedPackagesForAudit`'s second return value, `derivable`, distinguishes a genuinely clean git tree (nothing changed) from an underivable changed-set (git error, no repo, a fleet index-lock race). `apicoverEnforceChangedDefault` and `apicoverNewPackageGraduationDefault` each FAIL loud (a single actionable offender, err stays nil) when the module dir exists, an `.apicover-enforce` list is present, and the changed-set is underivable, instead of no-opping; a genuinely clean, git-derivable tree still stays `(nil, nil)`. Pinned by the `Test*_UnderivableChangedSet_FailsLoud` / `Test*_CleanGitTree_StaysNoOp` pairs in `ciparity_derivability_test.go`.
- The two documents that narrate the closure-citation gate (`docs/operations/batch-integrity-review-2026-08-04.md`, `docs/architecture/continuation-defect-ledger.md`) are run through the production `closureClaimOffenders` themselves, so a doc that announces the rule while breaking it cannot ship silently.
- The closure-citation gate's tests drive the rule through the real `hooks.Classify` seam rather than calling `closureClaimOffenders` in isolation, so a gate wired only to a unit test path would show up as dead code.
- Running the API-coverage gate over an enforced package must not create any executable file anywhere in the worktree, not just a historic `bin/apicover`: `apicover.Run` runs in-process, folded into the evolve binary, with no `go build -o bin/apicover` fork.
- The integration-tier subprocess always runs with a scrubbed allowlist environment (PATH survives, lane-leaked `EVOLVE_*` vars do not), matching CI's clean environment. On a red first attempt it retakes once under a cross-lane exclusive lock: a green retake is absorbed as a WARN-carrying flake, a red retake is genuine and FAILs with the retake's own offender lines; both attempts persist to `integration-tier.log`. Pinned by the `TestIntegrationTier_*` suite in `ciparity_unit_test.go`.
- The touched∧derivable decision for the three whole-repo CI-parity gates (go vet, acs-durable, integration-tier) has one owner; no gate re-derives the change-set independently. The no-Go-module guard is checked before derivability, so a worktree with no go module at all stays silent regardless of git state; a genuinely clean, derivable tree also stays silent; only an underivable change-set surfaces a WARN (not a FAIL, since a transient index-lock race must not hard-block a shippable cycle). Pinned by the `TestWholeRepoGates_*` suite in `ciparity_touchedgo_derivability_test.go`.
- The `.apicover-enforce` list is read before the derivable-changed-set check: a non-git root with go.mod and no `.apicover-enforce` is a silent no-op for both apicover gates, not the underivable hard-FAIL. Pinned by `TestApicoverGates_MissingEnforceListWinsOverUnderivable`.
- An underivable changed-set produces a severity asymmetry, byte-exact: the whole-repo CI-parity gates WARN with one shared underivable text, while the two apicover gates (enforce-changed and new-package-graduation) hard-FAIL with their own distinct offender sentence, because apicover scoping cannot safely no-op without a derivable changed-set. Pinned by `TestChangedSetUnderivable_SeverityAsymmetryBytes`.
- The per-Phase CI-parity adapter (`ciParity`) reads its package-var seams (`runCmd`, `integrationTierTimeout`) live on every call rather than caching them at construction, so a seam swapped after an earlier gate call is still observed by a later one built from the same adapter. Pinned by `TestCIParityFacades_ReadThePackageVarSeamsPerCall`.
- An Option over the full `Config` is honoured in full: a hook an Option sets through the production constructor is the hook the phase runs, never post-clobbered by the CI-parity wiring (which fills only the hooks no Option already set), and the hooks the Option left nil are still the wired production gates. Pinned by `TestNewDefaultWithStageCompactSpec_AnOptionSettingAHookIsHonoured`.
- `applyCIGate` keys off `len(offenders)`, not nilness: an empty-but-non-nil offender list is PASS at the consumer (no override, no diagnostic), while any non-empty list — even one item — FAILs. Pinned by `TestApplyCIGate_EmptyNonNilOffendersIsPass`.
- The integration-tier retake runs under a fresh budget: its context deadline is later than attempt 1's, never inherited from the same context. When the retake cannot even start (e.g. a fork/exec resource failure), the log holds attempt 1 only, the offenders are attempt 1's plus a pointer to the full log, and the cross-lane retake lock is released by the time the gate returns. Pinned by `TestIntegrationTier_RetakeUsesAFreshBudget` and `TestIntegrationTier_RetakeExecFailure_LogHoldsAttemptOneOnlyAndReleasesFirst`.
- The offender line `apicoverNewPackageGraduationDefault` emits for an ungraduated package carries the same copy-pasteable prescription the build-entry seam emits (the literal `.apicover-enforce` append line and the literal `apicover_named_test.go` path to create), not a generic instruction. Pinned by `TestApicoverNewPkgGraduationDefault_OffenderIncludesPrescriptiveFix`.
- `verdictConflictMessage` is the one place the verdict-conflict record's format lives; `core.normalizeReasonForFingerprint` stabilizes the `narrative=<verdict>` token and the bookkeeping-regrade classifier matches the record's head. Pinned by `bookkeeping_reason_singlesource_test.go`.
- The EGPS red_count diagnostic embeds the red predicates' semantic ac_ids (capped at 5, message stays one line), so distinct red predicates yield distinct failure fingerprints while a genuine recurrence of the same predicate on a later cycle still collides exactly on its cycle-stripped name. Pinned by `TestEGPSRedDiagnostic_CarriesPredicateIdentity` and `TestEGPSRedDiagnostic_CycleNumbersNeverEmbedded` in `audit_egps_red_identity_test.go`.
- A verdict with `ship_eligible:false` fails even when `red_count==0` and the auditor's narrative says PASS; a verdict with `ship_eligible:true`, or the field entirely absent (every verdict written before it existed), still passes on `red_count:0`. Pinned by the `TestRun_NormalCompletion_PassReport_*` suite in `audit_normalcompletion_reconcile_test.go`.
- A verdict conflict never collapses to one message: the auditor's verdict and the gate's red identity facts each ride their own error diagnostic, a coherent (agreeing) verdict emits the gate's facts with no conflict record, and a genuinely clean PASS emits no error diagnostics at all. Pinned by the `TestVerdictConflict_*` suite in `audit_verdict_conflict_egps_facts_test.go`.
- A cycle that trips several FAIL-forcing gates at once (e.g. EGPS-red, gofmt-dirty, skills-drifted and vet-broken together) still produces exactly one conflict record, and a gate that fails open (cannot run) never produces one. The returned verdict is byte-identical to the gate semantics alone; the conflict record never softens or changes what ships. Pinned by the `TestVerdictConflict_*` suite in `audit_verdict_conflict_gates_test.go`.
- `wiredDefectLedger` in `defect_ledger.go` is the ONE construction site of the production `defectledger.Ledger`; a source scan enforces this. Pinned by `TestDefectLedgerSeam_OneConstructionSite`. The Null-Object free-function facades (`emitDefectLedger`, `reconcileContinuationDefects`, `readDispositions`, `dispositionPreflight`) exist only for by-name tests and ACS predicates and have no production caller; production always goes through `hooks.defectLedger()`. Pinned by `TestNullLedgerFacades_HaveNoProductionCaller`.
- The disposition pre-flight (`dispositionPreflightMissing`/`dispositionPreflightIncomplete`) names `defect-dispositions.json`'s absence or partial coverage as one structural diagnostic distinct from the per-id "(no disposition)" fallthrough text, so an operator reading N unrelated-looking per-id gripes also gets one line stating whether the file itself is entirely missing or short of the inherited-id set.

## Findings

- A write-one-artifact-and-die class once let a session tear down before the auditor wrote `defect-dispositions.json` on a continuation cycle, losing lineage accounting; declaring it as a secondary artifact (see ADR-0074) now holds teardown until the auditor writes it.
- The gofmt and SKILL.md-drift checks exist because a cycle-scoped audit that never ran `gofmt` or the skills-drift projection over the worktree could ship locally clean and then go CI-red on `gofmt -d -s .` or `TestSkills_NoDrift` — a cycle that edits `.evolve/profiles/*.json` without regenerating a `SKILL.md`, or that leaves a generated file unformatted, is exactly the gap both checks close.
- `NewDefaultWithStageCompact` once shipped without a test naming it, and `apicover -enforce` flagged it as an uncovered export; `TestNewDefaultWithStageCompact_NamedPhase` exists to name it.
- A PASS report written as `**Verdict: PASS**` with `red_count==0` was once mis-graded FAIL because the parser only recognized the canonical `## Verdict` heading shape; `extractAuditVerdict` now tries several agent-produced shapes.
- The registry `init()` and the loop's runner map once constructed the audit phase through two different paths, and only one of them wired `GenerateVerdict`; the dormant path force-failed every cycle on a missing verdict. `NewDefault` is now the one seam both paths must use.
- A dropped or zero `ContractVersion` once silently disabled the explanation-documentation gate entirely: `Verify` resolved inactive and audit returned nil. The cross-check now fails loudly when a zero version meets an active host activation, or a live version meets none.
- Distinct red ACS predicates that produce a byte-identical generic reason (e.g. a bare "red_count=1") can collide on the identical-fingerprint breaker even though they are different defects; the EGPS diagnostic names each red predicate (with its cycle-numbered prefix stripped to a stable semantic name) to keep fingerprints distinct per defect.
- A red-count-only phantom-binding message once pushed agents toward deleting the predicate, the cheapest fix, instead of repointing it; the message now states the cure and forbids deletion in the same line.
- A local integration-tier run under a wave's own concurrent agent tmux sessions produced `TestRealTmux_Interactive_*` timeouts (exit 80) that passed cleanly on a quiet host and in CI; `ciParityCaveat` exists so that kind of host contention is not read as a CI-real failure.
- Unbounded substring matching on "closed" once matched inside "disclosed"/"foreclosed" on a line that explicitly asserted openness ("still open"), force-failing a narrative-PASS audit; the matcher is now word-bounded and the weak rung's negation/openness guards exclude such lines.
- Plain substring matching on "verified closed" once flagged an auditor who correctly quoted the repo's own canonical (still-open) defect text while reporting it as open; `stripQuotedSpans` strips quoted spans so quoting a claim reads as reporting it, not asserting it.
- Negation markers ("still open", "not closed") were first rejected as a bypass cheaper than the citation demand, then admitted for the weak closure-claim rung only, after several false-RED halts on lines that correctly refuted a closure; the strong rung keeps the original rejection in full.
- The naive `\bclosed\b` boundary matched inside compounds like "fail-closed" (a state adjective, not a closure claim) because a hyphen is itself a word boundary; `closureClosedTokenRE` uses `(?:^|[^-\w])` instead.
- A citation path like `.evolve/runs/cycle-N/...` was once the only cycle token on a line and force-failed an otherwise clean, narrative-green audit; path tokens are now dropped before the weak rung's cycle-reference check.
- The reasoning-chain shadow stage produces comparison data (whether the chain agrees with the narrative verdict, and which link the narrative was silent about) before any enforcement decision is made on it: the chain is parsed, concluded and recorded beside the cycle, but the phase's verdict never moves, and an absent chain block (the common case mid-rollout) is recorded as absent, never inferred as coherent or invented as empty.
- A shadow wave once dispatched three audits with byte-identical, chain-instructing prompts and only one of the three emitted a reasoning chain: the persona's line budget had 5 lines of headroom but the chain example is 9 lines, so the instruction described the format in prose without ever showing it. Injecting `auditchain.ChainBlockExample` directly into the dispatched prompt fixed this.
- A per-attempt-varying narrative (routine LLM phrasing like "PASS (2 caveats)") would mint a different failure fingerprint on every retry for the same defect, defeating the runaway-loop halt, and a newline-bearing sentinel verdict could render as multiple reason lines in the operator-facing dossier, letting one FailReasons entry forge a second, authoritative-looking line; the conflict record's narrative token is validated to a single canonical value for exactly this reason.
- Three audit FAILs were once tier false-REDs, with every named test passing in isolation in the failed cycles' own preserved worktrees: the gate subprocess inherited the lane's full environment (a nil env defaulting to `os.Environ()`) while CI runs clean, and `-race` integration tests starved under live fleet contention.
- The `go` workflow's `-tags integration` CI job (which runs `TestFleetSoak`, among others) once went red while the per-cycle audit stayed green, because the CI-parity gates ran go vet, acs-durable and apicover but never the integration tier; the integration-tier gate closes that hole. It then ran `go test -tags integration` without `-race`, one flag short of the CI step it mirrors, so a genuine data race in a touched package passed audit clean and only surfaced on the same CI tier the gate exists to pre-empt; the gate now runs with `-race`.
- `changedPackagesForAudit` once returned nil identically whether the tree was git-clean (nothing changed) or the changed-set was genuinely underivable (git error, no repo, a fleet index-lock race); both apicover gates treated a nil changed-set as "nothing to enforce" and silently no-opped — a fail-open PASS on exactly the cycle that most needed the gate.
- A prefix drift between a minted `AuditFailReasons` string and its `core` matcher can silently disarm the bookkeeping-regrade classification, making the eval quality gate vacuous without any test noticing; `bookkeeping_reason_singlesource_test.go` binds the real producers (defect_ledger.go, closure_claim.go, audit.go's verdict-conflict record) against the real `core` matchers to catch that class of drift.
- A FAIL dossier whose SubstantiveError named only a deterministic gate's own finding (e.g. "gofmt: 3 file(s) are not gofmt -s clean") could not be told apart from one where the auditor itself independently found the cycle broken; every FAIL-forcing gate now also records the auditor's overridden narrative verdict.
- A bare "EGPS: red_count=N" message with no predicate identity once let three distinct red predicates flaking under concurrent-lane contention produce a byte-identical failure reason, so the pipeline's identical-fingerprint breaker halted a batch on what were three distinct honest failures; the diagnostic now names each red predicate's semantic identity.
- A cycle-number normalizer that only stripped the three-part `TestC<cycle>_<index>_<Name>` shape left the cycle chrome embedded in the two-part `TestC<cycle>_<Name>` shape (e.g. leaving "C841_" in place), silently defeating the identical-fingerprint breaker for that naming convention; the normalizer now strips the C-group and the index group independently.
- The probe-quarantine anchor is audit-dispatch time only, so a probe left behind by an earlier adversarial-review phase pass is classified as builder work; that phase is responsible for deleting its own probes, and the residual risk is accepted rather than guessed at, since a wrong guess would quarantine bug-reproduction's legitimate repro tests.
