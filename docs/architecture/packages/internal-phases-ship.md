# internal/phases/ship

## Purpose

`internal/phases/ship` implements the native Go commit-and-push phase as a `core.PhaseRunner`. Unlike the LLM phases, it calls no Bridge: `Phase` runs the native atomic shipper directly, reproducing the audit-binding / EGPS-gate / atomic commit+ff-merge+push state machine that `legacy/scripts/lifecycle/ship.sh` used to own. `New`, `NewWithDefaultRunner` and `NewWithDefaultRunnerStage` construct the phase; `Config` and its `Runner`, `NowFn`, `PhaseIO` and `ManifestGate` fields are the seams production wiring and tests set.

## Design

- The package is organized by concern. Each file holds one concern:
  - `ship.go`: `Phase` and `Config`.
  - `audit.go`: the audit-binding verification.
  - `commitgate.go`: the review attestation for `--class manual`.
  - `consume.go`: the inbox consumption in the commit.
  - `carry.go`: the re-proof of a rebase carry for an audit whose HEAD moved.
  - `gitops.go`: the atomic commit, merge and push state machine.
  - `gitops_landing.go`: the seam into the `landing` leaf package.
  - `dryrun.go`: the DryRun journal.
  - `binary_staging_guard.go`: a backstop at staging time against binary commits that are accidental.
- Interactive commits route through `evolve ship --class manual` (a bare `git commit` is ship-gate-blocked), and ship runs that commit as an internal subprocess a PreToolUse hook cannot observe — so `commitgate.go` is the single enforcement point for the review attestation: it verifies here, at the real chokepoint, reusing the same `sha256(git diff HEAD)` the commit-gate writer (`internal/commitgate`, via `evolve commit-gate run`) stamped into the attestation.
- Review-attestation verification applies only to `--class manual`: `--class cycle` keeps audit-binding since autonomous cycles are exempt by construction, and `--class release`/`--class trivial` are driven by their own pipelines and are not interactive commits.
- `reviewTrailer` renders one `Reviewed-by: <name>` git trailer line per commit-gate attestation reviewer, and a `Review-waived: <waiver>` line when the attestation records the commit gate's review waiver (`review_waiver`, `comment-only` today), making "was this commit reviewed, by whom, or why not" a durable, machine-parseable property of the commit SHA (`git log --format='%(trailers:key=Reviewed-by)'`). A `--bypass-commit-gate` commit carries neither, so `git log` tells a waived commit from a bypassed one (`TestCommitGate_GitLogTellsAWaivedCommitFromABypassedOne`). It decodes the attestation into `commitgate.Attestation`, the writer's own type, so the schema has one home and ship's tests write attestations with the writer's `Marshal`. It returns `""` unless the class is manual, the commit gate was not bypassed, and the attestation parses with at least one valid reviewer name or waiver; a value spanning lines is dropped (`writeTrailer`), so a corrupt attestation cannot inject trailer lines, and a read or parse error is treated as no attestation (`TestReviewTrailer`).
- `runPersonaLint` wires `phasecoherence.Check` + `CheckArtifactNames` into the ship gate for both `--class manual` and `--class cycle`, so persona↔profile drift cannot silently enter the commit chain. It reads `agents/` under `opts.ProjectRoot` and profiles under `<ProjectRoot>/.evolve/profiles`. A `"disallowed"` violation (a persona declaring a tool its profile forbids) blocks with `*IntegrityError`; an `"undeclared"`/artifact-name `"mismatch"` violation (the profile allows more than the persona declares) logs loudly but never blocks. A missing `agents/` or profiles dir skips the lint with a log, and `Options.BypassCommitGate` skips it too. (TestPersonaLint_CleanTreePasses, TestPersonaLint_ViolationBlocks, TestPersonaLint_UndeclaredDriftLogsButPasses, TestPersonaLint_MissingDirsSkips, TestPersonaLint_BypassSkipsLint, TestCommitGate_CyclePersonaLint)
- `DryRun` mode has every would-be mutation site append a tag to an in-memory journal; `writeDryRunJournal` writes the full journal to `.evolve/release-journal/dry-run-<ts>.json` on exit, so operators and parity audits can compare the planned operations against what a real run would do.
- The PASS ship commit itself carries in-commit inbox consumption: the tracked root item file moves to the tracked `inbox/consumed/` with a consumption annotation, and both paths are staged into the very commit that lands the work — this is what lets `main` stop offering a closed item the moment the work lands, instead of relying on a later, gitignored `processed/` promotion a fresh lane worktree would never see.
- `consumeCommittedItems`'s id set is resolved by the same function postship's post-ship promotion uses (`committedInboxIDs`); reading triage's `top_n` alone (rather than also unioning lane-scope and Closes-Inbox ids) is what left consumption at zero on carryover-driven and decomposed lanes. (TestConsume_ResolvesIDsLikePostShip)
- `committedInboxIDs`'s lane-scope union: a PASS lane ship retires its assigned lane-scope ids regardless of triage renaming, decomposing or dropping them, with one exception — an id triage explicitly deferred stays pickable. Only a close-class drop reason (e.g. "already-shipped") consumes; an unrecognized reason, including a `"stale:"`-prefixed premise-recheck tag, keeps the item, since forgetting a live todo is worse than carrying a stale one. A present triage decision that committed zero ids and says nothing about the scope id keeps it pickable (lane-scope union must never override an explicit empty commitment). Lane scopes are multi-item menus: triage may commit a subset and leave a menu-mate pending as dispatchable backlog, and when triage engages the scope by name, an unmentioned mate must not be consumed. The widened union is PASS-only; a WARN landing promotes exactly the pre-union set. (TestCommittedInboxIDs_UnionsLaneScopeWhenTriageDroppedTheScope, TestCommittedInboxIDs_UnionsLaneScopeWithDecomposedTopN, TestCommittedInboxIDs_TriageDeferredScopeIDStaysPickable, TestCommittedInboxIDs_DeclinedMenuUnmentionedScopeStaysPickable, TestCommittedInboxIDs_PendingMenuMateStaysPickable, TestCommittedInboxIDs_DropReasonGate, TestCommittedInboxIDs_WarnLandingGetsNoScopeUnion)
- A rebase carry lets an audit verdict follow a change across a clean rebase without a full re-audit.
- Since 2026-10-21, ship accepts no `trivial-rebase` record. `composition.go` and its `tryTrivialRebaseCarryForward` are removed with RUNG 0. A moved HEAD with no other carry is `AUDIT_BINDING_HEAD_MOVED` (`TestVerifyAuditBinding_ARetiredTrivialRebaseRecordNeverCarriesAMovedHead`).
- `carry.go` has `carrySatisfied`, ship's own re-proof of an "identical rebase" carry claim. It does not trust the ledger record. It verifies the ledger hash chain with `ledger.New(...).Verify`. It checks git ancestry from the audited base through the audited HEAD to the current HEAD. It re-derives the tree-delta identity and recomputes the patch-id. (See ADR-0105)
- Since 2026-10-07 a held tree may differ from the carried tree of the record only by the sanctioned inbox consumption of the re-ship (`carryExplains`).
- Every binding check applies one rule: `auditBindingSatisfied`. The sites are the worktree and direct-path pre-commit and post-push checks, `verifyExecutionTree`, and the resume-unpushed heal in `repair.go`. The check before the push (`verifyLandingCommit`) uses it too.
- Since 2026-10-17 the post-push idempotency gate (`checkPostPushIdempotency`, `native.go`) and `verifyPostPushPredicateEvidence` (`audit.go`) use the rule. Each runs on a copy of the options that is bound to the audit in the ledger (`resumedAuditView`, `boundAuditView`).
- A carried ship that stops after its push therefore resumes report-only and does not re-audit. A drift that no re-proven carry explains still falls through to the full gates. (TestCheckPostPushIdempotency_HealsACarriedShipInterruptedAfterItsPush, TestCheckPostPushIdempotency_DoesNotHealADriftNoCarryExplains, TestVerifyPostPushPredicateEvidence_AcceptsACarriedLanding, TestVerifyPostPushPredicateEvidence_RefusesALandingNoCarryExplains)
- `carrySatisfied` never declines silently (since 2026-10-06). It is split into `boundCarryRecord` (the newest `identical-rebase` record for the bound audit must name the bound audited tree), `carryExplains` (the held tree is the record's tree, or differs from it only by the re-ship's sanctioned inbox consumption) and `reProveCarry` (the whole-ledger Verify, both ancestry edges, the tree-delta identity on the record's tree, the patch-id), and it returns the first reason that failed. `auditBindingSatisfied` appends `(carry not re-proven: <reason>)` to its failure detail, so the TREE_MISMATCH message of `verifyExecutionTree` and both integrity-breach messages name why; before, the live refusals read `… error=<nil>` and six carries were re-audited with no cause on record ([incident](../../incidents/2026-10-06-carry-refused-ledger-verify-f5.md)). When a record named the audit but was not re-proven, it also raises `SHIP_CARRY_NOT_REPROVEN` (a ship.warning with `carry_cycle`) through `Options.Signals`; a drift no record claims stays the tree-binding refusal's to report. A record that names the bound audit but another audited tree counts as such a record and signals. (TestVerifyExecutionTree_NamesWhyACarryWasNotReProven, TestCarrySatisfied_SignalsACarryRecordItCouldNotReProve, TestCarrySatisfied_SignalsARecordThatNamesAnotherAuditedTree, TestCarrySatisfied_SignalsNothingWhenNoCarryNamesTheAudit)
- The carry's whole-ledger Verify is what made one carry's lost evidence refuse every later carry: the identity carry kept its diffs in the cycle worktree (ADR-0105 F5). The ledger now keeps them in its content-addressed store, so a second carry ships after the first carry's worktree is gone. (TestVerifyAuditBinding_ShipsASecondCarryAfterTheFirstCarrysWorktreeIsGone, the 1782/1810 shape)
- The carry composes with the re-ship's inbox consumption (since 2026-10-07). A carried lane's re-ship consumes its inbox items again (ADR-0105 B1), so the tree ship holds after a carry is the record's tree plus that consumption. The carry once accepted only a held tree equal to the record's, and the consumption rule measures from the audited tree, so main's newly landed paths read as unsanctioned: neither rule alone accepted the sum, and cycle 1825 was sealed FAIL on a false `INTEGRITY_TREE_DRIFT` ([incident](../../incidents/2026-10-07-cycle-1825-carry-refused-the-reships-consumption.md)). `carryExplains` now requires the drift from the record's tree to the held tree to be only the sanctioned consumption (`treeDriftExplainedByConsumption(rec.TreeStateSHA, held)`), then re-proves the carry on the record's own tree; a decline names the paths the consumption does not explain. Every binding check shares the rule through `auditBindingSatisfied`, so the pre-commit and post-push checks compose the same way. An unprovable carry still returns to audit at the verify-class check, before consumption; a carry that stops re-proving between that check and the pre-commit check is still an integrity refusal (inbox `pre-commit-carry-refusal-returns-to-audit`). (TestVerifyStagedTree_ACarriedRebaseShipsWithTheReShipsInboxConsumption, TestVerifyStagedTree_ACarryPlusConsumptionStillRefusesAnUnsanctionedExtraPath, TestVerifyCommittedTree_ACarriedRebaseShipsWithTheReShipsInboxConsumption, TestVerifyCommittedTree_ACarryPlusConsumptionStillRefusesAnUnsanctionedExtraPath, TestCarrySatisfied_DeclinesWhatTheReShipsConsumptionCannotCompose)
- `enterShipWindow` (`shipwindow_lease.go`) takes the ship-window lease ([internal-shipwindow](internal-shipwindow.md)) for a cycle ship that is not a dry run. `verifyAndLandInShipWindow` holds it over `verifyClass` (the audit binding) and `atomicShip` (the commit, the re-proof of a recorded carry and the push). The lease ends before `postShip`.
  - `resumeLanding` takes the lease before the integrator lock, so a resumed landing pushes inside the window.
  - The repo-contract pack, the explanation gate and the self-SHA check run before the lease, so a sibling lane can ship during the scan.
  - A ship in a context that the orchestrator marked with `shipwindow.WithHeld` does not take the lease again.
  - A canceled wait logs `[ship] WARN: ship-window lease not acquired (<err>); proceeding unleased`, and the ship goes on. A break of a live holder at the TTL logs a WARN and emits `SHIP_WINDOW_LEASE_BROKEN`.
  - Pinned by (TestShip_TheShipWindowCoversTheBindingTheCarryGateAndThePush, TestShip_AResumedLandingPushesInsideTheShipWindow, TestPhase_TheRepoContractPackRunsOutsideTheShipWindow, TestEnterShipWindow_AHeldContextReentersWithoutWaitingOrReleasing, TestEnterShipWindow_BreakingAHungHolderWarnsAndSignals, TestEnterShipWindow_AWaiterOutlastsAHealthyHolderWithoutAWarn, TestEnterShipWindow_ACanceledWaitShipsUnleasedWithAWarn, TestEnterShipWindow_OnlyALiveCycleShipTakesTheLease, TestEnterShipWindow_AReleaseFailureIsLogged)
- `acquireShipLock` takes a blocking flock (`.evolve/ship.lock`) serializing the shared-main integration critical section; both `shipDirect` and `shipFromWorktree` hold it across their mutating section so two concurrent ships cannot corrupt main's index/ref/origin. See ADR-0049.
- `cycleStateFile` prefers the per-run `run.json` mirror over the global `cycle-state.json` when `WorkspacePath` is set, so a concurrent cycle's host-global file cannot make ship integrate the wrong run's worktree or cycle number; it falls back to the global file for a standalone `evolve ship`. See ADR-0049.
- `--class release` stages the explicit release set instead of `git add -A`: `add -A` would sweep untracked operator files (logs) into the release commit, and the churn discard would delete the release's own freshly rebuilt `go/evolve` binary (the pipeline's rebuild-binary step is the audited producer of that file for a release).
- `stageExplicitPaths` stages a non-release ship as an explicit `git add -A -- <paths>` pathspec, never a blanket `git add -A`: `-A` scoped to a pathspec safely stages adds, modifications and deletions idempotently within those paths, while a plain `add -- <path>` fatals rc=128 on an already-staged deletion. An empty selection stages nothing and runs no `git add` (`shipmanifest.StageRetrying` never calls the stager with an empty set): `git add -A --` with no pathspec stages the whole tree, so a selection emptied by gone or ignored paths swept undeclared files into the commit while the log said "staged 0 explicit path(s) … no `git add -A`" (F43 component 4, `TestStageExplicitPaths_NothingSelectedStagesNothing`; the direct push golden dropped its recorded empty `add -A --` call for the same reason).
- Which paths a non-release ship commits is decided in [`internal/shipmanifest`](internal-shipmanifest.md), not here: `shipmanifest.Select` reads the porcelain, takes the declared manifest (`ReportFiles`), composes `Stageable` and runs the `check-ignore` probe, and `StageRetrying` decides the one retry after git's own refusal; the gate's uncovered set (`OutOfManifest`) and the git path decoder (`UnquoteGitPath`) live there too. Ship keeps the git execution and its options: `stageExplicitPaths` passes its capture as the reader, logs the probe outcome (`logIgnored`), and runs the `git add` (`explicitAdd`, whose `failure` classifies a refusal); `reconcileManifest` applies the shadow/enforce manifest gate (`ManifestGateEnforce`). With a workspace the selection is only what the cycle declares: a workspace whose reports name nothing adopts no path (`TestShipDirect_AReportlessWorkspaceAdoptsNoPath`; until 2026-09-28 it fell back to every changed path, residue included), and the cycle's tracked edits ship because the worktree path stages them first (`worktreeShip.stageTrackedEdits`, `git add -u`, idempotent after the audit binding's own `add -u`). The direct path does not run `add -u`: it serves the operator plane, where it would sweep every tracked plane edit into a manual commit. Without a workspace (an operator's manual `evolve ship`) every changed path is staged. The audit's predicate tree and the binding are both `shipmanifest.TakeShipTree`, and the committed tree is pinned equal to it end to end (`TestShipFromWorktree_CommitsTheOneShipTree`; a declared file removed with plain `rm` ships its deletion because the selection is read after `add -u`, where the deletion is staged and the gone-path filter leaves it out of the pathspec: `TestShipFromWorktree_ADeclaredFileRemovedWithPlainRmShipsItsDeletion`; a failed `add -u` is a transient `GIT_STAGE_FAILED` before any commit: `TestShipFromWorktree_AFailedTrackedEditAddFailsTheShipBeforeAnyCommit`), so the tree audited, the tree bound and the tree committed are one (F43 part 2, component 4).
- Staging failures self-heal in two independent ways: (1) `check-ignore` can miss a directory hidden behind a negated parent `.gitignore` rule, so `stageExplicitPaths` trusts git's own `add` refusal (which names the offending pathspecs in stderr) rather than reimplementing ignore semantics, drops exactly those paths, and retries once (`shipmanifest.StageRetrying`, the retry the audit's staged snapshot shares); (2) the same pathspec refused twice in a row is treated as deterministic, not transient, and is routed to the continuation/salvage path instead of burning the whole retry budget on a doomed repeat.
- `discardBinaryChurn` restores a tracked binary from the git INDEX (`git checkout -- <path>`), not from `HEAD` (`git checkout HEAD -- <path>`): after `normalizeWorktreeToBase`'s `git reset --soft`, the index holds the full audited diff, so the index — not HEAD — is the audited reference on this path. This is the opposite of `core.discardMainLeak`, which runs mid-cycle on the main tree before the cycle is committed, where HEAD is still the audited reference; the two forms are not interchangeable.
- `detectColliders` and `stageExplicitPaths`'s classification reads carry `-c core.quotePath=false` before the git subcommand and decode results through `shipmanifest.UnquoteGitPath`, never a naive quote-strip: a naive strip on a non-ASCII, embedded-quote or backslash porcelain entry yields a literal path that exists on no disk, silently dropping a real untracked-main-side collider from both the pre-flight and the repair ladder. (TestDetectColliders_QuotePathDecodesPorcelainEntries, TestDetectColliders_QuotePathDecodesDiffNameOnly, TestDetectColliders_QuotePathNonCollidersStaySilent, TestDetectColliders_QuotePathDisabledOnGitReads)
- The collider repair ladder (`repair_colliders_test.go`, outside this file group) superseded an older refuse-and-stop pre-flight: colliders are now self-healed in-ship (byte-identical copies removed, differing copies quarantine-moved) and the merge proceeds; `gitops_collider_test.go` pins only the remaining false-positive guard — an untracked main-side file that does not collide with an incoming path must never trip the pre-flight or be touched by the repair.
- The worktree landing has two phases (ADR-0039 §8.1, since 2026-10-07, fix round 2026-10-08; `landing_intent.go`).
  - **Prepare.** `commit` makes the lane commit with `git commit-tree`, so no ref moves. Under `ship.lock`, `catchUpMain` fast-forwards `main` to `origin/main` when `main` is behind by journaled commits only. Then ship checks that `main` is an ancestor of the commit. It journals the commit with its cycle and writes `.evolve/landing/cycle-<N>.json`. Only then does `moveLaneRef` move the lane ref with `git update-ref`.
  - **Commit.** Ship checks the commit tree against the audit binding and pushes `commit_sha:refs/heads/<branch>`. Only after the push lands does `settleLanding` fast-forward the plane `main`. Then it runs the post-push tree check, writes `ship-binding.json` and marks the intent `complete`.
  - **Resume.** `resumeLanding` is the first stage of `Run` and of `runNative`, before the repo-contract pack. It reads a `prepared` intent, takes the branch from the plane, and rolls the lane ref forward after a stop. The host's witness reads the run from `cycle-state.json`, the journal, a PASS on the newest audit, the lane tip and the explanation digest. `Landing.Resume` checks them and the ancestry. When origin already holds the commit, ship settles with no push.
  - **Unwind or stale.** A declined resume unwinds the lane with `core.UnwindToAuditedShape` (B1 `unwindShipCommit`) to `lane_tree`, but only when the lane tip is the intent's commit of this run. Otherwise the intent is `stale`, and the lane does not change. A push failure that is not transient also unwinds the lane. A declined unwind is `GIT_LANDING_UNWIND_DECLINED`.

  (TestRun_ARetryAfterAFailedPushResumesAtThePushWithoutReverifying, TestRun_AFailedPushLeavesSharedMainAtItsPreLandingTip, TestRun_AFailedPushJournalsItsCommitSoPushOnlyCompletesIt, TestRun_ASupersededIntentOnItsOwnCommitUnwindsBeforeTheGates, TestRun_ASupersedingAuditOfAnotherTreeMarksTheIntentStaleAndTheGatesBindIt, TestRun_AResumeAfterTheOrchestratorPendedTheLaneMarksTheIntentStale, TestRun_AResumeDeclinesOnADivergedOriginAndUnwindsTheLaneToTheAuditedShape, TestRun_AResumeSettlesACommitOriginHoldsUnderAPeerLanding, TestRun_AKillBeforeTheLaneRefMovesRollsTheLaneRefForward, TestRun_ALaggingMainCatchesUpBeforeTheNextLandingChecksItsFastForward, TestRun_AForgedIntentNeverShipsAnAuditFAIL, TestRun_APolicyRefusalOfACarriedLaneUnwindsItToItsCarriedTree, TestRun_ALandingIntentThatCannotBeRecordedUnwindsAndNeverPushes, TestRun_ALandingThatCannotUnwindStopsTheCycleWithItsCommitJournaled, TestWorktreeShipLand_PushesTheLaneCommitBeforeMainMoves)
- `internal/phases/ship/landing` (seamed through `gitops_landing.go`) is the ADR-0103 unit-07 leaf the ship phase delegates the push step, ancestry checks and the `ship-binding.json` writer to. `(*Options).landing()` lazily builds and caches the leaf on `*Options`; `Run` threads the same `*Options` pointer to every stage, so the cache never leaks back to the caller. `wiredLanding` is the one construction site (TestLanding_OneConstructionSite). `pushWithRepair`'s once-per-Run repair ledger records itself before its probes, unconditionally, even on error; the result's `CommitSHA` is set only when the push actually landed. See ADR-0103.
  - Since 2026-10-07 the leaf also owns the landing intent (`Intent`, `IntentPath`, `WriteIntent`, `ReadIntent`) and the check before the push (`CheckFastForward`). It also owns the resume decision (`Resume`, with `Admit` for the ancestry).
  - It classifies a rejected push. A policy refusal is final (`GIT_PUSH_POLICY_REFUSED`). A transport error, a 5xx or a 429 gets the bounded backoff (`transportBackoff`) and pushes again. `Options.Sleep` and `Config.Sleep` inject the clock. Anything else gets the race probe.
- The native Go ship implementation dispatches through exactly one path, `Phase.Run` → `runNative`; `native_test.go` exercises the full native ship state machine, while `dispatch_test.go` only asserts the `PhaseResponse` translation at the phase boundary.
- `EVOLVE_BYPASS_SHIP_VERIFY` has no effect: the bridge branch it used to redirect around was removed, so ship ignores the flag and a `--class cycle` ship proceeds as an ordinary cycle ship. (TestRun_BypassShipVerify_NilEnvMap_FlagIgnored)
- Some verdict fixtures are built by calling the real producer (`acsrunner.ParseTestJSON` + `WriteVerdict`) rather than hand-written JSON, so a fixture cannot drift from what production actually writes. `TestConsumeGate_OnlyVerdictPASSConsumes`'s matrix runs each row in its own temp repo/worktree/workspace in parallel, since running its ~20 real-git ships serially would add real time against the integration tier's per-package timeout.
- `PlanLanding` and `LandPrefixes` are the fleet main-push wiring seams for `policy.FleetConfig.Landing`: `PlanLanding` only emits the landing plan, while `LandPrefixes` is the live driver that actually resolves culprits against a verify gate — in `"prefix-queue"` mode both route through `fleet.PrefixQueue` (enqueue, then `ComposePrefixes`/`ResolveCulprit`), and any other mode (`"per-lane"`, the default policy.FleetConfig falls an unknown value back to) lands each lane independently, verified on its own. An empty lane set yields an empty/nil result in both modes.
  - **Status (2026-10-09):** no production code calls `PlanLanding` or `LandPrefixes`, so `prefix-queue` changes no behavior today. [ADR-0128](../adr/0128-landing-queue-tiered-reverification.md) replaces both seams with a durable landing queue.
- `TestPlanLanding_RoutesOnLandingMode` and `TestPlanLanding_EmptyLanes` exist as default-tag coverage: the acs-tagged gate-wiring predicate that otherwise proves `PlanLanding`'s wiring does not run under `go test ./internal/...`, so repo-wide apicover would flag it as uncovered without this unit test pinning the same routing contract.
- `ship --push-only` is the sanctioned completion for an attested-but-stranded commit: when a push hits `GIT_PUSH_REJECTED` from true divergence and `evolve sync-main` reconciles merge-only (never pushing), a normal re-run reports "nothing to ship" while the plane sits ahead>0, and bare `git push` is guard-denied — leaving no sanctioned command to finish the strand until `--push-only`. Every successful ship appends its minted commit SHA to `.evolve/ship-journal.jsonl` (`finalize`'s success path, every class, never dry-run); push-only itself mints nothing so it never journals its own HEAD. Since 2026-10-07 a worktree landing journals its commit before the push, when it prepares the intent. `finalize` skips a SHA that the journal already holds. So push-only can complete a prepared commit that an operator fast-forwards onto `main`. `ship --push-only` pushes the ahead set only after verifying each ahead commit individually — via `rev-list`, so a merge can never wrap an unprovenanced commit past the check — is either journaled or a merge commit with an origin-ancestor parent (the `sync-main` reconcile shape); any other commit refuses by name, including one predating the journal.
- `manifest.go`'s `reconcileManifest` checks the paths ship is about to bind against the cycle's declared file manifest (the paths named in `build-report.md` and the TDD report: `shipmanifest.Declared` over `shipmanifest.ReportFiles()`); in SHADOW mode (`opts.ManifestGate` `""`, the default) it only logs out-of-manifest paths, and in `"enforce"` mode it fails closed, refusing to commit any path no phase report declared — typically a sibling lane's untracked leak under a fleet. The staging pathspec comes from the same manifest through `shipmanifest.Select`, so an ordinary ship never falls back to `git add -A`; with a workspace the selection is declared-only, and an empty selection stages nothing (`shipmanifest.StageRetrying` never runs `git add -A --` with no pathspec, which would stage the whole tree). A continuation cycle's declared manifest unions the prior attempt's declarations (via the continuation manifest the adoption seam copies in) so enforce mode never fails closed on legitimately resumed work. See ADR-0076.
- `Run` (native.go) is the single public entry point for both the `cmd_ship.go` CLI surface and the PhaseRunner dispatcher (`ship.go`); its `ExitCode` bins ship.sh's exit semantics (0 shipped, 1 runtime failure — bad args, missing binary, git fail; 2 integrity failure — audit binding, manual-confirm refused, SHA-pin tamper; 127 a required binary is missing). `native_test.go`'s parity matrix pins native `Run` behavior against the retired `ship-integration-test.sh` bash suite.
- `repocontract.go` is the repo-contract gate: before a lane ship binds or pushes, it runs the fixed scanner pack (`repoContractPackages`, projected from `repocontract.Packages()`, the list's one home, where `TestPackages_HoldEveryTestThatReadsTheWholeTree` checks it against the tests that read the whole tree) as `go test -json` in the lane worktree, then the whole-tree readers of the large packages by test name (`repoContractSelections`, from `repocontract.TreeReadingTests()`, run as `repoContractSelectionArgs`, and merged into one outcome by `packOutcome.merged`), then the added-test and importer backstops (`repocontract_importers.go`). A named red is `REPO_CONTRACT_GATE`; an exit that names no test is retried once and then `REPO_CONTRACT_INFRA`. `repoContractPackages` is the pack's one list in ship: the red message derives its suite names from it (`TestContractRed_NamesEverySuiteOfTheOnePackList`), and `RunRepoContractPack` is the one entry other packages use: it runs the gate's own seam (`repoContractTestFn`) in the gate's module dir (`repocontract.ModuleDir`, `<root>/go`) and returns names only for the gate's real red (`realRed`), with the failing tests' own output as the diagnostic, or, for an exit that names no test, no names, the run error and the pack's captured output. That failure text comes from `classifyPackEvents`, which keeps each named test's own lines, a broken build's compiler output (joined by `FailedBuild`, which also covers a pattern that matches nothing) and a failed package's lines only when no named test explains it (`packFailureLog`; `TestClassifyPackEvents_KeepsEachFailuresOwnOutput`, `TestRunRepoContractPackages_CarriesTheFailingTestsOwnOutput`). Whether the fixed pack runs is `repocontract.PackRuns(gate, root)`, the one decision the build floor shares: `runRepoContractGateAt` keeps `repocontract.GateOn` for the whole gate, since the added-test and importer backstops apply to any Go module, and `runFixedPack` runs the pack only where `<root>/go/go.mod` declares evolve-loop's own module, leaving a self-identifying `skipped (module …, changes vs …)` scan-log line otherwise (`TestRepoContractPack_ShipAndTheBuildFloorMakeOneDecision`). The build handoff floor runs it at build exit through `core.RepoContractFloorChecks`, injected by `cmd/evolve`'s `productionBuildFloorChecks` because ship imports core (`TestRunRepoContractPack_RunsTheGatesOwnPackAndNamesItsReds`, `TestRunRepoContractPack_NamesRedsOnlyForTheGatesRealRed`). Every `go test` the gate starts runs in its own process group (`repocontract_cmd_unix.go`, `Setpgid`), and a cancel SIGKILLs the whole group, with `WaitDelay` bounding the drain. `exec.CommandContext` alone killed only the `go` command, so a pack cancelled at the build floor's 120s deadline or by ship left its test binary running with PPID 1 until its own 20m `-test.timeout`. Platforms without process groups (`repocontract_cmd_other.go`) keep the default kill. The cancel still names no test (ACS cycle 1829, predicates 001 and 002). Dial and history: [runtime-reference.md](../../operations/runtime-reference.md) (Ship repo-contract gate).
- A named failure in a package that ends `pass` is not a red. Thus the `--- FAIL` line of a nested `testing.RunTests` fixture does not fail the gate. An example is `TestInnerRunCycleErrorF4` in `internal/routingtest`, which caused false reds in cycles 2041 and 2045.
  - `packFailureLog` holds the text of a named failure until the result of its package arrives. It keeps the failure and its text when no result arrives (`TestClassifyPackEvents_ANestedFixtureFailureInAPassingPackageIsNotARed`, `TestClassifyPackEvents_ANamedFailureWithNoPackageResultStaysARed`).
- `TestCancelKillsTheProcessGroup_CancelReapsTheGrandchildToo` proves the group kill. Its child runs `exec sleep`, so the exit of the child does not depend on the grandchild. The grandchild writes its pid to a pipe before the cancel. The test reads that pid with a deadline of 5 s.
- Before this design, the child was a shell that ran `wait`. On macOS, the group kill can reach the grandchild before the shell. Then the shell can return from `wait` and exit with status 0 before its SIGKILL comes. A shell `wait` without operands exits with status 0 when its child dies of SIGKILL (checked on macOS). `Wait` then returned `context canceled` (census F4.3; runs 39069306819, 39262811729 and 39392251222).
- The rates come from a 14-core macOS host with two rounds of 32 parallel processes of `-race -count=300` (19,200 runs for each side). Before the change, 9 of 19,200 runs failed. After the change, 0 of 19,200 runs failed, and a serial `-race -count=1000` also passed.
- `repocontract_output.go` splits the output of the gate (2026-10-08). The gate builds a typed `packLog{notes, raw}` and passes it to `runFixedPack`, the backstops and `runGoTestJSON`. `runGoTestJSON` writes the raw test stream to `raw` only.
  - With a run dir, `runRepoContractGateAt` opens `ship-repocontract-scan.log` and gives `runRepoContractSteps` the scan log as `notes` and `raw` (2026-10-20, inbox item `loop-log-test-output-prefix-noise`). The `[ship]` notes and the test stream go to the scan log only.
  - Stderr gets one line for each gate run: `[ship] repo-contract gate: <verdict>; full output: <path>` (`repoContractSummary`). The verdict is `green`, the `ShipError` code (`REPO_CONTRACT_GATE` or `REPO_CONTRACT_INFRA`), or `error`. The ship error carries the names of the red tests. When an alone re-run clears a red, the verdict is `green with SHIP_BACKSTOP_FLAKE for <tests>`.
  - A pass that needed the infra retry is `green after an infra retry of the <layer>` (`gateTally`, `infraRetryRecorder`).
  - The scan log is opened for append, and each gate run starts with a `[ship] repo-contract gate: run started <time>` line. Thus a ship retry or a resume keeps the output of an earlier red run.
  - Thus the loop log of a lane does not get fixture lines from a test, and each gate run adds one line to it.
  - With no run dir there is no scan log, so the notes and the raw stream stay on stderr.

- The repair ladder (`repair.go`) gives each `ShipError` code at most one typed, provably-safe repair attempt per `Run` before escalating to the orchestrator's recovery machinery: bounded (a code is repaired at most once per `Run`, `TestAttemptRepair_OncePerCode`), provably safe (every repair re-verifies the original invariant before completing), policy-compliant (never rebases, force-pushes, sets a bypass env var, or deletes content — a differing collider is quarantine-moved, never deleted), and observable (every attempt is logged and recorded on `RunResult.RepairAttempted`/`RepairOutcome`, stamped into the `ShipError` Debug map when declined).
- `repairSelfSHAPin` heals a stale TOFU pin: when the running ship binary's SHA equals the SHA of the binary blob committed at HEAD (a legitimate rebuild or manual ship of already-audited source whose pin was never refreshed), it re-pins and retries; any divergence from the committed blob keeps the integrity block — the same trust boundary `repinPostCycle` uses, where HEAD is the audited reference. (TestRepair_SelfSHA_VerifiedRebuild_RepinsAndShips, TestRepair_SelfSHA_GenuineTamper_StillBlocks, TestRepair_SelfSHA_BinaryNotAtHEAD_StillBlocks)
- `repairColliders` heals a ff-merge blocked by untracked main-side files colliding with incoming paths: byte-identical copies are removed (the same bytes arrive via the merge), differing copies are quarantine-moved to `.evolve/quarantine/cycle-<N>/` with a manifest record — content is never deleted — and the atomic-ship stage is re-run, re-detecting colliders from scratch rather than trusting the repair's own plan. Every collider is verified readable/comparable before any mutation, so an unreadable file declines with the main tree untouched, and a failure partway through logs exactly what already completed and never re-runs the stage over a half-healed tree. (TestRepair_Colliders_IdenticalHealed_ShipProceeds, TestRepair_Colliders_DifferingQuarantined_ShipProceeds)
- `repairResumeUnpushed` heals a strand from a ship before the two-phase landing: a commit that moved HEAD with no push. The rung needs two facts: HEAD's tree satisfies the audit binding (`auditBindingSatisfied`), and the audited base is an ancestor of HEAD. It builds a landing intent from these facts and calls only `Landing.Admit`, because it has no witness of its own. Then it runs the shared `pushLanding` and `settleLanding`, one home for both resumes; anything else declines to the re-audit route. A consuming ship from an older binary still declines here, because no intent records its consumed paths. (TestRepair_Resume_PostMergePrePush_PushOnlyCloses, TestRepair_Resume_BoundTreeMismatch_NoRepair, TestRepair_Resume_OriginDiverged_NoRepair)
- `PluginVersion` is exported so the boot-time self-SHA gate (`cmd/evolve`) classifies a ship-SHA mismatch byte-identically to the terminal ship gate's `verifySelfSHA`, sharing one resolver instead of duplicating the read.

## Invariants

- The audit-bound tree is always the ledger's `worktree_tree_sha` — the audit report's own `audit_bound_tree_sha:` comment is never a binding source, since the auditor persona's report computation binds `HEAD^{tree}` (the unchanged base on an uncommitted cycle), which can never equal the changes-commit tree the ledger records. An empty `WorktreeTreeSHA` leaves the field unset and is refused by `verifyPredicateReceipt` and the treefence check. `internalAuditBoundTreeSHA` may be assigned nowhere in this package except `audit.go`, enforced by a static source scan. (TestVerifyAuditBinding_ReportCommentNeverBindsTree, TestVerifyAuditBinding_LedgerTreeWinsOverReportComment, TestShipSource_NoAuditReportTreeCommentParser, TestInternalAuditBoundTreeSHA_OnlyAssignedInAuditGo, TestInternalAuditBoundTreeSHA_AuditGoStillAssignsIt, TestVerifyAuditBinding_WorktreeTreeSHA_TakesPriority)
- The plane-wide tree-state-SHA diff only binds a ship when the plane is the tree it lands from (`testedRoot == ProjectRoot`); a worktree ship is bound by the tree fence instead, since the plane's tracked bookkeeping (the inbox queue) is not part of what a worktree ship commits. (TestVerifyAuditBinding_PlaneBookkeepingAfterAuditDoesNotUnbindAWorktreeShip, TestVerifyAuditBinding_APlaneSpelledWithATrailingSlashIsStillThePlane, TestVerifyAuditBinding_AChangeToTheShippedWorktreeAfterAuditStillUnbinds)
- `shipDirect`'s pre-commit audit-binding check compares against the STAGED tree (`git write-tree`), never `HEAD^{tree}`: on an uncommitted cycle `HEAD^{tree}` is the base tree, and the binding that reaches `shipDirect` is always `entry.WorktreeTreeSHA` (`git add -u` + `git write-tree`, the changes tree). An earlier version compared against `HEAD^{tree}` on the strength of a test that hand-set a binding no producer emits; that version would have been inert wherever reachable, which is why `TestShipDirect_LegitimateBoundShipIsNotBlocked` now drives the real `seedAudit` producer instead of a literal. (TestShipDirect_LegitimateBoundShipIsNotBlocked, TestShipDirect_RefusesAnUnsatisfiedBinding)
- The post-push tree check after `shipDirect` mirrors the pre-commit check but inspects what actually landed (`HEAD^{tree}`) rather than the index — defense in depth against commit-time divergence, since no reachable branch gets past the pre-commit check with an empty index, and the landing's push repair never rebases or force-pushes.
- A staged executable outside `go/bin/**` and `go/evolve` is refused only when it exceeds 1MB — a small executable is not the failure mode `stageBinaryGuard` targets, only an oversized one indicates an accidental `go build` artifact. (TestBinaryStagingGuard_RejectsLargeExecutableOutsideAllowlist, TestBinaryStagingGuard_AllowsAllowlistedAndSmallFiles, TestBinaryStagingGuard_AllowsSmallExecutableOutsideAllowlist)
- `stageRefusalMemoFile` ("ship-stage-refusal.txt") is workspace-scoped, never global: concurrent fleet lanes must never let one lane's staging strike deterministically block a peer's first attempt.
- Consumption gates on the `acs-verdict.json` verdict PASS string alone — the sole authority it shares with postship's `landedPASS` gate. `acssuite` and `acsrunner` derive PASS from different counts (`red_count==0` vs. `red_count==0 AND incomplete_count==0`; in both, a run with no predicates is the harness red `egps/no-predicates`, never an empty result set), so a bare `red_count==0` is a weaker key: `acsrunner` can write `red_count:0` beside verdict FAIL for a suite that never finished. The cycle path's `acssuite.ReadVerdict` already refuses such a verdict before consumption runs; the manual path has no such reader, so the PASS-string gate is its only guard. Every consumption step is per-item fail-open and logs loudly: a consumption problem must never block a ship that already earned its verdict. (TestConsumeGate_OnlyVerdictPASSConsumes, TestShipFromWorktree_WarnVerdictDoesNotConsume, TestShipFromWorktree_WarnWithRedsDoesNotConsume, TestManualShip_NonShippableVerdictKeepsItemPickable, TestCheckEGPSGate_WarnWithZeroRedCountNeverReachesConsumption)
- Consuming an inbox item writes its scope-keyed continuation binding into the consumed item's `released_continuations[]`, and it leaves the binding in the registry. An unrelated live scope's binding is never touched, and an item with no binding never gains a `released_continuations[]` key. (TestConsumeCommittedItems_RecordsThePointerAndLeavesTheReleaseToTheLanding, TestConsumeCommittedItems_NoBindingIsCleanNoOp)
- The landing releases the binding (`releaseLandedBindings`, `consume.go`). After a successful push, ship lists the consumed items that the landed commit adds (`git diff-tree --diff-filter=A <commit>^ <commit> -- .evolve/inbox/consumed`). For each one, it deletes the registry binding of the last `released_continuations[]` entry, but only if that entry's cycle still owns the binding. The direct site releases after its push, the worktree site in `settleLanding`, and `--push-only` for each journaled commit. Thus a ship that fails at integrate or push keeps the binding, and a re-ship writes the pointer again. (TestReleaseLandedBindings_ReleasesEachBindingThatTheLandedCommitRecords, TestShipSites_EachSuccessfulLandingReleasesTheBindingItsCommitRecords, TestShipSites_APushThatFailsKeepsTheBinding, TestConsumeCommittedItems_KeepsTheBindingUntilTheLandingAndAReShipRecordsThePointerAgain)
- A landed item or a commit that ship cannot read releases no binding, and ship logs a WARN. (TestReleaseLandedBindings_AnUnreadableCommitOrItemReleasesNothingAndSaysSo)
- A consumption tree-drift is accepted only when it is EXACTLY the sanctioned consumption moves ship itself performed: when an audit binding is set, a consumed item's on-disk bytes must match what the audited tree carried, and any additional unsanctioned path in the delta (an extra smuggled file, a second unconsumed inbox item, a tampered item) still refuses. `internalConsumedPaths` — the sanctioned set — may be appended to nowhere in this package except `consumeCommittedItems`, enforced by a static scan; it is a smuggling channel for the drift tolerance the moment any other writer touches it. (TestShipFromWorktree_ConsumptionDriftIsSanctioned, TestShipFromWorktree_UnsanctionedDriftStillRefuses, TestShipFromWorktree_SecondUnconsumedInboxFileRefuses, TestShipFromWorktree_TamperedItemIsNotSanctioned, TestShipFromWorktree_NoBindingStillSkipsCheck, TestInternalConsumedPaths_OnlyWrittenInConsumeGo)
- The plane `main` is never ahead of origin through ship's own action: a worktree ship fast-forwards `main` only after its push lands. A lane can have nothing to commit and still hold a stranded landing. That is a journaled `cycle` commit that origin does not hold, whose intent is not `complete`. That lane is `GIT_LANE_NOT_ON_ORIGIN` (integrity), never a PASS with no push; the message gives the steps for the boundary. Boundary commits on local `main` keep "nothing to ship". (TestRun_APeerLaneOnAStrandedLandingStopsWithItsSteps, TestRun_ALaneOnAMainAheadByBoundaryCommitsIsStillNothingToShip, TestRun_ALaneOnACompletedLandingOriginLostIsStillNothingToShip, TestWorktreeShipLand_ARejectedPushNeverMovesMainAndKeepsTheIntentPrepared)
- A resume takes its audit binding from the newest audit row (`bindResumedAudit`, in `audit.go`). It takes its consumed paths through `adoptIntentConsumption` (in `consume.go`), which accepts only whole `.evolve/inbox/<item>.json` consumption pairs. The landing intent never writes the bound tree or the sanctioned set by itself, so the source scans of both writers hold. (TestInternalAuditBoundTreeSHA_OnlyAssignedInAuditGo, TestInternalConsumedPaths_OnlyWrittenInConsumeGo)
- `DryRun` skips all mutations (git add, commit, push, gh release) but still runs every read-only check, including audit-binding verification, before short-circuiting on the dry-run branch.
- `writeShipBinding` freezes the cycle identity it verified against before writing `ship-binding.json`; a concurrent rewrite of `cycle-state.json` after the push (removing `cycle_id`) cannot redirect which run's workspace the binding lands in. (TestShipFromWorktree_WriteShipBindingUsesFrozenCycleIdentity)
- `discardBinaryChurn` must never remove the binary it is currently executing from (`osExecutable`/`isRunningExecutable`): `evolve ship --class manual` never sets `Options.ShipBinaryPath`, so the churn discard's fallback resolves the running `go/bin/evolve`, which is untracked and gitignored — removing it has zero staging-hygiene value (`git add -A` could never stage it) but kills the binary every kernel hook and the rollback shellout are running from. The guard is narrow: it protects only the running executable, not the ordinary untracked `go/evolve` churn discard. (TestDiscardBinaryChurn_NeverRemovesRunningExecutable, TestManualShipSuccess_LeavesUntrackedGoBinEvolvePresent)
- `captureWithEBADFRetry` (test-infra only, never called from production ship code) retries exactly once on a transient EBADF or closed-pipe error and passes every other error straight through; it exists because the real-git integration tests flake on macOS CI with a darwin pipe-teardown race (`read |0: bad file descriptor`) in the test git-runner's `CombinedOutput` path. (TestCaptureWithEBADFRetry_RetriesOnceOnClosedPipe, TestCaptureWithEBADFRetry_PersistentEBADF_FailsAfterOneRetry, TestCaptureWithEBADFRetry_NonEBADFError_NoRetry)
- `isTerminal` treats an `*os.File` whose `Stat` fails (e.g. because it is closed) as non-terminal by conservative default, so `--class manual` refuses rather than hanging on a phantom tty. (TestIsTerminal_ClosedFile_ReturnsFalse)
- A non-JSON ("alien") line in the ledger is skipped rather than crashing ship-gate: `findLatestAudit` and `findCompositionVerdict` both walk backward past an unmarshal error to find the real entry below it. (TestFindLatestAudit_SkipsUnparseableLine)
- An auditor exit code of 2 or higher (an error state, not the unix findings-convention exit 1) blocks ship with an `*IntegrityError`; only exit 0 and 1 are treated as a findings signal. (TestVerifyAuditBinding_AuditorExitCode2_IntegrityError)
- The EGPS gate keys solely off `red_count`; unknown or new verdict fields are tolerated by its permissive unmarshal, so a `skip_count` or a `result:"skip"` field alongside `red_count==0` still clears the gate. (TestCheckEGPSGate_SkipCountWithRedZero_Passes)

- A read-only `.evolve` fails the first-run repin at lock-acquire with the same state-IO refusal the write path uses. See ADR-0049. (TestVerifySelfSHA_RepinWriteStateFails_Errors)
- `shipDirect`'s pre-commit binding check's `git write-tree` error propagates, and an exit-0-with-empty-stdout result fails closed rather than being read as "nothing staged". See ADR-0048. (TestShipFromWorktree_WriteTreeFails_Errors, TestShipFromWorktree_WriteTreeEmptyOutput_FailsClosed)
- An unreadable artifact (sha256 fails) or a ledger read error other than not-exist is a plain, transient error, never an `*IntegrityError` — only a positively-verified mismatch is integrity-class. (TestVerifyAuditBinding_UnreadableArtifact_SHA256Error, TestFindLatestAudit_ReadError_Propagates)

(TestVerifyNoControlPlaneEdits_RejectsGateEdit, TestVerifyNoControlPlaneEdits_RejectsUntrackedGate, TestVerifyNoControlPlaneEdits_AllowsNormalSource, TestVerifyNoControlPlaneEdits_RejectsTrackedGateModification)

(TestVerifyNoControlPlaneEdits_RejectsARenameOutOfTheSurface)
- The format of the ship journal (the entry, the file name, the class `cycle` and the time stamp) is in [internal/shipjournal](internal-shipjournal.md). The ship phase writes through it, and `selfheal` reads through it.

## Findings

- `binary_staging_guard.go` exists because a `go build` ACS predicate lacking `-o os.DevNull` once dropped an ~18MB `evolve` binary into a worktree that `git add -A` swept into git history; `.gitignore` closes that one instance, the guard closes the class.
- A cross-plane merge hazard: the ship commit's tracked root deletion of a consumed inbox item can meet a runtime plane whose local copy carries an unstaged failure-count write-back, so `git merge origin/main` aborts (modified-vs-delete). Recovery is `git checkout -- .evolve/inbox/<file>` and re-merge; the window is narrow (claimed items leave the root at dispatch) but real for root-resident failure-bumped items consumed via `skip_shipped`.
- The direct (non-worktree) ship path once carried the audit binding (writing `audit_bound_tree_sha` into `ship-binding.json`) while verifying nothing against it — a sidecar asserting a verification that had never happened. `TestShipDirect_RefusesAnUnsatisfiedBinding`, `TestShipDirect_UnboundShipIsUnaffected` and `TestShipDirect_LegitimateBoundShipIsNotBlocked` now pin the guard's boundaries; the third is the load-bearing one, since a guard that rejects real ships is worse than the gap it closes, and it is driven through the real `seedAudit` binding producer rather than a hand-set literal for that reason.
- Three defects once made a fully-successful worktree ship batch-fatal: (1) a correction re-dispatch after a successful push re-ran the full ship and hit `AUDIT_BINDING_HEAD_MOVED`, because HEAD was already the ship's own commit; (2) `git -C <worktree> add -A` swept unaudited `go/evolve` binary rebuild churn into the cycle commit, since the build phase's churn-discard pattern was not applied in ship; (3) `expected_ship_sha` was pinned from a pre-commit blob rather than the binary as actually committed at HEAD, producing a false `SELF_SHA_TAMPERED` next cycle. Ship now (1) recognizes a post-push re-dispatch by checking that `ship-binding.json`'s own commit equals HEAD and succeeds report-only — keyed on the binding's commit matching HEAD, never on the mere presence of the sidecar, so a stale binding from an earlier attempt cannot short-circuit a real not-yet-pushed cycle; (2) normalizes binary churn before Audit runs, scoped to the release-managed binary path so real Go source edits ship untouched; (3) pins `expected_ship_sha` from the content committed at HEAD. (TestShip_PostPush_Idempotent_CorrectReportOnly, TestShip_PrePush_CorrectionStillFullShip, TestShip_BinaryChurnNormalizedBeforeAudit, TestShip_SourceChangesPreserved, TestShip_PinPostCommitSha)
- `TestShipFromWorktree_PostPushTreeSHAMismatch_BreachLog` documents (via `t.Skip`) that the post-push tree-SHA mismatch path is structurally unreachable through a single ff-merge, because a ff-merge preserves the tree SHA — a pre-merge-bound tree therefore always equals the post-push committed tree by construction. Similarly, `postShip`'s `repinPostCycle` error-propagation branch has no reliable seam to force independently in an integration test and is covered indirectly by the standalone `TestRepinPostCycle_StateReadError_ReturnsError` unit test.
- `verifyAuditBinding`'s branch for an `os.ReadFile` failure after `sha256File` already succeeded is untestable without OS-level fault injection between two `open()` calls, since `sha256File` reads the same file `os.ReadFile` would; the unreadable-artifact chmod test covers the reachable half of that branch instead.
- An absent `Context["commit_message"]` was once not backfilled, so `Phase.Run` could reach commit with no message; it now synthesizes a default cycle commit message when the context omits one. (TestPhaseRun_DefaultCommitMessage_WhenContextMissing)
- The git-add staging-failure message once silently dropped its `-A` flag when staging moved from a blanket add to explicit pathspecs; the pinning test (outside this file group) covers the failure branch itself, not the exact wording.
- A bare `## Verdict` heading followed by an unbolded verdict word on its own line was once not recognized by the audit-binding parser, which would have produced a false malformed-verdict integrity error; the parser now accepts the bare form, matching only when the line is exactly the verdict word. (TestParseVerdicts_BareHeadingLine)
- A lone tag-guarded added test package (e.g. a cycle's own `go/acs/cycle<N>` predicate file, `//go:build acs`) has zero files under `go test`'s default tag set — which the toolchain reports as a build/setup failure and the classifier would otherwise grade a genuine contract RED, hard-blocking the very ship that minted it. The added-test backstop runs each candidate under the build tags its file actually declares instead, and the scan log records how a tag-guarded candidate was handled rather than dropping it silently. (TestRepoContractGate_NewlyAddedTagGuardedGreenPackageIsNotFalseRed)
- `TestShipGate_{Stale,Fresh,Missing}Attestation{Blocked,Passes}` (`shipgate_attestation_binding_test.go`) run UNGUARDED, outside `//go:build integration`, deliberately: the pre-existing commit-attestation coverage sits behind the integration tag, so a severed `verifyCommitGateAttestation` wire would be invisible to plain `go test ./...`; these three drive the enforcer directly against a real `.commit-gate` attestation fixture and a real git tree, so the wire is caught by normal CI.
- The commit-gate attestation binds to `sha256(git diff HEAD)` (`treeStateSHA`), computed before the `.commit-gate/attestation.json` fixture is written; the fixture itself is untracked, so writing it never perturbs that diff — the same tree-state SHA the enforcer recomputes at ship time still matches. (TestShipGate_AttestationDirDoesNotPerturbTreeState)
- `stageExplicitPaths`' failure classification derives the `ShipError` recovery class from the CAPTURED git stderr and exit code, before the two-strikes fallback runs — never from the Go error text wrapped around it, so an error-wrapper edit can never move a failure between recovery routes. An absolute pathspec, a path outside the repo, a missing pathspec and a gitignore refusal are all `ShipClassPrecondition` (deterministic — retrying wins nothing); an index-lock contention and any unrecognised stderr degrade to `ShipClassTransient` (deliberately conservative: only a recognized deterministic shape reclassifies). The two-strikes router for an unrecognised refusal still runs in front of this classifier, not replaced by it. (TestStageFailureClassification, TestStageFailureClassification_PreservesCapturedStderr, TestStageFailureClassification_TwoStrikesStillApplies)
- `stageExplicitPaths` must stage cleanly when a changed path is a deletion or rename already staged by an earlier step in the operator flow (explicit paths → commit-gate → ship re-stages): a plain `git add -- <path>` on an already-staged deletion fatals rc=128 ("pathspec did not match any files"), and git reports a staged rename as `R old -> new` rather than `D old`, so a naive "D " filter would miss it even though the old path is gone from both the worktree and the index under its old name. (TestStageExplicitPaths_AlreadyStagedDeletion, TestStageExplicitPaths_AlreadyStagedRename)
- Staging a declared path that is a gitignored DIRECTORY (a trailing-slash `dir/` ignore rule) must not kill the ship: git's `add` refuses it by name, the stager drops it and retries, the real declared change still lands, and the directory's runtime content survives on disk, untouched. (TestShipFromWorktree_DropsGitignoredDirectoryPathspec)
- `stageExplicitPaths` pre-filters the declared pathspec through `git check-ignore` before `git add`: an entry check-ignore reports as ignored is dropped and logged, never handed to `add`. A broken check-ignore probe (a non-{0,1} exit) fails OPEN — the full declared set flows through unfiltered, with the probe failure logged — since a probe failure must never block a ship. (TestShipDirect_CycleClass_DropsGitignoredDeclaredPaths, TestShipDirect_CheckIgnoreProbeFailure_FailsOpen)
- Only failure paths used to write `lastCycleNumber`, so a successful ship left the counter at the previous cycle and the dispatcher's next iteration recomputed the same cycle number, tripping the 5-repeat circuit breaker on legitimate runs; `advanceLastCycleNumber` now advances it on every successful class=cycle ship. (TestNative_S_CycleAdvancesLastCycleNumber)
- A `check-ignore` capture-runner unit test can stay green while the production feature is dead on arrival: an early fix used `check-ignore -z`, a stdin-mode-only flag that makes the real probe exit rc=128 on every ship, but the mocked unit tests never exercise the real flag semantics. The gitignored-declared-path contract is therefore pinned twice — once against a capture runner (arguments) and once against a genuine repository (observable effect) — since only a real-git integration test catches that class of defect. (TestShipFromWorktree_DropsGitignoredDeclaredEvalPath)
- The `landing/testdata` goldens pin the ship-landing behavior (argv order and streams, logs, result fields, structured errors) as byte-exact JSON captured before `internal/phases/ship/landing` was extracted as its own leaf package, so a transcription slip during the move shows up as a byte diff rather than a review opinion; every driving test is untagged and fake-only (scripts git by full argv, since the package's `scriptedRunner` cannot distinguish `rev-parse origin/main` from `rev-parse HEAD`). Since 2026-10-07 the worktree and integrate goldens are retired. They pinned the order that stranded cycle 1830: `main` moved before the push. `landing_order_test.go` pins the new order. The direct and push-only goldens keep their argv; their rejection messages no longer end in `: <nil>`.
- Cycle 1830 (2026-10-07): a GitHub 500 on the push left ship's commit on the lane and the shared `main` moved. No record existed that a retry can use. The transient retry ran the gates again, and they measured ship's own inbox consumption. So a re-audit FAIL followed, and a peer published the strand ([incident](../../incidents/2026-10-07-cycle-1830-a-failed-push-stranded-the-audited-commit.md)). The fixture of the old resume test consumed nothing and had no explanation contract, so it proved nothing about loop cycles.
- `repoContractTestTimeout` (`addedtests.PackageTimeout`) is set well above `go test`'s 10-minute default: a measured slow-but-green package under fleet load came close enough to a shorter deadline to coin-flip, and a deadline timeout makes `go test -json` emit a fail event for the running test and every paused `t.Parallel()` test, which the gate would misclassify as a real contract RED on green code. The wider margin lets slow-but-green survive fleet load while a genuine deadlock stays bounded. The build floor's three `go test` runs (the changed packages' unit self-check, the coverage pass and the tagged added-test check) use the same constant, and `TestGoTestTimeouts_AreTheSharedPackageBudget` (`internal/guards`) refuses any other `-timeout` value in pipeline code (2026-10-05, after the floor's 120 s literal failed cycles 1787, 1791, 1792 and 1798).
- The importer backstop (`repocontract_importers.go`) closes a gap the fixed scanner pack and the added-test backstop both miss: a lane modifies a package, its own package tests stay green, but an untouched test in a package that imports it still asserts the old contract — only the import graph can see that edge. Its seed is the tree the ship will land, measured against its base, via the one `internal/changedpkgs` derivation from the working tree (never the index, since a lane's build output is unstaged until the ship itself stages it); the closure is `changedpkgs.ImporterClosureChecked` — build deps and the direct imports of each package's tests — projected to what `go test` can run under the default build context, minus what the fixed pack and the added-test backstop already ran.
- The added-test detector (`addedtests.Groups`) and the importer backstop have deliberately distinct, complementary scopes: the detector selects only newly ADDED `_test.go` files (a modified tracked test or a newly added non-test file are never its candidates, and an empty candidate set runs nothing), while a modified tracked test that goes red is instead caught by the importer backstop, which runs every package the diff's import closure touches. (TestRepoContractGate_AddedTestSelectionIgnoresModifiedAndNonTestFiles)
- An honestly `t.Skip`-ped newly added test is not a hidden failure and must never trip the repo-contract gate — skip stays an honest, non-blocking signal here as elsewhere in the pipeline. (TestRunNative_AddedSkippedTestDoesNotBlockShip)
- A newly added test file that is genuinely un-runnable on the current host (e.g. a `requires_tmux` build constraint) is never silently claimed green nor silently skipped with no record: both would launder a real coverage gap. The gate does not fail the ship over a candidate it correctly cannot run, but it does leave a durable, explicit EXCLUDED record in the scan log naming the file and its exclusion reason. (TestRepoContractGate_AddedEnvExclusiveTestBackstopRecorded)

## Invariants the code comments used to carry

These rules held in comments before the comment-zero change. Tests pin the ones that name a test. The code shape must keep the rest.

### Audit binding and verdict parse

- `findLatestAudit` binds to the newest auditor row of the run in `opts.RunID`. With an empty run id it takes the newest row of any run. A miss is an integrity stop. It never falls back to another run's audit.
- The report SHA binds the host receipt. The mutable verdict must also match its exact execution identity and bytes before it can authorize ship.
- `readAuditArtifact` hashes and reads the same bytes once. No second read sits between the SHA check and the verdict parse.
- When a composition entry carries forward, the composed tree is already bound. The base-tree check is then superseded. Each rejected composition condition falls back to a full re-audit. The path can only narrow what ships.
- Review verdicts follow the patch-id (the change). Native gates must still follow the tree.
- `parseVerdicts` accepts two shapes. One is an inline `Verdict: <X>` line, case-insensitive, with optional asterisks. The other is a `## Verdict` heading with `**X**` or a bare verdict word within 5 lines. A sentence that contains the word must not match. At `StageEnforce` and above, the sentinel line is the only source.
- `computeTreeStateSHA` hashes `git diff HEAD`. A tracked-file change after audit invalidates the ship. A git exit above 1 is fatal. Exit 1 means differences exist, and the hash handles it.
- `integrity.go` joins the tracked diff and the untracked list without dedup. The two sets are disjoint by definition.
- `underlyingErr` keeps the `git_err` debug field equal to the raw runner message.
- `verifyNativeExplanation` lives below the Phase adapter. A direct `evolve ship` then cannot bypass the Build explanation contract.
- A standalone ship resolves the identity from host-owned global state. It never uses the Builder-writable run mirror. Each Run freezes one identity snapshot, and later stages do not re-read mutable cycle mirrors.
- The activation belt lives in `explanationdocs`, and audit runs the same check. A `Require=true` refusal after the belt is dead code. `ship.go` derives the handoff requirement from a non-zero version.

### Class verification and confirmation

- `verifyManualConfirm` stages with `git add -A` so the diff shows what will ship. The commit-gate attestation check must run after it. The computed tree SHA is then the tree that is committed. `Options.BypassCommitGate` skips only the attestation.
- `--class manual` refuses a stdin that is not a terminal, because an LLM agent cannot answer the prompt. The audited `--auto-confirm=<reason>` parameter (`Options.AutoConfirm`) is the CI escape. `evolve ship` writes one ledger entry and one `CONTROL_BYPASS_USED` signal for each use (X18d). Only the exact word `yes` confirms.
- The bypass flags are explicit CLI flags. The ship package does not read bypass environment variables.
- `errEmptyDiff` is the sentinel that `Run` turns into a clean exit. Nothing staged means exit 0.
- `Config` zero values are the safe defaults. `PhaseIO` zero is `StageOff`, which keeps the prose verdict parse. `ManifestGate` zero is shadow. `RepoContractGate` zero is off, so a construction site is safe. The cmd_cycle wiring test asserts that the production site passes `enforce`.
- A nil `Signals` is a Null Object. It drops warnings and does not panic.
- `defaultCommitMessage` builds a deterministic message when `Context["commit_message"]` is absent. The autonomous path does not always set it. The manual CLI always passes one.
- A document cycle commits under `solution(<slug>)`. The scope takes one slug, because the prefix grammar admits only `[a-z0-9-]`. Further slugs go in the subject.

### Manifest gate

- Shadow is the default and never blocks. Enforce fails closed on any path that no phase report declared. It uses `core.CodeManifestGate`, so the ledger and the debugger can tell a manifest block from a real `git add` failure.
- The mode comes from `policy.json` `gates.manifest_gate`. It never comes from a code literal.
- `shipmanifest` also extracts bare root-level filenames. A legitimate root-file change is then not a false block under enforce.
- `scanshadow.go`, `scanshadow_tree.go` and `scanshadow_tap.go` are the scan shadow (landing plan S5, [ADR-0134](../adr/0134-fleet-landings-scale-through-content-keyed-verification-and-group-commit.md)). `Phase.scanShadowFor` builds it from `gates.scan_cache_gate` (default `shadow`) and `runRepoContractGate` puts it in the context. `runRepoContractGateAt` calls `begin` before the first run and `finish` on every exit. `runClassifiedPackRetrying` calls `observe` with each run outcome. `runGoTestJSON` fills `packOutcome.pkgs` from a read-only tap on the event stream. At the stage `shadow` the scan runs every package as before.
- The verdict store is shared (plan [wave-latency-2026-10.md](../../plans/wave-latency-2026-10.md) D6, component W5). The scan writes its greens under the gate id `ship`. `RunRepoContractPack(ctx, projectRoot, root)` is the pack of the build floor: `floorRecorderFor` gives it a recorder that writes under the gate id `build-floor` and never reads. `runRecordedPack` keys the tree before the pack, records each green after it, and prints one `[build-floor] verdict store:` line with the counts. A failed write or an unkeyed tree never changes the floor verdict.
- At the stage `enforce` of `gates.scan_cache_gate`, `scanShadow.prune` runs before each `go test` of the scan. It lists the packages of the run with `go list` and keys each one with the flags of the run. It drops each package with a green from any gate on the same key, and the run gets the import paths of the rest.
- A run with no package left runs no `go test` and is green. `runGoTestJSON` names each skip on one `[ship] verdict store: skipped` line. Sometimes `prune` cannot decide: no tree id, no toolchain, a failed `go list` or a panic. Then the run keeps its arguments, and the summary names the cause.
- `cacheable` is the rule of the tiers that are never cacheable. A result with a build tag, or of a package that holds a test of `repocontract.TreeReadingTests()`, is counted as `uncacheable` and never stored or skipped. The reason is in [internal-testverdict.md](internal-testverdict.md).
- A mismatch is a stored green whose real run fails. It keeps the code `SHIP_SCAN_SHADOW_ESCAPE`, and the event names the writer in the field `gate`. The summary carries `stage`, `skipped` and `uncacheable`.
- The changed set is the porcelain dirt plus the commits already on the cycle branch. `detectColliders` binds the same inputs. A run with no readable reports skips the gate.

### Repo-contract gate

- A pack outcome has failures only when the pack said the code is broken. That means a `go test -json` fail event with a test name, or a build or setup failure.
- A nonzero exit with no failures is ambiguous. It retries once and then classes as `CodeRepoContractInfra`.
- A named red never retries. A retry doubles the wall time of every red ship. It also lets a flaky-but-real suite launder a violation onto main.
- A package-level fail with no test name counts only when the output marks a build or setup failure. A compile break shows twice. One is a `build-fail` action with no package on go1.26. The other is a `FAIL pkg [build failed]` line.
- The classifier collects build failures per package and appends them after the loop. One broken package reads as one failure. A build failure with no package still counts as a real red.
- A line that is not a JSON object is teed verbatim and skipped. One stray line cannot blind the classifier to later failures.
- The runner drains the event pipe to completion before `Wait`. An undrained pipe deadlocks the child.
- `lockedWriter` serializes the child's stderr copy and the event tee onto one writer. It implements `Write` only, so `io.Copy` takes the lock per chunk. Without it, a `bytes.Buffer` has a data race and loses tee writes made during a blocking read.
- The scan log `ship-repocontract-scan.log` is best effort and is truncated for each run. A missing run dir, an open failure or a close failure never fails a ship.
- The scan log is written on green runs too, with a header first. The green baseline disproves a false red.
- The alone re-run keeps the whole package, so same-package state stays in play. It removes only the pack's concurrent load. A package that is green alone contributes nothing. A package that is still red contributes the tests still red. A re-run that names nothing keeps the first-run reds.
- `aloneRerunMaxFailures` caps the reds worth a re-run. More named reds are a broken contract and not a timing window.
- `CodeBackstopFlake` is the warning for a cleared red. A recurrence across cycles marks a hygiene item. A nil Signal Center hears nothing.
- Discovery of the seed files retries once after `discoveryRetryPause`. A concurrent lane's `index.lock` is the known transient. A second failure is `CodeRepoContractInfra` and never a silent green.
- `importerBackstopTimeout` bounds the run so the ship phase ends. A timeout exits with no test-level failure and classes as infra. `importerBackstopRetryMaxTargets` caps the pack size that is worth a second full run.
- `repoContractGateRoot` fails closed with `CodeWorktreeResolve` for an unresolvable typed worktree. The gate then never tests the project root in the lane's place and reports a false green.

### Scan shadow

- The shadow changes no verdict, no exit code and no order. It adds a tap on the event stream, three calls in the gate and records in the store. A test pins the notes, the order and the error text against a run with the shadow off (`TestScanShadow_ChangesNoVerdict`).
- The shadow is read-only toward the lane. It lists files with `git ls-files`, reads them, and runs `go env -json`. It stages nothing and does not touch the index or the inbox (`TestScanShadow_IsReadOnlyTowardTheLane`).
- `begin` takes one snapshot before the first run. It hashes every file that git lists, tracked or not and not ignored, as the files are on disk. The result is the whole-tree id. A test that writes into the tree during the scan cannot change the key of its own record.
- Every key is a whole-tree key today. No producer of test logs exists, so `keyOf` gives an unknown log to `testkey.Compute`. A hit thus needs an identical tree. A producer of logs must come before the hit rate can reach the plan's exit of 500 hits.
- A package result is a hit when the store holds a green record for its key and the package passed. It is an escape when the package failed. An escape emits `CodeScanShadowEscape` (WARN, with the package, the key, the tags and the flags). A hit that passed counts only in the summary.
- The key holds the tags and the flags of the run. A by-name run (`-run`) and a whole-package run of one package are thus two keys.
- `settled` keeps one lookup for each key in one scan. A retry of the same run is not a hit on the record that the scan wrote a moment before.
- `finish` emits one INFO summary for each scan. Its fields count `packages`, `hits`, `escapes`, `recorded`, `unkeyed` and `store_errors`, and name `hit_packages` and any `degraded` cause. The count of summaries is the count of scans for the S5 exit.
- A fault degrades to no hit. A failed listing or `go env` sets `degraded` and every package is `unkeyed`. A failed store write is a `store_errors` count. Nothing fails the scan.
- A panic never reaches the gate. `begin`, `observe`, `finish` and each package in `settle` run under `guard`. `guard` recovers, adds the cause to `degraded` and emits one `CodeScanShadowFault` WARN for each scan.
- The tree hash has a budget. `begin` runs under a deadline (`scan_cache_budget_seconds`, default 60). `fileID` streams each file through `ctxReader`, so a cancelled context stops the hash within one read. A total over `scan_cache_max_mb` (default 2048) is `errTreeTooLarge`. Either bound degrades the scan, and the reason is in the summary.
- The tap exists only for a shadowed scan. `runGoTestJSON` makes no tap when the context holds no shadow. A line of more than 1 MiB with no newline is dropped and counted in `dropped_lines`.
- The store grows with each scan, so `evolve gc` trims it (`gc.testcache_ttl_days`, `gc.testcache_max_mb`). The ship path never trims.
- A retried package is settled once by key. A first-run failure that a green alone re-run clears still raises an escape. S6 must discount it (plan Q7).
- The alone re-run is not observed. A hit that failed in the first run is an escape even when the alone re-run clears it.
- The test environment is not in the key. No list of child-process variables exists yet, so `ChildVars` is empty.

### Inbox consumption and post-ship

- Post-ship work is bookkeeping. Every failure is a warning and never a ship failure, because the commit is already on the remote. The exception is a read error while the code advances `lastCycleNumber`. That error propagates. Only a write or lock error there is the non-fatal warning.
- All `state.json` read-and-write sections share one lock (ADR-0049).
- `retireCommittedCarryover` deletes the carryover entries that this cycle committed, with their cross-cycle class twins. It edits the raw entries, so a field that this binary does not model survives. A missing `state.json` is not an error.
- Without this retirement, a shipped entry persisted. It then filled the 20-slot carryover window of the router prompt.
- Promotion, superseded reconcile and carryover retirement all ride the same landing check. `isLanded` is true when the commit is an ancestor of local HEAD or of `origin/<branch>`. An empty sha is never landed.
- Retiring on an unlanded ship erases the only record of work that never shipped. In the post-ship caller, an absent `res.CommitSHA` fails open. No recorded commit is not evidence of an unlanded push.
- The residual drain always runs, also without `triage-decision.json`. It releases every claim left in `processing/cycle-<cid>/` back to the inbox root. Triage Step 0a reads that root at depth 1.
- When the landing check refused promotion, the ledger reason carries `unlanded`. Operators can then tell a delivery-failure retry from an ordinary drain.
- Promotion and drain are the two halves of one PASS transition, so both go through `ApplyCycleOutcome`. The "drain complete" line is a success claim and stays inside the success branch.
- `triageDecisionBytes` prefers the companion that the agent wrote, because it carries `skip_shipped`. Next it uses a deterministic projection of `triage-report.md`, which has `top_n` only. Last it returns nil. An unreadable companion keeps its WARN and is never lowered to INFO. The projection is saved, so a re-run sees the same companion.
- `committedInboxIDs` widens by lane scope only for a PASS landing. A non-PASS verdict leaves work pickable. A nil decision body falls back to the lane-scope ids.
- The widening relies on `lane-scope.json` living in a freshly provisioned per-cycle workspace. A change that recycles a workspace must re-check it.
- If triage names a scope id, only the named scope ids consume. A menu mate that triage left unmentioned stays pickable.
- `consumeCommittedItems` is gated on the verdict string PASS alone. This is the same authority as `landedPASS` in postship. `acsrunner` writes `red_count:0` beside a FAIL verdict for a suite that never finished, so `red_count` is weaker.
- On the cycle path, `acssuite.ReadVerdict` already refuses that shape. The manual path has no such reader, so this gate is its only guard. A missing verdict is a loud warning and not a silent skip.
- Every consumption step is fail-open per item and loud. The one atomic unit is a validated unified commitment (`consumeUnified`). Its members close all-or-nothing, and a failure rolls back files and index together. A member that is already in `consumed/` counts as closed.
- The raw `unified_commitment` claim alone never forms an atomic unit. Triage stamps `unified_projection` beside a claim that it accepted.
- A manual ship that claims a workspace consumes in the landing commit. A manual ship with no workspace has nothing to consume and returns silently (`consumesInboxAtLanding`). A cycle ship with no workspace still reaches the loud missing-verdict warning.
- The consumed id set also drives the continuation-binding release (`readBindingForConsume`, `released_continuations`, the registry delete). Lane-scope and Closes-Inbox ids reach it too.
- The binding is read from the root-owned registry. The registry delete waits for `record`, after the move is final. A rollback then leaves both stores unchanged. `DeleteRegistryEntryIfCycle` keeps a fresh binding of a sibling lane.
- The consumed item is tracked and public. `released_continuations` collapses host paths to `~`.
- With an audit binding set, the consumed bytes must equal what the audited tree carried. A file planted after the binding rolls back loudly and stays pickable.
- `shipDirect` has no binding and keeps consuming plane-side failure-count write-backs. A rolled-back move restores the filesystem, because on `shipDirect` the tree is the runtime plane.
- `treeDriftExplainedByConsumption` fails closed. No consumed paths, or a diff-tree that cannot run, explains nothing. It reads paths raw and unquotes them (`shipmanifest.RawPathRead`, `UnquoteGitPath`), so a non-ASCII filename matches the sanctioned set.
- The offender suffix in the refusal is bounded, because the message travels into digests.
- `workspaceACSVerdict` returns the empty string for an unreadable verdict. That fails closed for consumption.

### Staging and git

- `stageBinaryGuard` refuses an owner-executable staged file above `binaryStagingMaxBytes`. Files under `go/bin/**` and `go/evolve` are exempt. The guard fails open on the git query itself.
- A `git add` refusal is kept in a memo for each lane, keyed by the sorted path set. A first refusal keeps its retry. The same pathspec refused twice in a row is deterministic and escalates. A successful stage clears the memo. An unwritable workspace costs only the escalation.
- `stageReleaseSet` takes the `versionbump` paths as the single source for marker files. A new marker is then staged and never ships one version behind. It skips paths that are absent on disk, so a partial layout never fails on a missing pathspec.
- `isRunningExecutable` resolves symlinks on both sides. An untracked file is removed unless it is the running binary.
- `activeWorktreeForShip` takes the typed host identity. A Builder-writable `run.json` may corroborate it. It never selects or clears the tree that ship changes.
- A push rejection retries once through an inline fetch and ff-merge. A true divergence reclassifies to needs-reaudit. After the push, the landed tree is checked against the audit binding. This is the same defense as the pre-commit index check.
- `maybeCreateRelease` is best effort. A missing `gh` or a nonzero exit logs WARN, because the release may exist. `runCommitPrefixGate` passes a missing manifest through.
- `buildDiffFooter` matches the legacy `ship.sh` footer byte for byte. `acquireShipLock` is a blocking flock (ADR-0049).
- `landing()` is built lazily and cached on `*Options`. Streams and the Signal Center are read through accessors at each use. `Run` sets the default streams after `Options` is built.

### Repair ladder

- `repairNone` means the original error stands. `repairRetryStage` re-runs the failed stage once. `repairCompleted` means the repair finished the ship itself (push-only closure), so the other mutating stages are skipped.
- A repair is conservative. Any doubt gives `repairNone`.
- `GIT_PUSH_REJECTED` has no ladder entry. Its retry runs inline at the push site. That keeps the post-push tree check and the binding sidecar on the healed path.
- `repairColliders` plans first. It verifies each collider as readable and comparable before any change. A partial heal never re-runs the stage, so no merge lands over a half-healed tree.
- Quarantined content is moved and never deleted. The manifest is an atomic append-merge. The stage re-run finds colliders again from scratch.
- `repairSelfSHAPin` holds the `state.json` lock across read, check and write. Any lock, read or write error declines. `committedBinSHA` is shared with `repinPostCycle`.

### Test fixtures

- `tempRepoDir` removes best effort. On macOS runners, `os.RemoveAll` of a git work tree sometimes fails with EBADF under `-race` load. The failure turns a passing test red. The chmod walk makes git's read-only objects removable.
- `redPack` is a nonzero exit with named failures. `ambiguousPack` is a nonzero exit with none. `swapRepoContractTest` repeats its last outcome, so an over-eager retry loop shows in the invocation count.
- The seam tests cannot reach `classifyPackEvents`. `TestClassifyPackEvents_SeparatesRealFailuresFromNoise` pins it directly.
- The `landing_pins_test.go` goldens drive the three push sites against the repair matrix. They pin the argv, the stream routing, the logs, the result fields and the errors byte for byte. The capture was taken before the landing leaf was extracted.
