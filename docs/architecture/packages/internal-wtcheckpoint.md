# internal/wtcheckpoint

> Decision record: [ADR-0122](../adr/0122-checkpoint-uncommitted-worktree-work-as-refs.md). Operator procedure: [runtime-reference.md, "Operator commands (protect in-progress work)"](../../operations/runtime-reference.md) and [workspace-layout.md, "Checkpoints"](../../operations/workspace-layout.md#checkpoints-refscheckpoints).

## Purpose

`wtcheckpoint` keeps uncommitted work in a linked worktree safe from accidents: an agent dying, the worktree being removed, a reset, a checkout or a churn-discard. A save writes the worktree's staged tree and its full working tree as two commits under `refs/checkpoints/<worktree>/<UTC stamp>` in the shared store, without touching the branch, the index or the working tree. List, restore, prune and push read and manage those refs. `evolve checkpoint` (`go/cmd/evolve/cmd_checkpoint*.go`) is the only caller.

## Design

- **A checkpoint is two commits.** `c1` is the worktree's staged tree with parent `HEAD`, subject `checkpoint <name> staged <stamp>`. `c2` is the full working tree (tracked changes plus untracked files, ignored files excluded) with parent `c1`, subject `checkpoint <name> worktree <stamp>`. The ref names `c2`. So `ref^{tree}` is the full tree, `ref^^{tree}` the staged tree and `ref~2` the base `HEAD`, and the base stays reachable from the ref even after its branch is deleted. This is exactly the shape of the refs the console took with raw git plumbing on 2026-10-06, so the verb reads those too (`TestSave_RecordsTheStagedTreeUnderTheFullWorkingTree` pins the subjects).
- **Every tree is written through a copy of the index.** `snapshot` calls `gitexec.Git.TreeOfIndexCopy` twice, each time on a fresh copy of the worktree's index: with no add command for the staged tree, and with `add -A -- . ':!go/evolve' ':!.evolve/ledger.*'` for the full tree. The real index is never opened for writing, not even for git's cache-tree update, and its `index.lock` is never taken, so a save can run beside another process's `git add`. How the copy is made (one file handle, the original mtime kept for git's racy-clean check) is the primitive's, in [internal-gitexec.md](internal-gitexec.md).
- **Every git handle is `gitexec.Isolated`.** Inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and `GIT_COMMON_DIR` (a git hook sets them) are dropped, so a save run from a hook still reads the worktree it names and never writes through the hook's index.
- **Save prints one of three words.** `clean` when both trees equal `HEAD`'s tree (no ref written), `unchanged` when the worktree's newest checkpoint already has this full tree (no ref written; the newest ref is reported), `saved` otherwise. The unchanged check compares the full tree only, as the console snapshot did; a change only to what is staged does not make a new checkpoint.
- **A save is one `saver` value** (the worktree's git handle, its name and the options); `record` writes the two commits through `commit(commitSpec)` and creates the ref.
- **The new ref is created, never moved.** `update-ref <ref> <c2> ""` refuses an existing ref, so two saves in the same second fail loudly instead of overwriting one another.
- **Retention is per worktree.** After a save, `pruneWorktree` deletes that worktree's refs beyond the newest `Keep` (refnames sort chronologically because the stamp is fixed-width UTC). `Keep` comes from `.evolve/policy.json` `checkpoint.keep_per_worktree` (compiled default 20, see [internal-policy.md](internal-policy.md)); a non-positive `Keep` prunes nothing. Deletion passes the expected object id (`update-ref -d <ref> <oid>`), so a ref that moved in between is not deleted.
- **The hub is `plane.Hub`.** `ResolveHub` is `plane.ResolveHub`, the one definition of the [workspace layout](../../operations/workspace-layout.md) that `evolve worktree create|cleanup --dev` also uses: the project root must be a worktree root of a bare store (a non-bare `.git` is refused), the hub root is the store's parent, `DevDir()` is `<root>/dev` and `plane.OriginMainRef` is the fetched `refs/remotes/origin/main`. `Hub` embeds it. `Hub.Worktree` accepts only an entry of `git worktree list --porcelain` other than the first (the bare store, or a non-bare repository's main worktree), compared by resolved path, and never a prunable one. `Hub.DevWorktrees` returns the live linked worktrees whose resolved path is under `DevDir()`; the runtime plane, cycle worktrees under `runtime/.evolve/worktrees/` and the console are outside it by construction. A worktree's checkpoint name is its directory's base name, which `Save` checks with `git check-ref-format` before writing anything.
- **List takes a worktree directory or just its name.** The checkpoint name is the base name of either (the worktree may already be gone), the one rule `worktreeAt` holds; the CLI passes `--worktree` through unchanged.
- **List derives everything from the refs.** The time is the ref's stamp, the base is `ref~2`, the label is the `label: ` line of `c2`'s body (whitespace collapsed to single spaces at save time), and the change is `git diff --numstat --no-renames <base> <ref>` (a binary file counts as a file with no lines). A ref under `refs/checkpoints/` that is not a checkpoint (no stamp, no base, not a commit) is an error naming it, never skipped.
- **Restore never overwrites work.** A missing `--into` path becomes a new worktree (`git worktree add --detach <path> <base>` through `gitexec.AddWorktreeWithRetry`). An existing path must be a linked worktree of this hub (`Hub.Worktree`) with no dirty path (`gitexec.Git.DirtyPaths`) and no ignored file at a path the restore would write; if its `HEAD` is not the base it is detached at the base (it is clean, so nothing is lost, and its branch ref is untouched), and the result says so (`Detached`; a new worktree is detached too), so the CLI can tell the operator to `git switch -c`. Then `read-tree -m -u HEAD <full>` writes the full tree into the index and the working tree, `read-tree <staged>` resets the index alone to the staged tree, and `update-index -q --refresh` restores the stat data. Files of the full tree that the staged tree lacks come back untracked, so the staged/unstaged/untracked split is what was saved.
- **Prune --landed is per checkpoint and conservative.** A checkpoint is landed when it changed at least one path against its base and none of those paths differs between it and `plane.OriginMainRef` (`git diff --name-only -z --no-renames`). It never fetches: a stale `origin/main` only makes fewer checkpoints look landed. With no `origin/main` it refuses and deletes nothing, and every candidate is judged before the first ref is deleted.
- **Push is explicit and checkpoint-only.** `Push` sends exactly the named refs to `origin` as `<ref>:<ref>` and refuses any ref outside `refs/checkpoints/`; `Save` never calls it. The operator has not approved pushing work in progress to GitHub, so the CLI exposes it only as `save --push`.

## Invariants

- **A save never touches the real index.** Its bytes and mtime are identical before and after, and no `index.lock` is left (`TestSave_NeverTouchesTheRealIndex`). Run against a mutant that wrote trees through the real index, this test, `TestSave_SucceedsWhileAnotherProcessHoldsTheIndexLock` and `TestSave_AConcurrentGitAddNeverFails` all failed, the last one including the other process's `git add` failing on `index.lock`.
- **A save runs beside another process's `git add`.** With `index.lock` held it still saves and leaves the lock byte-identical (`TestSave_SucceedsWhileAnotherProcessHoldsTheIndexLock`); racing a loop of real `git add`s, neither side fails (`TestSave_AConcurrentGitAddNeverFails`).
- **The tracked binary and the ledger never enter a snapshot.** A rebuilt `go/evolve` stays at its index blob and untracked `.evolve/ledger.*` files are absent, while other untracked files are captured (`TestSave_NeverIncludesTheBinaryOrTheLedger`).
- **Only linked worktrees of this repository are targets.** A plain directory, the store, a subdirectory of a worktree, and another repository's main or linked worktree are refused (`TestHub_WorktreeRefusesATargetThatIsNotALinkedWorktree`). `--all` never includes the runtime plane, a cycle worktree, the console or a removed (prunable) worktree (`TestHub_DevWorktreesNeverIncludeTheRuntimePlaneOrACycleWorktree`).
- **Restore round-trips the staged/unstaged/untracked split.** A staged new file, an unstaged edit and an untracked file come back with identical `git status --porcelain -uall`, `git diff --cached` and `git diff`, into a new path (`TestRestore_IntoANewPathBringsBackTheStagedUnstagedAndUntrackedSplit`), into the same worktree after `reset --hard` and `clean -fd`, keeping its branch (`TestRestore_IntoTheSameCleanWorktreeAfterAnAccidentKeepsItsBranch`), and into a clean worktree whose branch moved on, which is detached at the base with its branch ref left where it was (`TestRestore_IntoACleanWorktreeOnAnotherCommitDetachesAtTheBaseAndKeepsTheBranchRef`). List counts a binary file as a file with no lines (`TestList_CountsABinaryFileAsAFileWithNoLines`).
- **Restore refuses a dirty target, an ignored-file collision, a non-worktree path and an unknown ref**, leaving every file as it was and creating nothing (`TestRestore_RefusesADirtyTargetAndLeavesItsWorkAlone`, `TestRestore_NeverOverwritesAnIgnoredFileInTheTarget`, `TestRestore_RefusesAPathThatIsNotALinkedWorktreeAndAnUnknownRef`).
- **Retention keeps the newest N of each worktree and no other worktree's refs** (`TestSave_KeepsOnlyTheNewestNPerWorktree`, `TestPrune_KeepsTheNewestNPerWorktree`), and a ref both past retention and landed is deleted once (`TestPrune_ARefPastRetentionThatAlsoLandedIsDeletedOnce`). **An unchanged save compares against the newest checkpoint, not an older one** (`TestSave_ComparesAgainstTheNewestCheckpointNotAnOlderOne`). **Prune --landed deletes only a checkpoint whose every changed path is on origin/main**; a partly landed one is kept (`TestPrune_LandedDeletesOnlyCheckpointsWhoseChangesAreAllOnOriginMain`), so is one that changed no path against its base (`TestPrune_LandedKeepsACheckpointThatChangedNothingAgainstItsBase`), and a missing `origin/main` or a malformed ref deletes nothing (`TestPrune_LandedWithoutOriginMainFailsAndDeletesNothing`, `TestPrune_LandedFailsOnACheckpointWithoutABaseAndDeletesNothing`).
- **Nothing is pushed unless asked, and only checkpoints can be** (`TestPush_SendsOnlyTheNamedCheckpointRefsAndSaveNeverPushes`, `TestPush_FailsLoudlyWithoutAnOrigin`).
- **Failures are loud.** An unmerged index fails the save and writes no ref (`TestSave_FailsLoudlyOnAnUnmergedIndexAndRecordsNothing`); a worktree name that cannot name a ref is refused (`TestSave_RefusesAWorktreeNameThatCannotNameARef`); a ref under `refs/checkpoints/` that is not a checkpoint fails `List` (`TestList_RefusesARefThatIsNotACheckpoint`).
- **Every export is named by a test** (`.apicover-enforce`), and the package holds an 87% statement floor (`.cover-strict`): it drives real git with no fake runner, and what it leaves uncovered are git-failure returns.

## Findings

- **`git read-tree -m -u` overwrites an ignored file without a word** (git 2.50.1, 2026-10-06). With `*.log` ignored, a clean worktree holding its own `build.log`, and a checkpoint whose tree carries a force-added `build.log`, the two-tree read exited 0 and replaced the target's file. git treats ignored files as expendable, so a clean `git status` does not prove a restore is safe. `ignoredCollisions` lists the target's ignored paths (`ls-files --others --ignored --exclude-standard --directory`) and refuses when any path the restore writes (base to full, plus current `HEAD` to base) is one of them or sits under an ignored directory. `TestRestore_NeverOverwritesAnIgnoredFileInTheTarget` was red before the guard.
- **The convergence with the dev-worktree landed proof.** A parallel console lane (`dev/cl-gc`) is building a content-landed proof for dev worktrees (`changesInMain` in `cmd/evolve`). It is not on main, so `--landed` uses the conservative per-path rule above. When that proof lands, `hasLanded` should call it instead, so the two answers cannot disagree. That lane's `devHub` now comes from `plane.ResolveHub` (its `taskDir` reads `DevDir()`), so the hub layout has one definition; its own `readDevTreeState` reads with `GIT_OPTIONAL_LOCKS=0` through a private `withGitEnv`, which is a candidate for `gitexec` when it lands.
- **The first `gitexec.Isolated` broke the index copy, and the real-index test caught it** (2026-10-06). It filtered every environment it was handed, so with `Isolated` handles here, the `GIT_INDEX_FILE` that `TreeOfIndexCopy` set was stripped again and `add -A` ran on the real index: `TestSave_NeverTouchesTheRealIndex`, `TestSave_RecordsTheStagedTreeUnderTheFullWorkingTree` and `TestSave_SucceedsWhileAnotherProcessHoldsTheIndexLock` went red. The filter now applies only to the inherited environment ([internal-gitexec.md](internal-gitexec.md), Findings).
- **Review-driven tests** (2026-10-06). The architecture review's mutation sweep left mutants alive in the unchanged check, the restore detach, the landed rule's empty-change case, the retention-plus-landed overlap, the binary-file count and `save --push`; each now has a test that kills it.
