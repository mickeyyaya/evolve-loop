# internal/phases/runner

> The verdict engine this package hosts is designed in [decomposition unit 11](../decomposition/11-phaserunner.md) ([ADR-0103](../adr/0103-component-breakdown-program.md)): settle ladder, teardown reconcile arms, ship guard, its signal codes and its goldens. The chain walk lives in [internal/llmroute](internal-llmroute.md). Host effects are [ADR-0100](../adr/0100-declared-deliverables-gate.md) amendment 10 and the [triage-claim incident](../../incidents/2026-09-26-triage-claim-left-to-the-agent.md). The worktree fence is [ADR-0097](../adr/0097-read-only-phase-worktree-fence.md). This page keeps the host-side detail those do not.

## Purpose

`internal/phases/runner` is the shared engine behind every subagent-dispatching phase. `BaseRunner` is a Template Method: a phase supplies a small `Hooks` value, and the runner does the rest. It composes the prompt, resolves the dispatch plan, walks the CLI and tier fallback chain inside the worktree fence, performs the phase's declared host effects, and hands the outcome to the verdict engine (`verdict/`) to judge.

## Design

- **Template Method, split into stages.** `Run` is prepare (`preparation.go`) → plan (`routing.go`) → dispatch (`dispatch.go`) → host effects (`host_effects.go`) → judge (`verdict_engine.go`). Each stage returns an immutable value the next one reads (`phasePreparation`, `phaseDispatchPlan`, `phaseDispatchResult`). `dispatchOf` is the one projection of those values onto the engine's `verdict.Dispatch`. It is a keyed literal because `go vet`'s composites check rejects a positional literal of an imported struct. The leaf's own test builds it positionally, so a new field breaks the build there.
- **Optional hooks are separate interfaces.** `Skipper`, `InlinePromptProvider` and `SecondaryArtifactsProvider` are type-asserted, never required. Most phases never skip and most load their persona from disk, so forcing a no-op method on every `Hooks` would break interface segregation. Minted and spec phases (`specrunner`) ship their prompt as data through `InlinePromptProvider`; returning `("", false)` keeps the disk load. Phases that can opt out before any bridge call, such as triage, tdd and intent, implement `Skipper`.
- **Profile and env keys use the agent name, not the phase name.** The profile file is `AgentPromptName` minus the `evolve-` prefix (`evolve-builder` → `builder.json`), and the per-agent keys (`EVOLVE_BUILDER_MODEL`, `EVOLVE_BUILDER_PERMISSION_MODE`) use the same name, because that is what `cmd_loop.go` writes.
- **Every seam is a per-instance `Options` field.** A nil seam takes its production default in `New` (`ResolveLLM`, `EventsProducer`, `StdoutFilter`, `VerifyFn`, `SleepFn`, `Diag`, `Signals`). Per-instance fields rather than package globals keep `t.Parallel()` tests race-free. `settleSleep` is the one package variable: a test `init` makes it a no-op, because the settle retry sits on the common clean-exit path and real sleeps would multiply the package's test time. Tests that count retries inject `SleepFn`.
- **The engine is built once.** `wiredVerdictEngine` is the only construction and the only place the engine's seams are resolved. `New` stores it eagerly, and nothing builds one lazily.
- **One verifier for gate and engine.** `Options.ContractVerifier` hands the engine the deliverables gate's own `deliverable.Reviewer`, so a salvaged verdict is classified on the repaired bytes the gate approves. It is an accessor because the composition root builds the Reviewer after the runners: it needs the merged phase catalog. `Options.HostEffects` is an accessor for the same reason. With neither `VerifyFn` nor a verifier, the probe is `deliverable.VerifyCatalogAwareStage` over `Options.PhaseIO`, so user and minted phases resolve under the host gate's policy. That default never salvages; only the gate repairs.
- **The Signal Center comes from one derivation.** `resolveSignals` returns `Options.Signals` when set, else the Center the injected Bridge exposes (the production adapter does), else nil, the Null Object. `signalSource` is unexported so the package's apicover row gains no type.
- **Universal fallback defaults are boot-time package variables.** `DefaultDiscoverCLIsFn` and `DefaultUniversalFallback` are set once in `cmd_cycle.go`, the same set-once pattern as `PhaseBoundaryCheckpointer`, so the ten or so per-phase constructors need not each thread a `bridge.Doctor` closure. `Options` fields override them. `DiscoverCLIsFn` is a seam so the runner never imports `bridge`. With both at zero the feature is inert.
- **The dispatch walks `llmroute.DispatchTiered`.** It is the same walk the advisor uses, never a copy in the runner. The tier string is passed as `BridgeRequest.Model`; the bridge realizer maps it per CLI through the manifest's `model_tier_map`, so the runner resolves no concrete model. Every attempt is marked `ChainAttempt`, so a chain-walking bridge handle passes it through instead of walking the chain a second time ([ADR-0104](../adr/0104-fallback-is-a-property-of-the-bridge-handle.md)).
- **Per-attempt work.** Skill overlays are resolved inside the attempt closure, because overlay rules key on the tier and a quota step-down changes the tier mid-walk ([skill-overlays](../skill-overlays.md)). The overlay's objective signals are core's one per-dispatch projection (`PhaseRequest.Signals`, [ADR-0099](../adr/0099-deliverable-kinds.md)); the runner copies them and never re-reads the workspace. The events producer runs after every attempt, so `<phase>-events.ndjson` describes the last CLI that ran.
- **The CLI-health bench is consulted and written by the runner.** `applyBenchToPlan` reorders the chain by the bench unless a policy pin fixes the CLI. An exit 85 with a fresh, benchable escalation report benches the candidate's family on every candidate, the last one included. Both are off under `EVOLVE_CLI_HEALTH=0`.
- **Prompt assembly.** `BaseCycleContext` writes the shared `## Cycle Context` block with its four mandatory fields; phases append their own fields after it. `cycleContextBoundary` is the one literal that both it and `StaticPrefix` use, so the cache-stable prefix and the per-cycle tail cannot drift apart and bust the provider prompt cache. A profile's `turn_budget_hint` and, for phases whose contract requires it, the challenge token are appended after the hook's prompt ([context-window-control](../context-window-control.md)).
- **`LaneScope` sanitizes.** The lane's ids come from the advisor's LLM-authored backlog, so line breaks and tabs are collapsed before the value reaches a prompt. A newline in an id would otherwise forge a new context bullet. An empty scope means a sequential cycle, and phases render nothing.
- **The fence reports, it never decides.** What the fence did becomes a diagnostic on the response and a WARN in the phase log. It never changes a verdict. The fence assumes the agent is gone when it closes: `Launch` is synchronous and the bridge tears the session down before returning. A driver that returned a still-running REPL could write after the close; those writes reach the ship's own explanation verification, which stays armed. The retro phase, which calls the bridge itself, holds the same `treefence.Fence` around its launch.

## Invariants

- **Host effects perform before the judge.** The engine's first verification must see what the host did, so a claim the persona skipped is already made when the gate checks it. Effects ignore cancellation, because a teardown is often what cancelled the context. A failed effect is a coded WARN (`RUNNER_HOST_EFFECT_FAILED`), and the gate still judges. Pinned by `TestRun_HostEffectsPrecedeTheFirstVerification` and `TestRun_AFailedHostEffectIsACodedWarning`; the code keeps a one-line why.
- **The fence spans the whole chain and closes before classification.** One snapshot precedes the first attempt and one restore follows the last, because the audit's explanation binding runs inside `Classify` and must judge the builder's tree, not the auditor's probes. Pinned by `TestRun_ReadOnlyPhaseWorktreeIsRestoredAndReported`, `TestRun_SourceWriterIsNotFenced` and `TestRun_FenceUnavailableWarnsAndProceeds`.
- **Only this run's fence may vouch for the tree.** `Run` clears the caller's `WorktreeVerified` before anything else, and `Classify` sees the value the fence stamped. Pinned by `TestRun_FenceVerificationCannotBeSuppliedByCaller` (build tag `integration`).
- **Preparation snapshots the artifact before any bridge side effect.** The snapshot is what lets the engine refuse a byte-identical leftover from a prior attempt on both reconcile doors, the verify door and the ACS floor. A leftover carries this cycle's challenge token and may sit beside a prior PASS `acs-verdict.json`, so token and ACS cannot tell stale from fresh. Pinned by `TestRun_Timeout_StalePreDispatchLeftoverIsNotReconciled`, `TestRun_Timeout_RewrittenLeftoverStillReconciles`, `TestRun_Timeout_OptionalPhaseStaleLeftoverDegradesToWarn` and `TestRun_Timeout_AcsFloorRefusesStaleLeftover`.
- **The challenge token is read only through `phasecontract.ChallengeToken`.** No file in the package spells the token file, so the prompt and the engine's ACS floor read one belief. Pinned by `TestPreparation_ChallengeTokenAndSnapshotProjectTheLeaf`. Scout mints the token, so its prompt never carries the echo instruction (`TestRun_NonTokenPhase_PromptUnchangedEvenWithFile`).
- **A policy pin is absolute.** It beats the per-agent env CLI and pins the model verbatim; it skips the capability probe and the bench, so a pinned binary is never silently demoted; an invalid or malformed pin fails the phase loudly. With a pin, the advisor overlay never applies and the recorded model source is `pin`. Pinned by the `TestRun_PolicyPin_*` tests, `TestRunner_PolicyPinWinsOverAdvisorOverlay_SourceIsPin` and `TestRun_ModelSourceReflectsResolutionPath`.
- **An advisor overlay is soft.** It promotes a CLI to primary but keeps the profile's chain, so a benched or missing overlay CLI can fall back. Both the applied and the absent overlay log a line. Pinned by `TestRunner_ModelRoutingAuto_BenchedOverlayPrimaryFallsBack`, `TestRunner_ContractEscalation_KeepsOriginalPrimaryInChain`, `TestRunner_AdvisorOverlayAppliedLogsLine` and `TestRunner_NoAdvisorOverlayLogsProfileDefault`.
- **A legitimate FAIL never reroutes.** Only a trigger exit (80, 81, 85, 124 or 127 by default) advances the chain, a tier steps down only when every CLI at it exited 85, and an exhausted chain ends on the last attempt's error. Pinned by `TestRun_NoFallbackOnNonTriggerExit`, `TestRun_ChainExhausted_LastErrorSurfaces`, `TestRun_FallbackOnArtifactTimeout_DefaultTriggerListIncludes81`, `TestRun_FallbackOnGNUTimeout_124` and `TestRunnerDispatch_AllDefaultTriggerExitCodesFallBackThroughRun`. `TestRunnerDispatch_NoInlineFallbackLoop` keeps the walk out of the runner.
- **Under tiering, the attempt log is the index.** The attempt counter grows past `len(Candidates)` once a tier steps down, so the previous attempt is read from `attemptLog`, never from `Candidates`. The code keeps the one-line why; `TestRun_QuotaExhaustedAcrossChain_NeverStepsDownTier` walks a step-down.
- **Overlays are recomputed per attempt.** Pinned by `TestRunner_TierStepDown_RecomputesOverlayPerAttempt`.
- **Events are produced on every attempt, bridge errors included, and never block.** A phase that fails on a timeout or a 429 is exactly the infrastructure failure `cycleclassify` must detect. A producer error only WARNs; the raw log stays the forensic source. The composed prompt reaches the producer so the classifier's echo veto can recognize quoted prompt text. Pinned by `TestRun_EventsProducer_RunsOnBridgeError`, `TestRun_EventsProducerError_NonBlocking` and `TestC672_002_RunnerThreadsComposedPromptToEventsProducer`.
- **A bench is advice, never a veto.** With every candidate benched the phase still dispatches, least recently benched first. A report captured before this run started is another phase's leftover and never benches; staleness counts from the run start, not from the attempt. Pinned by `TestRun_AllFamiliesBenchedNeverStrands`, `TestRun_StaleReportDoesNotBench` and `TestRun_CLIMismatchReportDoesNotBench`.
- **A missing profile fails fast only when the profiles directory exists.** An absent directory, or a file at that path, keeps the default resolution. Pinned by the `TestRunnerMissingProfile_*` tests.
- **Only a genuinely absent persona carries `core.ErrAgentDocMissing`.** An unreadable doc or a nil prompts source is a wiring or I/O fault; classifying it as missing would let the optional-skip admission absorb it. `PersonaAvailable` answers the same question before dispatch with the same sentinel, so the planner and the skip classifier agree. Pinned by `TestRun_MissingAgentDocCarriesTheTypedSentinel`, `TestRun_UnreadableAgentDocDoesNotCarryTheSentinel`, `TestRun_NilPromptsSourceDoesNotCarryTheSentinel` and `TestBaseRunner_PersonaAvailable`.
- **Inline bodies are never compacted.** `CompactPrompts` strips on-demand sections from disk-loaded docs only. Pinned by `TestRun_CompactPrompts_InlineBodyNotStripped`.
- **The deliverable is the verdict source on every completion path.** For a contracted phase, the recorded verdict comes from the on-disk deliverable whenever it verifies, and never from scrollback that echoes other phases' example sentinels. The rule holds for clean exit, artifact timeout (81), transient teardown (80, 85, 86) and context cancellation. A genuine PASS stays PASS, a genuine FAIL stays FAIL, and an absent or never-settling deliverable falls back after a bounded number of probes. Reconciliation only moves toward the agent's real deliverable, never invents one. The runner-level pins are the `runner_cleanexit_test.go`, `runner_reconcile_test.go` and `runner_reconcile_transient_test.go` suites; the engine's goldens pin every arm.
- **The classified bytes are the verified bytes.** The file is read once, by the probe, and those bytes are classified, so a writer racing the verify-to-classify window cannot change the verdict. The one exception is a dispatched artifact whose name differs from the contract's (intent's delta mode writes `intent-delta.md` while the contract names `intent.md`): the runner reads the dispatched file, so the phase's SKIPPED verdict survives. Pinned by `TestRun_CleanExit_FileSwappedAfterVerify_ClassifiesTheVerifiedBytes`, `TestRun_Reconciled_FileSwappedAfterVerify_ClassifiesTheVerifiedBytes`, `TestRun_ContractedPhase_ClassifiesWithoutReadingTheArtifactAgain` and `TestRun_DispatchedArtifactDiffersFromContractPath_ClassifiesTheDispatchedFile`.
- **The ship guard downgrades only a clean ship.** A contracted deliverable that fails verification turns PASS (or a non-canonical verdict) into FAIL and surfaces the violation codes. FAIL, WARN and SKIPPED pass through, because WARN shipping is the orchestrator's policy (`workflow.strict_audit`) and SKIPPED is a phase's legitimate verdict from partial content. `NextPhase` is never touched. Pinned by `TestRun_NonTimeout_ContractedDeliverableFailsVerification_ShipVerdictDowngraded`, `TestRun_ContractedPhase_UnverifiedDeliverable_NonShipVerdictPassesThrough`, `TestRun_ContractedPhase_UnverifiedDeliverable_WarnPassesThrough` and `TestRun_ShipGuardDowngrade_LeavesNextPhaseUntouched_AndPassesThroughFailWarnSkipped`.
- **An uncontracted phase keeps the pane as its source and pays no settle wait.** A verify error means no contract; waiting cannot resolve it. Pinned by `TestRun_UncontractedPhase_PaneRemainsVerdictSource` and `TestRun_UncontractedPhase_NoWastedSettleSleeps`.
- **Two cancellation policies for one settle ladder.** The teardown reconcile settles under `context.WithoutCancel`, because the cancel is often the teardown itself and a late deliverable must still be caught. The clean-exit path bails after its first probe once the context is cancelled, because nothing more is coming. Pinned by `TestRun_CancelledCtx_TeardownReconcileStillSettles`, `TestRun_AlreadyCancelledCtx_SettleWaitDoesNotBurnTheWindow`, `TestRun_CtxCancelledDuringSettleWait_StopsReprobing` and `TestRun_VerdictProbeCounts_CancelledCtx`.
- **The ACS floor rescues only an authenticated audit.** A teardown whose Verify says not-OK reconciles to PASS only for the audit phase, only when `acs-verdict.json` is ship-eligible, and only when the report carries this cycle's challenge token with a PASS sentinel. The rescue surfaces the overridden violation codes. Pinned by the four `TestRun_Teardown_VerifyNotOK_*` tests.
- **Ordering inside the judge.** The stdout filter runs after the verdict bytes are chosen and before `Classify` (`TestRun_StdoutFilter_RunsAfterVerdictSelectionAndBeforeClassify`). Diagnostics are ordered: `Classify`'s own, then the fence's, then the contract violations, then the reconcile warning and the ACS override (`TestRun_VerdictDiagnostics_OrderIsClassifyFenceViolationsReconcileOverride`).
- **The verifier sees the cycle.** The runner hands the verifier the same cycle the host gate and the agent self-check use, so a declared effect judged under `processing/cycle-N/` gets one answer from all three. Without it the verifier fails open on every effect-declaring phase. Pinned by `TestRun_VerifyRootsCarryTheCycle`.
- **An optional phase degrades only on a teardown.** An artifact timeout or transient teardown with no trustworthy deliverable is a WARN that lets the cycle advance; any other bridge error, and any mandatory phase, still hard-fails. Pinned by `TestRun_OptionalPhase_ArtifactTimeout_DegradesToWarn`, `TestRun_OptionalPhase_OtherBridgeError_StillFails` and `TestRun_MandatoryPhase_ArtifactTimeout_StillFails`.
- **One construction, one projection.** Pinned by `TestVerdictEngine_OneConstructionSite`, `TestNew_BuildsTheEngineOnceEagerly`, `TestDispatchOf_IsTheOneProjection` and `TestNew_SignalsResolveExplicitThenBridgeThenNull`.

## Findings

- **cycle 107**: the runner read only `EVOLVE_CLI` and defaulted to `claude-p`, silently ignoring `profile.cli`. An operator who set `"cli": "codex"` in every profile still ran claude. `TestRun_CLIResolutionPrecedence` pins env > profile > default.
- **cycle 120** (Workstream D): an optional phase (build-planner) whose artifact never appeared aborted the whole cycle with FAIL. It now degrades to WARN; see the optional-phase invariant.
- **cycles 121 and 122**: the fallback chain first covered only exit 80 (REPL boot timeout). A codex-tmux tdd hang caught at exit 81 (artifact timeout) was not retried on another CLI, so 81 joined the default trigger list, with 124 (`timeout(1)`) as its companion.
- **cycle 124** (Bug A): the model resolver read `EVOLVE_<PHASE>_MODEL` while `cmd_loop.go` writes `EVOLVE_<AGENT>_MODEL`, which dropped every override where phase and agent names differ (build/builder, audit/auditor, tdd/tdd-engineer, retro/retrospective). `TestRun_PerAgentModelEnvKey_AgentKeyedNotPhaseKeyed`.
- **cycles 254 and 255**: a complete PASS audit report was discarded because the bridge gave up on the wait window; this started reconcile-on-timeout. **cycle 835** extended it to transient teardowns: an auditor on an overloaded claude hit its own exit 85 after writing a complete PASS report.
- **cycle 262** ([ADR-0044](../adr/0044-unified-phase-recovery-protocol.md)): codex's mid-phase self-upgrade exited 81 and the fallback succeeded, but the orchestrator's abort path lost the record. The runner already carried the final attempt's verdict, cost and duration; `TestRun_FallbackOnArtifactTimeout_CarriesVerdictCostDuration` keeps it so.
- **cycle 269**: the move from bash to Go dropped the challenge-token prompt injection. Whether a builder echoed the token depended on it reading the scout report, the claude fallback did not, and a perfect build failed at audit. The runner now appends the token block for phases whose contract requires it.
- **cycle 283**: a codex rate-limit wall re-burned the benched primary's boot window on every dispatch. It produced the CLI-health bench hooks and the replay in `runner_clihealth_story_test.go`.
- **cycles 603 and 899**: an agent exited cleanly after writing a valid PASS, then idled. A single-shot verify raced the idle state and the runner classified multi-phase scrollback into a false FAIL, more than ten times on one goal. The clean-exit path now settles like the reconcile path. **cycle 921** widened the settle window after a late flush fell past the old three-retry window ([ADR-0072](../adr/0072-system-failure-policy-and-halt.md) verdict incoherence).
- **cycles 824 and 825**: a next phase's context cancel tore down the audit session while its PASS deliverable was still settling, and a single-shot verify discarded a genuinely passing cycle. That produced the bounded settle ladder and its teardown policy.
- **cycles 3, 603, 921, 924 and 931**: a tmux auditor wrote a complete PASS report and a ship-eligible ACS verdict, never ran the completion handshake, and was cancelled. Teardown-time Verify disagreed with a standalone verify, the phase failed, and the coherence floor halted on recorded FAIL against on-disk PASS. That produced the ACS floor.
- **cycle 435**: the runner and the advisor walked the CLI chain with two copies of one algorithm. The runner now calls the llmroute walk, and `runner_dispatch_dedup_test.go` keeps the copy out.
- **cycle 876**: the tier chain was built in `llmroute` but the runner still dispatched through the CLI-only walk with one fixed model, so a quota-walled top tier never stepped down. `runner_tier_fallback_reproduction_test.go` is the reproduction.
- **cycle 672**: the events producer ran without the composed prompt, so an agent quoting its own prompt was classified `infra_failure`, the third recurrence of the cycle-641 lesson.
- **cycle 1550**: a byte-identical leftover from a prior attempt was resurrected as the session's verdict after an artifact timeout. The pre-dispatch snapshot closes the runner's door; see the snapshot invariant.
- **cycle 1551**: the real load path did not wrap a missing persona in `core.ErrAgentDocMissing`, so the optional-skip admission one layer up never fired.
- **cycles 1603 to 1605**: an auditor's probes changed the builder's tree before the audit judged it. That produced the worktree fence ([ADR-0097](../adr/0097-read-only-phase-worktree-fence.md)).
- **cycle 1685** (F22): the engine verified with the plain verifier and classified unrepaired bytes while the gate salvaged and approved the repaired file, so a cycle with `red_count=0` sealed FAIL. One verifier fixed the class ([verification-wave findings](../../research/verification-wave-findings-2026-09-14.md), F22); `TestRun_ContractVerifierSalvagesBeforeClassification`.
- **F36**: triage's inbox claim was left to the agent, and a skipped claim cost a correction every time. The host now performs declared effects before every judge ([incident](../../incidents/2026-09-26-triage-claim-left-to-the-agent.md)).
