# internal/cliroute

> The design and its landing plan: [cli-routing-table-2026-10.md](../../plans/cli-routing-table-2026-10.md). The plan primitives this package composes: [internal-llmroute.md](internal-llmroute.md). The schema of the `cli_routing` block: [internal-policy.md](internal-policy.md). The Claude-family floor list and `cross_family_with`: [internal-profiles.md](internal-profiles.md). This page keeps the package-level detail those do not.

## Purpose

`internal/cliroute` is the one routing table and the one resolver for every launch path. The operator declares in `.evolve/policy.json` which CLIs exist, which CLI does each kind of work, and what happens when a chain runs out (the `cli_routing` block). `Compile` turns that block into a `Table` and reports every integrity finding at once. `Router.Resolve` turns one launch request into a dispatch `llmroute.Plan`. When the block is absent, `Resolve` reproduces today's resolution byte for byte (the legacy projection), so wiring a launch path through it changes nothing until the operator writes the block.

Status (L1a, 2026-10-05): built and tested, **not yet called by any launch path**. Wiring the runner, the bridge chain, `resolvellm`, the retro, the advisor, contract escalation, the loop preflight and setup is L1b of the plan.

## API

| Symbol | What it is |
|---|---|
| `Compile(p, cat, profs, opts...) (Table, []Finding)` | Snapshots every listed profile, then compiles `p.CLIRouting`. With no block it returns the legacy table; its only possible findings are a missing or unlistable profile source. `WithToolCapable(fn)` adds the tool-capability check; the composition root passes `bridge.HasToolUse`. |
| `(Table).Findings() []Finding` | The findings the table was compiled with (a copy). |
| `New(t Table, h Host) (*Router, error)` | One router per process, built at the composition root. It refuses a table that carries any error-severity finding, naming each, so a table with a defect never routes. |
| `(*Router).Resolve(req Request) (Decision, error)` | The plan for one launch. |
| `Catalog` | `Get(name)` and `Names()` of the merged phase catalog; `phasespec.Catalog` satisfies it. |
| `ProfileSource` | `Get(name)` and `List()`; `*profiles.Loader` satisfies it. |
| `Host` | The host seams: `LookPath` (the probe), `Discover` (the raw installed-CLI list for the legacy universal tail), `Bench` (the CLI-health reordering; production passes `bridgechain.ApplyCLIHealthBench`), `Logf`. |
| `Request` | `Agent` (the profile name), `Phase` (empty for a launch with no phase), `ProjectRoot`, `DefaultModel`, `Env`, `Overlay` (the advisor's soft CLI and tier), `CallerCLI` (the CLI a non-phase caller asked for), `Expand` (the `"auto"` expander). |
| `Decision` | `Plan`, `Rule` (`agents:<agent>`, `work:<role>`, `default`, `profile`, or one of `legacy:pin`, `legacy:env`, `legacy:caller`, `legacy:default`, `legacy:profile`), `Allowed` (the families the agent may use), `Trace` (one line per filtered or ignored input), and `Allows(cli)`. A legacy decision whose profile does not restrict `allowed_clis` has a nil `Allowed`, which allows every family. |
| `Finding` | `Severity` (`error` or `warn`), `Key` (the policy path or check, such as `cli_routing.agents.auditor`, `cross_family_with.auditor+builder`, `agent.auditor`, `pins`) and `Message`. |
| `RuleError` | The one refusal of rule selection: `Rule`, `Kind` (`RuleLeak`, an `agents` entry outside the allowed set; `RuleEmpty`, a chain the allowed set empties), `Dropped` and `Allowed`. `Resolve` returns it wrapped (`errors.As` finds it); `Compile` turns it into a finding keyed `cli_routing.agents.<key>` for a leak and `agent.<agent>` for an empty chain. The `show` and `explain` verbs will read it too. |
| `CeilingError` | The refusal of the tier ceiling: `Rule`, `Tiers` (the tier chain tried), `Chain` and `Ceiling`. One predicate, `Table.ceilingRefusal`, raises it for both `Resolve` (the resolved plan) and `Compile` (each selection's static plan), and `Compile` keys it `agent.<agent>.tier_ceiling`. |

## Design

- **Strategy: two resolvers behind one call.** A declared table runs the declared pipeline; an absent block runs the legacy projection. The caller never branches.
- **Pipeline: the declared resolve is a list of stages**, each a function of under 50 lines that takes and returns a `resolution` value: rule → the agent's `model` → guarded env → caller CLI → advisor CLI → advisor tier → probe → bench → `after_chain` → the tier ceiling. A stage that refuses returns an error naming the agent; a stage that drops or ignores an input appends a `Trace` line.
- **Builder: `Compile` accumulates findings** instead of stopping at the first. Each finding is recorded once, so an agent that serves two roles under one bad rule is reported once.
- **One rule predicate.** `Table.selectRule(agent, role selection, profile, allowed)` picks the rule, filters its chain by the allowed set and returns either the selection or a `RuleError`. `Compile` and `Resolve` both call it, so the check that a launch can run and the check that the table is valid are one function.
- **Profiles are snapshotted at `Compile`.** `Compile` lists the profiles and loads each once; `Resolve` never reads them again. In declared mode a listed profile that failed to load is an error from `Resolve` (and a `profiles.<agent>` finding), never a nil profile, because a nil profile would widen the allowed set to every CLI in `clis`. The legacy projection keeps today's behaviour: an unloadable profile resolves as no profile, as the bridge chain does now. An agent with no profile at all resolves with no profile restriction in both modes. A profile minted after `Compile` is not seen until the table is compiled again (an L1b decision in the plan).
- **Rule precedence.** `agents.<agent>` > `work.<role>` > `default` > the profile's own `cli` + `cli_fallback`. The role is `phasespec.PhaseSpec.RoleOrDefault()` of the request's phase, looked up through `phasecontract.RegistryKey` (so the runner's `retro` finds the registry's `retrospective`) and inferred from the name when the catalog lacks it. A request with no phase (a bridge-chain launch) takes the agent's role when every phase the agent serves has the same role (retrospective: `retro` and `retrospective`, both control), and otherwise has no role, so `work` does not apply. `Compile` checks every selection `Resolve` can make: each role of the agent's phases, plus the no-role selection whenever the agent serves no phase or phases of several roles.
- **Agent keys accept a phase name.** `agents.audit` normalizes to `auditor`: a profile name is taken as is; a built-in phase maps through its `phasecontract` contract (`build` → `builder`, `tdd` → `tdd-engineer`, `audit` → `auditor`, `retro` → `retrospective`); any other catalog phase maps through `PhaseSpec.AgentName()` without the `evolve-` prefix. The contract step exists because the phase registry leaves `agent` empty for those built-ins, so `AgentName()` alone yields `evolve-build`.
- **The allowed set.** `A(agent) = clis ∩ profile.allowed_clis ∩ ({claude} for a floor agent)`, in `clis` order. The profile part is `(*profiles.Profile).AllowsFamily`, the floor part `profiles.IsClaudeFamilyFloor`. Chains from `default`, `work` and the profile rule are filtered by `A` silently (a `Trace` line); an `agents` entry outside `A`, or a chain left empty, is an error from `Resolve` and a finding from `Compile`.
- **An assignment is a chain, not a lock.** Every rule keeps the probe, the bench and `after_chain`. `after_chain: other_clis` (the default) appends the rest of the allowed set `A`, which is already `clis` in their listed order, through `llmroute.ApplyUniversalFallback`; `stop` appends nothing. Building the tail from `A` means no later filter is needed.
- **The advisor overlay applies per dimension.** A table rule (`agents`, `work` or `default`) fixes the CLI chain, so the advisor's CLI is ignored and traced; under the profile rule it is promoted when it is inside `A`. The advisor may still raise the tier unless `agents.<agent>.model` sets one. A per-run `EVOLVE_<AGENT>_MODEL` outranks `agents.<agent>.model`.
- **Env and caller primaries.** `EVOLVE_<AGENT>_CLI` and `EVOLVE_CLI` stay per-run overrides, but a value outside `A` is an error naming the key. A `CallerCLI` (today's `bridgechain.leadWith`) applies only under the profile rule and only inside `A`; otherwise it is ignored and traced.
- **The tier ceiling rides the plan.** `tiers.<tier>` becomes `Plan.TierCeiling` (tier → families), and `llmroute.DispatchTiered` skips every (CLI, tier) attempt the ceiling excludes, including the `after_chain` tail. With `tiers.deep = [claude]`, (agy, deep) is never launched; a walled Claude at deep steps down the existing tier chain and may run agy at balanced. `Resolve` refuses a plan in which no (CLI, tier) pair is permitted at all, checking `Plan.Tiers`, or `Plan.Model` when `Tiers` is empty, exactly as the walk does. `Compile` runs the same predicate on each selection's static plan: the selected chain plus the `after_chain` tail unless `stop` (built by the same `Table.withAfterChain` that `Resolve` uses), all inside `A`, at each tier chain the configuration can produce. Those are the chain of `agents.<agent>.model` when it is set, because it fixes the tier; otherwise the chain of the profile's default tier (an unset default dispatches as balanced) and of each `model_tier_overrides` tier. Each tier chain comes from `llmroute.ApplySoftOverlay`, the code path `Resolve` takes, so the envelope floor applies alike. A per-run `EVOLVE_<AGENT>_MODEL` or an advisor tier can still reach a tier no configuration names; that refusal stays `Resolve`'s alone. The plan carries a deep copy of the ceiling. The tier names are `policy.TierNames()`, the one ordered vocabulary.
- **The legacy projection reproduces both of today's resolvers.** For a request with a phase it is the runner's `resolveDispatchPlan`: the phase-keyed pin (validated with `policy.ValidatePin`, the runner's own error), `llmroute.Resolve`, the advisor overlay unless pinned, then — unless a pin fixes the CLI — the probe, the bench and the universal tail (`workflow.universal_fallback`, with `universal_fallback_exclude` applied to `Host.Discover`). For a request with no phase it is `bridgechain.DefaultPlanResolver`: no pin, `CallerCLI` leading, probe, bench, tail. `leadWith` is that resolver's helper, moved here; L1b deletes the original.
- **Imports.** `policy`, `profiles`, `phasespec`, `phasecontract`, `llmroute` and `envchain`. Never `core` or `bridge`: the bench and the tool-capability check arrive as seams, so the runner and the bridge chain can import this package.

## Compile findings

| Key | Severity | When |
|---|---|---|
| `cli_routing.clis` | error | an unknown family or driver; a driver that is not tool-capable; `claude` missing |
| `cli_routing.default`, `cli_routing.work.<role>`, `cli_routing.agents.<key>` | error | an empty chain; an unknown family or driver |
| `cli_routing.work.<role>` | error | a role other than plan, build, evaluate or control |
| `cli_routing.agents.<key>` | error | the key is neither a tracked profile nor a catalog phase; two keys name one agent; an entry outside the agent's allowed set (reported instead of the empty-chain finding for that selection) |
| `cli_routing.agents.<key>.model` | error | not one of fast, balanced, deep, top |
| `cli_routing.tiers.<tier>` | error | an unknown tier; an empty ceiling; an entry not in `clis`; a ceiling that excludes claude at a tier a floor agent runs at (its `agents.<agent>.model` when set, otherwise its default tier and its `model_tier_overrides` tiers) |
| `agent.<agent>.tier_ceiling` | error | a selection's static plan has no CLI the ceiling permits along a tier chain the configuration can produce (`CeilingError`); for example an agy-only chain with `after_chain: stop` for an agent whose envelope pins it to deep under `tiers.deep: [claude]` |
| `cli_routing.after_chain` | error | a value other than `other_clis` or `stop` |
| `agent.<agent>` | error | the agent's chain is empty after the allowed-set filter, for any selection `Resolve` can make: each role of its phases, and the no-role selection when a phase-less launch has no single role |
| `cross_family_with.<a>+<b>` | error, or warn | the two resolved primaries share a family: an error when `clis` has two or more families, a warning on a Claude-only install; a warning when only their fallbacks share a family |
| `pins`, `workflow.universal_fallback`, `workflow.universal_fallback_exclude`, `router.cli`, `router.model` | error | set together with the block (two sources); the message points to `evolve cli-routing migrate` |
| `profiles` | error | no profile source, or the list fails; in both modes, since an empty snapshot would silently route every agent as profile-less |
| `profiles.<agent>` | error | a listed profile does not load (declared mode) |

An unknown key inside the block, or a `null` block or agent rule, is not a finding: `policy.Load` refuses the file (strict decode, see internal-policy.md).

## The legacy golden

`go/internal/cliroute/testdata/legacy-plans.golden.jsonl` pins today's dispatch plans: every tracked profile (92 on 2026-10-05) × eleven variants (no env, `EVOLVE_CLI`, `EVOLVE_<AGENT>_CLI`, a phase pin with a CLI and model, a model-only pin, the advisor overlay, a benched family, a missing binary, a caller CLI, the checked-in `universal_fallback_exclude: []`, and `--bypass-policy` over a policy that has both pins and that workflow) × the two resolvers, 2024 records. The `bypass` variant records today's meaning of bypass: the runner ignores the pins but keeps the workflow's universal tail, so this package projects bypass as `Compile(policy.Policy{Workflow: loaded.Workflow}, …)` (L1b decision 1). `internal/cliroute/cliroutetest` holds the variants and the record format.

- **Generated through today's entry points.** `TestLegacyDispatchPlans_MatchTheGolden` (in `internal/phases/runner`) calls the runner's `resolveDispatchPlan` and `bridgechain.DefaultPlanResolver`, with fake binaries on `PATH` (the runner probes through `exec.LookPath`), a fake `LookPath` and discovery for the bridge chain, a real CLI-health store with a fixed clock, and policy files written per variant.
- **Driven through this package too.** `TestResolve_AbsentTableMatchesLegacyGolden` resolves the same matrix through `Compile` + `Resolve` and compares the bytes, so the legacy projection equals the golden.
- **Regenerate** with `cd go && go test -count=1 ./internal/phases/runner -run TestLegacyDispatchPlans -update`. A tracked profile edit changes the golden, so the commit that edits a profile regenerates it and the diff shows which plans moved.

## Invariants

- **No block, no change.** With `cli_routing` absent, `Resolve` returns the plan today's resolvers return, error text included. Pinned by `TestResolve_AbsentTableMatchesLegacyGolden`; a mutant that drops the family ban, the caller CLI or the advisor overlay fails it.
- **Deep and top never run on agy under the operator's table.** `TestResolve_DeepAndTopNeverRunOnAgy` walks every tracked profile, with and without a phase, at its own tier and with an advisor raise to deep and top, with every attempt walled, and finds no `agy-tmux@deep` or `agy-tmux@top`. A mutant that ignores the ceiling in `DispatchTiered` fails it, `TestResolve_BuilderBalancedOnAgyEscalatesToClaudeAtDeep` and `TestResolve_WalledClaudeAtDeepStepsDownNotToAgyDeep`.
- **The floor needs no config.** A floor agent's allowed set is `{claude}` whatever the profile allows, so neither a `default` chain nor the `after_chain` tail can hand it to another family (`TestResolve_TheOperatorTableKeepsTheFloorAgentsOnClaude`, `TestResolve_TheFloorHoldsEvenWhenTheProfileAllowsEveryFamily`).
- **A table with a defect never routes.** `New` refuses any table that carries an error-severity finding (`TestNew_RefusesATableWithAnErrorFinding`). Inside `Compile`, an invalid entry in `tiers.<tier>` is still left out without uncapping the tier, so the compiled ceiling is never wider than the operator wrote.
- **Every refusal `Resolve` can make is a `Compile` finding.** `TestCompile_EveryRefusalResolveCanMakeIsACompileFinding` resolves every tracked agent, with and without its phase, under four tables (one of them the round-2 probe, an agy-only chain with `stop` under a claude-only deep ceiling) and requires, for every refusal of any type, an error finding keyed to that agent: `agent.<agent>`, `agent.<agent>.tier_ceiling`, `profiles.<agent>` or the `cli_routing.agents.<key>` the operator wrote. It never matches on message text, so a finding about `spec-verifier` cannot count for `spec-verify` (`TestReportsAgent_MatchesKeysNeverMessages`). A mutant that skips the `Compile` ceiling check fails it. The reviewers' probes are pinned too: under `{default: [agy], work.*: [claude]}` the tester and the retrospective resolve one chain with or without a phase (`TestResolve_APhaselessLaunchOfASingleRoleAgentGetsItsPhasesChain`).
- **A floor agent's override tiers are checked.** `TestCompile_AFloorAgentsOverrideTierChecksTheCeiling` fails a mutant that drops the `model_tier_overrides` tiers from the floor check.
- **Coverage.** The package is enrolled in `.apicover-enforce` and in `.cover-strict` at 100%; `cliroutetest` is enrolled in `.apicover-enforce`, and its own tests pin the fixtures and a byte-for-byte read-and-encode round trip of the golden.

## Findings

- **2026-10-05, building the golden.** Today's resolvers let per-run and advisor inputs cross `allowed_clis`: the advisor overlay `{cli: agy, tier: deep}` puts `agy-tmux` first on the builder's chain although `builder.json` allows only claude and codex, and `EVOLVE_BUILDER_CLI=agy-tmux` does the same. The bridge-chain resolver ignores policy pins and the advisor overlay altogether. The declared mode refuses or ignores each of these; the legacy projection keeps them, by design, until L2.
- **2026-10-05, the operator's table needs the builder edit.** Compiled against the tracked profiles, `{clis: [agy, claude], default: [agy, claude], tiers: {deep: [claude], top: [claude]}}` reports `cross_family_with.auditor+builder` as an error: `builder.json` does not allow agy, so the builder's chain collapses onto claude, the auditor's family. With `allowed_clis` widened to agy (L2), only the accepted warning remains (the two share claude as a fallback). `TestCompile_TheOperatorTableCollapsesTheBuilderOntoTheAuditorWithoutTheL2BuilderEdit` pins both halves.
- **2026-10-05, review round 1.** The architecture review found four gaps, now closed and pinned by tests that fail on a mutant of each fix. A walk the ceiling empties reported itself walled although no wall was known. A phase-less launch could take a different chain from the same agent's phase launch with no `Compile` finding (the tester and the retrospective). `Resolve` re-read profiles and silently widened an unloadable one to every CLI. And a `null` block decoded as the legacy sources. The reviewers' probes and mutants are recorded in the plan's L1a landing notes.
- **2026-10-05, review round 2.** The re-review confirmed round 1 and found one more gap of the same class. Under `{clis: [agy, claude], default: [agy], tiers: {deep: [claude], top: [claude]}, after_chain: stop}`, `Resolve` refused `intent` (its envelope pins it to deep, so its tier chain is `[deep]` alone) while `Compile` reported nothing. Under L1b that table would have passed `check` and the start gate, then failed mid-cycle. The ceiling refusal is now the typed `CeilingError`, and `Compile` runs it on every selection's static plan.
