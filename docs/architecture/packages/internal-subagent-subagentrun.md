# internal/subagent/subagentrun

> The full design, boundary, signal contract, byte-identity guarantees, preserved quirks (Q1–Q11) and numbered tests live in [decomposition/16-subagentrun.md](../decomposition/16-subagentrun.md) (ADR-0103 unit 16). This page keeps the package-level facts that the code's comments carried and that page does not state.

## Purpose

`internal/subagent/subagentrun` is the `evolve subagent run` execution path as a leaf package. One `Dispatcher` admits the request, resolves the profile, cli, model tier and capability manifest, places the artifact, mints the challenge token, captures git provenance, composes and stages the prompt, calls the bridge exec port, judges the artifact on the one verification ladder and appends the `agent_subprocess` ledger record. `internal/subagent`'s `Run` is the facade over it.

## Design

- **Ports and options.** The ten host-backed ports in `Deps` are all required; a nil port is a programming error that panics at first use. The six stdlib-backed collaborators (clock, entropy, the stat/read/hash trio, the prompt stager, the ledger opener, the Signal Center accessor) default in `New` and are replaced by `With…` options. The leaf never writes stderr, never reads the environment and never shells git or tmux; `importgraph_test.go` pins its import allowlist.
- **The clock is read four times per run:** exec start, exec end, the verification instant and the ledger timestamp. The duration brackets only the adapter call (`TestExecute_DurationFromTwoClockReads`).
- **`WithFS` covers the artifact side only.** `os.Stat` on the workspace and `os.MkdirAll` on the artifact directory stay direct, since a tmp dir and a file in the way provoke both.
- **`WithSignals` takes an accessor, read at every use.** A nil accessor, or one that returns nil, is the Null Object; `SignalsWired` reports whether a root wired one.
- **One producer.** `warn` stamps every event as `bridge.warning` WARN under module `bridge`, origin `Dispatcher.Dispatch`, with the cycle, the full dispatched agent name as the phase (the value the ledger's `role` carries) and the run id resolved at admission. Every event carries the parsed `role`, the `worker` subtask when there is one, and the caller's `step`.
- **The bridge-only invariant has one chokepoint.** `enforceBridgeOnly` rejects the retired in-process escape hatch (`LEGACY_AGENT_DISPATCH`) during admission, before any resolution work. Single, fan-out and recursive dispatches all funnel through `Dispatch`, so one check covers all three.
- **The recursion bound is the host's.** A fan-out worker re-enters through `evolve subagent run`; `Deps.GuardDepth` applies the host's cap and returns the host's sentinel.
- **Worker names** follow `<role>-worker-<subtask>`: the role is lowercase letters and hyphens, the subtask starts with a letter and may carry digits and hyphens (`TestParseAgentName`). A worker's artifact goes to `<workspace>/workers/<agent>.md`; anything else expands the profile's `output_artifact` template.
- **`ResolveArtifactPath`** replaces `{cycle}` in the template, keeps an absolute result and joins a relative one under the project root. An empty template yields `""`.
- **The challenge token.** `ChallengeTokenOverride` pins the token instead of minting one: a fan-out worker is dispatched with the parent's token, so its artifact bears a token the parent can verify. `MintToken` returns 16 lowercase hex characters from `ChallengeTokenBytes` random bytes, and a short read is an error.
- **`Profile.Overrides` is a closure** over the profile body, because the adapter overrides depend on the cli, which is known only after resolution.
- **Resolution precedence.** The router's cli wins when it returns one, and its tier rides along; otherwise the profile's cli with source `profile`. Both paths canonicalise (`antigravity` → `agy`). The adaptive tier resolver (profile, mastery gate, diff complexity) runs only when the router returned no tier. The capability manifest is read under `CapabilityDir`, or `AdaptersDir` when that is unset; its warns ride the Warns channel and its flags feed the env and the ledger's `quality_tier`.
- **`QualityTier`** is `full` when both capability supports are true, `degraded` when both are false and `hybrid` otherwise (`TestQualityTier`).
- **The prompt** is the INVOCATION CONTEXT block (the label vocabulary the tokenusage scanner anchors on and `bedrock.go` documents) above the `--- BEGIN TASK PROMPT ---` envelope. When the role is `auditor` and adversarial audit is on, the adversarial framing constant is appended after it. The framing is the canonical source of the auditor's adversarial stance; its blocks are described in `skills/adversarial-testing/SKILL.md` §8, and it is a constant because it sits in the prompt-prefix cache window.
- **`AdapterEnv.Map`** renders the 16-key adapter env, plus `EVOLVE_PROJECT_ROOT` when a project root is known. `VALIDATE_ONLY` is always `"0"` on this path, `BoolEnv` renders booleans as `"true"`/`"false"`, and `AdapterPath` (the vestigial `<AdaptersDir>/<cli>.sh`) never enters the map.
- **The production stager** writes the prompt to an `os.CreateTemp` file named `evolve-subagent-prompt-*.txt` and removes it after the exec. `stageFault` names the failing call (`create` or `write`) for the signal while the error text stays the run's own.
- **One verification ladder.** `VerifyArtifact` is the single answer to "is this dispatched agent's artifact valid?" for every dispatch path. `evolve subagent check-token` is a separate, lighter exists-and-token probe, not a dispatch verdict. `Verify` is pure: `VerifyArtifact` gathers the stat and, only when the stat succeeds, the body, then judges them against `ArtifactMaxAge` with the clock passed in.
- **The ladder order is** stat → freshness → readable → non-empty → token → exec status. The four integrity rungs take precedence over the exec status: a clean exit over a stale, empty or tokenless artifact is `INTEGRITY_FAIL`, and a sound artifact with a non-zero exit or an exec error is `FAIL`. An exec error adds a leading `bridge launch failed` diagnostic but never short-circuits the ladder. An artifact is stale when its age exceeds `ArtifactMaxAge` (five minutes). The diagnostic wording is the bash `verify_artifact()` wording (`TestVerify_LadderAndTypedRung`, `TestVerify_DiagnosticOrdering`).
- **The ledger line** keeps the retired bash writer's field order, because the chain hash depends on the exact bytes. `JSONStringEscape` escapes only backslash, quote, `\n`, `\r` and `\t`, which keeps every entry one JSONL line. `ChainLink` returns the zero seed and sequence 0 for an absent or empty ledger, otherwise the sha256 of the last line and the line count.
- **`appendLedger` returns every error bare**, and the failing call (`mkdir`, `chain_link`, `open`, `write`, `close`, `tip_tmp`, `tip_rename`) rides the signal's `op` field, never the text. The tip `<seq>:<sha256(line)>` is written through a `.tmp` file and a rename, after the line.

## Invariants

- **The run id is passed to `fmt.Sprintf` as an argument, never spliced into the format.** `fmt` rescans the format string for verbs but not its arguments, so a `%` inside a spliced run id would consume the next argument and silently shift every later field. An empty run id omits the key. Pinned by `TestLedger_LineGoldenChainAndRunID`.
- **The ledger line never carries `worktree_tree_sha`.** `internal/releasepreflight` reads the key's absence as "a manual release audit, not a cycle audit" when it scopes an audit's veto. Pinned by `TestLedger_NeverCarriesWorktreeTreeSHA`.
- **`EVOLVE_PROJECT_ROOT` is never exported empty.** An unset variable falls back to the cwd by the subprocess contract, and an empty one would not. Headless drivers inherit it through their env; the tmux drivers export it into the pane shell themselves. Pinned by `TestEnv_MapIsGoldenAndOmitsProjectRootWhenEmpty`.
- **The project-root worktree fallback is deliberate and loud.** A non-worktree dispatch has no lane worktree and must still run, but a fleet lane never wants it: an orchestrator that forgot to propagate `WorktreePath` points the agent at the main tree, the shape the tree-diff guard kills a lane for. The fallback keeps its Warns sentence and emits `BRIDGE_SUBAGENT_WORKTREE_FALLBACK`. Pinned by `TestEnv_WorktreeFallbackKeepsTheWarnsEntryAndEmitsTheCode`.
- **A rejected request never becomes a run.** No port is consulted after a rejection and the run id is never resolved. On admission the run id is read once, after the depth guard, as the gate's last act. Pinned by `TestAdmit_RejectsInOrderWithReasonClass` and `TestAdmit_ReturnsTheIdentityCompleteAsTheGatesLastAct`.
- **One outcome signal per non-PASS run, emitted before the ledger append,** so a ledger failure never hides an adapter failure on the stream. The error-return order is unchanged: a ledger error masks the exec error. Pinned by `TestRecord_ExecErrorWritesTheLedgerThenReturnsWithOneOutcomeSignal` and `TestRecord_LedgerWriteErrorMasksExecErrorAndNamesTheOp`.
- **A hash failure is signalled only when the artifact stood the ladder** (PASS or FAIL); on `INTEGRITY_FAIL` the rung already names the artifact fault (`TestRecord_HashFailedOnlyWhenTheArtifactStood`).
- **The host's default adapter returns exit -1 on an infrastructure error,** so an "exit 0 plus an error" never reaches the ladder as a clean exit (`TestExecAdapterDepsWith_CarriesTheCenter` in `internal/subagent`).
- **Clean-code limits are a test:** every function under 50 lines, nesting at most 4, every file under 800 lines (`TestLimits_FunctionsFilesAndNestingStayWithinTheBar`; a comment inside a function counts toward its length).

## Findings

- The request shapes (`Request`, `Outcome`, `TierRequest`) are built positionally in `TestRequestShapes_HaveExactlyTheDeclaredFields`, so a new field breaks that test at compile time and forces the host's one projection to be revisited.
