# internal/recovery

> Decision record: [ADR-0044](../adr/0044-unified-phase-recovery-protocol.md). Full design and the cycle-262 post-mortem: [phase-recovery.md](../phase-recovery.md). This page keeps the package-level detail those two do not.

## Purpose

`internal/recovery` owns the decisions of the Phase Recovery Pipeline. It holds the outcome envelope every phase dispatch records (`PhaseOutcome`), the deterministic fatal-pane registry (`FatalPaneDetector`), the recovery chain that turns a classified terminal state into an action (`Recover`), the observer's stall-policy port (`StallPolicy`), the loop that promotes an LLM diagnosis into a registry entry (`PromoteAdvice`), and the pane treatment that both registry consumers apply before matching (`StripAgentContent`).

## Design

- **Leaf package.** `core` and `phases/runner` both import it, so it imports neither of them, nor `bridge`. Its internal dependencies are `cyclestate` (a zero-dependency leaf that supplies the `TokenUsage` and `Diagnostic` value types) and `atomicwrite`. Phase names and verdicts cross as plain strings. `core` owns the verdict vocabulary and the never-invent-PASS rule (`core.phaseOutcomeFrom`), so this package carries no verdict constants that could drift.
- **Classify before handling.** Every decision is made on a typed `TerminalCause`, never on a raw exit code or on untyped pane text.
- **Substring signatures, not regexes.** A substring check keeps the hot-loop scan cheap, and an advisor-diagnosed signature promotes as a plain string.
- **Chain of Responsibility.** `Recover` follows the shape of `internal/router/recovery.go`: ordered handlers, the first match wins, and a terminal handler catches everything else. It only decides. The caller (the observer policy, the orchestrator's failure hook) acts under its own stage gate (`EVOLVE_PHASE_RECOVERY`). The chain order carries meaning:
  1. `integrity-escalate`: an integrity-adjacent state never auto-recovers (ADR-0044 locked decision).
  2. `process-dead-kill`: sits above `busy-extend` because a dead process can render busy-looking chrome forever. Pane echo is not proof of liveness.
  3. `busy-extend`: a visibly working agent is never killed, even when its scrollback contains a fatal signature.
  4. `known-fatal-kill`: a cause the registry classified kills at once, with zero LLM tokens. The runner's exit-81 fallback chain owns the fresh dispatch.
  5. `stall-budget-extend`: an unclassified stall within the extension budget waits, because the agent may be deep in thought. The budget comparison is strict (`Attempts < MaxAttempts`).
  6. `unknown-advise`: only the unclassified residue reaches the LLM failure-advisor, and its verdict is then promoted so the next occurrence is caught by `known-fatal-kill`.
- **Observer adapter.** `NewChainStallPolicy` adapts the chain to the observer's `StallPolicy` port. The observer subprocess cannot dispatch an advisor, so `advise` degrades to `escalate` there. The observer calls `Decide` on every tick rather than once per stall, so attempts are derived as elapsed idle seconds divided by the threshold. A budget of zero or less defaults to 6.
- **Stall policy as a Strategy.** `StallPolicy` is injected at the observer's two INCIDENT emit sites, which keeps the observer pure detection. A nil policy keeps the legacy enforce branch unchanged.
- **Reflexion-style promotion.** A novel pane state that the advisor classifies once becomes a registry entry: appended in memory for the running batch, and written to `.evolve/instincts/fatal-signatures/<id>.yaml` for every later boot (`SeedDetectorWithPromotions` replays them). The file is a fixed-key YAML subset that this package writes and parses itself, so it takes no YAML dependency. The id is a short content hash of the substring, so re-promoting the same signature targets the same file.
- **One pane treatment for both consumers.** `bridge.fatalPaneVerdict` (stop-review fast-fail) and `core.adviseOnUnclassifiedFailure` (the advise-and-promote hook) both call `StripAgentContent` before `Detect`. It lives beside the registry so the two consumers cannot drift apart. Its rules deliberately differ from the exhaustion-scan stripper (`bridge.strippedForExhaustionScan`), which deletes lines and has no protect list.

## Invariants

- **One outcome record per terminal disposition.** Every terminal path of a phase dispatch records exactly one `PhaseOutcome` through the orchestrator chokepoint `recordPhaseOutcome`. Spend (cost, duration, boot time, tokens) is recorded even on abort, so burned tokens are always accounted for.
- **An abort never rewrites the verdict.** `Verdict` stays the agent's own. `AbortReason` is additive. It is also set when a recovery path records the transient it recovered from and then continues, so a non-empty `AbortReason` does not prove the cycle died there. `core.backfillFailReasons` relies on that distinction.
- **Two clocks.** `DurationMS` is the runner's self-reported compute. The `StartedAt`→`EndedAt` span is the wall clock the orchestrator observed. The gap between them is the surrounding review and guard work, and it is a signal in its own right.
- **Archetype has one source.** `Archetype` is stamped at the chokepoint from the phasespec taxonomy, so latency roll-ups bucket cycle time without keeping a second list.
- **Diagnostics are relayed unfiltered.** The outcome record is the only durable home a non-floor phase's FAIL reason has. Consumers filter by severity.
- **Detection is side-effect-free and always on.** Acting on a classification is the caller's stage-gated decision. Three defenses bound the risk of killing a healthy agent whose pane happens to mention a signature: the detector is consulted only at a stop-review checkpoint (the artifact is already missing); a Busy pane skips fatal handling; and the kill itself is staged, shipping in shadow (log-only) first.
- **First match wins, seeds first.** Entries are ordered most specific first. Promotions append after the seeds, so a promotion can never shadow a vetted seed.
- **`Promote` is not concurrency-safe.** Each tmux launch builds its own detector today. A detector shared across goroutines would need a fresh instance after promotion, or a mutex.
- **`Signatures()` reads the live registry.** A caller that builds a protect list from it never works from a hand-copied literal that goes stale when a signature is promoted. Empty substrings are omitted, because a `Contains`-keyed consumer would match them on every line.
- **The colon in `": command not found"` is load-bearing.** It is the shell's own error rendering (zsh mid-line, `zsh: command not found: X`; bash at line end, `bash: X: command not found`). The bare phrase can appear in a healthy agent's debugging output.
- **Continuation-prompt seeds are newline-anchored.** `"\nquote>"`, `"\nbquote>"`, `"\ndquote>"` and `"\nheredoc>"` match only at a line start. The anchor is the only defense against a bare-word false positive. Matching is case-sensitive.
- **Known accepted limit.** A substring seed cannot tell a line-leading `dquote> …` in quoted prose from a real continuation prompt. Production stays safe because the seed is paired with the authoritative process-liveness check (`process_dead`), and because a real continuation prompt renders with nothing after it on the cursor line.
- **`PromoteAdvice` is the trust boundary.** The cause must be in the typed vocabulary (`CauseUnknown` is excluded, since promoting "unknown" is noise). The substring must be at least 12 characters, because a shorter one matches healthy output and would make a kill trigger too cheap to hit. The substring must not contain a neutralization artifact (`[REDACTED]`, `[untrusted]`, `'''`): the advisor reads the neutralized pane digest ([ADR-0045](../adr/0045-corrective-interaction-protocol.md) I5), but `Detect` matches the raw pane, so such a signature could never fire. Rejection returns an error and the caller escalates.
- **Promoted confidence is 0.5.** That is below the ≥0.9 of LLM-authored lessons and equal to faillearn's confidence for deterministic artifacts, so corpus consumers can weight promotions accordingly.
- **Durable writes are absent-only and atomic.** An existing file, possibly operator-edited, always wins. The write goes through `atomicwrite`, whose per-call unique temp file keeps concurrent writers of the same content-addressed path from colliding ([ADR-0049](../adr/0049-concurrent-multi-cycle-execution.md) N14). Under fleet mode the whole-cycle project lock is skipped, so these promotions genuinely overlap.
- **Loading is best-effort.** An absent directory or a corrupt file yields whatever is loadable, so a bad promotion never stops a boot. The write side is strict.
- **`StallPolicy.Decide` call contract.** It fires on every observer poll tick for as long as the stall holds, from one goroutine per observer. An implementation shared across observers must be concurrency-safe, and one that keeps state must expect rapid repeated calls per incident. Implementations are side-effect-free.
- **`StripAgentContent` rules:**
  - *D1*: a matched line is blanked in place (its newline kept), never deleted. Deleting the line above a continuation prompt would strip that prompt's leading `"\n"` and silently disable the dead-shell fast-fail.
  - *D2*: a line carrying any protected signature is exempt from the echo half. Echo stripping is substring-keyed and two seeds are ordinary English sentences, so a prompt that quotes a seed would otherwise make the CLI's real banner look like an echo. Callers pass `det.Signatures()`, so the protect list comes from the live registry.
  - The diff half is not protected: a diff prefix proves the agent wrote the line, and suppressing agent-written seed text is the point.
  - A diff line is an optional line number separated by whitespace, then `+` or `-`. `+++` and `---` file headers pass through, and a bare `72+` is arithmetic in prose, not a diff marker.
  - An empty or whitespace-only prompt strips no echoes (fail-open: never suppress a genuine signal for lack of context). The advise hook passes `""` on purpose, since D2 already neutralizes the echo half for a fatal-pane scan.
  - Blank protected entries are ignored, because they would protect every line.
  - `strip.go` imports only `strings`. `go/acs/cycle1123` mutates `StripAgentContent` through `go test -overlay`, and an import used only by that function would make the mutant fail to compile, turning a mutation verdict into a build error. The function name, parameter names and file path are part of that contract.

## Findings

- **cycle-262** (2026-06-09): the motivating incident. A build whose CLI fallback succeeded was recorded as if it never ran, and about 40 minutes of a 52-minute cycle went into waiting out the `maxExtends` backstop on three self-describing fatal panes. It produced the outcome envelope and the first three seeds (invalid model, codex self-update, `: command not found`). See [phase-recovery.md §2](../phase-recovery.md).
- **cycles 274/277** (R3.3, R3.4): the codex update menu swallowed the injected prompt and spilled it into zsh, leaving continuation prompts. That added the `quote>`/`bquote>` seeds (274) and the `dquote>`/`heredoc>` variants from the 274/277 transcripts. A wedged shell echoing prompt lookalikes read as busy for more than 25 minutes after the CLI was gone, which placed `process-dead-kill` above `busy-extend`.
- **ADR-0049 N14**: concurrent fleet cycles promoting the same novel pane shared a `path + ".tmp"` temp file. The loser's rename hit ENOENT (a lost promotion), and a partial write could tear the entry every later boot replays. Routing the write through `atomicwrite` fixed it; `TestPromoteSignature_ConcurrentSameSubstr_NoTornWriteOrLostError` is the regression.
- **cycle-1117**: an agent editing the registry had its own diff view (`+ Substr: "There's an issue with the selected model"`) classified as a fatal pane and was fast-failed on its own work. The fix stripped agent content in the bridge only.
- **cycle-1123**: the second consumer, `core.adviseOnUnclassifiedFailure`, still matched the raw pane. There the defect inverts into a false skip: agent text makes a genuinely novel wedge look already classified, so the advisor is never consulted, nothing is promoted, and every recurrence burns the ~20-minute backstop again. The two seams had drifted for six cycles. `StripAgentContent` became the single source for both, pinned by `strip_c1123_test.go` and the `go/acs/cycle1123` mutation predicates.
- **cycle-1115**: the auditor rejected reusing `bridge.strippedForExhaustionScan` for the fatal-pane scan, because it deletes lines (breaking D1) and has no protect list (breaking D2).
- **cycle-314** established diff prefixing as proof of agent authorship. **cycles 641/642** showed a prompt quoting a seed silencing that seed's real banner, which motivated D2.
