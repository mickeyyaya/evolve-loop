## Purpose

`internal/inboxbatch` is the inbox item model and the deterministic half of task selection. It loads and sanitizes `.evolve/inbox/*.json` records, groups them into batches that one cycle can carry (`Classify`), renders the batches for the triage prompt, decides which items are console-routed (operator-owned), and owns the `processing/cycle-<N>` claim layout. Grouping follows mechanical signals, so it lives in Go. Choosing a batch stays the triage LLM's judgment.

## Design

- **Why batch.** Consuming one item per cycle pays the full scout, triage, tdd, build, audit and ship overhead for each item. A batch spreads that cost over items that share a campaign or a package area.
- **Rules as a Strategy, clusters by union-find.** Each `Rule` emits `Edge`s, and each edge carries its own human-readable `Reason`, so the interface has one method and no name accessor. `Classify` unions every rule's edges (`clusterByRules`), orders each cluster's members by the injected rank (`rankOrder`), splits it at `MaxItems` (`chunkCluster`), and ranks the clusters by their best-ranked member. Classify is split into those helpers so each stays under 50 lines. A new signal is a new `Rule` passed through `Config.Rules`; no classifier change is needed.
- **The default rule set is `campaignRule` and `fileAreaRule`.** The order is presentation only, since edges union. `ConnectsRule` is exported for opt-in only: `connects_to` is prose navigation (the inbox house style is to link liberally), and entries resolve when they begin with a known id. `root_cause` is never a rule (see Findings). `ConnectsRule` has no production caller: the triage prompt classifies with the default rules (its `Config` sets only `Order`), so its `inbox_batches` line names only campaign and file-area, the signals it actually applied (pinned by `go/acs/cycle1724` 004). A `depRule`/dep-topological ordering pair existed through cycle-1723 but was removed in cycle-1724: under ADR-0106 W3 `dependency_blocked` routing, a dependent is never offered in the same lane menu as its unlanded dependency, so grouping or ordering a batch around a live `Deps` edge could no longer reach production dispatch — it ran only in tests. `Item.Deps` itself is unrelated to this package's dead removal and stays live: `internal/inboxmover`'s dispatch-state and dispatchability checks still read it directly for W3 routing.
- **File areas.** An area is a file's directory, capped at `areaDepth` (3) segments, so `go/internal/router/sub` groups with `go/internal/router`. A path ending in `/` names a directory and is its own area. Two discriminative bounds apply. The ceiling `hubAreaMaxItems` (5) drops an area that more items share than that, on the inverse-document-frequency idea: `go/internal/core` appears in half the backlog and says nothing. The floor `minAreaDepth` (2) drops a single top-level directory (`agents`, `skills`, `go`), which is a bag of unrelated files rather than a unit of work. Shallow areas slip under the ceiling, so the ceiling alone never caught them.
- **Campaign is a partition, not a signal.** The operator's `campaign` field declares one initiative. An inferred edge (file area, connects) never merges two distinct non-empty campaigns. `campaignOfRoot` tracks each root's campaign claim, so the guard holds transitively: a campaign-less item may join one campaign's cluster but can never bridge two. When two clusters merge and the merged root's claim is empty, one side was empty, so `ca + cb` is the other side's claim.
- **The order is injected, once.** `Config.Order func([]Item) []Item` is the seam through which the caller supplies the inbox rank, because this package cannot import `internal/inboxrank` (the rank imports this package). `rankPositions` calls it exactly once, over a copy of every item, and turns the result into one position per item keyed by `Item.Key()` (an `ItemKey{ID, Path}`, the one identity key `inboxrank.Sequence` and `Labels` use too; the review's NIT replaced two private copies), so two items sharing an id keep distinct places; scoring never runs per cluster, so it never goes O(N²). An item the order omits follows every ranked item, in input order, and is never lost. With no `Order`, the position is the caller's order: `Classify` never ranks by weight itself (the source scan in `internal/inboxrank` bans any weight sort outside the rank). The triage prompt and `evolve inbox batches` pass `inboxrank.Sequence` of one `Inputs.Order` run (ADR-0121, plan P2, 2026-10-06). Pinned by `TestClassify_RunsTheOrderSeamOnceOverEveryItem`, `TestClassify_WithoutAnOrderKeepsTheCallersOrder`, `TestClassify_AnItemTheOrderDropsFollowsEveryRankedItem` and `TestClassify_SameIDItemsKeepDistinctPlacesThroughTheOrder`.
- **Clusters rank as units.** Whole clusters, not chunks, sort by their best-ranked member (the maximum member score), members keep the rank order, and each cluster's chunks stay adjacent and predecessor-first, so a continuation always follows its predecessor. The note "run the previous batch first" therefore always points at the line above. Pinned by `TestClassify_ClustersRankByTheirBestRankedMember`.
- **A batch carries no weight** (since P2, 2026-10-06). Until then `Batch.Weight` was the maximum member weight, rendered in the batch line. In a ranked menu it read as the priority while the weight is only one input of the score, so it was removed; each item's score is rendered instead (see Rendering).
- **`DefaultMaxItems` is 4.** That is the most a single cycle's tdd, build and audit carry without entering the triage capacity clamp's overpacking range. Policy may override it per project. `UnifiedCommitment.Size` uses the same cap to call a commitment `small` or `large`.
- **Rendering.** `RenderMarkdown(batches, label)` writes one line per batch, `- batch N (<binding reasons>)[ (continuation …)]: id, id`, which is enough for triage to select a whole batch as `top_n`, and, when `label` is non-nil, one `  - <id>: <label>` sub-line per member. The triage prompt and `evolve inbox batches` label with `inboxrank.Labels` (`score 0.4475, top factor base`). The labels go on sub-lines, not into the batch line, so the batch line keeps the `…: id, id` tail that existing readers parse by its last `": "` (`go/acs/cycle1724` 004, `go/acs/cycle1678`). Pinned by `TestRenderMarkdown_LabelsEachItemOnItsOwnLineBelowTheBatch`. At most `maxRenderedReasons` (3) reasons render, followed by `+N more`, because the output is a prompt section rather than a forensic dump. Empty input renders the empty string, which keeps the triage prompt byte-identical.
- **Tolerant decoding.** Inbox records are a mix of hand-written and agent-filed JSON, so an absent field zero-values rather than erroring. `LoadDir` sorts by id. A missing directory is an empty inbox. A malformed file is skipped with a warning that names it (fail-open, but never silent). `ScanDir` is the one loader and `LoadDir` its text projection, in the same order: each `LoadWarning` is either unreadable (a file it could not read or parse, so its item is missing) or a notice about a readable item that is included (a sanitized field, a duplicate id). A caller that must fail closed on missing data asks `DirScan.HasUnreadable`, never the warning count (`TestDirScan_ANoticeAboutAReadableItemIsNotUnreadable`, `TestLoadWarning_AFileItCannotParseIsUnreadable`, `TestLoadDir_WarnsExactlyAsScanDirDoes`); a path it cannot list is an error, never an empty inbox (`TestScanDir_ADirectoryItCannotListIsAnError`). Non-JSON files are ignored, because the inbox holds notes and subdirectories. `LoadFile` loads one record with the same treatment, and falls back to the filename stem for a missing id, since the filename is unique by construction.
- **No production code calls `LoadDir` (2026-10-21).** Each loader names a skipped file.
  - Five sites read `ScanDir`: the wave seed, the lane scope, the retry-tier claim ids and the two loads of the unified commitment.
  - Each site names an unreadable file on its own channel, or refuses on `HasUnreadable`.
  - `TestNoProductionCodeCallsLoadDir` parses each non-test file of the module and fails on any call of `LoadDir`, whose text projection loses the unreadable flag. Tests can still call it.
- **One item identity** ([W5](../logic-first-delivery-design.md), 2026-10-20). `ItemID(recorded, path)` is the one rule for the id of an item. It takes the recorded id, else the filename stem, and then applies the loader's sanitizer. Thus an item without a recorded `id` takes its file name (`TestLoadFile_GivesAnIDLessItemItsFileName`). A reader that decodes the id alone calls it, for example `lifecycle.readID` and the consumed-record reader of `ConsumedRecords` (`TestConsumedRecords_KeysEachRecordByTheLoadersID`). Thus the lane menu, the planner's backlog and the lifecycle give an item the same id (`TestItemID_IsTheLoadersID`, and `TestInboxReaders_GiveEachItemOneID` in `internal/triagecap`).
  - Every reader that decodes an item id itself calls `ItemID` (2026-10-20, after an independent review of PR #1036). The continuation readers `itemIDAt` and `resolveClaim`, `evolve inbox consume`, the recurrence engine's `findItem` and `kbgraph` do so. The triage-tdd handoff finds an item with `inboxmover.Locate`, not by its file name.
  - `TestInboxItemIDReaders_ResolveTheIDThroughInboxbatchItemID` in `internal/guards` pins the class. It parses every non-test Go file and fails on a function that decodes a local struct with a `json:"id"` field and does not call `ItemID`. A function that reads another document, such as the triage decision, is listed with that document. A decode into a package-level type is outside the reach of the guard.
- **A numeric priority is the weight (2026-10-20).** `priority` is free text, but every author who wrote a number meant the weight. A number there failed the whole decode, so seven items were absent from the queue for a month. `Item.UnmarshalJSON` now reads a number in `priority` as an absent weight and keeps a declared weight, and `LoadFile` notes the move. A `priority` of another type is still an error. Pinned by `TestLoadFile_ANumericPriorityIsReadAsTheWeight`, `TestLoadFile_ANumericPriorityNeverOverridesAWeight` and `TestLoadFile_APriorityOfAnotherTypeIsAnError`.
- **A number outside 0..1 is not a weight.** The rank clamps a weight above 1 to the top, so `2` meant as P2 jumps the queue. Such a number is not read: the item loads with no weight and a WARN that names it (`TestLoadFile_ANumericPriorityOutsideTheWeightRangeIsNotAWeight`).
- **One wording for each warning.** `LoadWarning.String` gives `WARN skipped <text>` for an unreadable file and `WARN <text>` for a notice about an included item. The inbox verbs, `evolve wave supply` and the dashboard queue print it, so no surface calls an included item skipped (`TestLoadWarning_StringSaysSkippedOnlyForAnUnreadableFile`, `TestWaveSupply_ASkippedInboxFileReachesTheOperatorAsAWarning`, `TestReadQueue_OnlyAnUnreadableFileIsCalledSkipped`).
- **A resurrected item is skipped and named.** `ScanDir` reads the `consumed/` directory beside the scanned directory, with its `cycle-<N>` subdirectories, through `ConsumedRecords`. A scanned file that is a copy of a retired item (same id and `created_at`) leaves `Items`. A later `created_at` under the same id is a new occurrence and loads, because console filings reuse stable ids. When either side has no `created_at`, an exact file-name match decides. One notice goes to `Warnings`: `skipped resurrected item <id>, a copy of a retired item (consumed at <at> via <via>, record <file>) — remove the file`.
- **Every consumer reads the item set through `ScanDir`.** So none can offer a copy again. The loader never deletes the file, and the operator removes it.
- **`RecoverOrphans` applies the same copy rule.** `Mover.RecoverOrphans` leaves an exact copy of a retired item in `processing/` and names it. A claim with a later `created_at` recovers as usual.
- **Retirement records are read in sorted path order.** `ConsumedRecords` keeps every record of an id, and the first matching record gives the `at`, `via` and file, so the skip is one. A record with no `consumed` stamp reports `unknown`. A directory without a `consumed/` subdirectory, such as a `processing/cycle-<N>` claim, is not filtered. Pinned by `TestScanDir_ResurrectedConsumedItem`, `TestScanDir_ResurrectedFileIsNeverDeleted` and `TestConsumedRecords_KeepsEveryRecordPerIDInSortedPathOrder`, `TestCopyOf_MatchesOnCreatedAtElseOnFileName` and `TestScanDir_SixteenConsumedRecordsDoNotHideALaterFiling`.
- **Prompt-surface sanitization.** `id`, `title`, `campaign`, `route`, `deliverable_kind`, every `files[]` entry and every `acceptance[]` criterion reach LLM prompts (the batch render, edge reasons, the Task Contract block). Control characters become a single space, never a newline, so a batch stays one line. Fields are bounded at `maxFieldLen` (160 bytes), which fits every legitimate id; an acceptance criterion is bounded at `maxAcceptanceLen` (600 bytes), since real criteria run 150 to 400 characters and the bound stops an item from smuggling in a page of instructions. Any change produces one notice per record that names each kind apart: `sanitized control characters in <fields>` and `truncated overlength <fields> to bound (item loaded)`. The item still loads in both cases, so `evolve inbox batches|list|rank|show` and `evolve inbox quarantine list` print `WARN skipped` only for an unreadable `LoadWarning` and a bare `WARN` for a notice (`TestLoadFile_NoticeNamesTruncationApartFromControlCharacters`, `go/acs/cycle1837` 001-003). `SanitizedFields` runs the same rule on a copy and names the fields it would rewrite, so the filing verb refuses an item the loader would have to rewrite instead of repeating the bounds (`TestSanitizedFields_NamesEveryFieldTheLoaderWouldRewrite`, `TestSanitizedFields_NamesEachFieldOnceAndNeverRewritesItsArgument`). `FilenameStampLayout` is the one spelling of the inbox filename stamp, which `FiledAt` reads and the filing verb and `ciwatch`'s CI-red escalation write (colons are not filename-safe; `TestFilenameStampLayout_IsTheStampFiledAtReads`), and `IsConsoleRoute` is the one console-route rule `ConsoleRouted` applies (`TestIsConsoleRoute_IsTheRuleConsoleRoutedApplies`).
- **Item fields with downstream owners.** `Class` is the declared archetype that `IsOperatorState` keys on. `PriorityClass` is the `priority_class` of the item, the class that the inbox rank orders by ([ADR-0121](../adr/0121-inbox-priority-is-a-computed-rank.md)). It is different from `Class` and from the free-text `Priority`. `Route` and `InjectedBy` feed console routing. `Continuation` is for machines only, never goes into the triage prompt, and is validated at adoption.
- **Acceptance, kind and path.** `Acceptance` is the single source that the harness projects into the tdd, build and audit prompts. Thus the builder and the auditor grade against the same words. `DeliverableKind` is `code` by default, and the authoritative kind of the cycle is the one that triage declares. `Path` is the source file name, which `evolve inbox batches` shows. It never groups, but with the id it keys the place of an item in the injected order.
- **The priority-class rule.** `PriorityClassPosition` is the one membership rule for the class: its index in the class order of the policy, or -1. It uses `slices.Index`, so only an exact match is a member, and `CheckPriorityClass` validates with it, and `inboxrank` scores with it (`Facts.ClassPosition`). Thus validation and scoring cannot disagree (`TestPriorityClassPosition_IsTheOneMembershipRuleCheckPriorityClassJudgesBy`). The error `ErrUnknownPriorityClass` quotes the class with `%q`, so the text of an item never forges a line in a warning. `evolve inbox add` refuses with it, and `inboxrank.ClassWarnings` warns with it.
- **The class names.** The constants `ClassCorrectness` … `ClassSecurity` sit beside `CheckPriorityClass`. Every autofiler stamps one of them, so a writer cannot misspell a class. `TestClassNames_AreThePolicysCompiledClassOrder` requires them to be the compiled `class_order` of the policy, in order. The test is in this package, so apicover sees each constant named. The policy stays the owner of the vocabulary: a class rename there makes that test and the contract test of the autofilers fail.
- **One filing rule for the class.** `RequirePriorityClass` is the one rule that a filing names a class at all (`ErrNoPriorityClass` for a blank one). The three filing funnels call it instead of three sentinels: `dispositionrouter.StageIntent`, `retrofile.FileActions` and the inbox writer of faillearn (`TestRequirePriorityClass_RefusesOnlyABlankClass`). This is the dedupe from the engineering-craft audit. Membership in the order stays with `CheckPriorityClass`, which judges where the order is known (`evolve inbox add`, the warnings of the rank).
- **Mentions are derived at decode.** `Item.UnmarshalJSON` records the file paths the record's own author-written fields name. It runs at decode, not in one loader, because the claim floor and `LoadFile` each unmarshal records themselves (the wave seed decoded its own until P2, 2026-10-06, and now reads through `LoadDir`), and the console classifier must see the same surface from all of them. The walk reads decoded strings (so an escaped `\/` is still a slash) in sorted key order. It skips `surfaceAndProvenanceFields` (`files`, the declared surface, and `injected_by`) and every stamp in the field-owner table (`RoleOf(key).IsStamp()`: the loop's and the operator's, by exact key), because a stamp is verb-written text, never the item's own, and a reason or evidence naming a protected file must not route the item (`TestConsoleRouted_NoStampIsTheItemsText`, which also pins that an authored `routed_note` is read). Only file spellings count (a last segment with an extension after its first character); a directory mention is context, not surface. At most `maxMentions` (64) are kept, so a runaway record cannot make routing costly.
- **Declared surface.** `Item.DeclaredSurface` is the one home of "this item declares its fix surface": at least one path-shaped `files[]` token. Tokens split on whitespace, lose surrounding punctuation, and lose a trailing source locator (`:178`, `:178:5`, `:189,205,221`, `:10-20`, `#L10-L20`; a date-shaped suffix strips too). A path-shaped token is wholly slash-separated path characters, and not every segment is a single character. `TBD`, `N/A`, `w/o`, `()` and a bare `role.go` declare nothing. The console classifier judges exactly these tokens, so an annotation word such as the `go` in "(go test)" is never read as a directory.
- **Console routing.** `ConsoleRouted` is the one classifier the plan-time gate (`fleet.TodosFromTriage` through `RoutedResolver`), the triage prompt partition and `inboxmover.Claim` share. The precedence and the override clamp are ADR-0074's. `KindPipelineRepair` is the one symbol the ADR-0072 halt writer (`cmd_loop_escalation.go`) and the classifier share. A nil scope predicate disables only the derived surface rules; the route field and the kind still apply, for callers that cannot import `guards`.
- **`RoutedResolver`.** It loads the directory once; build one per wave so mid-batch inbox changes are seen. An unknown id is dispatchable, because scout-originated work has no inbox item. A load failure resolves every id as dispatchable, since a broken backlog must not stop the queue (ADR-0072). With duplicate ids the earliest-filed record wins, the same holder `ConnectsRule` and `UnifiedCommitment.Validate` resolve (one shared `indexByID` over `ScanDir`'s stable, filing-ordered ID sort). A routed item's own load warnings append to its reason as `INBOX_LOAD_WARNING: <warning>`, which the plan-time gate prints; they never change the routing decision (`go/acs/cycle1809` 004-010).
- **The operator-state archetype.** `IsOperatorState` recognizes a declared `pipeline-architecture` item whose every files[] entry declares only `.evolve/` paths, read through the same `declaredTokens` routing uses (`fileAreaRule` reads `DeclaredPaths` too, `go/acs/cycle1809` 011-013): a pure mutation of live runtime state with no build or audit surface, which can eventually be applied natively instead of paying for a worktree pipeline.
- **The claim layout lives here.** `layout.go` is the one home of the `processing/cycle-<N>` path. The writer (`inboxmover.Claim`), every reader (`inboxmover.Locate`, orphan recovery, dispatch state, failure counts, core's dispatch-time claim scan) and the parser derive it from here, so the gate that judges a claim reads the shape the claim wrote. It sits in this leaf because core cannot import inboxmover (the ledger adapter imports core). `CycleDir` and `CycleDirs` also serve the promoter's `processed/` and `rejected/` directories, so a respelling on one side cannot hide a retired item from the readers.
- **Unified commitments.** A `UnifiedCommitment` is triage's claim that several items close through one shared design. It is validated after mechanical classification and never changes the grouping rules. Callers that get a validation error fall back to the original independent selection.

## Invariants

- **`Classify` is deterministic for a deterministic order.** The campaign guard makes union outcomes depend on edge order (which cluster a campaign-less bridge joins depends on which edge unions first), and the campaign and file-area rules emit from map iteration. `sortedRuleEdges` therefore puts every edge in one canonical `(A, B, Reason)` order first, so determinism rests on the sorted edges. Positions are unique, so cluster ranking needs no tie-break. Pinned by `TestClassify_CampaignPartitionIsDeterministic`.
- **No batch spans two non-empty campaigns.** When two clusters merge, the merged root inherits whichever claim is non-empty; the guard has already ruled out two different non-empty claims, so this is correct for any choice of union root. Pinned by `TestClassify_TwoCampaignsSharingAreaNeverMerge` and `TestClassify_CampaignlessBridgeCannotFuseTwoCampaigns`.
- **Reasons follow the final root.** A later union can move a root, so every recorded reason list (`signalsByRoot`) is folded into the cluster's final root before rendering.
- **A later chunk is always flagged `DependsOnPrev`.** Chunks split a cluster in rank order, so every chunk after the first is a later piece of the same cluster and is flagged accordingly. Pinned by `TestClassify_OversizedClusterChunksInRankOrder`.
- **One order, no tie-break of its own.** Members and clusters both read the one position table `rankPositions` builds, so the two orderings cannot drift. Until P2 (2026-10-06) `weightDescThenID` played this part over the weight; it is deleted, and the rank's own tie-break (a declared surface, the older filing, the id) decides ties.
- **`DefaultRules` stays the two bounded structural rules.** A third default rule needs a discriminative bound (a ceiling or a floor) and an evaluation against real backlog data before it may default on. Pinned by `TestDefaultRules_DoesNotBindOnRootCauseProse`. `go/acs/cycle1205` mutates `rules.go` through `go test -overlay` by replacing the literal `return []Rule{campaignRule{}, fileAreaRule{}}`; that line's exact text is part of the predicate's contract. `go/acs/cycle1205` (001), `go/acs/cycle1206` (001) and `go/acs/cycle1633` (008) also pin the rule count, and `go/acs/cycle1724` (005) runs all three. `go/acs/cycle1206` (C1206-003) reads this notes file and requires `root_cause`, `failedApproaches[54]` and "zero edges", so the Findings bullet that holds them must keep them.
- **Sanitized fields never carry a newline.** Pinned by `TestLoadDir_SanitizesRenderedFields`.
- **One control-character rule for prompt-bound text.** `StripControl` maps C0 and DEL to spaces, never a newline: a newline in an id, a title or a commit subject would forge a new context line in the prompt that renders it. `cleanBounded` applies it and then the length bound. Pinned by `TestStripControl`.
- **A proven protected file binds like a declared one.** `protected_files` is the loop stamp that the cycle closeout writes when a tdd predicate reads a protected path. `protectedDerivation` judges `files` and `protected_files` together, so `route: lane` cannot relax a proven path. It is a loop stamp in `fieldowner.go` and not a `files` entry, because `sync-main` lands only stamp changes. On 2026-10-20 the closeout of cycle 2000 added `go/internal/core/cyclerun.go` to `files`, and `sync-main` blocked the boundary until #1008. Pinned by `TestConsoleRouted_AProtectedFileTheLoopProvedBindsLikeADeclaredOne`.
- **A proven protected file only grows.** The role of `protected_files` has the shape `grow-only-list` (`FieldRole.IsGrowOnly`). `inboxstamps.Classify` lands an added path as a stamp. `sync-main` refuses a removed path, as it refuses a curated change. The sanitizer cleans each entry as it cleans `files`. Pinned by `TestClassify_AProvenProtectedFileCanBeAddedButNeverRemovedAsAStamp` and `TestSanitizedFields_NamesAProvenProtectedFileWithAControlCharacter`.
- **A declared surface is only path-shaped tokens.** `declaredTokens` is the one token set the console classifier judges and `DeclaredSurface` and `DeclaredPaths` report, so an annotation word (`(go test)` yields `go`) is never read as a directory. Pinned by `TestConsoleRouted_AnnotationWordsAreNotSurface` and `TestItem_DeclaredPaths`.
- **One owner per item field** ([ADR-0116](../adr/0116-inbox-curation-verbs.md)). `fieldowner.go` is the one table of who writes each key of an item: the author at filing (every key it does not list), the curator (`evolve inbox edit`: `id` on an id-less item, `title`, `summary`, `fix`, `priority_class`, `weight`, `acceptance`, `files`, `deps`, `connects_to`, each with its value shape), the loop's mover (`route`, `routed_reason`, `routed_cycle`, `routed_at`, `failure_count`, `last_failure_reason`, `continuation`, `released_continuations`, `consumed`, `unbacked`, `retired_reason`, `retired_cycle`, `git_sha`), or the operator's `verify` (`premise_verified_at`, `premise_verified_sha`, `premise_verified_evidence`). Stamps are exact keys, never prefixes, so the table can be checked against its writers. Each stamp key is also an exported constant (`RouteField`, `RoutedReasonField`, …, `PremiseVerifiedEvidenceField`), and the table is keyed by those constants. Every writer spells a stamp only through its constant, so a new stamp key needs a new constant. `TestStampFieldConstants_NameEveryStampAndNothingElse` parses `fieldowner.go` and requires the `…Field` constants to name exactly the stamps, so a constant cannot exist outside the table. `TestStampFieldConstants_SpellTheKeysTheInboxHolds` pins each constant's spelling, because the keys are the on-disk format. A key that no constant names falls back to author. It lives here because this package owns the item schema (`Item`) and the lifecycle leaf imports it. The mention skip above, `add`'s and `edit`'s refusals and `IsMoverWritten` are projections of it (`RoleOf`, `FieldsOwnedBy`, `FieldRole.IsStamp`; `TestRoleOf_EveryItemFieldHasOneOwner`, `TestFieldsOwnedBy_ListsEachOwnersExactKeysSorted`). A loop stamp can also have the shape `counter` (`FieldRole.IsCounter`, now only `failure_count`): a monotonic count, which `ReleaseClaimKeeping` with `KeepRoot` must not lower (`TestFieldRole_IsCounterNamesOnlyTheMonotonicLoopCounters`). Moving the skip onto the table changed the placement of none of the 242 pending items. One writer outside the lifecycle still writes a curator field: the recurrence engine reweights items (`internal/recurrence/apply.go`); that is filed as a follow-up.
- **The failure record stamps.** The loop's mover also owns `last_failure_class` and `last_failure_fingerprint`. The failure drain writes them with `failure_count` ([retry-ladder.md §5](../retry-ladder.md#5-where-the-ladder-runs)). `TestStampFieldConstants_SpellTheKeysTheInboxHolds` pins their spelling.
- **`FiledAt` never guesses.** It reads `created_at` (RFC3339 or a bare date), else the file name's `2006-01-02T15-04-05Z` prefix (colons are not filename-safe), else returns zero. Triage's premise-drift check measures from it, so a guessed date would fake drift. Pinned by `TestItem_FiledAt`.
- **A duplicate id is kept but warned about.** Every resolver keeps the earliest-filed item with an id, but a later record with the same id is still unreachable by reference, so the operator is told. Pinned by `TestLoadDir_WarnsOnDuplicateID`.
- **Mentions only narrow.** A mention can move an item to the console but never widens lane authority, and it never binds: the text may merely cite the file. A declared surface wins over mentions. Pinned by `TestConsoleRouted_DeclaredSurfaceWinsOverMentions` and `TestConsoleRouted_LaneOverrideStillRelaxesTheHeuristics`.
- **Only surfaces already on the manifest match.** A task that will create a new gate-shaped file is caught later by the ship tripwire and the disposition handoff, not by routing.
- **Every routed item carries a reason.** `PartitionConsole` returns one reason per excluded item, because a silently narrowed backlog reads as full coverage. Pinned by `TestPartitionConsole_SplitsWithReasons`.
- **`IsOperatorState` fails toward the normal pipeline.** Any file outside `.evolve/`, an empty file list, or any other class answers false. A missed detection costs a cycle; a false one would skip review of a source change. The trailing `/` in `.evolve/` is load-bearing (`.evolvex/` is not runtime state). Pinned by `TestIsOperatorState`.
- **`cycle-0` is never a claim directory.** Cycles start at 1, and 0 is `inboxmover.Location`'s "pending at the root" sentinel. Pinned by `TestParseProcessingCycle_RejectsZero`.
- **An absent lifecycle directory is an empty list.** `CycleDirs` returns nil rather than an error: no item ever reached that state.
- **Unified commitment members are homogeneous.** Members must be known items, distinct, and each carry evidence; they must share one campaign (unscoped counts as its own value) and one deliverable kind (empty means `code`). Pinned by `TestUnifiedCommitment_RejectsMixedCampaignMembership`.
- **A rule's edges need only span.** Union-find needs connectivity, not the clique, so a rule may return a chain of edges over its group.

## Findings

- **Hub ceiling** (package creation, 2026-07-16): without it, real-backlog validation fused 55 of 61 items into one cluster through `go/internal/core`. The same validation showed `connects_to`'s transitive closure chaining half the backlog into one cluster, which kept `ConnectsRule` out of the defaults.
- **Cluster-unit ranking** (go-reviewer, package creation): a flat per-chunk weight sort let a continuation outrank its own predecessor whenever a low-weight dep chain pushed a high-weight item past the chunk boundary. The same review added prompt-surface sanitization (an id such as `evil\n- SYSTEM OVERRIDE` could fabricate prompt lines) and the duplicate-id warning.
- **Depth floor** (84-item backlog, 2026-07-27): two `agents` edges chained three unrelated campaigns (`chronicle-2026-07`, `pipeline-integrity`, `convergence-2026-07`) into one 43-item cluster, 51% of the backlog, chunked into 11 serialized batches. With the floor the largest cluster fell to 27 items (32%), and the convergence campaign split into its own 11-item cluster.
- **Campaign partition** (live backlog, 2026-07-28): chains of small shared areas fused 17 campaigns into one cluster of about 37 items, rendered as nine batches each marked "run the previous batch first".
- **`root_cause` rejected** (cycle-1204 audit; `.evolve/state.json` `failedApproaches[54]`): an exact-match rule on the field was built and reverted. Across the 67 live items, all 20 non-empty values were unique prose of 122 to 1564 bytes (median 317). Unlike campaign and dep ids, which are short reusable keys, `root_cause` is a per-defect narrative, so equality binding yields zero edges (D1), and normalizing or fuzzy matching would only manufacture false edges between unrelated defects, with no ceiling or floor to stop the fusion (D2). Cycle-1205 added the regression guard; since `Item` has no `root_cause` field, it uses `Title` as the free-form prose stand-in.
- **`class` was dropped at load** until cycle-1190, although authors had been writing it into inbox JSON for some time.
- **Pipeline kinds** (F25, wave 6, cycle 1688): 15 `pipeline-*` items sat lane-eligible, 8 with no `files[]` at all; one was claimed and failed triage before the breaker caught it.
- **Weight order superseded** (P2 of the [inbox prioritization plan](../../plans/inbox-prioritization-2026-10.md), 2026-10-06): `Classify` ranked clusters and members by the hand-typed weight, so a class, a waiting dependent or a recurrence could not move an item, and 33 items tied at 0.5 fell back to id order. The weight sort became the `Order` seam. `go/acs/cycle1724`'s 002, which asserted the weight-descending order of an un-ranked `Classify`, was archived under the A2 retention rule ([superseded predicates](../../private/research/archived-2026-10-06/superseded-predicates/README.md)); the rank deliberately lets an item that unblocks queued work rise, so "deps never reorder" no longer holds once the rank is injected.
- **Retired-item scan** (F18, [2026-09-15 incident](../../incidents/2026-09-15-shipped-item-re-pinned-and-sealed-lease-blocks-refresh.md)): the dispatch-state resolver read `processed/` flat while the promoter nests it by cycle, so cycle 1682 re-pinned a lane to an item cycle 1679 had already shipped. `CycleDirs` became the one scan.
