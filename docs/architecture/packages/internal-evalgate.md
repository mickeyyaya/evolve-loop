## Purpose

`internal/evalgate` replaces prose contracts between phases with verified checks. It mounts four gates behind one `core.DeliverableReviewer` (`NewReviewer`, wired by `cmd/evolve` through `core.WithReviewer`): Gate A after scout, Gates B, C and D after tdd. It also exports the slug parser those gates share (`SelectedSlugs`, `SelectedTasksParseMiss`) and a standalone acceptance-criterion lint (`LintMonotonicBinaryTarget`).

## Design

- **Composite reviewer.** Each gate states the phase it inspects (`appliesTo`) and returns `(reason, block)`. `Review` logs every non-empty reason to stderr. At `StageEnforce` the first gate that returns `block=true` rejects; at `StageShadow` every violation is logged and approved. `StageOff` is never constructed, because the composition root skips `WithReviewer` entirely.
- **Optional remediation.** A gate that can say exactly what would satisfy it implements `remediator`, and `Review` copies that text into `ReviewResult.Remediation`. The default correction directive tells the agent not to change unrelated files, which forbids the fix when the remedy is to create a missing file. Gates that do not implement it keep their correction text byte-identical. Only Gate A implements it.
- **Gate A, `evals-materialized` (scout).** Every slug scout selected must have `.evolve/evals/<slug>.md` under the project root or, as a fallback, the workspace, and the file must contain a `[code]` grader. An eval written only into the cycle worktree is not visible. The scout is the only phase whose sandbox may write `.evolve/evals` (the builder's denies it on purpose), so a graderless eval must fail here: at ship it costs a repair round the builder cannot apply.
- **Gate A remediation.** It lists the exact path per missing slug and restates the grader requirement, so the file the agent creates does not fail the next gate. For a missing eval it offers only the workspace path. Under the OS sandbox the project root is `RepoRoot`, which is deny-write (`adapters/sandbox`: `ReadOnlyRepo`, with only worktree, workspace and tmp re-permitted), so an agent told to write there would get EPERM. The workspace path alone satisfies the gate.
- **Gate A parse-miss advisory.** When the `## Selected Tasks` section has content but yields no slug, Gate A appends a non-blocking note to its line. The note says Gate A checked nothing only when the slug union is empty; when the `## Decision Trace` still supplied slugs it names them as the only ones checked.
- **Slug extraction.** `SelectedSlugs` unions two sources: the `## Decision Trace` JSON (entries with `finalDecision == "selected"`), the most reliable, and `- **Slug:**` bullets in `## Selected Tasks`, the fallback. Slugs are kebab-case, deduplicated and sorted. A bullet's slug may be wrapped in backticks, the form real reports emit. A trace that states its selection as a `"selected_tasks"` string array is not read. The fenced block must open at a line start, so an inline triple-backtick span in prose is never taken for it. `TestSlugParserContract` pins every token the parser reads against `agents/evolve-scout*.md`.
- **One section bound.** `selectedTasksBody` bounds `## Selected Tasks` from its heading to the next `## ` heading. `selectedTaskSlugs` and `SelectedTasksParseMiss` share it, because a miss signal computed over a different span than the parse it reports on would accuse text the parser never read.
- **`SelectedTasksParseMiss`.** True requires all three: the heading is present, the bounded body holds non-whitespace once HTML comments are stripped (so `<!-- none selected -->` reads as empty), and no slug bullet parses out of it. A malformed `## Decision Trace` is out of scope by construction.
- **Gate B, `predicate-quality` (tdd).** It runs `evalqualitycheck.Check` on each selected slug's eval. `LevelHalt` (a definite tautology) blocks; `LevelWarn` is advisory. A missing eval is Gate A's concern, and an unreadable one fails open.
- **Gate C, `floor-binding` (tdd).** EGPS floor predicates may bind only floors triage committed this cycle. It parses `go/acs/cycle<N>/predicates_test.go` with `go/ast`, takes `Test*` functions whose name contains `coverage` or `floor`, and collects package-path string literals from the whole body, closures included. A `/...` suffix is trimmed first so the wildcard form attributes to its package, and the target is the path's basename. It asks `triagecap` which of those packages appear in floor-bearing deferred or dropped items, then subtracts the committed ones.
- **Gate C provenance rule.** Declarations outrank prose. A declared `deferred_floors` entry yields only to a declared committed floor; a prose-derived deferral yields to committed evidence of any rank. When `deferred_floors` is declared and `committed_floors` is not, no subtraction happens.
- **Cycle number from the workspace.** `cycleNumFromWorkspace` accepts only a basename of exactly `cycle-<N>`. The orchestrator always passes the workspace root; a sub-path or an overflowing number yields 0, and Gates C and D treat 0 as "cannot locate this cycle's predicates".
- **Gate D, `flaky-predicate-shape` (tdd).** It runs `evalqualitycheck.LintFlakyPredicates` over this cycle's predicate directory. The reason lists at most five `file:func [class] reason` entries in sorted order and states the total and the linted-file count, so truncation is visible.
- **`LintMonotonicBinaryTarget`.** It flags an acceptance criterion that states where a count must end up ("to <=25", "to at most 25") on a monotonic task, one finding per criterion, each naming the direction-and-floor rewrite. A class is monotonic when it is `task-contract-design` or its name contains "monotonic", so the lint survives new class names. Non-monotonic classes are exempt, because an absolute target is the correct contract for one-shot work. The pattern is deliberately narrow: a false positive costs more than a miss.

## Invariants

- **Only a certain violation blocks.** A blocking gate returns `block=true` only for a stat'd-missing or graderless eval, a definite tautology, or a proven deferred-floor binding. Every ambiguity (no report, zero slugs, parse failure, unreadable file, missing triage artifact, no floor predicates) returns `block=false`, so enforce by default never false-blocks a healthy cycle. The fail-open paths are pinned in `gates_test.go` and `floorbinding_test.go`.
- **`block` is the violation signal, not `reason`.** Advisory gates return a reason on a healthy deliverable, since that is how their observation reaches the log. A `Review` that rejected on `reason != ""` would fail every tdd phase. Pinned by `TestNewReviewer_FlakyShapeSurfacesButNeverBlocksAtEnforce` and `TestNewReviewer_WeakEvalNeverBlocksAtEnforce`.
- **Gate D never blocks.** `block` is a constant `false`, not a computed value, so "this gate cannot fail a cycle" is checkable by reading one line. Promoting it to enforce means revoking that deliberately, after a per-class false-positive breakdown. Pinned by `TestFlakyShapeGate_EveryOutcomeIsObservable`.
- **Gate D speaks on every path.** Findings, clean, no predicate package, and each stand-down all return a non-empty reason that ends in "never blocks". If silence meant "clean", a live log could not tell a clean cycle from a gate that never ran. Pinned by `TestFlakyShapeGate_EveryOutcomeIsObservable`.
- **A parse-miss never blocks, and never hides a real block.** Gate A latches `block` from the missing and ungraded sets before it appends the advisory. Pinned by `TestMaterializationGate_ParseMissAdvisoryIsNonBlocking`.
- **Check and remediation agree.** Both derive from `missingSlugs` and `ungradedSlugs`, so the agent is never told to create a file the gate is not looking for, or to overwrite one it already accepted. Pinned by `TestMaterializationGate_RemediationNamesOnlyTheMissing`.
- **Remediation stays optional.** No gate but Gate A implements `remediator`. Pinned by `TestOtherGates_SupplyNoRemediation`.
- **Every composed gate carries a wiring pin.** `pinnedGateWirings` maps each gate name in `NewReviewer`'s slice to a test that finds it there, and may list no gate that is gone. Direct `check()` tests keep passing when a gate is dropped from the slice, so only a pin catches that. Pinned by `TestAllReviewerGates_HaveWiringPin` and `TestAllReviewerGates_NoStaleWiringPin`.
- **Only `Test*` functions yield floor targets.** A helper such as `floorPercentHelper` could otherwise contribute literals and false-block a healthy cycle. Pinned by `TestFloorBindingGate_NonTestHelpersIgnored`.
- **Committed wins over deferred.** A floor predicate on a package committed this cycle passes even when more of that package's work was also deferred. Pinned by `TestFloorBindingGate_CommittedWinsOverDeferredMention` and `TestFloorBinding_BilateralDeclarationCommittedWins`.
- **The scout artifact name has one source.** `scoutReportName` comes from `phasecontract.ArtifactName`, so a registry rename cannot leave Gate A reading a file nobody writes. Pinned by `go/acs/cycle1145`.
- **Comments `go/acs/cycle1685` reads.** `TestC1685_015` reads the comment above `slugLineRE` and requires the measured widening effect (6 of 84 unions changed, 2 newly blockable, both reports named, a measurement date). `TestC1685_008` requires a godoc opening `// SelectedTasksParseMiss`. Both comments stay for that reason.

## Findings

- **cycle-166**: scout selected slugs with no eval files, and audit failed after build tokens were already spent. That produced Gate A.
- **cycle-204**: tautological eval predicates passed as behavioral. That produced Gate B. Escalating a WARN that persists across a soak into a block is still open.
- **cycle-280** (R9.3): TDD authored floor predicates for deferred tasks, and the builder starved the committed task clearing them. That produced Gate C; see [internal-triagecap.md](internal-triagecap.md). **Cycle 305** moved Gate C onto the `deferred_floors` declaration (ADR-0046 Layer 1). **Cycle 310**: the gate blocked the committed package's own predicates, which produced the committed-wins subtraction.
- **Cycles 987 and 996**: every gate test called `check()` directly, so deleting a gate from `NewReviewer`'s slice passed the whole suite. That produced the per-gate wiring pins and the registry that forces one for each new gate.
- **Cycles 1173/1175/1178**: predicates that shelled a whole-package `go test` flaked under fleet load. That produced Gate D. Its review found two failure modes the gate is shaped against: the lint first shipped reachable only from `evolve eval quality-check` in discover, before any predicate exists (dead code), and a version that stayed silent on clean predicates could not be told apart from one that never ran. Calibration on 2026-07-30 flagged 64 of 282 `go/acs` directories, not yet broken down per class, which is why it stays advisory. See [acs-predicate-quality-gate.md](../acs-predicate-quality-gate.md).
- **Cycles 1471, 1476, 1504, 1531**: every recorded scout gate-block failure was Gate A, each rejected after two corrections, none recovered. The gate reported bare slug stems, and the generic directive then told the agent not to create files. That produced `remediator`.
- **Cycle 1679** (incident 2026-09-14): a scout eval with no `[code]` grader passed Gate A and was refused at the ship gate, where the builder could not fix it. Gate A now enforces the grader rule its remediation always stated (`TestMaterializationGate_RequiresACodeGraderPerEval`).
- **cycle-1570**: a `## Selected Tasks` section naming `config-gate-default-policy-authority` in prose parsed to no slug, Gate A failed open, and the missing eval surfaced three phases later at audit. That produced `SelectedTasksParseMiss` and the advisory (cycle 1685). Measured 2026-09-15 over the cycle-16* reports, the advisory fires on 59 of 84, 56 of them with an empty union. On 3 of the 59 the trace had supplied slugs, which is why the note narrows its claim (audit L1).
- **Cycle 1685, backtick widening**: 12 of 84 reports wrapped the slug in backticks. The widening changes the union on 6 of 84 and makes 2 newly blockable (cycles 1664 and 1669), a deliberate capability increase. An earlier claim that it was neutral rested on counting headings, not on comparing unions. `TestSlugLineWideningIsNotBlockingNeutral` re-runs the effect.
- **cycle-992**: a monotonic task that verifiably pruned 101 of 140 items scored zero against a "to <=25" criterion and its work was discarded. That produced `LintMonotonicBinaryTarget` (cycle 1190), which has no production caller yet.
