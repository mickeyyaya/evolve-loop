## Purpose

`internal/triagecap` bounds how many coverage floors triage may commit per cycle, based on observed builder throughput (the R9.2 capacity clamp). It also owns the parse of the triage report: the committed and deferred floor vocabulary that evalgate's Gate C reads, the deterministic `triage-decision.json` projection that ship promotes from, and the file-disjoint top_n selection that seeds fleet waves.

## Design

- **The clamp.** `Cap(K) = ceil(1.25·K)`. `K` is the half-up integer mean of floors per cycle over the last five floor-bearing shipped cycles (`state.json:triageThroughput`). An empty window seeds `K = 5`, the cycle-281 PASS baseline. A degenerate `K` clamps to 1, so the cap is never below 2 and a single-floor cycle always fits. `Recorder` appends at ship time, when committed equals passed because the cycle got through the gates. A zero-floor cycle records nothing, so non-coverage work cannot drag `K` toward zero.
- **Reviewer posture.** `CapReviewer` sits at the orchestrator's deliverable-review seam, chained after the eval and contract gates (`core.ChainReviewers`). Only the triage phase is in scope. A missing or unreadable artifact fails open, because the contract gate owns presence. Shadow logs the would-block. Enforce rejects into the correction ladder, whose bounded retries mean a miscalibrated clamp costs corrections, not a bricked loop. `readWindow` takes no project lock: the orchestrator's own lock prevents concurrent runs, and `WriteState`'s atomic rename prevents torn reads.
- **An actionable reject reason.** The reason states the counting rule, the packages the counter attributed, and the declaration escape (write `committed_floors` in `triage-decision.json`). An agent that cannot see the rule cannot comply with it.
- **Two non-blocking producer warnings.** A floor-bearing report without a `committed_floors` declaration logs a WARN naming the companion. A committed card that names a repo path in its prose but declares no usable `files=` footprint logs a WARN naming the card (`MissingCardFilesWarning`). Neither blocks: the ladder is for capacity, and refusing a deliverable over provenance would trade a silent overlap risk for a hard cycle failure. The card-files check runs on every triage deliverable, before the floor checks, so it does not depend on the report being floor-bearing.
- **Declaration first, prose second.** `CommittedFloorCount`, `CommittedFloorPackages` and `DeferredFloorPackagesDecl` trust the companion's `committed_floors` / `deferred_floors` when present. The prose scanners are the fail-open fallback for older artifacts. `FloorDivergenceCorrective` and `DeferredFloorDivergence` cross-examine the two and return a correction the agent can always satisfy, never a reject.
- **Target-scoped counting.** An item is floor-bearing when it mentions coverage or a floor and a percentage. It counts one floor per distinct known package in target position: named in the clause that ends at a target percent (`≥N%`, `>=N%`, or `to N%`). A clause starts after the previous percent, so an earlier measurement never leaks into a later target, and a list such as `core ≥85%, audit ≥96%` attributes each package to its own target. An item with no target marker counts one aggregate floor. The only target spellings in the replay corpus (281, 283, 298, 301, 448, 449) are these three; a new spelling needs `targetPercentRE` extended.
- **Deferred scanning stays mention-based.** The `## deferred` and `## dropped` sections answer "which targets did triage push out", not "what did it commit to", so every known package mentioned in a floor-bearing item counts.
- **Package vocabulary.** `KnownPackages` collects directory basenames under `go/internal` and `go/cmd` that hold `.go` files, skipping hidden directories and `testdata`. Tokens include hyphens, so a slug such as `fake-config` is not a mention of `config`. `pathOnlyPkgs` lists basenames that are also ordinary prose (`paths`); they count only slash-qualified. An `evidence=go/internal/paths/x.go` value still counts `paths`, because that is a real reference.
- **Two metadata strippers.** `metadataFieldRE` (floor counting) drops the `source=` and `priority=` values, drops `defer_reason=` to the end of the line, and keeps the `evidence=` value because evidence pointers name real packages. `proseMetadataRE` (the card-files warning) drops the `evidence=` value too: the contract requires an evidence pointer on every card and it is usually a path, so keeping it would warn on nearly every footprint-free card. RE2's ASCII `\b` also fires after a hyphen, so `low-priority=x` is stripped as well; that can only undercount.
- **Declared footprints.** `files=` is parsed by span, from `files=` to the next `, key=` field or the end of the line, so a value may contain commas. `;`, `,` and whitespace all separate paths, and repeated `files=` fields are unioned. `floorItem` removes the whole field before any floor scan; it is the one place that stripping happens. `declaredFilePath` trims the punctuation agents add (brackets, quotes, backticks, a trailing comma) and rejects what cannot be repaired: a template placeholder or glob, an absolute path or `..` escape, and a bare filename.
- **The projection.** Ship prefers an agent-authored `triage-decision.json`, but the triage agent rarely writes one, so `ProjectDecisionJSON` derives it from the report. It is a subset by design, and every omitted field has absent-safe consumer semantics. `committed_floors` and `deferred_floors` are omitted so the floor readers keep counting the markdown. `skip_shipped`, `skip_rejected` and `escalate_block` need Step-0a's git-log judgment, so they are omitted and promotion walks top_n only. `files` is never inferred from prose. `projected_by_orchestrator` marks the file for forensics. The `## superseded` ids are deduplicated for `inboxmover.ReconcileSuperseded`.
- **Section headings.** `## top_n` is anchored on `phasecontract.Triage`'s canonical heading, and an `init` guard turns an empty `Sections` table into a named panic rather than an index error. The deferred, dropped and superseded headings are anchored to the literals in the triage persona. The floor scanner matches deferred-or-dropped as one case-insensitive set that tolerates suffixes; the projection keeps the sections distinct.
- **Fleet seed selection.** `rankForDispatch` is the one ordering every seed path shares: weight first, then a verified declared surface (`FleetCandidate.Declared`, see ADR-0074 F29), then input order. `SelectFleetWidthTopN` delegates the disjoint packing to `fleet.Partition` and takes each bucket's first member as the lane's representative. `WidenTopNToFleetWidth` backfills a narrow committed prefix up to the fleet width; it cannot reuse `fleet.Partition`, which would drop overlapping committed items, so `overlapsClaimed` repeats Partition's `filepath.Clean` normalization. `ExpandWithClusterMates` deepens each lane into a menu of same-file mates. `SelectWaveSeedMenus` falls back to `SelectFleetWidthTopN` when nothing is committed, because that still yields one lane at `count < 2` where `WidenTopNToFleetWidth` would yield none. `ReadInboxBacklog` reads the inbox in filename order and drops console-routed items at read time.
- **Demotion.** The ADR-0046 Layer 2 demotion lives inside `CapReviewer.Review` and is consulted only at rejection time, so the approve path never reads `state.json`. A failure summary belongs to this gate when it carries both the reason prefix `triage overpacked` and `during triage:`, so another phase quoting the gate's text cannot demote it. `ReasonTemplateHash` replaces each digit run with its length before hashing. The pair's auto-filed inbox defect doubles as the relief-consumption marker. The generic GateClass registry the ADR describes is not built while this is the only heuristic gate.

## Invariants

- **Committed wins over deferred.** Gate C subtracts `CommittedFloorPackages` from the deferred set, so a floor predicate on the cycle's own committed package is a legitimate ratchet and never the deferred-floor starvation Gate C blocks.
- **The attributed-package list never exceeds the count.** `proseFloorPackages` is target-scoped exactly like `CountCommittedFloors`, so the reject reason and the divergence corrective list only what the counter attributed.
- **A footprint never adds a floor.** A declared path such as `go/internal/triagecap/floors.go` contains a floor trigger word and names packages; left in the item it would flip a non-floor card into a floor and attribute deferred floors to packages the card merely edits.
- **A malformed companion is never trusted.** The counters fall back to prose, because an unparseable declaration must neither crash the gate nor count as zero floors. `MalformedCommittedFloorWarning` and `MalformedDeferredFloorWarning` name the parse error, but no production path calls them yet, so today the fallback is silent.
- **Absent files mean "declared nothing".** `files` is `omitempty`, so a consumer can tell "declared nothing" from "declared an empty footprint". A wrong inferred file would merge or split real lanes; an absent one is honest.
- **Projected arrays are never null.** `top_n`, `deferred`, `dropped` and `superseded` start as empty slices, because consumers expect arrays and disjoint packing can legitimately narrow top_n to zero.
- **Projected ids must be kebab slugs.** Promotion moves an id out of the inbox, so an id parsed from free prose could act on a nonexistent item.
- **The card-files warning stays narrow.** It fires only when a card's own prose names a repo path, so footprint-free work (research, docs) stays silent and the warning keeps its meaning. An unusable declaration is reported separately, because it looks compliant while matching nothing. The companion is the authority when it parses, since it is what the lane planner reads.
- **Demotion fails toward enforcement.** An unreadable `state.json`, a missing `run.json` cycle id, or an unreadable relief marker all keep the gate enforcing. Without a provable current cycle the one-cycle scope cannot hold.
- **Relief is one cycle, bounded by a window.** The two most recent recorded rejections must be adjacent cycles; a gap inside the pair means a cycle got past the gate, which breaks the determinism signal. The newer one must lie within `demotionWindow` (3) of the current cycle, so up to two reset-sealed cycles, which leave no rejection record, are transparent. A pair whose relief another cycle consumed keeps enforcing, so gap transparency never widens into free passes. A re-review of the relieved cycle itself (a crash resume) stays relieved and files nothing new.
- **The demotion ledger speaks a closed vocabulary.** `remedy_status` is `pending`, `salvage_attempted` or `no_remedy_possible`. It is caller-declared, since nothing in `state.json` says whether a salvage happened, and anything else normalizes to `pending`. The record is written once per pair (the filename embeds both cycles), and a later consumer may rewrite it with the terminal outcome.
- **Lane disjointness holds by construction.** A backlog candidate joins a lane only when every lane-owned file it touches belongs to that one lane, and it then claims its own files, so clusters grow transitively without crossing lanes. A candidate touching no lane is width material, never depth filler; one touching two lanes would bridge two worktrees into a ship-time collision and joins neither. When a committed prefix overlaps itself, the first lane touching a file keeps it.
- **Committed intent is preserved verbatim.** `WidenTopNToFleetWidth` never drops or reorders a committed candidate, even one overlapping another; only the backfilled tail must be disjoint.
- **Pruning fails open.** `PruneConsumed` drops only terminal lifecycle states (processed, consumed, rejected, quarantine). An id with no lifecycle evidence stays, because dropping what cannot be resolved would starve every wave of non-inbox-backed cards. It is exported so `loopwave.WidenNarrowDecision` uses the same primitive as the seed path.
- **The throughput window is immutable.** `Record` returns a new slice and never aliases its input.

## Findings

- **Cycles 280/282/283**: three coverage cycles failed after triage committed about 12 package floors against a sustainable throughput of about 5 per builder turn (cycle 281). That produced the clamp. Cycle 280 also showed a builder starving its committed task to clear predicates bound to deferred floors, which produced the deferred-floor vocabulary and Gate C (R9.3).
- **Cycles 298/301**: contract metadata and the prose word "paths" counted as package floors. See the [incident record](../../operations/incident-2026-06-12-triagecap-phantom-floors.md). ADR-0046 adds that the bug shipped because the test vocabulary omitted the colliding basenames, which is why `knownPkgsFixture` carries `evidence`, `scout` and `paths`.
- **Cycle 310** (soak #3d): a `defer_reason` that mentioned the committed package ("co-scheduling with the looppreflight blocker fix") made Gate C block that package's own predicates. `defer_reason` values are now stripped to the end of the line.
- **Cycles 308/316/320–322**: the triage agent almost never wrote the companion, so promote-to-processed never ran and claimed items bounced back to the inbox every cycle. That produced `ProjectDecisionJSON`.
- **Cycle 305 audit (M1), fixed in cycle 308**: a malformed companion fell through to prose silently, indistinguishable from a missing one. That produced the `Malformed*FloorWarning` pair.
- **Cycles 448/449** (the F1–F5 chain, fixed in cycle 459): both cycles complied with the correction twice and died at this gate. F1: evidence citations counted as floors (449 committed 3 and counted 7), fixed by target scoping. F2 and F5: the reason showed neither the rule, the counted packages, nor the declaration escape. F3: nothing checked that a floor-bearing report carried a declaration. F4: an operator reset sealed cycle 450 without a rejection record, and the old demand for rejections at `current−1` and `current−2` could not see across the hole; the demotion window and the relief marker replaced it. The goldens under `testdata/triage-cycle44{8,9}-golden.md` are the preserved reports.
- **ADR-0046 Layer 2**: cycles 301/302 re-rejected an honest commitment with one template until both burned. Cycle 306's attempt erased all digits, collapsing magnitudes; cycle 307's was never wired into the composition root. See ADR-0046.
- **Cycle 1301**: the demotion record carried only prose, so commit `29915424` had to explain two demotions in a chore commit body. That produced `remedy_status`.
- **Cycles 544–548**: work shipped under a different id left the original inbox item orphaned. That produced the `## superseded` section.
- **Cycle 503**: triage committed a single top_n item and starved a two-lane fleet. That produced `SelectFleetWidthTopN`. Cycles 508 and 518 then shipped it tested but with no caller; `SelectWaveSeedTopN` wired it into the wave seed, and `SelectWaveSeedMenus` has since replaced that on the production path.
- **Batch 7, wave 0**: the raw top-N seeded only console-routed items, the plan-time gate rightly refused them all, and the wave planned zero lanes. `ReadInboxBacklog` now excludes console-routed items so the seed backfills.
- **Batch 14, wave 1** (cycles 1127/1128): each lane scope held one todo while its same-file partition mates were discarded. That produced the lane menus (`ExpandWithClusterMates`).
- **Cycle 1130** (live on 1133/1134): a card naming `go/internal/phases/audit/audit.go` in prose carried no `files[]`, so the planner treated it as an id island and a second lane took the same file. That produced `files=` projection and `MissingCardFilesWarning`. The same work found that an unstripped footprint added a phantom floor ([change log 2026-07-30](../../operations/change-log-2026-07-30.md)).
- **Cycle 1159** (`menu-pass-preserve-committed-ids`): the menu pass seeded through the committed-blind selector and could drop or reorder committed ids. See [the carryover resolution](../../operations/carryover-resolutions/todo-quarantine-dead-lane-code.md).
- **Cycles 1113/1116**: a consumed id was re-pinned into a later lane scope; cycle 1182 exported `PruneConsumed` for the per-wave seam. See ADR-0079.
