# internal/faillearn

## Purpose

`internal/faillearn` is the kernel-owned failure floor beneath the LLM retrospective: when the retro cannot run (bridge failure, operator reset, loop fatal), it renders a durable `retrospective-report.md` and a failure lesson from structured failure data the caller already holds, and optionally files the retro's remediation items into `.evolve/inbox` in the same call. It mirrors the integrity-floor pattern (the LLM proposes, the kernel disposes). It is a leaf package (stdlib plus `yaml.v3`); callers choose where artifacts land and own the `state.json` records (`failurelog`).

## Design

- **Scopes.** `ScopePhase` is a mid-cycle phase failure, `ScopeReset` an operator `evolve cycle reset`, `ScopeLoop` a loop-runner fatal exit. `FailureEvent.Classification` is one of `cycle-mid-execution-fail`, `operator-reset` or `loop-fatal`. Every `FailureEvent` field comes from data the caller already holds: rendering needs no LLM and no I/O.
- **Byte-deterministic renders.** `RenderRetrospectiveMarkdown` and `RenderLessonYAML` produce the same bytes for the same event (goldens in `testdata/`, regenerated with `go test ./internal/faillearn/ -run Golden -update`; the test fixture fixes `Now`).
- **Rune truncation.** The rendered summary and description are capped at `summaryMaxRunes` (500) runes, not bytes, so multi-byte text truncates cleanly; `truncateRunes` returns the string unallocated when its byte length is within the cap, since byte length bounds rune count from above.
- **Fallback confidence.** `deterministicConfidence` (0.5) ranks floor lessons below LLM-authored ones (corpus norm at least 0.9) so KB recall weights them accordingly.
- **The lesson is a YAML list.** `research.parseLessonFile` unmarshals `[]lessonYAML`; a bare mapping would be invisible to KB recall. `lessonYAML` mirrors the corpus schema; change the shape in `internal/research`'s contract test first.
- **Lesson id.** `cycle-N-<scope>-<slug>`; the slug prefers the failed phase (most specific) over the classification. `slugify` lowercases and maps each run of non-alphanumerics to one hyphen (`stop_reason=circuit_breaker` becomes `stop-reason-circuit-breaker`).
- **`yaml.Marshal` of the lesson slice cannot fail**, so `RenderLessonYAML` panics on an error instead of emitting a contract-violating artifact through a silent fallback.
- **`StructuredDefects`** returns the defect list only when it carries real content (ADR-0039 §7 self-reported defects); a list that merely echoes the synthesized summary is omitted, and the lesson's `defects,omitempty` tag keeps a summary-only lesson byte-identical. It is exported so the inbox remediation path in core (`writeDeterministicLearning`) applies the same rule: two definitions of "a real defect" would let the lesson and the queue disagree about what happened.
- **Functional options.** `Option`, `WithInbox` and `WithNoveltyThreshold` leave the option-free callers (core failure learning, core reset, `cmd_loop_outcome`) byte-identical.
- **`InboxItem`'s JSON tags mirror `inboxbatch.Item`'s wire shape** (`id`, `title`, `weight`, `kind`, `priority`, `files`, `injected_by`). `inboxbatch` is the consumer and binds by tag; this leaf cannot import it, so parity is by tag, and a renamed tag produces items the loader drops.
- **Autofiled items carry a non-empty `InjectedBy`.** `inboxbatch.ConsoleRouted` treats an empty `InjectedBy` as operator-authored and honors its `route:"lane"` override; an autofiled item must never inherit that authority. The callers set it.
- **Inbox first, then the retrospective.** `WriteArtifacts` writes the remediation items before the retrospective and aborts on their failure, so a `retrospective-report.md` on disk never claims remediation that did not reach the queue. Already-written items are not rolled back: `writeIfAbsent` makes the retry idempotent, and a queued remediation item is the safe direction to fail in.
- **The degraded retrospective.** On that failure arm, `preserveDiagnosis` publishes the diagnosis under a distinct name, `retrospective-unqueued.md` (`retrospective-report.md` means "the remediation is queued"), with an explicit `UNQUEUED` marker and the id of every item that did not reach the queue. It returns the queue failure unchanged; a failure to publish the degraded artifact is joined onto it, never replaces it. It is failure-arm-only.
- **An empty `runDir`** (a loop-scope fatal has no cycle workspace) writes the lesson only; it never invents a report location or treats the process cwd as one, including on the degraded path.
- **`unqueuedItems` reads the inbox back from disk** instead of slicing at the failure index. `writeInboxItems` writes one file per item and returns on the first failure, so earlier items are already queued; reading back also covers an item a concurrent fleet lane wrote under the same deterministic id (queued) and an id collision where a different item holds the name (unqueued). `itemReachedInbox` requires the file to carry the item's own content; any doubt (no inbox dir, an unaddressable id, an unreadable file) reports unqueued, so the failure direction names work that may already be filed rather than losing work.
- **`itemPath` is the single home of the addressability rules**, shared by the writer and the read-back. An id is concatenated into a path, so it must be a bare filename; an empty or path-shaped id is rejected loudly, never sanitised, since a silently rewritten id is unaddressable by the id it was filed under.
- **Id collisions fail loudly.** Inbox ids are deterministic (`retro-<cycle>-<slug>` over agent-authored defect text), so a concurrent fleet lane or stale state from an earlier run of the same cycle number can already hold the filename. A skip is tolerated only when the file on disk carries the same item (an idempotent retry); different content under the id is a collision and an error.
- **`WithInbox` with no items mints nothing**, not even the inbox directory.
- **`writeIfAbsent`** writes a file only when the path is absent and reports whether it skipped; the caller decides what a skip means (for the retrospective and the lesson a richer existing artifact wins; for the inbox it is a potential collision). The temp file is written whole in the destination's directory and published with `os.Link`, which makes "does not exist" and "I created it" one atomic step: link fails `EEXIST` against a concurrent winner (reported as a skip), where rename would silently clobber it, and a crash mid-write never leaves a partial artifact under the real name. `os.Link` only works within one filesystem, so the temp file cannot live elsewhere.
- **Published mode.** `publishedFileMode` (0644) is the same literal `internal/atomicwrite.Bytes` enforces: other fleet lanes and the operator read the floor's artifacts. `os.CreateTemp` creates at 0600 (not umask-derived) and the link publishes the inode itself, so the temp file is chmodded before linking, never the destination, which would also rewrite a preserved artifact's mode.
- **Novelty gate.** `writeIfAbsent` dedupes by exact path, but the lesson id embeds the cycle number, so the same observation recurring on a later cycle lands under a new filename. `isNearDuplicate` compares the incoming lesson's observation tokens with every lesson already in `lessonsDir` by Jaccard similarity and skips the write at or above the threshold. A suppressed near-duplicate is not an error, and suppression is scoped to the lesson: the retrospective is written regardless.
- **The gate is conservative in one direction.** Suppression destroys failure evidence and cannot be undone, so anything short of an almost token-identical match is written: an empty token set, an absent or unreadable corpus and an unreadable neighbour all mean "write". An unparseable neighbour yields no tokens, so corpus rot is inert: it neither suppresses a write nor is rewritten or deleted.
- **Observation tokens.** `observationTokens` uses only the observation-bearing fields; `id`, `source` (evidence paths) and `preventiveAction` embed the cycle number and would make every recurrence look novel. `tokenizeObservation` lowercases, splits on every non-alphanumeric rune and drops pure-digit tokens (cycle numbers, counts). `jaccard` is symmetric, so the verdict cannot depend on write order, and two empty sets score 0, so an empty comparison never suppresses.
- **Threshold resolution.** `defaultNoveltyThreshold` (0.9) mirrors `policy.ResearchConfig().NoveltyThreshold`'s built-in; the leaf cannot import `policy`, so `core/failurelearning` passes the resolved value through `WithNoveltyThreshold`, and the constant only covers option-free callers. A value outside (0, 1] falls back to 0.9: 0 would suppress every write and above 1 would disarm the gate.

## Invariants

- The summary is truncated by runes, not bytes. Pinned by `TestSummaryTruncation`.
- The rendered lesson is a YAML list the corpus reader parses. Pinned by `TestRenderLessonYAML_IsYAMLList`, and across packages by `internal/research`'s `TestLessonSchema_FieldCountPinsFaillearnParity` and `TestParseLessonFile_RoundTripsFaillearnRender`.
- The lesson id and slug are stable and renders are byte-deterministic. Pinned by `TestRenderLessonYAML_IDSlugStable`, `TestRenderLessonYAML_Deterministic`, `TestRenderRetrospectiveMarkdown_GoldenBytes` and `TestRenderLessonYAML_GoldenBytes`.
- A defect list that only echoes the summary is omitted; independent defects are kept. Pinned by `TestStructuredDefectsOmitSingleSummaryDuplicate` and `TestStructuredDefectsRetainIndependentDefects`.
- Option-free callers see exactly the report and the lesson, and no inbox directory. Pinned by `TestWriteArtifacts_WithoutInboxOptionIsUnchanged`; applying an `Option` mutates the write config, pinned by `TestOption_AppliesInboxDestination`.
- Inbox items land as addressable `<id>.json` files whose raw JSON keys match `inboxbatch.Item`'s tags. Pinned by `TestWriteArtifacts_InboxItemsLandBesideRetrospective`.
- A retro-filed item's `injected_by` is non-empty. Pinned by `acs/cycle1292`'s `TestC1292_004_DeferralClaimIsBackedByALoadableInboxItem`.
- An inbox failure fails loudly and leaves no `retrospective-report.md`. Pinned by `TestWriteArtifacts_InboxFailureLeavesNoRetrospective`.
- The degraded retrospective is written on every inbox failure arm (unwritable directory or rejected item), is idempotent on retry, is never written on success, and an empty `runDir` still errors. Pinned by `TestWriteArtifacts_InboxFailureWritesUnqueuedRetro`, `TestWriteArtifacts_ItemLevelRejectionAlsoPreservesDiagnosis`, `TestWriteArtifacts_InboxFailureDegradedRetroIsIdempotent`, `TestWriteArtifacts_SuccessMintsNoUnqueuedMarker` and `TestWriteArtifacts_InboxFailureWithNoRunDirStillErrors`.
- On a partial write the degraded artifact names exactly the unqueued items. Pinned by `TestWriteArtifacts_PartialWriteNamesOnlyUnqueuedItems`, `TestWriteArtifacts_PartialWriteItemRejectionNamesOnlyUnqueuedItems`, `TestWriteArtifacts_PartialWrite_TotalFailureNamesEveryItem` and `TestWriteArtifacts_PartialWrite_FirstItemFailsNamesEveryItem`.
- A path-escaping id is rejected and nothing escapes the inbox; an ordinary slug id is written. Pinned by `TestWriteArtifacts_InboxRejectsPathEscapingID` and `TestWriteArtifacts_InboxAcceptsOrdinaryID`.
- A different item under our id fails loudly; an identical item is an idempotent retry. Pinned by `TestWriteInboxItems_CollidingFilenameIsNotSilentlyDropped` and `TestWriteInboxItems_IdenticalItemIsIdempotent`.
- An empty item list mints no inbox directory. Pinned by `TestWriteArtifacts_EmptyInboxItemsMintsNoFiles`.
- An existing artifact is never clobbered and no temp residue remains; an empty `runDir` skips the report. Pinned by `TestWriteArtifacts_DedupesByLessonID`, `TestWriteArtifacts_PreservesExistingReport`, `TestWriteArtifacts_NoTmpResidue` and `TestWriteArtifacts_EmptyRunDirSkipsReport`.
- Every published artifact is 0644, with or without the inbox option, and a preserved artifact's mode is left alone. Pinned by `TestWriteArtifacts_PublishedArtifactsHaveMode0644`, `TestWriteArtifacts_ModeParityAlsoHoldsWithoutTheInboxOption` and `TestWriteArtifacts_ExistingArtifactModeIsNotRewritten`.
- The novelty gate suppresses a recurring observation, still writes the retrospective, keeps a distinct failure, is inert on corpus rot, and honors a valid threshold while clamping a malformed one. Pinned by the `TestWriteArtifacts_NoveltyGate*` and `TestWriteArtifacts_NoveltyThresholdOption*` tests in `novelty_test.go`, `TestTokenizeObservation_SplitsOnNonASCIIAlphanumericsAndDropsBareNumbers`, and `policy`'s `TestResearchConfig_NoveltyThresholdRangeResolution` for the shared 0.9 default.
- `writeIfAbsent` publishes by `os.Link` from a temp file in the destination's directory. Not yet pinned by a test (no concurrent-writer or cross-filesystem test); `writer.go` keeps a one-line why at each site.

## Findings

- Remediation items a retrospective files only inside its report never reach the loop's queue and are lost by later continuations; routing them into the inbox in the same call as the retrospective makes "the retro was written" imply "the remediation was queued".
- A silent skip on an occupied inbox filename drops a real remediation item while `WriteArtifacts` reports success; only a same-content skip is a safe retry.
- Stat-then-write lets two fleet lanes both observe "absent" and both write; the content-equality check can then only observe the race after the fact, which is why publication is a single `os.Link`.
- Test fault injection: a regular file where the inbox directory must go makes `MkdirAll` and create fail with `ENOTDIR` deterministically, needs no fault-injection seam, and is not defeated by a root CI runner the way a chmod-based injection is. A genuine partial write comes from an id collision on the middle item of a three-item fixture, which separates the queued items before the failure from the failing item and everything after it; the assertion reads only the degraded artifact's "still UNQUEUED" section, because the embedded retrospective can legitimately mention an item id.
