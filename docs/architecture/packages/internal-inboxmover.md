# internal/inboxmover

> Decision records: [ADR-0079](../adr/0079-cycle-outcome-inbox-lifecycle-seam.md) (one cycle-outcome seam), [ADR-0089](../adr/0089-continuation-retirement-and-live-scope-guard.md) (retirement releases the continuation binding), [ADR-0074](../adr/0074-typed-signal-contracts-routing-authority.md) (the console-routing claim floor) and [ADR-0072](../adr/0072-system-failure-policy-and-halt.md) (the retry ceiling and quarantine). The lifecycle leaf, this seam, the goldens and the preserved quirks: [decomposition unit 06](../decomposition/06-inboxmover.md). The `Closes-Inbox:` marker: [inbox-injection-protocol.md](../inbox-injection-protocol.md). This page keeps the host-package detail those do not.

## Purpose

`internal/inboxmover` hosts the inbox lifecycle: `inbox/` → `processing/cycle-N/` → `processed/`, `rejected/`, `retry/`, `quarantine/`, or back to the root. The movers themselves live in the `lifecycle` leaf. This package owns `Options` and its defaults, builds the leaf's `Mover`, and applies each cycle's verdict (`ApplyCycleOutcome`). It also holds the readers that sit beside the lifecycle: the triage-decision readers, the `Closes-Inbox:` parser, dispatch-state resolution and the continuation-binding trio.

## Design

- **A seam over a leaf.** `Options` is a value copied at every entry point, so there is no host object to cache a `Mover` on. `(Options).reader()` resolves the defaults and builds one per call. It is the only non-test construction site (`TestOptionsMover_OneConstructionSite`). `(Options).mover()` adds the cycle-worktree refusal (next bullet) and returns the `Mover` or the refusal. Each exported mover is a short facade, so the cmd layer, the ship phase and the ACS predicates keep their spellings (`TestFacades_KeepEverySpelling`).
- **No `inboxmover` verb moves the inbox copy of a cycle worktree.** `.evolve/inbox` is tracked, so each cycle worktree has a stale copy of the queue. Provisioning (`core.linkGuardDeps`) makes the worktree's `.evolve/state.json` a symlink to the plane's file. `cycleWorktreeRefusal` reads that symlink beside the resolved `InboxDir`. If it is a symlink, every mutating facade refuses with `errCycleWorktreeInbox`. The message names the plane root and `EVOLVE_PROJECT_ROOT=<plane>`.
  - A command that resolves its root from a worktree cwd thus fails loudly and moves nothing. In batch cycle 1631 (2026-09-12), such a claim moved the worktree copy and reported success.
  - The ship's landing consumption moves items in the worktree on purpose (`phases/ship/consume.go`), outside this package, so that the consumption rides the landing commit.
  - The check cleans the inbox path first, so a trailing slash or a `.` element cannot hide the link (`TestCycleWorktreeRefusal_AnUncleanInboxPathStillRefuses`).
  - The mark is only as strong as the link. `symlinkForce` logs a WARN and continues when `os.Symlink` fails, and then the worktree has no mark. The guard hooks of the worktree read the same link, so a missing link is already a provisioning defect that the WARN reports. A second mark is not added, because the worktree base directory is configurable and has no fixed path to test.
  - The refusal keys on the inbox directory, not on the root. A caller from a worktree that sets `InboxDir` to the plane inbox works as before. `ReadFailureCount` moves nothing and does not refuse.
  - Rejected option: stop the tracking of `.evolve/inbox` and symlink it into each worktree. Every console PR consumes an item with `git mv` into `consumed/`, so the queue must stay in git. A symlink in place of a tracked directory also shows every item as deleted in the worktree, and a cycle ship stages that worktree.
  - Pinned by `TestMutators_RefuseACycleWorktreeInboxCopyAndNameThePlane`: 20 facades and `ReleaseContinuationBinding` refuse, no item moves and no ledger line is written. `TestMutators_AnExplicitPlaneInboxFromACycleWorktreeIsAllowed` and `TestCycleWorktreeRefusal_ARelativeStateLinkResolvesThePlane` pin the plane cases.
  - An unreadable link refuses, because the check fails closed (`TestCycleWorktreeRefusal_AnUnreadableStateLinkRefuses`). Real provisioning is pinned by `TestProvisionedWorktree_ItsTrackedInboxCopyRefusesTheMover` in `core`.
- **Defaults.** `InboxDir` is `<root>/.evolve/inbox`. `LedgerPath` defaults to `<root>/.evolve/ledger.jsonl`, but only its directory is used, because the chained `FileLedger` owns its file names. That fallback ledger is the one unobserved ledger construction that `TestUnobservedLedgerRootsArePinned` (cmd/evolve) allows in this package. `ActiveCycleFn` reads `cycle_id` from `.evolve/cycle-state.json`.
  - `IsLandedFn` runs `git merge-base --is-ancestor <sha> main`.
  - `MainHeadFn` runs `git rev-parse --verify origin/main^{commit}` in the project root. `VerifyPremise` stamps that sha. A root without `origin/main` is an error, never a guess (`TestVerifyPremise_StampsTheShaOfOriginMain`, `TestVerifyPremise_WithoutOriginMainStampsNothing`).
- **The landing probe.** Exit 0 means landed and exit 1 means unlanded. Any other answer (128 for a non-git root, an unknown sha or no local `main`) and any exec fault fail open as landed. The error is returned, so the leaf reports `INBOX_LANDED_CHECK_FAILED`. Delivery evidence gates a promotion; missing git must not invent a false negative. The probe runs only for a processed promotion that carries a commit sha.
- **The curation facades** `Edit`, `Withdraw` and `VerifyPremise` ([ADR-0116](../adr/0116-inbox-curation-verbs.md)) are one-line doors like the rest. They re-export the leaf's `FieldEdit`, `EditOp` and `ErrNotWithdrawable`, so `evolve inbox edit`, `withdraw` and `verify` never import the leaf.
  - `(Options).mover()` wires `WithBinding` to `continuation.ReadRegistryEntry` under the project root. So `Withdraw` refuses an item that the registry binds (`TestWithdraw_RefusesAnItemAContinuationBinds`, the architecture review's probe inverted).
  - `(Options).mover()` also wires `WithProtectedPath` from `Options.IsProtectedPath`, which `Edit`'s console guard reads.
  - The read verbs `evolve inbox show` and `list` need no facade. They read through `inboxbatch.LoadDir` and place each item with `PlaceOnLaneMenu`, the rule that `PartitionLaneMenu` applies for `evolve inbox batches`. So a listing and the batches report cannot disagree on who owns an item.
  - PR #758 adds the host `IsMoverWritten` facade; this package's projection of it lives in the leaf.
  - `Options.PriorityClasses` is the class order that `File` judges an item's `priority_class` against ([ADR-0121](../adr/0121-inbox-priority-is-a-computed-rank.md)). `(Options).mover()` passes it to the leaf's `WithPriorityClasses`, and `evolve inbox add` fills it from `policy.InboxPriorityConfig().ClassOrder` (`TestFile_JudgesThePriorityClassAgainstTheOptionsOrder`). Left empty, the leaf refuses every filing as a wiring fault.
  - `Options.Origin` and `Options.IntakeRecord` reach `lifecycle.WithOrigin` and `lifecycle.WithIntakeRecord`. The add verb sets both, the split verb sets the origin `console`, and the host console follow-up filer (`cmd_cycle.go`) sets `cycle`. The cycle-outcome companion and the practice watch stamp `origin` in the item itself (2026-10-27, [internal-inboxcurator.md](internal-inboxcurator.md)).
- **Two voices.** With `Options.Signals` set, the leaf's faults become `inbox.warning` events. With it nil, the leaf prints the legacy `[inbox-mover]` line instead, so a Center-less root (the post-ship mover, the operator commands) loses nothing. The sibling files here print through `logf`, which uses the leaf's one `LegacyPrefix` (`TestInboxMoverPrefix_OneHome`).
- **Exit codes** are the cmd layer's map over the sentinel errors. The sentinels are the leaf's own pointers, so `errors.Is` holds across the seam.
- **One door for a cycle's verdict.** `ApplyCycleOutcome` handles PASS and FAIL. `releaseCycleProcessing` stays unexported so the failure drain has no second entry point, and `TestLifecycle_OnlyHostImportsTheLeaf` keeps the leaf's `Release` behind this package. PASS promotes the committed ids to `processed/cycle-N/` from wherever they are, then drains the cycle's remaining claims to the root. FAIL claims the committed ids into `processing/cycle-N/` (`ClaimLaneScope`); the drain then bumps `failure_count` on those ids only and quarantines any that reach the ceiling. Uncommitted menu ids release untouched.
  - ADR-0079 explains why the claim happens at outcome time and not at dispatch.
- **The charge carries the failure record.** `CycleOutcome.FailureClass` and `CycleOutcome.Fingerprint` reach the drain through `lifecycle.Policy`. The bump writes them as `last_failure_class` and `last_failure_fingerprint` ([retry-ladder.md §5](../retry-ladder.md#5-where-the-ladder-runs)). `cycleoutcome.FailureInputsFor` derives them from the cycle workspace.
- **Retire by id.** `SupersededInboxIDs` reads triage's `superseded[]`. `ReconcileSuperseded` promotes each id on its own, independent of the committed set, so an item that shipped under a different id leaves the root. `ReleaseCycleProcessingWithReason` lets a drain that an unlanded ship causes record a reason with `unlanded`. So the ledger tells a delivery-failure retry from an ordinary residual drain.
- **Triage-decision readers.** `CommittedIDs` (top_n ids plus skip_shipped task ids) is the one worked-set reader both closeouts use. `DeferredIDs` names ids consumption must never retire. `ClosedDroppedIDs` retires only drops whose reason leads with a close-class tag: `already-shipped`, `already-done`, `already-landed`, `duplicate`, `superseded` or `obsolete`. Triage also drops valid work (`requires-split`, `out-of-scope`) and stale premises. An unknown reason keeps the item too, because the loss of a live todo is worse than a stale todo that stays.
- **Three readers of `dropped[]`.** `ClosedDroppedIDs`, `triageDroppedIDs` in `internal/core/carryover` and `committedset.DispositionsFrom` parse the same field with three deliberate policies. `triageDroppedIDs` is reason-blind, for the carryover store. In `committedset.DispositionsFrom`, a drop with a reason ends a fleet lane as planned no-work. A schema change to `dropped[]` must land in all three. The follow-up `decision-document-single-declaration` proposes one declaration for them in the stdlib-only `committedset` leaf.
- **`Closes-Inbox:` markers.** `ClosesInboxIDs` parses a build report. A line whose first non-blank content, after one optional markdown bullet (`-`, `*` or `+`), is the marker in any case contributes its comma-separated ids. Ids are trimmed of whitespace and backticks and must match `[A-Za-z0-9._-]+`, so a `<id>` placeholder is dropped. The result is deduped in first-seen order. A mention mid-sentence contributes nothing.
  - Closure is an explicit marker and is not inferred from the diff, because an item's `connects_to` is a hint, not an acceptance predicate. An inference from the diff can consume items that an unrelated diff brushed past. Over-consumption is silent data loss; under-consumption costs one bookkeeping cycle.
- **Dispatch state.** `ResolveDispatchState` re-resolves a planned id against the live lifecycle just before a lane launches. It lives here because this package owns the lifecycle dirs, so the fleet and cmd layers stay layout-agnostic.
  - A claim in `processing/cycle-N/` means processing. It is read before the root, so a root copy of a held id is never pending (cycle 1838).
  - The inbox root means pending (with its deps and live path). Then each `retirementStates` dir is checked flat and then by `cycle-N`, newest first, because a hit is almost always recent.
  - No evidence means unknown. Unreadable evidence counts as none, so a bad inbox can only fail open at the gate.
- **Dispatchability.** `ResolveDispatchability` is the one rule for if a fleet lane can take an id now. Every planner reader asks it: the loop's carried-id prune, the widen's prune, the backlog and the launch gate. The seed, the widen and the refill read that backlog.
  - A pending id is dispatchable unless a declared dep is still pending, processing or in retry (`deps unmet: needs <dep>`). An id with no lifecycle evidence is dispatchable, because not every planned id is inbox-backed. Every other state is not (`consumed: <state>[ <cycle dir>]`).
  - `PendingDispatchability` is the pending branch alone, for the backlog reader. That reader already knows that a root item is pending, so the branch saves a rescan of the inbox once per item.
  - `PlaceOnLaneMenu` is the one per-item judgment of where a pending item sits on the lane menu (Specification). It gives `MenuConsole` when `inboxbatch.ConsoleRouted` routes the item. It gives `MenuWaiting` when a claim holds its id (`held by the claim of cycle-N`) or when `PendingDispatchability` refuses its deps (`deps unmet: needs <dep>`). In all other cases, it gives `MenuReady`. The claim check reads only the claim dirs and does not scan the root again for each item. Console routing is judged before the dependency rule, so operator-owned work is never listed as waiting (`TestPlaceOnLaneMenu_OneJudgmentPerItem`).
  - `PartitionLaneMenu` folds `PlaceOnLaneMenu` over a list (`LaneMenu{Ready, Console, ConsoleReasons, Waiting, WaitingReasons}`, reasons as `<id>: <reason>`). `triagecap.ReadInboxBacklog` reads the same fold. Until the inbox rank's P2 (2026-10-06), it asked `PlaceOnLaneMenu` per item. Then it moved onto `inboxbatch.LoadDir` and `PartitionLaneMenu` to rank the ready list against the whole queue.
  - So four readers share one judgment. The triage prompt lists the waiting items under `dependency_blocked`. `evolve inbox batches` gives them its own heading and the `dependency_blocked` JSON field. The wave planner's backlog reads the fold, and the orchestrator's no-work check reads it through `core.WithLaneMenu`, on both the lane-scoped and the sequential path. `triagecap`'s `TestReadInboxBacklog_OffersExactlyTheLaneMenusReadyItemsThatCarryAnID` pins the planner to the menu.
  - `RankLaneMenu(opts, queue, isProtected, rank)` is the one "partition, then rank the ready list against the whole queue" step (the P2 architecture review's W1, 2026-10-06). It returns `PartitionLaneMenu`'s menu with `Ranked = rank.Order(menu.Ready, queue)`. The triage prompt, `evolve inbox batches` and `triagecap.ReadInboxBacklog` all call it. So none can rank the ready list against itself and lose the `unblocks` count of a waiting dependent. The review's surviving mutant `Order(menu.Ready, menu.Ready)` now reds `TestRankLaneMenu_RanksTheReadyListAgainstTheWholeQueue` and the three consumers' rank tests.
  - `PartitionLaneMenu` ends with the console companion check of [ADR-0158](../adr/0158-a-repair-round-runs-only-for-a-finding-the-lane-can-fix-and-the-auditor-applies-a-small-prescribed-fix.md) decision 6, with the stage in `Options.Companions`. At `enforce`, a ready lane item with an open console companion (`fixability.Companions`) moves to `Waiting` with the reason `<id>: console_companion_pending: <companions>`. At `shadow` and with no stage, the item stays ready and the reason goes to `LaneMenu.WouldDefer`. At `off`, nothing is checked. All readers of the menu agree, because the check is in the partition. Each caller reads the stage with `policy.FixabilityFor` (`TestPartitionLaneMenu_TheCompanionCheckIsPartOfThePartition`, `TestRankLaneMenu_EnforceDefersALaneItemWithAPendingConsoleCompanion`).
  - These rules live here beside `ResolveDispatchState` for the same reason: this package owns the lifecycle.
  - Pinned by `TestResolveDispatchability_IsTheOneRuleForWhetherALaneMayTakeAnID` and `TestPendingDispatchability_NamesTheFirstUnmetDependency`. The consumers' agreement is pinned in `internal/loopwave` (`TestPlanPruneWidenPruneAndLaunchGateGiveOneAnswer`).
- **The continuation trio** (`continuation_release.go`, `continuation_resolve.go`, `continuation_retire.go`) implements ADR-0089. `ReleaseContinuationBinding` is the one release transaction, shared by the retire hook, the read-side guard, the consumed-corpus sweep and `evolve continuation release`. `resolveClaim` walks the cycle's claims in filename order and returns the first stamped one the lane's scope admits. `ResolveContinuationForScope` then falls back to the registry for the lane's ids, in declared order so a re-run resolves the same binding. A claim that merely exists never suppresses the fallback; only a stamped one does.
  - An entry with no snapshot sha is not a binding. A corrupt registry resolves to nil with a loud line, because the orchestrator must never crash mid-cycle over a salvage index.
- **The consumed-corpus sweep.** `ReconcileConsumedBindings` runs before every cycle dispatch on the blocker-breaker path. It is O(consumed items) with a registry read per bound id. `consumed/` is never pruned. If the corpus grows by an order of magnitude, revisit the cost.
- **Claim liveness and release** (`holder.go`, `claims.go`; plan [inbox-stale-claims-2026-10.md](../../plans/inbox-stale-claims-2026-10.md)). One judge serves the verb, the planner and gc, so they cannot disagree.
  - `ClassifyHolder` gives the verdict of the cycle that holds a claim. A run lease with a live owner (`runlease.LiveOwner`: a fresh heartbeat and a live pid) is `live`.
  - A dossier closeout (`dossier.CloseoutPath`) or the phase `end` is `stale`.
  - A checkpoint that `core.CheckpointResumable` accepts is `resume-pending`: that is the one resume rule, the loader that `evolve loop --resume` uses. A per-run checkpoint also needs a reason that `core.IsResumableReason` accepts, as in the per-run discovery. `Options.CurrentGoal` (the planner's goal) or a higher cycle with a different goal hash makes it `stale`. All else is `stale`.
  - `Holder.Keeps` is true for `live` and `resume-pending`.
  - `SurveyClaims` gives every claim with its holder, and the empty claim dirs. The verbs `evolve inbox claims` and `evolve gc` read it.
  - `ReleaseClaim` refuses a holder that keeps its claim (`ErrClaimHeld`). It returns `not-claimed` for an id at the root only. Otherwise it calls the leaf's `Mover.ReleaseClaim`.
  - `ReleaseStaleClaims` releases every claim whose holder is `stale`, and judges each claim again just before its move. The wave planner and `evolve inbox-mover recover-orphans` call it.
  - `AbsorbRootCopies` is the facade of the leaf's `Mover.AbsorbRootCopies`. `sync-main` and the wave sync call it after the merge or the fast-forward.
- **`RecordRootTaskFailure`** was retired under 06-F2 in cycle 1864 (deleted as a second quarantine writer).

## Invariants

- **Every lifecycle move is one `os.Rename` on one filesystem,** so an item is never in two states at once. The leaf pins the movers.
- **Lifecycle ledger lines are chain participants.** They go through the chained `FileLedger` append (flock, `prev_hash`, `entry_seq`, atomic tip update), never a raw append. Pinned by `TestLedgerWrites_AreChainValid` and `TestLedgerAppender_SatisfiedByFileLedger`. Ledger writes are best-effort: a failed append never blocks a move.
- **A drain never clobbers a root copy.** An item whose basename already sits at the root (a concurrent release got there first) is warned about, skipped and not counted as recovered. Pinned by `TestInboxRelease_DoubleClaimRaceIsWarn`, `TestReleaseCycleProcessing_DoubleMove_NotCountedAsRecovered` and `TestReleaseCycleProcessing_NilStderrNoPanicOnDoubleMove`. `RecoverOrphans` deliberately has no such guard, a preserved quirk pinned by `TestRecoverOrphans_ClobbersExistingRootCopy`.
- **A drain touches only its own cycle dir,** so a concurrent lane's claims are never released. Pinned by `TestReleaseCycleProcessing_ReleasesScopedCycle`.
- **The claim floor (ADR-0074).** `Claim` is the one physical handoff to a lane. It refuses a console-routed item even when triage names it. Prompts advise, and the mover enforces.
  - `route:"console-*"` always refuses. `IsProtectedPath` adds the files-derived rule. The roots wire it to `laneForbidden`, which composes `guards.IsProtectedScope` with the sandbox denials ([internal-lanerouting](internal-lanerouting.md)). A nil value disables only that rule.
  - A malformed item stays `ErrNotFound`, never `ErrConsoleRouted`.
  - Pinned by `TestClaim_RefusesConsoleRoutedItem`, `TestClaim_RefusesProtectedFixSurfaceItem`, `TestClaim_LaneOverrideClaims`, `TestClaim_MalformedItemUnchangedContract` and `TestOptionsMover_ThreadsEverySeam`.
  - `RouteConsole` rewrites a refused item in place as `route:console-manual`, so every later lane is refused too (`TestRouteConsole_NamesTheFacadeAndRoutesThroughOptions`).
  - `File` is how the operator files an item. The claim floor, the batcher and triage load such an item cleanly (`TestFile_FilesAnItemTheClaimFloorCanHandToALane`).
  - The kernel minters (`faillearn`'s retrospective floor and `ciwatch`) still write their items directly. Readers still accept the shapes that those produce, until they converge through `retro-minting-files-through-inbox-add`.
  - `RouteLane` is the inverse of the operator. It writes `route:"lane"` only when the claim floor will then hand the item to a lane. It judges with the same `Options.IsProtectedPath` (`TestRouteLane_LetsALaneClaimAPipelineRepairItem`, `TestRouteLane_JudgesWithTheOptionsLanePredicate`). It keeps an earlier `routed_reason` in the new one (`TestRouteLane_KeepsTheReasonOfAnEarlierRoute`).
- **A PASS always drains.** Promote errors are collected and joined after the residual drain, never returned early, so one failed promote cannot strand the other claims. `go/acs/cycle1157` pins the behavior.
- **A FAIL claims before it drains,** because the drain bumps only what sits in `processing/cycle-N/`. An id this cycle already claimed counts as claimed and is not re-claimed from the root (`TestClaimLaneScope_AlreadyClaimedIdIsNotANotFoundClaim`). An id that cannot be claimed is skipped, so a partial claim never aborts a lane (`TestClaimLaneScope_ToleratesUnresolvableIDs`).
- **A routed id accrues no failure.** `CycleOutcome.RoutedIDs` names the ids that a closeout routed. The drain skips the bump for each of them and bumps the others (`TestMover_Release_ARoutedIDIsNotBumpedAndTheOthersAre`). `Routed` still skips the bump for the whole cycle.
- **`EditHeld` edits the claim of the caller.** It applies the edit verb only to an item in the claim directory of the given cycle. It refuses an item that another cycle holds. It also refuses an item at the root. The inbox has no lock, so a lane claim inside the read-and-rename window of a root edit makes a second copy. The FAIL closeout uses it to add a `deps` entry before the release (`TestMover_EditHeld_EditsTheCyclesOwnClaimInPlace`, `TestEditHeld_AddsADepToTheItemThatTheCycleHolds`).
- **`RouteConsoleValue` is the route value of the console.** It is the value that `RouteConsole` stamps, so a filer that authors the console route writes the same value (`TestRouteConsoleValue_IsTheRouteThatRouteConsoleStamps`).
- **Only the committed set accrues failures** (`TestApplyCycleOutcome_FailDrain_BumpsOnlyCommittedIDsAlreadyInProcessing`). A nil committed set bumps the whole cycle dir. A system-level failure never quarantines (`TestReleaseWithQuarantine_SystemLevelNeverQuarantines`, `TestShouldQuarantine_NamesThePredicate`).
- **Root failure accounting was retired.** Under 06-F2 in cycle 1864, `RecordRootTaskFailure` and its `.bump.lock` were deleted.
- **Preserve, then release.** A binding's value is written into the retired item's `released_continuations[]` before the registry entry is deleted. So a crash between the two leaves a live binding plus a preserved copy, never a lost pointer. The delete is `DeleteRegistryEntryIfCycle`, so a sibling lane that rebound the scope in between keeps its fresh binding. Pinned by `TestReleaseContinuationBinding` and `TestPromote_ReleasesBindingAndPreservesPointer`.
- **Every release names its authority.** `released_by` sits beside `released_at` and `reason`, because a binding is lineage that the defect-ledger gate reads as anti-tamper evidence. An erasure that names no actor is itself the defect (ADR-0089 amendment). Runtime paths name themselves (`runtime (inbox retirement)`). Pinned by `TestReleaseContinuationBinding`.
- **Host paths are redacted** (`continuation.RedactHostPaths`) before a pointer is preserved, because the item rides the ship commit to a public remote. Only the worktree and findings paths change; the snapshot, base and branch refs that salvage resumes from are untouched.
- **A scoped lane adopts only its own claims,** or two lanes work one task. An unscoped cycle stays scope-blind. Pinned by `TestResolveContinuationForScope_DoesNotAdoptAPeerLanesClaim`, `TestResolveContinuationForScope_ContinuesPastAPeerClaimToItsOwn` and `TestResolveContinuationForScope_UnscopedCycleIsUnchanged`.
- **Retirement needs positive evidence.** A binding is released only when its id sits in a retirement dir and in no live place (the root or a claim). Absence is not death, because carryover lane scopes never have an inbox file. Pinned by `TestResolveContinuationForScope_NoItemAnywhereStillAdopts`, `TestResolveContinuationForScope_ClaimedItemIsLive` and `TestResolveContinuationForScope_RetiredDirsAreNotLive`. An item deleted outright leaves no evidence; the write-side retire is the primary fix and this guard is the belt.
- **Recency.** A retired copy older than its binding is stale evidence: the item was re-filed and rebound since, and releasing on it destroys live preserved work. Unknown (0) is not stale, because the ordinary quarantine copy carries no stamp. Pinned by `TestResolveContinuationForScopeRecency` and `TestReconcileConsumedBindings`.
- **One list of retirement states.** `retirementStates` feeds both `ResolveDispatchState` and the retire scan. Each state is scanned flat and nested, so no layout change hides a retired item from one reader but not the other. The dispatch gate fails open on unknown, so a state missing from the list relaunches retired work. Pinned by `TestRetirementStates_CoverEveryRetiredStateOnce` and `TestResolveDispatchState`.
- **A pending state carries the live path.** Auto-minted ids are stable per category, so `consumed/` accumulates same-id namesakes and a bare id is unsafe to hand to an agent. A processing state carries the path of the claimed record in `processing/cycle-N/`. A reader that opens the item after the claim moved it finds it there. Pinned by `TestResolveDispatchState_PendingCarriesTheLivePath`, `TestResolveDispatchState_ProcessingCarriesTheClaimedPath` and `TestResolveDispatchState_NonPendingCarriesNoPath`.
- **A promote of a missing source is a no-op, not an error.** This contract comes from the deleted `ship.sh`. A destination mkdir failure is `ErrMvFailed` with the item left in place. Pinned by `TestPromoteResult_NamesNoOpWhenMissing` and `TestPromote_MkdirFailsLoudly`.
- **An id no inbox item backs is retired by record.** `Promote` no-ops on it, so the PASS seam retires each id that it did not move through `RetireUnbacked` (`processed/cycle-N/[<sha8>-]<id>.json`, reason `ship-promote-processed: no inbox item backs the id`). The planned no-work closeout retires every such scoped id as rejected with the lane's answer. The door writes only for an id whose dispatch state is unknown. So an inbox-backed item keeps its own lifecycle, and a retired id is never written twice. A FAIL never writes, so the id stays retryable (ADR-0106 W1).
  - Pinned by `TestRetireUnbacked_RetiresOnlyIDsWithNoLifecycleEvidence`, `TestRetireUnbacked_ReportsAWriteFaultAndRetiresTheRest`, `TestApplyCycleOutcome_PassRetiresACommittedIDNoInboxItemBacks` and `TestApplyCycleOutcome_FailRetiresNoUnbackedID`.
- **Goldens are never regenerated by a flag.** A drift is a declared deviation in its own commit. The goldens template the root, the pid and the chained `prev_hash`, which covers absolute paths.
- **Source-scanning tests read this package.** `TestOptionsMover_OneConstructionSite` counts the leaf's constructor call in non-test sources, `TestInboxMoverPrefix_OneHome` counts the quoted legacy prefix, and `TestUnobservedLedgerRootsArePinned` counts ledger constructions in `inboxmover.go`. A comment that spells one of those calls or literals changes their counts.

## Findings

- **cycle-598** (`inbox-promotion-requires-landed-ship`): `Promote` keyed promotion on the caller's verdict alone. A push-rejected ship whose recovery still reported PASS promoted to `processed/` a commit that no ref contained, so the directive was dropped while reported done. That added the landing probe (unlanded goes to `retry/`) and the `unlanded` release reason.
- **cycles 1706, 1709, 1710, 1713** (wave 15): cycle 1706 committed and shipped `gittest-fixture-centralize`, an id its triage authored with no inbox item behind it. The promote no-op'd, and no retirement dir ever held the id. The wave planner keeps an id with no lifecycle evidence, so it re-pinned the id as a lane in 1709, 1710 and 1713. Each of those lanes shipped nothing. The retirement record closes the class (ADR-0106 W1, [logic-first-delivery-design.md](../logic-first-delivery-design.md) §5.6).

## Rules kept from code comments

- **Consumption retires only close-class drops.** `closedDropReasons` lists the only drop reasons that consumption may retire. An unknown reason keeps the item pickable. So does `stale`. A live todo outranks a stale one.
- **A reason is classified by the text before its first `:`.** So `stale: superseded by X` stays stale.
- **`dropped[]` has two sibling readers with other policies.** They are `triageDroppedIDs` in carryover and `committedset.DispositionsFrom`. A schema change must land in all three.
- **A `Closes-Inbox` marker is anchored to a line start.** An optional markdown bullet may precede it. The match ignores case. A mention in the middle of a sentence is not a marker. Too much consumption loses data.
- **The id pattern drops anything that is not an id.** A `<id>` placeholder is an example. A documented example must never consume a real item.
- **Retirement releases the binding loudly and never blocks.** It preserves the continuation pointer before it releases. A crash then cannot lose the pointer.
- **The preserved pointer rides the ship commit to a public remote.** Host paths are redacted first.
- **The delete happens only if the binding is still this cycle's.** A fresh rebinding of a sibling lane survives.
- **A malformed released-continuations list is replaced.** The entry that is written now is the one that matters.
- **A scope is live only at the inbox root or in a claim.** The batch loader can pick it from those places only.
- **Only positive evidence of a retired copy counts.** Carryover lane scopes never have an inbox file. A retired copy with no stamp is unknown, not stale. The ordinary quarantine copy has no stamp.
- **A copy older than its binding was re-filed and rebound since.** A release on it destroys live work. A re-filed live copy owns the binding.
- **A binding is a ghost when its scope is retired and has no live copy.** It is released, so it stops re-arming.
- **A scoped lane skips the claims of a peer lane.** Two lanes must not work one task. A lane that declares no ids stays scope-blind.
- **A claim that this cycle holds is not claimed again from the root.** That raises a false not-found.
- **Dispatch state resolves the newest cycle first.** A hit is almost always recent, and the nested trees only grow.
- **A bare id is unsafe to give to an agent.** Ids repeat across `consumed/` namesakes. A pending state carries the path of the live record.
- **`retirementStates` is the one list for every "has this id retired" reader.** The list is in resolution order. The dispatch gate fails open on unknown. A missing state relaunches a retired item.
- **`releaseCycleProcessing` stays unexported.** `ApplyCycleOutcome` stays the one door into the failure drain. A second entry point lets PASS and FAIL drift.
- **The failure drain claims first.** It bumps only what sits in `processing/cycle-N/`.
- **`IsLandedFn` fails open.** `shaLandedOnMain` answers exit 0 as landed and exit 1 as unlanded. Any other answer is landed, with the error. A missing git never blocks a promotion.
