# internal/inboxmover

> Decision records: [ADR-0079](../adr/0079-cycle-outcome-inbox-lifecycle-seam.md) (one cycle-outcome seam), [ADR-0089](../adr/0089-continuation-retirement-and-live-scope-guard.md) (retirement releases the continuation binding), [ADR-0074](../adr/0074-typed-signal-contracts-routing-authority.md) (the console-routing claim floor) and [ADR-0072](../adr/0072-system-failure-policy-and-halt.md) (the retry ceiling and quarantine). The lifecycle leaf, this seam, the goldens and the preserved quirks: [decomposition unit 06](../decomposition/06-inboxmover.md). The `Closes-Inbox:` marker: [inbox-injection-protocol.md](../inbox-injection-protocol.md). This page keeps the host-package detail those do not.

## Purpose

`internal/inboxmover` hosts the inbox lifecycle: `inbox/` → `processing/cycle-N/` → `processed/`, `rejected/`, `retry/`, `quarantine/`, or back to the root. The movers themselves live in the `lifecycle` leaf. This package owns `Options` and its defaults, builds the leaf's `Mover`, and applies each cycle's verdict (`ApplyCycleOutcome`). It also holds the readers that sit beside the lifecycle: the triage-decision readers, the `Closes-Inbox:` parser, dispatch-state resolution and the continuation-binding trio.

## Design

- **A seam over a leaf.** `Options` is a value copied at every entry point, so there is no host object to cache a `Mover` on. `(Options).mover()` resolves the defaults and builds one per call. It is the only non-test construction site (`TestOptionsMover_OneConstructionSite`). Each exported mover is a one-line facade, so the cmd layer, the ship phase and the ACS predicates keep their spellings (`TestFacades_KeepEverySpelling`).
- **Defaults.** `InboxDir` is `<root>/.evolve/inbox`. `LedgerPath` defaults to `<root>/.evolve/ledger.jsonl`, but only its directory is used, because the chained `FileLedger` owns its file names. That fallback ledger is the one unobserved ledger construction `TestUnobservedLedgerRootsArePinned` (cmd/evolve) allows in this package. `ActiveCycleFn` reads `cycle_id` from `.evolve/cycle-state.json`. `IsLandedFn` runs `git merge-base --is-ancestor <sha> main`.
- **The landing probe.** Exit 0 means landed and exit 1 means unlanded. Any other answer (128 for a non-git root, an unknown sha or no local `main`) and any exec fault fail open as landed, and the error is returned so the leaf reports `INBOX_LANDED_CHECK_FAILED`. Delivery evidence gates a promotion; missing git must not invent a false negative. The probe runs only for a processed promotion that carries a commit sha.
- **Two voices.** With `Options.Signals` set, the leaf's faults become `inbox.warning` events. With it nil, the leaf prints the legacy `[inbox-mover]` line instead, so a Center-less root (the post-ship mover, the operator commands) loses nothing. The sibling files here print through `logf`, which uses the leaf's one `LegacyPrefix` (`TestInboxMoverPrefix_OneHome`).
- **Exit codes** are the cmd layer's map over the sentinel errors. The sentinels are the leaf's own pointers, so `errors.Is` holds across the seam.
- **One door for a cycle's verdict.** `ApplyCycleOutcome` handles PASS and FAIL. `releaseCycleProcessing` stays unexported so the failure drain has no second entry point, and `TestLifecycle_OnlyHostImportsTheLeaf` keeps the leaf's `Release` behind this package. PASS promotes the committed ids to `processed/cycle-N/` from wherever they are, then drains the cycle's remaining claims to the root. FAIL claims the committed ids into `processing/cycle-N/` (`ClaimLaneScope`); the drain then bumps `failure_count` on those ids only and quarantines any that reach the ceiling. Uncommitted menu ids release untouched. ADR-0079 explains why the claim happens at outcome time and not at dispatch.
- **Retire by id.** `SupersededInboxIDs` reads triage's `superseded[]`, and `ReconcileSuperseded` promotes each id on its own, independent of the committed set, so an item that shipped under a different id leaves the root. `ReleaseCycleProcessingWithReason` lets a drain caused by an unlanded ship record a reason carrying `unlanded`, so the ledger tells a delivery-failure retry from an ordinary residual drain.
- **Triage-decision readers.** `CommittedIDs` (top_n ids plus skip_shipped task ids) is the one worked-set reader both closeouts use. `DeferredIDs` names ids consumption must never retire. `ClosedDroppedIDs` retires only drops whose reason leads with a close-class tag: `already-shipped`, `already-done`, `already-landed`, `duplicate`, `superseded` or `obsolete`. Triage also drops valid work (`requires-split`, `out-of-scope`) and stale premises, and an unknown reason keeps the item too, because forgetting a live todo is worse than carrying a stale one.
- **Three readers of `dropped[]`.** `ClosedDroppedIDs`, `triageDroppedIDs` in `internal/core/carryover` (reason-blind, for the carryover store) and `committedset.DispositionsFrom` (a drop with a reason ends a fleet lane as planned no-work) parse the same field with three deliberate policies. A schema change to `dropped[]` must land in all three. The follow-up `decision-document-single-declaration` would give them one declaration in the stdlib-only `committedset` leaf.
- **`Closes-Inbox:` markers.** `ClosesInboxIDs` parses a build report. A line whose first non-blank content, after one optional markdown bullet (`-`, `*` or `+`), is the marker in any case contributes its comma-separated ids. Ids are trimmed of whitespace and backticks and must match `[A-Za-z0-9._-]+`, so a `<id>` placeholder is dropped. The result is deduped in first-seen order. A mention mid-sentence contributes nothing. Closure is an explicit marker rather than inferred from the diff, because an item's `connects_to` is a hint, not an acceptance predicate: inference would consume items an unrelated diff brushed past. Over-consumption is silent data loss; under-consumption costs one bookkeeping cycle.
- **Dispatch state.** `ResolveDispatchState` re-resolves a planned id against the live lifecycle just before a lane launches. It lives here because this package owns the lifecycle dirs, so the fleet and cmd layers stay layout-agnostic. The inbox root means pending (with its deps and live path), `processing/cycle-N/` means processing, then each `retirementStates` dir is checked flat and then by `cycle-N`, newest first, because a hit is almost always recent. No evidence means unknown. Unreadable evidence counts as none, so a bad inbox can only fail open at the gate.
- **The continuation trio** (`continuation_release.go`, `continuation_resolve.go`, `continuation_retire.go`) implements ADR-0089. `ReleaseContinuationBinding` is the one release transaction, shared by the retire hook, the read-side guard, the consumed-corpus sweep and `evolve continuation release`. `resolveClaim` walks the cycle's claims in filename order and returns the first stamped one the lane's scope admits. `ResolveContinuationForScope` then falls back to the registry for the lane's ids, in declared order so a re-run resolves the same binding. A claim that merely exists never suppresses the fallback; only a stamped one does. An entry with no snapshot sha is not a binding. A corrupt registry resolves to nil with a loud line, because the orchestrator must never crash mid-cycle over a salvage index.
- **The consumed-corpus sweep.** `ReconcileConsumedBindings` runs before every cycle dispatch on the blocker-breaker path. It is O(consumed items) with a registry read per bound id, and `consumed/` is never pruned, so revisit the cost if the corpus grows by an order of magnitude.
- **`RecordRootTaskFailure`** is the root-resident twin of the drain's bump: it bumps `failure_count` where a root item lives and quarantines at a positive ceiling. It has no production caller today, and it is a second quarantine writer without the drain's continuation shed or ledger line (decomposition unit 06, follow-up 06-F2).

## Invariants

- **Every lifecycle move is one `os.Rename` on one filesystem,** so an item is never in two states at once. The leaf pins the movers.
- **Lifecycle ledger lines are chain participants.** They go through the chained `FileLedger` append (flock, `prev_hash`, `entry_seq`, atomic tip update), never a raw append. Pinned by `TestLedgerWrites_AreChainValid` and `TestLedgerAppender_SatisfiedByFileLedger`. Ledger writes are best-effort: a failed append never blocks a move.
- **A drain never clobbers a root copy.** An item whose basename already sits at the root (a concurrent release got there first) is warned about, skipped and not counted as recovered. Pinned by `TestInboxRelease_DoubleClaimRaceIsWarn`, `TestReleaseCycleProcessing_DoubleMove_NotCountedAsRecovered` and `TestReleaseCycleProcessing_NilStderrNoPanicOnDoubleMove`. `RecoverOrphans` deliberately has no such guard, a preserved quirk pinned by `TestRecoverOrphans_ClobbersExistingRootCopy`.
- **A drain touches only its own cycle dir,** so a concurrent lane's claims are never released. Pinned by `TestReleaseCycleProcessing_ReleasesScopedCycle`.
- **The claim floor (ADR-0074).** `Claim` is the one physical handoff to a lane, so it refuses a console-routed item even when triage names it: prompts advise, the mover enforces. `route:"console-*"` always refuses. `IsProtectedPath` (wired to `guards.IsProtectedScope` at the roots) adds the files-derived rule, and nil disables only that rule. A malformed item stays `ErrNotFound`, never `ErrConsoleRouted`. Pinned by `TestClaim_RefusesConsoleRoutedItem`, `TestClaim_RefusesProtectedFixSurfaceItem`, `TestClaim_LaneOverrideClaims`, `TestClaim_MalformedItemUnchangedContract` and `TestOptionsMover_ThreadsEverySeam`. `RouteConsole` rewrites a refused item in place as `route:console-manual`, so every later lane is refused too (`TestRouteConsole_NamesTheFacadeAndRoutesThroughOptions`).
- **A PASS always drains.** Promote errors are collected and joined after the residual drain, never returned early, so one failed promote cannot strand the other claims. The code keeps a one-line why; `go/acs/cycle1157` pins the behavior.
- **A FAIL claims before it drains,** because the drain bumps only what sits in `processing/cycle-N/`. An id this cycle already claimed counts as claimed and is not re-claimed from the root (`TestClaimLaneScope_AlreadyClaimedIdIsNotANotFoundClaim`). An id that cannot be claimed is skipped, so a partial claim never aborts a lane (`TestClaimLaneScope_ToleratesUnresolvableIDs`).
- **Only the committed set accrues failures** (`TestApplyCycleOutcome_FailDrain_BumpsOnlyCommittedIDsAlreadyInProcessing`). A nil committed set bumps the whole cycle dir. A system-level failure never quarantines (`TestReleaseWithQuarantine_SystemLevelNeverQuarantines`, `TestShouldQuarantine_NamesThePredicate`).
- **Root failure accounting serializes.** The inbox root is shared, so `RecordRootTaskFailure` takes the inbox-level `.bump.lock` and re-resolves the item inside it. An unserialized read-modify-write loses attempts and can rename a stale copy back into the root after another lane quarantined it, defeating the ceiling in exactly the contended case it exists for. The lock wait is bounded at 30 seconds, because accounting is best-effort and a wedged sibling must cost an error, not a hang. No test pins the lock, so the code keeps a one-line why at both points.
- **Preserve, then release.** A binding's value is written into the retired item's `released_continuations[]` before the registry entry is deleted, so a crash between the two leaves a live binding plus a preserved copy, never a lost pointer. The delete is `DeleteRegistryEntryIfCycle`, so a sibling lane that rebound the scope in between keeps its fresh binding. Pinned by `TestReleaseContinuationBinding` and `TestPromote_ReleasesBindingAndPreservesPointer`.
- **Every release names its authority.** `released_by` sits beside `released_at` and `reason`, because a binding is lineage the defect-ledger gate reads as anti-tamper evidence, and an erasure that names no actor is itself the defect (ADR-0089 amendment). Runtime paths name themselves (`runtime (inbox retirement)`). Pinned by `TestReleaseContinuationBinding`.
- **Host paths are redacted** (`continuation.RedactHostPaths`) before a pointer is preserved, because the item rides the ship commit to a public remote. Only the worktree and findings paths change; the snapshot, base and branch refs that salvage resumes from are untouched. The code keeps a one-line why.
- **A scoped lane adopts only its own claims,** or two lanes work one task. An unscoped cycle stays scope-blind. Pinned by `TestResolveContinuationForScope_DoesNotAdoptAPeerLanesClaim`, `TestResolveContinuationForScope_ContinuesPastAPeerClaimToItsOwn` and `TestResolveContinuationForScope_UnscopedCycleIsUnchanged`.
- **Retirement needs positive evidence.** A binding is released only when its id sits in a retirement dir and in no live place (the root or a claim). Absence is not death, because carryover lane scopes never have an inbox file. Pinned by `TestResolveContinuationForScope_NoItemAnywhereStillAdopts`, `TestResolveContinuationForScope_ClaimedItemIsLive` and `TestResolveContinuationForScope_RetiredDirsAreNotLive`. An item deleted outright leaves no evidence; the write-side retire is the primary fix and this guard is the belt.
- **Recency.** A retired copy older than its binding is stale evidence: the item was re-filed and rebound since, and releasing on it destroys live preserved work. Unknown (0) is not stale, because the ordinary quarantine copy carries no stamp. Pinned by `TestResolveContinuationForScopeRecency` and `TestReconcileConsumedBindings`.
- **One list of retirement states.** `retirementStates` feeds both `ResolveDispatchState` and the retire scan, and each state is scanned flat and nested, so no layout change hides a retired item from one reader but not the other. The dispatch gate fails open on unknown, so a state missing from the list relaunches retired work. Pinned by `TestRetirementStates_CoverEveryRetiredStateOnce` and `TestResolveDispatchState`.
- **A pending state carries the live path.** Auto-minted ids are stable per category, so `consumed/` accumulates same-id namesakes and a bare id is unsafe to hand to an agent. Pinned by `TestResolveDispatchState_PendingCarriesTheLivePath` and `TestResolveDispatchState_NonPendingCarriesNoPath`.
- **A promote of a missing source is a no-op, not an error** (the ship.sh compatibility contract), but a destination mkdir failure is `ErrMvFailed` with the item left in place. Pinned by `TestPromoteResult_NamesNoOpWhenMissing` and `TestPromote_MkdirFailsLoudly`.
- **Goldens are never regenerated by a flag.** A drift is a declared deviation in its own commit. The goldens template the root, the pid and the chained `prev_hash`, which covers absolute paths.
- **Source-scanning tests read this package.** `TestOptionsMover_OneConstructionSite` counts the leaf's constructor call in non-test sources, `TestInboxMoverPrefix_OneHome` counts the quoted legacy prefix, and `TestUnobservedLedgerRootsArePinned` counts ledger constructions in `inboxmover.go`. A comment that spells one of those calls or literals changes their counts.

## Findings

- **cycle-598** (`inbox-promotion-requires-landed-ship`): `Promote` keyed promotion on the caller's verdict alone. A push-rejected ship whose recovery still reported PASS promoted to `processed/` a commit that no ref contained, so the directive was dropped while reported done. That added the landing probe (unlanded goes to `retry/`) and the `unlanded` release reason.
- **cycle-308** (`inbox-promote-on-ship-missing`): items claimed into `processing/` stranded when a cycle failed or a claimed item fell out of top_n on a PASS; orphans had piled up from cycles 124, 234, 240, 243, 248, 265, 294 and 295. That produced the scoped, idempotent `ReleaseCycleProcessing` and its double-move guard, and later the always-run residual drain (ADR-0079, cycle-1157 amendment).
- **cycles 544–548**: a prose-only carryover instruction ("verify vs HEAD, move to consumed") silently lapsed. Cycle 544 shipped the fleet-starvation observer as `recover-ship-fleet-starvation-observer`, stranding its originating request `loop-self-prioritize-unmet-fleet-concurrency` at the root. That produced the data-driven `superseded[]` declaration and `ReconcileSuperseded`.
- **cycle 767** (`dispatch-freshness-gate`) introduced `ResolveDispatchState`. Quarantine and then `consumed/` were missing from it in turn; in cycle 1682 a shipped item resolved unknown, survived both prunes and the launch probe, and was re-pinned to a lane, because `processed/cycle-N/` was read flat (ADR-0079 amendments).
- **2026-08-11 ledger forensics**: the old raw `O_APPEND` lifecycle line was the fleet-concurrency chain-break generator and defeated the rebaseline seal. See [the incident](../../incidents/2026-08-11-verify-wave-halts-and-ledger-forensics.md).
- **`Closes-Inbox:`**: #453 landed `schema-aligned-salvage-layer` without consuming its item, and wave cycle-1448 re-picked the shipped work. See [inbox-injection-protocol.md](../inbox-injection-protocol.md).
- **The immortal-binding class** (cycles 1484/1487/1497, ADR-0089): a parked scope re-dispatched for three waves from a binding nothing released. The cycle-1507 audit then found that the read-side delete skipped preservation and sent the pointer to stderr only (H2), trusted stale evidence (H1; 7 of 91 real bindings on the runtime plane would have been destroyed) and leaked host paths into a public commit (M1). Cycle 1515 moved the transaction into one function. Cycle 1558 recurred through the operator consume, which moved the file but not the binding ([incident](../../incidents/2026-08-25-manual-consume-immortal-binding.md)).
- **cycle-1536**: a scoped lane adopted a peer lane's stamped claim, shipped its eval file and cost cycle-1535 its landing. The lane's own claim was unstamped and skipped, which is what let the peer's win. See [runtime-reference](../../operations/runtime-reference.md), "Continuation adoption is lane-scoped".
- **cycle-1548**: the dispatched scope id resolved to 17 records, one live and sixteen consumed namesakes. The resolver had the live path in hand and dropped it; the agent name-searched the tree, and every phase report cited a consumed record from a halt cured two weeks earlier. That added `DispatchState.Path`.
- **cycle 1675** (the 2026-09-14 poison loop): `ClaimLaneScope` re-claimed ids the lane already held and raised a false `INBOX_CLAIM_NOT_FOUND` on every closeout, and `RouteConsole` became the breaker. See [the incident](../../incidents/2026-09-14-triage-refusal-poison-loop.md).
- **F40 architecture review** (cycle 1691): `stale` used to be close-class, which would have let a lane's PASS consume a stale-dropped menu-mate unverified, and a substring match read any mention of a close-class word as retirement. Classification moved to the leading tag. The re-review found 6 of 16 real close-class reasons are hyphen-joined (`already-shipped-in-797b8518`), so an exact-match rule would have dropped them. See [the incident](../../incidents/2026-09-26-stale-premise-reached-build.md).
- **Root-resident accounting** (landed with the ADR-0080 slices, #372, though that ADR does not describe it): wave lanes never entered `processing/`, so graded FAILs bumped nothing; workspace-hygiene burned 12 lanes and quarantine-dead 7 with `failure_count` still 0. That produced `RecordRootTaskFailure`, and its review found the unserialized read-modify-write race that the bump lock closes.
