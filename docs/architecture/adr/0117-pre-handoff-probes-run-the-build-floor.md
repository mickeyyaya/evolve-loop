# ADR-0117 — The builder's pre-handoff probes run the build handoff floor itself

- **Status:** Accepted (2026-10-01). Console landing on branch `fix/pre-handoff-probes-run-the-floor`, revised the same day after the architecture review (FIX_THEN_MERGE: the floor's file protected, one resume projection, the unused floor constructors removed, one state read and one probe). Consumes inbox `pre-handoff-probes-run-the-build-floor`.
- **Amends** [ADR-0076](0076-convergence-architecture.md) slice B (`evolve selfcheck build` ran "the floor's exact checks") and [ADR-0034](0034-unified-deliverable-contract.md) (`evolve phase verify` shares the host gate's verifier): both probes now also run the build handoff floor, with the floor's own inputs.
- **Related:** [the build handoff floor](../packages/internal-core.md) (`internal/core`); [the composition root](../packages/cmd-evolve.md); [`evolve phase verify`](../packages/internal-cli-phasecmd.md); retrospectives of cycles 1763, 1764 and 1788 (lessons `inst-L1763a`, `inst-L1764b`, `inst-L1788b`).

## Context

A builder has two probes it runs before handing off: `evolve selfcheck build` (the persona's mandatory pre-flight) and `evolve phase verify build` (the self-check line every Deliverable Contract prints). Both are meant to predict the build handoff floor, the deterministic reviewer that rejects a build before audit. Three cycles in 25 failed on a floor check that a probe had just reported green:

| Cycle | Probe | Probe said | The floor said |
|---|---|---|---|
| 1763 | `selfcheck build` | GREEN | `Explanation Documentation: Changed Areas does not explain material path go/internal/core/phase_bindings_selfcheck.go` |
| 1764 | `selfcheck build` | GREEN | `./acs/cycle1761 (-tags acs): unit tests FAIL` |
| 1788 | `phase verify build` | OK | `Explanation Documentation: build-report.md is missing the required ## Explanation Documentation section` |

Each probe held its own, weaker copy of what a valid handoff is:

- The floor was composed in three places: core's mandatory explanation reviewer (`NewBuildExplanationReviewer`, run only when the cycle's explanation contract is active), the composition root's `productionBuildFloorChecks` (protected surface, the default deterministic engine, the repo-contract pack), and a document cycle's solution floor chained in `cmd_cycle.go`.
- `selfcheck build` ran only `productionBuildFloorChecks`, with only `Worktree` set. With no base SHA it diffed against `HEAD`, which is empty once the builder commits, and it skipped the added tag-gated package run (1764). With no cycle, run id or contract version it could not run the explanation floor at all (1763).
- `phase verify build` ran the deliverable contract and the docs floor, and none of the build handoff floor (1788).

This is the replicated-belief defect the campaign retrospective names: two copies of one rule, and the copy the agent can see is the weaker one.

## Decision

1. **One named check set.** `core.BuildHandoffFloor` is an ordered list of `core.BuildFloorCheck{Name, Run}`. It is a Composite: `Failures` runs every check in order on one input and returns every failure line, `Names` lists the checks, and the list is itself a `DeliverableReviewer` whose `Review` judges build handoffs only and rejects with the floor's usual reason (`build handoff floor: N deterministic check failure(s) — …`), so the correction ladder reads the same text. It is the only floor constructor: the opaque `NewBuildFloorReviewer(fn)`, `NewBuildExplanationReviewer()` and `ChainBuildFloorChecks(...)` are gone, the first folded into `Review`, the others replaced by the list.
2. **Two halves, one list, one order.** Core owns the mandatory half, `MandatoryBuildHandoffFloor()` (the explanation-documentation check, which now skips a cycle whose contract version is 0 itself, as the mandatory reviewer decides). The composition root owns the composed half, `composedBuildHandoffFloor(workflow, routing config)`: `productionBuildFloorChecks`, plus the document solution floor when the registry declares a document contract, and nothing when `workflow.build_floor` is off. `core.WholeBuildHandoffFloor(composed)` is the mandatory half followed by the composed half, the order the cycle runs them in.
3. **The cycle mounts the list.** `cmd_cycle.go` appends the composed half itself to the reviewer chain. The mandatory reviewer runs the mandatory half. No floor engine is composed anywhere else.
4. **One build self-check.** `phasecmd.BuildSelfCheck{Floor, Probe}.Verify` is the one probe: it reads the cycle binding once, judges the deliverable contract on `deliverable.RootsFor` of that input (the projection the host contract gate uses), and runs the whole floor on the same input, each floor failure a violation with the code `build_handoff_floor` in the floor's own words. `evolve phase verify build` and `evolve selfcheck build` both call it; they differ only in how they locate the binding and print the result. The floor comes from `probeBuildHandoffFloor(projectRoot)`, which builds `WholeBuildHandoffFloor(composedBuildHandoffFloor(...))` from the project's `policy.json` and registry with the loaders the cycle uses, behind one seam (`buildHandoffFloorFor`). `phasecmd` cannot import `cmd/evolve`, so the composition root injects it (`phasecmd.NewRunPhase(floor)`, Dependency Injection); `phasecmd.RunPhase` is gone, so no entry point runs `phase verify` without it. The builder is told to run one: the persona names the Deliverable Contract's rendered self-check, `evolve phase verify build`, and says `selfcheck build` is the same probe. That was the smaller change: re-rendering the self-check for build would have changed a renderer every phase prompt shares, and `selfcheck` would still have needed the contract half.
5. **Same inputs, one projection.** `core.ReviewInputFor(cs, phase, projectRoot)` is the one projection of a cycle's binding (cycle, run id, contract version, base SHA, workspace, worktree, project root) into the floor's input. The orchestrator's live and resumed review paths build their input with it, and the probes build theirs with it from the persisted state. It is total on resume because the resume bootstrap sets a legacy checkpoint's missing `cycle_id` to the resumed cycle once, instead of each caller patching its copy. The correction ladder reads its worktree from that input too, not from the dispatch-time snapshot. `core.ReadRunCycleState(workspace, evolveDir)` is the one reader of that state (the run workspace's `run.json`, else the evolve dir's cycle-state file; a cycle worktree's `.evolve/cycle-state.json` is a symlink to its run's `run.json`). `core.BuildHandoffProbe.Input()` reads it, refuses a state that binds a different worktree than the one asked about, and projects it. `phase verify` resolves from `--workspace`; `selfcheck` resolves from the worktree's `.evolve`. The project root is `EVOLVE_PROJECT_ROOT`, which the host exports to every phase session. With a binding, the contract half judges the bound workspace and worktree, so the host gate's stray-artifact check sees the cycle's worktree even without `--worktree`.
9. **Every check reports at the host's severity.** With a binding, the contract half runs exactly the host contract gate's checks (`deliverable.VerifyWithStage`), not the self-check-only ADR-0077 docs violation. The docs floor reaches the builder through the floor half, which is the host's own `docsFloorWarn` with the host's `docs_floor` policy stage, so it prints the host's `[docs-floor] WARN` line and never fails the self-check while the host only warns. When the host promotes the docs floor to blocking, the self-check follows with no edit here. Without a binding there is no host floor to match, so an explicit `phase verify build --worktree` keeps the ADR-0077 addendum's blocking docs check (cycle 1150's contract, unchanged).
6. **No binding is said, never hidden.** When the probe cannot bind the cycle (no state, or a state for another worktree), it runs the contract and the floor on the unbound input (the flags it was given), prints a WARN naming why, and never prints `safe to hand off`.
7. **The equality is tested at the composition root.** `Orchestrator.BuildHandoffFloorNames()` walks the reviewer chain: the mandatory reviewer's half and every `BuildHandoffFloor` mounted in the chain, nested chains included. `TestBuildHandoffProbes_IterateTheCycleFloorsCheckList` builds the real orchestrator with `wireOrchestratorDeps` and requires its list to equal the probes' list.
8. **The floor's file is protected surface.** `go/internal/core/build_handoff_floor.go` holds the mandatory half, the walker, the review and the input projection, so it is a `guards.ProtectedSurfaceManifest` row like its neighbours `build_floor_reviewer.go`, `reviewer.go` and `resume.go`.

## Alternatives considered

| Alternative | Why it was not chosen |
|---|---|
| Pass the worktree base SHA to `selfcheck` (the cycle-1764 todo) | Fixes one input on one probe. The explanation floor (1763) and `phase verify` (1788) stay blind. |
| Teach the build contract the `## Explanation Documentation` section (cycle 1788's first recommendation) | A second copy of one floor rule inside the contract gate: the same class, one rule smaller. |
| Move the composed floor into `internal/phases/build` so `phasecmd` imports it directly | Moves the protected-surface predicate, ship's pack and their test seams out of the composition root, and makes every `phasecmd` unit test run `go test` in its fixtures. |
| A package-level setter in `phasecmd` that `cmd/evolve` fills at init | Mutable global state that depends on init order; the constructor injection is explicit and testable. |
| Mount the whole floor in one reviewer owned by the orchestrator | Truest to "one reviewer", but it reorders the mandatory wrapper and the optional chain on the orchestrator's review path. The named list and the walker give the same guarantee with no change to the cycle's review order. Left open. |
| Refuse (exit 2) when the probe cannot bind the cycle | Breaks operator use outside a cycle and every contract-only `phase verify` test. A WARN plus no "safe to hand off" claim is honest without it. |

## Consequences

- A probe costs what the floor costs: `phase verify build` now runs the changed packages' tests too. The persona names one probe, so a builder runs the floor once per iteration. The host never reuses a probe's result: the floor recomputes at handoff.
- A passing explanation check writes the derived `build-explanation.json` handoff, as the floor does. The floor rewrites it at handoff and the seal revalidates it, so a probe's copy is never trusted on its own.
- `selfcheck build` now runs the document solution floor on a document cycle (it mirrored the code floor only), and it diffs against the cycle's base, so committed work is visible (the known gap F38 in the composition root's notes).
- A check added to either half reaches both probes with no other edit. The list is the only floor constructor in the tree, so any floor the cycle mounts is a list the walker names, and one the probes lack fails the equality test. The residual gap: a list hidden inside another reviewer type (a struct wrapping it) is invisible to the walker; review has to catch that shape.
- A loop cycle cannot empty the floor: `build_handoff_floor.go` is on the protected surface, so the build floor, ship's tripwire and the lane claim refusals treat an edit to it as control-plane work.
- A resumed legacy checkpoint now persists its resumed cycle number, where it kept `cycle_id: 0` before.
- The ADR-0077 addendum's docs floor in `phase verify build` applied only with `--worktree`, which the rendered self-check never passes, so it never ran for a builder. A first revision of this ADR applied it to the bound worktree as a blocking violation, which made the probe stricter than the host floor (a red probe on a green floor wastes builder turns and pushes a correction nothing on the host demands). It now reports at the host's severity instead (decision 9): a bound architecture-class diff with no docs gets the host's `[docs-floor] WARN` line and exits 0. The two docs checks also classify differently: the host counts any `docs/` path (so a cycle's own explanation document satisfies it), the self-check-only one counts `docs/architecture/` and the runtime reference.
- The rest of the contract half matches the host only under the live dials: the host gate blocks at `contract_gate=enforce` (the compiled default; the checked-in policy sets no gate keys) and its report-size check only WARNs at the default `report_size_gate=shadow`. Under other dials, or while the gate's breaker has demoted it, the host's severity differs (stricter or weaker); aligning those needs the host's stage projection and breaker state in the probe and is filed as a follow-up.
- The mandatory explanation check now gates itself on the contract version. It returned the same result through the mandatory reviewer before, which already skipped version 0.
