# ADR-0119 — One routing table, one resolver

- **Status:** Accepted (operator, 2026-10-05: the design in [cli-routing-table-2026-10.md](../../plans/cli-routing-table-2026-10.md)). L1a built the resolver unwired (PR #770); L1b (2026-10-06) wires every launch path through it. The operator's own table lands in L2; the legacy keys are retired in L3.
- **Amends:** [ADR-0029](0029-cli-fallback-chain-and-per-agent-overrides.md) (the per-agent chain is no longer each launcher's own `llmroute.Resolve` call) and [ADR-0104](0104-fallback-is-a-property-of-the-bridge-handle.md) §2–3 (the universal tail and its family ban are applied by the resolver, once, not by the discovery closure and each walker).
- **Related:** the package notes [internal-cliroute.md](../packages/internal-cliroute.md); [internal-llmroute.md](../packages/internal-llmroute.md) (the plan primitives the resolver composes); [ADR-0104](0104-fallback-is-a-property-of-the-bridge-handle.md) (the walk stays a property of the bridge handle).

## Context

The operator subscribes to Claude Code and agy only, with no codex, and asked for one place that says which CLIs exist, which CLI does each kind of work and what happens when a chain runs out. Two problems stood in the way:

- **Eleven launch paths each built their own chain.** The runner's `resolveDispatchPlan`, the bridge chain's `DefaultPlanResolver`, the retro's `resolveCLI`, the advisor's `resolveRouterDispatch*`, contract escalation, `resolvellm.Resolve` (subagent run, `resolve-llm`, the failure advisor, setup detect), the loop preflight's `distinctDrivers` and the model classifier's `classifierCLIPreference` each read the profiles, env and policy their own way. They shared a lookup function, not a decision, so a control honoured by one path was ignored by another (`pins.builder` never applied; the preflight halted on codex whatever the config said).
- **The controls disagreed.** Pins were keyed by role in setup and by phase in the runner, a pin was a lock that dropped the probe, bench and tail, the universal tail and its family ban lived in a discovery closure, and `router.cli/model` fed only the advisor.

## Decision

1. **One table.** The `cli_routing` block in `.evolve/policy.json` declares the CLIs (`clis`), the chain for any work (`default`), per role (`work.<role>`) and per agent (`agents.<agent>`), a per-tier ceiling (`tiers.<tier>`) and what follows a chain (`after_chain`). When the block is absent, the *legacy projection* reproduces each of today's resolvers byte for byte, pinned by `go/internal/cliroute/testdata/legacy-plans.golden.jsonl` and `legacy-advisor.golden.jsonl`.
2. **One resolver.** `internal/cliroute` is the only package that builds a CLI chain. Every launch path calls `Router.Resolve` (or `Router.ResolveRole` for a role-level answer). A request names the agent, the phase (empty for a phase-less launch) and, for the two launches whose legacy semantics differ, `Request.Launch` (`advisor`, `classifier`), so the legacy projection reproduces that launch exactly while a declared table answers every launch from the same rules. `TestOnlyCliRouteBuildsChains` (`internal/guards`) bans every chain builder outside `cliroute`, `llmroute` and `resolvellm`: `llmroute.Resolve`, `ApplyUniversalFallback`, `ChainFor`, `ExcludeFamilies` and `AllowedDiscovered`, and `resolvellm.Resolve`. It refuses a dot-import of `llmroute` or `resolvellm`, since a dot-import would hide those calls from the scan. It admits one named, file-pinned exception: `internal/core/advisor/launch.go`'s `llmroute.ChainFor`, the advisor's own walk, which L2 question 1 replaces with the table's chain. `TestChainBuilderAllowlist_EveryEntryIsStillNeeded` fails when that exception is no longer used.
3. **Compile once, refuse at start.** One profiles directory routes a project, `<project>/.evolve/profiles` (`routingProfilesDir`), the one the runner always read, whatever `--evolve-dir` or the plugin root say. Each process that dispatches (`evolve cycle run`, `evolve loop`, `evolve subagent run`, and `resolve-llm`) loads the policy and compiles the table once at its composition root (`cmd/evolve/cli_routing_root.go`), with the merged phase catalog and `bridge.HasToolUse` as the tool-capability check. A malformed `policy.json` or any error finding exits 2 before the first dispatch; the per-phase FAIL on a bad policy is gone. Beside a declared block, every legacy routing key is a second source and an error finding: `pins`, `workflow.universal_fallback(_exclude)`, `router.cli`, `router.model`, and `router.plan_model` / `router.propose_model`, which would otherwise swap the advisor's tier after the table decided it. `Resolve` never re-reads profiles: the snapshot taken at `Compile` is what every launch of the run sees.
4. **A mint recompiles.** A profile minted mid-cycle is invisible to a table compiled at start, so the catalog publisher that re-binds the contract resolver after a mint also calls `Router.Recompile` with the new catalog. The swap is atomic; a recompile that would carry an error finding is refused, logged loudly, and the table compiled at start keeps routing.
5. **Bypass is a second table, not a branch.** The Router holds the declared table and a bypass table compiled from `policy.Policy{Workflow: loaded.Workflow}`. `Request.BypassPolicy` picks the table, so `--bypass-policy` ignores the pins (and any `cli_routing` block) but keeps the workflow's universal tail, as today, and never the profile ceilings.
6. **One home for the tail's family ban.** Discovery hands the resolver the raw list of present, tool-capable drivers; the resolver applies `workflow.universal_fallback_exclude`. `universalFallbackTail` no longer filters.
7. **An unreachable chain is a system failure, a wall is capacity.** A walk the tier ceiling empties launches nothing and returns `llmroute.ErrNoPermittedAttempt` with `Walled` false. Both walkers (the runner's dispatch and `bridgechain.Walking.Launch`) now surface it through one rule, `bridgechain.Unlaunched`, as a loud FAIL naming the rule, the chain, the tiers and the ceiling. A walk that met a quota wall still goes to the existing quota-pause path.

## Consequences

- **No behaviour change without the block.** The checked-in `.evolve/policy.json` has no `cli_routing` block, so every plan is the legacy projection: the runner and bridge-chain golden (2208 records) and the advisor golden (96 records) are byte-identical through the wired launch paths.
- **Small, intended legacy differences, each recorded in the plan's L1b landing notes:**
  - the advisor's benched swap walks the router's chain instead of a hard-coded `claude-tmux` (the legacy chain ends with that `claude-tmux`, so the result changes only for a router profile with a `cli_fallback`);
  - contract escalation picks from the chain the runner walks (probe, bench and tail included);
  - the retro names the CLI the walk actually launches first, and it honours `EVOLVE_RETROSPECTIVE_CLI` like every other agent (its old `resolveCLI` read only `EVOLVE_CLI`);
  - the legacy probe and tail reorders, and the root's cli-health bench lines, are logged by `cliroute` with a `[cliroute]` prefix, replacing the runner's own `[runner]` lines;
  - `evolve subagent validate-profile` compiles the table at start and exits 2 on a refusal, like the dispatching roots;
  - `profileForModelRouting` reads a minted phase's own `<phase>.json`, so the model-routing clamp now applies to phases outside the built-in table;
  - `evolve models` live refresh fails when the routing table refuses to route the model classifier, instead of falling back to the old classifier order;
  - the preflight probes and boots the resolved chains' drivers.
- **Read-only verbs.** `evolve cli-routing show [--static] [--json]`, `check` (0 clean, 1 on an error finding, 2 on usage) and `explain <agent>` render the table. The write verbs (`set`, `unset`, `init`, `migrate`) and the env/`--cli` guard are L2.
- **Cost.** Each dispatching process lists and loads every profile once at start, and `evolve subagent run` and `resolve-llm` also load the phase catalog. The runner no longer reloads `policy.json` per dispatch.

## Verification

- `TestLegacyDispatchPlans_MatchTheGolden` (runner and bridge chain through `Router`), `TestResolve_AbsentTableMatchesLegacyGolden` (cliroute directly) and `TestLegacyAdvisorDispatch_MatchesTheGolden` (the advisor root) keep the goldens byte-identical.
- `TestOnlyCliRouteBuildsChains` was red on the pre-L1b tree (11 references) and is green after. It also bans `llmroute.ChainFor`, `ExcludeFamilies` and `AllowedDiscovered` and every dot-import of a chain-building package, with one named allowlist entry (the advisor's walk, open for L2).
- `TestProductionRouter_ReplaysTheLegacyGolden` replays the golden through the production composition root (`buildCLIRouter` + `routingHost`, a fake doctor report with a banned, a toolless and a blocked driver), and `TestOneProfilesDirectory_ThePreflightAndTheCycleCompileTheSameTable` pins one profiles directory per project for every root.
- Per launch path: `TestResolveDispatchPlan_TheInjectedRouterDecidesThePlan`, `TestDefaultPlanResolver_DeclaredTableOutranksCallerCLI`, `TestRetro_DispatchesTheResolverPrimary`, `TestContractEscalation_PicksFromTheTable`, `TestRouterDispatch_ComesFromTheTable`, `TestFailureAdvisor_ComesFromTheTable`, `TestClassifierOrder_ComesFromTheRoutingTable`, `TestDetect_RendersEachRoleFromTheInjectedTable`, `TestDistinctDrivers_FollowsTheResolvedChains`, `TestPreflight_CliRoutingHaltsOnAFinding`.
- Start-up refusal and recompile: `TestWireOrchestratorDeps_AnErrorFindingRefusesBeforeAnyDispatch`, `TestRunCycleRun_ARefusedRoutingTableExitsTwo`, `TestRunLoop_ARefusedRoutingTableExitsTwo`, `TestRouter_RecompileSeesAProfileMintedAfterBuild`, `TestCatalogPublisher_RecompilesTheRouterOnAMint`.
- The empty walk: `TestDispatchPhaseAttempts_AWalkThatLaunchesNothingIsALoudSystemFail` and `TestWalking_AWalkThatLaunchesNothingSurfacesTheError`, both red on the pre-L1b code (0 launches, exit 0, nil error).
