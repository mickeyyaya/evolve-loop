# ADR-0114 — The ACS verdict is always written and complete, and predicates run in the suite's own environment

- **Status:** Accepted (2026-10-01, console lane `fix/acssuite-run-and-report`)
- **Supersedes nothing.** Amends how [ADR-0042](0042-egps-v11-go-native-predicates.md)'s Go predicate lane reports a scope that could not run, and extends [ADR-0053](0053-dual-root-source-state-resolution.md)'s dual-root exports into a whole environment policy.
- **Related:** [`internal/acssuite` design notes](../packages/internal-acssuite.md); [`internal/phases/audit` design notes](../packages/internal-phases-audit.md); [`internal/acsrunner` design notes](../packages/internal-acsrunner.md); [`internal/policy` design notes](../packages/internal-policy.md); [runtime reference, `evolve acs suite`](../../operations/runtime-reference.md). Consumes inbox items `acs-verdict-always-written-with-reason`, `acssuite-no-results-hides-exec-error`, `acssuite-relative-evolvedir-litter`, `acssuite-seam-mode-respells-the-cycle-package` and `acssuite-lane-env-policy` (its predicate half; the rest is filed as a follow-up).

## Context

The ACS verdict (`acs-verdict.json`) decides whether a cycle ships: `red_count == 0` is the only path to PASS. Five defects in how `internal/acssuite` ran predicates and reported the result shared one shape: the suite could fail to execute and the artifact would not say so.

1. **No verdict when the suite could not run.** A predicate package that did not compile, declared tests that never ran, and a scope with no results each made `acssuite.Run` return an error. The audit then wrote no verdict, and on a suite with zero predicates it deliberately wrote none, so the missing-file floor would fail the cycle. The floor held, but in cycle 949 the only diagnostic was `acs-verdict.json: read: no such file or directory`; the real cause (`undefined: core.WithJudgeModel`) sat in the retrospective's log. PR #535 carried the compiler excerpt into `audit-fail-reason.json`, but the artifact still said nothing, and `evolve acs suite` on a tree with no predicates wrote a zero-result PASS and exited 0.
2. **A deadline reported as an empty package.** The lane runs every scope under one context bounded by `acs.go_timeout_s`. In cycle 1762 a `-count=50 -race` cycle predicate spent the 600 s budget, the next scope's `go list` died on the expired context, and the report said only `active predicate scope "./acs/regression/apicover" produced no execution results`; the no-results branch dropped the error that explained it. Whether the budget was per scope or shared was nowhere stated.
3. **The lane's IPC environment reached every predicate.** The predicate environment was `os.Environ()` plus the suite's keys, so a fleet lane's `EVOLVE_FLEET`, scope, width and cycle-state file reached every predicate and every inner `go test` a meta-predicate shells: the 2026-09-14 incident (ship ran `go test` in the lane's environment) through another spawner, found root-causing cycle 1700.
4. **Relative roots.** An invocation from `<worktree>/go` resolved the CLI's default `--evolve-dir .evolve` against that cwd and wrote a phantom `go/.evolve/runs/cycle-104/acs-verdict.json`. With no project root the suite also read its budget from a cwd-relative `.evolve/policy.json`: a wrong-root read.
5. **Two spellings of a cycle package.** The seam branch built `./acs/cycle%d` by hand instead of calling `CyclePackage`, the package's one documented spelling.

## Decision

1. **`acssuite.Run` returns an error only for options it cannot run at all** (no root, a cycle that is not positive, a root it cannot make absolute). Every other outcome is a `Verdict`.
2. **What kept predicates from producing evidence is a harness red in that verdict.** A harness red is a result whose `ac_id` starts with `acsverdict.SyntheticRedPrefix` (`egps/`, the prefix the parse-error and incomplete-test reds already used), with exit code 1, the reason in `evidence_excerpt` and the full text in `acs-red-evidence/`:
   - `egps/no-predicates` when there is no predicate tree, no active scope for the cycle, or no scope produced a result;
   - `egps/go-lane-scope-failed/<scope>` when a scope exited nonzero with no red of its own, when declared tests never ran, or when the lane budget ran out. The scope's own results stay beside it.

   A harness red is an ordinary red to every reader, so `red_count == 0 ⟺ PASS` and the ship rule are unchanged, and the verdict passes `acssuite.ReadVerdict`'s consistency checks as a FAIL the ship gate refuses.
3. **The audit always writes the verdict.** `generateACSVerdict` no longer skips a zero-predicate suite. `readACSVerdict` collects the harness reds with their excerpts, and the `red_count>0` diagnostic appends the first one's reason, so `audit-fail-reason.json` names the cause. The missing-file floor stays as the backstop for a generator that could not write. The verdict-incoherence floor needs no change: a harness red makes the verdict FAIL, which is coherent with a recorded FAIL.
4. **The lane budget is one deadline shared by every scope.** A scope that finds it spent is never started and is reported as such; a scope the deadline killed says the budget expired while it ran. Shared, not per scope, because the suite holds the host-wide single-flight lock (`internal/verifylock`, see the acssuite design notes) for its whole run; a per-scope budget over some forty scopes could hold the lock far past `maxLockWait`, turning every sibling lane unserialized.
5. **Predicates run in the suite's own environment.** `predicateEnv` starts from `ipcenv.Scrub(os.Environ())` and adds two named sets, which together are the allowlist:
   - the suite's own exports: `EVOLVE_PROJECT_ROOT`, the worktree-root key and `CHANGED_PACKAGES`. When the caller names no project root, the state root is the suite root, not whatever the caller's environment held;
   - the operator-owned keys the state root's `.evolve/policy.json` names in `acs.predicate_env`, copied from the host environment when set. They are operator runtime state, not lane IPC, and a predicate gate reads them. The checked-in policy names one, `EVOLVE_FLAG_CAMPAIGN`, which activates the [ADR-0063](0063-autonomous-loop-integrity-hardening.md) `flagprogress` gate. Only the state root's policy is read; a cycle worktree's own `policy.json` cannot widen the list (`TestRun_ACycleWorktreesPolicyCannotWidenTheForwardedKeys`).

   The rule is: strip every `EVOLVE_` key except the suite's exports and the operator keys the policy names. The suite's export keys are also removed from the host environment, so a caller's stale `CHANGED_PACKAGES`, which the scrub alone would keep, never reaches a predicate.

   **The list is bounded, in one place** (`acssuite.forwardableKeys`): an entry that is a lane protocol key (`ipcenv.ProtocolKeys()`: fleet, scope, width, the worktree-root key, the cycle-state file and the tmux socket, which moved into `ipcenv` for this) or one of the suite's own exports is refused. The refusal is a warning, not an error: the key is not forwarded, `[acs] WARN` names it on stderr, the verdict's `warnings` carry `acs.predicate_env names <key>, …; it is not forwarded`, and the other entries still forward (`TestRun_APolicyCannotForwardALaneProtocolKeyOrASuiteExport`). It happens when the lane reads its policy, not in `policy.Load`, for three reasons: `policy.Load` serves every loop consumer and its error fails the phase runner, so one bad ACS entry would stop the loop; the suite's export keys are `acssuite`'s names, which the policy package cannot import without a cycle; and refusing a single entry keeps the flag-campaign forward alive, where a load error would drop the whole block. The reverse holds too: every checked-in entry is read by some curated predicate (`TestCheckedInPredicateEnvNamesOnlyKeysACuratedPredicateReads`). `TestCuratedPredicatesReceiveEveryEvolveKeyTheyRead` keeps it honest for the curated scopes: it finds every constant `EVOLVE_` key a regression or red-team predicate reads through `os.Getenv` or `os.LookupEnv` and fails when the projection under the checked-in policy drops one. The sibling spawners of the same artifact and class use `ipcenv.Scrub` alone, since neither runs a predicate that reads an operator key: `acsrunner` (`evolve acs run`, whose `go test` carries no `-tags acs`) and both `go test` runners in `releasepreflight` (through one `goTestCommand`, unit suites only).
6. **Every path is absolute before it is used.** `Run` makes its roots absolute and resolves every `.evolve/` read and write under one state root (the project root, else the suite root). `WriteVerdict` refuses a relative evolve dir. `evolve acs run|suite` resolve `--evolve-dir` to an existing directory and exit 10 otherwise.
7. **A run that executed nothing never reads as a pass, and both writers say so the same way.** `acsrunner` records a run with no predicate as the same `egps/no-predicates` red, so the red is in `red_ids` from either writer (`TestNoPredicates_BothVerdictWritersNameTheSameHarnessRed`). The names both writers share live in a leaf package, `internal/acsverdict`: `Filename`, `Path` (which refuses a relative evolve dir), `SyntheticRedPrefix` and `NoPredicatesID`. `acsrunner` imports that and `ipcenv` only, not `acssuite` and its seventeen internal dependencies, and `acssuite` keeps no aliases: every reader moved to the leaf. `evolve acs run` exits 1 when its `go test` exited nonzero with no predicate red to explain it.

## Alternatives considered

| Alternative | Why it was not chosen |
|---|---|
| Keep the error and also return a verdict (`Run` returns both) | Keeps the CLI's old exit 1 for a compile error, but the contract ("a verdict is meaningful beside a non-nil error") cannot be stated in code under the no-comments rule, and a caller that follows Go's convention and drops the value on error would lose the artifact again. One channel is clearer: the verdict carries every outcome. |
| A `zero_predicates: true` field on the verdict, as the item proposed | A second source of truth beside `red_count`, which every reader already gates on. `ReadVerdict` rejects a verdict with no results, and a FAIL with `red_count 0` is exactly the ambiguous shape `acsrunner`'s incomplete runs already cause the ship's consumption gate to guard against. The harness red names the condition in the `red_ids` every reader already prints. |
| A per-scope deadline | Bounds each scope but not the lane, so the single-flight lock could be held for many multiples of `maxLockWait`. |
| Refuse a bad `acs.predicate_env` entry in `policy.Load` | Fails every policy consumer, the phase runner included, for an ACS-only mistake, and drops the whole block (the flag-campaign forward with it); the policy package also cannot see the suite's export names without an import cycle. Refusing at projection with a named warning keeps the bound in the one package that owns both halves. |
| Make a refused entry a harness red | Blocks every cycle on an operator config slip whose effect the refusal already removed. A warning in the verdict is visible without stopping the loop. |
| Scrub only the named IPC keys (`EVOLVE_FLEET`, scope, width, cycle-state) | A key added tomorrow would leak until someone remembered to list it; `ipcenv.Scrub` drops the namespace, which is the rule the ship gate and the build floor already use. |
| Name the operator keys (`EVOLVE_FLAG_CAMPAIGN`) as a Go constant in `predicateEnv`, as the architecture review proposed | The repository's own gates read a production Go literal of an `EVOLVE_` key as an operator-dial reader: `regression/flagreaders` and `regression/envtaint` both fail on a key with no `flagregistry` row (probed 2026-10-01), so every cycle's regression scope would go red. A row cannot be added: `len(flagregistry.All)` is at `FlagCeiling` (26), and the zero-flags rule forbids raising it. Declaring the key in `internal/ipcenv`, which both gates skip, would hide an operator dial among IPC constants. The policy is where an operator setting belongs, and `.evolve/` is outside both scans. |
| Require the evolve dir's basename to be `.evolve` | The litter was `go/.evolve`, which has that basename. Refusing a relative path in the writer and a missing directory in the CLI catches the class. |

## Consequences

- An operator reading `acs-verdict.json`, `acs-red-evidence/` or `audit-fail-reason.json` sees why predicates could not run. No layer reports a missing verdict for a suite that ran.
- `evolve acs suite` exits 2, not 1, for a compile error, a missing predicate tree or a spent budget, and writes a FAIL verdict; exit 1 now means the suite could not run at all or the verdict could not be written.
- A scope's harness red counts in its own scope's `predicate_suite` bucket (a regression scope's in `regression_suite_count`, the red team's in `red_team_count`); `egps/no-predicates`, like the parse-error red, counts in `this_cycle_count`.
- A predicate that relied on an inherited `EVOLVE_` key other than the suite's exports and the policy's named keys no longer sees it; one that needs such a key for itself sets it with `t.Setenv`. The keys the predicates read (every `os.Getenv` and `os.LookupEnv`, checked 2026-10-01):
  - the red team reads `EVOLVE_PROJECT_ROOT` (`redteam/predicates_test.go:27`, `redteam/cycle_dossier_test.go:81`);
  - `regression/flagprogress` reads `EVOLVE_FLAG_CAMPAIGN` (`progress_test.go:163`, through the const `campaignEnvKey`). The first version of this change stripped it, which turned the ADR-0063 strict-reduction gate off during a flag campaign: under `EVOLVE_FLAG_CAMPAIGN=1` a cycle that deleted no registry row got verdict PASS with the gate skipped, where it had been FAIL (found by the architecture review). The policy's `acs.predicate_env` now forwards it;
  - no other curated package reads an `EVOLVE_` key (the `envtaint` matches are fixture source inside string literals);
  - cycle packages read `EVOLVE_PROJECT_ROOT`, the worktree-root key (`cycle1632`), and keys they set on their own children (`cycle1684`, `cycle1765`).
- `EVOLVE_FLAG_CAMPAIGN` is still an environment flag. Moving the campaign state to config under the state root, so the forward is no longer needed, is filed as a follow-up (`flag-campaign-state-as-config`).
- **Not covered here, filed as a follow-up:** one `go test` environment projection pinned across every production spawner by an AST test; the tmux pane's inherited cycle-state override in the bridge; and the audit of the direct cycle-state spellings that bypass `paths.CycleStateFileFor`.
