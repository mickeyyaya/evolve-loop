Ship & release

Four commit classes, one attestation chokepoint, a release pipeline with rollback — and the binary-deletion defect that hid on the success path in July.

How it works today

ClassVerification (code: verifyClass in go/internal/phases/ship/verify.go)
cycleno control-plane edits (ADR-0064) + no weakened gates + audit↔tree binding + persona-lint
manualconfirm (a terminal, or the audited --auto-confirm=<reason> parameter, which replaces the old EVOLVE_SHIP_AUTO_CONFIRM env name) + commit-gate attestation (tree-SHA of the reviewed diff must equal the staged tree) + persona-lint
releasepipeline-only; audit skipped (version bump mutates files after audit)
trivialrequires trivial size estimate + zero pipeline-critical paths
  • The attestation chokepoint: a bare git commit or git push is hook-denied; ship commits internally, so the Go-side check (go/internal/phases/ship/commitgate.go) is the single enforcement point — a missing or stale attestation refuses the ship. Reviewers become durable Reviewed-by: trailers.
  • sync-main: merge-only reconciliation of diverged main (no rebase, no force, no push); refuses on live leases or uncommitted tracked changes (an untracked file never blocks it; a merge that would overwrite one is refused by git, tree unchanged).
  • Landing and a rejected push: today a lane lands its own work, and the console lands through evolve integration batch. The wave orchestrator that owns integration is the target, and its driver runs at shadow. GIT_FLEET_REBASE_NEEDED sends the cycle back to audit on the new base. GIT_PUSH_REJECTED, when origin has diverged from the local main, seals the cycle as FAIL; the item returns to the queue and evolve sync-main reconciles by merge. Thus a rejected push can cost a cycle.
  • Release pipeline (go/internal/releasepipeline/releasepipeline.go, DefaultSteps): preflight → changelog-gen → version-bump → rebuild-binary → consistency → atomic ship (evolve ship --class release) → marketplace-poll → release-verify, journaled per attempt for rollback. The pipeline does not verify GitHub CI. Run evolve ci watch --tag after a release. A failed marketplace poll or release verify rolls the release back. A red CI is fixed forward, not rolled back. The pre-flight reads the required.yml run of HEAD as an advisory check; --require-ci makes it fail. The no-WIP gate fails the pre-flight on a commit subject that starts with WIP, fixup!, squash! or amend! (docs/operations/runtime-reference.md).

How it got built

Ship-gate v8.13.0 ended a five-cycle parser-bypass arms race; the commit-gate’s bash runner was deleted only after a differential test proved the Go port byte-identical; the release CI hard-gate of cycle 748 followed a release that shipped on red CI. The release pipeline of v23.1.0 no longer verifies GitHub CI itself; evolve ci watch --tag does. Every door out of the repo has a story about someone (usually an agent) trying to walk around it.
