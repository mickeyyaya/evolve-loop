Phase pipeline

Phases are configuration; legality, spine, and the ship floor are kernel-validated code.

How it works today

  • The registry is the SSOT (docs/architecture/phase-registry.json, schema v4): 17 phases — intent, scout, triage, spec-verify, architecture-design, plan-review, tdd, build-planner, build, doc-sync, tester, audit, ship, secret-leak-scan, flake-rerun-scan, retrospective, memo. Spine order: intent → scout → triage → tdd → build-planner → build → audit → ship (then the sentinel end). Goal recipes insert conditional phases (coverage-gate, adversarial-review, scans…) per goal type; the single-word phase vocabulary is CLOSED (micro-phase-catalog.md). The registry also pins code-review between build and audit for a code cycle that touched files (conditional_mandatory, ADR-0124). That phase runs at shadow, because it uses the compiled default.
  • Orchestrator = bounded loop (go/internal/core/orchestrator.go): plan → select → dispatch → review → record, with a chokepoint-escape guard (ADR-0044) so no cycle can exit unrecorded. At the wave level, the fleet orchestrator and its admission run at enforce (fleet.orchestrator in policy.json).
  • State machine legality (go/internal/core/statemachine.go): explicit graph — audit→{ship,retro}, retro→{ship,tdd,end}, etc. Verdict branches resolve from each phase spec’s on_pass/on_fail.
  • Spine gate (StateMachine.SpineSatisfiedUpTo and UnsatisfiedSpineAnchor, statemachine.go): a mandatory anchor runs only if every earlier mandatory anchor left its gate satisfied (a real on-disk handoff artifact, or an accepted verdict). When the gate is not satisfied, the dispatcher keeps the static next phase (routing_dispatch.go). The 2026-07 note about a fail-open spine and 76 warnings is not re-verified here.
  • The floor is not config: router.DefaultShipFloor() = {tdd, build, audit} (go/internal/router/floor.go) — ship implies those ran, policy can relax only build/tdd (trivial class), never audit. The floor block of policy.json sets the policy side.
  • Contract gate: every phase’s deliverable is checked for well-formedness (path, sections, parseable verdict). The compiled default is enforce (ADR-0034, go/internal/config/config.go). The checked-in retry.contract_correction_retries is 1, so a blocked deliverable gets one correction re-dispatch.
Model proposes, kernel disposes — the LLM advisor proposes per-cycle phase plans and per-phase {cli, tier}; the router clamps every proposal against mandatory phases, insertion caps (registry default 6), profile envelopes, and the ship floor. Clamps are recorded (Clamp{Rule,Proposed,Forced}), never silent.
Stages today (policy file, 2026-11-07) — at enforce: isolation I-2, the fleet orchestrator and admission, comment_floor, docs_floor.ste_stage, failure_disposition, retrospectives, retry_ladder.audit_fix, builder_selfcheck and gc. At shadow: retry_ladder, audit_cascade, parallel_evaluate, regression_tia, inbox.curator, the code-review phase and the integration driver. A shadow stage records what it would do and changes nothing.

How it got built

ADR-0058/0060 made verdict branches, spine, legality and gates config-driven with a one-time ValidateSafetyInvariants trust anchor (go/internal/core/safety_invariants.go); ADR-0052 added goal recipes and post-scout replanning; ADR-0024 set the proposes/disposes doctrine (first live advisory cycle-108, default flipped to advisory after soak). The registry config.dynamic_routing value is now advisory. ADR-0124 added the code-review phase.
