# Build Explanation — Cycle 1813

## Build Binding
- Cycle: 1813
- Base SHA: 41e704a0f6540337a16b1fd35d5a7260f78889c7

## Summary
This build, the retry of cycle 1811, closes the silent paths in `go/internal/router` that the inbox item `router-silent-errors` reported. `PolicyForProject` now takes variadic `config.Option`s and loads the registry through `config.New(opts...)`, so a caller that passes `config.WithSignals` gets the loader's coded `CONFIG_REGISTRY_MALFORMED` / `CONFIG_REGISTRY_UNREADABLE` WARN, and the policy still fails open to the defaults. `Digest`'s error return, which was always nil, now has a real failure: a workspace that does not exist or is not a directory. `AssembleHandoffs` forwards that error. `retroDecision`'s three-arm switch becomes a default plus one exception. The triage `cycle_size` fallback and the git-fallback package count are named in code instead of explained by a comment, and the test helper `routeC1140` is renamed for what it does.

## Rationale
The inbox allowed either dropping `Digest`'s error or giving it a real failure. Dropping it would change the signature for five earlier cycles' ACS predicates (cycles 1623, 1633, 1637, 1638 and 1747 call `router.Digest` with two results). The builder role may not edit those predicates, so the regression suite would stop compiling. A workspace that is missing or is a file is a fault the digest could not detect before: it returned a clean, all-absent digest, and at spine-floor enforce a clean absence fail-closes the spine gate with a misleading "handoff artifact is missing" message. Each existing caller already handles the error and fails open, so the new failure needs no caller signature change; the spine gate's outcome on a missing workspace does change (see Compatibility). A failing Propose already emits exactly one coded WARN at the production proposer (`core/advisor`). A second router-level WARN would break the "one WARN" acceptance, so `LLMProposal.Decide` is unchanged.

## Design Decisions
The options seam reuses the existing exported `config.Option` and `config.WithSignals` instead of adding a router-level Center parameter, and it is variadic, so the four phase `ShouldSkip` callers (triage, tdd, swarmplan, buildplanner) keep compiling unchanged. None of them is wired to a Center: they receive only a `core.PhaseRequest`, and the composition root's wired loader (`wiredRoutingConfigLoader`) already emits the same registry WARN once per cycle, so wiring the hooks would repeat it up to four times. A second `config.New(` site is a deliberate change to an existing invariant. The acceptance requires a Center injected per call, and an `Option` only takes effect on a `Loader`, so some construction outside the root is unavoidable. Hiding it behind a new `config` helper would only dodge the textual pin, so the pin test now names both sites. The FilesTouched item was resolved by naming the value rather than splitting the field: `build.files_touched` is a routing condition read by the phase registry's plan-review trigger, and a split would silently stop the git fallback from feeding it.

## Compatibility
`Digest`, `AssembleHandoffs` and `PolicyForProject` keep their call shapes. A missing or non-directory workspace now yields an error instead of an empty digest, and every production caller already fails open on that error. That changes one outcome: at spine_floor=enforce, the spine gate in `go/internal/core/cyclerun_select.go` used to treat a missing workspace as a clean absence and abort the cycle fail-closed, and now it sees a digest error, so for a missing workspace the spine gate proceeds fail-open with a WARN that names the re-digest error. A missing workspace is a harness fault rather than a skipped phase, and the WARN now names the real cause instead of a misleading missing-handoff message.

## Limitations
`LLMProposal.Decide` still discards Propose's error, because the production proposer reports it; a future proposer that does not emit its own WARN would fail silently there. The phase hooks still load the registry without a Center. The comment above `wiredRoutingConfigLoader` in the composition root still calls it "the one construction of the Loader", which is no longer true now that `PolicyForProject` builds a second, caller-wired loader. That file is a protected control-plane path (ADR-0064), so a cycle cannot correct the comment; it is left to console work, and the pin test `TestRoutingConfigLoader_ConstructionSitesArePinned` is the authoritative record of both construction sites.
