## Summary
The package ratchet of `testlatency` now judges the CPU of each test binary after a host speed index. The wall of a package only has to stay under the `go test` timeout. Both CI ratchet steps fail a regression again.

## Rationale
Five CI runs showed that the wall of one package changes by 2.3 times with the host. The host class and the CPU speed explain 69.0% of the wall variance of `internal/bridge`. A wall limit therefore fails clean runs. A CPU value divided by a median speed index stays stable, and it still fails a real regression of 1.48 times or more.

## Design Decisions
The speed index leaves the judged package out of its own median. A regression in one package then cannot hide in the index. A package with fewer than three other reference packages is reported and never fails. A baseline of another OS never gates the host. The `class` field stays in the file as a checked label, so the 300 existing records need no rewrite.

## Compatibility
