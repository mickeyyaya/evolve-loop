# Build Explanation — Cycle 2425

## Build Binding
- Cycle: 2425
- Base SHA: 38bc28bc639269d8e738b125443e9ce24a44a869

## Summary
The fingerprint normalizer now folds glued cycle tokens, hex lane hashes, ULID suffixes, and file counts into stable placeholders.

## Rationale
Cycles 2049 and 2051 hit one build-floor defect and produced two fingerprints. The previous regex missed glued cycle numbers, letter-starting lane hashes, and file counts. Updating the token patterns in place fixes the split without a new configuration surface.

## Changed Areas
- `go/internal/core/failure_digest.go` — updates `cycleNumberToken` for glued cycle numbers, colon and underscore separators, and eight-char hex lane hashes, and adds `fileCountToken` for `<n> file(s)`.
- `docs/architecture/failure-identity-lifecycle.md` — updates section 3 to document `cycle=N`, `cycle-N-<ulid>`, `<n> finding(s)`, `<n> file(s)`, and the check-count identity rule.
- `docs/architecture/packages/internal-core.md` — records the AD3-1 normalizer update and its three pinned test functions.

## Design Decisions
One `fileCountToken` regex handles singular, plural, and `(s)` file counts, while `N deterministic check failure(s)` stays identity-bearing. Extending `cycleNumberToken` with an optional eight-char hex prefix keeps words such as `recycle` untouched.

## Verification
The `internal/core` package tests and all seven `cycle2425` ACS predicates pass with 100% statement coverage on `normalizeReasonForFingerprint` and zero added code comments.

## Compatibility
The digest schema, fingerprint prefix format, and `AssembleFailureDigest` signature do not change.

## Limitations
Non-hex lane hashes or file counts outside `<n> file(s)` remain unnormalized until a concrete failure shape requires them.
