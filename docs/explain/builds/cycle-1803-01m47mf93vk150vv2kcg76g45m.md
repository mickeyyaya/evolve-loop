## Summary
This build finishes the `evolve failures` record and adds `evolve salvage list`. `failures prune` gains `--dry-run`, which prints each expired entry and writes nothing. The real prune now also drops expired carryoverTodos. The prune runs the same expiry function as the loop's launch-time auto-prune but leaves out the per-batch bookkeeping. `failures list` shows each entry's expiry and the acknowledged fingerprints. The group's exit codes are now 0/1/2/10. `evolve salvage list [--json]` inventories the leaves `evolve gc` salvages under `.evolve/operator-salvage/`, and it reads them through one exported gc path helper and reader.

## Rationale
Two operator tasks needed a loop launch or hand work. Acking a fingerprint or pruning failedApproaches happened only as a side effect of `evolve loop`, and an operator had to list the salvage directory, read each HEAD and size each patch by hand. Cycle 1801 shipped list/reset/prune. This cycle adds what that record still lacked: a dry run, carryover expiry, expiry and the fingerprint ledger in `list`, the exit-code vocabulary, and documentation. The salvage inventory reads the layout through gc's own helper and file-name constants, so the writer and the reader cannot drift apart.

## Design Decisions
The dry run gets its own read-only `failurelog.PreviewExpired` instead of a `dryRun` flag on the prune functions, so no mutating function grows a no-write mode. It shares `isExpired`, and one test proves the two sets are equal. `pruneExpiredState` returns both step results instead of printing, so the loop keeps its `[loop] auto-prune:` wording while the verb prints its own. `landed` is computed in the CLI: gc's listing stays subprocess-free, and an unknown result never changes the exit code. An empty salvage directory prints nothing in both forms, which is the literal acceptance. I rejected `[]` for JSON on that ground.

## Compatibility
Two behaviours change, both covered by the contract's migration plan. First, state and ledger I/O errors from `failures list|reset|prune` now exit 2 instead of 1. Second, a leftover positional argument now exits 10 instead of being ignored. The missing-`--project-root` refusal still exits 1. The `list --json` shape and every loop stderr line are unchanged. `OperatorSalvageDir` was unexported, so the rename breaks no external caller.

## Limitations
`failures prune` and `reset` take no run lease, so they are between-batches tools. `salvage list` never fetches, so `landed` reflects the local `origin/main`. When gc re-salvages a leaf with an empty diff, an older `uncommitted.patch` stays in place, and the list reports what is on disk.
