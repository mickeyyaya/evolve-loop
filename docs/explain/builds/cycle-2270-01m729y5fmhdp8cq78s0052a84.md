# Build Explanation — Cycle 2270

## Build Binding
- Cycle: 2270
- Base SHA: 389887d3dedfaff4f8d43acfef79a744fd984292

## Summary
A continuation build now receives one line that tells if the salvage commit is already an ancestor of the project root HEAD.

## Rationale
An agent that resumes a salvage cannot know if the salvage already shipped. One `git merge-base --is-ancestor` call answers this. The answer is true, false or unknown, and unknown is never reported as false.

The line goes to the Build prompt only, because adoption runs after triage. The alternative was to give the line to scout, which needs adoption before triage. The tradeoff: Build gets the answer now, and scout does not.

## Changed Areas
- `go/internal/core/continuation_ancestor.go` — adds the probe and the context key. It reads the workspace manifest, validates the sha as hex, and runs the probe through the injected git runner.
- `go/internal/core/continuation_stamp.go` — serves the line into the Build context when a continuation is adopted.
- `go/internal/phases/build/build.go` — renders the served line in the prior-findings section, after the repair-first block.

## Design Decisions
A malformed sha never reaches git, so a manifest value cannot become a git option. A git failure maps to unknown. A fresh cycle has no manifest and carries no key, so its prompt does not change.

## Verification
The tests in `go/internal/core/continuation_ancestor_test.go` and `go/internal/phases/build/continuation_ancestor_prompt_test.go` pass. The cycle 2270 predicates pass.

## Compatibility
Prompts of cycles without a continuation are byte-identical.

## Limitations
The probe checks the local project HEAD only. It does not fetch the remote. The scout phase does not receive the line, because only the Build prompt renders it (`go/internal/core/continuation_stamp.go:232`, `go/internal/phases/build/build.go:67`).
