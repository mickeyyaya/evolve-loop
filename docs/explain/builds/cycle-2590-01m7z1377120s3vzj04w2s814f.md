## Summary
The PR-refresh integration test now reuses a `gittest.FromTemplate` fixture and runs only the `signals codes` and `docs index` real generators in-process. Its macOS wall time drops from 89.83 s to 1.33 s. The research doc now reports the measured split between clone, checkout, and generator runs.

## Rationale
A split timing run on macOS measured `git clone --no-checkout` at 0.8% (0.41 s) and `git checkout HEAD` at 15.6% (7.50 s). The eight `go run ./cmd/evolve` generator calls take 83.6% (40.28 s) of the 48.18 s run. Reusing a `gittest.FromTemplate` fixture alone cannot satisfy the 20 s budget while `go run ./cmd/evolve` compiles and runs `darwin-set` twice.

## Changed Areas
- `go/cmd/evolve/cmd_pr.go` — extracts `prRefreshWorktree` as a package-level variable initialized to `core.DerivedWorktree` so integration tests in `cmd/evolve` can substitute an in-process generator worktree without changing production behavior.
- `go/cmd/evolve/cmd_pr_refresh_integration_test.go` — replaces the full-repo `gittest.Clone` with a `gittest.FromTemplate` fixture holding only the `signal-codes` and `research-index` files, and invokes `runSignals` and `docsIndexVerb.run` in-process while skipping `ci darwin-set`.
- `docs/research/ci-wall-variance-2026-11.md` — replaces the unmeasured note on `TestPRRefresh_TheRealGeneratorsOfACloneCommitOnlyTheStaleIndex` with the measured shares, marks R7 done in cycle 2590, and adds section 6.5 with the step-by-step timings.

## Design Decisions
Running the real `signals codes` and `docs index` handlers in-process through `prRefreshWorktree` avoids eight `go run ./cmd/evolve` subprocess builds. Omitting `ci darwin-set` avoids two 6.8 s scans of the Go tree. `TestDarwinSetFile_MatchesTheSetDerivedFromTheTree` in `go/internal/ciparity/darwin_set_test.go` continues to verify `go/.darwin-set` against the full tree.
