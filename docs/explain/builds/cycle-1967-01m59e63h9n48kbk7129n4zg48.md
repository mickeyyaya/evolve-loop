# Build Explanation — Cycle 1967

## Build Binding
- Cycle: 1967
- Base SHA: 760e31c0b09474184355ac60e3d33a109fa9b8f5

## Summary
The orchestrator pool emits a warning when idle below the minimum lane count. The wave watch command prints pool transitions and loop wave warnings.

## Rationale
Wave 130 published idle pool events at partial capacity over three hours. The watch printed only per-cycle lines, which masked pool starvation.

## Changed Areas
- `go/cmd/evolve/cmd_loop_orchestrator.go` — passes fleet.min_lanes to the orchestrator pool builder.
- `go/cmd/evolve/cmd_wave_status.go` — reads signals and prints pool transitions and loop wave warnings in wave watch.
- `go/internal/fleet/pool.go` — tracks pending todo counts on every pool transition.
- `go/internal/orchestrator/orchestrator.go` — defines and registers the LOOP_ORCH_POOL_UNDERFILLED signal code.
- `go/internal/orchestrator/pool.go` — adds MinLanes to Pool and publishes a warning on underfilled idle transitions.
- `go/internal/wave/events.go` — adds the pool event kind and formats pool event details.

## Design Decisions
The pool emits a warning only when idle and live lanes fall below min_lanes. It suppresses the warning when the operator brake is engaged. The watch filters out events before the wave start and non-pool info signals.

## Verification
ACS predicates in cycle 1967 pass. Targeted unit tests in fleet, orchestrator, wave, and cmd/evolve pass without regressions.

## Compatibility
The changes extend existing event structures with backwards-compatible defaults. Existing consumers ignore the new signal code without disruption.

## Limitations
The underfill signal depends on configured fleet.min_lanes. If min_lanes is zero, the pool emits no underfill warnings.
