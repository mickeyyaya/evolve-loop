# Build Explanation — Cycle 2324

## Build Binding
- Cycle: 2324
- Base SHA: 2b3c322a0bfa08dbe198248734accf709d5bcfad

## Summary
CI now runs golangci-lint on each Go route. The required gate waits on that job. The CI job and the local commit gate use one config and one pinned version.

## Rationale
CI ran go vet, gofmt and tests, but not golangci-lint. Lint debt reached main. The local gate then refused a merge that touched the same packages. One job in the required workflow closes that gap.

## Changed Areas
- `.github/workflows/required.yml` — adds the golangci-lint job on the Go route. The job installs the version from the pin file and runs the plain `golangci-lint run`. The CI required job fails when the job result does not match the route.
- `go/.golangci-version` — the one home of the golangci-lint version.
- `go/.golangci.yml` — the header no longer says that CI skips golangci-lint.
- `go/cmd/vulnfilter/filter.go` — writes the summary with fmt.Fprintf and discards the close error of the summary file explicitly.
- `go/cmd/vulnfilter/main.go` — moves the logic of main into a run function that takes its streams and exit code, so a test can call it.
- `go/cmd/vulnfilter/main_test.go` — tests each exit path of run, main, the summary path and the open error.
- `docs/explain/builds/cycle-2324-01m75xcpse43jh979k9ted7914.md` — this document.

## Design Decisions
The workflow reads the version from the pin file with no second literal. The job has no flag that changes the config, so CI and the gate run the same command.

## Verification
The ACS predicates TestC2324_001 to TestC2324_006 pass. They run the gate script with each lint result, run the workflow command on a fixture with an unchecked error, and run it on main.

## Compatibility
No public API changes. A pull request with lint debt now fails CI.

## Limitations
The host binary must match the pin file. A change of the pin file needs a new host binary.
