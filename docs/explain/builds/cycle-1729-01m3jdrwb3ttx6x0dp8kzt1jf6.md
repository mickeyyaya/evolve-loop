## Summary
The new package `internal/rawgitratchet` is a repo-wide ratchet that fails when a test outside `internal/gittest` builds its own git repository. The existing call sites are listed per file with their site count in `baseline.json`: 133 files and 185 sites. The list may only shrink. The ratchet reads only git-tracked test files (index-staged included), so an untracked file never turns it red. The ship-time repo-contract scanner pack runs it, so a lane that adds a raw git fixture fails at ship with a named test failure instead of turning main red.

## Rationale
Cycle 1706 moved three flaky tests onto `gittest.Fixture` / `gittest.Bare`. The flake was git's detached maintenance child racing `t.TempDir()` removal. Nothing stopped a new raw fixture from appearing, so the class stayed open. Cycle 1725 built a ratchet, but its audit was WARN with M1: the ratchet walked untracked on-disk files, which violates ADR-0084 I1. That audit's lesson is the main change in this retry. Tracked files come from `internal/repostate`, the one I1 answer, and the ratchet falls back to reading every on-disk file only when git cannot list the tracked set. The list also counts sites per file, not just files. Without per-site counts, one more raw init in an already-listed file would pass unseen.

## Design Decisions
Tracked-set binding goes through `repostate`, not a private `git ls-files` call, because ADR-0084 says all real-tree scanners must share one source for I1. A per-directory `TrackedFiles` call would have kept `repostate` unchanged, but the module has 734 test directories and those calls took about 13s. One recursive `TrackedTree` call plus the scan takes about 0.3s. The baseline requires exact counts. A listed file that grows, shrinks or loses every site fails until its entry is updated, so a migration cannot free a slot for a new site. Only literals in call-argument or composite-element position count, which excludes near-misses such as `case "init":`. The git spawn is matched per directory, because a helper in a sibling file spawns git as surely as an inline `exec.Command`.

## Verification
All 12 cycle ACS predicates pass, and every negative predicate runs the real ratchet against a copy of the module. They check that literal, helper-wrapped, `cmd/` and same-file-extra sites fail with the file named, and that `internal/gittest` stays allowed. They check that migrated sites must leave the list and a migration frees no slot. An untracked site passes until it is staged, and a module outside git reads every file. The ship pack reports a named test failure, and apicover is clean. The package tests pass at 96.0% coverage, `repostate` at 93.1%, and the ship package suite passes with the fifth pack entry.

## Compatibility
The existing `repostate` exports behave as before: `TrackedFiles` returns the same direct-children set with the same error text. The shape of `repoContractPackages` is unchanged. Existing raw fixtures keep working: they are listed, not migrated.

## Limitations
Detection is lexical. An `init` argument built at run time, or git reached through a helper in a different directory or a non-test file, is not seen. A non-git `"init"` call argument in a directory whose tests spawn git is counted. Moving the 133 listed files onto `gittest` is follow-up work, and each migration lowers or removes its entry in the same diff.
