# Build Explanation — Cycle 2418

## Build Binding
- Cycle: 2418
- Base SHA: b3724ac1bc026e4f759920fbb436380843af21c1

## Summary
Added `changedpkgs.RunShadowTests` and `evolve test-scoped`. They run `go test` on packages changed against the branch merge base and their importers, strictly in shadow.

## Rationale
Lanes lacked a fast change-scoped test command. The new helper isolates branch edits from later `main` commits while keeping all gates on the full module.

## Changed Areas
- `go/internal/changedpkgs/shadowtest.go` — implements `RunShadowTests` with `git merge-base HEAD <baseRef>`, `ChangedFilesChecked`, `PackagesOf`, `ImporterClosureChecked` and `withoutAcs`.
- `go/internal/changedpkgs/shadowtest_test.go` — tests importer closure, `main` divergence, non-Go empty selection, failures and errors with `gittest.Fixture`.
- `go/cmd/evolve/cmd_test_scoped.go` — implements `runTestScoped` with `--base`, `--root`, and `--json`. It exits `0` on pass, `1` on failure, `2` on I/O error and `10` on usage error.
- `go/cmd/evolve/cmd_test_scoped_test.go` — covers JSON output, human output, failing test exit `1`, empty selection exit `0`, and usage/I/O errors.
- `go/cmd/evolve/registry.go` — registers the `test-scoped` subcommand.
- `docs/architecture/packages/internal-changedpkgs.md` — documents `RunShadowTests` and its merge-base and non-Go invariants.
- `docs/architecture/packages/cmd-evolve.md` — documents `evolve test-scoped` flags, exit codes, and shadow-only invariant.

## Design Decisions
Resolving `git merge-base HEAD <baseRef>` before `ChangedFilesChecked` isolates the lane from unrelated commits on `main` after the fork point without modifying `ChangedFilesChecked` or `GateScope`. An alternative of adding a merge-base flag to `GateScope` was rejected so existing gate behavior remains untouched and `test-scoped` stays strictly in shadow.

## Verification
Unit tests in `internal/changedpkgs` and `cmd/evolve`, cycle 2418 ACS predicates, `gofmt`, `go vet`, and `evolve docs ste-lint --strict` verify the implementation.

## Compatibility
All existing `floor`, `cover`, `ship`, and `audit` gates and `go/Makefile` targets remain unchanged and continue to target the full module.

## Limitations
The helper assumes a git repository with a reachable `<baseRef>` and a `go/` module directory under `--root`.
