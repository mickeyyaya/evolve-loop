# Build Explanation — Cycle 2535

## Build Binding
- Cycle: 2535
- Base SHA: 234383500cc7a7a113a70a9889b950ed247c6a6b

## Summary
`FlagKey` now keys on `action|branch` when `Branch` is non-empty, and on `action|path` when `Branch` is empty. `CountFlags` reads legacy `action|branch|path` entries and keeps the higher count.

## Rationale
Previously `FlagKey` joined `Action`, `Branch`, and `Path`. When a branch lost its worktree between `evolve gc` runs, `Path` changed to empty and started a second count. Keying named branches without `Path` keeps one count and one inbox item across worktree removal.

## Changed Areas
- `go/internal/gc/flagtally.go` — updates `FlagKey` to omit `Path` when `Branch` is non-empty, and adds `priorFlagCount` in `CountFlags` to read legacy `action|branch|path` keys.
- `go/internal/gc/flagtally_test.go` — updates `TestFlagKey_SeparatesActionBranchAndPath` for the new key format and adds tests for worktree removal and legacy tally migration.

## Design Decisions
`FlagKey` uses `action|branch` instead of `action|branch|` to keep the key compact and consistent with `action|path`. `priorFlagCount` scans `prior` for the prefix `action|branch|` when `Branch` is non-empty so counts carry over even if a branch lost its worktree before the upgrade. `CountFlags` still writes only new-shape keys back to `gc-flag-tally.json`.

## Verification
Unit tests in `go/internal/gc`, the entry-point test in `go/cmd/evolve`, and all cycle-2535 predicates pass after the final edit.

## Compatibility
Legacy `gc-flag-tally.json` entries in `action|branch|path` or `action||path` format retain their counts on the next `CountFlags` run. Path-only flags with an empty `Branch` continue to key on `action|path`.

## Limitations
`FlagKey` assumes a named branch does not equal a worktree path under the same `WorktreeAction`. Git branch names in this repository do not start with a slash, while worktree paths are absolute.
