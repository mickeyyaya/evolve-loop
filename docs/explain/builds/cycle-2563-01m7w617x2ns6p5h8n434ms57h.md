# Build Explanation — Cycle 2563

## Build Binding
- Cycle: 2563
- Base SHA: 499c111b5f3a1ddb8e30fec6de050faf4d5233ce

## Summary
The `test-integration-darwin` target in `go/Makefile` pins `go test -p 3` so 3-core and 5-core macOS runners share one package schedule.

## Rationale
Without `-p`, `go test` uses the host CPU count. That splits macOS CI runs across 3-core and 5-core schedules. A target-specific variable removes that split on `test-integration-darwin` at zero runner cost and leaves `test-integration` at the host default.

## Changed Areas
- `go/Makefile` — adds `TEST_PARALLEL`, `DARWIN_PARALLELISM := 3`, and `PARALLEL_FLAG` to `INTEGRATION_TEST`, and sets `TEST_PARALLEL = $(DARWIN_PARALLELISM)` on `test-integration-darwin`.
- `go/internal/ciparity/darwin_budget_test.go` — adds `captureGoTestArgs` and `TestMakeIntegrationDarwin_FixesParallelismWithoutChangingTheFullSuite` to verify `-p 3`, no `-p` on `test-integration`, and `TEST_PARALLEL` overrides.
- `docs/research/ci-wall-variance-2026-11.md` — marks row `R3` done and adds section `6.4` to record `-p 3` and explain the predicted span limits.

## Design Decisions
- **Target-specific `TEST_PARALLEL` over a separate recipe:** Reusing `INTEGRATION_TEST` through `TEST_PARALLEL = $(DARWIN_PARALLELISM)` matches `TEST_TIMEOUT = $(DARWIN_TEST_TIMEOUT)`, avoids duplicate `coversplit` logic, and keeps `TEST_PARALLEL=<n>` overrides working.
- **No edit to `.github/workflows/go.yml`:** The macOS CI job already calls `make test-integration-darwin` with a 45-minute step timeout above `DARWIN_TEST_TIMEOUT := 30m`.
- **Rejected runner-label pin:** Pinning the macOS job to the XLarge runner costs money on every run, whereas `-p 3` needs no workflow edit.

## Verification
The cycle-2563 ACS suite (`evolve acs suite --cycle 2563`), `go test -tags integration ./internal/ciparity`, `go test ./internal/testaudit`, `go vet`, `gofmt`, and `evolve docs ste-lint --strict` all pass.

## Compatibility
`test-integration` and all non-darwin callers of `INTEGRATION_TEST` receive no `-p` flag and keep the host CPU default. Callers of `test-integration-darwin` can override `-p` with `TEST_PARALLEL=<n>`.

## Limitations
Live CI runs on 3-core and 5-core macOS hosts are absent here, so no measured span ratio exists yet. Each test binary keeps `GOMAXPROCS` at the host CPU count, and the 5-core host holds 14 GB of memory against 7 GB. The build predicts that the 5-core span can differ from 1.0x and can exceed 1.3x until live CI runs measure both classes.
