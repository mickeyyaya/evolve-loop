## Summary
Two inbox items in `go/internal/cli/phasecmd` land together. First, five silent fallbacks are gone. A malformed `.evolve/policy.json` now raises the coded WARN `OBSERVER_POLICY_LOAD_FAILED` from `evolve phase-observer` (through its Signal Center) and from `evolve phase-watchdog` (on stderr). A `--persona-override` value without `:` is a usage error. A zero, negative or non-numeric pgid is rejected at the flag boundary. The `evolve phases` usage and unknown-subcommand texts come from one subcommand table. Second, `evolve phases check-provenance --cycle N [--json]` is the first production caller of `phasecoherence.CheckProvenance`. It exits 0 when clean, 1 on an `error` finding and 2 when the ledger cannot be read or scanned to its end, because `CheckProvenance` now returns the ledger error instead of dropping it.

## Rationale
Each fallback hid an operator mistake behind a zero value. A broken policy file silently reset every observer threshold and the `--enforce` stall chain's artifact extends. A colon-less override was silently ignored, so a coherence check ran against the wrong persona. A bogus pgid became 0 and reached the engine. The usage text had already drifted, leaving out two dispatched verbs. The fixes report the fault where it happens and keep the existing fallback behavior (compiled defaults) where that behavior is still right.

For provenance, the check existed but nothing in production called it, and it treated an unreadable ledger, or a ledger line past 64 KiB, as a clean pass. Returning the error from `CheckProvenance` was the smallest change that lets a caller tell "no mismatch" apart from "could not look". The alternative, a second ledger-aware function beside the old one, would have left two entry points with different failure semantics.

## Design Decisions
`check-provenance` fails only on `error` findings. No production writer emits the provenance header yet, so counting the `WARN` for a missing header as a violation would make every real cycle exit 1 and the command useless. The verb's exit codes (1 = violation, 2 = unreadable) differ from the other `evolve phases` verbs (1 = I/O, 2 = validation) because the inbox item fixed them; runtime-reference.md says so. The artifact path is the base name of each phase's first declared output, joined to `.evolve/runs/cycle-N/`, so user phases whose outputs are bare file names resolve the same way as built-ins. The observer's warning goes through its Signal Center, because a raw `[phase-observer] WARN` line is what an earlier test removed. The code is declared and registered under module observer in `phase_observer.go`, the CLI host that loads the policy, and not in `go/internal/observerengine`: that package is a protected control-plane path (ADR-0064) a cycle may not edit, and the engine never reads the policy. The watchdog has no Center, so it prints the same registered code directly.
