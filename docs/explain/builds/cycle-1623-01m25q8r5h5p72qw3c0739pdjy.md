# Build Explanation — Cycle 1623

## Build Binding
- Cycle: 1623
- Base SHA: 88227972c724dfd77085be4bc1143ddeeb3e6c57

## Summary
The composed dispatch path now stops after triage when the authoritative decision explicitly commits no tasks, preventing TDD, Build, and Audit from running without owned work.

## Rationale
The triage decision is the existing task-ownership authority. Carrying its committed count through the existing digest and honoring it at both the router and orchestrator closes the defect without introducing another configuration or routing surface.

## Changed Areas
- `go/internal/router/digest.go` — reads `triage-decision.json` and distinguishes an explicit empty `top_n` from a missing or unreadable decision so degraded workspaces remain fail-open.
- `go/internal/router/router.go` — terminates the post-triage transition only when the digested commitment is known and empty.
- `go/internal/router/signals.go` — carries the committed-task count and its internal availability state between the digest and routing decision.
- `go/internal/core/routing_dispatch.go` — preserves deterministic empty-commitment termination at the final dispatch authority even when the cycle plan includes ship.
- `go/internal/core/empty_commitment_dispatch_test.go` — pins the consuming authority's empty, non-empty, unknown, and post-build cases.
- `go/internal/router/apicover_named_test.go` — executes the new routing-signal query through its real digest producer to keep the exported seam named and covered.

## Design Decisions
The zero count is paired with an internal known bit because existing callers construct zero-valued routing signals and must not be reclassified as explicit empty commitments. One query owns that distinction for both routing layers. The existing ship-planned early-exit invariant remains unchanged; only a known-empty triage commitment receives the deterministic no-work exception.

## Verification
Focused router and core tests cover explicit-empty termination, non-empty preservation, unknown commitment, and post-build behavior. The cycle ACS predicates exercise a whole `RunCycle`, failed-claim atomicity, and git tracking of the recovery contract.

## Compatibility
Cycles without `triage-decision.json`, and tests or callers that construct `TriageSignals` directly, retain the previous fail-open routing behavior.

## Limitations
This cycle cannot modify the protected sandbox control plane; allowing sandboxed inbox claims remains a console-owned manual repair documented in the TDD report.
