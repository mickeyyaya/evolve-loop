# Build Explanation — Cycle 1749

## Summary
`naminguard.Fix` and `verifyeval.shellWords` each move one block into a new unexported helper, which brings both under the 50-line size-ratchet limit without changing behavior. New characterization tests, written and run green against the unchanged baseline before the extraction, pin the behavior. `cyclehealth.Check` already met the limit at base (shrunk in cycle 1741), so this cycle changes no code there.

## Rationale
Both functions were 51 lines, one over the ratchet ceiling. Each needed the smallest extraction that stays readable. In `Fix`, the per-file read → apply → compare → atomic write sequence becomes `rewriteFile`. That block is already one step with a single outcome ("was this file rewritten?"), and moving it takes `Fix` from 51 to 37 lines. In `shellWords`, the quoted-character branch becomes `consumeQuoted`, which returns the new quote and escape state (51 → 45 lines). I rejected two alternatives. Replacing `Fix`'s sort-tail with `slices.Sorted(maps.Keys(...))` would drop lines but extract no helper, which is what the task asked for. A tokenizer struct for `shellWords` would add more code than it removes. `offenders.json` is deliberately left unchanged: a lane never edits it, and the boundary `evolve sizeratchet tighten` removes the slack (see `docs/architecture/logic-first-delivery-design.md`).

## Changed Areas
- `go/pkg/naminguard/naminguard.go` — the per-file rewrite in `Fix` moves into `rewriteFile(root, rel, f) (bool, error)`. The atomic-write comment moves with its code. The error wrapping (`%w` for read and write) and the manifest-order loop stay the same.
- `go/pkg/naminguard/fix_characterization_test.go` — new tests call `Fix` and pin: binary files are skipped, changed paths come back sorted, entries apply in manifest order, and read and write failures keep their `fs.ErrNotExist` / `fs.ErrPermission` cause.
- `go/internal/verifyeval/shell_commands.go` — the quoted branch of `shellWords` moves into `consumeQuoted(word, quote, char) (byte, bool)`. Inside double quotes a backslash still starts an escape, the matching quote still closes, and every other byte is still kept.
- `go/internal/verifyeval/shell_words_characterization_test.go` — a table test calls `shellWords` and pins separators (space, tab, CR), single- and double-quote escape rules, dropped closing quotes, kept edge whitespace, escaped spaces and newlines, and empty quoted words.

## Design Decisions
Both helpers are unexported and have a single caller. Each keeps its parent's name and signature, so the mutation predicates can substitute the baseline body back in. `consumeQuoted` returns `escaped=false` on its non-escape paths. That matches the baseline, because the escaped branch in the caller has already returned by the time a quoted byte is consumed. The new tests live in new `_test.go` files, so the baseline test files are unchanged, and the git fixtures reuse `initRepo`/`writeTracked` instead of adding a raw `git init`.
