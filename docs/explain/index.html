The loop in one paragraph

Each loop (lane) is a full autonomous cycle. It runs a fixed spine: intent → scout → triage → tdd → build-planner → build → audit → ship. This order is the literal spine_order of docs/architecture/phase-registry.json. Its last entry, end, is a graph sentinel. retrospective and memo are optional phases after the ship, not part of the spine.

For some goal types, the goal recipes of the registry insert more phases around tdd and build. Examples are test-amplification, secret-leak-scan, flake-rerun-scan, error-handling-scan, coverage-gate and adversarial-review. These phases are not universal. A code cycle that touches files also runs code-review between build and audit (conditional_mandatory, ADR-0124; in shadow since v22.27.0).

Each lane works in its own git worktree. It takes tasks from a queue in the order of a computed rank (ADR-0121). A supervisor dispatches N lanes per wave. A trust kernel binds audit verdicts to exact trees, and it reserves git commit for evolve ship. If lanes race to land, they rebase and audit again.
