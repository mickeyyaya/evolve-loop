# Inbox review: why the loop had no work, and how the queue was reopened (2026-09-30)

## Summary

On 2026-09-30 the loop's work queue was empty in practice: `evolve inbox batches` planned **0 dispatchable batches from 183 pending items**, and wave 52's only cycle ended no-work. Every item was either console-owned (by its kind, a declared protected file, a console route) or waiting on a dependency.

The operator asked for the inbox to be prioritised and batch-implemented through the loop. Six read-only agents re-verified all 183 items against main `1e6912c4`. The results, and what was done with them:

| Verdict | Items | Action |
|---|---|---|
| FIXED | 3 | retired with its evidence as the resolution (`evolve inbox consume`) |
| DUPLICATE | 4 | retired, pointing to the item that stays |
| UNCLEAR | 1 | kept as is |
| ACTIONABLE, small | 74 | 43 routed to the lanes with `evolve inbox route-lane`; 12 refused because they declare a protected file; 19 not routed, so they stay console-owned |
| ACTIONABLE, medium | 71 | kept queued for later tranches |
| ACTIONABLE, large | 30 | kept queued; many need an operator or design decision |
| **Total** | **183** | |

After the drain (PR #747) the plan was **29 dispatchable batches from 181 items**. Wave 53 shipped the first of them (cycle 1779). After PRs #750 and #752 merged, `evolve inbox batches` on the synced runtime plane reported **68 batches from 243 items** (20:58 local time).

## Why the queue looked empty

- **Most items were console-owned by derivation.** An item whose kind is a pipeline kind, or that names a file the loop may not change, is kept for the console. The derivation is deliberately conservative, so a small, well-specified item could stay console-owned only because of its kind.
- **The operator had no way to say otherwise.** There was no verb to route an item to the lanes. PR #745 added `evolve inbox route-lane <id> <reason>`, which records the operator's decision as `route: lane`, judged by the same claim rule the lanes use.
- **Why the small items were console-owned.** Of the 74 small items, 49 were console-owned only because of their pipeline kind, 15 declared a protected file, 3 a protected directory, and 7 carried an explicit console route.
- **A route never overrides a protected file.** `route-lane` refuses an item that declares a protected file, because triage and the ship's tripwire would refuse the lane's work anyway (ADR-0074). Those 12 items stay console work.

## Method

Each agent received one sixth of the inbox and a fixed brief: read the item, check current main read-only, and give exactly one verdict with evidence. A FIXED verdict had to cite the code that now does what the item asks, a named test that pins it, or the commit that landed it, because a wrong FIXED verdict silently loses real work. Every ACTIONABLE verdict also confirmed that the item's cited files and lines still exist and the defect is still present.

| Verdict | Meaning |
|---|---|
| FIXED | The defect or gap no longer exists, with cited code, test or commit. |
| OBSOLETE | The premise no longer applies (none this round). |
| DUPLICATE | The same defect as another item still in the inbox. |
| ACTIONABLE-S | Still valid; about 60 lines of production code or less, 1–3 files, no design decision. |
| ACTIONABLE-M | Still valid; one focused PR, possibly a small design choice. |
| ACTIONABLE-L | Still valid; multiple PRs, cross-cutting, or needs a decision. |
| UNCLEAR | The state could not be determined with reasonable effort. |

The FIXED verdicts were spot-checked by the console before retirement: the pinning tests exist and the fixing commits are on main.
