# Duplicate test dispositions — 2026-09-14

All **59 exact-body candidate groups (161 test declarations)** have a semantic disposition below: **10 keep distinct contracts; 2 implemented consolidations; 47 potential future consolidations with missing proof**. “Future” means keep the current tests until the stated proof exists. It is not a deletion authorization or a claim that 47 groups can safely be collapsed to one test each.

The input is [duplicate-candidates.tsv](../research/testing-review-2026-09-14/duplicate-candidates.tsv), whose schema is `body_sha256`, `members`, `disposition`, `test_locations`. D01–D59 are review IDs assigned in TSV data-row order, so D01 is physical line 2; each row also carries the original hash prefix. Member links are pinned to the original baseline commit and identify its file and line; exact test names and full hashes remain in the TSV. The earlier candidate dispositions are superseded by these reviewed judgments, without rewriting the original inventory.

Source baseline: `80b348e6943b08b3bfc4e2d30f06f42db69c1db9`; reviewed from the validation checkout at `1b4bd9d62238796d3a83a484c0bda42b5fafb2b5`, whose intervening changes are the design documentation. Implemented claims were separately checked against fixtures commit `63d87f00fbea7d03e1ea06194748800cb9d84ae6` and structure-checker commit `9bdbc46634b02f70e783bdde5c60485ee8d2ff74`. Those source snapshots, rather than an assumed merge state, define this review. This report changes no executable source.

Review method: parsed every candidate declaration with Go’s AST, then inspected its body, package imports, relevant constants/variables, local helper implementations and file-level acceptance/provenance comments. Phase constructors, hooks and fake implementations were inspected separately; same-spelled `New`/`Config`/`fakePromptsFS` were not treated as the same symbol across packages. The AST extraction was a read aid, not an automated equivalence proof. Local source/reference searches and the ACS selection/evidence implementation informed the dispositions. Historical runtime dossiers, mutable `.evolve` state, all Git history, and every possible external selector were not exhaustively replayed. In particular, all seven distinct historical eval files in D02/D16/D26 are absent from this checkout. No historical ACS suite was executed for this review and no new coverage or performance claim is made.

High confidence (H) means the concrete distinction or implemented preservation is directly supported by the reviewed source/evidence. Medium confidence (M) means the repeated operation is visible, but safe consolidation is conditional on unresolved selector, execution or runtime-state proof. Medium confidence is not uncertainty about whether the bodies were inspected.

The following missing-proof requirements are referenced explicitly by each future row:

- **P1 — Identity and acceptance preservation.** Map every old package/test/cycle identity to an executed replacement and its acceptance criterion. Retain thin cycle wrappers by default; do not delete a cycle package because another cycle tests the same behavior. [CyclePackage and goLanePatterns](../../go/internal/acssuite/acssuite.go#L354) select the current cycle plus curated regression and redteam scopes, not every historic cycle. [Declared-test accounting](../../go/internal/acssuite/inventory.go#L21) keys expectations by package/test; [evidence inventory hashing](../../go/internal/acssuite/evidence.go#L88) includes predicate and AC identity, and [verification](../../go/internal/acssuite/evidence.go#L157) binds the receipt to host cycle/run/round/tree. A body hash is not such a receipt. Selector migration must preserve scope-lint outcomes, explicit skip semantics and tamper rejection.
- **P2 — Equivalent execution.** Establish the same package, exact named child-test set, flags/tags/race behavior, toolchain, working directory and environment. Require terminal evidence for every selected child case and correct nonzero-exit propagation. Default [acsassert.SubprocessOutput](../../go/pkg/acsassert/assertions.go#L179) inherits the current working directory and environment; [RepoRoot](../../go/pkg/acsassert/assertions.go#L231) uses Git’s current worktree and skips outside it. Do not replace their actual resolution behavior with an assumed global root. Moving helper code must keep the intended default/ACS tag boundary and avoid recursive suite invocation.
- **P3 — Strengthen weak oracles with TDD first.** Baseline helpers in 573/594, 652/655 and 675/678 can accept exit-zero no-match runs; 1546/1547 require PASS markers but only separately reject launch code -1, not all nonzero exits; 2/3 look for the test-name substring, which does not prove PASS. These are source-observed gaps, not newly executed exploits in this review. Add behavior-failing negative controls for absent, skipped and failing children as appropriate, then repair minimally before claiming a canonical executor preserves a reliable contract. Do not weaken stronger existing helpers to match weaker ones.
- **P4 — Input, timing and state preservation.** Prove the same repository/source tree, config/artifact bytes, live-state snapshot or isolated fixture semantics. Preserve setup, cleanup, error and skip paths. A new shared helper is often reasonable; execution caching or one historical success replacing another cycle requires separate evidence. No cache or provenance framework is proposed in this report.
