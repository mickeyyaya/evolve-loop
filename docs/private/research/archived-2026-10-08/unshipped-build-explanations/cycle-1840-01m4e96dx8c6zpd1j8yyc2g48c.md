## Summary
Every generated `commands/<name>.md` wrapper now tells the reader to read `${CLAUDE_PLUGIN_ROOT}/skills/<name>/SKILL.md` directly instead of loading the Skill tool id `evo:<name>`. The command and the skill share that id, so the old stub sent the Skill tool back to the wrapper itself: a circular load that three console lanes hit on 2026-10-06.

## Rationale
The plugin root variable is the one stable, resolvable path to the skill file in both the Claude Code plugin and the agy staging tree (`<plugin>/skills/<name>/SKILL.md`). Naming the file keeps the stub a thin delegate with `SKILL.md` as the single source, and needs no new configuration. Six skill descriptions also said "Use when the user invokes /evo:<name>"; the stub copies the description verbatim into its menu text, so that clause put the same self-id back into the wrapper. The clause carried no triggering value (the user who typed the command is already in it), so it was dropped from the skill rather than filtered in the renderer.

## Design Decisions
`RenderCommandStub` stays the single renderer shared by `evolve skills generate` and the agy publisher, so both surfaces change together. The instruction line keeps its position (two lines above `Arguments:`), so the drift check flags any legacy self-referencing stub left on disk. Descriptions are fixed at the source (`SKILL.md`) rather than rewritten during rendering, which would make the menu text diverge from the skill.

## Verification
`go test -count=1 ./internal/skillcheck ./cmd/evolve ./internal/prompts` passes; the four cycle 1840 ACS predicates pass; `evolve acs suite --cycle 1840` reports red=0.

## Compatibility
Command filenames, `/evo:<name>` menu entries, descriptions' remaining text and argument hints are unchanged. Old checked-out stubs report as drift until regenerated.

## Limitations
In a runtime that does not expand `${CLAUDE_PLUGIN_ROOT}`, the reader sees the literal variable and must resolve the plugin root itself.
