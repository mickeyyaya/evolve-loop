The inventory was generated by a one-off Go parser over `git ls-files -z`, selecting tracked `*_test.go` and excluding vendor. It parsed source without executing it, separated TestMain, and formatted function bodies without comments before hashing. Whitespace/function-name-independent body comparison is only a candidate heuristic: helper bindings, globals, package identity, input data, build constraints and provenance can differ even when bodies match. It does **not** normalize variable names or resolve identifiers. Static literal `t.Run`/`b.Run` labels are not full subtest paths; 770 functions include dynamic Run names. Examples embedded in comments or source strings are not counted as executable declarations.

These TSVs are a dated review snapshot, not a second live test registry or CI input. Keep the snapshot immutable; a later campaign records a new revision-specific inventory rather than maintaining these counts by hand. The current Go toolchain remains authoritative for build selection; use `go list -json -tags ...` under each supported environment and `go test -json` to obtain compiler-selected and executed cases during implementation.

No mass-deletion list was created. One exact cyclecost duplicate is confirmed; additional manually reviewed families have their specific disposition in [test-review.md](test-review.md). The candidate file labels the rest as requiring semantic review. All original test files are preserved.

## Limits and continuation contract

No full local Go suite, cross-platform local baseline, real-provider evaluation, repository-wide measured mutation score or before/after refactor coverage comparison was performed. GitHub evidence is tied to the reviewed SHA and observation time. All tracked test files were inventoried, but only high-risk assertion families were manually inspected; the package inventory is the worklist for further owner-by-owner review.

The design preserves existing test logic during pure refactors. Fixes to a broken fake, scanner, gate, simulator or stricter TDD proof are separate behavior changes with regression and preservation tests. Repository policies on isolated branches, independent review and sanctioned ship apply to later implementation. No commits, pushes, releases or deployments were performed for this step.

Historical testing documents are retained. Their baseline numbers, shell-path references, universal coverage claims and command labels must be checked against this dated audit; the new design is a proposal, not a claim that old gaps are already resolved.
