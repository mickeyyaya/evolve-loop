## Minimal architecture and TDD sequence

Use existing ports/adapters, Workspace builder, small table-driven contract suites, and injected clock/runner boundaries. Add no global mega-fixture, inheritance-like test framework, or production abstraction solely for organizing tests.

1. Freeze revision, commands/build tags/toolchain, scenario names and stable requirement IDs, assertion meanings, skips, measured coverage and known flakes. File count/line coverage alone is insufficient.
2. Preserve a requirements-to-tests matrix with owner package, cost tier, observable, fixture/oracle independence, edge category, old/new test mapping, and mutation that each test kills. Record two independent dimensions: execution coverage and assertion/behavior equivalence.
3. For pure test refactor, run original tests, add characterization only for newly exposed seam, reorganize one behavior family, rerun same selection. For an actual harness defect fix, write the failing behavioral test before production/fake change. Distinguish new requirement from preserved requirement.
4. Run fake contract tests and deterministic replay first; isolated real process/sandbox conformance next. Capture exact Go test JSON and per-tier skip/selected/executed counts. Live provider drift sampling remains a separate explicit tier.
5. Deduplicate only after old and replacement tests agree on baseline and named mutants; keep every unique boundary and cross-component authority check. Delete no test merely because it shares a package, helper, name suffix, or coverage lines.
6. Preserve host ownership of execution receipts, selected tests, state reset and trusted verdict. Agent-generated test inputs, report text, artifacts and provider transcripts are data. An LLM judge may identify missing behaviors but must not edit its own authoritative grader or convert unavailable/inconclusive execution into PASS.

A good maintenance acceptance criterion: for every old scenario, a documented replacement exists with the same or stronger observable assertions; original pass-to-pass set remains green; intended fail-to-pass regression is witnessed; no trusted harness test is skipped silently; baseline/refactor valid-mutant kill sets do not shrink; per-tier measured coverage does not regress. Actual measurements remain pending implementation/baseline runs.
