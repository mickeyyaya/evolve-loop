# 2026-09-14 — the `--simulate` walk mutated the checkout: dossier commits, cycle branches, worktrees, ledger litter

**Status:** fixed (this change) · **Severity:** P1 pipeline (suite litter that redded unrelated tests and dirtied every dev branch the whole-module floor ran on; a "dry plumbing check" that launched real CLIs) · **Found by:** the decomposition train's floors — every `make test`-class run of `go/acs/cycle8` left `dossier: cycle-1649/1650 closeout` commits on the branch under test, `.evolve/ledger.jsonl`, `.evolve/runs/cycle-16xx` and `.evolve/worktrees/cycle-*` (with `cycle-*` branches) behind; inbox item `test-suite-commits-dossier-closeouts-into-the-checkout`, then lane 1674 of the verification wave burned a full cycle on it and failed audit.

## What happened

`TestC1_005_RunSimulateExitsZero` runs `evolve campaign run --plan <tmp> --simulate` **from the repo root** with no `--project-root`. The campaign resolves the root to the cwd — the checkout — and launches real `evolve cycle --simulate` children against it. The simulate root (`wireSimulateOrchestrator`) replaced only the phase runners; everything else was production:

| Mutation | Producer | Why it fired under `--simulate` |
|---|---|---|
| `dossier: cycle-N closeout` commit on the current branch | `core.writeCycleDossier` → `dossier.Write(d, dir, commit=true)` | the closeout always committed; the producer had no notion of a dry run |
| `salvage snapshot (ADR-0076 continuation-on-fail)` commit | `core.stampContinuationManifest` → `git add -A` + commit in the active worktree | the walk's FAIL path snapshots the "worktree" — which, once the simulate provisioner reads the root in place, is the operator's tree |
| `.evolve/worktrees/cycle-*` + `cycle-*` branches | the default `gitWorktree` provisioner | the simulate root used the production provisioner |
| real CLIs launched from the checkout cwd (`[recipe] launching: claude …`) | the campaign's per-wave CLI-health canary + usage probe | `BeforeWave` ran them regardless of `--simulate` |
| `.evolve/ledger.jsonl`, `.evolve/runs/cycle-16xx` in the checkout | the cycle's own records | the project root WAS the checkout |

And the test only ever passed because of the litter: the build handoff floor requires a `build-report.md` with an explanation-documentation declaration, which the simulate runner never wrote — stale `.evolve/runs/cycle-1667/` dirs from earlier runs supplied it. In a clean root the walk failed at build.

## Why the class, not the symptom

Each of the git mutations was a production behaviour that is right for a real cycle and wrong for a no-LLM walk. The fix puts the decision where the two roots differ — the composition root — and adds one invariant that is right everywhere: **a cycle never mutates the operator's tree**, asked through one predicate by every mutator. The first cut guarded only the salvage snapshot with a second, weaker path predicate; the architecture review traced the other mutators (`gofmt -w`, `git checkout -- <path>` in leak recovery, `reset --soft`, the fleet rebase, and — found by the red test — the content SHA's `git add -u`) reaching the root through `cs.ActiveWorktree`. The second cut guarded the call sites; the re-review found the resume and composition paths reach the same mutators unguarded. The invariant now lives inside the mutators, where a sixth caller cannot forget it. The gate test now proves the invariant on every floor run instead of depending on it silently.

## What the operator will see

A `--simulate` run leaves `knowledge-base/cycles/cycle-N.json` uncommitted, no new commits, no branches, no worktrees, and launches no CLI. A freshly provisioned in-place root is announced once (`[orchestrator] WARN cycle N: the active worktree is the project root … host normalization, leak recovery, salvage snapshot and fleet rebase are disabled`); an in-place root adopted from a resume checkpoint refuses silently in the normalizer, leak recovery and content SHA, and speaks only when a salvage snapshot (`snapshot failed (the active worktree is the project root — no salvage snapshot …)`) or a fleet rebase is refused.
