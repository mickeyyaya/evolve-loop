## Summary

After #518 (`b83a74d6`), `recoverFromShipError` invalidated the build explanation on every `GIT_FLEET_REBASE_NEEDED` recovery. It returned to Build before the carry-forward ladder ran. In cycle 1637, peers moved `main` during each rebuild and re-audit, so the lane ran five rounds across 21 phases and ended in FAIL. Cycle 1691 took the same detour after cycle 1690 landed on disjoint files, and survived only because no peer was in flight. [ADR-0105](../architecture/adr/0105-identity-preserving-fleet-rebase.md) fixed this by unwinding ship's consumption, rebinding the explanation under a byte-identity proof, and carrying the verdict to Ship. The replay test `TestCycle1637Replay_ShipsOnFirstRecovery` in `go/internal/core/carry_chase_replay_test.go` pins this recovery path.

## Root cause

**F1.1** For every cycle with `ExplanationDocumentationVersion > 0`, `recoverFromShipError` ran `explanationdocs.RebaseBuildAndPersist` and returned `PhaseBuild` before the carry-forward ladder (`go/internal/core/ship_recovery.go:57-59`).
*Implication:* Every fleet rebase forced a fresh Build and Audit round, even when the lane diff did not change.

**F1.2** In cycle 1637, each rebuild and re-audit round took 11 to 25 minutes (`knowledge-base/cycles/cycle-1637.json:138-306`), while peer lanes landed on `main` faster than that window.
*Implication:* Returning to Build on a clean rebase creates a chase loop whenever sibling lanes are active.

**F1.3** The failed ship run committed its inbox consumption onto the branch (`go/internal/core/ship_recovery_unwind.go:19-45`), and the explanation document held the old base SHA (`docs/architecture/adr/0105-identity-preserving-fleet-rebase.md:18-19`).
*Implication:* Recovery must unwind the consumption commit and rebind the host explanation metadata before it compares the rebased worktree against the audited tree.

## What changed

| Id | Decision | Because (findings) | Rejected options and why |
|---|---|---|---|
| D1 | Unwind the ship consumption commit, rebase onto `main`, and soft-reset the lane change onto the new fork point (`unwindUnlessPredictedConflict`, `pendRebasedChange` in `go/internal/core/ship_recovery.go:47-54`). | F1.3 | Rebase the ship commit directly: the consumption pairs stay in the commit and break tree-identity proofs against the audited tree. |
| D2 | Rebind the host explanation state (`rebindPendingChange` in `go/internal/core/ship_recovery.go:94-142`) and run `identityCarryForward` (`go/internal/core/identity_carry_forward.go:24-95`) to route to `PhaseShip`. | F1.1, F1.2 | Always re-run Build or Audit after a rebase: an unchanged diff needs no new prose, and the 20-minute delay causes the chase loop. |
| D3 | Pin the cycle 1637 multi-peer sequence with `TestCycle1637Replay_ShipsOnFirstRecovery` and `TestCycle1637Replay_ByteDivergentRebaseDeclinesCarry` in `go/internal/core/carry_chase_replay_test.go:41-95`. | F1.1, F1.2 | Rely on `routeRebasedExplanation` unit tests alone: they do not enter through `recoverFromShipError` after ship's consumption commit and multiple peer landings on `main`. |

### Worked example

In `go/internal/core/carry_chase_replay_test.go:41-76`, the fixture builds a lane on `fx.base`, seals its explanation, records `fx.auditedTree`, and commits the inbox consumption on the branch. Two peer commits then advance `main` on disjoint files (`peer.txt` and `peer2.txt`) to `fx.newBase`. Next, `recoverFromShipError` runs for `CodeGitFleetRebaseNeeded` at depth 0. It unwinds the consumption commit, rebases onto `fx.newBase`, pends the audited change, and verifies byte identity. It then rebinds `WorktreeBaseSHA` to `fx.newBase` while keeping `AuthoredBaseSHA` at `fx.base`, writes one `identical-rebase` record, and returns `PhaseShip` with `recovering=true`.

## What we learned

- A deterministic host invariant that embeds the base SHA must provide a deterministic rebind rule when the lane's own files do not change ([ADR-0105](../architecture/adr/0105-identity-preserving-fleet-rebase.md)).
- End-to-end incident replays must enter through `recoverFromShipError` with the composition fast path wired, and fail when an overlay disables the carry (`go/acs/cycle1931/predicates_test.go:154-170`).
- Every incident fix must ship with its `docs/incidents/` record and its [REGRESSION-COVERAGE-INDEX.md](REGRESSION-COVERAGE-INDEX.md) row in the same delivery so that traceability never lags behind the code.
