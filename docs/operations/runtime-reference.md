## Operator verbs: clihealth, cli update and ratchet

- `evolve clihealth list [--json] [--project-root DIR]` (also spelled `evolve cli-health`) prints the active CLI-family benches from `.evolve/cli-health.json` (family, reason, `benched_until`); `--json` prints an array, `[]` when none. `evolve clihealth clear <family> [--project-root DIR]` removes that one bench; a family list does not show (never benched, or its bench expired) exits 1 and touches nothing. Both run over `clihealth.Store.Active` / `Clear` (`go/cmd/evolve/cmd_clihealth.go`).
- `evolve clihealth usage [--json] [family...] [--project-root DIR]` (2026-10-06) runs each named family's usage command now, every installed interactive family when none is named, and prints the typed windows the family's manifest reads (`controls.usage.windows`). It prints one row per window: CLI, scope, kind (`session`, `week`, `5h`), percentage used, reset text, target (a family, or `family/model` for a per-model window), exhausted, and whether it benches the family (only an exhausted family-scoped window does; a per-model window is reported, never benched). `--json` prints `[{cli, observed_at, windows, note, error}]`. It is read-only: it benches nothing and records nothing (the pre-wave usage probe is what benches, and it records the latest windows per CLI in `.evolve/usage-windows.json`). It boots each CLI once, in a throwaway workspace. A CLI with no usage command, or whose screen yields no window, gets a note. A probe that fails is named on stderr and exits 1. It is the first step of a CLI-failure investigation: quota verified or ruled out before anything else (`go/cmd/evolve/cmd_clihealth_usage.go`). The whole procedure, and what the loop records on its own, is the [CLI-failure triage runbook](cli-failure-triage.md).
- `evolve cli update [--dry-run] [--json] [--project-root P]` updates each CLI family the operator subscribes to and smoke-tests a changed version (`go/cmd/evolve/cmd_cli.go` over `internal/cliupdate`; [plan C4](../plans/model-currency-2026-10.md)). Per family it reads `<bin> --version`, smoke-tests first a version that differs from the one the last boundary recorded (a self-update or a manual install between boundaries; the row reads `self-updated`; that smoke replaces the `doctor live` subscription check, so a self-updated CLI that no longer boots is `smoke-failed`, not skipped), runs the family manifest's `update_argv` (claude: `claude update`; agy: `agy update`; codex and ollama declare none and print `no-updater`), reads the version again, and runs the `evolve doctor live <family>-tmux` probe on a changed version or after an updater error. "Subscribed" means, until the routing table's `cli_routing.clis` is wired: installed, not on a cli-health credential-wall bench, and answering `doctor live`. Each family gets one row: `unchanged`, `updated`, `self-updated`, `update-failed`, `smoke-failed`, `no-updater`, `skipped` (with the reason, explained by a usage query), `quota-exhausted` (the `doctor live` probe failed and a usage query showed an exhausted window), `boot-timeout` (the `doctor live` REPL never drew its prompt on any attempt the driver's manifest allows, `probe_boot_retries`, agy 1; the detail carries the final pane; never reported as unsubscribed; not a failure for the exit code) or, under `--dry-run`, `planned` with its argv; `--dry-run` probes, runs and records nothing. `--json` prints the report. Every version the boundary accepts is appended to `.evolve/cli-updates.json` (family, kind `baseline`/`update`/`self-update`, old, new, at; newest 64 kept; a smoke-failed version is never accepted, so the next run tests it again); the next run compares against it, and the readiness gate's `cli-version-drift` reads it. The updater runs in its own process group under a 10-minute bound (a deadline kills the whole group, so a relaunching child cannot hold the boundary) and without the family's own off switch in its env. Exit 0 when nothing failed, 1 on any `update-failed` or `smoke-failed`, 2 on a usage error or when a run holds a live lease under `.evolve/runs` (CLIs stay frozen within a wave; `--dry-run` still runs), 130 when interrupted (an interrupted family reads `skipped: interrupted`, never `smoke-failed`). The loop runs the same update at every boundary (the "Boundary CLI update" row below).
- `evolve ratchet check [size|rawgit] [--root DIR]` runs the function-size ratchet and the raw-git-fixture ratchet, or only the named one, through `sizeratchet.Scan` and `rawgitratchet.Scan`; the packages' repo-wide gate tests call the same `Scan`. It exits 1 naming each violation, 0 when clean, and 2 on an unknown selector or an extra argument. It never edits `offenders.json` or `baseline.json` (`go/cmd/evolve/cmd_ratchet.go`).

## Autonomous execution (bypass-permissions / yolo / auto-approve) — full text

When operating in autonomous mode, AGENTS.md Rule 4 ("stop and ask") is overridden. All 8 items below remain **mandatory** — bypass means "don't ask the user," not "skip integrity checks."

1. **Continue all cycles without pausing.** Never output "should I continue?" between cycles. Complete every requested cycle end-to-end.
2. **Run the FULL pipeline every cycle.** Launch Scout, Builder, Auditor for every cycle. No inline edits skipping agents, no batch-claiming multiple cycles. Each cycle must produce `scout-report.md`, `build-report.md`, `audit-report.md`.
3. **The phase gate runs at every transition.** Phase ordering is enforced natively by the Go orchestrator state machine (`go/internal/core`); it is non-negotiable in bypass mode. (`evolve guard phase` is a complementary in-process-`Agent`-dispatch backstop, not the phase-order authority — see ADR-0074.)
4. **Never fabricate cycles.** Every cycle number must correspond to real Scout → Build → Audit → Ship → Learn execution. Claiming a number without doing the work is a CRITICAL violation.
5. **Phase agents MUST be invoked through the native bridge (`evolve subagent run`, or the in-process `go/internal/bridge` launcher driven by `evolve loop`/`evolve cycle run`).** In-process `Agent` is denied by `orchestrator.json:disallowed_tools`; the `evolve guard phase` hook is intended as a second, PreToolUse-layer backstop for this but is currently a wired no-op (wired under the `Bash` matcher instead of `Agent`) — ADR-0074 records the decision to rewire it to the `Agent|Task` matcher (operator-applied control-plane change). No bypass. The runner enforces per-agent CLI permission profiles in `.evolve/profiles/`, generates a challenge token, and writes a tamper-evident ledger entry.
6. **OS-level sandboxing wraps phase subprocesses.** `EVOLVE_SANDBOX` takes `auto` (default) | `on` | `off` — not `0/1` (see the env-var table below). For legacy cycles, `auto` may disable confinement when nested-Claude is detected and `EVOLVE_SANDBOX_FALLBACK_ON_EPERM=1` retains the compatibility fallback. A version-1 Build explanation contract is stricter: Build requires `sandbox-exec` (macOS) / `bwrap` (Linux) regardless of `off`; fresh-cycle preflight HALTs on nested or otherwise unavailable confinement, and a resumed version-1 Build fails closed at launch. Auditor/Evaluator profiles run `read_only_repo: true`. **The write surface is the profile's declaration:** every grant in `sandbox.write_subpaths` (repo-relative, absolute, or `{worktree_path}`-prefixed; a `cycle-*` glob widens to its parent directory) is resolved by the bridge and added to the floor every sandboxed phase gets (the worktree, the cycle workspace, and `/tmp`; declarations add to that floor and cannot narrow it) — so a lifecycle write a persona instructs (triage's `evolve inbox-mover claim` into `.evolve/inbox/processing/`, retrospective's `.evolve/instincts/lessons/`, doc-sync's `docs/`) is granted because the profile declares it, never because the bridge special-cases the phase. A declared grant whose path is symlink-retargeted below its base (the project root, the worktree, or the entry itself when absolute) refuses the launch. `go/internal/bridge/sandbox_write_subpaths_test.go` renders every checked-in profile and fails if a declared entry's grant is missing from the rendered sandbox (the cycle-1623 regression class, where triage could not claim its own inbox item and the cycle ran its whole spine against an empty commitment).
7. **Eval-quality pre-flight on every eval.** The discover→build gate runs the native eval-quality check (`evolve eval quality-check`) against each new eval. A tautological / low-kill-rate eval is flagged. Promotion path: WARN-only → fail-gate after one verification cycle.
8. **Adversarial Auditor mode is default-on.** Runner prepends "ADVERSARIAL AUDIT MODE" framing requiring positive evidence for PASS. Auditor defaults to Opus (different family from Builder's Sonnet) to break same-model-judge sycophancy. Disable only with `ADVERSARIAL_AUDIT=0`.

**The rule is: maximum velocity, zero shortcuts.** Go fast by being efficient, not by skipping steps.

**Runtime constraints.** Per-cycle git worktrees are provisioned natively by the orchestrator (`go/internal/core`; manage manually with `evolve worktree create|list|cleanup`; `evolve worktree cleanup --stale` lists the sealed cycle worktrees that no continuation binding (by branch or worktree leaf), fresh run lease or uncommitted change holds and names the reason each other lane is kept, and with `--apply` removes the listed ones and `git branch -d`s their branches; console dev trees use `evolve worktree create --dev <task> --branch <b>` (exit 1 on an existing task or branch) and `evolve worktree cleanup --dev <task>`, or `--dev --all` with `--dry-run` to preview. Cleanup removes a tree and its branch only on a proof that its work is in `origin/main`. The tree's head may be in it, or every change in the tree, committed, staged, unstaged or untracked, may already be in it (the content-landed proof), or `gh` may report a merged PR whose `headRefOid` is the local head. Cleanup refuses anything else with exit 1 and the reason, and exits 2 on a git failure, per [workspace-layout.md](workspace-layout.md); `evolve branches audit` reports a lane branch whose cycle holds a fresh run lease as `live superseded=false`, and `branches prune` keeps it), recorded in `cycle-state.json:active_worktree`. Orchestrator and phase agents MAY NOT call `git worktree add/remove` (denied by profiles). **Lane base ref (cycle-1196):** a FRESH lane is cut from the current upstream tip, not the local checkout's `HEAD` — `gitWorktree.Create` (`go/internal/core/worktree.go`) runs `git fetch origin` in the project root and bases the `-B` branch on `origin/<default-branch>` (read from `refs/remotes/origin/HEAD`, floor `main`). A fetch failure is FATAL (nothing is provisioned) — a best-effort fetch that continued from the stale local tip would be the very defect this closes, since in a multi-lane fleet the shared checkout drifts behind origin as sibling lanes land. A repo with no `origin` remote skips the fetch and keeps the documented local-`HEAD` fallback. The idempotent-reuse path never fetches or re-bases: re-basing a live lane mid-cycle would discard in-progress work. The native failure-adapter (`go/internal/core`) computes a deterministic PROCEED/RETRY/BLOCK from `state.json:failedApproaches[]` — the orchestrator follows it verbatim. Ledger hash-chain via `prev_hash` + `entry_seq`; verify with `evolve ledger verify`. The native ship phase advances `state.json:lastCycleNumber` after a successful ship.

**Cycle-number recovery floor.** A new cycle reserves `max(lastCycleNumber, lastAllocatedCycleNumber, highest occupied go/acs/cycle<N>)+1`. The local source floor is read before workspace and worktree creation and folded into the atomic state lease. Because worktree creation can fetch a newer upstream commit, the orchestrator then checks the selected identity in the provisioned source before cycle-state persistence or phase dispatch. A fetched-source collision aborts setup, reports and preserves the worktree for inspection, and leaves the lease burned so the next run advances. Preservation is mandatory because provisioning may have reused an existing recovery location. Missing ACS trees preserve the normal state-only path; module lookup errors, inventory errors, and integer exhaustion fail closed. Resume reuses its recorded identity and bypasses this fresh-run check.

**SSE / streaming endpoints**: disable middleware buffering, add explicit timeouts, provide a cancel-UI button. Don't rely on browser-side timeout alone.

## Shell & environment conventions (full table)

Shell scripts target **bash 3.2** (macOS default). Banned/required:

| Status | Pattern | Reason |
|---|---|---|
| Banned | `declare -A` | bash 4+ |
| Banned | `mapfile` / `readarray` | bash 4+ |
| Banned | `${var^^}` / `${var,,}` | bash 4+ |
| Banned | `sed -i ''` | BSD-incompatible — use `> "${file}.tmp.$$" && mv` |
| Banned | `date -d` | GNU-only — use `date -u -j -f` on macOS; fallback chain `gdate || date -d || date -j -f` |
| Required | `set -uo pipefail` | NOT `set -e` for orchestrator scripts capturing sub-script exit codes |
| Required | Atomic writes via `mv` of `${file}.tmp.$$` | Crash-safe |
| Required | `git diff HEAD` for tree-state SHA | Match audit-binding model (untracked files don't count) |

`skills/<name>/` is canonical; `.agents/skills/<name>/` are symlinks → `../../skills/<name>/` for cross-CLI auto-discovery. Git tracks content at the canonical path.

## Task Contract block in the tdd, build and audit prompts (ADR-0098)

Every tdd, build and audit dispatch carries a harness-owned `## Task Contract` block: the bound inbox item(s)' `acceptance[]` verbatim (one `### <id> — <title>` per task) and, for build and audit, the ACS predicate names the harness listed with `go test -list . -tags acs ./acs/cycle<N>`. Operator reading: `### <id> — inbox record not resolved` means the lane scope named a task the scope-path resolver could not place (check `.evolve/inbox` for the id); `declares no acceptance[]` means the item was filed without criteria — author them on the item, the block is a projection; `no ./acs/cycle<N> package` on a predicate-dispositioned task means tdd wrote no predicates and the auditor will see the same line. The block is absent (byte-identical prompt) when the cycle binds no task.

## Worktree fence for read-only phases (ADR-0097)

Every phase without write permission (registry `writes_source=false`: audit, adversarial-review, retrospective, user evaluate phases, …) is dispatched with `worktree_read_only=true`. The phase runner snapshots the cycle worktree before the first dispatch attempt and restores it after the last, BEFORE the phase is classified — so the audit's explanation-digest check, the retro's verification and the ship always judge the builder's tree. A write by such a phase shows up as a `warning` diagnostic on its response (`worktree fence: read-only phase audit wrote N path(s) …; restored to the dispatched tree: …`) in the phase log, the dashboard and the retro. Operator reading: a fence diagnostic on a phase that SHOULD write means its spec is missing `writes_source: true`; a fence diagnostic on the audit means the auditor mutated the tree (cycles 1603–1605) and the pipeline held. `snapshot unavailable` means the worktree was not a git repository — the phase ran unfenced and the downstream gates stay armed. The fenced set is exactly the set the explanation digest hashes: every tracked path (the worktree's tracked `.evolve/` files — policy, profiles, phases, evals — included) plus untracked files that are not ignored; ignored paths (build outputs, `go/bin`, the worktree's `.evolve/runs` and `guards.log` scratch) are outside both. `retrospective` runs through its own bridge call and holds the same fence.

> - **The console route at a boundary** (the procedure behind the entry above; 2026-09-29, automated 2026-10-01 by [ADR-0112](../architecture/adr/0112-loop-inbox-stamps-land-at-the-sync.md)). A plane-side file at a path origin has since added still blocks the fast-forward and is named as `[loop] WARN: wave-boundary sync: N plane-side inbox file(s) block it: <paths> — …`: remove the plane copy, then `evolve sync-main`. To route an item by hand, `evolve inbox route-console <id> "<what the lane found>" <cycle>` in the plane still writes the `route-console` ledger line into the plane's chained ledger, and the stamp lands at the next `evolve sync-main`.
> - `evolve continuation list` / `evolve continuation release <scope-id>` `[-project-root P]` (cycle-1515) — the operator surface for the scope-keyed continuation registry (`.evolve/continuation-registry.json`), which until now could only be inspected or corrected by hand-editing the file OUTSIDE its flock sidecar, destroying the salvage pointer it dropped. `list` is a pure read (exit 0 always — an absent registry is the normal state of a healthy project) reporting scope id, `snapshot_sha`, `base_sha`, branch, ancestor cycle and worktree per binding. `release` drops exactly one binding through the SAME transaction every retirement path uses (`inboxmover.ReleaseContinuationBinding`): the released VALUE is preserved into the scope's inbox item under `released_continuations[]` FIRST, then the entry is deleted with `DeleteRegistryEntryIfCycle`, so a sibling lane that rebound the scope in between keeps its fresh binding (reported, exit non-zero, nothing dropped). A scope holding no binding is an ERROR, not a silent success — a typo'd id must never read as a completed release. The project root resolves from the working directory (deliberately NOT `$EVOLVE_PROJECT_ROOT`: running inside a lane's environment would otherwise release bindings in a different tree than the operator is standing in). Host paths in every emitted/preserved pointer are collapsed to `~` (`continuation.RedactHostPaths`) because consumed items ride the ship commit to a public remote.
> - **Registry lifecycle invariants the above shares with the runtime** (cycle-1515): (1) an item LEAVING the pending pool releases its binding in the same operation — `Promote` to processed/rejected/retry/quarantine (`inboxmover.releaseContinuationOnRetire`) and ship-time consumption (`internal/phases/ship/consume.go`); (2) the read-side belt in `ResolveContinuationForScope` refuses a binding whose scope names no live pending item, but only on RECENT retirement evidence — a retired copy from an EARLIER cycle than the binding means the item was re-filed and rebound after that retirement, so the binding is adopted, not released (an unstamped quarantine copy is still evidence; that is the ordinary shape). Every release preserves before it deletes.
> - `evolve setup detect [--json]` — onboarding digest (read-only): per-CLI binary/auth-mode/capability-tier/verdict + per-phase current routing + envelope/cross-family/allowed_clis constraints, with `.evolve/policy.json` pins overlaid (`source=policy-pin`) and any floor breach reported as `pin_violation` (a malformed policy → top-level `policy_error`). Backs the in-session `/setup` skill. (Step 9b removed the `evolve setup validate` subcommand + the `llm_config.json` it clamped; the same envelope + allowed_clis clamp now lives in `policy.ValidatePin`, surfaced inline by `detect` and hard-enforced at dispatch.) > **Wave boundary, through the CLI only (2026-09-28).** Every loop control goes through the `evolve` CLI and the GitHub CLI; a control they cannot perform is an interface defect to file and fix, never a script to write.
>
> 1. **Stop.** `evolve loop-stop --wait [--timeout D]` (2026-09-29; `--wait` 2026-09-30) engages the brake: it writes `.evolve/loop-stop` with a timestamp line and says what happens next, then blocks until no run lease is live, printing the live run and its phase whenever they change. The running loop finishes the wave in flight, closes it out (finalize, the batch-end sweep, pending dossiers published on exit) and exits at the next wave boundary with `stop_reason: loop_operator_brake`, exit 0; a chained run (`--until-inbox-empty`) then stops at its batch boundary with `chain_operator_brake`. Its exit 0 is the confirmation to merge: no lease has a fresh heartbeat with a live owner (`runlease.LiveOwner`, the same verdict `evolve sync-main` refuses on). Exit 1 means the timeout (default 10m) passed with the named run still live and the brake kept; re-run it. The loop log's `[loop] operator brake …/.evolve/loop-stop is engaged — stopping before cycle N` line (followed by the run's JSON with `"stop_reason": "loop_operator_brake"`) remains the secondary evidence. The brake is checked at the start of every iteration, the first included, so while it stays engaged a new launch stops before its first wave. The simple one-wave form is still `evolve loop --max-cycles 1`, which exits after its wave. In fleet mode `--max-cycles N` counts waves, not cycles: each batch iteration dispatches one wave of `fleet.count` lanes (`runLoopBatch`), so `--max-cycles 2` at width 2 is two waves and up to four cycles; a boundary refresh's re-exec keeps that count and the wave index, so a multi-wave run no longer outlives it. SIGINT remains the immediate stop: it checkpoints, and one that lands during a boundary refresh ends the run instead of re-execing.
> 2. **Merge** console PRs with `evolve pr merge <n>... [--update-branch] [--wait D]`. It refuses with exit 1 while any run lease in the plane is live (every worktree of the store, checked at launch and again before each merge), and for a PR that is not open, is a draft, conflicts, is behind its base without `--update-branch`, or whose newest `required.yml` run on the head is red, pending or absent (`--wait D` polls a pending run at `ci_watch.poll_s` until the deadline; red refuses at once). A green PR merges with `gh pr merge --<pr.merge_method> --match-head-commit <verified head>` (policy `pr.merge_method`: `merge` default, `squash` or `rebase`; any other word exits 2), and stdout carries one `merged #<n> <sha>` line per PR. PRs run in operand order and the first refusal stops the run; earlier merges stay merged and stderr lists the rest as `not attempted`. Exit 2 is a `gh`/`git` or policy failure, 10 a usage error.
> 3. **Sync the plane**: `evolve sync-main` merges origin/main into the plane's `main` (merge only, never pushes). It refuses while a run lease is live or a tracked file outside the loop's inbox stamps has uncommitted changes; it lands the stamps itself (ADR-0112), and an untracked file never blocks it. A loop that boots behind origin halts and names this command (ADR-0081). Then publish the closeouts a killed loop left in `.evolve/dossiers-pending` with `evolve dossier publish [--dry-run] --project-root <plane>` (cycle 1826): it runs the loop exit's own checks through the same function (`holdDossierPublish`: the plane classification, no other live run, the git-mutation lock, the plane current with or ahead of origin/main) and then commits each complete pair as one `dossier: cycle-N closeout` commit, which the next lane ship pushes; a half pair (a `.md` without its `.json`) stays pending and is named. Exit 0 published, or nothing pending; exit 1 held, naming the live run and its pid, the busy lock, or the relation to origin/main, without waiting on the lock; exit 2 when the pending directory cannot be listed or a pair fails to commit; exit 10 on a usage error. `--dry-run` lists the pending cycles, the half pairs and what would hold the publish, and changes nothing. Then release what the finished wave left behind with `evolve gc --project-root <plane>` (see "Operator commands (release resources)" below). Then run `evolve worktree cleanup --dev --all --project-root <plane>`, after reading its `--dry-run` plan first. It removes every console dev tree whose work is in `origin/main` and that nothing has changed for 2 hours, and it names the reason it keeps each other tree ([workspace-layout.md](workspace-layout.md) has the proofs). It never deletes a `refs/checkpoints/*` ref, and a checkpoint never makes an unlanded tree removable. This step stays with the operator: the loop never removes a dev tree.
> 4. **Launch**: `evolve loop-stop --release` (a no-op when no brake is engaged), then `evolve loop --preflight-only [--skip-preflight-boot]` to run the readiness gate alone (exit 0 READY, exit 1 naming each blocking check; it writes only `.evolve/loop-preflight.json` and dispatches nothing), then `evolve loop --goal-text "..." --max-cycles N` (`--max-cycles 1` for one wave). To launch in the background, use `evolve loop --detach --log loop.log [--goal-text "..."] [--max-cycles N]` instead of nohup: it re-execs the same arguments in a new session with stdout and stderr appended to the log and prints the child's pid. It then waits up to the policy bound `boot.detach_wait_s` (default 600) for a live run lease. Exit 0 means the loop is running. Exit 1 means the child exited during boot (this launch's log tail is printed), the boot was not confirmed in time (the child is not killed), or a run was already live. `--detach` requires `--log` and refuses `--dry-run` and `--preflight-only`. The boot refresh rebuilds and re-execs a binary behind HEAD and re-pins the ship SHA; run `evolve reset-sha --operator` only when the boot reports that the repin was declined.
>
> **The boundary as one verb (2026-10-06, cycle 1810):** `evolve boundary run [--merge n,…] --goal-text-file F [--max-cycles N] [--dry-run] [--project-root P]` runs steps 1 to 4 in order through the existing verbs, reimplementing none: `loop-stop --wait`, `pr merge <n>…` (omitted without `--merge`), `sync-main`, `gc`, `loop-stop --release`, then `loop --detach --log <plane>/.evolve/boundary-loop.log --goal-text <the file's trimmed text> [--max-cycles N]` (the log is appended to across launches), each with `--project-root` set to the resolved plane (`--project-root`, else `$EVOLVE_PROJECT_ROOT`, else cwd). It prints `boundary: step i/n: evolve …` before each step and the step's own output under it, and stops at the first failed step with that step's own exit code, naming the step on stderr. A failure before the release leaves the brake engaged, which is the safe state; a full run ends with the detached loop's pid and boot verdict. `--dry-run` prints the plan and runs nothing. Bad arguments (no `run` sub-verb, a missing, unreadable or empty goal file, a `--merge` entry that is not a distinct positive number, a non-positive `--max-cycles`, an unknown flag) exit 10 before any step runs. The `evolve worktree cleanup --dev --all` sweep stays a separate operator step.
>
> **Landing a patch or a salvaged cycle (2026-10-06, cycle 1810):** `evolve land --branch B (--patch F | --salvage <leaf>) [--project-root P]` creates the console dev worktree `dev/<B with / as ->` on a new branch `B` at the freshly fetched `origin/main`, through the same code as `evolve worktree create --dev`, then applies the patch with `git apply --3way` and, for a salvage leaf (a directory name under `.evolve/operator-salvage/`, or a path to one), applies its `uncommitted.patch` and restores its `untracked.tgz` (regular files only; an entry that escapes the worktree or would overwrite a file is refused). It never commits or pushes, and prints the next commands: the commit gate, then `evolve ship --class manual`. Exit 0 landed; exit 1 on an existing dev directory or branch (nothing created) or a patch that conflicts with or does not apply to `origin/main`, naming the conflicted files and leaving the worktree with the conflict markers for resolution; exit 2 when the patch or leaf is missing, checked before any branch or worktree is created, or on a git or archive failure; exit 10 usage.
>
> File a new inbox item as a tracked file through a PR (the `inbox-add-cli` item will make it a command); an untracked item left in the plane is the operator's own work in the tree.

> **Plane layout (ADR-0080, live since 2026-07-28):** the loop runs from a dedicated RUNTIME worktree (`../evolve-loop-runtime`, branch `main`); the primary checkout is the operator CONSOLE plane (parked on `console-plane`; feature branches). Console work cannot trip the tree-diff guard or delete runtime-minted `.evolve` files — the four batch-15 operator-kill classes are structurally closed. Integration flows through origin only: console PRs merge there; the loop fast-forwards `main` from `origin/main` at every wave boundary (FF-only, loud skip on divergence). Boot prints the plane (`[loop] plane: …` — a PRIMARY-checkout launch WARNs); `evolve doctor plane [root]` reports it (exit 2 = loop state in the console plane); `evolve console-lease <path>... --ttl 30m` records a bounded, exact-path, WARN-per-waiver operator lease for the rare must-touch-runtime case; inbox items for the loop are filed with `--project-root <runtime>`.
>
> **Lane base authority (2026-09-10):** a fresh lane bases on the INTEGRATION HEAD its landing targets, resolved by `core.laneStartRef`: `origin/main` when the plane's local `main` is current or behind (the wave boundary fast-forwards it), the local `main` when it is strictly ahead (unpublished dossier closeouts ride the next lane ship's push), and DIVERGED history halts the batch at the wave boundary (`stop_reason: plane_diverged_halt`, exit 2) before any lane spends a phase — no base choice avoids a rebase then; reconcile the plane (`git merge origin/main` in the runtime worktree) and relaunch. One resolver (`gitexec.RelationToRemote`) serves both the boundary and the lane base, so their sentences match. The boundary reports a local-ahead `main` as `AHEAD of origin/main by N commit(s)`; it never reports a fast-forward that did not move HEAD. Batch exit (including the SIGINT unwind) kills the loop's OWN per-run tmux socket (`evolve-bridge-p<pid>`), so a stopped batch leaves no provider session behind; a pre-set `EVOLVE_TMUX_SOCKET` is never killed.
>
> **Lane base fetch and the lane deferral (2026-10-06):** `core.laneStartRef` fetches only the remote's default branch (`git fetch origin +refs/heads/main:refs/remotes/origin/main`), never every remote-tracking ref: the hub's one bare store backs the plane, every lane and every console dev worktree, and a bare `git fetch origin` failed whenever another process was moving any ref (cycle 1806: a train branch moved by `gh pr update-branch`). Ref-lock contention on the base ref (`cannot lock ref`, `unable to update local ref`) is retried up to 3 attempts, 2 s then 4 s apart, each announced as `[worktree] retry N/2: git fetch origin main after ref-lock contention rc=…`; `evolve sync-main` fetches its checked-out branch the same way and refuses a detached HEAD before fetching. If a fleet lane's provisioning still fails, the orchestrator re-provisions once (`[orchestrator] WARN worktree provisioning failed, re-provisioning once: …`). A fleet lane that still has no worktree is **DEFERRED, not FAILed**: no phase dispatches, the cycle seals with `cycle.sealed` WARN `ORCHESTRATOR_LANE_DEFERRED` (`fields.cause` is the git error), `evolve cycle run` releases any claim unbumped and exits 5, and every lane report counts it apart: `wave N: X/Y lanes ok, K deferred`, the pool line, `evolve fleet` (`deferred`, exit 0 when nothing failed) and `evolve fleet soak`. Nothing about the task is recorded (no failure digest, failure-learning todo or retrospective), so the deferral never counts toward the consecutive-FAIL rules; the item stays in the queue for the next wave. **A deferral that does not clear halts the batch:** the pipeline-blocker breaker's `lane-deferrals` rule halts after `failure_policy.thresholds.lane_deferral_halt_ceiling` (default 3) consecutive deferred cycles, through the standard halt (escalation dossier, P0 inbox item `pipeline-defect-lane-provisioning…`, exit 4, one `LOOP_PIPELINE_BLOCKER_HALT` INCIDENT with `fields.rule=lane-deferrals` and the git cause in its reason). A quota DEFERRED never counts, and any cycle that did not defer breaks the run; a deferred cycle is transparent to the `consecutive-failures` run (it neither counts nor breaks it), so deferrals alternating with FAILs still halt there. A deferral whose record cannot be written fails the cycle loudly instead, because the breaker could not see it. What usually needs fixing is outside the items: a stale `.lock` under `.repo.git/refs/remotes/origin/`, the network, or credentials. A sequential cycle keeps its old best-effort behaviour. Incident: [2026-10-06-cycle-1806-fetch-ref-lock.md](../incidents/2026-10-06-cycle-1806-fetch-ref-lock.md).

> **Operator commands (write a verdict file):**
>
> - `evolve acs suite --cycle N [--root .] [--evolve-dir .evolve]` — runs the Go EGPS predicate lane (`./acs/cycle<N>`, each `./acs/regression/<sub>`, `./acs/redteam`) and writes `<evolve-dir>/runs/cycle-N/acs-verdict.json`; exit `2` when any predicate is RED, `0` when all green, `1` when the suite cannot run at all or the verdict cannot be written, `10` on a bad flag. Host-side deterministic replacement for the deleted `run-acs-suite.sh` (ADR-0025). `evolve acs run --cycle N <pkg>` runs `go test -json` on a package into the same verdict file, and exits `1` when that `go test` exited nonzero with no predicate red to explain it; a run that executed no predicate writes the same `egps/no-predicates` red as the suite (`acsverdict.NoPredicatesID`), never a pass, and both subcommands derive the verdict path from `acsverdict.Path`, which refuses a relative evolve dir. **The verdict is always written and complete (2026-10-01, [ADR-0114](../architecture/adr/0114-the-acs-verdict-is-always-written-and-complete.md)):** anything that kept predicates from running is a named harness red, an `ac_id` starting `egps/`, whose `evidence_excerpt` states the cause and whose full text lands in `runs/cycle-N/acs-red-evidence/`: `egps/no-predicates` (no `go/go.mod` + `go/acs/`, no active scope for the cycle, or no scope produced a result; this used to write a zero-predicate PASS from the CLI and nothing at all from the audit, whose only diagnostic was `acs-verdict.json: read: no such file or directory`), and `egps/go-lane-scope-failed/<scope>` (a compile error, declared tests that never ran, or a spent lane budget). The audit's EGPS diagnostic, and so `audit-fail-reason.json`, carries the first harness red's reason. **`acs.go_timeout_s` is one budget shared by the whole lane**, not a per-scope allowance: a scope that finds it spent is reported `…budget … was spent before this scope started` and is never started, and a scope the deadline killed says `…expired while this scope ran: context deadline exceeded`. **Predicates run in the suite's own environment:** `ipcenv.Scrub` drops every `EVOLVE_` key, so a fleet lane's `EVOLVE_FLEET`, scope, width, cycle-state file and tmux socket never reach a predicate or an inner `go test` it shells; the suite then exports `EVOLVE_PROJECT_ROOT` (the plane, else the suite root), the worktree-root key and `CHANGED_PACKAGES`, and copies in the operator-owned keys the state root's `.evolve/policy.json` names in **`acs.predicate_env`** (the checked-in policy names `EVOLVE_FLAG_CAMPAIGN`, so an active flag campaign still reaches the ADR-0063 `flagprogress` gate). The list is bounded: an entry that is a lane protocol key (`ipcenv.ProtocolKeys`: `EVOLVE_FLEET`, its scope and width, the worktree-root key, the cycle-state file, `EVOLVE_TMUX_SOCKET`) or one of the suite's own exports (`EVOLVE_PROJECT_ROOT`, `CHANGED_PACKAGES`) is refused, named by an `[acs] WARN` on stderr and in the verdict's `warnings`, and the rest still forward. Only the state root's policy is read, so a cycle worktree's own `policy.json` cannot widen the list; a caller's `CHANGED_PACKAGES` never reaches a predicate. **Paths:** the suite makes `--root` and its state root absolute, and both subcommands exit `10` unless `--evolve-dir` resolves to an existing directory, so running from `go/` with the default `.evolve` no longer mints a phantom `go/.evolve/runs/` tree. **Project-root derivation (cycle-1434, #449):** `EVOLVE_PROJECT_ROOT` for the predicates is the parent of `--evolve-dir` whenever that directory holds the kernel-owned `runs/cycle-N/cycle-state.json` (`suiteProjectRoot`, `cmd_acs.go`); the legacy `git --git-common-dir`-parent walk is only the no-plane-evolveDir fallback — it resolves the OWNING repo, which is wrong when the plane is itself a linked worktree (all linked worktrees share one common dir). Verdicts stamp `suite_root`/`project_root`; a pre-staged verdict whose *stamped* root mismatches the audit phase's own is regenerated, with the foreign artifact preserved as `acs-verdict.foreign.json` (unstamped files stay honored — operator/CI pre-stage unchanged).
> - `evolve ledger rebaseline -note "<why>"` — seals a densely damaged chain prefix in ONE call (landed cycles 1433/1435; physical-tail binding fixed in #450): appends one operator `reset-seal-rebaseline` entry chained from the **physical** last line of `ledger.jsonl` (not `ledger.tip` — foreign lines past the tip are exactly the damage class this repairs), moves the tip to the seal, and deep-verifies before reporting OK. The damaged prefix is preserved byte-for-byte (append-only, ADR-0048 posture), just no longer chain-validated. The `-note` is REQUIRED — sealing a prefix is a trust decision and must carry its justification. Refuses an empty chain. Contrast `evolve ledger anchor <seq>`: one accepted break, and non-unique seqs are rejected (`ErrAmbiguousAnchorSeq`, cycle-1433) with SHA disambiguation.
> - `evolve ledger evidence restore [--evolve-dir .evolve] [--repo <dir>] [--dry-run]` (2026-10-06, ADR-0123 C3) — makes every `composition-verdict` line's diffs durable in the content-addressed store `.evolve/ledger-artifacts/` without rewriting any line: for each diff the store cannot already produce it tries the recorded path, then (identical-rebase lines) regenerates it from the commits and trees the line names, accepts only bytes that re-derive the recorded patch-id, stores them and appends one chained `composition-evidence` record per legacy line. Prints one `line N cycle C method: durable|stored|rebuilt|unrestorable[: reason]` per line (`would be …` under `--dry-run`, which writes nothing); exit `1` when a line is unrestorable, `2` when the chain still does not verify after a real run. It covers only lines after the epoch anchor, as Verify does. `--repo` defaults to the evolve dir's parent. `evolve ledger verify` takes the ledger lock shared, so it needs no write access to `.evolve` and does not wait for another verify. Run it at a boundary with no loop running; the 2026-10-06 plane repair is in [the incident](../incidents/2026-10-06-carry-refused-ledger-verify-f5.md).
> - **Ledger lifecycle records are CHAIN PARTICIPANTS (#450):** inbox-lifecycle events (claim/promote/recover…) go through `FileLedger.AppendLifecycle` — same flock, `prev_hash`/`entry_seq`, atomic tip replace — as entries with `kind:"inbox-lifecycle"`, `action`, `task_id` (additive `core.LedgerEntry` field), and from/to/reason folded into `message`. The old raw-`O_APPEND` unchained shape (`class`/`from`/`to` top-level keys) was the per-cycle chain-break generator under fleet concurrency; historical lines with that shape remain on disk, tolerated by the wire parser, never rewritten. Grep guard: no `O_APPEND` opens of `ledger.jsonl` outside `internal/adapters/ledger`.
> - `evolve loop --reset --fingerprint <fp>` — blocker-breaker fingerprint-ack operator unblock (ADR-0072 extension, cycle-1332; the cycle-1329 recurrence fix). Gated on `--reset`: appends one record `{fingerprint, resolved_at, resolved_by: "operator-reset"}` to `.evolve/resolved-fingerprints.json` (atomic tmp+rename write) before the pre-existing `--reset` failedApproaches prune runs. This acknowledges the named failure fingerprint so the blocker breaker's Rule B ("identical-fingerprint") excludes it from its recurrence count on every subsequent relaunch — without a fingerprint whose root cause was already diagnosed and fixed re-tripping the halt on relaunch after relaunch. The exclusion is scoped to exactly the one named fingerprint; any other, unacked fingerprint still halts at the ceiling unchanged. Consumed via `core.LoadResolvedFingerprints` into `BlockerBreakerConfig.AckedFingerprints` (`go/internal/core/blocker_breaker.go`), which `EvaluateBlockerBreaker`'s Rule B checks before counting a digest. Empty `--fingerprint` (the default) is a no-op — byte-identical pre-existing `--reset` behavior. Example: `evolve loop --reset --fingerprint 'ship|unknown|76d0f4fca190'`. **Batch-window floor (fail-advance):** the breaker scopes to THIS batch's digests only — the window floor is `max(lastCycleNumber, lastAllocatedCycleNumber)` (`readBatchWindowFloor`, `cmd/evolve/cmd_loop_control.go`). Two counters with two meanings: `lastCycleNumber` tracks cycles COMPLETED (an aborted cycle writes its failure digest via `abnormalEpilogue` but returns before `finalizeCycle`, so the counter never advances past it), while `lastAllocatedCycleNumber` tracks cycles DISPATCHED (advances at mint time — a crashed run BURNS its number). Anchoring the window on the completion counter alone kept re-collecting aborted cycles' digests on every relaunch, so Rule B re-tripped before any cycle ran (the cycle-1335 triple re-halt: `lastCycleNumber=1325` while cycles 1326/1328/1329 had aborted with one shared fingerprint); anchoring on the allocation lease advances the window past failed cycles. `max`, not a bare swap: legacy state can carry a zero lease, and anchoring on it alone would zero the window and re-collect all of `runs/`. The same prune and ack run standalone, without launching or preparing a loop, as `evolve failures reset [--fingerprint F] --project-root D` (next bullet).
> - `evolve failures list|reset|prune` (cycles 1801 and 1803) — the failedApproaches lifecycle without a loop launch. `list [--class C] [--json] [--project-root D]` is read-only and defaults to the working directory. `--json` prints the raw `failedApproaches` array, every classification included. The text form adds each entry's `expiresAt=` (`-` when absent) and a sorted section of the fingerprints acknowledged in `.evolve/resolved-fingerprints.json`. `reset [--fingerprint F] --project-root D` runs `resetFailures` (`go/cmd/evolve/cmd_loop_maintenance.go`), the one function `loop --reset` also runs: it prunes infrastructure-systemic, infrastructure-transient and ship-gate-config entries and, with `--fingerprint`, records the `operator-reset` ack. The ack still runs when the prune fails. `prune --project-root D` removes the expired failedApproaches **and** carryoverTodos through `pruneExpiredState`, the expiry step the loop's launch-time auto-prune also runs. Unlike the launch path, it never backfills `expiresAt` and never increments `cycles_unpicked`. Those stay per-batch bookkeeping. `prune --dry-run [--project-root D]` prints each entry the prune would remove (`failedApproaches cycle=… expiresAt=…`, `carryoverTodos id=… expiresAt=…`). It judges expiry with the same oracle (`failurelog.PreviewExpired`) and leaves state.json byte- and mtime-identical. Exit codes: 0 ok; 1 a mutating run (`reset`, a real `prune`) without an explicit `--project-root`; 2 state.json or resolved-fingerprints.json unreadable, unparseable or unwritable (the file is never rewritten); 10 usage, including a leftover positional argument, so a typo such as `prune --project-root D dry-run` can never fall through to the mutating prune. These are between-batches tools: they take no run lease.

> **Operator commands (release resources; 2026-09-29):**
>
> - `evolve gc --project-root <plane> [--dry-run]` releases what finished cycles left behind, one step per resource, each printing its counts. `--dry-run` prints what each step would release and mutates nothing. A mutating run needs an explicit `--project-root`; the run makes it absolute first, because the retention engine and git's worktree list both work in absolute paths. The steps, in order:
>   1. **tmux sessions and sockets.** Evolve-namespace sessions, per-run sockets (`evolve-bridge-p<pid>`) and test-process sockets (`evolve-bridge-t<pid>`, one per test binary that runs real tmux) whose creator pid is dead are killed, and a dead server's socket file is removed. A live loop's or a live test process's socket is never touched, and every kill names its session exactly (`=<name>:`), so a session that already ended never resolves to a live one whose name starts with it.
>   2. **Orphan processes.** A process is sent SIGTERM only when it is an orphan (ppid 1) and its working directory lies inside a cycle worktree under `.evolve/worktrees/` that is not live (the same liveness rules as the worktree step) and that no longer exists or whose cycle has a closeout dossier. A dossier alone is not enough, because a resumed cycle keeps its FAIL dossier while it runs again in the same tree. Phase agents run with their cwd in the cycle's worktree, so this is an ownership proof: an operator shell `cd`'d into an old tree is not an orphan and is never signaled. The trigger was cycle 1762's auditor leaving 14 `while :; do :; done` load loops running for 47 minutes.
>   3. **Worktrees and branches.** A merged, clean, dead tree is removed and its branch deleted with `git branch -d`, as before. A dirty or unmerged tree whose cycle closed out at least `gc.worktrees.salvage_after_hours` ago is **salvaged, then removed**. The salvage is `.evolve/operator-salvage/<leaf>/HEAD` (sha and branch), `uncommitted.patch` (`git diff HEAD --binary`, apply with `git apply`) and `untracked.tgz`, and it is followed, after one more liveness check, by `git worktree remove --force`. The branch is kept, so the lane's commits and any continuation's `snapshot_sha` survive. A failed salvage keeps the tree. A live tree (the plane's cycle state, a fresh lease, or an open run's `run.json` pointer) is never planned; a closed-out run's leftover pointer no longer counts.
>   4. **Run dirs.** The retention ladder the loop's hook runs in shadow is applied: `gc.runs.keep_full` (default 10) newest are kept, and older dead runs past `gc.runs.delete_after_days` / `archive_after_days` are deleted or archived. It also applies `salvage_ttl_days` (30) to `operator-salvage`, `logs_ttl_days` and `tracker_ttl_days`. Apply re-checks each item's liveness. An item it cannot delete or archive fails the run (exit 1).
>   5. **Go build cache.** Entries (`<hash>-a`/`<hash>-d` in `go env GOCACHE`'s hex shards) unused for `gc.go_cache_ttl_hours` are removed. That is Go's own trim criterion (the go command refreshes an entry's mtime on use) with a policy horizon instead of Go's fixed 5 days, which the loop outgrows: every cycle builds in a new worktree path, and a package's cache key includes its directory. A build that looks an entry up at the instant it is trimmed can see a miss or a missing output file, the same race Go's own trim has; an entry unused for a day is in no running build's working set, so this is safe while a loop builds.
>      - **The size cap (2026-10-06).** After the age trim, the least recently used entries are removed until the cache fits `gc.go_cache_max_gb` (compiled default 20 GB). The cap never takes an entry whose mtime is under 2 hours old. The go command refreshes an entry's mtime only once it is an hour old, so the window covers every entry looked up within about the last hour, plus a one-hour hold. It does not protect a build that holds a looked-up output for longer than that. Every victim's mtime is re-read just before its removal, and a victim a build has since used is skipped. When the entries in the window alone exceed the cap, the step stops short and warns `go build cache still holds X, over its Y cap`.
>      - **The report.** The step prints both counts and the bytes that remain: `trimmed N … (X GB unused > 24h …)` and `trimmed M … to fit the 20.00 GB cap (Y GB, least recently used first); Z GB remains`.
>      - **The first measurement.** On 2026-10-06 the dry run on the plane would have trimmed 5.03 GB by age and 48.88 GB by the cap, leaving 19.99 GB of a 74 GB cache.
>      - **A host without Go.** A host with no `go` on `PATH` has no cache to trim, so the step is skipped without failing the run.
>   6. **Pipeline temp artifacts.** Top-level `os.TempDir()` entries older than `gc.temp_ttl_hours` are removed when their names have one of the pipeline's exact shapes: `go-build<N>` (killed builds), `acs[-cycle]<N>-*` and `cycle<N>-*` (predicate binaries and fixtures), and `release-pipeline-dryrun-*.json`. Nothing else in the temp dir matches. `Test*` (a killed test's `t.TempDir`) is deliberately not a shape: any project's or program's `Test…` entry in the shared temp dir would match it, so it proves no ownership.
>   7. **Report.** A real run ends with `evolve gc: disk free A → B (net released C)`, the free space of the project root's filesystem measured before and after.
> - `evolve salvage list [--json] [--project-root P]` (cycle 1803) inventories the leaves step 3 wrote under `.evolve/operator-salvage/<leaf>/` (root: `--project-root`, else `$EVOLVE_PROJECT_ROOT`, else `.`). It prints one row per leaf, sorted by cycle: `leaf`, `cycle` (0 when the name carries none), `branch` (`-` when the HEAD file names none), the full `head`, `changed` (the `diff --git` count in `uncommitted.patch`), `patch` bytes, `untracked` (entries in `untracked.tgz`), `age` in whole hours since the leaf's mtime (the clock `salvage_ttl_days` ages by) and `landed`. `landed` is `yes`, `no` or `unknown`: the result of `git merge-base --is-ancestor <head> origin/main`, where `unknown` covers an absent commit or ref. It never fetches, and an unknown result never fails the run. `--json` prints the same rows as an array (`salvaged_at` RFC3339, `landed` true/false/null). The verb is read-only. gc and the list share one path helper, `gc.OperatorSalvageDir`, and one reader, `gc.ListSalvage` (`go/internal/gc/salvage_list.go`). A leaf whose HEAD is missing or malformed, or whose patch or archive cannot be read, is named on its own stderr line and makes the run exit 2, while every readable leaf is still printed. A missing, empty or leafless salvage directory prints nothing and exits 0. Usage errors exit 10.
> - **Policy knobs** (`.evolve/policy.json` `gc`; each horizon's zero value means never): `go_cache_ttl_hours`, `temp_ttl_hours`, `worktrees.salvage_after_hours`, `runs.delete_after_days` and `runs.archive_after_days`. The checked-in values are 24, 24, 24 and 14 (archive unset). A `go_cache_ttl_hours` below 2 acts as 2, so the age trim never cuts inside the cache's in-use window. `go_cache_max_gb` is a bound, not a horizon, and the one gc knob with a compiled default: an unset, zero or negative value means 20 GB, and the checked-in file leaves it unset. `worktrees.dev_quiet_minutes` is the quiet period of `evolve worktree cleanup --dev --all`: unset, zero or negative means 120 minutes, and values below 30 are raised to 30, so it can never turn the grace off. `gc.mode` governs only the loop's hook, which runs at every batch start and batch end. Its values are `off`, `shadow` (an absent mode) and `enforce`. The checked-in file sets **`enforce`** since 2026-10-06, so the hook applies its run-dir and worktree sweeps instead of only reporting them. An operator run always applies.
> - **When to run it**: at a wave boundary, after `evolve sync-main` and before the next launch, aimed at the plane (`evolve gc --project-root <runtime>`). The loop's hook covers only run dirs and cycle worktrees. The processes, the Go build cache, the temp artifacts and the tmux leftovers are released only by this command. The cache and temp steps are host-wide, and their removals are gated by mtime age. A mid-wave run is safe for every build that looked its cache entries up within about the last hour, because the cap's in-use window and the re-check before each removal keep those entries. The residual race is the same as Go's own trim: a build that holds a looked-up output for over an hour, or an entry looked up at the instant it is removed, sees a cache miss or a missing file and rebuilds or fails that build. Running at the boundary avoids even that. On 2026-09-29 the dry run with the checked-in values reported 61.1 GB of temp artifacts and 21.1 GB of cache to release. The disk-full incident behind the cache and temp steps is [2026-09-28-the-disk-filled-and-two-lanes-failed-for-it.md](../incidents/2026-09-28-the-disk-filled-and-two-lanes-failed-for-it.md).

> **Operator commands (protect in-progress work; 2026-10-06):**
>
> - `evolve checkpoint save [--worktree DIR | --all] [--label TEXT] [--push] [--json] [--project-root P]` snapshots uncommitted work as `refs/checkpoints/<worktree>/<UTC yyyymmddThhmmssZ>` in the shared store and never changes the branch, the index or the working tree. It works on copies of the worktree's index, so it is safe beside a running lane's own `git add`, and it ignores inherited `GIT_DIR`/`GIT_INDEX_FILE`, so it is safe from a git hook. `--project-root` must be a worktree root of the hub's bare store (the layout `evolve worktree create --dev` requires). Without a target it saves the `--project-root` worktree (default `.`); `--worktree DIR` names any linked worktree of the repository and refuses anything else; `--all` saves every live linked worktree under the hub's `dev/` directory, never the runtime plane or a cycle worktree. Each worktree prints `saved <name> <ref>`, `unchanged <name> <ref>` (the newest checkpoint already has this content) or `clean <name>`. `--label` goes into the checkpoint's commit message. The snapshot holds the staged tree and the full working tree (untracked files included, ignored files excluded), and never `go/evolve` or `.evolve/ledger.*`. A save keeps the newest `checkpoint.keep_per_worktree` of that worktree (`.evolve/policy.json`, compiled default 20, strict decode; a zero or negative value is refused) and deletes the older ones; if the policy cannot be loaded it warns, saves and prunes nothing. `--push` also pushes the saved refs to `origin refs/checkpoints/*`; it is never the default, because pushing work in progress to GitHub is not approved.
> - `evolve checkpoint list [--worktree DIR] [--json] [--project-root P]` prints each checkpoint's ref, time, label, base `HEAD` and the files and lines it changes against that base. `--worktree` takes the worktree's directory or just its name, so a removed worktree's checkpoints can still be listed.
> - `evolve checkpoint restore <ref> --into DIR [--json] [--project-root P]` brings a checkpoint back. `<ref>` is `<worktree>/<stamp>` or the full ref. A missing `DIR` becomes a new worktree detached at the checkpoint's base; an existing `DIR` must be a clean linked worktree of the repository, and is detached at the base only when its `HEAD` differs (its branch ref is never moved). Whenever it leaves `HEAD` detached, the output says so and names `git switch -c <branch>`. It refuses a dirty target, and a target holding an ignored file at a path the restore would write, so it never overwrites work. The staged, unstaged and untracked split comes back exactly as saved.
> - `evolve checkpoint prune [--landed] [--json] [--project-root P]` applies the retention to every worktree's checkpoints. `--landed` also deletes each checkpoint whose every changed path already matches `refs/remotes/origin/main` (the last fetched one; it never fetches). It refuses when the policy cannot be loaded, and with `--landed` when there is no `origin/main`; nothing is deleted then.
> - Exit codes for all four: 0 ok; 1 refused or failed (each failing worktree is named on stderr, the others are still saved); 10 usage.
> - **When to use it:** a console lane runs `evolve checkpoint save` in its dev worktree before anything risky (a rebase, a `git stash`, a long agent run) and whenever it pauses; the console sweeps every lane with `evolve checkpoint save --all`. The refs and the restore procedure are in [workspace-layout.md](workspace-layout.md#checkpoints-refscheckpoints); the design is [ADR-0122](../architecture/adr/0122-checkpoint-uncommitted-worktree-work-as-refs.md).

> **Session cost isolation (v10.8.0+):** `claude -p` subagent invocations bill to the OAuth session that launched the dispatcher (the parent Claude Code session), not the batch budget meter. To isolate `/evo:loop` costs from your prior session context, run `/clear` before starting a new evolve-loop batch. The batch meter (`state.json:currentBatch.cycleAccruedCostUSD`) tracks per-cycle accumulation but cannot capture OAuth session charges.

## Ship classes (`evolve ship --class <X>`, native)

| Class | Use case | Verification |
|---|---|---|
| `cycle` (default) | `/evo:loop` cycle commits | Full audit-binding: recent PASS, SHA match, HEAD/tree bound, `acs-verdict.json` red_count==0, **and the auditor entry must belong to THIS run** (see the run-scoped binding row below) |
| `manual` | Operator-driven manual commits | Skips audit-binding, but requires a fresh commit-gate review attestation (`.commit-gate/attestation.json`; bypass with `EVOLVE_BYPASS_COMMIT_GATE=1`); interactive y/N. CI mode: `EVOLVE_SHIP_AUTO_CONFIRM=1`. |
| `release` | `evolve release` pipeline only | Skips audit (version-bump mutates files post-audit); logs RELEASE class loudly |

Bare `git push origin main` is denied by ship-gate (v8.13.0+). `EVOLVE_BYPASS_SHIP_VERIFY=1` is a permanent compatibility bridge but emits deprecation WARN — prefer `--class manual`.

**Binary-churn discard (`cycle`/`manual` staging):** before `git add -A`, these classes discard
post-audit rebuild churn of the tracked `go/evolve` (restore from index) and remove an *untracked*
`go/evolve` so unaudited binaries never ride into commits. The discard **never deletes the
currently-executing binary** — e.g. the gitignored `go/bin/evolve` that the kernel hooks and the
rollback shellout (`evolve ship --class manual`) run — it is skipped with a
`[ship] WARN: churn discard skipped …` line instead (cycle-764 fix; previously a *successful*
manual ship deleted the running binary → exit 127 on the next invocation; heal was
`make -C go build && evolve reset-sha -operator`). `release` ships skip the discard entirely —
the pipeline's rebuild-binary step is the audited producer of `go/evolve`.

### Ship self-healing (repair ladder, ADR-0039 §8)

Ship attempts ONE typed, provably-safe repair per error code per run before surfacing a
failure — no new bypass env vars, no rebase, no force-push, no content deletion:

- **Stale TOFU pin** (`SELF_SHA_TAMPERED`): re-pins when the running binary matches the blob at
  `HEAD:<bin>` (verified rebuild of committed source); any divergence still BLOCKs.
- **Merged-but-unpushed** (`AUDIT_BINDING_HEAD_MOVED`): when HEAD already carries the
  audit-bound tree and origin is strictly behind, ship completes with a push-only closure.
- **Untracked colliders** (`GIT_FF_MERGE_DIVERGED`): byte-identical main-side copies are
  removed; differing copies are quarantine-moved to `.evolve/quarantine/cycle-<N>/` (with
  `manifest.json`) — inspect/restore from there; content is never deleted.
- **Push race** (`GIT_PUSH_REJECTED`): one fetch + ff-retry; a diverged origin reclassifies to
  `needs-reaudit` (local commit preserved — the recovery chain re-audits on the new base).

Operator-visible: `[ship] REPAIR:` log lines; `ship.repair_attempted` / `ship.repair_outcome`
signals; declined attempts annotate `ship-error.json`. On an unresolved ship failure the cycle
worktree is PRESERVED (not pruned) — reclaim via `evolve loop --resume` or `evolve cycle reset`.

### Rebuilding the tracked `go/evolve` binary (recurring chore)

> **Self-heal note (2026-08-05):** the *running loop binary* (`go/bin/evolve`) staleness class no longer
> requires a manual rebuild — the boot-time binary refresh (`boot.binary_refresh=auto`, see the env-var
> table) rebuilds and re-execs a behind-HEAD binary at every fresh `evolve loop` boot. The chore below
> concerns the **tracked release artifact** `go/evolve` (committed to the repo), which is still rebuilt
> and shipped manually.

`go/evolve` is a **tracked build artifact**; rebuild it from HEAD whenever loop behavior changes — a stale
binary truncates cycles (e.g. a pre-A0 binary emits no `boot_ms`, a pre-18.0.0 binary lacks the artifact-timeout
reconciliation). The build is **reproducible**, and the ship gate's TOFU self-SHA pin makes an *intentional*
same-version rebuild trip `SELF_SHA_TAMPERED` — the new binary isn't at `HEAD:go/evolve` until the very commit
being gated puts it there, a chicken-and-egg the auto-repair can't resolve, so it declines. Procedure:

```bash
cd go
HEAD_SHORT=$(git -C .. rev-parse --short=12 HEAD)
LDF="-X github.com/mickeyyaya/evolve-loop/go/pkg/version.version=<VERSION> \
     -X github.com/mickeyyaya/evolve-loop/go/pkg/version.commit=${HEAD_SHORT} \
     -X github.com/mickeyyaya/evolve-loop/go/pkg/version.builtAt=<FIXED-UTC-TIMESTAMP>"
go build -trimpath -buildvcs=false -ldflags="$LDF" -o evolve ./cmd/evolve   # run twice → byte-identical
```

- `-buildvcs=false` is **required** for determinism (else the git VCS stamp varies between builds); `-trimpath`
  strips absolute paths; pin a **fixed** `builtAt` (never `date`) so two builds hash-match.
- Ship as a chore: `EVOLVE_SHIP_AUTO_CONFIRM=1 EVOLVE_BYPASS_COMMIT_GATE=1 ./go/evolve ship --class manual "chore(build): …"`.
  The bypass is justified for a **zero-source-diff binary artifact** — the source was already reviewed and the
  gate's lint/test/review steps no-op on a binary blob; verify *reproducibility* (2× byte-identical) instead.
- **SELF_SHA dance** (expected on a same-version rebuild): clear the pin and re-ship — TOFU re-pins on the
  first run. `.evolve/state.json` is gitignored, so this never pollutes the commit:
  ```bash
  jq 'del(.expected_ship_sha)' .evolve/state.json > .evolve/state.json.tmp.$$ && mv .evolve/state.json.tmp.$$ .evolve/state.json
  ```
- `go build ./...` (and `go test` on `cmd/evolve`) rebuild this binary as a side effect — `git checkout -- go/evolve`
  after non-release builds to keep commits source-only.
Ship-local residues (`GIT_FF_MERGE_DIVERGED`, `COMMIT_PREFIX_GATE`, `GIT_DETACHED_HEAD`,
`WORKTREE_RESOLVE`) route to the debugger phase, never back into the audit↔ship loop.

## Publishing releases

"publish" ≠ "push". Use the native self-healing pipeline:

```bash
evolve release X.Y.Z                  # full publish
evolve release X.Y.Z --dry-run        # simulate
evolve release X.Y.Z --skip-tests     # hot-fix (CI-pre-verified)
```

Each release is classified in its notes as a **binary-release** (the compiled
binary changed → a new macOS fingerprint, needs a fresh approval) or a
**config-release** (binary byte-identical to a prior version → no new approval).
Releases publish one universal macOS artifact (`evolve_darwin_all.tar.gz`) plus
`checksums.txt`.

Pipeline lifecycle: pre-flight (`evolve release-preflight`) → version bump (`evolve version-bump`) → auto-changelog (`evolve changelog-gen`, conventional commits) → consistency check (`evolve release-consistency`) → atomic ship via native `evolve ship` → marketplace propagation polling (`evolve marketplace-poll`, 5 min) → cache refresh → auto-rollback (`evolve rollback`) on post-push failure.

**Demote-on-failure net (#394, landed 2026-07-31; proven live at v22.13.0):** the local ship pipeline
publishes the tag's GitHub release listing BEFORE the remote workflow's suite runs. When that suite fails,
the build/verify jobs are SKIPPED — not failed — and the listing would sit live with **zero assets**: the
`latest` pointer serves it and the one-line installer's prebuilt path 404s on every platform, silently
degrading to build-from-source (v22.11.0 and v22.12.0 both hit this). The `demote-on-failure` job in
`.github/workflows/release.yml` now marks the failed tag's release object `prerelease=true`, so
`releases/latest` keeps resolving the newest release WITH binaries. v22.13/v22.14 lessons: at v22.13.0 the
release suite failed on tracked runtime-minted profile stubs (`TestSmoke_RealProfiles` +
`TestRepoPersonaProfilePairing`, fixed in #406), the tag auto-demoted, and v22.12.1 stayed Latest — the net
worked as designed. Re-promote after fixing with
`evolve release-promote <tag> [--rerun]` (PATCHes `prerelease=false` only after the release workflow run is green and every asset is present; `--rerun` first runs `gh run rerun --failed`; exit 1 = refused, 2 = gh/usage error). **Known gap (QUEUED, not
fixed):** `evolve release-preflight`'s gate suites do not run the ship-time repo-contract scanner pack, so
a repo-contract violation can still first surface in the remote release suite (inbox item
`release-preflight-repo-contract-suites`).
