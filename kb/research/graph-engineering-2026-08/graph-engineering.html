Graph Engineering × Evolve Loop

What the 2026 "graph engineering" concept teaches this project — and the one place it changes what we build. Companion to kb/research/graph-engineering-2026-08/README.md.

1 · The concept in one picture

An AI system is designed as an executable graph: nodes are agents, deterministic functions, and validators; edges are handoffs, gates, and recovery paths. Engineering effort lives on the edges.

The execution half needs vocabulary, not code. The memory half is the real gap.

3 · The gap: a knowledge graph nobody traverses

Dossiers, inbox items, lessons, and fingerprints already carry edge fields — connects_to, deps, class, failure.fingerprint, carryover — written by gated stages and read by nobody. The apicover defect class recurred six times before a human counted the edges by hand.

4 · What we merge — three slices, one invariant

Slice 1

evolve kb graph — a read-only Go projector over the committed corpus. Typed nodes (cycle · defect · item · class · fingerprint · file · commit), typed edges (recurs-as · consumed-by · fixed-by · touches). No DB, no daemon — in-memory, milliseconds.

Slice 2

Brief-time traversal — scout/triage briefs get the 2-hop neighborhood of the batch's items: prior same-class fixes, their squash SHAs, touched files, attached lessons. Precision where it converts to pass-rate.

Slice 3

Recurrence as a query — recurs-as edges over the full corpus surface a repeating class after its second instance, mechanically — not its sixth, by hand.

Invariant

SSOT stays the JSON files; the graph is a derived projection guarded by a drift test. And per the production-validated pattern: zero LLM calls at retrieval time — the LLM consumes the traversal, never performs it.

5 · Deliberately not merged

✗ Graph database / vector store — corpus is hundreds of nodes; projection wins.  ✗ LangGraph adoption — the Go orchestrator is the executable graph.  ✗ LLM-extracted edges — edges come only from fields gated stages already write; extraction would reintroduce drift.
